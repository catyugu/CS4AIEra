一个笔记程序要把记录交给另一个程序。直接传“字典的内存地址”没有用：另一个进程有自己的地址空间。双方需要约定一份独立于当前内存布局的表示。

## 从记录到字节，再恢复为记录

<Term id="serialization">序列化</Term>把程序中的值转换成可保存或传输的表示；反序列化按约定的格式恢复值。JSON 是常用的文本格式，可以表达名称到值的结构、数组、字符串、数值、布尔值和 `null`。

下面让一条记录完成往返。`json.dumps` 生成 JSON 字符串，`encode` 将字符串编码为字节；接收方先解码，再用 `json.loads` 解析：

```python run id="program-composition.serialization-and-compatibility.roundtrip"
import json

note = {"id": 7, "title": "读书", "done": False}
text = json.dumps(note, ensure_ascii=False)
data = text.encode("utf-8")
received = data.decode("utf-8")
restored = json.loads(received)

print("JSON:", text)
print("bytes:", list(data))
print("restored:", restored)
print("same values:", restored == note)
```

`ensure_ascii=False` 让 JSON 字符串直接显示中文，便于观察。实际传输的 `data` 是字节序列。JSON 对象的字段名为字符串，网络交换的 JSON 使用 UTF-8，见 [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html#section-8.1)。

| 阶段 | 本例的对象 | 使用的规则 |
| --- | --- | --- |
| 程序内部 | Python 字典 | Python 对象与类型 |
| 文本表示 | JSON 字符串 | JSON 格式 |
| 保存或传输 | 字节序列 | UTF-8 字符编码 |
| 接收方内部 | 新建的字典 | JSON 解析与 Python 类型映射 |

接收方创建了新的对象。两份记录可以具有相同的字段值，但修改接收方字典不会自动改动发送方的字典。

## 字符数与字节数

字符编码规定文本怎样变成字节。UTF-8 对不同字符使用不同数量的字节；ASCII 字符 `A` 占一个字节，汉字“中”占三个：

```python run id="program-composition.serialization-and-compatibility.utf8"
text = "A中"
data = text.encode("utf-8")
print("text length:", len(text))
print("byte length:", len(data))
print("decoded:", data.decode("utf-8"))
```

这里 `len(text)` 统计 Unicode 码点，`len(data)` 统计字节，见 [Python Unicode 指南](https://docs.python.org/3/howto/unicode.html#encodings)。设置消息的字节长度、限制文件大小时，应计数编码后的数据。解码也必须使用发送方采用的编码，否则可能报错或出现乱码。

## 格式还要表达字段含义

`{"duration": "fast"}` 是合法 JSON，但不满足“duration 是非负整数秒数”的接口要求。<Term id="schema">数据模式</Term>描述字段、类型和允许范围；接口还需要说明单位和缺失字段的含义。

例如，两方都接受 `{"duration": 8000}`，一方按秒处理，另一方按毫秒处理，解析过程可以完全成功，计算结果却相差一千倍。数据交换需要共同的格式与共同的解释。

二进制格式也需要这些约定，只是用字节位置、长度或字段编号表达结构。选择格式时，可以比较可读性、编码大小、解析成本以及已有工具支持。

## 往返会保留什么

JSON 不能直接保留任意 Python 类型。把坐标元组编码为 JSON 数组，解析后得到列表，见 [Python json 类型转换表](https://docs.python.org/3/library/json.html#encoders-and-decoders)。

```python run id="program-composition.serialization-and-compatibility.types"
import json

point = (3, 4)
restored = json.loads(json.dumps(point))
print(point, type(point).__name__)
print(restored, type(restored).__name__)
```

如果接口只要求一对坐标，这种表示可以满足需求；调用方若依赖元组类型，就要在读取后恢复。普通 JSON 也不记录对象地址或共享引用关系。

格式随版本变化时，新旧读写方还要相互配合。完整的兼容检查与发布安排见 <CrossRef id="change-and-review.compatibility-and-migration" />。

## 练习

为一条“计时记录”选择字段，至少包含编号、耗时和备注。写明耗时的类型与单位、备注是否允许省略，再修改第一个单元格完成往返。

将记录分别改成备注含中文、耗时为字符串、缺少耗时字段。哪些变化会让 JSON 解析失败？哪些要由接收程序另外检查？构造一条合法 JSON，让双方因单位不同而得到不同结果。
