查找记录时，“记录不存在”和“记录存在但内容为空”需要不同的处理。接口若都返回空字典，调用方就分不清这两种情况；若用异常表示不存在，就需要约定异常类型。这些行为与函数名、参数类型一起构成接口的使用规则。

## 接口约定与前后置条件

应用程序接口（<Term id="api">API，Application Programming Interface</Term>）是组件向使用者提供的操作及其约定。接口约定写清调用要求、成功结果、状态变化和失败行为。

例如 `get_record(key)` 可以约定：

| 条件 | 结果与状态 |
| --- | --- |
| `key` 是非空字符串，记录存在 | 返回记录字典的外层副本，不修改已有记录 |
| `key` 是非空字符串，记录不存在 | 抛出 `KeyError`，不修改已有记录 |
| `key` 的类型或内容无效 | 抛出 `ValueError`，不开始查询 |
| 存储组件无法完成读取 | 继续报告读取故障，不当作记录不存在 |

<Term id="precondition">前置条件</Term>规定调用开始时必须成立的要求，后置条件规定调用结束后的结果与状态。接口也可以明确拒绝无效输入时的行为，例如表中的“抛出 `ValueError`，不开始查询”。本例的记录字段值都是不可变值，因此外层副本可独立修改。调用方根据这些规则区分正常结果、找不到记录和输入错误。

只要满足这些规则，实现就可以选择用列表、字典或文件保存记录，调用方按同一约定使用接口。

## 正常结果与错误的区分

下面的查找允许合法记录内容恰好是空字典。字典的 `copy()` 创建一份外层副本。

```python run id="program-composition.contracts-and-errors.missing-record"
records = {"a": {}, "b": {"count": 2}}


def get_record(key):
    if not isinstance(key, str) or key == "":
        raise ValueError("key must be a nonempty string")
    return records[key].copy()


for key in ["a", "missing", ""]:
    try:
        print(key, get_record(key))
    except KeyError:
        print(key, "not found")
    except ValueError as failure:
        print(key, "invalid:", failure)
```

`isinstance(key, str)` 检查值是不是字符串；`or` 在左边已经为真时跳过右边。正常数据、目标不存在、输入无效，在这里经过不同路径。调用方可以据此展示空内容、提示换一个键，或要求改正输入。

若把所有异常都转换成 `{}`，三种情况得到同样的值，调用方失去了作出不同决定所需的信息。异常如何沿调用关系传播，见 <CrossRef id="program-logic-and-state.exceptions-and-cleanup" />。

## 错误转换与异常关联

底层读取可能报告操作系统错误，上层只关心“记录目前无法读取”。组件可以将底层异常转换成自己的错误类型，让调用方按统一约定处理，并保留原异常用于诊断。Python 的 `raise NewError(...) from failure` 把新异常与原异常关联起来，见 [Python 语言参考：raise 语句](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)。

转换位置取决于谁有足够信息。例如读取函数知道“文件不存在”，却未必知道文件是否代表一条不存在的记录，还是一份意外丢失的索引。只有知道这层映射的组件，才有依据将它转换成“记录不存在”。

修改状态的接口还要交代失败后留下什么。例如库存不足时，预订操作可以拒绝请求并保持库存不变。这样，调用方才知道下一次读取会得到什么；课末用例将检查这项保证。

## 实现替换与接口兼容

旧接口接受任意非空字符串。新实现只接受长度至少为三的字符串，增加了前置条件：旧调用方原本合法的输入现在会失败。旧接口返回记录字典的外层副本，新实现返回内部记录，削弱了后置条件：旧调用方原本安全的字段替换现在会改变组件状态。

兼容的新实现应继续接纳原接口允许的输入，并保留这些输入对应的结果与状态变化。内部工作量可以变化，新的可选操作也可以增加；已有调用方依赖的结果、修改规则和失败含义需要逐项核对。

## 练习

下面的库存操作约定：“请求正整数数量；库存不足时报错；失败时库存不变。”分别用 `2`、`5`、`0` 与 `-1` 审查它。哪些是合法请求，哪些应该被拒绝？单次调用失败之后，再调用一次，观察到的状态是否符合约定？`global stock` 让函数中的赋值更新函数外的 `stock`。

```python run id="program-composition.contracts-and-errors.exercise-reserve"
stock = 3


def reserve(quantity):
    global stock
    stock -= quantity
    if stock < 0:
        raise ValueError("insufficient stock")
    return stock


quantity = 5
try:
    print("remaining:", reserve(quantity))
except ValueError as failure:
    print("failed:", failure)
print("stock:", stock)
```
