一个程序要把图片转成另一种格式，可以调用同一进程里的库，也可以启动独立的转换工具。两者都能提供转换功能，传递数据和接收结果的方式不同。

## 函数调用与进程间通信

函数调用可以直接传入 Python 列表，返回对象，或让异常沿调用链传播。独立进程有自己的地址空间，双方要通过参数、文件、管道或网络传递数据。需要交换结构化记录时，可以使用上一课的 JSON 等格式。

一个命令行工具通常从参数与标准输入取得数据，通过退出状态、标准输出和标准错误报告结果：

| 通道 | 图片转换工具的用法 |
| --- | --- |
| 命令行参数 | 指定输入路径、输出路径和选项 |
| 标准输入 | 可以接收待处理内容 |
| 标准输出 | 可以返回处理结果 |
| 标准错误 | 通常输出诊断信息 |
| 退出状态 | 按工具约定表示成功或失败 |

调用方和工具不必使用同一种语言。工具退出会结束它自己的运行；它已写入的文件则可以继续存在。

## 子进程调用与结果读取

下面的 Python 代码在普通桌面或服务器环境启动工具，供阅读。浏览器里的单元格不能启动这种操作系统进程。

```python
import subprocess

completed = subprocess.run(
    ["converter", "input.png", "output.webp"],
    capture_output=True,
    timeout=2,
    check=True,
)
```

参数列表的第一项是程序名，其余项交给程序。`capture_output=True` 收集两个输出通道；`check=True` 在非零退出状态时抛出 `CalledProcessError`；`timeout=2` 限定等待时间，见 [Python subprocess.run](https://docs.python.org/3/library/subprocess.html#subprocess.run)。

正常返回时，`completed.stdout` 和 `completed.stderr` 保存输出字节。若工具约定标准输出是 UTF-8 JSON，可以先解码，再解析，最后检查结果中的字段：

```python
import json

result = json.loads(completed.stdout.decode("utf-8"))
```

退出状态、文本编码和数据结构分别提供一层信息。工具返回成功后，调用方按约定读取输出；标准错误中即使有警告，也应结合退出状态判断此次结果。

## 调用生命周期与失败处理

一次调用会依次启动进程、等待处理、收集输出并回收进程资源。故障发生的位置影响下一步动作：

| 结果 | 下一步 |
| --- | --- |
| 程序不存在，无法启动 | 检查安装位置和程序搜索路径 |
| 工具报告输入格式错误 | 向用户说明可接受的格式 |
| 输出无法按约定解析 | 检查工具版本、输出内容和接口约定 |
| 等待超时 | 按调用 API 的规则结束等待并检查遗留状态 |

本例的 `subprocess.run` 在超时后会终止直接启动的子进程，等它结束，再抛出 `TimeoutExpired`。此前写入的文件仍可能存在。等待期限与操作效果的关系，会在 <CrossRef id="networks-and-web.latency-timeouts-and-retries" /> 中结合请求过程展开。

## 练习

转换工具约定：零退出状态表示已生成输出，非零表示失败，标准输出保存一份 JSON 结果，标准错误可以包含警告。

分别考虑程序未安装、输入格式被拒绝、成功但有警告、输出不符合 JSON 四种情况。调用方应从哪个通道取得依据，又应向用户或维护者提供什么信息？
