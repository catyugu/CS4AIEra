笔记应用要把上传的 PNG 转成 WebP 预览图。它选用一个命令行转换工具，由应用启动转换进程，交给它两条文件路径，再根据进程退出状态决定何时可以提供预览。

## 函数调用与进程间通信

函数调用可以直接接收 Python 对象，并返回另一个对象；异常可以沿调用关系传播。独立进程拥有各自的地址空间，进程可以通过命令行参数、文件、管道或网络等机制传递数据。传输结构化记录时，可以使用 JSON 等双方约定的格式。

一个命令行工具通常从参数与标准输入取得数据，通过退出状态、标准输出和标准错误报告结果：

| 通道 | 图片转换工具的用法 |
| --- | --- |
| 命令行参数 | 指定输入路径、输出路径和选项 |
| 标准输入 | 可以接收待处理内容 |
| 标准输出 | 可以返回处理结果 |
| 标准错误 | 通常输出诊断信息 |
| 退出状态 | 按工具约定表示成功或失败 |

这项约定允许应用与工具分别用不同语言实现。工具写入的文件在它退出后仍可由应用打开。

## 子进程调用与结果读取

下面是服务端 Python 中的一段调用。假设这里的 `converter` 是已安装的工具，按顺序接收输入和输出路径。

```python
import subprocess

completed = subprocess.run(
    ["converter", "input.png", "output.webp"],
    capture_output=True,
    timeout=2,
    check=True,
)
```

参数列表的第一项是程序名，其余项交给程序。`capture_output=True` 收集两个输出通道；`check=True` 在非零退出状态时抛出 `CalledProcessError`；`timeout=2` 给这次等待设定超时，进程启动本身在一些平台上可能额外耗时。参见 [Python subprocess.run](https://docs.python.org/3/library/subprocess.html#subprocess.run)。

正常返回时，应用按工具约定从 `output.webp` 取预览图。`completed.stdout` 和 `completed.stderr` 是收集到的字节。这个工具用文件交付结果，因此标准输出可以为空。有些工具约定把 JSON 写到标准输出，这时应用要再解码和解析，并检查返回字段。标准错误也可能记录警告，判断结果要结合退出状态和输出约定。

## 调用生命周期与失败处理

一次调用会依次启动进程、等待处理、收集输出并回收进程资源。故障发生的位置影响下一步动作：

| 结果 | 下一步 |
| --- | --- |
| 程序不存在，无法启动 | 检查安装位置和程序搜索路径 |
| 工具报告输入格式错误 | 向用户说明可接受的格式 |
| 输出无法按约定解析 | 检查工具版本、输出内容和接口约定 |
| 等待超时 | 按调用 API 的规则结束等待并检查遗留状态 |

本例的 `subprocess.run` 在超时后会终止直接启动的子进程，等待它结束，再抛出 `TimeoutExpired`。已经写入的 `output.webp` 可能只包含部分数据，调用方需要按约定检查或清理。如果工具还会启动其他进程，管理和终止这些进程需要额外安排。等待期限与操作效果的关系，会在 <CrossRef id="networks-and-web.latency-timeouts-and-retries" /> 中结合请求过程展开。
