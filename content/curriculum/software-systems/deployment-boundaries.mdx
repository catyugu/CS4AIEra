任务 17 在 API 实例 A 上提交。上午的请求集中到来，团队启动第二个实例，入口开始把查询分给实例 B。B 能接着处理，是因为它连到同一个数据库，取得相同的任务记录和结果对象键。

## 无状态实例与共享存储

如果 A 把上传文件留在本机的 `./uploads`，B 看到的同名路径可能是另一个目录。在另一台机器运行的工作进程也会遇到这个问题。把输入和报告文件放在各方都可访问的对象存储，数据库记录中的对象键才有共同的含义。

后续请求所需的信息保存在实例外，各实例可以根据请求和共享数据独立处理。这种应用服务通常称为**无状态服务**。进程仍可以持有临时计算数据和连接；替换实例时，另一实例能够接手下一次请求。共享数据库和文件存储也要随部署保留，它们承担了这部分状态。

## 进程运行环境与连通性

| 要验证的操作 | 检查位置和目标 |
| --- | --- |
| 打开页面并提交任务 | 从浏览器检查公开入口，入口将 API 请求转给可接收请求的实例 |
| 按编号查询任务 | 从各 API 实例检查数据库地址、权限和实际查询 |
| 完成并下载报告 | 从工作进程检查队列和文件存储，从浏览器走一遍实际下载 |

`localhost` 指发起连接的本地网络环境。数据库若在另一台机器，应用应配置那台机器可达的地址。使用独立网络的容器时，从容器内检查连通性。相对路径以进程的工作目录为起点，上传文件需要保存到应用版本替换后仍可访问的位置。

端口和监听地址见 <CrossRef id="networks-and-web.network-communication" />，入口和反向代理见 <CrossRef id="networks-and-web.development-and-deployment" />。

## 存活检查与就绪检查

进程已经启动，数据库也可能处于重启中。存活检查判断进程是否需要重启，就绪检查判断实例现在能否接收工作。提交一份小报告，等计算完成再下载，可以检查各组件是否能协同完成这项业务。

## 练习

在一次部署测试中，实例 A 接纳任务 17，并把它记入数据库。工作进程生成 PDF 后把文件放进自己的临时目录，并把路径写进任务记录。随后实例 B 收到查询和下载请求。分别追踪查询和下载会得到什么，指出需要修改哪处部署或存储安排。
