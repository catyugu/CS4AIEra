Python 中，两个名字可以引用同一份列表，修改列表时两处都会看到变化。C 语言中的指针也能让多个变量访问同一个对象。指针保存用于定位对象的地址，访问时还要满足对象的范围和生命周期要求。以下代码使用 C 语言，供阅读而不在浏览器单元格中运行。

## 指针与对象别名

在 C 中，`int` 表示整数类型，`int *` 表示指向整数对象的指针类型。`&x` 取得 `x` 的地址，`*p` 访问 `p` 指向的对象。分号结束一条语句：

```c
int x = 7;
int y = 20;
int *p = &x;
int *q = p;
*q = 9;
p = &y;
*p = 21;
```

| 执行到 | x | y | p 指向 | q 指向 |
| --- | --- | --- | --- | --- |
| `int *q = p` | 7 | 20 | x | x |
| `*q = 9` | 9 | 20 | x | x |
| `p = &y` | 9 | 20 | y | x |
| `*p = 21` | 9 | 21 | y | x |

`q = p` 复制地址，两个指针找到同一个整数。给 `p` 换一个地址后，`q` 仍指向 `x`。这与 Python 的<Term id="alias">别名</Term>现象相通：修改共享对象，所有引用它的名字都能看到变化；改变一个名字的绑定，只影响这个名字。C 还允许对指针做运算，访问时需要遵守对象的边界与生命周期。

## 指针与数组范围

`int values[3] = {10, 20, 30};` 声明一个含有三个整数的数组，元素连续存放。合法下标是 0、1、2，`values[1]` 读取第二个整数。C 的数组访问不会自动执行 Python 列表那样的下标检查。

```text
values → [10] [20] [30]
index      0    1    2
```

`values[3]` 试图访问数组之外。那里即使恰好有可读的内存，也没有这个数组的第四项。接口只传一个指针时，调用方通常还需要单独知道可访问的元素数量。例如，处理这份数组的函数可以同时接收起始指针和长度 3。

## 调用栈与局部状态

函数被调用后，需要保存参数、局部变量和返回位置。常见实现使用调用栈组织这些信息，每次调用对应一个栈帧。例如上一课的 `main` 调用 `twice(21)`，可以这样追踪：

| 执行时刻 | 尚未返回的调用 | 局部状态 |
| --- | --- | --- |
| 进入 `main` | `main` | 准备调用 `twice` |
| 进入 `twice` | `main → twice` | `twice` 的参数 `x = 21` |
| `twice` 返回 42 | `main` | `twice` 的这次调用结束 |

递归调用同一个函数时，每次调用也保留自己的参数和局部状态，参见 <CrossRef id="data-algorithms-and-scale.memoization-and-dynamic-programming" />。

## 对象生命周期与悬空指针

函数调用结束也会影响局部对象。下面的 `value` 具有自动存储期，每次进入函数时产生，函数返回时生命周期结束：

```c
int *make_value(void) {
    int value = 42;
    return &value;
}
```

`int *` 表示函数返回整数指针，`void` 表示没有参数。执行 `return &value` 时，函数取得了局部对象的地址；函数返回后，`value` 的生命周期结束，指向它的指针值也变成不确定值。调用者无法通过这个返回值读取原来的 `42`。

如果函数只需要把整数 42 交给调用者，可以直接返回它的值：

```c
int make_value(void) {
    int value = 42;
    return value;
}
```

调用者接收整数值后，就可以独立使用它。返回一个值与返回指向局部对象的指针，对生命周期的要求不同。

C 也提供动态分配内存的方式。`malloc` 取得一块可用空间，`free` 释放它。函数可以把动态分配的空间交给调用方，使调用方在函数返回后继续使用；接口需要约定谁负责释放。遗漏释放会造成内存泄漏，提前释放则会使持有旧指针的调用方失去访问对象的资格。复制指针不会复制对象，也不会延长其生命周期。

数组越界和访问生命周期已结束的对象属于<Term id="undefined-behavior">未定义行为</Term>：C 标准不规定程序会得到什么结果，出现崩溃或看似正常的输出都无法作为正确性的依据。对象生命周期与指针值的规则见 [WG14 C 工作草案 N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf) 和 [WG14 对指针生命周期的讨论](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n2012.htm)。

例如，一个返回动态分配数组的 C 接口应同时交代元素类型、元素数量，以及由谁调用 `free`。即使数组长度正确，调用者也必须在对象被释放之前访问它。

## 练习

一个接口返回动态申请的数组，同时给出元素数，约定由调用方释放。A 把指针复制给 B 后释放数组，B 随后读取第一项。数组长度正确能使这次读取合法的吗？若改为 A 不释放，B 使用结束后也不释放，又留下什么问题？
