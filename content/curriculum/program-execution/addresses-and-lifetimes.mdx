Python 中，两个名字可以指向同一份列表，修改列表以后，两个名字都能看到变化。运行中的程序需要一种办法找到这份共享数据。在机器这一层，内存提供按地址编号的字节位置；一个整数可能占多个连续字节，它的地址标出起始位置。

C 的指针让这个“找到对象”的过程直接可见。下面只读函数体内的语句，追踪地址与对象怎样分别变化；这里的 C 片段供阅读，浏览器单元格不执行它们。

## 两个指针可以找到同一个对象

在 C 中，`int` 表示整数类型，`int *` 表示指向整数对象的指针类型。`&x` 取得 `x` 的地址，`*p` 访问 `p` 指向的对象。分号结束一条语句：

```c
int x = 7;
int y = 20;
int *p = &x;
int *q = p;
*q = 9;
p = &y;
*p = 21;
```

| 执行到 | x | y | p 指向 | q 指向 |
| --- | --- | --- | --- | --- |
| `int *q = p` | 7 | 20 | x | x |
| `*q = 9` | 9 | 20 | x | x |
| `p = &y` | 9 | 20 | y | x |
| `*p = 21` | 9 | 21 | y | x |

这里有四个对象：整数对象 `x`、`y`，以及保存地址的指针变量 `p`、`q`。`int *p = &x` 中，`*` 是声明的一部分，说明 `p` 的类型是整数指针；`*p = 21` 中，`*` 是访问操作，找到 `p` 所指的整数并修改它。因此 `p = &y` 改的是指针保存的地址，`*p = 21` 改的是整数 `y`。

`q = p` 复制地址，两个指针找到同一个整数，整数本身没有复制。给 `p` 换一个地址后，`q` 仍指向 `x`。这与 Python 的<Term id="alias">别名</Term>现象相通：共享对象与改变某个名字的指向是两件事。Python 的名字绑定没有提供 C 这样的直接指针运算。

## 地址不会告诉你数组有多长

`int values[3] = {10, 20, 30};` 声明一个含有三个整数的数组，元素连续存放。合法下标是 0、1、2，`values[1]` 读取第二个整数。C 的数组访问不会自动执行 Python 列表那样的下标检查。

```text
values → [10] [20] [30]
index      0    1    2
```

`values[3]` 试图访问数组之外。那里即使恰好有可读的内存，也没有这个数组的第四项。指针只提供定位信息，不会自动附带“这里有三项”的长度。接口只传一个指针时，调用方通常还需要单独知道可访问的元素数量。

## 对象结束后，旧地址不能继续使用

下面的 `value` 是普通局部对象，每次调用都会创建一份；函数返回后，这份对象的生命周期结束：

```c
int *make_value(void) {
    int value = 42;
    return &value;
}
```

函数名前的 `int *` 表示返回整数指针，`void` 表示没有参数，花括号围住函数体。`return &value` 返回的是地址，没有返回一份独立的整数。追踪一次调用会得到：

| 时刻 | value 是否仍存在 | 返回地址能否用来读取 value |
| --- | --- | --- |
| 在函数体内，完成初始化 | 是，值为 42 | 可以 |
| 计算返回地址 | 是 | 此刻可以 |
| 函数已返回，调用方继续执行 | 否，生命周期已结束 | 不可以 |

存储位置上的旧字节不一定立刻被擦除，但“仍看到旧字节”与“对象仍然存在”不同。后续调用还可能复用这片存储。因而调用方碰巧读到 42，也不能使访问合法；换一次编译或多调用一个函数，就可能表现不同。如果只要整数值，函数应返回 `int` 和 `value`，让调用方取得值，而不是把已经结束的局部对象地址交出去。

C 还可以动态申请内存，让对象不随这次函数调用结束而消失。`malloc` 申请空间，`free` 释放空间；这时必须约定由谁负责释放。把指针返回给调用方，可以让调用方继续使用对象，也可以把适时释放的责任交给它。若一直不释放，不再需要的对象仍占着空间；若过早释放，其他使用者手中的指针就失效了。

释放后，指向它的所有旧指针都不能再用来访问该对象。即使内存分配器随后在同一位置创建了别的对象，也不能把旧对象当成仍然存在。复制指针不会复制对象，也不会延长生命周期。

数组越界和访问已经失效的对象属于<Term id="undefined-behavior">未定义行为</Term>：C 不规定这类程序的结果，不能要求它一定报错或立即崩溃。对象生命周期与访问规则见 [WG14 C 工作草案 N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)。

因此，一个返回数组的接口通常要一起交代元素类型、元素数量和释放责任。调用方用地址找到起点，用长度限定访问范围，并在约定的生命周期内使用它。Python 把许多这样的管理工作交给运行时；调用本地库时，接口仍可能要求使用者遵守这些约定。
