一份程序要取得两份网络数据。发送第一项请求后，要等对方返回，才能继续使用结果。这段时间里，它可以先发出第二项请求，让两项等待重叠。要解释这种安排，先区分执行工作与等待条件。

## 线程与调度

同一进程中的多个<Term id="thread">线程</Term>共享内存和打开的资源，各自保留执行到哪里、有哪些尚未返回的调用。操作系统选择可运行的线程使用 CPU。

| 状态 | 此时在做什么 |
| --- | --- |
| 运行 | 正在 CPU 上执行指令 |
| 就绪 | 可以继续，但还没得到 CPU |
| 阻塞 | 等待数据、锁或其他条件，暂时不能继续 |

阻塞读取可以让线程等待，CPU 转去执行别的就绪线程。条件满足后，线程成为就绪，何时运行由调度决定。不断循环询问“数据到了吗”则会持续占用 CPU，这叫忙等。

并发（concurrency）表示多项工作在重叠的时间段里进行；并行（parallelism）要求同一时刻实际执行多项工作。单核交替执行也能并发，多核才提供更多同时计算的机会。

## 事件循环与异步任务

<Term id="event-loop">事件循环</Term>（event loop）记录哪些任务能继续、哪些还在等待。协作任务在等待时交回控制，事件循环便可以选择另一项就绪任务。

线程和异步任务是两种组织并发的方式。线程可以由操作系统切换；同一事件循环中的协作任务在交出控制后，其他任务才有机会运行。因此，一个线程也能同时管理许多等待中的请求。

下面只用 Python 的一个短例子观察交错。`async def` 定义异步工作，`create_task` 把工作交给事件循环安排，`await` 等待结果。任务调度的规则见 [Python asyncio 任务文档](https://docs.python.org/3/library/asyncio-task.html)。

下面先创建 A、B 两个任务，再依次等待结果。`sleep(0)` 明确让出一次执行机会，不测量真实耗时。浏览器单元格已有事件循环并支持顶层 `await`，可以直接等待 `main()`：

```python run id="program-execution.threads-and-waiting.cooperate"
import asyncio


async def step(label):
    print(label, "start")
    await asyncio.sleep(0)
    print(label, "resume")


async def main():
    first = asyncio.create_task(step("A"))
    second = asyncio.create_task(step("B"))
    await first
    await second


await main()
```

虽然 `await first` 和 `await second` 写成两行，B 不需要等第一行结束才开始：两个任务都已创建，A 等待时，B 就有机会执行。这个单元格展示当前运行时的一次调度顺序。分析程序时，可以依赖每项自己的 `start` 在 `resume` 之前，以及 `sleep(0)` 会让出控制的约定。

`await` 也不一定暂停：等待对象已完成时，可以继续执行。任务和 `sleep` 的规则见 [Python asyncio 任务文档](https://docs.python.org/3/library/asyncio-task.html#sleeping)。

异步函数也在执行它的线程上运行。如果它长时间计算，或调用阻塞读取而一直没有让出控制，事件循环中的其他任务就要等它交回控制后才能继续。

## 练习

两份请求各需本机计算 10 毫秒，再等待远端 90 毫秒。忽略其他开销，串行执行需多少时间？若第一份等待时就开始第二份，两者在单核上可以怎样交错？写出一份可能的时间安排。

再看单元格：把 `main` 中的两次任务创建改成依次 `await step("A")`、`await step("B")`。预测 A、B 的开始和结束次序，再运行。哪一段等待不再重叠？

等待多的工作常能从并发中受益，计算多的工作则需要实际的计算资源。线程还有调度开销，语言运行时也可能限制并行执行。选择执行方式时，应先分清时间花在计算还是等待；再通过测量判断增加线程后节省的等待时间能否抵消调度开销。
