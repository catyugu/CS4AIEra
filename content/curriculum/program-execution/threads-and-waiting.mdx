程序需要从两台服务器分别取得一份数据。假设每份请求先花 10 毫秒进行本地计算和发送，再等待远端返回 90 毫秒。依次完成两份请求需要约 200 毫秒；若第一份请求进入等待后就处理第二份，等待时间可以重叠。

```text
时间（毫秒）   0       10       20                 100      110
请求 A         [本地计算][──────── 等待 ────────][完成]
请求 B                  [本地计算][──────── 等待 ────────][完成]
```

在这个忽略调度和通信开销的模型中，两份请求约在第 110 毫秒全部完成。处理器在等待网络响应时，可以继续执行其他工作。

## 线程与调度

同一进程可以有多个<Term id="thread">线程</Term>。它们共享进程的内存和已打开的资源，每个线程各自记录执行位置、函数调用和局部状态。操作系统调度线程使用 CPU。

| 线程状态 | 含义 |
| --- | --- |
| 运行 | 正在 CPU 上执行指令 |
| 就绪 | 可以执行，正在等待处理器 |
| 阻塞 | 正在等待数据、锁或其他条件 |

例如，线程 A 发起阻塞式文件读取后，可以暂时停止执行；操作系统让线程 B 使用处理器。读取完成时，A 重新进入就绪状态，之后再由调度器安排运行。

几项工作在一段时间内交错推进，叫并发（concurrency）。并行（parallelism）则是多项工作在同一时刻分别执行。单核处理器可以通过交替调度实现并发；多个处理器核心可以同时执行多个线程。

## 异步任务怎样交出控制

网络等待也可以由一个线程中的多个异步任务共同处理。<Term id="event-loop">事件循环</Term>（event loop）管理这些任务：一项任务等待结果时，事件循环运行另一项可以继续执行的任务。

下面的 Python 代码先创建 A、B 两个任务。`async def` 定义异步函数，`create_task` 将协程安排为任务；`await` 等待相应操作完成：

```python run id="program-execution.threads-and-waiting.cooperate"
import asyncio

async def step(label):
    print(label, "start")
    await asyncio.sleep(0)
    print(label, "resume")

async def main():
    first = asyncio.create_task(step("A"))
    second = asyncio.create_task(step("B"))
    await first
    await second

await main()
```

`sleep(0)` 让当前任务主动交出一次执行机会。A 和 B 都创建后，事件循环可以在其中一个任务让出控制时运行另一个。两个任务各自先打印 `start`，再打印 `resume`；具体交错顺序取决于任务调度。`sleep(0)` 用来观察交错，不模拟真实网络耗时。相关行为见 [Python asyncio 任务文档](https://docs.python.org/3/library/asyncio-task.html)。

把 `main` 改成下面这样，程序就会先完整执行 A，再执行 B：

```python
async def main():
    await step("A")
    await step("B")
```

前一个版本虽然也依次写了 `await first`、`await second`，但等待前已经创建了两个任务。因此 A 暂停时，B 可以推进。

异步任务在事件循环所属的线程上执行。如果一项任务持续计算而没有交出控制，其他协作任务就要等待；调用会阻塞该线程的同步操作也有同样的问题。异步适合把等待时间与其他工作交错安排，但同时运行多项 CPU 计算仍需要实际的处理器资源。

## 练习

将第一段时间模型中的第二份请求改为“本地计算 10 毫秒，等待远端 150 毫秒”。先后串行完成两项请求需要多久？按图示安排，在第一份开始等待后处理第二份，最早何时两项全部完成？

运行代码中的两个 `step` 任务，然后把 `main` 改成依次 `await step("A")` 和 `await step("B")`。预测打印顺序，并指出哪一次 `await` 阻止了另一项任务提前开始。
