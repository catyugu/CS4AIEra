在 Python 中，`255 + 1` 得到 256，继续加下去，整数也可以继续变大。整数计算可以先按值理解。把计算结果交给其他组件时，还要问：保存到文件或传输时，实际用哪些字节表示它？

假设文件格式只给计数器留一个字节。这个位置能保存的模式有限，写入 256 时就需要决定：拒绝写入，扩大格式，还是丢掉装不下的部分。计算出的值与保存它的表示方式，从这里开始要分别考虑。

## 位宽决定可表示范围

一个位（bit）保存 0 或 1。二进制按位置给每一位不同权重：从右向左依次是 1、2、4、8。因此二进制 `101` 表示 $1\times4+0\times2+1\times1=5$。

这里讨论字节为 8 位的平台，一个字节（byte）有 $2^8=256$ 种模式。若用它表示无符号整数，范围是 0 到 255；八位全为 1 时，权重相加得到 $1+2+4+\dots+128=255$。一般的 $w$ 位无符号整数范围是 $0$ 到 $2^w-1$。

保存 256 需要第 9 位。某些规则拒绝这次计算；某些规则丢弃超出位宽的部分，得到 0。这种回绕相当于对 $2^w$ 取余。业务要求“总数不能减少”时，回绕即使符合表示规则，也违反业务条件。

C 的变量声明把类型写在名字前面。下面是一份供阅读的完整 C 程序，浏览器里的 Python 单元格不执行 C。`#include` 引入类型声明，`uint8_t` 在提供它的平台上表示恰好 8 位的无符号整数；`main` 是程序入口，花括号围住函数体，分号结束语句：

```c
#include <stdint.h>

int main(void) {
    uint8_t count = 255;
    count = count + 1;
    return count;
}
```

`void` 表示没有参数，`return` 返回结果。这里没有打印：`main` 返回的 0 成为程序的退出状态。

加法先将这里的小整数提升为 `int`，算出 256，再转回 `uint8_t`，保存为 0。C 的无符号规则允许这种模转换；有符号加法超出其结果类型范围则属于<Term id="undefined-behavior">未定义行为</Term>，不能从某台机器上观察到的回绕推定保证，见 [WG14 C 工作草案 N3096 的整数类型、整数转换与表达式规则](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)。判断溢出要先确定表达式的类型，不能只看接收结果的变量。

Python 整数按需要增加表示空间，没有固定 8 位上限，仍受可用内存限制，见 [Python 内置数值类型](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex)。写入定宽格式时，保存函数应先检查值是否落在格式的范围内。这也说明为什么这里要读少量 C：C 的类型让表示宽度和转换规则直接出现在代码里，帮助我们观察 Python 运算中暂时没有遇到的问题。

## 字节的顺序也是规则

两个字节可以装下 16 位整数。十六进制用 `0` 到 `9`、`A` 到 `F` 表示 0 到 15，前缀 `0x` 标出这种写法。`0x1234` 表示 $1\times16^3+2\times16^2+3\times16+4=4660$。每两个十六进制位正好表示一个字节，把这个数拆开就是 `0x12` 与 `0x34`。

| 按地址从低到高存放 | 解读规则 | 得到的整数 |
| --- | --- | --- |
| `0x12`、`0x34` | 大端：高位字节在前 | 4660 |
| `0x12`、`0x34` | 小端：低位字节在前 | 13330 |

字节序（endianness）规定多字节数的高低位怎样安排。解码方必须采用与编码方相同的规则。字节没有改变，错误发生在解释规则上。

`bytes([0x12, 0x34])` 创建两个字节；`int.from_bytes` 按指定顺序读成整数。`byteorder="big"` 是具名参数：明确把字节序设为大端，`"little"` 则表示小端。可以调换字节，也可以只改解码规则：

```python run id="program-execution.bytes-and-numbers.endian"
data = bytes([0x12, 0x34])
print(int.from_bytes(data, byteorder="big"))
print(int.from_bytes(data, byteorder="little"))
```

## 有限精度怎样表示小数

二进制小数的小数位权重依次是 $1/2,1/4,1/8$。因此 0.5 和 0.125 可以精确表示。有限位二进制小数必然是某个整数除以 $2^k$；$1/10$ 的分母含有因子 5，约分后也消不掉，所以不能用有限位二进制小数精确表示。

常见 Python 实现采用<Term id="binary64">binary64</Term> 格式表示 `float`，它提供有限有效位并按数量级改变数值间距，见 [Python 浮点数文档的表示误差](https://docs.python.org/3/tutorial/floatingpoint.html#representation-error)。输入的十进制小数先舍入到可表示值，运算结果也可能再次舍入。

```python run id="program-execution.bytes-and-numbers.rounding"
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print((1e16 + -1e16) + 1.0)
print(1e16 + (-1e16 + 1.0))
```

`1e16` 表示 $10^{16}$。在这个数量级，间隔已经大到加上 1 可能无法改变所存的浮点数。因此运算顺序会影响最后保留下来的信息，数学上成立的结合律不能直接用于逐步舍入的计算。

允许近似误差的测量结果可以按业务容差比较。`math.isclose` 提供相对与绝对容差，见 [Python math.isclose](https://docs.python.org/3/library/math.html#math.isclose)；容差必须来自“多大偏差仍可接受”的要求。若金额始终以分计数，可以直接用整数保存分数，避免把舍入误差混进计数。

## 练习

一个文件格式把数量保存为 16 位无符号整数。计数从 65535 增到 65536 时，格式还能装下吗？如果写入函数只保留低 16 位，读回的数量是多少？要避免把真实数量保存错，写入前需要检查什么？

两次测量相加，要求与目标 0.3 的偏差不超过 0.01。下面两种比较是否都表达了这个要求？先运行原输入，再将它换成 `[0.1, 0.206]` 和 `[0.1, 0.209]`。若比较方式与要求不同，应直接比较哪个量？`round(value, 2)` 把数值舍入到两位小数；`abs(value)` 取得绝对值。

```python run id="program-execution.bytes-and-numbers.exercise"
parts = [0.1, 0.2]
total = parts[0] + parts[1]
print(total == 0.3)
print(round(total, 2) == round(0.3, 2))
```
