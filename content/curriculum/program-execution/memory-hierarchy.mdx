顺序遍历数组与跳着读取数组，即使访问的元素相同、次数相同，也可能有不同的运行时间。这与处理器取数据的方式有关：一次从主存取得的数据，通常包含相邻的多个字节。

## 缓存为什么影响访问成本

CPU 运算使用寄存器中的数据。需要的数据若已经在 CPU 缓存中，就可以较快取得；缓存里没有时，需要从更远的存储层读取：

```text
寄存器
  ↕
CPU 缓存
  ↕
主存（RAM）
  ↕
文件与持久存储
```

缓存容量通常小于主存，访问速度则更快。CPU 从主存向缓存搬运数据时，通常以固定大小的连续块为单位，这种块称为缓存行（cache line）。访问某个位置，如果相应数据已经在缓存中，就是缓存命中；否则发生未命中，需要取回数据。文件中的数据要先经操作系统读入主存，CPU 才能按内存地址访问它。

## 同样的十二次读取

假设数组的 12 个整数连续存放，每四个整数占一块。我们暂时把缓存简化为只能容纳一块，而且开始时为空：

```text
第 0 块：[a b c d]
第 1 块：[e f g h]
第 2 块：[i j k l]
```

顺序 `a b c d e f g h i j k l` 访问时，读到 `a` 才装入第 0 块；接着读取 `b`、`c`、`d` 都命中。读到 `e` 才换成第 1 块，之后换成第 2 块。总共装入三块。

若改为 `a e i b f j c g k d h l`，每次访问都切换到另一块。缓存只能保留一块，因此十二次读取都需要装入数据。

可以用下面的 Python 程序统计这个简化模型中的装入次数。`index // 4` 表示元素所在的块编号，`resident` 记录缓存当前保存的块：

```python run id="program-execution.memory-hierarchy.blocks"
def count_loads(order):
    resident = None
    loads = 0
    for index in order:
        block = index // 4
        if block != resident:
            resident = block
            loads += 1
    return loads

sequential = list(range(12))
jumping = [0, 4, 8, 1, 5, 9, 2, 6, 10, 3, 7, 11]

print("顺序读取:", count_loads(sequential))
print("跳跃读取:", count_loads(jumping))
```

两种顺序都读取十二次；模型分别需要装入 3 块和 12 块。

连续访问附近的数据，有助于利用<Term id="locality">空间局部性</Term>。如果一段数据在被逐出缓存之前再次访问，则体现时间局部性。例如在同一个四元素块中反复读取 `a、b、a、b`，第一次装入后，其余访问都能命中。

## 从模型到真实程序

真实处理器有多级缓存，一次可以容纳许多缓存行，还可能提前取入接下来要用的数据。不同访问顺序的实际耗时，取决于这些机制与数组的大小、布局。

还要确认数据的物理布局。这里假设的是连续存放的整数数组；Python 的普通列表主要保存对象引用，整数对象本身可能位于别处。相同的 `a[i]` 访问形式，在不同数据结构下会产生不同的访存过程。

对每个元素都做一次固定工作，扫描与跳跃访问的算法工作量可以同为 $O(n)$。局部性影响的是完成这些工作的实际成本。

## 练习

把程序中的两种访问顺序换成：

`sequential = [0, 1, 2, 3, 4, 5, 6, 7]`

`jumping = [0, 4, 1, 5, 2, 6, 3, 7]`

缓存仍只能保存一个四元素块。先预测两种顺序分别需要装入几次，再运行验证。如果将顺序读取完整执行两遍，但缓存中的内容在两遍之间保留，第二遍还需要装入多少块？
