一份源代码是文本；CPU 执行的是机器指令。对下面的 C 程序，构建先把源文件转换成代码产物，启动再把产物装载到一次程序运行中。源码、构建产物和正在运行的状态，分别出现在这条路径的不同位置。

先看最小的两文件程序：一份负责调用，另一份提供实现。构建工具怎样把它们接起来？

```c
/* main.c */
int twice(int x);

int main(void) {
    return twice(21);
}
```

```c
/* twice.c */
int twice(int x) {
    return x + x;
}
```

这两个源文件合起来才是完整程序。`main.c` 调用 `twice`，`twice.c` 提供实现。`int twice(int x);` 是声明，告诉编译器参数和返回值的类型；带函数体的写法是定义。`/* ... */` 是注释。程序没有打印语句，`main` 把计算出的 42 返回为退出状态；退出状态的含义需由调用方约定。

## 编译每个文件，再把实现连起来

编译器检查源代码，并把它转换成机器指令。C 的构建工具可以先为每个源文件生成目标文件（object file），其中包含已编译的代码和仍需找到的外部引用。编译 `main.c` 时，声明足以让编译器处理这次调用，尚不需要把 `twice` 的实现放进同一个文件。

链接器再组合目标文件与库，为引用找到对应的定义：

```text
main.c  → main.o  ┐
                 ├→ executable
twice.c → twice.o┘
```

因此，每个文件编译成功后，整个构建仍可能因缺少实现而失败。阶段划分见 [GCC Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)。

| 日志中的现象 | 应检查的位置 |
| --- | --- |
| 源文件有语法或类型错误 | 报错的源码与声明 |
| `twice` 的引用未找到 | 实现是否参与链接 |
| 启动时找不到所需动态库 | 部署产物与运行环境 |

若链接时报告找不到 `twice`，检查构建命令是否包含 `twice.o`。实现可能已经写好，只是没有参与这次构建；继续修改函数体不会补齐这个输入。

## 启动还需要运行环境

操作系统装载可执行文件，建立运行时的代码、数据和资源。有些库代码已经并入产物；有些以<Term id="dynamic-library">动态库</Term>形式单独提供，需要在启动或运行时找到。部署机器缺少必需库，程序可能还没进入 `main` 就失败。Linux 的具体搜索规则见 [Linux ld.so 手册](https://man7.org/linux/man-pages/man8/ld.so.8.html)。

动态库还要与程序采用的机器架构和调用约定匹配。这些约定统称为<Term id="abi">应用二进制接口</Term>（ABI）；这里先用它解释一件事：部署时要提供匹配的库产物，而不是随意找一个同名文件。

CPU 执行机器指令，指令读取数据、计算、写回或跳转。调用函数时，需要传入参数并保存返回后从哪里继续；尚未完成的调用也需要保存自己的局部状态。用于组织这些调用信息的区域称为调用栈，每次调用对应的记录称为栈帧。`main` 等待 `twice(21)` 返回，取得 42 后继续自己的返回语句。编译器可以内联函数或消除不需要的记录，源码中的每次调用不一定都产生独立的机器栈帧。

## Python 调用库时，谁在执行计算

Python 程序可以把工作交给编译好的本地扩展。例如 NumPy 的许多数值运算由编译实现处理数组，见 [NumPy 对运算实现的说明](https://numpy.org/doc/stable/user/whatisnumpy.html)。一次 Python 调用内部就能完成整个循环，省去逐项执行 Python 循环体的开销。

处理 $n$ 项仍需相应工作，运行更快不等于渐近复杂度改变。调用本地扩展通常也没有新建进程：它仍可能访问同一进程的内存，扩展中的内存错误可能使整个进程退出。代码用什么语言实现，与它是否被隔离在另一个进程，是不同问题。
