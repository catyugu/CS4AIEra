前两章的 Python 程序从第一条语句开始执行，改变对象，再输出结果。CPU 执行的却是机器指令。源码与机器指令之间，需要有负责执行或转换代码的程序。

## Python 程序怎样运行

```python
print(2 + 3)
```

Python 运行时读取这段源码，安排加法和函数调用，管理计算中的对象，并把打印内容交给输出设施。CPU 执行运行时及其调用的本地代码。操作系统则管理进程、内存、文件和终端等资源。

常见的 CPython 实现先把源码编译成字节码，再由解释器执行。字节码是供运行时使用的指令，见 [Python 术语表：字节码](https://docs.python.org/3/glossary.html#term-bytecode)。执行 `print` 时，CPU 仍在执行解释器和输出库的机器指令。

| 层次 | 在本例中承担的工作 |
| --- | --- |
| 源码 | 写出加法与打印操作 |
| Python 运行时 | 解释操作，管理值与调用 |
| 操作系统 | 提供并管理运行需要的资源 |
| CPU | 执行机器指令 |

桌面上，Python 解释器通常在操作系统管理的进程中运行。本教材使用浏览器中的 Python 运行时，代码可以计算和输出，访问外部资源的能力由浏览器环境决定。

## 编译与链接

另一种常见方式是在运行前把源码转换成机器代码。下面的 C 程序分成两个文件，供阅读；这里只需关注调用与实现怎样连接。

```c
/* main.c */
int twice(int x);

int main(void) {
    return twice(21);
}
```

```c
/* twice.c */
int twice(int x) {
    return x + x;
}
```

`int` 是整数类型，花括号围住函数体。`int twice(int x);` 声明函数接收和返回整数；另一个文件中的定义给出函数体。编译器可以根据声明处理调用，再由链接器找到实现。

| 阶段 | 输入 | 结果 |
| --- | --- | --- |
| 编译 | `main.c` | `main.o`，包含对 `twice` 的调用 |
| 编译 | `twice.c` | `twice.o`，包含 `twice` 的实现 |
| 链接 | 两个目标文件 | 把调用与实现连接成可执行文件 |
| 装载与运行 | 可执行文件及运行所需的库 | 操作系统建立运行环境，程序开始执行 |

目标文件（object file）保存编译后的代码和链接所需信息。工具可以用一条命令驱动多个阶段，见 [GCC：编译阶段](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)。

若忘记把 `twice.o` 交给链接器，`main.c` 仍可能编译成功，链接时才报告找不到 `twice`。需要补齐的是链接输入。运行成功时，`main` 把 42 作为退出状态返回；程序没有打印语句，屏幕上不会显示 42。

## 程序运行还依赖什么

库提供可复用的功能。一些库代码在链接时并入程序；另一些以<Term id="dynamic-library">动态库</Term>单独提供，在启动或运行时装入。部署机器缺少必需库，程序可能在进入 `main` 之前就失败。库还需与程序的目标平台和<Term id="abi">二进制接口约定</Term>匹配，才能正确交换参数与结果。库的查找规则随平台改变，例如 [Linux 动态装载器](https://man7.org/linux/man-pages/man8/ld.so.8.html)会按规定位置寻找它们。

| 观察到的错误 | 应检查的对象 |
| --- | --- |
| 源码语法或类型错误 | 源码与声明 |
| 链接时找不到 `twice` | 目标文件和链接的库 |
| 启动时找不到动态库 | 部署文件和库搜索位置 |

Python 也会使用编译好的库。例如 NumPy 的许多数值运算由本地代码处理数组，见 [NumPy 简介](https://numpy.org/doc/stable/user/whatisnumpy.html)。Python 一次交出整个数组，可以省去逐项执行 Python 循环的开销；求和仍要处理全部元素。运行时与编译代码可以在同一程序中合作。

## 练习

一份日志显示两个源文件都编译成功，随后链接器报告找不到 `twice`；另一份日志在启动时报告缺少动态库。分别指出需要检查哪些文件。若只把两个 C 源文件复制到另一台机器，那里还需要什么，才能执行这份程序？
