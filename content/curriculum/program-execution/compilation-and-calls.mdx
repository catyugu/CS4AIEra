前两章的 Python 代码可以直接放进单元格运行。计算机的 CPU 执行的是机器指令，这段文本要经过什么程序，才能变成屏幕上的结果？

## Python 代码由谁执行

先看一行熟悉的代码：

```python
print(2 + 3)
```

源码保存了我们要求执行的计算。Python 运行时读取源码，安排表达式计算和函数调用，管理对象，再将打印请求交给输出设施。CPU 执行运行时本身以及它调用的本地代码；操作系统提供内存、文件和终端等资源。

常见的 CPython 实现会先把 Python 源码编译为字节码，再由解释器执行。字节码是供运行时使用的指令形式，与 CPU 直接执行的机器指令不同。这个过程通常由运行时自动完成，见 [Python 术语表：字节码](https://docs.python.org/3/glossary.html#term-bytecode)。

| 对象 | 在这次运行中的作用 |
| --- | --- |
| Python 源码 | 描述计算与输入输出 |
| Python 运行时 | 执行代码，提供对象、函数调用和库功能 |
| 操作系统 | 管理进程与资源，处理受控的输入输出 |
| CPU | 执行运行时及本地程序的机器指令 |

桌面上执行 Python，通常是在操作系统管理的进程中运行解释器。本教材把 Python 运行时带进浏览器，在 Web Worker 中执行代码。两处都需要运行时，但它们能访问的外部资源由宿主环境决定。后文的进程、文件接口和本地工具案例会明确运行环境。

## C 源码怎样形成机器代码

C 项目常在运行前生成供目标机器执行的产物。编译器转换源码，链接器组合代码和库，操作系统在启动时装载程序。下面用两个小文件观察这些阶段；C 只用于展示构建过程，片段供阅读，无需先学习一门完整的语言。

## 声明让调用可以先于实现编译

下面是一个完整程序的两个源文件。`main.c` 调用 `twice`，`twice.c` 提供计算：

```c
/* main.c */
int twice(int x);

int main(void) {
    return twice(21);
}
```

```c
/* twice.c */
int twice(int x) {
    return x + x;
}
```

这些 C 代码供阅读。`int` 是整数类型，分号结束语句，花括号围住函数体，`/* ... */` 是注释。`int twice(int x);` 是声明，说明函数接收并返回整数；带函数体的写法是定义，给出实际计算。

编译 `main.c` 时，编译器可以依据声明检查调用，生成传递参数和接收返回值所需的代码。此时 `twice` 的实现还在另一个文件里。

## 目标文件怎样组合成可执行文件

编译器可以先为每个源文件生成目标文件（object file）。目标文件包含编译后的代码，以及仍需找到的外部定义。链接器再组合目标文件与库，为这些引用找到定义。

| 阶段 | 输入 | 产物或动作 |
| --- | --- | --- |
| 编译 | `main.c` | `main.o`，包含对 `twice` 的引用 |
| 编译 | `twice.c` | `twice.o`，包含 `twice` 的实现 |
| 链接 | 两个目标文件 | 可执行文件，调用与实现连接起来 |
| 装载与运行 | 可执行文件及所需运行库 | 建立进程并开始执行 |

这是一种分步构建方式，工具也可以用一条命令驱动这些阶段，见 [GCC Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)。

如果忘了把 `twice.o` 交给链接器，两个源文件都可能已经编译成功，链接仍会报告找不到 `twice`。此时应补齐链接输入。修改已经正确的函数体无法让链接器找到一个未参与构建的文件。

程序运行到 `main` 后，调用 `twice(21)`，取得 42，再把它作为退出状态返回。这段程序没有打印语句，因此不会把 42 显示在屏幕上。

## 启动时还需要哪些文件

链接时，有些库代码已并入产物；有些库以<Term id="dynamic-library">动态库</Term>形式单独提供，需要在启动或运行时找到。部署机器缺少必需库，程序可能尚未进入 `main` 就失败。Linux 的具体搜索规则见 [Linux ld.so 手册](https://man7.org/linux/man-pages/man8/ld.so.8.html)。

库也要与目标平台兼容，例如为不同机器架构编译的库不能直接混用。程序与库配合所需的二进制约定称为<Term id="abi">应用二进制接口</Term>（ABI）。

可以根据日志先定位阶段：

| 现象 | 先检查什么 |
| --- | --- |
| 编译器报告语法或类型错误 | 报错源码与声明 |
| 链接器报告 `twice` 的引用未找到 | 实现是否参与链接 |
| 启动时报告缺少动态库 | 部署目录、库搜索位置与运行环境 |

## Python 怎样使用编译好的代码

Python 也可以调用编译好的本地扩展。例如 NumPy 的许多数值运算由编译实现处理数组，见 [NumPy 对运算实现的说明](https://numpy.org/doc/stable/user/whatisnumpy.html)。一次 Python 调用可以把整个数组交给本地实现，省去逐项执行 Python 循环体的开销。

逐项相加仍要处理 $n$ 项；这里降低的是每项处理的开销，工作量仍随 $n$ 线性增长。调用本地扩展通常仍在同一进程中，扩展中的内存错误可能导致整个进程退出。进程如何隔离内存，见 <CrossRef id="program-execution.processes-and-kernel" />。

一份日志先写“源文件编译成功”，随后报告 `twice` 未定义；另一份日志在启动时报告缺少动态库。这两种故障分别应在哪个阶段修复？如果只把源文件复制到部署机器，还需要哪些步骤和输入才能运行？
