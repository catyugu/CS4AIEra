在 Python 中写下 `print(2 + 3)`，程序会显示 5。处理器执行的是机器指令，而这行代码是 Python 源码。要让它运行，需要一套负责读取、转换和执行源码的程序。

## Python 源码如何运行

在最常见的 Python 实现 CPython 中，执行过程可以表示为：

```text
Python 源码：print(2 + 3)
        ↓ 编译
Python 字节码
        ↓ 由解释器执行
调用 Python 对象运算与输出功能
        ↓
显示 5
```

这里的编译把源码转换为 CPython 解释器认识的字节码（bytecode）；字节码本身并不是处理器的机器指令。解释器是已经编译好的程序，CPU 运行解释器及其调用的本地代码，完成加法、函数调用和输出。CPython 的字节码及其实现细节见 [Python 术语表](https://docs.python.org/3/glossary.html#term-bytecode)。

`print` 将计算结果交给标准输出。在终端运行 Python 时，终端显示这份输出；在本教材的浏览器运行环境中，输出由页面中的运行器收集并展示。这两种环境都能执行 Python 计算，但可使用的文件和设备不同。

## 从 C 源码到可执行程序

C 程序通常先编译为目标机器的机器代码。下面将函数调用和函数定义放在两个文件中：

```c
/* main.c */
int twice(int x);

int main(void) {
    return twice(21);
}
```

```c
/* twice.c */
int twice(int x) {
    return x + x;
}
```

`int` 表示整数类型，`int twice(int x);` 是函数声明，说明参数和返回值的类型；`twice.c` 中的函数定义才包含计算过程。

编译器分别处理两个源文件，产生目标文件 `main.o` 和 `twice.o`。`main.o` 中记录了调用 `twice` 的位置，但函数实现位于另一个目标文件。链接器根据函数名等符号信息，把调用与定义关联起来，生成可执行文件。

```text
main.c  ──编译──→ main.o  ──┐
                           ├──链接──→ 可执行文件
twice.c ──编译──→ twice.o ──┘
                                      ↓ 装载与执行
                                  进程开始运行
```

链接缺少 `twice.o` 时，编译 `main.c` 可以成功，链接却会报告找不到 `twice` 的定义。完整的编译与链接阶段见 [GCC 文档](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)。

程序开始运行后，`main` 调用 `twice(21)`，得到 42，再把它作为返回值交给运行环境。在常见的操作系统上，这个返回值成为进程退出状态。程序没有调用输出函数，因此终端不会显示 `42`。

## 启动程序还需要什么

可执行文件也可能依赖单独安装的<Term id="dynamic-library">动态库</Term>。操作系统装载程序时，需要找到这些库；程序和库还要遵守兼容的<Term id="abi">应用二进制接口（ABI）</Term>，包括参数传递、数据布局等约定。例如，Linux 上的动态装载器按既定规则查找共享库，见 [ld.so 手册](https://man7.org/linux/man-pages/man8/ld.so.8.html)。

三个故障发生在不同阶段：

| 观察到的结果 | 发生的阶段 | 检查什么 |
| --- | --- | --- |
| 编译器报告类型或语法错误 | 编译 | 源码与声明 |
| 找不到 `twice` 的定义 | 链接 | 是否提供了 `twice.o` |
| 启动时报告缺少动态库 | 装载 | 库文件、搜索位置及平台匹配情况 |

Python 也可以调用编译好的本地库。例如 NumPy 将许多数值运算交给编译后的代码；Python 负责调用与组织数据，底层程序执行相应的计算。

## 练习

将 `main.c` 与 `twice.c` 分别交给编译器，两份目标文件都已生成，但链接器报告 `twice` 未定义。应该修改函数的加法代码，还是检查链接的输入文件？

另一台机器已经拿到了可执行文件，启动时却报告找不到动态库。它缺少的是哪一个阶段的输入？如果程序能够启动并正常结束，却没有显示 `42`，应检查哪一行代码？
