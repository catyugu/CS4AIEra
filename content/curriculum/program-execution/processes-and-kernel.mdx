同一份程序可以启动两次，得到两份独立的计数器。停止其中一次，不会自动把另一次的计数也清零。代码文件相同，运行期间的状态与资源却不同。

## 进程把运行状态与资源组织起来

进程（process）是操作系统管理的一次程序运行所使用的资源与执行环境，包括地址空间、打开的资源和执行线程。程序文件给出代码与初始数据；运行进程包含随执行不断变化的状态。<Term id="process">进程</Term>的身份在进程退出后不应继续当作有效资源引用。

两个进程里的同一个数字地址，可以分别指向不同对象。程序使用的是虚拟地址，由地址转换机制按当前进程的映射找到实际存储位置。地址空间（address space）指可使用的地址及其映射和权限；<Term id="virtual-memory">虚拟内存</Term>让进程使用的地址与物理主存位置分离。

```text
process A: 0x1000 ─→ mapping A ─→ physical page X
process B: 0x1000 ─→ mapping B ─→ physical page Y
```

这是地址关系的示意，不代表真实分配一定从 `0x1000` 开始。普通私有内存的修改按进程隔离；显式共享映射可以让不同地址空间访问同一份数据。Linux 的共享和私有映射规则见 [Linux mmap 手册](https://man7.org/linux/man-pages/man2/mmap.2.html)。进程隔离也不表示文件和外部服务是各自一份：两个进程可以同时修改同一个文件。

## 缺页不一定是程序错误

地址转换常以固定大小的页为单位。一个合法映射可以已经存在，但相关内容暂时没有可直接访问的主存页。访问触发缺页异常后，内核可以准备相应页面，例如按需建立匿名内存页，或读入文件映射的数据，再恢复原指令。

另一种情形是地址根本没有合法映射，或者程序试图写入只读页。此时不能按普通按需装入处理；Linux 可以向进程发送 `SIGSEGV` 等信号，文件映射的某些错误也可能产生 `SIGBUS`，见 [Linux mmap 的信号与映射约束](https://man7.org/linux/man-pages/man2/mmap.2.html#NOTES)。判断“缺页很多”与“越界崩溃”要区分资源需求与非法访问。

进程退出后，操作系统回收其私有地址空间。重新启动会建立新的运行状态，原来只在私有内存里的列表和计数器不会因此恢复。`free` 通常结束分配对象的生命周期，也不保证分配器立即将全部相关空间交回操作系统；对象是否可用与进程占用多少主存是不同问题。

## 系统调用请求内核处理资源

普通函数在用户执行环境内按调用规则运行。读取文件、管理映射等操作需要受控进入内核，这个入口称为<Term id="system-call">系统调用</Term>（system call）。处理器进入内核执行环境，内核依据权限和参数处理请求，再返回结果；Linux 各架构的入口指令与寄存器规则见 [Linux syscall 手册](https://man7.org/linux/man-pages/man2/syscall.2.html#NOTES)。

库函数可能直接计算，也可能包装一个或多个系统调用。调用本地 C 函数并不意味着自动进入内核；进入内核也不意味着一定切换到别的进程。需要等待时才可能让当前线程阻塞，并让其他可运行线程得到 CPU。

## 文件描述符连接进程与已打开资源

以下是 Linux/POSIX 风格的静态 C 代码。`open` 以只读模式打开文件，返回进程中一个整数<Term id="file-descriptor">文件描述符</Term>；`read` 把字节放进数组，返回实际读取数量；`close` 释放这个描述符。头文件提供这些声明与常量。

```c
#include <fcntl.h>
#include <unistd.h>

int read_piece(void) {
    int fd = open("data.bin", O_RDONLY);
    if (fd < 0) {
        return -1;
    }
    char buffer[16];
    ssize_t n = read(fd, buffer, sizeof buffer);
    int closed = close(fd);
    if (n < 0 || closed < 0) {
        return -1;
    }
    return (int)n;
}
```

`ssize_t` 是能表示读取数量与负错误值的整数类型；`(int)n` 将这里最多为 16 的正常结果转成 `int`。`||` 表示“或”。数组只在这次调用期间有效，返回的只是数量。

| 操作结果 | 进程需要怎样理解 |
| --- | --- |
| `open` 返回非负整数 | 得到当前进程中的描述符 |
| `read` 返回 1 到 16 | 只有返回数量对应的字节有效 |
| `read` 返回 0 | 此次读取遇到文件结束 |
| `read` 返回负值 | 读取失败，不能按有效内容处理 |
| `close` 成功 | 描述符不再保持这次打开关系 |

`read` 允许读取数量少于请求数量，见 [Linux read 手册](https://man7.org/linux/man-pages/man2/read.2.html)；`open` 的资源关系见 [Linux open 手册](https://man7.org/linux/man-pages/man2/open.2.html)。描述符数字可以被后来的打开复用，所以保存数字 3 不等于永久绑定某个文件。关闭释放的是打开关系，不是删除文件。

每次跨内核边界都有参数处理和进入、返回的成本，数据可能还需复制或等待。若读取一百万字节，逐字节调用与分块调用的有效数据量相同，调用次数却不同。库缓冲可以合并请求；真正是否减少系统调用，要看调用轨迹，不能只数源代码中的函数调用。
