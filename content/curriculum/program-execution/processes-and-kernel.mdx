假设一个程序启动后建立空列表，每收到一条记录就追加进去。在两个窗口里各启动一次，第一份收到三条记录，第二份仍然为空。关掉第一份再启动，它也从空列表开始。

要解释这些结果，需要把三个东西分开：磁盘上的程序文件、这一次正在运行的程序、列表里的记录。程序文件提供定义；运行时才创建列表，接收输入并改变它。

## 一个程序文件可以有多个运行进程

<Term id="process">进程</Term>（process）是操作系统管理的一次程序运行的资源与执行环境，包括内存地址空间、打开的资源和执行线程。两次启动通常建立两个进程。它们可以使用相同代码，各自拥有自己的列表与执行位置。

这也决定了状态存放的位置：要让两份运行看到同一组记录，就得安排共享数据。仅仅使用同一份程序文件，不会让两个列表自动合成一个。

## 地址要放在所属进程里解释

前面用地址找到内存中的对象。对普通应用进程，这个地址由操作系统安排的映射解释：程序使用虚拟地址，再由当前进程的映射找到实际存储位置。可使用的地址及其映射、权限构成地址空间；<Term id="virtual-memory">虚拟内存</Term>使程序里的地址与物理主存位置分离。

```text
process A: 0x1000 ─→ object A
process B: 0x1000 ─→ object B
```

图中的地址只是示意。同一个数字在两个进程中可以指向不同对象。普通私有内存按进程隔离，显式共享内存则可让两个进程访问同一份数据。文件和外部服务也可能被多个进程共同使用。

进程退出后，它的私有内存会被回收。重启会重新执行建立空列表的代码。若程序先把记录写入文件，下次启动再读入，就能重新建立列表；跨重启延续的是文件中的数据，内存对象则是这次运行重新创建的。文件在什么故障以后仍能保住数据，见 <CrossRef id="persistence.files-and-durability" />。

## 内核负责受控访问资源

一个进程也需要读文件、连接网络或取得更多内存。这些资源由操作系统内核管理，程序通过<Term id="system-call">系统调用</Term>（system call）提出请求。内核检查权限与参数，执行允许的操作，再返回结果。

例如，程序要读一个文件，先请求打开路径。路径不存在，或当前运行身份没有读取权限，打开就会失败。把路径写进程序，只是在表达要访问哪个文件；操作系统决定这次访问是否允许。

普通函数可以在当前进程里完成计算；库中的文件读取函数则可能包装系统调用。两种调用在源码里都像函数调用，但后者要越过程序与内核的边界。内核可以直接返回，也可以让等待资源的线程暂停；线程怎样等待与继续，见 <CrossRef id="program-execution.threads-and-waiting" />。

## 文件、打开关系与内存副本

文件路径用来找到文件。Linux/POSIX 接口中，成功打开文件会返回一个整数<Term id="file-descriptor">文件描述符</Term>，表示当前进程里这一次打开关系。后续读取通过它指定文件，把内容放到进程的内存缓冲区。

这时有三份不同的状态：文件保存字节，打开关系记录这次访问，内存缓冲区保存已经读到的内容。关闭描述符释放打开关系；文件继续存在，已读入内存的内容也可以继续使用。进程退出会清理自己的资源，文件则可以留给下一次运行。

## 阅读接口：一次读取返回了多少字节

读取文件时，程序提供的缓冲区大小是上限，返回值才说明实际读到了多少。下面以 Linux/POSIX 的 C 接口展示这项约定。

以下调用片段请求最多读取 16 字节。`fd` 是已打开的描述符；`char buffer[16]` 是容纳字节的数组；`ssize_t` 是可以同时表示读取数量和负错误值的整数类型：

```c
char buffer[16];
ssize_t n = read(fd, buffer, 16);
```

| 返回值 n | 可以怎样使用数组 |
| --- | --- |
| 1 到 16 | 只有前 n 个字节来自此次读取 |
| 0 | 此次读取遇到文件结束 |
| 负值 | 读取失败，不能当成收到内容 |

读取允许少于请求数量，见 [Linux read 手册](https://man7.org/linux/man-pages/man2/read.2.html)。把整个数组交给解析函数，会把未读到的部分也当作文件内容。若要收齐 16 字节，就要继续读，并处理文件结束或错误。

库可以通过缓冲把多次小读取合并成较少的内核请求。查看文件 I/O 性能时，读取的字节数与请求次数是两个可以分别观察的量。

## 练习

两个进程都记录地址 `0x1000`，却各自读到不同整数。这与进程隔离是否矛盾？若两者需要修改同一组记录，除了程序文件相同，还需要安排什么？

一个程序已把文件读入列表，然后关闭文件。此时修改列表会不会自动改写原文件？若随后关闭程序再启动，要从哪里找回修改后的记录？
