同一份程序启动两次，可以得到两份独立计数器。停止其中一次，不会把另一次的计数也清零。代码文件相同，运行期间的状态与资源却不同。

## 一个程序文件可以有多个运行进程

<Term id="process">进程</Term>（process）是操作系统管理的一次程序运行的资源与执行环境，包括内存地址空间、打开的资源和执行线程。程序文件提供代码；进程保存执行过程中不断变化的状态。

程序使用虚拟地址，由当前进程的映射找到实际存储位置。可使用的地址及其映射、权限构成地址空间；<Term id="virtual-memory">虚拟内存</Term>使程序里的地址与物理主存位置分离。

```text
process A: 0x1000 ─→ object A
process B: 0x1000 ─→ object B
```

图中的地址只是示意。同一个数字在两个进程中可以指向不同对象。普通私有内存按进程隔离，显式共享内存则可让两个进程访问同一份数据。文件和外部服务也可能被多个进程共同使用。

进程退出后，它的私有内存会被回收。重启程序会建立新的内存状态；原来只在列表里的记录不会自行回来。需要跨重启保存的数据必须另有保存位置。

## 内核负责受控访问资源

操作系统内核管理内存映射、文件、设备和调度等资源。程序通过<Term id="system-call">系统调用</Term>（system call）请求内核处理操作，内核检查权限与参数后返回结果。

普通函数调用可以只在当前进程里计算；库中的文件读取函数则可能包装系统调用。调用 C 函数不等于进入内核，进入内核也不一定切换到另一个进程。需要等待资源时，当前线程才可能停下来，让其他可运行的工作使用 CPU。

## 打开文件后，读取多少就使用多少

文件路径用来找到文件。Linux/POSIX 接口中，成功打开文件会返回一个整数<Term id="file-descriptor">文件描述符</Term>，表示当前进程里这一次打开关系。读取操作使用描述符，关闭则释放这份关系，文件本身不会因此删除。

以下调用片段请求最多读取 16 字节。`fd` 是已打开的描述符；`char buffer[16]` 是容纳字节的数组；`ssize_t` 是可以同时表示读取数量和负错误值的整数类型：

```c
char buffer[16];
ssize_t n = read(fd, buffer, 16);
```

| 返回值 n | 可以怎样使用数组 |
| --- | --- |
| 1 到 16 | 只有前 n 个字节来自此次读取 |
| 0 | 此次读取遇到文件结束 |
| 负值 | 读取失败，不能当成收到内容 |

读取允许少于请求数量，见 [Linux read 手册](https://man7.org/linux/man-pages/man2/read.2.html)。把整个数组交给解析函数，会把未读到的部分也当作文件内容。若要收齐 16 字节，就要继续读，并处理文件结束或错误。

每次系统调用都要处理参数、进入内核并返回。逐字节读取与分块读取可能取得同样的内容，调用次数却差很多；库缓冲可以合并请求。

两个进程都记录地址 `0x1000`，却各自读到不同整数。仅凭这件事，能否认定内存损坏？若两者需要修改同一个对象，应当共享什么？
