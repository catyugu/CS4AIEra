一个记录程序启动时先建立空列表，收到一条记录就追加一项。如果在两个窗口中分别启动它，一份收到三条记录，另一份的列表仍为空。关闭第一份后重新启动，列表也会重新变空。

要解释这些结果，需要把三个东西分开：磁盘上的程序文件、这一次正在运行的程序、列表里的记录。程序文件保存代码；每次运行再按代码创建列表，接收输入并改变列表。

## 程序与进程

<Term id="process">进程</Term>（process）是操作系统管理的一次程序运行的资源与执行环境，包括内存地址空间、打开的资源和执行线程。两次启动通常建立两个进程。它们可以使用相同代码，各自拥有自己的列表与执行位置。

两份运行各自创建的列表属于不同的进程。若要让它们处理同一组记录，就需要通过文件、数据库、进程间通信或共享内存来交换状态。

## 进程地址空间

内存中的字节位置用地址标识。对普通应用进程，地址由操作系统安排的映射解释：程序使用虚拟地址，再由当前进程的映射找到实际存储位置。可使用的地址及其映射、权限构成地址空间；<Term id="virtual-memory">虚拟内存</Term>使程序里的地址与物理主存位置分离。

```text
process A: 0x1000 ─→ object A
process B: 0x1000 ─→ object B
```

图中的地址只是示意。同一个数字在两个进程中可以指向不同对象。普通私有内存按进程隔离，显式共享内存则可让两个进程访问同一份数据。文件和外部服务也可能被多个进程共同使用。

进程退出后，它的私有内存会被回收。重启会重新执行建立空列表的代码。若程序先把记录写入文件，下次启动再读入，就能重新建立列表；跨重启延续的是文件中的数据，内存对象则是这次运行重新创建的。文件在什么故障以后仍能保住数据，见 <CrossRef id="persistence.files-and-durability" />。

## 内核与系统调用

一个进程也需要读文件、连接网络或取得更多内存。这些资源由操作系统内核管理，程序通过<Term id="system-call">系统调用</Term>（system call）提出请求。内核检查权限与参数，执行允许的操作，再返回结果。

例如，程序要读一个文件，先请求打开路径。路径不存在，或当前运行身份没有读取权限，打开就会失败。把路径写进程序，只是在表达要访问哪个文件；操作系统决定这次访问是否允许。

普通函数可以在当前进程里完成计算；库中的文件读取函数则可能包装系统调用。两种调用在源码里都像函数调用，但后者要越过程序与内核的边界。内核可以直接返回，也可以让等待资源的线程暂停，等待条件满足后再继续，见 <CrossRef id="program-execution.threads-and-waiting" />。

## 文件描述符与打开的文件

文件路径用来找到文件。Linux/POSIX 接口中，成功打开文件会返回一个整数<Term id="file-descriptor">文件描述符</Term>，表示当前进程里这一次打开关系。后续读取通过它指定文件，把内容放到进程的内存缓冲区。

文件、打开关系和内存缓冲区各有作用：文件保存字节，打开关系记录访问方式和当前位置等信息，缓冲区保存已经读到的内容。关闭描述符释放打开关系；文件继续存在，已读入内存的内容也可以继续使用。进程退出会清理自己的资源，文件则可以留给下一次运行。

一次典型的读取顺序是：按路径打开文件，取得当前进程的文件描述符；用该描述符读入字节；读取完成后关闭描述符。关闭描述符不会删除文件，读入缓冲区的字节也仍归调用程序使用。底层接口可查阅 [Linux read 手册](https://man7.org/linux/man-pages/man2/read.2.html)。
