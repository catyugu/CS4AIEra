浏览器访问 `https://notes.example:8443/items/7`，希望另一台机器上的程序返回一条记录。这个网址至少提出了三个不同问题：目标网络地址是什么，目标机器上谁接收连接，接收之后请求哪份资源？

## 名字、地址与进程

域名 `notes.example` 是名称。<Term id="dns">DNS</Term> 查询可以把这个名称解析成一个或多个 IP 地址；客户端据此选择要连接的地址。名称和地址的对应可以改变，解析结果也可能被缓存。因此一次名称解析成功，只说明拿到了记录，没有证明当前地址上的程序正在运行。DNS 的记录与缓存生存时间见 [RFC 1034：资源记录](https://www.rfc-editor.org/rfc/rfc1034.html#section-3.6)。

<Term id="ip">IP</Term> 为分组提供源地址和目的地址。路由器根据目的地址和本地转发表决定下一跳；分组可以经过多台路由器才能到达目的网络。地址指向网络接口，不能单独说明这台机器上应该由哪个应用接收。

端口（port）是传输协议用于区分端点的数字。服务器进程先让操作系统在指定本地地址和端口上**监听**，准备接受到来的连接。客户端使用目标 IP 地址和目标端口建立通信，操作系统再把数据交给对应端点。路径 `/items/7` 则由应用解释；路由器不会按它选择负责处理记录 7 的进程。

```text
notes.example ── DNS ──> 目标 IP 地址
                             │
浏览器 ── 网络与路由器 ──> 目标机器 :8443
                             │
                         监听进程
                             │
                          /items/7
```

网址开头的 `https` 指定使用受 TLS 保护的 HTTP；域名后显式写出的 `8443` 指定端口。没有显式端口时，客户端根据方案使用默认端口。默认值只是约定，机器必须确实有程序在接收。

## 共享网络怎样承载多份数据

网络通常把数据切成有边界的分组，经共享链路逐个发送，这种组织方式叫<Term id="packet-switching">分组交换</Term>。同一条链路可以交替传送多个通信方的分组。某个分组到达时，若链路正在发送别的分组，它可能先进入队列；队列空间耗尽时可能被丢弃。不同分组的等待、到达顺序和是否到达都可能不同。

应用因此需要规定“收到的字节怎样构成请求”，传输协议需要规定“丢失和乱序怎样处理”，IP 需要规定“分组怎样寻址并转发”。分层使各层可以承担不同规则；某层完成任务，并不代表其他层完成了任务。

| 观察到的结果 | 已有的证据 | 仍未得到的证据 |
| --- | --- | --- |
| 名称解析返回地址 | DNS 给出了地址记录 | 目标可达、端口监听 |
| 传输连接建立 | 此时对端参与了连接建立 | HTTP 请求合法、应用处理成功 |
| 收到 HTTP 响应 | 一个 HTTP 处理方返回了报文 | 内容符合业务要求、修改已持久保存 |

IP 的基本转发信息包括源地址、目的地址以及限制转发次数的字段；[RFC 8200：IPv6 基本首部](https://www.rfc-editor.org/rfc/rfc8200.html#section-3) 给出其格式。推理网络故障时，先确认失败停在表中的哪个位置，才能决定检查解析、监听还是应用。

## localhost 指向访问者自己

`localhost` 通常解析到回环地址，例如 IPv4 的 `127.0.0.1`。回环通信留在当前机器。你在自己的浏览器里打开 `http://localhost:8000`，连接的是你自己的机器；同事打开同一个地址，连接的是同事的机器。

监听地址还决定服务接收哪些目标地址上的连接。在 Linux 的 IPv4 套接字模型中，绑定 `127.0.0.1` 只接收回环通信；绑定 `0.0.0.0` 表示绑定所有本地 IPv4 接口。后者仍受路由、防火墙和网络环境限制，见 [Linux ip(7)：地址与绑定](https://man7.org/linux/man-pages/man7/ip.7.html)。`0.0.0.0` 在这里是监听配置，不能当成同事应该访问的服务器地址。

“端口被占用”表示新进程请求的本地绑定与现有绑定冲突；它发生在进程准备接收通信时。“本机能访问，别人不能”则可能是只监听回环，也可能是远程路径被拦截。换端口解决不了只监听回环的问题，改变监听地址也证明不了远程网络可达。

## 练习

服务器机器上有一个进程只监听 `127.0.0.1:8000`。另一个进程监听它的局域网地址 `192.0.2.20:9000`。假设客户端能路由到服务器、没有防火墙阻挡，分别判断服务器本机与另一台机器访问这两个监听端点需要使用什么地址。`192.0.2.20` 是用于文档的示例地址，不要求实际连接。

一次访问已经取得 DNS 结果，随后连接被拒绝。另一份访问成功建立连接，却收到 `404` 响应。两份证据分别支持检查哪些位置？为什么“域名是对的，所以网络没有问题”不足以结束诊断？
