浏览器访问 `https://notes.example:8443/notes/7`，要找到目标机器、接收请求的程序，再告诉程序需要哪条笔记。网址把这几项信息放在一起。

## 从名字找到服务

域名 `notes.example` 是便于使用的名称。<Term id="dns">DNS</Term> 将域名解析为网络地址等信息；<Term id="ip">IP</Term> 地址用于网络寻址，数据经过中间设备转发，到达目标网络端点。

端口帮助操作系统把通信交给相应的服务。程序启动后，在某个地址与端口监听，才能接收发往该处的连接。路径 `/notes/7` 则交给应用解释，不是另一台机器的地址。

| URL 部分 | 本例 | 作用 |
| --- | --- | --- |
| 方案 | `https` | 指定访问协议 |
| 主机 | `notes.example` | 指定要访问的主机名 |
| 端口 | `8443` | 指定服务端口 |
| 路径 | `/notes/7` | 指定应用中的资源 |
| 查询参数 | 如 `?format=json` | 向应用提供参数 |

网址省略端口时，协议有默认值。`localhost` 指发起访问者自己的环境：服务端程序使用它访问本机服务，用户浏览器使用它则访问用户自己的机器。

## 传输负责把数据交给对方

网络将数据拆成分组转发，这种共享链路传送数据的方式称为<Term id="packet-switching">分组交换</Term>。传送时，分组可能延迟、丢失或乱序。TCP 为应用提供有序、可靠的字节流，通过序号、确认和重传处理这些情况。TCP 不保留应用每次写入的边界，应用协议要规定消息怎样结束。

UDP 提供数据报，保留单份消息边界，不承诺按序、可靠到达。它适用于由上层安排所需传输行为的场景。HTTP/1.1 和 HTTP/2 通常使用 TCP；HTTP/3 使用建立在 UDP 上的 QUIC。底层不同，仍可表达相同的 HTTP 请求与响应语义，见 [MDN：HTTP 概述](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)。

传输确认说明数据已按传输协议交给对端，并不说明后端已经保存笔记。是否完成业务操作，要读取应用响应。

## HTTP 表达请求和响应

下面是一组构造的 HTTP/1.1 报文，供阅读。客户端请求笔记，服务器返回 JSON：

```http
GET /notes/7 HTTP/1.1
Host: notes.example
Accept: application/json

```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"id":7,"title":"reading"}
```

请求中的 `GET` 是方法，`/notes/7` 是目标。响应中的 `200` 是状态码。首部字段说明内容类型等信息，空行之后是正文。实际 HTTP/1.1 还按协议规则界定正文长度；这里省略成帧细节，只观察报文含义。

常见方法包括取得表示的 `GET`、提交内容进行处理的 `POST`、创建或替换目标状态的 `PUT`，以及删除目标的 `DELETE`。例如，创建笔记可以用 `POST /notes`，内容放在 JSON 正文中。

`200` 通常表示成功，`201` 表示已创建，`404` 表示找不到可提供的目标，`500` 表示服务端处理遇到意外错误。`202` 表示已接纳但尚未完成。方法和状态的准确含义见 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。

## HTTPS 保护通信

HTTPS 使用 TLS 保护通信内容的保密性和完整性，并通常通过证书验证服务器身份。浏览器检查证书是否适用于访问的主机名，以及是否有可信的认证链，见 [MDN：TLS](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Transport_Layer_Security)。

这层保护覆盖传输过程。服务器收到请求后，还要检查用户是否能读取笔记；浏览器收到内容后，还要按正确格式解释它。

## 练习

访问 `https://notes.example:8443/notes/7` 时，分别遇到“域名无法解析”“连接被拒绝”“收到 404 响应”。每种结果说明请求最远到达了哪一阶段？应该先检查名称、监听服务，还是应用路径？

后端部署在远程服务器，前端脚本却请求 `http://localhost:8000/notes`。用户打开页面时，请求会发到哪里？改成对外可访问的服务地址以后，还应检查哪些连接与协议条件？
