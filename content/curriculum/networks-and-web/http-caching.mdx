服务器已经修改了一份页面，客户端再次打开时却看到旧内容。一次响应保存之后，缓存什么时候可以不联系服务器直接复用它？答案来自服务器声明的复用规则，以及缓存保存的时间和请求信息。

## 新鲜度允许暂时不联系服务器

HTTP 缓存保存响应，后续符合条件的请求可以复用它。浏览器缓存服务一个用户环境；共享缓存可能服务多个用户，例如服务器前的代理缓存。两者允许复用的范围可以不同。下面是请求 `/notice` 得到的响应：

```http
HTTP/1.1 200 OK
Date: Tue, 06 Oct 2026 00:00:00 GMT
Cache-Control: max-age=60
ETag: "v7"
Content-Type: text/plain
Content-Length: 5

hello
```

`max-age=60` 为这份响应声明 60 秒的新鲜期。响应的年龄小于新鲜期，并且其他复用条件满足时，缓存可以直接返回内容。若服务器在第 20 秒修改了资源，客户端在第 30 秒仍可能合理地使用旧响应。这种设计接受一段时间内的旧值，以省去通信。

年龄不只是“从当前缓存收到响应起过了多久”。一份响应可能先在上游缓存停留，再被转交给浏览器；已有年龄必须计入。[RFC 9111：年龄计算](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2.3) 规定了结合 `Date`、`Age` 与本地计时计算年龄的方法。分析多层缓存时，把每一层的接收时刻都当成年龄零会错误延长复用时间。

## 验证可以省内容，不能省往返

响应超出新鲜期后，缓存通常需要验证或重新取得响应；协议也允许在特定指令或错误条件下使用过期内容，不能把“过期”直接解释成“字节立刻删除”。验证是询问服务器：保存的表示是否仍适用？

`ETag` 是服务器给表示的验证标记，客户端把保存的标记放入条件请求：

```http
GET /notice HTTP/1.1
Host: notes.example
If-None-Match: "v7"

```

```http
HTTP/1.1 304 Not Modified
Date: Tue, 06 Oct 2026 00:01:10 GMT
ETag: "v7"
Cache-Control: max-age=60

```

这里服务器判断现有表示仍与标记相符，返回 `304`，没有再传输表示内容。缓存更新相关元数据，并使用保存的内容。如果表示已经变化，服务器应返回新的表示和相应状态，而不是用 `304` 掩盖变化。条件请求的验证规则见 [RFC 9110：If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2)。标记可以是任意合适的不透明值，客户端无需根据它猜测版本的大小。

| 响应指令 | 主要限制 |
| --- | --- |
| `no-cache` | 可以保存，复用前必须验证 |
| `no-store` | 不得按该指令存储请求或响应 |
| `private` | 不允许共享缓存存储，私人缓存仍可按其他规则保存 |

这些指令控制保存和复用，不能当成浏览器历史、截图或服务器日志的全面删除保证；精确规则见 [RFC 9111：响应缓存指令](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2)。需要每次检查更新但希望节省大文件传输，可以允许保存、要求验证；如果连保存也不允许，就要禁止存储。

## 相同 URL 未必有相同表示

服务器可能按 `Accept-Language` 返回不同语言。如果共享缓存只按 URL 识别响应，先来的中文请求可能让后来的英文请求得到中文。`Vary: Accept-Language` 告诉缓存：复用时还要匹配请求中这个字段的值。

```http
HTTP/1.1 200 OK
Cache-Control: max-age=60
Vary: Accept-Language
Content-Type: text/plain; charset=utf-8
Content-Length: 5

hello
```

如果响应还按 `X-Region` 选择价格单位，两个 URL 和语言相同、地区不同的请求是否仍能共用它？服务器还应声明哪个字段？

`Vary` 指定的是表示选择所依赖的请求字段，不负责为应用检查权限。个人页面如果因 cookie 或身份不同而不同，就不能随意让共享缓存对所有用户复用；通常应明确使用私人缓存规则或禁止存储。单独按 URL 缓存个人内容会同时破坏结果正确性和保密性。

资源修改后，响应指令不会主动把所有已保存副本同步改写。可以让缓存按短新鲜期或验证规则重新取得内容；也可以使用带内容版本的资源 URL，使新版本和旧版本成为不同缓存对象。选择取决于允许多旧的内容，以及额外请求的代价。
