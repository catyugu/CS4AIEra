浏览器访问 `https://notes.example:8443/notes/7` 时，需要找到运行笔记服务的主机，与服务建立通信，再请求编号为 7 的笔记。网址中的不同部分分别参与这些步骤。

## DNS、地址与端口

域名 `notes.example` 是主机名。浏览器通常先通过<Term id="dns">DNS</Term> 查询与它对应的 IP 地址。<Term id="ip">IP</Term> 地址用于网络寻址，路由设备依据地址转发数据包。

到达主机后，传输层还需要把通信交给相应的服务。TCP 端口承担这个作用：服务端程序在指定地址与端口上监听连接。本例使用端口 `8443`，而路径 `/notes/7` 由收到请求的 Web 应用解释。

| URL 部分 | 本例 | 作用 |
| --- | --- | --- |
| URL 方案（scheme） | `https` | 指定使用 HTTPS |
| 主机 | `notes.example` | 指定要访问的主机名 |
| 端口 | `8443` | 指定服务端口 |
| 路径 | `/notes/7` | 指定应用中的资源 |
| 查询参数 | 如 `?format=json` | 向应用提供参数 |

HTTPS 的默认端口是 443，HTTP 的默认端口是 80，因此省略端口仍可找到相应服务。`localhost` 则指运行请求程序的那台机器：用户浏览器中的 `localhost` 是用户自己的计算机，远程服务器中的 `localhost` 是服务器自身。

## 连接与数据传输

网络把数据分成数据包，由中间设备逐段转发，这称为<Term id="packet-switching">分组交换</Term>。数据包可能延迟、丢失，或者以不同于发送时的顺序到达。

TCP 使用序号、确认和重传，为应用提供按序交付的字节流。例如，浏览器可以通过 TCP 连接发送 HTTP/1.1 请求。应用需要按 HTTP 格式识别请求的起止和内容；TCP 本身只处理字节流。UDP 则以数据报为单位传递消息，是否重传由使用它的协议决定。

这一区别也有助于定位故障：连接被拒绝时，通常应检查目标地址、端口和监听服务；收到 HTTP 404 时，服务器已经返回了 HTTP 响应，接下来应检查请求路径和应用路由。

## HTTPS 与传输安全

HTTPS 在 HTTP 通信中使用 TLS，保护传输内容的保密性和完整性。建立加密连接时，浏览器还会验证服务器证书，检查证书上的主机名和可信认证链，见 [MDN：TLS](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Transport_Layer_Security)。

TLS 保护笔记在网络传输中的内容；服务端仍需根据当前用户的身份和权限判断是否可以读取笔记 7。

## 从网址到响应

使用 HTTP/1.1、TCP 和 TLS 时，首次访问这条网址通常经历以下过程：

```text
URL: https://notes.example:8443/notes/7
  │  提取主机名、端口和路径
  ▼
DNS 解析主机名，取得 IP 地址
  │  向该地址的 8443 端口建立 TCP 连接
  ▼
TLS 握手，验证服务器身份并建立加密通信
  │  发送 HTTP GET /notes/7 请求
  ▼
服务端处理请求，返回 HTTP 响应
```

后续访问可能复用 DNS 查询结果或已有连接。HTTP/2、HTTP/3 在传输方式上有所不同，这里选择 HTTP/1.1 便于观察完整过程。HTTP 请求与响应的消息结构见 <CrossRef id="networks-and-web.addressing-and-listening" />。
