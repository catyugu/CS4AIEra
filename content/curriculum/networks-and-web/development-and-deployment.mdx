一个前端项目包含 TypeScript、组件文件和许多依赖。开发时启动工具，浏览器就能看到页面；发布时却常得到一个装着 HTML、CSS 和 JavaScript 的目录。这两种使用方式怎样对应？

## 前端工具链与构建产物

开发者用模块拆分代码，用组件文件组织界面，也可能用 TypeScript 为 JavaScript 增加类型检查。构建工具处理这些输入，生成目标浏览器能够使用的脚本、样式和其他资源。

例如 Vite 提供开发服务器和生产构建能力。开发服务器用于本机调试与更新反馈；生产构建产生可部署资源。具体产物取决于项目配置，见 [Vite：构建生产版本](https://vite.dev/guide/build)。

| 名称类别 | 例子 | 主要工作 |
| --- | --- | --- |
| 页面基础技术 | HTML、CSS、JavaScript | 结构、样式和运行中的交互 |
| 类型工具 | TypeScript | 检查源码中的类型关系，转换代码 |
| 界面库或框架 | React、Vue | 组织组件与界面状态 |
| JavaScript 运行时 | 浏览器、Node.js | 在各自环境执行 JavaScript |
| 前端开发与构建工具 | Vite | 提供开发服务，准备发布资源 |
| 后端框架 | Django、FastAPI | 组织请求处理与后端功能 |
| 数据库 | SQLite、PostgreSQL | 查询和修改持久记录 |

Node.js 常在开发机上执行构建工具。构建完成后，如果只发布静态文件，线上静态服务器不必为了提供这些文件再运行同一套构建工具。应用若包含 Node.js 后端，则需要另外运行相应程序。

## 静态资源部署与后端服务

纯静态前端部署时，要让 Web 服务器能找到并返回构建产物；后端部署则还要启动应用进程、准备配置，并让它访问数据库。

开发服务器可能替前端转发 `/api` 请求。复制静态文件并不会复制这个开发代理，线上需要安排等效入口。Vite 的预览服务用于本地检查构建结果，部署方式应依据目标环境选择，见 [Vite：静态部署](https://vite.dev/guide/static-deploy)。

构建产物就是浏览器实际取得的文件。构建输入与依赖版本的管理见 <CrossRef id="change-and-review.dependencies-and-reproducible-builds" />。

## 反向代理与 CDN

反向代理接收来自客户端的请求，再转交后面的服务器。笔记应用可以这样安排：

| 外部请求 | 入口处的处理 | 最终处理者 |
| --- | --- | --- |
| `/`、`/assets/app.js` | 返回发布目录中的文件 | 静态资源服务 |
| `/api/notes` | 转交后端端口 | 应用进程 |
| HTTPS 连接 | 入口处理 TLS 后转发 | 代理与后端共同完成请求 |

浏览器看到同一个网站入口，后面仍可能有不同进程。静态资源和 API 也可以使用不同域名，此时要相应安排 CORS 与身份凭据。

CDN（内容分发网络）在多个位置分发内容，常用于缓存静态资源。它可以减少重复传输和远距离访问，但缓存会按规则保留副本；用户专属数据需要明确的访问与缓存策略。

开发时前端在端口 5173，API 在 8000，开发代理把 `/api` 转给后端。发布后只复制了前端文件，静态服务器对 `/api/notes` 返回 404。
