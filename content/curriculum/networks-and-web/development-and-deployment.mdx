小林在本机开发笔记应用时，从 5173 端口打开网页。浏览器请求 `/api/notes/7`，开发服务器把它转给 8000 端口的后端。上线后，浏览器访问的是 `https://notes.example`。这时谁提供网页，谁把同一个 API 路径交给后端？

## 从前端源码到发布目录

前端源码可能包括 TypeScript、界面组件和样式。构建工具在开发机或构建环境中处理这些输入，输出浏览器可加载的 HTML、脚本和样式。例如，Node.js 可以运行 Vite，Vite 负责本机开发服务和生产构建。生产构建的产物可以交给静态 Web 服务器提供。工具和产物的关系见 [Vite 的生产构建指南](https://vite.dev/guide/build)。

浏览器收到的是构建后的文件。如果发布时把后端地址写入脚本，用户也能从脚本中读取该值。需要保密的数据库口令等配置应由后端在自己的运行环境中读取。如何固定生成这些文件所需的工具与依赖，见 <CrossRef id="change-and-review.dependencies-and-reproducible-builds" />。

## 同一个域名下的两类请求

一台 Web 服务器可以区分静态文件和 API 路径。它向浏览器交付文件，也可以作为反向代理，把请求交给负责处理的后端进程。

| 浏览器请求 | 线上入口的职责 | 后续处理 |
| --- | --- | --- |
| `GET /notes/7` | 返回笔记页面的 HTML | 浏览器继续加载脚本和样式 |
| `GET /app.js` | 从发布目录返回脚本 | 浏览器运行界面代码 |
| `GET /api/notes/7` | 转交运行中的笔记后端 | 后端校验访问权限并读取数据库 |

浏览器与入口用 HTTPS 通信。入口与后端之间的连接由部署配置决定。若静态资源的使用者分布很广，还可以由 CDN 在靠近使用者的位置缓存这些文件。带版本标识的脚本适合复用，按身份返回的笔记响应需要单独的访问和缓存规则。

## 练习

线上已经复制了发布目录，笔记页面和脚本都返回 200，`/api/notes/7` 却由静态服务器返回 404。对照开发环境，指出这里少了哪一段转发，转发的目标进程在哪里运行。如果该进程也没有启动，应从哪一层补上？
