前端已经发出 `GET /api/notes/7`。服务器怎样知道应该运行哪段代码，又怎样把数据库中的记录变成响应？

## 路由把请求交给处理函数

后端框架提供路由：根据请求方法与路径选择处理代码。例如：

| 方法与路径 | 处理工作 | 可能返回的结果 |
| --- | --- | --- |
| `GET /api/notes/7` | 查询并读取笔记 7 | 笔记 JSON，或不存在、无权限 |
| `POST /api/notes` | 创建笔记 | 新笔记编号 |
| `PUT /api/notes/7/title` | 替换标题 | 更新结果 |
| `DELETE /api/notes/7` | 删除笔记 | 删除结果 |

下面用接近 Python 的伪代码说明一次读取，省略框架的具体声明语法：

```python
def get_note(request, note_id):
    user = authenticate(request)
    note = database.find_note(note_id)
    if note is None:
        return response(status=404)
    if note.owner != user.id:
        return response(status=403)
    return json_response({"id": note.id, "title": note.title})
```

`authenticate`、`database` 和响应函数表示由应用或框架提供的操作。请求携带身份信息，程序找到记录并检查权限，最后将结果编码为 JSON。数据库怎样组织与修改记录，下一章会展开。

## 框架、运行时与 Web 服务器

Python 需要运行时执行代码；Django、FastAPI 等后端框架在运行时之上组织路由、请求解析、响应等功能。不同框架还可能提供模板、会话和数据访问工具，见 [MDN：服务端框架](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Web_frameworks)。

Node.js 则是 JavaScript 运行时，可以在浏览器之外执行 JavaScript 后端或开发工具，见 [Node.js 介绍](https://nodejs.org/en/learn/getting-started/introduction-to-nodejs)。浏览器和 Node.js 可以使用同一种语言，但宿主接口不同；后端没有当前用户页面的 DOM。

Web 服务器接收 HTTP 通信，直接返回静态文件，或将动态请求交给应用处理。实际部署中可能由同一个程序提供这些能力，也可能由反向代理、应用服务器与后端分别承担。程序的名称要与正在承担的职责一起理解。

## 业务规则要落实在服务端

浏览器可以提示标题为空、禁用重复点击。服务器仍需检查实际请求，因为请求可以由其他客户端直接构造。

业务处理还要决定何时返回成功。例如创建笔记要求保存后才能跨设备查询，后端就应在完成相应保存后返回成功。若只把记录放进进程字典，进程退出时会丢失，见 <CrossRef id="persistence.files-and-durability" />。

## 方法要与操作效果对应

HTTP 的 `GET` 用于读取，属于安全方法；`PUT` 和 `DELETE` 具有<Term id="idempotence">幂等性</Term>语义：重复相同请求的预期效果与执行一次相同。把标题设为“reading”，执行两次仍得到这个标题；阅读次数加一，执行两次则增加两次。

`POST` 没有一般的幂等保证。创建操作需要安全重试时，应用可约定使用稳定操作标识识别重复提交。方法属性见 [RFC 9110：共同属性](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2)。

资源的业务结果也要与状态对应：返回 `202` 的报告任务可能还在等待，客户端应按任务地址查询；返回文件正文则表明此次响应已提供内容。后台处理见 <CrossRef id="software-systems.queues-and-background-work" />。
