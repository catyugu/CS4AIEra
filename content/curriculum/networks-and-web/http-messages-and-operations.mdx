请求 `GET /api/notes/7` 已到达 Web 服务器，并被交给笔记应用。后端框架用请求方法和路径选择处理函数。这组匹配规则称为路由。

## 路由与请求处理函数

| 方法 | 路由规则 | 框架交给应用的工作 |
| --- | --- | --- |
| `GET` | `/api/notes/{note_id}` | 把编号 7 交给读取函数 |
| `POST` | `/api/notes` | 把提交的正文交给创建函数 |
| `PUT` | `/api/notes/{note_id}/title` | 把编号和正文交给标题更新函数 |

下面是接近 Python 的伪代码，路由已把路径参数解析为编号。框架提供请求和响应对象，应用提供登录身份、访问权限和数据查询。

```python
def get_note(request, note_id):
    user = signed_in_user(request)
    if user is None:
        return sign_in_required()

    note = database.find_note(note_id)
    if note is None:
        return response(status=404)
    if not can_read(user, note):
        return response(status=403)

    return json_response({"id": note.id, "title": note.title, "body": note.body})
```

应用先确定当前用户，再按编号取得记录并判断他能否读取这条笔记。允许读取时，框架把选中的字段编码为 JSON，连同状态和首部交给 Web 服务器。前端根据权限显示操作入口。每次读取时，后端依据数据库中的权限关系作出授权决定。笔记共享规则见 <CrossRef id="security.identity-authorization-and-sessions" />。

## Web 服务器、框架与运行时

在这条路径上，Web 服务器负责接收和发送 HTTP 消息，框架负责路由、解析与封装响应，Python 运行时执行处理函数。Django、FastAPI 属于框架，Node.js 是另一种语言运行时。实际部署可由一个程序承担多项职责。服务端框架提供的常见功能见 [MDN 的服务端框架介绍](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Web_frameworks)。

## 业务校验与响应

更新标题的处理函数还要读请求正文，检查标题的类型和内容，再判断用户能否编辑这条笔记。最后把修改交给数据库，并在写入成功后返回 `204 No Content`。浏览器可提前提示标题为空，后端仍要对收到的实际数据执行业务校验。

校验失败、笔记找不到、数据库写入故障分别代表三种事情。应用可以为无效标题返回带字段错误的响应，为找不到的笔记返回 404，为失败的数据库操作返回服务端错误并留下诊断记录。前端由此知道该请用户改输入、离开当前页面，还是提示保存失败。

## 练习

用户提交 `PUT /api/notes/7/title`，正文中标题为一个数字。沿处理函数写出请求应当在哪一步被拒绝，数据库里的标题应是什么，前端需要哪项信息才能指出具体问题。
