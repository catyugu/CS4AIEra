打开笔记列表，屏幕上显示“读书”和“会议”。同样的两个条目，可以预先写进站点的 HTML，可以在访问时由后端写进 HTML，也可以由浏览器取得 JSON 后再生成。区分这几种方式，要看列表结构生成的位置，以及那时能取得哪一份数据。

| 方式 | 列表在哪里生成 | 访问时发生什么 | 列表用的是什么数据 |
| --- | --- | --- | --- |
| 服务端渲染（SSR） | 后端处理页面请求时 | 浏览器接收已经含列表的 HTML | 后端按当前用户读取的笔记 |
| 客户端渲染（CSR） | 浏览器运行页面脚本时 | 浏览器先取得页面和脚本，再请求列表数据 | API 按当前用户返回的 JSON |
| 静态站点生成（SSG） | 发布前的构建过程中 | 静态服务器返回已经含列表的 HTML 文件 | 构建时取得的公开笔记快照 |

## 私人列表

服务端渲染时，后端收到 `GET /notes` 后确认用户身份，查询他的笔记，把标题填入 HTML 模板。浏览器解析响应便能看到列表。

客户端渲染时，`GET /notes` 可以向各个用户返回同一份页面。页面脚本再请求 `GET /api/notes`，按照返回的 JSON 建立列表元素。数据请求未完成时，界面可以先显示列表框和加载提示。用 DOM 插入数据的过程见 <CrossRef id="networks-and-web.browser-and-frontend" />。

两种页面都可以用脚本实现局部更新。例如初次打开时由后端生成列表，之后修改标题时只请求更新接口，再更新对应的一个条目。

## 公开快照

笔记应用还可以发布一个公开示例，列出同样两条经过整理、允许公开的笔记。构建工具在发布前把它们生成 HTML，站点上线后直接提供文件。要更新该列表，可重新生成并发布。文件里只有构建时选定的数据，个人笔记仍由访问时的登录身份和查询结果决定。静态生成的具体示例见 [Astro 的按需渲染文档](https://docs.astro.build/en/guides/on-demand-rendering/)。

## 练习

打开 `/notes` 后，页面响应的 HTML 中已经含有“读书”和“会议”。单凭这一点可以把生成方式缩小到哪些候选？如果小林新增一条私人笔记后刷新，列表立即新增一行，需要检查哪些响应，才能判断这一行是哪里生成的？
