笔记页面已经打开。用户点“重新读取”，浏览器要取回笔记 7 的最新内容，并替换阅读区显示的文字。其他部分留在原处。

## HTML、CSS 与 DOM

HTML 声明按钮、标题和正文区域。浏览器解析 HTML，建立文档对象模型（DOM）。CSS 决定这些元素的样式和布局，JavaScript 可以通过 DOM 读取或更新元素。下面是页面的一个片段。

```html
<button id="reload" type="button">重新读取</button>
<p id="status" role="status"></p>
<h1 id="title"></h1>
<pre id="body"></pre>
<script type="module" src="/app.js"></script>
```

## 事件处理与界面状态

`app.js` 中的代码监听按钮点击。它在浏览器里执行，下面的片段供阅读。

```javascript
const button = document.querySelector("#reload");
const status = document.querySelector("#status");
const title = document.querySelector("#title");
const body = document.querySelector("#body");

button.addEventListener("click", async () => {
  button.disabled = true;
  status.textContent = "正在读取";
  try {
    const response = await fetch("/api/notes/7");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const note = await response.json();
    title.textContent = note.title;
    body.textContent = note.body;
    status.textContent = "已更新";
  } catch {
    status.textContent = "读取失败，请重试";
  } finally {
    button.disabled = false;
  }
});
```

`querySelector` 找到 HTML 里的元素，`addEventListener` 指定点击后要做的事。`await fetch` 等待 HTTP 响应，`await response.json()` 再读取并解析正文。只有解析成功后，代码才更新标题和内容。`textContent` 把笔记内容作为文字显示。

收到 404 时，`fetch` 仍可返回响应对象，`response.ok` 此时为假。如果网络故障使浏览器拿不到响应，`await fetch` 就会进入错误处理。两种情况下都保留旧内容，显示失败提示并恢复按钮。接口行为见 [MDN 的 Fetch 指南](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)。

界面再复杂一些，标题、正文、编辑状态和错误提示会有各自的显示规则。React、Vue 等前端工具常把每一块界面组织成组件，再根据状态更新显示。在这段例子里，等待、完成和失败就是会影响显示的三个状态。

## 同源策略与 CORS

`/api/notes/7` 是相对于当前站点的路径。网页来自 `https://notes.example`，请求就发往同一个<Term id="origin">源</Term>。源由 URL 方案、主机和端口决定；把 API 移到 `https://api.notes.example` 就会形成跨源访问。此时浏览器根据同源策略和 API 的跨源资源共享（CORS）规则决定脚本能否读取响应。有些跨源请求还要先经过浏览器发出的预检请求。对到达笔记应用的请求，应用按用户和资源检查读写权限。具体规则见 [MDN 的 CORS 指南](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)。
