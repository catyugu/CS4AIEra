打开一个在线笔记应用，输入文字并保存；换一台电脑登录，仍能看到同一条笔记。界面出现在浏览器里，数据却能跨设备保留。这项功能需要哪些程序合作？

## 界面与数据来自哪里

浏览器是访问 Web 的客户端。它向服务器发送请求，取得页面资源，解释 HTML 和 CSS，运行 JavaScript，最终显示界面并处理用户操作。

服务器可以直接返回预先准备好的文件，也可以运行程序，根据请求生成响应。笔记应用还使用数据库保存用户和笔记记录，让后续请求能查询已经保存的数据。

| 部分 | 在笔记应用中做什么 | 通常在哪里运行 |
| --- | --- | --- |
| 浏览器中的前端 | 显示笔记，接收输入，发出保存请求 | 使用者设备 |
| Web 服务器 | 接收 HTTP 请求，提供文件或转交后端处理 | 服务端 |
| 后端程序 | 判断身份与权限，读取和修改笔记，生成响应 | 服务端 |
| 数据库 | 保存记录，执行查询和修改 | 服务端可访问的存储环境 |

这里的“服务器”既可以指提供服务的机器，也可以指接收请求的程序。Web 服务器和后端处理可以由同一程序承担，也可以分成多个程序。分析应用时，应具体指出正在讨论哪一个。

客户端与服务器的基本协作见 [MDN：客户端与服务端交互](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Client-Server_overview)。

## 一次使用包含多份请求

打开笔记列表，可以依次发生这些事情：

| 阶段 | 浏览器 | 服务端 |
| --- | --- | --- |
| 打开网址 | 请求页面 | 返回 HTML |
| 准备界面 | 按 HTML 加载样式、脚本和图片 | 返回对应资源 |
| 取得列表 | 页面脚本请求笔记数据 | 后端查询数据库，返回记录 |
| 显示列表 | 根据记录生成界面 | 等待后续请求 |
| 保存修改 | 发送编号与新内容 | 检查权限，更新记录，返回结果 |

这是“页面脚本另外请求数据”的一种安排。服务端也可以先查出笔记，再把内容写进返回的 HTML；后面的渲染课会比较两者。

页面中的一份资源加载成功，不代表后续数据请求也完成。能看到按钮却看不到笔记，可能是页面已加载，取得数据的请求失败了。

## 静态网站也能运行前端程序

静态网站返回预先准备的文件。同一文件可以由普通 Web 服务器或内容分发网络（CDN）交给许多访问者。脚本文件送到浏览器后，仍然可以计算、响应点击和更新页面。

因此，静态网站可以有复杂交互。本教材的代码编辑与 Python 实验就在浏览器运行，服务器只提供文件。若要让不同设备共享笔记，还需要一个双方都能访问的数据服务；仅修改当前页面的变量无法完成跨设备保存。

动态服务则在收到请求后执行处理，按用户、参数或数据库状态生成内容。一个应用常同时使用静态资源和动态接口。

## 技术栈描述这些部分怎样实现

技术栈是一组共同实现应用的语言、运行时、框架、存储和工具。例如，一个笔记应用可以用 Vue 组织界面，用 Python 后端处理请求，用关系数据库保存笔记，再由 Web 服务器提供访问入口。

认识技术栈时，先将名称对应到实际工作。前端框架组织界面，后端框架组织请求处理，数据库负责记录；构建工具则准备可发布文件。后续各课会逐一解释这些位置。
