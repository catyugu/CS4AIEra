在笔记应用里保存一处修改，换台电脑登录，仍能看到修改后的内容。要解释这次操作，需要分别找到显示编辑器的程序、接收保存请求的程序和留下记录的地方。

## 前端、后端与数据存储

小林访问 `https://notes.example/notes/7`。Web 服务器先交付页面和脚本，浏览器用这些资源显示编辑区。编辑区的脚本再发送 `GET /api/notes/7` 读取笔记。在这个例子中，页面文件对所有人相同，笔记正文由后端按访问权限提供。

| 顺序 | 请求或动作 | 负责的组件 |
| --- | --- | --- |
| 1 | 打开 `/notes/7`，加载 HTML、样式和脚本 | 浏览器请求资源，Web 服务器返回文件 |
| 2 | 编辑区请求 `GET /api/notes/7` | 浏览器发送请求，Web 服务器把 API 请求转给后端 |
| 3 | 查找笔记和访问权限，返回标题与正文 | 后端向数据库查询，按结果生成 HTTP 响应 |
| 4 | 把响应里的文字放入编辑区 | 浏览器中的前端代码更新界面 |

这里的前端是浏览器内运行的界面代码，后端是负责业务处理的程序。Web 服务器负责 HTTP 接入，可以与后端同属一个程序，也可以单独部署。数据库保存可供后续请求查询的记录。一次保存走同样的入口，后端检查编辑权限并写入数据库，浏览器收到保存结果后更新提示。换设备时，新的浏览器按自己的请求重新读取这份记录。

## 静态文件与按请求处理

静态站点交付提前准备好的文件。这个教材的 Python 和 SQL 实验由浏览器运行，静态服务器只要提供网页、脚本和解释器文件。图像裁剪同样可以只在用户设备上完成，浏览器直接下载结果。

共享笔记需要按用户查询和修改记录，因此还要运行能接收请求的后端，并给不同设备提供共同可访问的数据。一个 Web 应用可以同时交付静态文件和提供动态 API。

所谓技术栈，是完成这些工作所用的一组技术。例如 Vue 组织界面，Python 与 FastAPI 运行和组织后端处理，数据库保存笔记。这些名字标识的是不同职责。接下来从浏览器已经拿到的网址出发，逐层看请求经过的地方。
