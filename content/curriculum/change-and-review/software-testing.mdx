导出功能的一个版本已经能生成 CSV。给它指定的书目记录，读回文件能否得到相同的标题和价格字段？下面的 Python 示例故意用逗号连接字段。第一条断言检查普通标题，其预期值来自 <CrossRef id="change-and-review.requirements-and-acceptance" /> 的文件约定。

```python run id="change-and-review.software-testing.csv-round-trip"
import csv
from io import StringIO


def render_csv(books):
    lines = ["id,title,price"]
    for book_id, title, price in books:
        price_field = "" if price is None else str(price)
        lines.append(f"{book_id},{title},{price_field}")
    return "\n".join(lines) + "\n"


def read_rows(books):
    return list(csv.reader(StringIO(render_csv(books))))


assert read_rows([(1, "程序与状态", 80)]) == [
    ["id", "title", "price"],
    ["1", "程序与状态", "80"],
]
print("普通标题通过")

# 取消下面三行的注释，检查含逗号的标题和未定价记录。
# assert read_rows([(2, "数据,算法", None)])[1] == [
#     "2", "数据,算法", "",
# ]
```

`StringIO` 把字符串作为文本流，供 `csv.reader` 逐行解析。`assert` 的条件为假时，Python 抛出 `AssertionError`。普通标题通过后，取消后面三行的注释，再运行一次。

## 从失败定位原因

查看第二个用例的实际结果，一行本应有三个字段，实际被读成 `["2", "数据", "算法", ""]`。追踪编码函数可见，它生成了 `2,数据,算法,`。解析器将标题中的逗号也当成了列分隔符。

修复时可以用 `csv.writer` 逐行写入字段，由它加上必要的引号。把包含逗号的用例保留下来，今后若有人重新引入字符串拼接，测试会再次失败。这样的用例叫回归测试。标准库的读写接口见 [Python csv 文档](https://docs.python.org/zh-cn/3/library/csv.html)。

## 从编码函数到下载按钮

| 测试范围 | 设置与操作 | 核对的结果 |
| --- | --- | --- |
| 单元测试 | 把少量记录交给编码函数 | 标题读回保持原值，未定价字段为空 |
| 集成测试 | 在测试库中准备两个分类，调用导出接口 | 查询选中分类的全部记录，行按编号升序 |
| 端到端测试 | 在浏览器选择分类，点击下载并读取文件 | 页面把分类传给后端，取得的文件可解析 |

三种测试从不同入口发现故障。编码错误可从函数的输入和输出着手。导出漏行应检查查询和分页。点击后无下载时，可以先看浏览器实际发出的请求。按改动涉及的路径安排测试，失败时就有一个可重复的起点。
