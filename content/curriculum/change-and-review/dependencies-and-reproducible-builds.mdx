导出按钮的代码合并后，需要把这一版前端构建成浏览器可加载的文件。设书目应用用 npm 管理前端工具，后端则用 Python 标准库生成 CSV。要在另一台机器构建前端，光有按钮的源码还缺安装依赖和选定构建环境这两步。

## 安装依赖

`package.json` 声明项目直接使用的包和允许的版本范围。构建工具本身也可能用到其他包，这些是传递依赖。包管理器解析依赖后，在<Term id="lockfile">锁文件</Term>中记录具体选定的依赖树。遵循<Term id="semantic-versioning">语义化版本</Term>的包会用版本号表达公开接口的变化。例如在正式版本中，破坏公开接口兼容性的改动需要升级主版本。

```bash
npm ci
npm run build
```

在这个项目中，第一条命令按锁文件安装依赖。声明与锁文件不匹配时，`npm ci` 报错退出。第二条命令执行项目声明的构建脚本，读入页面和脚本源码，输出 HTML、JavaScript 和样式文件。如果这次改动升级了构建工具，审查时需要把新的依赖声明和锁文件一起看。参见 [npm ci 文档](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。

## 构建产物的来源

构建前端时，项目把导出接口的地址写入浏览器脚本。测试包中的地址指向测试服务。把包复制到生产服务器后，脚本仍会请求原地址。要让两处部署使用同一份前端文件，可以把接口改成同源的相对地址，由各自的入口服务器转交请求。后端的数据库地址则可以在服务启动时读取配置。

为重建产物，需要记录源码提交、锁文件、Node.js 和 npm 的版本、目标环境以及构建用到的配置。**可复现构建**还要求，在规定的源码、构建环境与步骤下，重建出的指定产物在字节上完全相同。前端文件若写入构建时间，即使用相同的源码和锁文件，输出字节也会变化。参见 [Reproducible Builds 的定义](https://reproducible-builds.org/docs/definition/)。
