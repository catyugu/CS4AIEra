书目应用的 `main` 分支有一条查询全部书目的语句。我们开一个功能分支，先在 `export.sql` 中加上分类条件。

```bash
git switch -c export-by-category
```

<Term id="commit">提交</Term>保存暂存区为这次记录准备的项目快照，并记录父提交、作者和说明。分支是指向提交的名字。新建分支时，它指向当前提交；随后在功能分支上产生的提交会移动这个分支的指针。

## 工作区、暂存区与提交

编辑 `export.sql` 之后，在终端运行 `git status --short`，得到下面一行。行首两列分别表示暂存区和工作区的状态，`M` 表示已修改。参见 [Git status 的短格式](https://git-scm.com/docs/git-status#_short_format)。

```text
 M export.sql
```

`git add export.sql` 把这一刻的文件内容放入暂存区。接着在编辑器里试加 `DESC` 调换顺序，再看状态，会得到 `MM export.sql`。两个 `M` 说明暂存内容与当前提交有差异，工作区与暂存内容也有差异。

```bash
git diff --cached -- export.sql
```

下面截取这条命令输出的两行。查询里的 `?` 是参数占位符，由调用查询的程序提供分类。

```diff
-SELECT id, title, price FROM books ORDER BY id;
+SELECT id, title, price FROM books WHERE category = ? ORDER BY id;
```

运行 `git diff -- export.sql` 则能看到工作区尚未暂存的 `DESC`。验收需要编号升序，删掉刚试加的 `DESC` 后，工作区就与暂存区一致。提交并查看最新一条记录。

```bash
git commit -m "按分类查询导出书目"
git log -1 --oneline
```

```text
6743fd7 按分类查询导出书目
```

末行的前缀是示例提交的缩写标识。后续测试报告可以用提交标识记录当时的源码版本。暂存与差异的命令语义见 [Git diff 文档](https://git-scm.com/docs/git-diff)。

## 合并基点与三方合并

在功能分支上运行 `git diff main...HEAD --stat`，可查看从功能分支与 `main` 的共同起点到当前提交的差异统计。去掉 `--stat` 即可读到逐行修改。这个共同起点在本例中就是分支分开时的提交，Git 称为<Term id="merge-base">合并基点</Term>。

| 提交 | 两个分支的变化 |
| --- | --- |
| B | 共同起点，已有书目表和查询 |
| C | `main` 修复了文件名的编码 |
| E | 功能分支增加了按分类查询 |
| M | 合并结果，同时带有两项改动 |

功能分支的 diff 以 B 为起点，聚焦 B 到 E 的变化。合并时，Git 以 B 为参照合并两边的修改。即使合并过程顺利，仍需在 M 上检查分类筛选和下载文件名能否一起正常工作。若要在共享分支撤销一次已合入的修改，`git revert` 可以建立一个撤销原修改的新提交，保留共享历史。参见 [Pro Git 分支和合并](https://git-scm.com/book/zh/v2/Git-分支-分支的新建与合并) 和 [Git revert 文档](https://git-scm.com/docs/git-revert)。
