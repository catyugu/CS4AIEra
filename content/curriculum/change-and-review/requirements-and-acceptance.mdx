书目应用准备增加“按分类导出”功能。用户选择分类，下载一份 CSV 文件，供其他工具读取。开始写代码之前，需要确定导出哪些记录、哪些列，以及文件应怎样表示缺失价格。

## 功能需求与输入输出

CSV 用文本行和分隔符表示表格，适合把记录交给表格软件或另一段程序。这里构造一份明确需求：导出当前选择分类中的全部书目，只包含编号、标题和价格，按编号升序，价格缺失时留空。文件使用 UTF-8。

| 项目 | 约定 |
| --- | --- |
| 输入 | 选定分类与当前书目数据 |
| 记录范围 | 该分类中的全部书目，包括无库存的书 |
| 列与次序 | `id`、`title`、`price` |
| 行次序 | 按 `id` 升序 |
| 缺失价格 | 空字段 |
| 无匹配记录 | 仅包含标题行 |

这些约定使“导出正确”有了可核对的含义。数据库查询、文件编码和下载界面可以分别实现，但最后要共同满足这份输出要求。

## 示例数据与预期结果

假设当前数据为：

| id | title | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | 程序与状态 | computing | 80 | 3 |
| 2 | 数据与查询 | computing | 缺失 | 0 |
| 3 | 历史资料 | history | 50 | 5 |

选择 computing 时，应导出前两本书。无库存不构成排除条件，第二本的价格也不能自动填成零。先写出这份预期结果，就能发现“只导出可借书”和“缺失价格记为零”改变了需求。

标题还可能包含逗号或换行，CSV 编码器需要按格式规则处理。实现时应使用现有库，例如 [Python csv](https://docs.python.org/3/library/csv.html)，并检查其他工具能否正确读回记录。

## 验收标准与实现方案

验收标准规定可观察结果，实现方案说明怎样产生它。例如，可以查询匹配记录后生成文件，也可以分批读取并逐步生成。数据量很小时，两种方式都可能合适；数据量很大时，还要比较内存占用与等待时间。

性能要求也应有使用条件。例如“在指定规模书目上导出一个分类，全部行应在规定时间内可下载”。这里需要同时确定记录规模、运行环境和允许时间，再进行测量。

## 验收用例

| 验收情形 | 需要检查的结果 |
| --- | --- |
| 一个分类有多本书 | 编号完整，行次序正确 |
| 某本书无库存 | 仍包含该记录 |
| 价格缺失 | 空字段，读回后能与零区分 |
| 标题含逗号或中文 | 文件读回后标题保持原值 |
| 分类没有记录 | 只有标题行 |
| 查询失败 | 告知导出失败，不提供一份貌似成功的空结果 |

预期结果来自需求和示例数据。让实现者或 Agent 准备实现与测试之后，使用者仍需判断这些行为是否符合实际用途。下一课用版本控制组织这次修改，再逐步准备测试和审查。

## 练习

需求改为“只导出当前筛选结果”，页面还增加了价格门槛和排序选项。指出原验收标准中哪些仍适用、哪些需要修改，并用三条记录写出一份新预期结果。
