书目应用要增加按分类导出功能：用户选择分类，得到一份可由其他工具读取的 CSV 文件。功能能否正确交付，取决于哪些记录应当出现、列的排列次序、缺失价格的表示方式，以及导出失败时应用怎样响应。

## 功能需求与输入输出

CSV 用文本行和分隔符表示表格，适合把记录交给表格软件或另一段程序。这里构造一份明确需求：导出当前选择分类中的全部书目，只包含编号、标题和价格，按编号升序，价格缺失时留空。文件使用 UTF-8。

| 项目 | 约定 |
| --- | --- |
| 输入 | 选定分类与当前书目数据 |
| 记录范围 | 该分类中的全部书目，包括无库存的书 |
| 列与次序 | `id`、`title`、`price` |
| 行次序 | 按 `id` 升序 |
| 缺失价格 | 空字段 |
| 无匹配记录 | 仅包含标题行 |

这些约定使“导出正确”有了可核对的含义。数据库查询、文件编码和下载界面可以分别实现，但最后要共同满足这份输出要求。

## 示例数据与预期结果

假设当前数据为：

| id | title | category | price | stock |
| --- | --- | --- | --- | --- |
| 1 | 程序与状态 | computing | 80 | 3 |
| 2 | 数据与查询 | computing | 缺失 | 0 |
| 3 | 历史资料 | history | 50 | 5 |

选择 `computing` 时，完整的 CSV 内容应为：

```csv
id,title,price
1,程序与状态,80
2,数据与查询,
```

第二条记录没有库存也要导出，价格缺失表现为最后的空字段，而不是数值 0。这个预期文件可以直接交给测试程序读回比较；“只导出可借书”或“把缺失价格填成零”都会违反要求。

CSV 使用逗号分隔列，标题本身也可能含逗号、双引号或换行。例如标题 `数据,算法` 必须作为同一字段编码，不能拆成两列。应使用 [Python csv](https://docs.python.org/3/library/csv.html) 等库生成文件，再读回检查字段和值；简单地用逗号拼接字段容易破坏格式。

## 验收标准与实现方案

验收标准规定可观察结果，实现方案说明怎样产生它。例如，可以查询匹配记录后生成文件，也可以分批读取并逐步生成。数据量很小时，两种方式都可能合适；数据量很大时，还要比较内存占用与等待时间。

性能要求也应有使用条件。例如“在指定规模书目上导出一个分类，全部行应在规定时间内可下载”。这里需要同时确定记录规模、运行环境和允许时间，再进行测量。

## 验收用例

| 验收情形 | 需要检查的结果 |
| --- | --- |
| 一个分类有多本书 | 编号完整，行次序正确 |
| 某本书无库存 | 仍包含该记录 |
| 价格缺失 | 空字段，读回后能与零区分 |
| 标题含逗号或中文 | 文件读回后标题保持原值 |
| 分类没有记录 | 只有标题行 |
| 查询失败 | 告知导出失败，不提供一份貌似成功的空结果 |

预期结果来自业务约定和示例数据。实现者或 Agent 可以负责生成代码与测试，但测试中的期望值应独立于实现确定，否则代码即使按错误规则执行，也可能得到“全部通过”的结果。

## 练习

需求改为“只导出当前筛选结果”，页面还增加了价格门槛和排序选项。指出原验收标准中哪些仍适用、哪些需要修改，并用三条记录写出一份新预期结果。
