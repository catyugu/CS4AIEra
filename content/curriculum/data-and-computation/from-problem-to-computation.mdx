需求：「从一批测量记录里取出误差低于上限、参数匹配并且有效的那些，按误差从小到大排好；再能按记录标识查看其中任意一条的记录标识、参数、有效性与误差。」这句话没有说这批记录有多少条，也没有说这套条件一天会被问多少次、单条记录会被打开多少次。两位设计者读到同一句话，得到两份不同的方案：一位把它当成偶尔问一次的一次性筛选，每次都从头把记录列表看一遍；另一位担心记录会持续增加、条件会被反复问，于是把重点放在会反复发生的那件事上。两份方案都符合这段要求，处理的是两个不同的问题。

一段要求要能当成计算问题来讨论，得把几件事补齐：输入是什么、输出是什么、哪些条件必须成立、数据大概有多少、这些数据在使用期内会增长到多大，以及哪些操作会被反复执行、各执行多少次。漏掉其中一项，后面的选择就建立在一个未确认的假设上。

## 把要求写成输入、输出与条件

从这段话里读出的计算问题：

| | 内容 |
| --- | --- |
| 输入 | 一批测量记录，每条带记录标识、采样时间、参数、是否有效与误差；一次查询，带目标参数、有效性要求与误差上限 |
| 输出 | 命中的记录，按误差从小到大排列；按标识查看一条记录时给出它的标识、参数、有效性与误差 |
| 必须满足的条件 | 每条命中记录满足全部三个筛选条件；同一条记录不重复出现；排序覆盖全部命中项 |

要求里有两种读法没被定下来，各对应一个要补的条件。误差相同的两条记录谁在前——排序规则没有给出同分的处理。结果是全部命中项还是只取靠前的若干项——输出没有给出截断的位置。这两种情况在算完之前看起来像细节；只要记录里有误差相同的两条，或者命中的条数超过一次返回给出的条数，它们就决定输出的具体内容。

## 哪些操作会被反复执行

要求里能数出两类操作。一类是筛选：把每条记录依次对照参数、有效性与误差三个条件，留下命中的。另一类是按标识定位：打开一条记录时，用它的记录标识在列表里找到它。

两类操作的代价随它们各自发生多少次累积。筛选发生一次，就把每条记录看一遍。按标识从头查找，找列表里靠后的记录要先看过它前面的每一条——把每条记录各打开一次，定位的查看次数就是各条所在位置之和。同一批记录，筛选做一次和定位做很多次，得到的工作量完全不同。把这两类操作在同一批记录上各数一遍，再把记录换成更大的一批，查看次数分别变成多少？

```python run id="data-and-computation.from-problem-to-computation.work-counts"
base = [
    ("m-101", "2024-05-02", "gain 2", True,  0.012),
    ("m-102", "2024-05-02", "gain 4", True,  0.008),
    ("m-103", "2024-05-03", "gain 2", False, 0.310),
    ("m-104", "2024-05-03", "gain 2", True,  0.021),
    ("m-105", "2024-05-04", "gain 8", True,  0.004),
    ("m-106", "2024-05-04", "gain 4", True,  0.033),
]
more = [
    ("m-201", "2024-05-05", "gain 4", True,  0.006),
    ("m-202", "2024-05-05", "gain 2", True,  0.045),
    ("m-203", "2024-05-06", "gain 8", False, 0.290),
    ("m-204", "2024-05-06", "gain 4", True,  0.019),
    ("m-205", "2024-05-07", "gain 2", True,  0.012),
    ("m-206", "2024-05-07", "gain 8", True,  0.009),
]
limit = 0.02
wanted = "gain 2"

for label, records in (("records", base), ("records with 6 more", base + more)):
    open_ids = []
    for row in records:
        open_ids.append(row[0])

    examined = 0
    matched = 0
    for row in records:
        examined += 1
        if row[3] and row[2] == wanted and row[4] < limit:
            matched += 1

    looked_at = 0
    for want in open_ids:
        for row in records:
            looked_at += 1
            if row[0] == want:
                break

    print(label, "records", len(records), "filter examines", examined, "matches", matched)
    print(label, "locate each record once examines", looked_at)
```

筛选的查看次数等于记录条数：一次筛选会把每条记录看一遍。按标识定位的查看次数等于各条位置之和；找靠前的记录看得少，找靠后的记录要先看过它前面所有条。记录增多时两类计数都变大，定位的计数增长得更快，因为位置本身也在随条数变大。这段要求没有写筛选与定位各发生多少次，也没有写这批记录会停在哪个量级，所以这两个计数里哪一个会主导，还没有定。

## 数据规模与它在使用期内会增长到多大

首先要估的一项，是使用期末的条数。测量记录在使用期内只会增加——新的记录不断写入，旧记录很少删除——使用期末的条数大于今天的条数，查询发生的总次数也随使用时长累积。这两个数只要求量级和方向，不要求精确值：这批记录停在今天的量级，还是会增长几个数量级；条件是被问一次，还是每次请求都被问；完整内容是偶尔点开，还是每条记录每天都被打开。从当前条数和增长速度外推使用期末的条数，再把每一类操作在那段时间里会发生多少次估出来，就得到判断方案要用的两个数。方向不同，值得优先照顾的操作也不同。

记录很少、条件偶尔被问，两类操作的总量都小，按最简单的写法就够用。记录增长、定位被反复触发，按标识从头查找就从可忽略变成主导量。要求只给出「要有这个查询」，上面这些要么从服务的实际使用里读出来，要么向需求方问出来；不补齐它们，方案就在替需求方选一个他还没作出的决定。

## 哪些信息必须保留

一条记录身上带着很多字段，要求只用得到其中一部分。在这段要求里，记录标识、参数、有效性与误差都被读到：三个筛选条件读参数、有效性与误差，排序读误差，输出与按标识定位读记录标识。采样时间这类字段，没有一条输出或条件读它，删掉它不改变命中结果、排序，也不改变按标识查看时显示的那四个字段，也就不属于这个计算问题。要求一旦补上「误差相同时按采样时间早的排在前」，采样时间就从「可以不保留」变成「必须保留」——只有那一条排序规则读它，读不到，顺序就定不出来。

一项信息是否必须保留，看有没有一条输出或条件读它；筛选条件、排序规则、去重判等、打开记录时显示的字段都算读。没有一处读它的信息，删去不改变任何结果。信息「被要求」和「被读」是两回事：要求里提到一个字段，却没有一条输出或条件用它，它就不进入这个计算问题；换一条用到它的要求，它就要被保留。

## 练习

一份方案这样写：

> 每条查询都从头遍历记录列表，逐条比对参数、有效性与误差上限，把命中的记录按误差排好返回；打开某条记录的完整内容时，再从头遍历一遍找到它。记录不多，这样最简单。

这段话对要求做了哪些没被确认的假设？逐条指出，并说明要求要补上什么，才能判断这个方案是否成立。下面一段代码把方案里的两类操作各数了一遍。

```python run id="data-and-computation.from-problem-to-computation.exercise-scan-count"
records = []
for index in range(50):
    records.append((index, "gain 2" if index % 5 else "gain 4"))

requests = 20
scans = 0
for request in range(requests):
    for row in records:
        scans += 1

for opened in range(requests):
    for row in records:
        scans += 1
        if row[0] == opened:
            break

print("records", len(records), "requests", requests, "scans", scans)
```
