夜间报表在一批商品上做两件事：先把目录从头到尾过一遍，数出价格不超过上限、并且在库的商品；再给数出来的每一件补上它的类目——报表手里只有标识，于是又拿着标识从目录开头找起。目录 200 件时它很快返回；目录 400 件时它就慢了，慢出来的部分几乎全在给每件商品补类目那一步。数件数那次从头到尾的扫描，查看次数随件数按比例增长，件数翻倍就翻一倍；补类目那一段给每一件都从头找一遍，件数翻倍，它的查看次数涨到接近原来的四倍。

同一批商品，同样的翻倍，两段工作的放大方式不同。差别来自每一段工作随件数怎样重复；把它的查看次数数出来，就得到一条随件数变化的形状。知道形状，才能在件数再涨一个量级之前判断出先变贵的是哪一段、会不会到不可接受的地步。

## 一段程序里的三种形状

把这份目录放进一段程序，在三个规模上数一数三种做法的查看次数。每查看一件商品就是读它的一整行，行里有标识、价格、是否在库与类目。这里把每查看一件商品记作一次工作。件数就是这段工作的<Term id="input-size">输入规模</Term>。查看目录里任意位置的一件都记一次，位置越靠后并不更贵。

```python run id="data-and-computation.cost-shape.three-shapes"
catalogue = []
for index in range(400):
    catalogue.append(("p-" + str(index), 10.0 + index, index % 3 != 0, "cat-" + str(index % 5)))


def first_row_count(rows):
    row = rows[0]
    return 1


def full_scan_count(rows):
    inspected = 0
    for row in rows:
        inspected += 1
    return inspected


def locate_each_count(rows):
    inspected = 0
    for target in rows:
        for row in rows:
            inspected += 1
            if row[0] == target[0]:
                break
    return inspected


print("n first-row full-scan locate-each")
for n in (100, 200, 400):
    rows = catalogue[:n]
    print(n, first_row_count(rows), full_scan_count(rows), locate_each_count(rows))
```

三列随件数变化的方式不同。

第一列始终是 1。报表取目录的第一件读它的字段，无论目录是 100 件还是 400 件，都只看这一件。这是一段**固定不变**的工作：件数再多，它的计数不动。

第二列等于件数。从头到尾完整过一遍，看过的件数就是目录的长度；件数翻倍，查看次数翻倍。这是**与规模成正比**的工作：一段按件数等比例重复的查看。

第三列在件数翻倍时涨到接近四倍。每件商品都再从头找一遍自己，找第 $k$ 件要先看过它前面的每一件，给全部 $n$ 件各补一次类目，查看次数是

$$1 + 2 + \dots + n = \frac{n(n+1)}{2}.$$

件数从 $n$ 变成 $2n$，这个和从约 $n^2/2$ 变成约 $2n^2$，约是原来的四倍。这是**两层相乘**的工作：外层每一件都把内层整段重做一遍，件数既做了外层的次数、又做了内层的长度，两个因素乘在一起，放大时比成正比更快。

同样把件数翻倍，一段工作涨一倍、另一段涨到四倍，差别不在机器，在计数里出现了几次重复的相乘。

## 每次减半

目录若已经按价格从低到高排好，补类目可以换一种做法：不再从开头一件件找，而是每次取可能位置区间的中点那一件，和要查的价格比一下，把可能的位置缩到其中一半。区间每步砍掉一半，查看次数会随件数怎样变？

```python run id="data-and-computation.cost-shape.halving"
catalogue = []
for index in range(800):
    catalogue.append(("p-" + str(index), 10.0 + index, index % 3 != 0, "cat-" + str(index % 5)))


def bisect_count(rows, target):
    low = 0
    high = len(rows)
    looks = 0
    while low < high:
        middle = (low + high) // 2
        looks += 1
        if rows[middle][1] < target:
            low = middle + 1
        else:
            high = middle
    return looks


print("n middle-looks")
for n in (100, 200, 400, 800):
    rows = catalogue[:n]
    print(n, bisect_count(rows, rows[n - 1][1]))
```

件数从 100 增到 800，查看次数从 7 增到 10：件数每翻一倍，查看次数只多 1。区间每比较一次就减半，件数翻倍只是多切一刀。这是**每次减半**的工作：件数与查看次数之间隔着一次对折，件数翻很多倍，查看次数才缓缓增加几次；件数越大，它比从头走一遍省下的越多。

## 逐步分支

前面几种形状里，每一步只是把一段工作原样重复若干次。另一种写法的每一步都分成两个方向各继续一次，两边都要算到底。

枚举「每件在库商品放不放进这个优惠包」的所有取法就是这种写法：从只有一种空取法开始，每考虑一件商品，就把现有的每种取法各留一份、再各加一件商品，取法的份数每步翻一倍。

```python run id="data-and-computation.cost-shape.branching"
bundles = [()]
print("items bundles")
for index in range(16):
    grown = []
    for bundle in bundles:
        grown.append(bundle)
        grown.append(bundle + (index,))
    bundles = grown
    if index + 1 == 8 or index + 1 == 12 or index + 1 == 16:
        print(index + 1, len(bundles))
```

考虑的商品每多一件，保留下来的取法份数就翻一倍：8 件时是 256 份，16 件时是 65536 份。这是**逐步分支**的工作，它的增长比前面几种都快：多一件商品只是多加一层，份数却按层数翻倍，几层之间就从几百涨到几万。规模再往上加几层，计数冲出可运行的范围。

## 五种形状放在一起

把五种形状摆在同一把尺上，看同一段工作在件数翻倍时计数变成原来的几倍：

| 形状 | 一段这样的工作 | 件数翻倍时计数怎样变 |
| --- | --- | --- |
| 固定不变 | 读目录的第一件 | 不变 |
| 每次减半 | 每步把可能区间砍掉一半 | 多 1 次 |
| 与规模成正比 | 从头到尾过一遍 | 变成 2 倍 |
| 两层相乘 | 每一件都再对全部件做一遍 | 约变成 4 倍 |
| 逐步分支 | 每一步分成两个都继续 | 变成原来的平方 |

这张表用来给一段程序里的每个部分定位。一段工作落在哪一行，件数翻倍时它与其他部分的差距就朝哪个方向走：行越靠下，倍数越大，件数放大以后它越早盖过上面的部分。程序里同时有成正比和两层相乘的两段，件数只要足够大，两层相乘的那段就吃掉绝大部分查看次数；再往下一行是逐步分支，它会先于其他所有部分变得不可行。

两层相乘里的两层不必是同一个规模。让每件商品对照每个类目各检查一次，两层分别是件数与类目数，查看次数是两者的乘积；翻倍的是哪一层，计数就按那一层的倍数增长，两层同时翻倍则约变成四倍。看一段两层相乘的工作，要分别问清两层各自是什么、放大时哪一层在涨。

## 小规模上量一次能说明多少

一份实现给每件商品做四项检查再过滤，全部件数过一遍是每件 4 次；另一份实现按标识给每件商品补类目，是 $1 + 2 + \dots + n$ 次。把两者在几个规模上各数一遍：

```python run id="data-and-computation.cost-shape.small-sample"
def per_item_count(n):
    inspected = 0
    for index in range(n):
        inspected += 4
    return inspected


def locate_each_count(n):
    inspected = 0
    for target in range(n):
        for row in range(n):
            inspected += 1
            if row == target:
                break
    return inspected


print("n four-per-item locate-each")
for n in (4, 8, 12, 100):
    print(n, per_item_count(n), locate_each_count(n))
```

在 4 件商品上，两层相乘的那份查看次数比逐件检查的更少，只量这一个规模会得出它更快；件数过了 8，先后就反了过来；到 100 件，两层相乘已经比逐件检查多出一个数量级。小件数上谁多谁少由常数决定——每件固定做的几次检查、固定不变的那点工作在件数小时占的比例大，形状还来不及显出来。规模一大，形状接管：两层相乘迟早超过成正比。

一次测量只给出它测的那个规模上的一个比值，看不出这段工作是哪一种形状，因此定不出下一个规模上计数会变成几倍。逐步分支更极端：在一二十层上跑得动，多几层就停不下来，而在小深度上测到的那点计数看不出这件事。要判断放大以后的行为，看的是件数翻倍时计数变成原来的几倍，那个倍数就是形状本身。

## 练习

一份方案给每件商品对照每个类目各做一次检查，用来给商品打上覆盖到的类目标记。它附带的判断是：「件数翻倍时，这部分最多慢一倍。」这个判断在什么前提下成立，又在什么情况下失效？

一行判据：把件数与类目数分别翻倍、再一起翻倍，看计数各变成原来的几倍。

```python run id="data-and-computation.cost-shape.exercise"
def category_checks(n, c):
    checked = 0
    for row in range(n):
        for category in range(c):
            checked += 1
    return checked


print("items categories checks")
for n in (100, 200):
    for c in (5, 10):
        print(n, c, category_checks(n, c))
```

## 那份夜间报表里，风险落在哪一段

报表的两段各有自己的形状。数件数那段把目录从头到尾过一遍，是与规模成正比的工作；件数翻倍，它的查看次数翻倍。补类目那段给每一件都从目录开头再找一遍，是两层相乘的工作；件数翻倍，它接近原来的四倍。件数还小时两段的查看次数相差不大，件数一大，两层相乘那段按平方增长，很快占掉报表的绝大部分工作——风险在这里，不在那次从头到尾的扫描上。

判断这份报表放大以后还撑不撑得住，看的是两段各落在哪一行，以及件数翻倍时各自的查看次数变成原来的几倍。如果报表后面再加一段枚举商品取法的写法，它落在逐步分支那一行，件数一变就冲到前面两段之外，最先让报表停在可运行范围里。
