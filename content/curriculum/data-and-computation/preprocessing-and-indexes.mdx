一次参数扫描跑出 256 条结果记录，每条由一个运行标识与一段结果内容组成，程序按运行标识取出对应内容。同一个批次在一天里被按标识取用 200 次。

一个版本每次取用都从第一条看起，逐条比对标识，命中就停。另一个版本在第一次取用之前先按标识把整批记录排一次序，此后每次取用只在目标标识应当出现的那段边界附近找。排序要走过整批记录并做大量两两比较，这笔支出在第一次取用之前就付掉了；取用次数不够多时，它省下的工作盖不住自己的成本。值不值得先排序、或者另建一份按标识定位的结构，取决于取用的次数、每次原本要走过多少条记录，以及数据变化时这份结构还要付出什么。

## 有序把查找变成定位边界

没有次序的一批记录里，一次取用没有可以先排除的位置：除了逐条比对标识，程序拿不到「这一段不可能命中」的依据。目标排在最后一条、或者根本不在批次里时，全部记录都要走过一遍。

记录一旦按标识排好，每一条记录的标识就给出了一条分界：排在它前面的标识不超过它，排在它后面的标识不小于它。取用因此从逐条找相等变成定位边界——找出目标标识在次序里的位置。每次比对都能把可能的位置砍掉一半，取用只看边界附近的少数几条记录；目标不在批次里时，定位同样给出一个位置，它夹在两条相邻标识之间。

次序本身不减少查看。记录排好却仍然从头逐条比对时，每次取用要看的条数没有变化；省下查看的是用次序定位边界这一步。

同一条标识出现多次时（同一次运行被记了两行），定位给出的是一段区间，取用方要在这段区间里决定取哪一条。标识不在批次里时，逐条扫描必须走到最后一条才能判定缺失，边界定位仍然返回一个位置，调用方据此报告缺失。

## 一次排序换取多次查询

批记录 $n$ 条、取用 $q$ 次时，逐条扫描一边的总查看次数约是 $O(qn)$：每次取用各走一遍整批记录，$q$ 与 $n$ 相乘。先排序一边分成两段：排序那一次约 $O(n\log n)$，此后每次定位约 $O(\log n)$，$q$ 次合计约 $O(n\log n + q\log n)$。

排序一次比把记录完整过一遍贵得多：比较排序要把记录过好几层。要比较的是「一次排序加很多次较便宜的定位」与「每次取用都重新扫过全部记录」，排序那一次的成本靠后续取用的次数摊开。取用次数少时，先排序一边更贵；多过某个交叉点以后，它才低于逐条扫描。交叉点由 $n$ 与 $q$ 的关系决定：$n$ 条记录排序一次约花 $n\log n$，每次定位省下约 $n/2$ 次比对，两者相等时 $q$ 大致是 $\log n$ 的一个常数倍。$n$ 翻倍，排序只多一层、定位只多一次比对，所需的取用次数只挪动常数条，不与记录条数同比例增长。

在同一批 256 条记录上把两边的查看次数并排打印。逐条扫描一边的计数是实测的：每读一条记录记一次，命中之前或走到末尾之前都算。先排序一边的计数由两样相加：排序那一次按比较排序的量级 $n\log_2 n$ 记（$n$ 条记录要分 $\log_2 n$ 层，每层把记录过一遍），定位部分把每次比对写出来计数，标准库的 `bisect` 做的正是这次定位。取用的标识从一个固定列表里循环取用，既有存在的标识，也有不存在的。

```python run id="data-and-computation.preprocessing-and-indexes.counts"
def make_batch(size):
    batch = []
    for index in range(size):
        batch.append(("run-" + str((index * 97) % size), index))
    return batch


def scan_reads(batch, targets):
    reads = 0
    for target in targets:
        for record in batch:
            reads += 1
            if record[0] == target:
                break
    return reads


def locate_reads(ordered, targets):
    reads = 0
    for target in targets:
        low = 0
        high = len(ordered)
        while low < high:
            middle = (low + high) // 2
            reads += 1
            if ordered[middle][0] < target:
                low = middle + 1
            else:
                high = middle
    return reads


batch = make_batch(256)
ordered = sorted(batch)

rounds = 0
width = 1
while width < len(batch):
    width = width * 2
    rounds += 1
sort_once = len(batch) * rounds

queries = ["run-255", "run-0", "run-128", "run-100", "run-200", "run-99", "run-250", "run-300"]

print("queries rescan sorted")
for count in (1, 2, 4, 8, 16, 32, 64, 128, 200):
    targets = []
    for index in range(count):
        targets.append(queries[index % len(queries)])
    print(count, scan_reads(batch, targets), sort_once + locate_reads(ordered, targets))
```

先排序一边的排序成本按 $n\log_2 n$ 记：256 条记录分八层，每层把记录过一遍，约两千次查看；此后一次边界定位只比对八次左右，记录翻一倍也只是多切一刀。取用两次时，逐条扫描累计不到一百次，先排序一边停在两千次上下，排序的成本远没有摊开。取用涨到二十次上下，两边相等；再往上，逐条扫描一边每多一次取用就多走一遍整批记录，先排序一边只多一次定位。取用两百次时，逐条扫描累计约两万五千次，先排序一边约三千七百次，约为其七分之一。交叉点由记录条数与取用次数的关系决定：记录翻倍只让排序多一层、定位多一次比对，所需的取用次数只挪动常数条。

## 建索引：读更快，写更贵

按标识取内容还可以靠一份专门的索引：一张按标识直接给出位置或内容的表。建立它要读一遍整批记录、把每条登记进去，之后一次取用就是一次定位，不必走到边界附近。这类结构由成熟实现提供：`sorted` 给出有序序列，`bisect` 在有序序列上定位边界，`dict` 直接把标识映到内容。成熟实现已经处理了边界取法、键的比较规则与性能细节，不同写法在重复键与缺失键上的行为也已经固定，从零实现一遍没有收益。

建立的代价只在写的一侧。数据发生变化时索引必须跟着变：把一条记录插进排好的序列，它的位置未必在末尾，插入点之后的记录要逐条挪开；删掉一条，后面的记录同样要挪回来。改用按标识直接定位的表，插入只是登记一条，但数据更新时仍要同步写进去，这张表本身也占额外空间。读一侧因此变快，代价在写一侧与空间上；写多读少时，维护索引的开销可以超过它省下的取用次数。

排序与取用必须用同一套标识次序。两处用了不同的比较规则，定位出的位置就不是目标标识应在的位置，取用会拿到相邻的一条记录，或者把一条在批次里的记录报成缺失。主数据本身用序列、集合还是映射来组织，与是否需要这份额外索引是两件事（见 <CrossRef id="data-and-computation.representation-and-workload" />）。

## 练习

先排序再定位也可以写成每次取用之前重排一次，看起来同样利用了有序。两种写法都在同一批记录上做同一串定位：一种只排序一次，另一种每定位一次就重排一次。

```python run id="data-and-computation.preprocessing-and-indexes.exercise"
import bisect


def make_batch(size):
    batch = []
    for index in range(size):
        batch.append(("run-" + str((index * 97) % size), index))
    return batch


def sort_once_then_locate(batch, targets):
    ordered = sorted(batch)
    sorts = 1
    for target in targets:
        bisect.bisect_left(ordered, (target,))
    return sorts


def sort_before_each_lookup(batch, targets):
    sorts = 0
    for target in targets:
        ordered = sorted(batch)
        sorts += 1
        bisect.bisect_left(ordered, (target,))
    return sorts


batch = make_batch(64)
targets = ["run-5", "run-40", "run-63", "run-0", "run-300", "run-17"]

print("sort once, then locate:  ", sort_once_then_locate(batch, targets))
print("sort before each lookup: ", sort_before_each_lookup(batch, targets))
```
