取一份具体的从属关系：A 的下级是 B 与 C，B 的下级是 D 与 E，C 的下级是 F 与 G。把它画出来是一棵树：

```text
        A
      /   \
    B       C
   / \     / \
  D   E   F   G
```

A 没有上级，是这棵树的根（root）。一对上下级里，上方的是父节点（parent），下方的是子节点（child）：A 是 B 与 C 的父节点，B 是 A 的子节点。没有子节点的 D、E、F、G 是叶节点（leaf）。一个节点连同它下面的全部后代构成一棵子树（subtree）：B 与 D、E 是根为 B 的子树，C 与 F、G 是根为 C 的子树。从根到最远叶节点的边数是树的高度（height），这棵树的高度是 2。每个子节点连同它的后代又是一棵树，所以遍历、高度、节点数都写成递归定义——访问次数由节点数 $n$ 决定，递归所需的辅助空间与沿根到叶路径的操作还受高度 $h$ 控制。

## 树的定义

什么样的节点与父子关系才构成一棵树？下面四条共同回答这个问题；它们针对非空树，实现通常还允许一个「不含任何节点」的空树，作为单独状态：

1. 恰好一个根节点没有父节点；
2. 其余每个节点恰好有一个父节点；
3. 从根出发沿父到子的方向可以到达每个节点（连通）；
4. 不存在从节点出发经过若干子节点又回到自己的路径（无环）。

**子节点的次序是否属于定义**，决定了两种不同的抽象：**有序树**里兄弟之间有次序，遍历顺序是定义的一部分；**无序树**里兄弟之间没有次序，只有集合结构。二叉搜索树与二叉堆都使用左、右孩子位置有区别的有序二叉树结构。这里的「有序」只表示孩子的位置属于抽象结构，并不表示兄弟节点按照键值排好顺序；二叉搜索树的键序不变量与堆序不变量是另外的性质。

**深入阅读（四条性质的逻辑关系）**：这四条并不逻辑独立。在「恰好一个根节点没有父节点、其余每个节点恰有一个父节点、从根可以到达所有节点」都成立时，无环已经随之成立——任何从根进入的环都会使环的入口有两个父节点，或者使根本身有父节点。反过来，若不要求根可达所有节点，只保留「唯一根 + 非根唯一父」，则允许根所在的树之外再出现一个独立的有向环。对可变指针表示而言，把「无环」单独列出来仍然有用：一次错误的引用修改就可能破坏这项全局性质。

## 同一棵树的三种表示

同一棵树可以有多种表示，它们实现同一组操作，成本形态却不同：一个节点既可以是持有子节点引用的对象，也可以只是数组里一个由下标算术定位的槽位。**表示**指的是内部状态怎样保存。三种常见形态：

| 表示 | 内部状态 | 访问子节点 | 形状要求 | 就地修改 |
| --- | --- | --- | --- | --- |
| 指针节点 | 每个节点一个对象，持有子节点引用 | 跟随引用，常数成本 | 无 | 改引用即可 |
| 嵌套容器 | 元组或列表的嵌套，子节点是元素 | 索引元素，常数成本 | 无 | 元组不可变，列表可改 |
| 隐式二叉树数组布局 | 一个数组按位置存节点 | 下标算术，常数成本 | 任意二叉形状可用空洞表示；近完全时才紧凑 | 需按下标关系维护 |

这里讨论的数组布局特指**隐式二叉树数组布局**：一个数组按位置存节点，若一个节点位于下标 $i$，它存在的左、右孩子放在 $2i+1$ 与 $2i+2$。这套下标公式把抽象结构特化成了二叉树；指针节点与嵌套容器则可以自然表示任意数量的孩子。

不同表示对树不变量的保证程度也不同。可变指针节点不会自动阻止同一节点被两个父节点引用，也不会阻止某个孩子重新指向祖先，因此单父与无环必须由更新操作维护。纯粹由有限嵌套元组构成、并把每个出现位置视为一个节点的表示，会由嵌套结构本身给出唯一父位置并排除环；可变列表或共享对象仍可能重新引入别名和环。隐式数组布局中，每个下标 $i > 0$ 只有唯一的候选父下标 $(i-1) // 2$，而且父下标严格小于子下标，因此结构上不可能形成环；连通性还要求每个已占用位置的祖先位置都已占用。指针表示本身并不要求节点可变，不可变树也可以通过路径复制产生新树。

Python 没有内置的树类型，常见写法包括对象加引用、嵌套容器，以及用数组保存近完全二叉树；`heapq` 使用的正是后一种隐式下标关系。Python 的 `dict` 保证的是插入顺序，不是按键排序；需要按键序执行查找、前驱、后继或区间遍历时，需要另外维护具有键序不变量的数据结构。二叉搜索树就是有序映射的一种表示（见 <CrossRef id="algorithms.ordered-maps" />）。

## 遍历与递归结构

遍历顺序由「什么时候访问节点」相对「什么时候进入子节点」决定。对有序树，前序、后序和层序会给出确定的线性序列；对无序树，兄弟之间的相对次序不属于定义，因此遍历结果不唯一。二叉树还定义了中序遍历；它与二叉搜索树的键序直接相关（见 <CrossRef id="algorithms.ordered-maps" />）：

- 前序：先访问节点，再依次遍历每棵子树。
- 后序：先依次遍历每棵子树，再访问节点。
- 广度优先（层序）：按层从上到下、层内从左到右访问，它不用递归，用队列。

**覆盖与不重复不变量**：一次完整遍历应当使每个节点恰好被访问一次，因此总访问次数必然等于节点数 $n$。但反过来，总次数等于 $n$ 并不能证明遍历正确——完全可能漏掉一个节点，同时重复访问另一个节点。即使已经证明每个节点恰好一次，这也仍然只是遍历正确性的必要条件；前序、后序和层序还分别需要满足自己的次序约束。

```python run id="alg.trees.representations"
class Node:
    """Pointer representation: one object per node, children in a list."""

    def __init__(self, name, children=()):
        self.name = name
        self.children = list(children)


def preorder(node, visits=None):
    """Postcondition: this node's name, then each child's preorder, in order."""
    visits = visits if visits is not None else []
    visits.append(node.name)
    for child in node.children:
        preorder(child, visits)
    return visits


root = Node("A", [Node("B", [Node("D"), Node("E")]), Node("C", [Node("F"), Node("G")])])
visits = preorder(root)
print("preorder:", visits)
print("nodes visited:", len(visits))
```

在这棵七个节点的树上，前序序列是 `['A', 'B', 'D', 'E', 'C', 'F', 'G']`，每个节点恰好访问一次，所以访问次数等于节点数 $n = 7$。序列完全由「先访问节点、再依次进入子树」这条规则决定；同一组节点与父子关系换一种表示来保存，只改变访问孩子与存储节点的成本，不改变这条序列。

## 形状决定成本

树的高度定义为最长的根到叶路径长度（按边计，叶节点高度为 0）。高度同时决定两件事：递归遍历的调用深度，以及在有序结构上做按键查找时需要跟随的引用数。节点数相同、形状不同，高度可以差出数量级。

```python run id="alg.trees.height"
class Node:
    def __init__(self, key, left=None, right=None):
        self.key = key
        self.left = left
        self.right = right


def build_balanced(keys):
    """Precondition: keys is sorted ascending."""
    if not keys:
        return None
    middle = len(keys) // 2
    return Node(keys[middle], build_balanced(keys[:middle]), build_balanced(keys[middle + 1:]))


def build_chain(keys):
    """The right chain that inserting keys in ascending order produces."""
    root = None
    for key in reversed(keys):
        root = Node(key, None, root)
    return root


def measure(node):
    """Postcondition: (node count, height in edges); an empty tree has height -1."""
    if node is None:
        return 0, -1
    left_count, left_height = measure(node.left)
    right_count, right_height = measure(node.right)
    return 1 + left_count + right_count, 1 + max(left_height, right_height)


keys = list(range(500))
for label, root in (("balanced", build_balanced(keys)), ("ascending chain", build_chain(keys))):
    nodes, height = measure(root)
    print(label, "nodes =", nodes, "height =", height)
```

同一批 500 个键，平衡形状的高度是 8，升序插入得到的右链高度是 499，而 8 已经是 500 个节点下可能的最小高度。递归度量沿最深路径的调用深度与高度同阶，因此辅助栈空间是 $\Theta(h)$。随着 $h$ 继续增大，这类递归实现最终会受到 Python 递归深度限制（见 <CrossRef id="algorithms.recursion" />）。

高度还控制沿根到叶路径执行的操作：例如二叉搜索树查找一个键时，比较次数至多与 $h+1$ 同阶。所以「树的操作多快」由形状与平衡保证决定。

以节点数 $n$ 为规模、高度 $h$ 为形状参数：完整遍历访问每个节点恰好一次，因此时间为 $\Theta(n)$，与形状无关；递归深度优先遍历另需 $\Theta(h)$ 辅助栈空间。在二叉搜索树中，查找、插入等沿一条根到叶路径执行的操作成本为 $\Theta(h)$。未经平衡约束时 $h$ 最坏可以达到 $\Theta(n)$；具有平衡保证时才有 $h = \Theta(\log n)$，从而得到相应的对数时间保证。因此不能笼统地说「树的操作是对数时间」，必须同时说明操作类型与高度保证。空间上节点数是 $\Theta(n)$，每节点的额外开销由表示决定：指针节点至少多一个子引用结构，字典支撑的实例还要一份实例字典，数组布局则是每槽一个引用加可能的空洞。
