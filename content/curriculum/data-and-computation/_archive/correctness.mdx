从整数列表里挑出最大的元素，小到可以一口气写完：

```python run id="alg.correctness.counterexample"
def maximum(values):
    """Return the largest element of a non-empty list."""
    best = values[0]
    i = 1
    while i < len(values):
        if values[i] > best:
            best = values[i]
        i += 1
    return best


print(maximum([-3, -1, -2]))
```

扫描维护一个已比较前缀中的最大值，初值取列表首元素。把 `best = values[0]` 误写成 `best = 0`，同一个输入 `[-3, -1, -2]` 会返回 `0`——`0` 不在输入列表里，输出却看不出任何异常。`[-3, -1, -2]` 这一个合法输入就推翻了「这段实现对所有输入都返回最大值」。一个反例足以推翻一条全称主张；反过来，跑通再多输入也只是没发现问题，有限测试不能证明所有输入都正确。判断一段代码「对」还是「错」，要先把「对」写成一条可以判定真假的命题，再让论证把它接上实现。

## 把「对不对」写成规约

写下这条命题，就是在写这段代码的 <Term id="specification">规约</Term>：<Term id="precondition">前置条件</Term>界定允许执行开始时的状态，由调用方负责满足；<Term id="postcondition">后置条件</Term>界定执行结束后必须成立的性质，可以关联初始状态、最终状态与返回值。

取最大值的规约可以写得更精确。设输入列表为 $v$、返回值为 $r$：前置条件是 $v$ 非空，且元素来自同一个全序集合；后置条件有两句：

$$r \in v, \qquad \forall x \in v,\ x \le r.$$

第一句要求返回值来自输入，第二句要求它不小于输入中的每个元素。两句缺一不可——只写第二句，会放过一个根本不在列表里的返回值，`best = 0` 的反例正是这么失败的。前置条件要覆盖实现实际用到的操作：这一族实现在比较元素，所以除了非空，还要求元素两两可比；`[1, "x"]` 非空却无法比较。

## 循环不变量

**循环不变量**是在**循环头**——每次检查循环条件之前——都成立的性质。这个位置既包括第一次检查，也包括最后一次条件为假、循环即将退出时的检查。它对循环体的要求是：若循环头满足不变量且循环条件为真，则执行一次循环体后，回到下一次循环头时不变量仍然成立。

## 用不变量论证扫描

论证一个循环满足后置条件分三步。设 $P$ 是前置条件，$B$ 是循环条件，$Q$ 是后置条件，$I$ 是候选不变量：

1. **初始化**：从满足 $P$ 的状态执行循环之前的初始化代码，第一次到达循环头时 $I$ 成立。
2. **保持**：若循环头满足 $I$ 且 $B$ 为真，执行一次循环体之后，回到下一次循环头时 $I$ 仍然成立。这一步必须用循环体的代码说话。
3. **退出**：循环条件为假时，$I$ 与 $\neg B$ 一起推出 $Q$。

要论证扫描对每个满足前置条件的输入都给出正确答案，先写下循环头处必须成立的性质。把 $i$ 记为本轮开始时已经比较过的元素个数，候选不变量是：

- `1 <= i <= len(values)`
- `best == max(values[:i])`

第一条把 $i$ 限制在合法范围里，第二条把 `best` 钉死在已比较前缀的最大值上。它比「返回值是最大值」更强：后者只描述终态，在循环中途无从检查，也无法被循环体逐轮重建。

对输入 `[3, 1, 4, 2]` 把每次循环头处的状态写成一张表：

| `i` | 已比较前缀 | `best` |
| ---: | --- | ---: |
| 1 | `[3]` | 3 |
| 2 | `[3, 1]` | 3 |
| 3 | `[3, 1, 4]` | 4 |
| 4 | `[3, 1, 4, 2]` | 4 |

每一行的 `best` 都是同一行前缀的最大值：处理到 `[3]` 时是 `3`，到 `[3, 1]` 时仍是 `3`，到 `[3, 1, 4]` 时是 `4`，整个列表处理完也是 `4`。把这条观察写成一般式，就是候选不变量的第二条；循环体把前缀扩大一格，同时把 `best` 更新到新的前缀最大值。轨迹检查只在它执行过的输入上成立，不构成一般性的证明。

一般的证明要交代三件事。

**初始化**：循环开始前 `best = values[0]`、$i = 1$，需要 `best == max(values[:1])`。单元素前缀的最大值就是那个元素本身。这一步用到的假设是前置条件里的「列表非空」：`values[0]` 才有定义。

**保持**：假设本次循环头满足 $I$ 且循环条件为真（$i \lt n$）。循环体只做两件事：当 `values[i]` 大于 `best` 时把 `best` 换成 `values[i]`，然后把 $i$ 加一。回到下一个循环头时 $i$ 变成 $i+1$。新的 `best` 是上一轮 `best` 与 `values[i]` 中较大的一个；由 `best == max(values[:i])`，它等于 `max(values[:i+1])`。这一步用到的假设是元素两两可比，`values[i] > best` 这个条件才总能选出较大者。

**退出**：循环条件为假时 $i \ge n$，与 $I$ 中的 $i \le n$ 合起来得到 $i = n$，于是 `best == max(values[:n]) == max(values)`。返回值属于输入列表由赋值来源推出：`best` 要么是 `values[0]`，要么在循环体里被赋成某个 `values[k]`，一定是输入中的一个元素。后置条件的两条都满足。

初始化与退出各只需一句话；需要论证的是保持这一步，它必须用循环体的代码说话。整段证明用到的假设正是前置条件给出的两条：初始化用到「列表非空」，`values[0]` 才有定义；保持用到「元素两两可比」，`values[i] > best` 才总能选出较大者。

## 终止

循环不变量的三步证明：循环一旦结束，结果就满足后置条件。它没有说循环会不会结束；正确性还要求**终止**——对每个满足前置条件的输入，循环都在有限步内结束。

找最大值的扫描把 $i$ 从 $1$ 推到 $n$，尚未处理的元素个数 $V = n - i$ 始终是非负整数，并且每轮严格减少 1，所以循环不可能无限执行，一定在有限轮内触底于 $0$。

终止是一条对所有输入成立的主张，观测只覆盖跑过的那些输入，「跑一会儿看会不会停」回答不了它。忘记推进的循环没有可用的下降度量：循环体若从不改变 `index`，`while index < len(values)` 就永远为真，终止主张不成立。
