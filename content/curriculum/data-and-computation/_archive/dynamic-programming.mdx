给定一列数 $[4, 10, 3, 1, 5]$，从中挑出若干个数，要求任意两个被挑出的数在原序列里都不相邻，问挑出的数的总和最大是多少。挑走第 2 个数 10 之后，它左右两侧的 4 与 3 就都不能再挑：一个选择会封锁它相邻的两个位置。

决定落在最后一个数上。第 5 个数有两种处境：不挑它，答案来自前 4 个数的最优选择；挑它，第 4 个数被封锁，答案来自前 3 个数的最优选择再加上 5。两条分支的优劣取决于具体的数，都得算。把「前 $i$ 个数里能挑到的最大总和」记作 $F(i)$，第 5 个数上的分叉写成

$$F(5) = \max\bigl(F(4),\ F(3) + a_5\bigr).$$

同一个写法对每个下标都成立：

$$F(i) = \max\bigl(F(i-1),\ F(i-2) + a_i\bigr).$$

$F(i-1)$ 覆盖不挑第 $i$ 个数的全部情形，$F(i-2) + a_i$ 覆盖挑它的全部情形，两者合起来穷尽了第 $i$ 个数上的两种处境。$F(0) = 0$、$F(1) = a_1$ 是这条递推式的两个基本情形。

| 项 | 内容 |
| --- | --- |
| 输入 | 一列数 $a_1, \dots, a_n$，$a_i \ge 0$，$n \ge 0$ |
| 可行 | 任意两个被挑出的下标都不相邻的子集 |
| 输出 | 可行子集里元素和的最大值 |

$a_i \ge 0$ 保证空集不会比非空可行子集更好；允许负数时基本情形要改成 $F(1) = \max(0, a_1)$。

## 同一个子问题被反复求解

把递推式直接当作递归展开，$F(5)$ 长出两棵子树：

```text
F(5)
├─ 不挑第 5 个 → F(4)
│  ├─ 不挑第 4 个 → F(3)
│  └─ 挑第 4 个   → F(2) + a_4
└─ 挑第 5 个   → F(3) + a_5
   ├─ 不挑第 3 个 → F(2)
   └─ 挑第 3 个   → F(1) + a_3
```

$F(2)$ 在两棵子树里各出现一次：一条路径是「不挑第 5 个、挑第 4 个」走到的，另一条是「挑第 5 个、不挑第 3 个」走到的。两条不同的选择历史落在同一个剩余问题上，它下面的整棵子树因此要原样算两遍；继续展开，重复还会成倍增加。

把算过的情形记下来就能去掉这些重复。存下来的「前 $i$ 个数的最优值」称为一个**状态**，状态的值是这一类子问题的答案；再次遇到同一个状态时直接取用，这一步称为<Term id="memoization">记忆化</Term>。多条路径汇合到同一批状态，是重叠子问题（overlapping subproblems）的形状（<CrossRef id="algorithms.divide-and-conquer" />）。

## 记忆化：一个状态只算一次

显式写出来是一张字典，状态作键、算出的值作值。

```python run id="alg.dp.memo-nonadjacent"
values = [4, 10, 3, 1, 5]
memo = {}


def best(i):
    """Best total from the first i values, no two chosen adjacent."""
    if i <= 0:
        return 0
    if i in memo:
        return memo[i]
    answer = max(best(i - 1), best(i - 2) + values[i - 1])
    memo[i] = answer
    return answer


print("best total:", best(len(values)))
for i in range(len(values) + 1):
    print(f"{i:>2} {memo.get(i, 0)}")
```

`best` 先查 `memo`，命中就直接返回，未命中才递归下去并把结果写回，所以每个下标只进入函数体一次。打印出的下标到最优值这一列就是状态表，一共 $n + 1$ 个状态。朴素递归在同一份输入上按 $F(i)$ 分出两支，调用数随 $n$ 指数增长；每个状态只算一次之后，调用数降到状态数那一档。

标准库里的 [functools.cache](https://docs.python.org/3/library/functools.html#functools.cache) 维护同一种映射：把参数当作键、返回值当作值，命中时不再进入函数体。手写字典在需要直接查看表里存了什么时更直接。

## 第二个问题：网格路径计数

一个 $3 \times 3$ 的格子，从左上的 `S` 走到右下的 `T`，每步只能向右或向下，中间的 `#` 是障碍不能经过，问共有多少条路径：

```text
S . .
. # .
. . T
```

把「从左上角走到 $(r, c)$ 的路径数」记作 $ways(r, c)$。每一条这样的路径，最后一步只能来自上方 $(r-1, c)$ 或左方 $(r, c-1)$；这两个来源的路径集合不相交，合起来就是全部，于是

$$ways(r, c) = ways(r-1, c) + ways(r, c-1),$$

障碍格的值为 0，起点为 1。单元格里第 0 行与第 0 列留作空边界，值都是 0，第一行与第一列的格子因此各自只有一个来源。

```python run id="alg.dp.grid-paths"
grid = ["...", ".#.", "..."]

rows, cols = len(grid), len(grid[0])
ways = [[0] * (cols + 1) for _ in range(rows + 1)]
for r in range(1, rows + 1):
    for c in range(1, cols + 1):
        if grid[r - 1][c - 1] == "#":
            ways[r][c] = 0
        elif r == 1 and c == 1:
            ways[r][c] = 1
        else:
            ways[r][c] = ways[r - 1][c] + ways[r][c - 1]

for r in range(1, rows + 1):
    print(" ".join(f"{ways[r][c]:>2}" for c in range(1, cols + 1)))
```

障碍把中间的通道切断，只有贴着上边和贴着左边绕过去的两条路径能到终点，右下角的值是 2。

两个例子放在一起看，共同点不在 $\max$ 上：$F$ 取两个候选里较大的一个，$ways$ 把两个候选相加，当前状态的答案都由一批更小状态的答案组合出来。组合方式由问题要求什么决定——最大、最小、求和、计数都可以；状态的值一旦定下就只算一次这条性质不受它的影响。

## 多一个约束就多一维：0/1 背包

最大不相邻和只用 $i$ 一个数就描述完了剩余问题：知道处理到第几个数，剩下的问题就确定了。换成 0/1 背包就不够。背包给出一组物品 $(w_i, v_i)$ 与一个容量 $W$，每件物品至多取一次，问总重量不超过 $W$ 时总价值最大是多少。

处理到第 $i$ 件时，剩余问题还取决于前面取走的物品占掉了多少容量：两段历史都走到第 $i$ 件，一段还剩 4 个单位的容量，另一段只剩 0，它们接下来能装下的东西不一样。$i$ 决定还剩哪些物品可选，剩余容量决定还能装下什么，两者都是必要信息。把「前 $i$ 件、剩余容量 $c$ 的最大总价值」记作 $best(i, c)$，第 $i$ 件上仍然只有取与不取：

$$best(i, c) = \max\bigl(best(i-1, c),\ best(i-1, c - w_i) + v_i\bigr), \quad w_i \le c ;$$

$w_i > c$ 时第 $i$ 件装不下，$best(i, c) = best(i-1, c)$；$best(0, c) = 0$。

```python run id="alg.dp.knapsack-memo"
items = [(5, 6), (4, 7), (3, 5), (3, 4)]
capacity = 7
memo = {}


def best(i, c):
    """Best value from the first i items with c capacity left."""
    if i == 0:
        return 0
    if (i, c) in memo:
        return memo[(i, c)]
    weight, value = items[i - 1]
    answer = best(i - 1, c)
    if weight <= c:
        answer = max(answer, best(i - 1, c - weight) + value)
    memo[(i, c)] = answer
    return answer


print("best value:", best(len(items), capacity))
print("states stored:", len(memo), "of", (len(items) + 1) * (capacity + 1))
```

状态是两个下标的组合 $(i, c)$，总数是 $(n+1)(W+1)$；记忆化只在被触及的状态上花时间，输出里的两个数是这次运行存下的状态数与这个上界。容量加一倍、物品多一件，上界都会成倍变化，而实际存下的状态数由输入的具体数值决定。

## 从递归树到状态图

到这里可以写出这三个例子共用的一笔账。记实际求值的状态数为 $S$、每个状态检查的转移次数为 $T$，以「检查一个转移」为计数单位，填出全部答案的工作量约是

$$\text{工作量} \approx S \times T.$$

朴素递归的调用数由递归树给出；两条分支在同一状态汇合时，汇合点下面的整棵子树被折叠成一个状态，递归树上的节点数就被压到状态数那一档，多出来的调用全部消失。

```text
递归树 ──▶ 重复子问题 ──▶ 状态 ──▶ 递推
                                    ├─▶ 自顶向下：递归 + 记忆化
                                    └─▶ 自底向上：按依赖顺序求值
```

自顶向下的记忆化在遇到没算过的状态时才递归下去。同一张表也可以从最小的状态开始，按依赖方向逐格填出，两种方式折叠的是同一批重复。
