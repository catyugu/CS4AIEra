一批互不相同的键里要回答两个问题之一：排序后位于某个下标的元素是谁，或者最小的若干个是哪些。完整排序能同时给出两者，代价是确定全部元素的最终位置，而每个答案只用得到结果里的一两个位置。能不能跳过其余位置，只做确定答案所必需的比较？可随机访问的数组和只能从头读一遍的流是两种访问条件，同一个问题在两者上要用不同的做法。

## 第 k 个元素：一次分区，只递归一侧

秩 $r$ 的顺序统计量（order statistic）是完整排序后位于下标 $r$ 的那个元素，$0 \le r < n$。问题的答案就是位置 $r$ 上的这一个元素；其余 $n - 1$ 个元素彼此之间的次序可以任意。

quickselect 复用 <CrossRef id="algorithms.quicksort" /> 的分区：一次分区把区间按主元（pivot）分成两段，让主元落在它的最终位置 $p$。目标秩小于 $p$ 时答案只在左段，大于 $p$ 时只在右段，相等就直接返回；无论走哪一边，另一侧连同主元一起被排除，此后不再参与任何比较。

它维持的循环不变量是：目标秩始终位于当前区间 $[low, high]$ 内，已经排除在左侧的元素都不大于候选区间里的元素，已经排除在右侧的元素都不小于候选区间里的元素。第一条保证目标还在区间里，后两条保证被丢掉的部分里没有更小的候选：

```python run id="alg.ordering.quickselect"
from random import Random


def partition(items, low, high):
    """Postcondition: returns the pivot index p with items[low..p) < pivot <= items[p..high]."""
    pivot, boundary = items[high], low
    for j in range(low, high):
        if items[j] < pivot:
            items[boundary], items[j] = items[j], items[boundary]
            boundary += 1
    items[boundary], items[high] = items[high], items[boundary]
    return boundary


def quickselect(items, low, high, rank, rng, stats):
    """Postcondition: returns the element that would sit at index rank after sorting."""
    if low == high:
        return items[low]
    index = rng.randrange(low, high + 1)
    items[index], items[high] = items[high], items[index]
    position = partition(items, low, high)
    stats["partitions"] += 1
    stats["scanned"] += high - low + 1
    if position == rank:
        return items[position]
    if rank < position:
        low, high = low, position - 1
    else:
        low, high = position + 1, high
    stats["widest"] = max(stats["widest"], high - low + 1)
    return quickselect(items, low, high, rank, rng, stats)


size, rank = 4096, 16
case = list(range(size))
Random(20261040).shuffle(case)
stats = {"partitions": 0, "widest": 0, "scanned": 0}
value = quickselect(case, 0, size - 1, rank, Random(20261040), stats)
print("partitions", stats["partitions"], "| widest candidate interval", stats["widest"], "| elements scanned", stats["scanned"])
print("rank", rank, "->", value, "| matches a full sort:", value == sorted(case)[rank])
```

摘要里的三项计数——分区次数、候选区间曾达到的最大宽度、被扫描的元素总数——合在一起说明区间在按比例收缩：各轮排除的元素合计 $n - 1$ 个，扫描总数与 $n$ 同阶。打印出的值与完整排序中同一秩的元素一致。

随机主元的秩在当前区间里均匀分布，落在中间一半（约 $m/4$ 到 $3m/4$）的概率不低于 $1/2$；一旦如此，区间长度降到至多 $3m/4$。等到一次这样的成功，轮数期望不超过 2，每轮成本不超过 $m$ 次比较，把区间收到 $3m/4$ 的期望成本是 $O(m)$。总期望成本因此是公比为 $3/4$ 的几何级数：

$$
O\left(m + \frac{3}{4} m + \left(\frac{3}{4}\right)^2 m + \cdots\right) = O(m).
$$

推导用到的是「目标秩落在当前区间内」这一条；随机主元对每个固定秩给出同样的分布，所以找最小值、找中位数与找第 $n - 1$ 个的期望成本都是 $O(n)$。

**边界**：上面的期望界要求键两两不同。二路 `<` / `>=` 分区把与主元相等的键全部归到同一侧，重复键占多数时该侧几乎不缩小，期望界失效——随机主元改变不了这一点。最坏情形仍是 $\Theta(n^2)$：主元每轮落在区间端点时，区间每轮只缩小一个元素；随机化把这种输入压成低概率事件，单次运行的上界不变。单侧递归的栈深度等于轮数，期望 $O(\log n)$，最坏 $O(n)$。

## 前 k 个元素：一个有界堆

「取前 $k$ 个」有两种后置条件：返回恰好 $k$ 个最小元素，重复元素各占一个名额，这 $k$ 个之间的次序任意；或者把它们按非降序给出。第二种在第一种之上多做一次对这 $k$ 个元素的排序。

输入只能单遍读取、也不该整份保留时，用一个最大堆装当前见过的 $k$ 个最小元素，堆顶是缓冲里的最大值。新元素先与堆顶比较一次：更小就替换堆顶，否则直接丢弃。缓冲大小因此始终不超过 $k$，堆顶是当前已见元素里第 $k$ 小的门槛值。

```python run id="alg.ordering.streaming-top-k"
import heapq


def keys(count, seed):
    """The same deterministic key stream on every run, produced one value at a time."""
    state = seed
    for _ in range(count):
        state = (1103515245 * state + 12345) % 2147483648
        yield state % 100000


def stream_top_k(stream, k):
    """One pass; returns the k smallest values in order and the largest heap size reached."""
    heap = []                                    # max-heap of negatives, size <= k
    peak = 0
    for value in stream:
        if len(heap) < k:
            heapq.heappush(heap, -value)
        elif value < -heap[0]:
            heapq.heapreplace(heap, -value)
        peak = max(peak, len(heap))
    return sorted(-value for value in heap), peak


count, k = 50000, 8
result, peak = stream_top_k(keys(count, 20261040), k)
print("peak heap size", peak, "of k =", k)
print("k smallest:", result)
print("matches a full sort of the same stream:", result == sorted(keys(count, 20261040))[:k])
```

摘要给出的堆峰值等于 $k$：堆填满之后一直保持 $k$ 个元素，整条键流被遍历一次。取出的 $k$ 个值与整条流排序后的前 $k$ 个一致。

前 $k$ 个元素用于建立缓冲，每个花 $O(\log(k + 1))$；此后每个元素做一次常数时间的门槛比较，通过门槛的才触发一次 $O(\log(k + 1))$ 的堆替换。若替换发生 $r$ 次，总时间是 $O(k \log(k + 1) + (n - k) + r \log(k + 1))$，最坏 $O(n \log(k + 1))$，空间恒为 $\Theta(k)$。要按非降序给出这 $k$ 个元素，再对缓冲排一次序，附加 $O(k \log k)$。

Python 的 `heapq.nsmallest()` 与 `heapq.nlargest()` 返回已排序的前 $k$ 个结果；[Sorting HOWTO](https://docs.python.org/3/howto/sorting.html) 把它们描述为单遍处理输入、同时只保留所需数量元素的部分排序工具。`heapq` 的公开契约是返回结果；用大小受 $k$ 限制的堆还是退回完整排序，由实现选择。

## 需要保存的结果与成本

把每个任务必须保存下来的结果大小写清楚，成本就跟着出来：

| 需求 | 需要保存的结果 | 典型成本 |
| --- | --- | --- |
| 第 $k$ 个元素 | 一个值 | 期望 $O(n)$ |
| 无序 Top-K | $k$ 个值 | $O(n \log k)$ |
| 已排序 Top-K | $k$ 个有序值 | $O(n \log k + k \log k)$ |
| 完整排序 | $n$ 个有序值 | $O(n \log n)$ |

只确定一个位置的任务，每轮把候选区间按常数比例期望缩小，期望 $O(n)$；保存最小的 $k$ 个，每个元素最多付一次缓冲更新，$O(n \log k)$，要求它们有序再付一次 $O(k \log k)$ 排序。完整排序要让全部 $n$ 个元素进入输出顺序，基于比较的排序在最坏输入上需要 $\Omega(n \log n)$ 次比较，归并与堆排序以 $\Theta(n \log n)$ 达到这个阶。

把 $\log k$ 写成 $\log(k + 1)$ 让 $k = 1$ 也严格成立，$k \ge 2$ 时简写成 $O(n \log k)$。$k = n$ 时已排序 Top-K 就是完整排序，成本与表里最后一行的 $O(n \log n)$ 重合。

表里的比值以一趟线性扫描为单位，随 $n$ 与 $k$ 的取值变化。

```python run id="alg.ordering.three-contracts"
from math import log2

print(f"{'n':>10} {'k':>8} {'top-k / k-th':>14} {'sorted top-k / k-th':>21} {'full sort / k-th':>18}")
for n, k in ((2**20, 2**3), (2**20, 2**10), (2**20, 2**17), (2**16, 2**3), (2**24, 2**3)):
    print(f"{n:>10} {k:>8} {log2(k):>14.1f} {log2(k) + k * log2(k) / n:>21.1f} {log2(n):>18.1f}")
```

表里可以读出三件事：无序 Top-K 相对第 $k$ 个元素的倍数是 $\log_2 k$；完整排序的倍数是 $\log_2 n$；已排序 Top-K 的倍数在 $k$ 小时与无序 Top-K 几乎相同，在 $k$ 接近 $n$ 时被 $k \log_2 k$ 抬到接近完整排序。

表里列出的成本都是上界：要求部分顺序时存在比完整排序更便宜的算法。完整排序的 $\Omega(n \log n)$ 比较下界与「找最小至少 $n - 1$ 次比较」都在 <CrossRef id="algorithms.lower-bounds" /> 中证明。
