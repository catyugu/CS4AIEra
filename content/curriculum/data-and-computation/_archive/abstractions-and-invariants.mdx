在序列的头部插入一个元素，连续存放的版本把已有的每个元素依次后移一位，链式存放的版本新建一个结点、改一条引用。两种情况调用方读到的序列完全相同，花掉的工作量却不同。

```python run id="alg.adt.head-insert-cost"
def array_insert_front(slots, value):
    slots.append(None)
    moves = 0
    for position in range(len(slots) - 1, 0, -1):
        slots[position] = slots[position - 1]
        moves += 1
    slots[0] = value
    return moves


# Node repeats in the indexed-read cell; cells share no state.
class Node:
    def __init__(self, value, next=None):
        self.value, self.next = value, next


def chain_insert_front(head, value):
    return Node(value, head), 1


print("n", "array moves", "chain writes")
for n in (100, 200, 400):
    _, writes = chain_insert_front(None, -1)
    moves = array_insert_front(list(range(n)), -1)
    print(n, moves, writes)
```

头部插入在连续槽位上移动全部已有元素，移动次数等于元素个数；在链式结点上新建一个结点、只写一条引用，写入次数不随元素个数变化。

```python run id="alg.adt.index-read-cost"
# Node repeats in the head-insert cell; cells share no state.
class Node:
    def __init__(self, value, next=None):
        self.value, self.next = value, next


def array_get(slots, index):
    return slots[index], 0


def chain_get(head, index):
    hops = 0
    while hops < index:
        head, hops = head.next, hops + 1
    return head.value, hops


head = Node(0, Node(1, Node(2, Node(3, Node(4, Node(5))))))
slots = list(range(6))
print("index", "array visits", "chain hops")
for index in (0, 2, 5):
    _, visits = array_get(slots, index)
    _, hops = chain_get(head, index)
    print(index, visits, hops)
```

按下标读取时，连续槽位一次取到元素，不碰其他元素；链式结点要走下标那么多步引用，跳数随下标增长。两种存放各自给出自己那条序列，逐项相等，调用方从返回值读不出用的是哪一种存放。序列接口规定的是按位置读取、追加、插入、删除四种动作与它们的结果（见 <CrossRef id="algorithms.arrays-and-lists" />）；元素放在哪里、每种动作花多少工作量，由存放方式给出，也就是由**表示**给出。同一接口因此允许代价不同的多种表示。

## 表示不变量

链式存放要让追加保持在一次引用改写上，就得随时握住最后一个结点；下面这份实现额外存了一个尾引用 `_tail`。尾引用与结点之间有一条必须成立的关系：它指向从头结点沿引用走到的最后一个结点，且当且仅当链为空时它是 `None`。这条关系不写在任何一次动作的返回值里，它约束的是表示的合法状态。删除末尾的那个结点时，必须把尾引用移回新的末尾；漏掉这一步：

```python run id="alg.adt.invariant-check"
class Node:
    def __init__(self, value, next=None): self.value, self.next = value, next

class Chain:
    def __init__(self): self._head = self._tail = None
    def append(self, value):
        node = Node(value)
        if self._tail is None: self._head = self._tail = node
        else: self._tail.next = self._tail = node
    def delete_last(self):
        node = self._head
        while node.next.next is not None: node = node.next
        node.next = None
    def tail_holds(self):
        node = self._head
        while node.next is not None: node = node.next
        return node is self._tail

chain = Chain()
for value in (5, 6, 7, 8): chain.append(value)
print(chain.tail_holds())
chain.delete_last()
print(chain.tail_holds())
chain.append(9)
print(chain.tail_holds())
```

删除本身做对了：它摘掉末尾的结点 8，`tail_holds` 在删除之前为 `True`，删除之后变成 `False`。尾引用仍指着那个已经被摘掉的 8。下一次 `append(9)` 把新结点接到这个已经离开链的结点后面，从头结点出发再也走不到 9——追加执行了，序列却没有变长，`tail_holds` 仍是 `False`。缺陷不在这两次调用的任何一次返回上，而在两步之间：尾引用与末尾结点之间那条关系不再成立。

尾引用与末尾结点之间那条必须在每个公开操作返回时成立的关系，是链式表示的**表示不变量**（representation invariant）：尾引用指向最后一个结点，链为空时它与头引用同时为 `None`。

更一般地，<Term id="invariant">不变量</Term>规定哪些具体状态是合法表示；每个满足它的合法具体状态都解释为调用方能观察到的某个状态，多个不同的合法状态也可以对应同一个可观察状态。尾引用不表示序列里的任何元素，它是为了让追加便宜而添的一格**冗余表示状态**：去掉它、改成走到末尾，调用方看到的序列不变。

在合法状态上，每个操作在返回之前都要让不变量重新成立：

| 步骤 | 需要证明的性质 |
| --- | --- |
| 构造器 | 构造完成时 I 成立 |
| 每个公开操作 | 假设进入这个操作时 I 成立，证明它在正常返回前重新成立 |

初始化是基例，每个操作是归纳步，两者合起来说明 I 在每一次调用边界上都成立。不变量在操作执行过程中可以暂时不成立：删除先摘掉结点、再把尾引用移回新的末尾，中间那一刻尾引用指着已经离开链的结点，它只需在返回之前重新成立；上面那次删除漏掉的正是最后这一步。

这是实现内部需要证明的性质；调用方依赖的是可观察的状态转移、返回值与失败行为，尾引用这类表示细节与它的不变量不在公开规约之内。违反它通常不会立刻报错：它先让实现所依赖的事实失效，再在某次看起来无关的调用上表现为错误结果，上面丢掉的那个 9 就是这种延迟表现。

## 两种表示的成本

两种表示各记一次成本，得到这张对照。计数方式是在单位成本模型下「一次元素移动、一次引用跳转、一次引用改写各记 1」（见 <CrossRef id="algorithms.cost-model" />）；按位置读取与头部插入两列的计数来自上面两段真实运行，追加与删除两列由表示直接读出。

| 表示 | `get(i)` | `append(x)` | `insert(0, x)` | `delete(i)` | 额外空间 |
| --- | --- | --- | --- | --- | --- |
| 连续槽位（已预留容量） | 一次地址计算，$\Theta(1)$ | 有剩余容量时写到末尾，$\Theta(1)$ | 移动 $n$ 个元素，$\Theta(n)$ | 移动 $n - i - 1$ 个后继元素，$\Theta(n - i)$ | 元素之外不存结点 |
| 链式结点（另存尾引用） | 沿引用走 $i$ 步，$\Theta(i)$ | 改尾引用，$\Theta(1)$ | 新建结点、改入口引用，$\Theta(1)$ | 定位前驱 $\Theta(i)$ 后改引用 | 每元素一个结点，另加一格尾引用 |

两行把同一笔工作量在按位置读取、修改与额外空间之间换位置：连续槽位让读取不碰其他元素，代价压在头部插入的移动上；链式结点让头部插入不碰其他元素，代价压在按位置读取的定位上，另存尾引用又把追加降到常数，代价是尾引用必须在每次改动末尾结点时同步。两份实现对调用方是同一条序列：同样的四种操作、同样的返回值、同样的前置条件，不同只在表示与算法两层。表示不变量在每次公开操作返回时重新成立，是这类用额外状态换操作成本的实现能成立的前提：漏掉一次重建，留下的是过去状态算出的结果。

上表的追加一列以连续块还留着容量为前提；容量用尽时要先扩容、把已有元素搬进更大的块，一次扩容是 $\Theta(n)$，把这类偶发成本摊到每次追加上才是常数（<CrossRef id="algorithms.amortized" />）。
