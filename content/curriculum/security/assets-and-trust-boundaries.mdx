文档服务要让获授权成员读取内容，允许编辑者修改，并阻止其他人取得私人数据。设计安全措施时，可以先列出要保护的东西、对手能做什么，以及可能的攻击路径。这项分析称为威胁建模。

例如，服务已经使用 HTTPS，数据库也没有开放到公网。普通用户仍可能把请求里的文档编号从 7 改成 8，从而读到其他人的文档。这里被保护的是传输路径和网络入口，缺少的却可能是应用对每份文档的访问判断。

## 资产与安全目标

**资产**是需要保护的数据、能力或服务。例如私人文档的内容、修改权限、用于访问数据库的凭据，以及合法用户能够继续使用服务的能力。

安全目标可以从三个方面说明。保密性要求文档只交给获准的用户；完整性要求内容只接受获准的修改；可用性要求合法用户能在规定条件下取得服务。窃取文档、未授权改写和耗尽处理资源，分别威胁这三个目标。

| 资产 | 允许的行为 | 不允许的行为 |
| --- | --- | --- |
| 私人文档 | 所有者和获授权成员读取 | 普通用户读取其他人的文档 |
| 文档内容 | 具有编辑权限的用户修改 | 只读成员修改 |
| 数据库凭据 | 指定服务进程使用 | 浏览器或公开构建产物取得 |
| 查询能力 | 有限规模的合法请求 | 任意请求耗尽全部资源 |

这些规则还取决于产品的具体约定，例如是否允许公开分享、管理员能否读取内容，以及备份保留多久。确定约定后，才能为允许和拒绝的操作准备预期结果。

## 威胁模型与信任边界

**威胁模型**（threat model）说明资产、对手能力和可能的攻击路径。设对手可以注册普通账户，构造自己的 HTTP 请求，并向文档写入内容；不能直接登录服务器。这已经允许它改变文档编号、绕过页面按钮、提交异常大的内容、向其他读者提供自己编写的数据。

浏览器代码和请求格式交给了客户端，对手可以跳过页面按钮，使用别的 HTTP 客户端构造请求。因此，页面是否显示按钮只影响界面，服务器仍需检查对应操作的权限。

```text
用户控制的浏览器
      │ HTTP 请求
      ▼
服务进程 ── 查询与修改 ──> 数据库
      │                         │
      └── 审计事件 ──> 日志存储  │
      ▲                         │
      └────── 文档内容 ─────────┘
```

**信任边界**是不同信任假设适用的区域之间的分界。请求从用户控制的浏览器进入服务端时，就跨过了这样的边界：服务器要自行验证身份，并查询文档归属和角色，而不是采用客户端自报的值。数据库中的内容也可能最初由用户提交；返回浏览器时，应按预定用途将其作为文本或受限的富文本处理。

画出存储、外部参与者和信任边界后，就可以沿数据流逐段检查：输入由谁控制，接收方怎样解释，执行时获得哪些能力。威胁建模中的系统建模方法见 [OWASP：威胁建模的系统模型](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html#system-modeling)。

## 攻击路径与防护措施

对手读取他人文档的路径是：取得普通账户身份，发送他人文档编号，服务器只检查已登录，再返回内容。服务器应在返回前检查当前身份对目标文档的读取权限。HTTPS 不会阻断这条路径，因为对手完全可以通过一条合法的加密连接提交请求。

对手拖慢服务的路径可能是：发送格式正确但规模巨大的请求，触发长时间计算，占满服务的并发处理能力。可以在执行昂贵计算前限制输入规模，并为处理设置工作量或并发数量上限。

防护措施需要对应可检查的行为。例如，用户 A 请求属于用户 B 的非共享文档时，服务器拒绝且不返回正文；内容超过规定大小时，在进入昂贵处理前被拒绝。测试同时覆盖正常操作，确认获授权用户仍能读取文档，符合规模要求的任务仍能完成。

增加公开分享链接、第三方转换服务或管理员能力时，应在数据流图中加入相应参与者与权限，再检查新增的访问路径。

## 练习：第三方预览服务

团队准备把文档发给第三方服务生成预览。该服务需要看到完整内容，预览再返回给用户。画出新增的数据流，说明哪个参与者新获得了读取能力；如果产品承诺“文档内容只由本服务保存和处理”，这个改动需要改变什么决定？
