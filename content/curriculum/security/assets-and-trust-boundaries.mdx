一份私人文档服务已经使用 HTTPS，数据库也没有开放到公网。普通用户仍可能把请求里的文档编号从 7 改成 8，从而读到其他人的文档。这里被保护的是传输路径和网络入口，缺少的却可能是应用对每份文档的访问判断。

## 要保护什么，允许谁做什么

**资产**是需要保护的数据、能力或服务。例如私人文档的内容、修改权限、用于访问数据库的凭据，以及合法用户能够继续使用服务的能力。

保护要求需要具体到行为：文档内容只交给获准的用户，这是保密性；修改只接受获准操作，这是完整性；合法用户能在规定条件下取得服务，这是可用性。它们可能分别受到攻击。“服务已加密”没有说明这三项要求都满足。

| 资产 | 允许的行为 | 不允许的行为 |
| --- | --- | --- |
| 私人文档 | 所有者和获授权成员读取 | 普通用户读取其他人的文档 |
| 文档内容 | 具有编辑权限的用户修改 | 只读成员修改 |
| 数据库凭据 | 指定服务进程使用 | 浏览器或公开构建产物取得 |
| 查询能力 | 有限规模的合法请求 | 任意请求耗尽全部资源 |

安全要求还需要假设：服务是否允许公开分享？管理员能否读取内容？备份保留多久？如果这些问题没有决定，测试也无法判断什么结果是正确的。

## 对手能控制哪些输入

**威胁模型**（threat model）说明资产、对手能力和可能的攻击路径。设对手可以注册普通账户，构造自己的 HTTP 请求，并向文档写入内容；不能直接登录服务器。这已经允许它改变文档编号、绕过页面按钮、提交异常大的内容、向其他读者提供自己编写的数据。

“用户只能点击界面上的按钮”不是可信假设。浏览器代码和请求格式交给了客户端，对手可以使用别的 HTTP 客户端发送同样的协议请求。页面隐藏一个按钮，不能撤销服务器提供的能力。

```text
用户控制的浏览器
      │ HTTP 请求
      ▼
服务进程 ── 查询与修改 ──> 数据库
      │                         │
      └── 审计事件 ──> 日志存储  │
      ▲                         │
      └────── 文档内容 ─────────┘
```

**信任边界**是数据或能力从一种控制与信任假设进入另一种的地方。浏览器到服务是一个边界：服务器不能把客户端声称的用户身份、文档归属或管理员角色直接当成事实。数据库返回到浏览器也会经过解释边界：已保存内容仍可能最初来自对手，不能因此当成可执行网页。

数据流图需要包含存储、外部参与者和边界；它提供的是分析对象，随后才寻找威胁与控制，见 [OWASP：威胁建模的系统模型](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html#system-modeling)。

## 控制要阻断一条具体路径

对手读取他人文档的路径是：取得普通账户身份，发送他人文档编号，服务器只检查已登录，再返回内容。服务器应在返回前检查当前身份对目标文档的读取权限。HTTPS 不会阻断这条路径，因为对手完全可以通过一条合法的加密连接提交请求。

对手拖慢服务的路径可能是：发送允许解析但规模巨大的请求，触发长时间计算，占用全部工作槽位。这里需要请求规模、工作量或并发数量限制；仅对输入做类型检查并没有解决资源成本。

控制的要求应能被证据验证。例如“用户 A 请求属于用户 B 的非共享文档，服务器拒绝且不返回文档内容”；“超过规定大小的内容在进入昂贵处理前被拒绝”。合法请求也必须继续完成，不能通过拒绝全部操作来声称安全。

系统增加公开分享链接、第三方转换服务或新的管理员能力时，资产与边界也改变。旧测试仍通过，只证明旧判据继续满足，不能自动证明新路径已经检查。

## 加入第三方预览服务以后

团队准备把文档发给第三方服务生成预览。该服务需要看到完整内容，预览再返回给用户。画出新增的数据流，说明哪个参与者新获得了读取能力；如果产品承诺“文档内容只由本服务保存和处理”，这个改动需要改变什么决定？
