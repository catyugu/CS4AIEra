执行 `b = a` 后，两个名字指向同一份数据吗？对整数重新赋值时，另一个名字的值不会跟着改变；列表却可以直接修改自己的内容。要判断这种修改会影响谁，需要分清名字和它指向的对象。

## 列表与点号调用

列表把多个值按顺序放在一起，写在方括号里，用逗号分隔。`[10, 20]` 创建一个含有两项的列表；每一项称为元素，`[]` 则创建空列表。

列表可以追加元素：`samples.append(30)` 中的点号表示使用 `samples` 这个对象提供的操作，`append` 在末尾追加一项，括号里是要追加的值。通过对象调用的这类函数称为<Term id="method">方法</Term>。

```python run id="program-logic-and-state.names-objects-and-state.alias"
samples = [10, 20]
view = samples
view.append(30)
print("samples:", samples)
print("view:", view)
print("same object:", samples is view)

view = [40]
print("samples:", samples)
print("view:", view)
print("same object:", samples is view)
```

`samples = [10, 20]` 创建列表，把名字绑定到它。`view = samples` 读取已有对象，再绑定另一个名字，**没有复制列表**。两个名字指向同一个对象，互为<Term id="alias">别名</Term>。

`view.append(30)` 修改这个列表，所以两个名字都看到追加后的内容。`view = [40]` 则创建另一个列表，只改变 `view` 的指向。`samples` 仍指向原列表。

| 执行后 | samples 指向的列表 | view 指向的列表 | 是否为同一个列表 |
| --- | --- | --- | --- |
| `view = samples` | `[10, 20]` | `[10, 20]` | 是 |
| `view.append(30)` | `[10, 20, 30]` | `[10, 20, 30]` | 是 |
| `view = [40]` | `[10, 20, 30]` | `[40]` | 否 |

`is` 判断是不是同一个对象，返回 `True`（是）或 `False`（否）。`==` 判断值是否相等：两个分别创建的 `[10, 20]` 内容相等，但不是同一个列表。

## 对象可以变，名字也可以换指向

Python 中的值都是对象。对象有自己的身份，用来区分“同一个对象”和“内容相等的两个对象”；类型决定它允许哪些操作；值则是它当前的内容。列表追加元素后，内容变了，仍然是原来的列表。

列表是可变对象，可以通过 `append` 等操作修改内容。整数、浮点数和字符串是不可变对象，不能就地改写自己的值。

```python run id="program-logic-and-state.names-objects-and-state.immutable"
number = 10
kept = number
number = number + 1
print("number:", number)
print("kept:", kept)
```

`number + 1` 算出另一个整数，再把 `number` 绑定到它。`kept` 仍指向原来的 `10`。原来的整数没有变成 `11`。

对名字的赋值 `name = expression` 改变绑定。列表的 `append` 则修改对象本身。`view = [40]` 改变名字的绑定，`view.append(30)` 修改它指向的列表。

## 复制列表

`list(samples)` 创建一个新列表。给新列表追加元素，不会给原列表追加：

```python
samples = [10, 20]
working = list(samples)
working.append(30)
```

此时 `samples` 是 `[10, 20]`，`working` 是 `[10, 20, 30]`。`list(...)` 只复制外层列表；元素本身可变时仍可能共享，这种<Term id="shallow-copy">浅拷贝</Term>在 <CrossRef id="program-composition.modules-and-boundaries" /> 的返回结果中再看。

## 共享是否符合要求

共享本身可以是有意的。例如两处代码都要看到同一份记录，追加记录就应该在两处可见。如果一处要求保留原记录，另一处却把它当工作清单修改，共享就违反了这个要求。

判断一次追加会影响谁，先找出哪些名字指向同一个列表。

## 练习

预测三个名字的内容，以及哪些名字指向同一个列表，再运行验证：

```python run id="program-logic-and-state.names-objects-and-state.exercise-append-then-rebind"
samples = [10]
view = samples
spare = list(samples)
view.append(20)
spare.append(30)
view = [40]

print("samples:", samples)
print("view:", view)
print("spare:", spare)
print("samples is view:", samples is view)
print("samples is spare:", samples is spare)
```
