把字符串 `"12"` 转成整数可以得到 12；把 `"fast"` 转成整数则会失败。某一步无法正常完成时，Python 会抛出异常（exception）；异常携带类型和错误信息，供程序选择怎样处理。

## try 与 except

`int(text)` 尝试把字符串解析成整数。无法转换时，它抛出 `ValueError`。`try` 中写要尝试执行的代码，`except ValueError` 指定发生这类异常时怎么办：

```python run id="program-logic-and-state.exceptions-and-cleanup.catch"
text = "fast"
try:
    seconds = int(text)
    print("seconds:", seconds)
except ValueError as failure:
    print("invalid duration:", failure)
print("finished checking")
```

`int(text)` 失败后，`try` 中剩下的 `print` 被跳过，程序转去执行匹配的 `except`。`as failure` 把异常对象绑定到名字，便于读取它的消息。捕获结束后，继续执行整个 `try` 语句后面的代码。

## 异常可以传到调用方

如果当前函数没有处理异常，它就不能正常返回。异常沿调用关系传播，由调用方继续寻找匹配的处理代码。下面的两个函数分别负责转换耗时、处理一条记录：

```python run id="program-logic-and-state.exceptions-and-cleanup.path"
def parse_seconds(text):
    return int(text)


def process(name, text):
    seconds = parse_seconds(text)
    print("processed:", name, seconds)
    return seconds


try:
    process("entry 1", "fast")
    print("batch complete")
except ValueError as failure:
    print("stopped:", failure)
```

失败发生在 `parse_seconds` 里。它没有 `except`，异常离开这次调用；`process` 也没有捕获，因而不能执行打印或返回。最外层的 `except` 接住了异常，`batch complete` 不会输出。如果一直没有匹配的处理代码，这次执行就以未捕获异常结束，并显示回溯，列出经过的调用位置。

| 位置 | 失败后的动作 |
| --- | --- |
| `int("fast")` | 抛出 `ValueError`，没有转换结果 |
| `parse_seconds` | 没有处理代码，异常离开调用 |
| `process` | 没有处理代码，打印和返回都被跳过 |
| 外层 `try` | 跳过剩余语句，执行匹配的 `except` |

异常不会撤销已经完成的修改和输出。若前一项任务已经加入结果列表，后一项失败并不会自动删除它。

## 捕获位置与失败的含义

如果要求“坏记录单独报告，其余记录继续处理”，就把捕获放在逐项处理的循环里。`("entry 1", "12")` 是包含两项的元组，用来把名称与耗时放在一起。`for name, text in entries` 在每轮将这一对值分别赋给两个名字，这叫解包：

```python run id="program-logic-and-state.exceptions-and-cleanup.positions"
entries = [("entry 1", "12"), ("entry 2", "fast"), ("entry 3", "5")]
total = 0
for name, text in entries:
    try:
        seconds = int(text)
    except ValueError:
        print("skipped:", name)
        continue
    total += seconds
print("total for valid entries:", total)
```

这里报告的是**有效记录的总和**，失败记录另有输出。如果要求所有记录都有效才给出总和，就应让异常离开循环，由调用方报告整批失败。把未知耗时悄悄替换成 0，会让调用方误以为得到了完整总和。

代码也可以主动拒绝不符合要求的值。`raise ValueError("duration must be nonnegative")` 创建并抛出异常；例如转换成功后发现 `seconds < 0`，便可以这样拒绝负耗时。

## finally 在退出时执行

无论转换成功还是失败，都想记录处理结束，就把记录放进 `finally`：

```python run id="program-logic-and-state.exceptions-and-cleanup.finally"
log = []


def process(text):
    log.append("start")
    try:
        return int(text)
    finally:
        log.append("end")


print("result:", process("12"))
try:
    process("fast")
except ValueError as failure:
    print("failed:", failure)
print("log:", log)
```

成功时，先计算返回值，再执行 `finally`，最后返回。失败时，先执行 `finally`，再继续传播异常。因此两次调用都记录了 `end`，失败那次仍然抛出异常。普通地把日志追加写在 `return` 之后，两种情况都执行不到它。

关闭已经打开的文件等清理操作，也需要在正常返回与异常传播时执行。执行顺序见 [Python 的 try 语句](https://docs.python.org/3/reference/compound_stmts.html#the-try-statement)。`finally` 不保证在进程被强制终止或机器断电时执行。

## 练习

要求每条记录的耗时都能转换成非负整数；只要一条不符合要求，就报告整批失败，不给出总和。下面把捕获放在循环外，是否就满足了要求？分别用 `"fast"` 和 `"-2"` 替换一项耗时，并把它放在不同位置，检查失败报告与总和输出。需要增加什么检查？成功时才应执行的输出要放在哪里？

```python run id="program-logic-and-state.exceptions-and-cleanup.exercise-batch"
entries = [("entry 1", "12"), ("entry 2", "fast"), ("entry 3", "5")]
total = 0
try:
    for name, text in entries:
        total += int(text)
except ValueError as failure:
    print("batch failed:", failure)
print("total:", total)
```
