三次测量得到 `[4, 7, 4]`。需要计算平均值时，两次 4 都要保留；只问出现过哪些数时，重复次数可以忽略。列表、集合和字典都能容纳多个值，但保存的信息不同。

## 序列保存次序和重复

列表 `[4, 7, 4]` 有三项，两个 4 出现在不同位置。下标从 0 开始，`values[1]` 读取第二项，`len(values)` 返回元素数。列表属于序列：元素有确定的先后次序，允许重复。

列表可以修改：`values[1] = 8` 替换第二项，`values.append(9)` 在末尾追加。这些操作改变原列表，所有指向它的名字都会看到修改。

```python run id="program-logic-and-state.sequences-sets-and-mappings.list-positions"
values = [4, 7, 4]
print("length:", len(values))
print("second:", values[1])
values[1] = 8
values.append(9)
print("updated:", values)
```

直接读取 `values[10]` 会报 `IndexError`，因为列表没有这个位置。空列表的长度为 0，也没有下标为 0 的元素。

## 集合保存不同的值

集合只保留互不相同的元素。`{4, 7}` 直接创建一个集合，`set(values)` 将列表转换成集合，`4 in unique` 判断 4 是否在集合里。观察转换后还剩哪些信息：

```python run id="program-logic-and-state.sequences-sets-and-mappings.set-membership"
values = [4, 7, 4]
unique = set(values)
print("list length:", len(values))
print("set size:", len(unique))
print("contains 4:", 4 in unique)
print("list first:", values[0])
```

列表长度为 3，集合大小为 2。集合仍能回答“有没有 4”，但两个 4 变成一项，已经无法恢复原来的次数与位置。集合没有第一个、第二个这样的下标，也不保证按加入顺序遍历。

`unique.add(9)` 把 9 加入集合，再加入相同的值也不会多出一项。`in` 检查某个值是否存在，也能用于列表。

## 映射保存键值对应

映射按键找到对应值。Python 的字典 `dict` 就是一种映射：

```python run id="program-logic-and-state.sequences-sets-and-mappings.mapping-update"
prices = {"apple": 4, "pear": 7}
print("apple:", prices["apple"])
prices["apple"] = 5
print("updated:", prices["apple"])
print("key count:", len(prices))
```

`"apple"` 是键，4 是原来的值。对同一键再次赋值，替换它对应的值，不增加一个同名键。一个键只对应一个值，这个值也可以是列表等容器。

`"apple" in prices` 检查键是否存在。直接读取没有保存的键会抛出 `KeyError`，如 `prices["banana"]`。键标识的是所查项目，不是它在容器中的第几个位置。

## 哪些信息必须保留

| 需要保留的信息 | 合适的基本容器 |
| --- | --- |
| 每项的顺序和重复次数 | 序列，例如列表 |
| 某个值是否出现 | 集合 |
| 一个键对应什么值 | 映射，例如字典 |

如果原始数据是三次测量 `[4, 7, 4]`，转换为集合后就不能再计算同一份数据的平均值：少了一次 4。容器转换会改变可回答的问题。
