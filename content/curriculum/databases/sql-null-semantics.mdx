## 目的

本课解释 SQL 中 <Term id="null-logic">NULL</Term> 的语义，以及它如何把二值逻辑扩展为三值逻辑。

这不是一个语法细节。它决定了 `WHERE` 子句会返回哪些行、`NOT IN` 为什么会静默返回空结果、聚合函数为什么忽略 NULL、以及 `UNIQUE` 约束为什么允许同一列出现多行 NULL。把 NULL 当作"空字符串"或"零"来推理，是查询结果与预期不符的最常见来源。

本课使用实验夹具 <LabRef id="sql.orders.basic" />：一个含外键、唯一约束与若干可空列的小型订单模式。

## 模型：三个真值

SQL 的布尔表达式有三种结果：`TRUE`、`FALSE`、`UNKNOWN`。`WHERE` 子句只保留结果为 `TRUE` 的行；`FALSE` 与 `UNKNOWN` 都会被丢弃。

NULL 是"此处没有值/值未知"的标记。因此：

| 表达式 | 结果 |
| --- | --- |
| `NULL = NULL` | `UNKNOWN` |
| `NULL = 1` | `UNKNOWN` |
| `1 = 1` | `TRUE` |
| `NULL IS NULL` | `TRUE` |
| `NOT UNKNOWN` | `UNKNOWN` |
| `TRUE OR UNKNOWN` | `TRUE` |
| `FALSE OR UNKNOWN` | `UNKNOWN` |

关键推论：**UNKNOWN 会传播**。一个由多个条件用 `AND`、`OR` 组合的谓词，只要含有 UNKNOWN 且其余部分不足以决定结果，整体就是 UNKNOWN，于是行被丢弃。

## 观察：比较不等于匹配

夹具中 `customer_id = 3` 的客户 `country` 为 NULL。下面第一条查询按常规比较取国家为 `'GB'` 的客户，第二条查询想取"不是 GB"的客户。

```sql run id="sql.null.comparison" fixture="sql.orders.basic"
SELECT customer_id, full_name, country
FROM customers
WHERE country = 'GB';

SELECT customer_id, full_name, country
FROM customers
WHERE country <> 'GB';
```

第二条查询漏掉了 `country` 为 NULL 的那一行：`NULL <> 'GB'` 求值为 `UNKNOWN`。这是三值逻辑的直接后果，与数据是否缺失无关。

## 正确写法：IS NULL 谓词

要表达"没有值"，必须用 `IS NULL` 与 `IS NOT NULL`。它们是谓词而不是比较，因此对 NULL 有确定结果。

```sql run id="sql.null.is-null" fixture="sql.orders.basic"
SELECT customer_id, full_name
FROM customers
WHERE country IS NULL;
```

要"取所有不是 GB 的客户，包括国家未知的客户"，必须显式写出两个分支：

```sql run id="sql.null.not-gb-or-unknown" fixture="sql.orders.basic"
SELECT customer_id, full_name, country
FROM customers
WHERE country IS NULL OR country <> 'GB';
```

`IS NULL` 与 `IS NOT NULL` 的并集覆盖全部行，而 `= 'x'` 与 `<> 'x'` 的并集不覆盖含 NULL 的行。这条差异是编写"互斥且完备"过滤条件的判据。

## 陷阱：NOT IN 与 NULL

`NOT IN` 是这一语义最容易出错的地方。下面是两个只差一个元素的子查询。

```sql run id="sql.null.not-in" fixture="sql.orders.basic"
SELECT customer_id, country
FROM customers
WHERE country NOT IN ('GB', 'US');

SELECT customer_id, country
FROM customers
WHERE country NOT IN ('GB', 'US', NULL);
```

第二条返回空集。原因是 `x NOT IN (a, b, NULL)` 等价于 `NOT (x = a OR x = b OR x = NULL)`。对任何非 NULL 的 `x`，`x = NULL` 为 `UNKNOWN`；当 `x` 与 `a`、`b` 都不相等时，整个 `OR` 链为 `UNKNOWN`，取反后仍为 `UNKNOWN`，行被丢弃。对 NULL 的 `x` 同样得到 `UNKNOWN`。

因此：**子查询可能产生 NULL 时，不要用 `NOT IN`**。改用 `NOT EXISTS` 或先过滤掉 NULL：

```sql run id="sql.null.not-exists" fixture="sql.orders.basic"
SELECT c.customer_id, c.full_name
FROM customers AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
);
```

`NOT EXISTS` 只关心子查询是否产生行，不把值代入比较，因此不受 NULL 影响。这条查询返回没有任何订单的客户，结果是确定的行集合。

## 聚合与分组

聚合函数（`COUNT`、`SUM`、`AVG`、`MAX`）忽略 NULL 输入。这带来两个必须区分的计数：

```sql run id="sql.null.aggregates" fixture="sql.orders.basic"
SELECT
    COUNT(*)                    AS total_rows,
    COUNT(country)              AS rows_with_country,
    COUNT(*) - COUNT(country)   AS rows_with_null_country
FROM customers;
```

`COUNT(*)` 计行数，`COUNT(column)` 只计该列非 NULL 的行。`SUM` 与 `AVG` 在分母上使用非 NULL 行数，因此 `AVG(discount_cents)` 在含 NULL 的列上并不等于"把 NULL 当 0 的平均值"。

`GROUP BY` 把所有 NULL 归入同一个组：在 SQL 分组语义里 NULL 彼此"相同"，这与 `WHERE` 比较中的 `UNKNOWN` 并不矛盾——分组用的是"是否同一组"的等价关系，不是 `=` 谓词。

## 具名 session：连续观察同一连接

默认情况下每个单元格使用独立连接并重新加载夹具。需要连续观察同一连接上的状态时，作者给单元格指定同一个 session 名。

```sql run id="sql.session.load" session="orders-demo" fixture="sql.orders.basic"
SELECT COUNT(*) AS orders_before
FROM orders;
```

```sql run id="sql.session.mutate" session="orders-demo"
INSERT INTO orders (order_id, customer_id, placed_on, status, discount_cents)
VALUES (1005, 2, '2026-03-01', 'pending', NULL);
```

```sql run id="sql.session.after" session="orders-demo"
SELECT COUNT(*) AS orders_after
FROM orders;
```

第三个单元格看到 1005，因为三个单元格共享同一个连接。**Reset** 会重建该 session 的连接并重新应用夹具，`orders_after` 回到原值——这正是夹具"可重现"的含义。

## 约束与 NULL

约束在含 NULL 的列上保证的范围比直觉要窄：

- `NOT NULL` 排除 NULL；没有它，列上的任何其他约束都可能被 NULL 绕过。
- `CHECK (x > 0)` 在 `x` 为 NULL 时结果为 `UNKNOWN`，而约束只在结果为 `FALSE` 时被违反。因此 `CHECK` 不禁止 NULL，需要与 `NOT NULL` 配合。
- `UNIQUE` 允许任意多行 NULL：唯一性按"两个值是否相等"判定，而 `NULL = NULL` 是 `UNKNOWN`，不构成冲突。要禁止多个 NULL，需要部分索引或额外的约束设计。
- 外键列上的 NULL 表示"没有引用对象"，不触发引用完整性检查。

```sql run id="sql.null.unique-insert" fixture="sql.orders.basic"
INSERT INTO orders (order_id, customer_id, placed_on, status, discount_cents)
VALUES (1006, 1, '2026-03-02', 'paid', NULL);

SELECT order_id, discount_cents
FROM orders
WHERE discount_cents IS NULL
ORDER BY order_id;
```

两行 `discount_cents` 为 NULL 的行可以共存，但把 `order_id` 换成重复值会立即因主键冲突失败。

## 方言说明

本课的可执行基线是 SQLite，以上语义是 SQL 标准的三值逻辑，主流引擎一致。但要注意 SQLite 特有的部分：

- SQLite 是动态类型系统，列类型是"亲和性"而非强制约束；`CHECK` 与 `NOT NULL` 仍被强制，但把字符串写入 `INTEGER` 列通常不会报错。其他引擎的行为不同。
- `COUNT(*)`、`NOT IN` 与 `NOT EXISTS` 的语义在各引擎一致，但查询计划与索引使用方式差异很大，不能由 SQLite 的表现推断其他引擎。
- 部分引擎提供 `IS DISTINCT FROM` 这类把 NULL 当作普通值的比较运算符，SQLite 没有。

## 生产后果

- 过滤条件必须成对检查：`=`/`<>` 覆盖不到 NULL，需要显式分支，否则行会静默消失。
- 应用层用"空字符串"或"0"表示缺失时，写入数据库就变成了真实值，三值逻辑不再能区分"未知"与"空"，这类混淆会一直传播到报表与对账。
- 聚合结果的分母决定业务指标。`AVG` 忽略 NULL 可能让"平均折扣"偏高，需要在口径上明确 NULL 的处置。
- 迁移与回填时，`NOT NULL` 约束的添加会因既有 NULL 行失败，需要显式的回填步骤。
- 生成式工具常写出 `NOT IN (SELECT ...)` 形式的查询，在含 NULL 的子查询上静默返回空结果，看起来"没数据"而不是"写错了"。

## 小结

- NULL 表示未知，不是空值；比较运算遇 NULL 得到 UNKNOWN。
- `WHERE` 只保留 `TRUE` 的行，`FALSE` 与 `UNKNOWN` 都被丢弃。
- `IS NULL`、`IS NOT NULL` 是谓词，对 NULL 有确定结果。
- `NOT IN` 在子查询含 NULL 时可能返回空集；用 `NOT EXISTS` 表达"不存在"。
- 聚合忽略 NULL，`COUNT(*)` 与 `COUNT(column)` 含义不同。
- `NOT NULL`、`CHECK`、`UNIQUE` 在含 NULL 的列上保证范围各不相同，需要分别核对。
