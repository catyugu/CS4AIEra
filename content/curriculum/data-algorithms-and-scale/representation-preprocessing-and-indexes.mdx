多本书的记录已经保存成列表，按编号找一本时，可以逐条比对。如果这个查找每天发生很多次，值得考虑先整理数据。要比较的是一次准备、反复查询与后续更新的总工作。

<Term id="workload">工作负载</Term>描述实际发生哪些操作、各有多少次，以及数据的规模与分布。记录数相同，每天查一次与每天查几万次，可能适合不同的结构。

## 先确定要保留什么

列表可以保留全部记录和原有次序。以编号为键的字典，每个编号只有一个对应值。如果编号重复，后写的记录会覆盖先写的记录。先确定编号是否唯一、旧版本是否需要保留，再决定这种表示是否合适。

下面分别比较扫描、排序后查找、按键索引，假定记录编号唯一，查询要求返回该编号对应的记录。数据在查询期间保持不变。

## 排序让一次比较排除一半候选

编号 `[8, 2, 11, 5, 1]` 排序后是 `[1, 2, 5, 8, 11]`。找 8 时，比较中间的 5，便知道目标如果存在，只能在右半边。反复取中间位置并缩小范围，这叫二分查找。

排序只是建立有序性；查询程序还要利用它，才会减少比较。下面输出每次检查的位置：

```python run id="data-algorithms-and-scale.representation-preprocessing-and-indexes.binary-search"
values = [1, 2, 5, 8, 11]
wanted = 8
left = 0
right = len(values) - 1
found = None
while left <= right:
    middle = (left + right) // 2
    print("range:", left, right, "checked:", values[middle])
    if values[middle] == wanted:
        found = middle
        break
    if values[middle] < wanted:
        left = middle + 1
    else:
        right = middle - 1
print("found at:", found)
```

`//` 对商向下取整，这里用来取得中间下标。`left` 与 `right` 是尚未排除范围的两个端点。每次排除已比较的位置及不可能的那一半；范围变空就结束，没有命中时 `found` 仍为 `None`。标准库也提供二分定位工具，见 [Python bisect](https://docs.python.org/3/library/bisect.html)。

本例先检查下标 2 的值 5，再检查下标 3 的值 8。将 `wanted` 改成 7，观察没有命中时两个端点怎样变化。二分查找依赖有序性，不能把这段代码直接用于未排序的列表。

设有 $n$ 条记录、$q$ 次查询，每次比较按固定成本计算：

| 方案 | 一次准备 | 单次查询的最坏成本 | 全部查询的成本上界 |
| --- | --- | --- | --- |
| 直接扫描 | 无 | $O(n)$ | $O(qn)$ |
| 先排序，再二分查找 | $O(n\log n)$ | $O(\log n)$ | $O(n\log n+q\log n)$ |

查询越多，越容易收回准备成本。只查一次时，排序通常没有优势；实际交叉点需要结合数据与实现测量。后续追加和修改也要计入成本，例如往有序列表末尾追加，可能破坏有序性。

## 按键索引避免反复扫描

索引保存从查询条件到记录的定位信息。主列表保留记录，额外字典保存“编号 → 记录”；如果查询按分类进行，还可以保存“分类 → 这一类的记录列表”。

```python run id="data-algorithms-and-scale.representation-preprocessing-and-indexes.record-sharing"
books = [{"id": "b1", "category": "science", "price": 30}]
by_id = {}
for book in books:
    by_id[book["id"]] = book

by_id["b1"]["price"] = 35
print("price in original list:", books[0]["price"])
print("same record:", books[0] is by_id["b1"])
```

`by_id` 保存的是原记录对象。通过索引修改价格，主列表也会读到新价格。

分类索引除了共享记录，还保存了记录属于哪个分组：

```python run id="data-algorithms-and-scale.representation-preprocessing-and-indexes.index-update"
books = [
    {"id": "b1", "category": "science", "price": 30},
    {"id": "b2", "category": "history", "price": 40},
    {"id": "b3", "category": "science", "price": 50},
]
by_category = {}
for book in books:
    category = book["category"]
    if category not in by_category:
        by_category[category] = []
    by_category[category].append(book)

book = books[0]
book["category"] = "history"
print("science entries:", by_category["science"])
print("history entries:", by_category["history"])
```

改变分类后，记录没有自动从 `science` 移到 `history`。**共享记录与维护分组是两件事。** 修改分类时，还要从旧列表移除这条记录，并加入新列表。

按编号查询可以用 `by_id["b1"]`；允许编号不存在时，`by_id.get("missing")` 返回 `None`。`get` 的第二个参数可以指定默认值，例如 `by_category.get("art", [])` 在没有该类时返回空列表。直接遍历字典取得的是键。

## 抽象保证与实现性能

映射规定按键取值的结果，却不要求用某种存储方式实现。这种只规定操作与结果的模型称为<Term id="abstract-data-type">抽象数据类型</Term>。

本课程运行环境中的 Python `dict` 采用哈希表实现：从键计算<Term id="hash-value">哈希值</Term>，用它缩小要检查的位置范围，再比较键。不同键可能算出相同的哈希值，这时仍要比较键本身，不能把哈希值当成唯一编号。

| 步骤 | 查找时做什么 |
| --- | --- |
| 计算哈希值 | 根据查询键计算一个整数 |
| 确定候选位置 | 根据哈希值与表的内部结构确定要检查的位置 |
| 比较键 | 确认候选位置保存的键是否等于查询键，匹配后取得值 |

发生冲突时，需要继续检查其他候选位置。速度取决于能否把候选范围缩得足够小。

在通常的哈希分布、固定成本的键处理假设下，按键查找的平均成本为 $O(1)$；最坏情况可能为 $O(n)$。平均成本描述某种输入分布下的总体表现，最坏成本则考虑最不利的合法输入。不能因为通常查得快，就保证每次都查得快，也不能从“映射”这个抽象名称直接推出查找成本。实现说明见 [Python FAQ：字典如何实现](https://docs.python.org/3/faq/design.html#how-are-dictionaries-implemented-in-cpython)。

按分类索引后，一次查询只检查目标分类的 $k$ 条记录。它不能直接按价格筛选或排名；这些操作仍要检查分类内的记录，或者维护另一个适合价格查询的结构。

## 高效查询的成本：空间消耗和更新代价

额外字典及分组列表占空间，建索引要读一遍数据，写入和分类修改要同步维护。查询频繁、单次能排除很多记录时，这些代价可能值得；目标分类包含大部分记录时，节省就有限。

选择时先确认信息保留与结果要求，再比较准备、查询、更新和空间成本。两个索引都能“加速查询”，加速的可能是不同操作。

## 练习

书目系统用 `by_category` 按分类查询。下面的函数将一本书改到另一类。调用后，按 `science` 查询应得到 `b3`，按 `history` 查询应得到 `b2` 和 `b1`，不要求它们的排列次序。

先预测两个分组的内容，再运行。这个函数是否满足要求？如果不满足，修改函数，使记录中的分类与分组中的位置保持一致。还要检查将书改到原来不存在的 `art` 类时是否正常。

```python run id="data-algorithms-and-scale.representation-preprocessing-and-indexes.exercise-change-category"
books = [
    {"id": "b1", "category": "science"},
    {"id": "b2", "category": "history"},
    {"id": "b3", "category": "science"},
]
by_category = {}
for book in books:
    category = book["category"]
    if category not in by_category:
        by_category[category] = []
    by_category[category].append(book)


def change_category(book, new_category):
    book["category"] = new_category


change_category(books[0], "history")
print("science:", by_category["science"])
print("history:", by_category["history"])
```

> 注：列表的 `remove` 方法移除第一个与参数相等的元素，找不到时会报错。例如 `numbers = [10, 20]`，调用 `numbers.remove(10)` 后只剩 `[20]`。练习中的书目编号唯一，因此不同记录不会比较为相等。

直接扫描时，每次查询需要检查全部书目；维护分类索引时，只需读取目标分类的记录，但每次修改分类都要维护分组。分别估算两种方案每天查询需要读取多少条记录，再比较以下两个使用情况：它们都保存 10000 条书目，每次按分类查询约返回 100 条，不要求排序。哪种方案适合场景甲？哪种方案适合场景乙？
