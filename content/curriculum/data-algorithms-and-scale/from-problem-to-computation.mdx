“在书目里找出某类现在能借的书，按评分排序，还能点开看详情。”

这是一项需求，但还不足以决定怎样实现。评分相同时怎样排序？评分等于门槛算不算符合条件？返回全部结果还是前十本？这些选择会改变程序应当返回的答案。

## 写清输入和输出

每本书的记录包含编号、分类、是否可借和评分。假设用户要查询某个分类中，评分不低于门槛、现在可借的书。这里先用编号区分书目，不处理同一本书的多册副本。

| | 约定 |
| --- | --- |
| 输入 | 书目记录、目标分类、评分门槛 |
| 输出 | 全部符合条件的记录，按评分从高到低排列 |
| 筛选规则 | 分类匹配、可借、评分大于或等于门槛，三个条件都要满足 |
| 特殊情况 | 没有命中时返回空列表；评分相同时按编号升序排列 |

这些约定有可观察的后果：评分恰好等于门槛的书不能漏掉，没有命中时不能返回一本“最接近”的书。用户如果只想要前十本，也应该明确写出来。

先用几条记录检查自己是否理解了要求。字典里的字段名比 `row[2]` 这样的数字下标更容易辨认：

```python run id="data-algorithms-and-scale.from-problem-to-computation.filter"
books = [
    {"id": "b1", "category": "science", "available": True, "rating": 4.0},
    {"id": "b2", "category": "science", "available": False, "rating": 4.9},
    {"id": "b3", "category": "history", "available": True, "rating": 4.7},
    {"id": "b4", "category": "science", "available": True, "rating": 4.5},
]
wanted_category = "science"
threshold = 4.0
matched = []
for book in books:
    if book["category"] == wanted_category and book["available"] and book["rating"] >= threshold:
        matched.append(book)
print(matched)
```

一个字典表示一本书，外面的列表保存全部书目。`book["available"]` 本身就是布尔值，可以直接作为条件。筛选得到 `b1` 和 `b4`：`b2` 评分虽高，却不可借；`b3` 分类不匹配。

这段代码只完成筛选，还没有完成排序，输出仍按原列表的次序排列。排序该怎样做、反复查询时是否值得预先整理，见 <CrossRef id="data-algorithms-and-scale.representation-preprocessing-and-indexes" />。把需求拆成几个操作后，可以分别检查每一步是否满足要求。

## 一个需求可能包含几种不同操作

“筛选书目”和“打开详情”是两种操作。筛选需要检查分类、可借状态和评分；打开详情则已经知道 `id`，只需找到那一本书。按编号查得快，不表示筛选也快。

设计之前，需要估计记录数，以及各类操作发生的次数。例如几十条记录、偶尔查询，与几百万条记录、每秒查询很多次，可能需要不同的组织方式。还要知道记录库是否持续追加、旧记录是否删除，以及一次查询允许等多久。

这些信息暂时不确定时，可以写成明确的方案假设。后续测量或真实用量超过假设，就需要重新评估方案；“数据应该不多”无法给出这个检查点。

## 保留哪些信息

筛选需要分类、可借状态和评分，详情需要编号。如果评分相同时还要按出版时间排序，就必须保留出版时间。

某个字段没有参与这次计算，只说明这次计算不需要读它，不能据此决定从整个记录库删除它。历史查询、审计或其他需求可能仍然需要这个字段。

## 练习

把需求改成“推荐评分最高的三本书”。你会先向提出需求的人确认什么？写出一份能确定答案的约定，再依据上面的四条记录给出结果。检查你的约定能否同时处理评分相同、可选书不足三本这两种情况。
