图书馆提出一项需求：“按分类找出现在能借、评分较高的书。”这句话还不足以确定查询结果。比如，评分 4.0 算不算高？找到多本书以后按什么次序排列？如果只需要三本，又该选哪三本？这些问题决定程序要做哪些计算。

## 输入与输出约定

假定每条书目记录包含唯一编号、分类、可借状态和评分。这里一条记录对应一本书目，暂不考虑同一种书有多册副本的情况。

我们先约定一个完整的筛选操作：

| 项目 | 约定 |
| --- | --- |
| 输入 | 书目列表、目标分类、最低评分 |
| 筛选条件 | 分类相同、当前可借、评分大于或等于最低评分 |
| 输出 | 所有符合条件的书目记录，保持原列表中的先后次序 |
| 无匹配记录 | 返回空列表 |

例如，最低评分是 4.0，评分恰好为 4.0 的书应该入选。一本书即使评分很高，只要已经借出，也不能出现在结果里。若产品希望按评分从高到低排列，还需要另加排序规则；目前的约定保留原次序。

下面用六条记录验证这份约定。`available` 已经是布尔值，可以直接用作条件；`matched` 保存筛选得到的完整记录。

```python run id="data-algorithms-and-scale.from-problem-to-computation.filter"
books = [
    {"id": "b1", "category": "science", "available": True, "rating": 4.0},
    {"id": "b2", "category": "science", "available": False, "rating": 4.9},
    {"id": "b3", "category": "history", "available": True, "rating": 4.7},
    {"id": "b4", "category": "science", "available": True, "rating": 4.5},
    {"id": "b5", "category": "science", "available": True, "rating": 3.0},
    {"id": "b6", "category": "science", "available": False, "rating": 4.8},
]
wanted_category = "science"
threshold = 4.0
matched = []
for book in books:
    if book["category"] == wanted_category and book["available"] and book["rating"] >= threshold:
        matched.append(book)

print("count:", len(matched))
for book in matched:
    print(book["id"], book["rating"])
```

结果按顺序列出 `b1` 和 `b4`。`b2`、`b6` 已借出，`b3` 属于历史类，`b5` 的评分低于门槛。虽然 `b4` 评分更高，它仍排在 `b1` 后面，因为程序按照输入顺序收集记录。

可以把门槛改成 4.5，检查 `b1` 是否被排除；再改成 5.0，检查空结果。改变输入后得到什么结果，应当由约定决定，而不是由某个样例碰巧决定。

## 需求中的操作分解

“按条件筛选”和“按编号打开详情”涉及不同的查找方式。

筛选时，程序要检查书目的分类、可借状态和评分。打开详情时，用户已经指定编号，程序只需定位这一条书目，再读取页面需要的字段。即使我们已经建立了按编号快速查找的字典，分类筛选仍可能需要逐条检查。

选择方案还要知道记录数量、各类查询的发生频率以及更新频率。几十条记录偶尔筛选一次，与几十万条记录每天筛选数万次，适合的数据组织方式可能不同。记录是否经常新增、改分类或借出，以及一次查询可以等待多久，也会影响选择。

在实际数据尚不清楚时，可以明确写下估计的记录数、查询量和可接受耗时。以后用真实数据检查这些假设，才知道何时需要改进。

## 数据选择与信息保留

筛选用到 `category`、`available` 和 `rating`；按编号打开详情还需要 `id`。如果改成“按评分降序，同分时按出版年份排列”，出版年份也会成为计算所需的字段。

一次筛选只读取相关字段即可，原始记录仍应保留其他业务需要的信息。

## 练习

产品现在要求“从所有可借书目中推荐评分最高的三本”。先写出输入、输出、排序及同分时的规则，再用上面六条记录给出结果。规定同分时按编号升序，结果应如何排列？

如果只有两本书可借，或者没有可借书，输出应是什么？将这些情况写入约定，让实现者不必自行猜测。
