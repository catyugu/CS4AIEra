处理一万条记录，可以逐条检查，也可以把每两条记录拿来比较。两个程序都可能只写几行循环，但数据增加时，它们的工作量会拉开差距。分析这种差距，要从实际执行了多少次操作开始。

## 输入规模与计数单位

把列表的元素数记为 $n$，称为<Term id="input-size">输入规模</Term>。先约定一个简化的计数方法：读取列表中的一个位置、比较两个小整数、做一次小整数加法，各算一次固定成本的操作。

这个模型适合分析操作次数随 $n$ 怎样增长。实际耗时还受操作类型、数据和运行环境影响。例如比较很长的字符串，成本还与字符串长度有关。

## 线性增长与二次增长

看两个函数：一个求列表元素之和，另一个列出所有值相等的元素对。两个函数都只做需求规定的计算，没有额外的计数代码。

```python run id="data-algorithms-and-scale.cost-and-growth.sum-and-pairs"
def total(values):
    answer = 0
    for value in values:
        answer += value
    return answer


def equal_pairs(values):
    pairs = []
    for i in range(len(values)):
        for j in range(i + 1, len(values)):
            if values[i] == values[j]:
                pairs.append((i, j))
    return pairs


values = [2, 5, 2, 8]
print("sum:", total(values))
print("equal pairs:", equal_pairs(values))
```

求和循环执行 $n$ 次加法。`equal_pairs` 的内层循环只检查当前位置后面的元素：第一个位置比较 $n-1$ 次，第二个位置比较 $n-2$ 次，依此类推。下标对 `(0, 2)` 表示第一个和第三个元素相等，`(i, j)` 是用元组保存的两个位置。

总比较次数为

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}{2}.
$$

这一次数与实际有多少对相等无关，因为程序会检查所有不同位置的元素对。

| 元素数 | 求和加法次数 | 元素对比较次数 |
| --- | ---: | ---: |
| 100 | 100 | 4950 |
| 200 | 200 | 19900 |
| 400 | 400 | 79800 |

求和次数随 $n$ 成比例增长，称为线性增长；元素对的比较次数含有 $n^2$ 项，称为二次增长。规模翻倍，前者的操作次数翻倍，后者的比值随着规模增大逐渐接近四倍。

读取一个非空列表中已知位置的元素，只需一次读取，属于常数工作量。可见工作量来自执行过程，不能从代码的行数判断。

时间之外还要看额外空间。`total` 只保留一个累加值；`equal_pairs` 保存所有找到的元素对。如果 $n$ 个值全部相等，结果列表就含有 $n(n-1)/2$ 项，所需额外空间也随 $n^2$ 增长。若需求只问“是否存在重复值”，找到第一对便可返回，省掉后续比较和结果列表。**输出要求本身也影响成本。**

## 对数增长

在已排序的列表中查找目标，可以先检查中间位置，再排除一半候选。原来有 16 个可能位置，连续减半后剩下 8、4、2、1；若从 32 个开始，则需要多减半一次。

从 $n$ 个候选不断减半到一个，轮数约为 $\log_2 n$。$\log_2 n$ 表示“2 的多少次方等于 $n$”。因此规模翻倍时，减半轮数只增加约一次，二分查找的最坏比较次数属于对数增长。实际比较几次还取决于边界和终止条件；查找过程见 <CrossRef id="data-algorithms-and-scale.representation-preprocessing-and-indexes" />。

还有一种常见情况：计算分为约 $\log_2 n$ 层，每层都处理 $n$ 个元素，总工作量便约为 $n\log_2 n$。例如归并排序把序列逐层拆分，再在各层合并，合并阶段的总工作符合这一规律。

## 渐近上界与 Θ 记号

分析算法时，通常关心规模足够大以后，操作次数按什么规律增长。$O$（大 O）和 $\Theta$（Theta）用于表达这种关系：

- $O(n^2)$ 是渐近上界：存在常数倍的 $n^2$，在足够大的规模下可以压住操作次数。
- $\Theta(n^2)$ 是渐近紧确界：操作次数在足够大的规模下被两个正的常数倍 $n^2$ 夹住。

例如 $T(n)=3n+2$ 表示规模为 $n$ 时执行 $3n+2$ 次操作。对 $n\ge 1$，有

$$
3n\le T(n)\le 5n.
$$

所以 $T(n)=\Theta(n)$。完整的记号定义可查<Term id="asymptotic-notation">渐近记号</Term>。

求和的加法次数是 $\Theta(n)$，检查全部元素对的比较次数是 $\Theta(n^2)$。线性工作量也满足 $O(n^2)$，因为上界允许比较宽松。想判断规模翻倍后的具体工作量，仍应使用操作次数公式，而不能只看一个大 O 记号。

| 增长阶 | 例子 |
| --- | --- |
| $\Theta(1)$ | 读取已知位置的元素 |
| $\Theta(\log n)$ | 二分查找的最坏比较次数 |
| $\Theta(n)$ | 逐项求和 |
| $\Theta(n\log n)$ | 逐层合并处理元素 |
| $\Theta(n^2)$ | 检查所有元素对 |
| $\Theta(2^n)$ | 对每个子集各做固定数量的工作 |

最后一行的来源是：$n$ 个元素各有“选”或“不选”两种决定，共有 $2^n$ 个子集。元素数每增加一个，子集总数就翻倍。

## 算法复杂度与实际耗时

低增长阶的方案在小数据上未必更省工作。假设方案甲执行 $4n$ 次操作，乙执行 $n(n-1)/2$ 次，且计数单位相同：

| 规模 | 甲：$4n$ | 乙：$n(n-1)/2$ |
| --- | ---: | ---: |
| $n=4$ | 16 | 6 |
| $n=100$ | 400 | 4950 |

在这个成本模型里，$n=4$ 时乙更省，$n=100$ 时甲更省。对于真实程序，还要在目标环境中测量：一次读取、比较、分配内存等操作的成本可能不同，输入的分布也可能影响实际执行次数。具体成本模型可参阅 [MIT 6.006：计算模型与 Python 成本](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-fall-2011/resources/mit6_006f11_lec02/)。

当输入涉及两种独立规模时，也要分开计数。例如有 $n$ 条记录，每条有 $m$ 个指标，逐条读取全部指标会进行 $nm$ 次读取；只有当 $m$ 也与 $n$ 同步增长时，才可以把它看作关于 $n$ 的二次工作量。
