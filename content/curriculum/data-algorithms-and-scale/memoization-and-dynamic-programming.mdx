沿着一排格子前进，每次跨 1 格或 2 格，必须恰好到达终点。只想知道走法有多少种，怎样避免先列出全部走法？

距离是非负整数，步长固定为 1 或 2。到第 4 格有五种：`1+1+1+1`、`1+1+2`、`1+2+1`、`2+1+1` 和 `2+2`。顺序不同算不同走法。可以按第一步分成两组：

| 第一步 | 后面要完成的事 | 第 4 格例子中的走法 |
| --- | --- | --- |
| 跨 1 格 | 走完剩下 3 格 | 1+1+1+1、1+1+2、1+2+1 |
| 跨 2 格 | 走完剩下 2 格 | 2+1+1、2+2 |

每种走法都有且只有一个第一步，两组没有重复，也没有遗漏。因此先算出剩下 3 格和 2 格各有几种，再把两个数量相加，就得到总数。递归与复用都以这种问题拆分为基础。

## 递归会重复计算同一个问题

`ways(remaining)` 表示还剩 `remaining` 格时的走法数。函数调用自己称为递归（recursion）。它仍然遵守普通函数调用的规则：每次调用有自己的参数和局部名字，调用方等待返回值，再继续执行。这里每次算一个更小的问题，剩余距离为 0 或 1 时直接返回，这两个情形是递归的终止条件。

```python run id="data-algorithms-and-scale.memoization-and-dynamic-programming.repeated-solves"
computed = []


def ways(remaining):
    computed.append(remaining)
    if remaining == 0 or remaining == 1:
        return 1
    return ways(remaining - 1) + ways(remaining - 2)


print("ways:", ways(4))
print("computed distances:", computed)
print("times distance 2 was computed:", computed.count(2))
```

剩余 0 格时，有一种走法：不再迈步。剩余 1 格时，只能迈一步。调用 `ways(4)` 时，`ways(3)` 和 `ways(2)` 分别求出 3 和 2，相加得到 5。一次调用得到返回值后，调用方才继续相加；不是两次调用同时执行。

先单独追踪 `ways(2)`，看“调用自己”怎样返回：

| 执行位置 | 动作 | 尚未完成的计算 |
| --- | --- | --- |
| ways(2) | 调用 ways(1) | 等待左边的返回值 |
| ways(1) | 命中终止条件，返回 1 | ways(2) 继续，左边已有 1 |
| ways(2) | 调用 ways(0) | 等待右边的返回值 |
| ways(0) | 命中终止条件，返回 1 | ways(2) 可以相加 |
| ways(2) | 返回 1 + 1，即 2 | 这次调用结束 |

外层的 `remaining` 一直是 2，内层的参数分别是 1 与 0；它们没有改掉外层参数。递归让一次调用暂停去解决较小的问题，返回后继续余下计算。如果较小的问题没有走向终止条件，递归就无法按预期结束。

其中 `ways(2)` 被计算了两遍：`ways(4)` 直接调用一次，`ways(3)` 又调用一次。`computed` 记录函数进入时的距离，`count(2)` 数出 2 出现的次数。

```text
ways(4)
├── ways(3)
│   ├── ways(2)
│   │   ├── ways(1)
│   │   └── ways(0)
│   └── ways(1)
└── ways(2)
    ├── ways(1)
    └── ways(0)
```

两个 `ways(2)` 的输入和规则完全相同，返回值都是 2。终点越远，同样的子问题重复出现得越多。

## 把结果存起来

用字典保存“剩余距离 → 走法数”。再次遇到算过的距离，直接返回已有结果，这叫<Term id="memoization">记忆化</Term>。

```python run id="data-algorithms-and-scale.memoization-and-dynamic-programming.memoized-solves"
memo = {}
computed = []


def ways(remaining):
    if remaining in memo:
        return memo[remaining]
    computed.append(remaining)
    if remaining == 0 or remaining == 1:
        answer = 1
    else:
        answer = ways(remaining - 1) + ways(remaining - 2)
    memo[remaining] = answer
    return answer


print("ways:", ways(4))
print("computed distances:", computed)
print("saved answers:", memo)
```

结果仍是 5，但工作过程变了：

| 调用请求 | 没有记忆化 | 有记忆化 |
| --- | --- | --- |
| 第一次求 `ways(2)` | 求 1、0 两个子问题后相加 | 同样计算，再保存 `memo[2] = 2` |
| 外层再次求 `ways(2)` | 再求一次 1、0，然后相加 | 发现键 2 已存在，直接返回已存的 2 |

调用仍然发生；省掉的是键命中后对这个问题的重新求解。`computed` 放在命中检查之后，所以只记录真正重新求解的距离，0 到 4 各出现一次。若把它移到函数第一行，就会看见包含命中的调用记录；两种计数回答不同问题。

这是自顶向下的记忆化：从原问题递归到较小子问题，算出后保存结果。它有效的前提是，走完同样的剩余距离，不会因为先前采用了不同走法而改变答案。

对于距离 $n$，不同距离至多有 $n+1$ 个；每个距离的答案只重新计算一次。每次求解至多调用两个更小的问题，再做一次加法，因此总调用次数也随 $n$ 线性增长。在字典访问和整数加法按固定成本计的模型下，总工作为 $O(n)$，保存的结果数也是 $O(n)$。走法数不断变大时，整数加法本身的成本也会增加，不能把这个模型直接当成任意大距离的真实耗时。

多用一张结果表减少了重复计算，但仍要逐层进行递归调用。Python 对递归深度有限制；要处理更远的终点，可以保留结果复用，改变求解次序。

## 按依赖次序计算，也能复用结果

也可以按距离从小到大计算，避免递归调用。先保存距离为 0 和 1 的答案，再依次求距离为 2、3、4 的答案，每个新值都使用已经保存的两个较小值：

```python run id="data-algorithms-and-scale.memoization-and-dynamic-programming.bottom-up"
distance = 4
answers = [1, 1]
for remaining in range(2, distance + 1):
    answers.append(answers[remaining - 1] + answers[remaining - 2])
print("ways:", answers[distance])
```

`range(2, distance + 1)` 从 2 开始，包括 `distance`。距离为 0 或 1 时不用进入循环，直接取已有的答案。递归版按调用需要求子问题，循环版按依赖次序求子问题，两者复用的是同一组结果。

这种先求小问题、再逐步求大问题的顺序称为自底向上。动态规划（dynamic programming）把计算组织为一组子问题，并复用它们的结果；这里递归记忆化与自底向上循环分别按“需要哪个就求哪个”和“从小到大逐个求”的次序计算同一组子问题。

自底向上的次序保证了先求出所需结果。计算距离 4 时，3 和 2 的答案已经在表中；计算距离 5 时，4 和 3 又已经在表中。需要检查的依赖关系是：每次用到某个子问题的结果时，它是否已经求出。

## 哪些信息决定一个可复用的结果

现在改一条规则：不能连续跨两次 2 格。还剩 2 格时，结果如下：

| 上一步 | 可以采用的后续走法 | 走法数 |
| --- | --- | ---: |
| 跨了 1 格 | 1+1 或 2 | 2 |
| 跨了 2 格 | 只能 1+1 | 1 |

剩余距离相同，答案却不同。旧的 `memo[2]` 只有一个位置，无法同时表示这两项结果。需要以 `(remaining, last_step)` 为键，把剩余距离和上一步共同作为查找条件；整数元组可以作为字典键。

这里的**状态**是决定接下来怎样计算的信息。上一步会限制现在的选择，所以要保存；更早的全部步数不会增加其他限制，就无须保存整段走法。这样既保留了求解所需信息，又让不同历史能够复用相同的后续问题。

还要确认计算规则和外部输入没有变化。例如规则固定为“跨 1 或 2 格”时，按距离缓存足够；改成“跨 1 或 3 格”后，即使距离相同，旧答案也不能直接使用。可以为新规则重新建立缓存，或把规则放进缓存键。缓存命中只说明键相同，不能替程序证明答案仍然适用。

状态复用的成本取决于有多少种完整状态，以及求解每一种需要多少工作。状态本身很多时，存下每个结果也可能做不完，见 <CrossRef id="data-algorithms-and-scale.search-pruning-and-branch-and-bound" />。

## 练习

下面的函数处理“不能连续跨两次 2 格”的规则。先分别列出还剩 2 格、上一步为 1 格或 2 格时的合法走法，再预测两次调用的输出。交换两次调用的次序，结果是否还符合规则？如果需要修改，怎样让同一份缓存安全地服务这两次调用？

```python run id="data-algorithms-and-scale.memoization-and-dynamic-programming.exercise-cache-key"
memo = {}


def ways(remaining, last_step):
    key = remaining
    if key in memo:
        return memo[key]
    if remaining == 0:
        answer = 1
    else:
        answer = ways(remaining - 1, 1)
        if remaining >= 2 and last_step != 2:
            answer += ways(remaining - 2, 2)
    memo[key] = answer
    return answer


print("after step 2:", ways(2, 2))
print("after step 1:", ways(2, 1))
```
