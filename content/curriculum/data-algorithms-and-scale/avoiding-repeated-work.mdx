从起点走到终点，每步可以跨 1 格或 2 格。终点距离起点 4 格时，有五种走法：`1+1+1+1`、`1+1+2`、`1+2+1`、`2+1+1` 和 `2+2`。

输入允许剩余距离为非负整数，步长固定为 1 或 2。怎样计算更远的终点有多少种走法？先跨 1 格，剩下的距离少 1；先跨 2 格，剩下的距离少 2。两种开头互不重叠，把后续走法数相加即可。

## 递归会重复计算同一个问题

`ways(remaining)` 表示还剩 `remaining` 格时的走法数。函数调用自己称为递归（recursion）。每次调用都要算一个更小的问题，直到剩余距离为 0 或 1，可以直接给出答案。

```python run id="data-algorithms-and-scale.avoiding-repeated-work.repeated-solves"
computed = []


def ways(remaining):
    computed.append(remaining)
    if remaining == 0 or remaining == 1:
        return 1
    return ways(remaining - 1) + ways(remaining - 2)


print("ways:", ways(4))
print("computed distances:", computed)
print("times distance 2 was computed:", computed.count(2))
```

剩余 0 格时，有一种走法：不再迈步。剩余 1 格时，只能迈一步。调用 `ways(4)` 时，`ways(3)` 和 `ways(2)` 分别求出 3 和 2，相加得到 5。一次调用得到返回值后，调用方才继续相加；不是两次调用同时执行。

其中 `ways(2)` 被计算了两遍：`ways(4)` 直接调用一次，`ways(3)` 又调用一次。`computed` 记录函数进入时的距离，`count(2)` 数出 2 出现的次数。

```text
ways(4)
├── ways(3)
│   ├── ways(2)
│   │   ├── ways(1)
│   │   └── ways(0)
│   └── ways(1)
└── ways(2)
    ├── ways(1)
    └── ways(0)
```

两个 `ways(2)` 的输入和规则完全相同，返回值都是 2。终点越远，同样的子问题重复出现得越多。

## 把结果存起来

用字典保存“剩余距离 → 走法数”。再次遇到算过的距离，直接返回已有结果，这叫<Term id="memoization">记忆化</Term>。

```python run id="data-algorithms-and-scale.avoiding-repeated-work.memoized-solves"
memo = {}
computed = []


def ways(remaining):
    if remaining in memo:
        return memo[remaining]
    computed.append(remaining)
    if remaining == 0 or remaining == 1:
        answer = 1
    else:
        answer = ways(remaining - 1) + ways(remaining - 2)
    memo[remaining] = answer
    return answer


print("ways:", ways(4))
print("computed distances:", computed)
print("saved answers:", memo)
```

结果仍是 5，但距离 0 到 4 各自只计算一次。把调用改成 `ways(8)`，仍只有 9 种不同距离，各算一次；没有保存结果的版本却会进入函数 67 次。

对于距离 $n$，至多保存 $n+1$ 个结果。若把字典访问和整数加法按固定成本计，每个距离只需固定数量的操作，总工作与 $n$ 成正比。代价是多用一张表，而且递归调用仍有深度；终点非常远时，Python 的递归深度限制也需要考虑。这里的目的在于观察复用，而非推荐递归处理任意大的输入。

## 字典的键必须足以决定答案

现在改一条规则：不能连续跨两次 2 格。还剩 2 格时，如果上一步跨了 1 格，可以选 `1+1` 或 `2`；如果上一步跨了 2 格，只能选 `1+1`。剩余距离相同，答案却不同。

这时只用距离作键会混淆两个问题。必须同时记录上一步迈了几格：

```python run id="data-algorithms-and-scale.avoiding-repeated-work.state-columns"
memo = {}


def ways(remaining, last_step):
    key = (remaining, last_step)
    if key in memo:
        return memo[key]
    if remaining == 0:
        answer = 1
    else:
        answer = ways(remaining - 1, 1)
        if remaining >= 2 and last_step != 2:
            answer += ways(remaining - 2, 2)
    memo[key] = answer
    return answer


print("after step 1:", ways(2, 1))
print("after step 2:", ways(2, 2))
print("from the start:", ways(4, 0))
```

前两个输出分别是 2 和 1。`last_step = 0` 表示还没有迈出第一步。这里的计算状态是 `(remaining, last_step)`：知道这两个值，才知道可以怎样继续。

保存结果时还要留意规则是否变化。若步长或限制发生变化，旧表里的结果不能直接沿用；规则需要固定，或也成为键的一部分。

## 不同状态太多，复用也未必够用

有些问题的状态要记录“已经选了哪些元素”。$n$ 个元素可能组成 $2^n$ 个子集。即使每个子集只计算一次，也可能有这么多不同状态需要处理。

| 元素数 | 可能的子集数 |
| --- | ---: |
| 10 | 1024 |
| 20 | 1048576 |
| 30 | 1073741824 |

复用减少的是重复计算，不能保证不同状态的数量很少。能否完成，还要估算每个状态的处理成本和存储成本；候选过多时的取舍见 <CrossRef id="data-algorithms-and-scale.search-space-and-pruning" />。


## 练习

一份仿真计算用 `score(parameters, model_version)` 返回确定的指标值，两次使用相同参数和模型版本时结果相同。缓存只以 `parameters` 为键是否足够？构造模型版本不同、结果也不同的情况，说明键要包含什么。若模型改变却没有改变版本号，这份缓存还能可靠吗？
