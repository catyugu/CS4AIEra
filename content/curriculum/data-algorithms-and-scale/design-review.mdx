图书馆的书目查询功能准备上线。第一课实现了按分类、可借状态和评分门槛筛选，结果保持原始次序。现在产品增加一条要求：**按评分从高到低返回，同分时按编号升序排列。** 一次查询必须同时完成筛选与排序。

有人提出以下实现：

> 用以 `id` 为键的字典保存书目。打开详情时直接按键查找；按条件筛选时遍历字典中的全部记录，再将命中的书按评分排序。字典查找很快，这个方案应该也能满足筛选需求。

评审这份方案，需要把“按编号查找”和“按条件筛选”分开估算。书库会不断增大，借出、归还和修改分类也会改变查询结果。目前的工作负载估计如下：

| 项目 | 规模或频率 |
| --- | --- |
| 书目数量 | 50000 条，每月增长约 5% |
| 条件筛选 | 每天约 20000 次 |
| 按编号打开详情 | 每天约 2000 次 |
| 追加或更新记录 | 每天约 200 次 |
| 分类 | 20 类，各类记录数量尚未统计 |

## 索引支持的查询

用编号作字典键，可以直接找到对应的书目。条件筛选依赖分类、可借状态和评分；这些字段保存在字典的值里，以编号建立的索引没有按它们整理数据，因此仍需检查所有记录。

假设每次筛选都检查 $n$ 条书目，一天的检查次数是 $20000n$：

| 时点 | 书目数量约为 | 每天检查记录的总条次约为 |
| --- | ---: | ---: |
| 当前 | 50000 | 10 亿 |
| 一年后，每月增长 5% | $50000\times1.05^{12}\approx89800$ | 18 亿 |

这里的“十亿条次”是一天所有筛选请求合计的检查次数；同一本书可能被反复检查。它是工作量估计，尚不能直接换算为耗时。还需要测量每次查询花多长时间，以及业务允许用户等待多久。

筛选命中 $r$ 条记录后，要按评分排序。一般比较排序的成本上界是 $O(r\log r)$。总成本既包括查找候选记录，也包括检查条件、排序和返回结果。如果筛选已经耗掉大部分时间，即使按编号查找很快，也解决不了瓶颈。

## 预处理、查询与更新成本

可以为分类筛选另外组织数据。下面比较三种选择，$k$ 表示目标分类中的记录数，$r$ 表示最终命中的记录数：

| 方案 | 每次筛选 | 初始准备与后续更新 |
| --- | --- | --- |
| 全库扫描 | 检查 $n$ 条，再排序 $r$ 条 | 无额外分类索引 |
| 先按分类排序 | 二分找到分类范围，检查其中 $k$ 条，再排序 $r$ 条 | 初次排序；追加或改分类时维护有序性 |
| 分类到书目列表的索引 | 直接取目标分类的 $k$ 条并检查，再排序 $r$ 条 | 初次分组、额外空间；追加或改分类时维护分组 |

按分类整理可以缩小筛选范围，但分类顺序本身不能替代评分排序。筛选是否值得建索引，要看 $k$ 通常有多大、查询与更新各有多少，以及索引维护的实际成本。

用第一课的六条书目记录演示。为打开详情建立 `by_id`，为条件筛选建立 `by_category`。两张索引保存的是同一批记录对象的引用。`search` 负责完整的筛选与排序，两种方案只改变传给它的候选范围。

```python run id="data-algorithms-and-scale.design-review.group-query"
books = [
    {"id": "b1", "category": "science", "available": True, "rating": 4.0},
    {"id": "b2", "category": "science", "available": False, "rating": 4.9},
    {"id": "b3", "category": "history", "available": True, "rating": 4.7},
    {"id": "b4", "category": "science", "available": True, "rating": 4.5},
    {"id": "b5", "category": "science", "available": True, "rating": 3.0},
    {"id": "b6", "category": "science", "available": False, "rating": 4.8},
]
by_id = {}
by_category = {}
for book in books:
    by_id[book["id"]] = book
    category = book["category"]
    if category not in by_category:
        by_category[category] = []
    by_category[category].append(book)


def sort_key(book):
    return (-book["rating"], book["id"])


def search(records, category, threshold):
    matched = []
    for book in records:
        if book["category"] == category and book["available"] and book["rating"] >= threshold:
            matched.append(book)
    return sorted(matched, key=sort_key)


whole = search(books, "science", 4.0)
grouped = search(by_category.get("science", []), "science", 4.0)
print("whole scan:", [book["id"] for book in whole])
print("category index:", [book["id"] for book in grouped])
print("records checked:", len(books), len(by_category["science"]))
print("detail rating:", by_id["b4"]["rating"])
```

两次筛选都返回 `["b4", "b1"]`：评分 4.5 的 `b4` 排在评分 4.0 的 `b1` 前。`sort_key` 返回一对用于排序的值。Python 按元组从左到右比较；评分取负数后，高分排在前面，评分相同时再按编号升序排列。`sorted` 返回一个排好序的新列表，原始书目记录没有被重新排列。

全库扫描检查六条记录，分类索引只检查五条。这个小样本主要用于核对结果正确性；用它证明性能优势还太早。若 20 类书目数量接近，$k$ 才可能大致是 $n/20$；如果某一类占了大部分记录，索引对那一类查询的帮助就有限。

## 数据更新与索引维护

分类索引保存“分类 → 书目列表”的关系。借出一本书时，若只是将记录的 `available` 改为 `False`，`search` 会读取更新后的状态；分类不变，无须移动这条索引记录。

修改分类则不同。假设把 `b1` 从科学类改为历史类，必须同时修改记录字段和索引分组：

| 更新状态 | science 分组 | history 分组 | `b1` 的分类 |
| --- | --- | --- | --- |
| 修改前 | b1、b2、b4、b5、b6 | b3 | science |
| 正确修改后 | b2、b4、b5、b6 | b3、b1 | history |
| 只修改记录字段 | b1、b2、b4、b5、b6 | b3 | history |

在最后一种状态下，按历史类查询会漏掉 `b1`。`b1` 仍在科学类列表中，但查询时又会因分类不匹配被排除。共享对象使字段修改立即可见，却不会自动更新它属于哪个分组。

正确的维护过程是先记住旧分类，从旧分组移除 `b1`，修改记录的分类字段，再将它加入新分组。若分组用列表保存，移除时可能需要搜索旧列表，更新成本也要计入方案比较。可以用修改前后分别按科学类、历史类查询，检查记录是否恰好出现在正确的分组。

编号索引也有自己的约束：本例假定书目编号唯一。如果不同记录使用相同编号，向 `by_id` 的同一键写入新值会覆盖原映射。若要保存同一种书的多册副本，必须先明确编号标识书目还是单册，再设计数据表示。

因此，对工作负载的现阶段判断是：**分类索引有机会减少大量重复扫描，值得实现并测量；是否采用，还要看分类分布、查询耗时和更新成本。** 这个结论来自已知的操作频率与成本结构，并没有假设每类书目平均分布。

## 练习

为了进一步缩小候选范围，有人只把当前可借的书放进分类索引。下面单独用两条书目测试这种做法。先预测输出，再修改代码，使借出和归还之后的查询仍能找到全部可借书目。

```python run id="data-algorithms-and-scale.design-review.exercise-availability-index"
books = [
    {"id": "b1", "category": "science", "available": True},
    {"id": "b2", "category": "science", "available": False},
]
available_by_category = {"science": []}
for book in books:
    if book["available"]:
        available_by_category[book["category"]].append(book)

books[0]["available"] = False
books[1]["available"] = True
matched_ids = []
for book in available_by_category["science"]:
    if book["available"]:
        matched_ids.append(book["id"])
print("available science books:", matched_ids)
```

再分析两项需求变化：

- 分类很少改变，但借出和归还频繁发生。相较于保存某分类的全部书目，只保存可借书目会增加哪些索引维护工作？它节省了哪部分查询成本？
- 查询改成“只返回评分最高的十本”。扫描到十本就停止，能否保证它们是最高分的十本？构造一个反例。若希望只保留十个候选，继续扫描时需要支持怎样的替换操作？同分时按编号升序的规则是否也影响这个判断？
