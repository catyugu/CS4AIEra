这个模型是后续所有内容的共同前提。函数参数传递、类属性与实例属性、闭包捕获的变量、并发下的共享状态、数据库事务里的两个视图，处理的都是同一件事：谁在什么时候能看到对哪个对象的修改。

读一段代码时的第一步判断是：这条语句创建或找到了哪个对象，哪个名字绑定到它，还有谁绑定到同一个对象。

## 名称、对象与引用关系

- **对象**有三个属性：身份（identity）、类型（type）、值（value）。身份在对象的整个存活期内不变，两个存活的对象身份不同；`id(x)` 给出身份对应的整数。
- **名称**是命名空间中的一项绑定。名称指向对象，不持有数据的副本。
- `name = expr` 的语义分两步：先求值 `expr` 得到一个对象，再把当前命名空间中的 `name` 绑定到该对象。语句执行前后，任何对象都没有被改写。
- 读取名称是解引用，取回它当前指向的对象。
- 两个名称指向同一对象时，称它们互为<Term id="alias">别名</Term>。

由此得到两条必须分开的规则：

| 操作 | 形式 | 效果 |
| --- | --- | --- |
| 修改对象 | `x.append(1)`、`x.sort()`、`x[k] = v` | 所有指向该对象的名称都观察到变化 |
| 重绑定名称 | `x = expr` | 只有被重新绑定的那个名称改变指向 |

链式赋值 `a = b = []` 把两个名称绑定到同一个列表，`a.append(1)` 之后 `b` 也是 `[1]`；需要两个独立容器时写两条独立的赋值。

## 修改对象与重绑定名称

```python run id="py.names.binding"
a = [1, 2]
b = a
b.append(3)
print("a =", a)
print("b =", b)
print("a is b:", a is b)

b = [7]
print("a =", a)
print("b =", b)
print("a is b:", a is b)
```

`b = a` 之后两个名称指向同一个列表，`append` 通过 `b` 修改了这个列表，因此 `a` 也看到 `[1, 2, 3]`。`b = [7]` 创建了新列表并把 `b` 换指过去，`a` 仍绑定在原来的列表上，于是 `a is b` 变为 `False`。`del name` 删除的是名称本身：对象只有在没有任何引用之后才被回收，删除一个名称不影响其他名称。`b = a[:]`、`dict(d)`、`list(x)` 消除的是外层容器的别名，元素仍然共享，复制的深度与共享子图的完整模型由 <CrossRef id="python.mutability-and-copy" /> 处理。

## 身份与相等

两种关系回答不同的问题：

| 表达式 | 判据 | 说明 |
| --- | --- | --- |
| `x is y` | 是否同一个对象 | 由语言保证：对存活对象，`is` 为真当且仅当身份相同 |
| `x == y` | rich comparison 协议的结果，通常从 `x.__eq__(y)` 开始 | 默认实现比较身份，类可以重新定义；反射与 `NotImplemented` 的回退见 <CrossRef id="python.dunder-protocols" /> |

```python run id="py.names.identity"
x = [1, 2]
y = [1, 2]
z = x
print("x == y:", x == y)
print("x is y:", x is y)
print("x is z:", x is z)


class Tagged:
    pass


t = Tagged()
print("t == Tagged():", t == Tagged())
print("t is t:", t is t)
```

`x` 与 `y` 内容相同但是两个对象，`==` 为真而 `is` 为假。`z` 是 `x` 的别名，两者 `is` 为真。自定义类没有定义 `__eq__` 时，相等退化到身份比较：`Tagged()` 的每个实例只与自身相等。

`is` 与 `==` 是两个独立的判定：同一对象与自身 `is` 恒为真，而 `x = float("nan")` 之后 `x == x` 为假；内容相同而身份不同的对象可以相等，也存在身份相同而 `__eq__` 判定不等的对象（NaN 就是后者）。两者的完整契约由 <CrossRef id="python.equality-and-hashing" /> 展开。小整数、短字符串与空元组可能被实现缓存而复用同一对象：`int("256") is int("256")` 在这台运行时为真，`int("257") is int("257")` 为假，这是 CPython 的实现行为，不是语言保证。`is` 的正确用途是 `None`、哨兵对象与显式身份判断；`id` 只在对象存活期内有效，对象被回收后地址可能被复用，把 `id` 写入日志或存储后再比对会给出错误结论。

## 不可变对象没有原地修改

`int`、`float`、`str`、`tuple` 不提供原地修改的操作。所有看起来在改它们的语句都产生新对象并把名称重绑定过去。

```python run id="py.names.immutable"
s = "ab"
t = s
s = s + "c"
print("s =", s)
print("t =", t)
print("s is t:", s is t)
print("lengths:", len(s), len(t))
```

`t` 保持 `"ab"`。`s + "c"` 创建了第三个字符串对象，`s` 换指它，`t` 的绑定没有受到影响。不可变对象因此不存在「一个名字的修改被另一个名字看到」这类问题。

## 函数边界

函数调用按对象绑定传参：实参对象被绑定到形参名。由此产生两种结果完全不同的写法。

```python run id="py.names.arguments"
def grow(values):
    values.append(99)


def replace(values):
    values = values + [99]


data = [1]
grow(data)
print("after grow:   ", data)
replace(data)
print("after replace:", data)
```

`grow` 对形参指向的对象做了原地修改，调用方看到 `[1, 99]`。`replace` 只在函数内把形参重绑定到新对象，调用方的 `data` 不变。两个函数的签名相同，接口语义不同。

形参是否会原地修改实参属于接口契约的一部分。契约无法从签名看出，只能写进文档，或通过返回新对象、传入副本、返回不可变视图来体现在代码里。

## 复合赋值的两种语义

`x += y` 先对 target 求值一次，再按 `x` 的类型查找对应的 in-place operation（`+=` 找 `__iadd__`）。该 operation 可能修改原对象并返回它，也可能返回另一个对象；无论哪种情形，结果都重新赋给那个 target。类型没有对应的 in-place operation 时走普通二元运算的回退路径，效果等同于 `x = x + y`。

target 只求值一次这一点与类型无关：`a[f()] += y` 只调用 `f()` 一次，`a[f()] = a[f()] + y` 调用两次。in-place operation 按运算符提供，不按类型提供：列表定义了 `__iadd__`（`+=`），集合与字典对应的是 `|=`（`__ior__`），因此 `+=` 只在 `+` 本身有定义的类型上成立。

```python run id="py.names.augmented"
items = [1]
items_alias = items
items += [2]
print("items:      ", items)
print("items_alias:", items_alias)
print("same object:", items is items_alias)

pair = (1,)
pair_alias = pair
pair += (2,)
print("pair:      ", pair)
print("pair_alias:", pair_alias)
print("same object:", pair is pair_alias)
```

同一个 `+=` 在列表上修改对象（别名看到变化），在元组上重绑定名称（别名不变）：元组没有 `__iadd__`，走回退路径。读代码时不能从运算符的字面形式推断对象有没有被修改，判据是类型是否提供对应的 in-place operation；提供了也不保证沿用原对象。

集合与字典的原地合并走 `|=`：

```python run id="py.names.augmented-operators"
numbers = {1, 2}
alias = numbers
numbers |= {3}
print("set  |=", numbers, numbers is alias)

mapping = {"a": 1}
mapping_alias = mapping
mapping |= {"b": 2}
print("dict |=", mapping, mapping is mapping_alias)

try:
    numbers += {4}
except TypeError as failure:
    print("set  +=", type(failure).__name__, "-", failure)
```

`numbers |= {3}` 修改原集合，`alias` 跟着变化；这里失败的原因是 `+` 没有为集合定义，与原地机制无关。读代码时把 `+=`、`|=`、`&=` 一律当成「原地修改」会在不支持该运算符的类型上给出错误预测。

in-place operation 返回另一个对象是合法的，此时别名看不到变化，尽管类型确实提供了该方法：

```python run id="py.names.augmented-custom"
class Buffer:
    def __init__(self, text):
        self.text = text

    def __iadd__(self, other):
        return Buffer(self.text + other)


original = Buffer("a")
alias = original
original += "b"
print("after +=, text is:", original.text)
print("alias text is:   ", alias.text)
print("same object:", original is alias)
```

`Buffer.__iadd__` 存在，但返回的是新对象，`alias` 仍指向旧对象。判据是运算结果是不是原对象，`+=` 这个写法本身不保证任何一项。
