## 目的

本课建立 Python 的名称与对象模型：赋值语句改变了什么，身份与相等如何区分，共享结构如何跨越函数边界传播。

这个模型是后续所有内容的共同前提。函数参数传递、类属性与实例属性、闭包捕获的变量、并发下的共享状态、数据库事务里的两个视图，处理的都是同一件事：谁在什么时候能看到对哪个对象的修改。

读一段代码时的第一步判断是：这条语句创建或找到了哪个对象，哪个名字绑定到它，还有谁绑定到同一个对象。

## 模型

- **对象**有三个属性：身份（identity）、类型（type）、值（value）。身份在对象的整个存活期内不变，两个存活的对象身份不同；`id(x)` 给出身份对应的整数。
- **名称**是命名空间中的一项绑定。名称指向对象，不持有数据的副本。
- `name = expr` 的语义分两步：先求值 `expr` 得到一个对象，再把当前命名空间中的 `name` 绑定到该对象。语句执行前后，任何对象都没有被改写。
- 读取名称是解引用，取回它当前指向的对象。
- 两个名称指向同一对象时，称它们互为<Term id="alias">别名</Term>。

由此得到两条必须分开的规则：

| 操作 | 形式 | 效果 |
| --- | --- | --- |
| 修改对象 | `x.append(1)`、`x.sort()`、`x[k] = v` | 所有指向该对象的名称都观察到变化 |
| 重绑定名称 | `x = expr` | 只有被重新绑定的那个名称改变指向 |

## 修改对象与重绑定名称

```python run id="py.names.binding"
a = [1, 2]
b = a
b.append(3)
print("a =", a)
print("b =", b)
print("a is b:", a is b)

b = [7]
print("a =", a)
print("b =", b)
print("a is b:", a is b)
```

`b = a` 之后两个名称指向同一个列表，`append` 通过 `b` 修改了这个列表，因此 `a` 也看到 `[1, 2, 3]`。`b = [7]` 创建了新列表并把 `b` 换指过去，`a` 仍绑定在原来的列表上，于是 `a is b` 变为 `False`。

## 身份与相等

两种关系回答不同的问题：

| 表达式 | 判据 | 说明 |
| --- | --- | --- |
| `x is y` | 是否同一个对象 | 由语言保证：对存活对象，`is` 为真当且仅当身份相同 |
| `x == y` | `x.__eq__(y)` 的判定结果 | 默认实现比较身份，类可以重新定义 |

```python run id="py.names.identity"
x = [1, 2]
y = [1, 2]
z = x
print("x == y:", x == y)
print("x is y:", x is y)
print("x is z:", x is z)


class Tagged:
    pass


t = Tagged()
print("t == Tagged():", t == Tagged())
print("t is t:", t is t)
```

`x` 与 `y` 内容相同但是两个对象，`==` 为真而 `is` 为假。`z` 是 `x` 的别名，两者 `is` 为真。自定义类没有定义 `__eq__` 时，相等退化到身份比较：`Tagged()` 的每个实例只与自身相等。

身份相同必然相等（对行为正常的对象），相等不蕴含身份相同。相等与哈希的完整契约由 <CrossRef id="python.equality-and-hashing" /> 展开。

## 不可变对象没有原地修改

`int`、`float`、`str`、`tuple` 不提供原地修改的操作。所有看起来在改它们的语句都产生新对象并把名称重绑定过去。

```python run id="py.names.immutable"
s = "ab"
t = s
s = s + "c"
print("s =", s)
print("t =", t)
print("s is t:", s is t)
print("lengths:", len(s), len(t))
```

`t` 保持 `"ab"`。`s + "c"` 创建了第三个字符串对象，`s` 换指它，`t` 的绑定没有受到影响。不可变对象因此不存在「一个名字的修改被另一个名字看到」这类问题。

## 函数边界

函数调用按对象绑定传参：实参对象被绑定到形参名。由此产生两种结果完全不同的写法。

```python run id="py.names.arguments"
def grow(values):
    values.append(99)


def replace(values):
    values = values + [99]


data = [1]
grow(data)
print("after grow:   ", data)
replace(data)
print("after replace:", data)
```

`grow` 对形参指向的对象做了原地修改，调用方看到 `[1, 99]`。`replace` 只在函数内把形参重绑定到新对象，调用方的 `data` 不变。两个函数的签名相同，接口语义不同。

形参是否会原地修改实参属于接口契约的一部分。契约无法从签名看出，只能写进文档，或通过返回新对象、传入副本、返回不可变视图来体现在代码里。

## 复合赋值的两种语义

`x += y` 先查找 `x` 类型上的 `__iadd__`。列表、集合、字典等提供原地版本，运算结果绑定回原对象；没有原地版本的类型退化为 `x = x + y`，产生新对象。

```python run id="py.names.augmented"
items = [1]
items_alias = items
items += [2]
print("items:      ", items)
print("items_alias:", items_alias)
print("same object:", items is items_alias)

pair = (1,)
pair_alias = pair
pair += (2,)
print("pair:      ", pair)
print("pair_alias:", pair_alias)
print("same object:", pair is pair_alias)
```

同一个 `+=` 在列表上修改对象（别名看到变化），在元组上重绑定名称（别名不变）。读代码时 `x += y` 与 `x = x + y` 并不等价，区别取决于类型。

## 边界与失败情形

- **链式赋值引入别名**：`a = b = []` 把两个名称绑定到同一个列表；`a.append(1)` 之后 `b` 也是 `[1]`。需要两个独立容器时应写两条独立的赋值。
- **`is` 与对象缓存**：小整数、短字符串、空元组可能被实现缓存而复用同一对象。`int("256") is int("256")` 在这台运行时为真、`int("257") is int("257")` 为假，这是 CPython 的实现行为，不是语言保证。`is` 的正确用途是 `None`、哨兵对象与显式身份判断。
- **`id` 不是持久标识**：`id` 只在对象存活期内有效。对象被回收后地址可能被后来的对象复用，把 `id` 写入日志或存储后再比对会给出错误结论。
- **`del` 解除绑定**：`del name` 删除名称本身。对象只有在没有任何引用后才被回收，删除一个名称不影响其他名称。
- **浅拷贝仍然共享**：`b = a[:]`、`dict(d)`、`list(x)` 消除的是外层容器的别名，元素仍然共享。复制的深度、共享子图与环的完整模型由 <CrossRef id="python.mutability-and-copy" /> 处理。
- **修改输入对象的契约要写下来**：函数是否就地修改参数、是否返回内部容器，决定了调用方能否复用数据，这类契约无法从签名看出。
