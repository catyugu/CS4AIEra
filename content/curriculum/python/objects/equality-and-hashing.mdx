上一课的结论是对象可以被多个名称共享并就地修改。它的直接后果是：哈希表用插入时算出的哈希值决定条目的位置，用相等比较确认候选。参与哈希的字段在插入之后改变，条目仍然在表里，查找路径却不再经过它。

这类失效没有异常也没有警告：查找返回「不存在」，重新插入产生重复条目，集合去重静默失效。

## 模型

- `__eq__` 定义等价关系：自反、对称、传递。`==` 调用它，结果为 `NotImplemented` 时交给另一方处理；跨类型比较在无法判定时应返回 `NotImplemented` 而不是 `False`，两者是不同的结论，否则 `Money(1) == 1` 与 `1 == Money(1)` 可能给出不同结果。子类继承 `__eq__` 又新增字段时，两个不同子类的实例可能都与父类实例相等，等价关系不再传递。
- `__hash__` 把对象映射到整数。相等与哈希的契约是单向的：`a == b` 蕴含 `hash(a) == hash(b)`。逆命题不成立，不同的值可以有相同的哈希，这种情形称为<Term id="hash-collision">哈希冲突</Term>。哈希值不是标识：CPython 对字符串与字节的哈希做随机化（`PYTHONHASHSEED`），跨进程、跨运行不保证一致，把哈希值写入存储、缓存键名或日志后再比对会得到错误结论；需要稳定输出时显式排序，哈希随机化属于实现行为（见 <CrossRef id="python.runtime-vs-language" />）。
- 哈希表用哈希值选定候选位置，再用 `==` 在候选之间确认目标。冲突由确认步骤吸收，不破坏正确性。
- 默认的 `__eq__` 比较身份，默认的 `__hash__` 基于身份，因此两个内容相同的实例默认是两个不同的键；用默认的身份哈希作键时，跨进程或反序列化得到的「同一个值」会成为不同的键，缓存与去重都不生效。
- 一个类定义 `__eq__` 而未定义 `__hash__` 时，`__hash__` 被置为 `None`，实例变为不可哈希。可哈希的类需要显式给出 `__hash__`，并且只用不参与可变状态的字段计算。

## 跨类型的相等

```python run id="py.hash.cross-type-keys"
print("hashes:", hash(1) == hash(1.0) == hash(True))
print("equalities:", 1 == 1.0 == True)

table = {1: "int", 1.0: "float", True: "bool"}
print("entries:", table)
print("len:", len(table))
```

数值相等跨类型成立，哈希值也随之相同，因此 `1`、`1.0`、`True` 落在同一个键上。字典保留最后写入的值，长度仍为 1。从 JSON 或配置文件读到的 `1` 与 `true` 在 Python 中无法共存于同一个字典，去重与计数会因此少算。`-0.0` 与 `0.0` 相等且哈希相同，作为键时也是同一个键。

## 插入后修改键

```python run id="py.hash.mutable-key"
class Key:
    def __init__(self, value):
        self.value = value

    def __hash__(self):
        return hash(self.value)

    def __eq__(self, other):
        return isinstance(other, Key) and self.value == other.value


key = Key(1)
lookup = {key: "stored"}
print("before mutation:", lookup.get(key))

key.value = 2
print("after mutation: ", lookup.get(key))
print("membership:     ", key in lookup)
print("entries:        ", len(lookup))

lookup[Key(2)] = "reinserted"
print("after reinserting the same value:", len(lookup))
print("lookup by a fresh Key(2):", lookup.get(Key(2)))
```

修改 `key.value` 之后，查找、成员判定都失败，而 `len(lookup)` 仍为 1：条目没有消失，只是位于旧哈希对应的位置上。用 `Key(2)` 重新赋值不会更新原条目，而是在新哈希的位置上插入第二个条目，于是表里出现两个 `__eq__` 判定相等的键。这个对象就是<Term id="mutable-key">可变键</Term>。自定义的 `__hash__` 一旦用到可变字段，对象被修改后哈希随之变化，查找变成静默失败，没有任何可观测信号；包含列表字段的对象默认不可哈希。

## 定义 `__eq__` 的后果

```python run id="py.hash.unhashable"
class Money:
    def __init__(self, cents):
        self.cents = cents

    def __eq__(self, other):
        return isinstance(other, Money) and self.cents == other.cents


class FrozenMoney(Money):
    def __hash__(self):
        return hash(self.cents)


print("Money.__hash__ is:", Money.__hash__)
print("FrozenMoney.__hash__ is None:", FrozenMoney.__hash__ is None)

try:
    {Money(100): "coffee"}
except TypeError as exc:
    print("failed:", type(exc).__name__, "|", "unhashable" in str(exc))

print("frozen works:", {FrozenMoney(100): "coffee"}[FrozenMoney(100)])
```

类一旦定义 `__eq__`，Python 把 `__hash__` 置为 `None`，把它放进字典或集合抛出 `TypeError`。异常消息的具体文本随版本变化，判据是类型名与「不可哈希」这一事实。可哈希性需要显式恢复；`FrozenMoney` 用不变字段 `cents` 计算哈希，因此可以作键。改了 `__eq__` 而没有同步 `__hash__`，字典与集合的行为会静默错误。数据类上的同一个问题表现为：`eq=True` 且未冻结时实例不可哈希，`frozen=True` 时按字段生成 `__hash__`。

## 哈希定位与相等确认

```python run id="py.hash.confirms"
class Always:
    def __init__(self, value):
        self.value = value

    def __hash__(self):
        return 1

    def __eq__(self, other):
        return isinstance(other, Always) and self.value == other.value


table = {Always("a"): 1, Always("b"): 2, Always("c"): 3}
print("same hash:", hash(Always("a")) == hash(Always("b")))
print("distinct keys:", len(table))
print("lookup:", table[Always("b")])

nan = float("nan")
sameness = {nan: "same object"}
print("lookup with the same nan object:", sameness[nan], nan in sameness)
print("lookup with a fresh nan:", float("nan") in {float("nan"): 1})
print("nan == nan:", nan == nan)
```

三个对象的哈希完全相同，字典仍然区分它们：查找先定位到同一个候选集合，再逐个用 `==` 确认，因此结果是确定的。冲突只增加比较次数，不改变语义，代价是哈希在每次查找时都要计算，过重的 `__hash__` 会让字典与集合退化为昂贵的操作。

NaN 展示同一机制的另一面。`nan == nan` 为假，因此一个新的 NaN 对象找不到任何以 NaN 为键的条目。但 Python 在调用 `==` 之前先做身份判定，同一个 `nan` 对象与自身匹配，所以 `nan in sameness` 为真。查找结果取决于对象身份而不只是值。

## 等价类与集合

```python run id="py.hash.set-classes"
print("int, float, bool:", len({1, 1.0, True}), {1, 1.0, True})

nan = float("nan")
print("same nan twice:", len({nan, nan}))
print("two fresh nans:", len({float("nan"), float("nan")}))
print("tuple vs list:", len({(1, 2), (1, 2)}))

try:
    {[1, 2]}
except TypeError as exc:
    print("list is unhashable:", type(exc).__name__)
```

集合按等价类去重：`1`、`1.0`、`True` 落进同一个元素，内容相同的两个元组落进同一个元素（元组可哈希的前提是元素都可哈希）。NaN 与任何值都不相等，因此每个独立的 NaN 对象都是一个新元素；同一个对象重复出现只算一个。
