到目前为止的代码都写在同一个命名空间里。程序还有两条边界要跨：代码如何跨越文件复用，数据如何跨越进程存活。一个文件可以扮演两种角色（被导入的模块、被执行的程序），一段字节序列在进入字符串之前必须经过一层解码。

## 模型

**模块**是一个 Python 文件执行完之后留下的命名空间。导入一个模块意味着：找到文件、执行它的顶层语句、把结果命名空间装进一个对象、并把该对象绑定到当前命名空间里的一个名字。

| 写法 | 绑定的名字 | 值 |
| --- | --- | --- |
| `import math` | `math` | 模块对象 |
| `import math as m` | `m` | 同一个模块对象 |
| `from math import sqrt` | `sqrt` | 模块里的一个属性 |

三种写法导入的是同一个模块对象；`from ... import` 只是省掉前缀，代价是读代码时看不出 `sqrt` 来自哪个模块。导入失败会在入口处终止程序，导入语句的位置本身是一种依赖声明。

成功导入之后，后续对**同一模块名**的普通 `import` 通常复用 `sys.modules` 里的那个模块对象，不重新执行模块体。`sys.modules` 是一个普通字典，条目可以增删：删掉条目后再次 `import` 会重新搜索并执行模块体，`importlib.reload` 也会重新执行（细节与代价见 <CrossRef id="python.modules-and-imports" />）。能进缓存的是「模块名」，因此模块顶层的副作用在正常导入路径上只发生一次——这决定了初始化代码能不能放在模块顶层。

**`__name__`** 是每个模块都有的属性。被导入的模块，它的值是模块名；作为程序启动的那个文件，它的值是 `"__main__"`。这就是脚本入口写法的依据：

```text
if __name__ == "__main__":
    运行命令行入口
```

**文件**在磁盘上是字节序列。`open(path, "r", encoding="utf-8")` 在字节之上加一层解码，读出来是 `str`；写方向同理，文本模式编码、字节模式原样写入。编码与解码的完整模型（码点、UTF-8、错误处理、默认编码为什么不固定）见 <CrossRef id="python.text-and-bytes" />，本课只用到文本模式与 `with`。

## 导入与属性

```python run id="py.mod.import-forms"
import math

from math import sqrt

import math as shorthand

print("module object:", math)
print("the same object under two names:", shorthand is math)
print("attribute access:", math.pi, round(math.pi, 3))
print("imported directly:", sqrt(9))

print("module name:", math.__name__)
print("the name of the module that is running:", __name__)
```

`math.pi` 不是局部变量，而是模块对象上的属性：`import math` 之后 `math` 这个名字指向模块对象，`math.pi` 从它上面取属性。因此「名字来自哪个模块」在代码里是可追查的，只要不用 `from ... import *`。

## 模块体执行几次

把一个模块文件写进当前工作目录，导入两次：模块体只在第一次导入时执行，第二次拿到的是缓存里的同一个对象。

```python run id="py.mod.body-runs-once"
import importlib
import os
import sys

path = os.path.join(os.getcwd(), "demo_module.py")
with open(path, "w", encoding="utf-8") as handle:
    handle.write('print("demo_module body runs")\nvalue = "loaded"\n')
importlib.invalidate_caches()
sys.modules.pop("demo_module", None)  # drop the entry so the cell can be re-run

import demo_module
import demo_module

print("value:", demo_module.value)
print("the second import returned the cached object:", sys.modules["demo_module"] is demo_module)

os.remove(path)
```

`demo_module body runs` 只打印一次：第二次 `import` 发现模块名已经在 `sys.modules` 里，直接返回那个对象，不再读文件。模块是**独立命名空间**，`demo_module.value` 与当前命名空间里的 `value` 是两个不同的名字。模块体里的 `print` 就是副作用本身——模块顶层不做重活，需要初始化时把初始化写成函数，在入口处调用。
## 同一个文件的两种角色

```python run id="py.mod.script-vs-module"
import importlib
import os
import runpy
import sys

path = os.path.join(os.getcwd(), "entry_module.py")
with open(path, "w", encoding="utf-8") as handle:
    handle.write(
        'label = __name__\n'
        'ran_as_entry = False\n'
        'print("body runs, __name__ =", __name__)\n'
        'if __name__ == "__main__":\n'
        '    ran_as_entry = True\n'
        '    print("entry point runs")\n'
    )
importlib.invalidate_caches()

sys.modules.pop("entry_module", None)
import entry_module

print("imported: __name__ =", entry_module.__name__, "| entry point ran:", entry_module.ran_as_entry)

result = runpy.run_path(path, run_name="__main__")
print("run as a program: __name__ =", result["label"], "| entry point ran:", result["ran_as_entry"])

os.remove(path)
```

`runpy.run_path(path, run_name="__main__")` 按「这个文件就是程序」的方式执行一次，因此守卫里的代码运行了；上一段用 `import` 导入同一个文件时，`__name__` 是模块名，守卫不运行。把初始化与命令行入口写进守卫，文件就同时可以作为库和作为程序使用。

## 读写文件

本课程的可执行环境运行在 WebAssembly 上，文件写在内存里的文件系统：路径的用法与真实机器一致，内容不落磁盘，页面刷新后不再存在。

```python run id="py.files.text-and-bytes"
import os

path = os.path.join(os.getcwd(), "notes.txt")
text = "€100\nsecond line\n"

with open(path, "w", encoding="utf-8") as handle:
    written = handle.write(text)
    closed_inside = handle.closed

with open(path, "r", encoding="utf-8") as handle:
    read_back = handle.read()

with open(path, "rb") as handle:
    raw = handle.read()

print("write returned the number of characters:", written)
print("closed inside the block:", closed_inside, "| closed after it:", handle.closed)
print("text mode reads back:", repr(read_back))
print("binary mode returns bytes:", type(raw).__name__)
print("byte length:", len(raw), "| text length:", len(text))

os.remove(path)
```

写入返回的字符数与字节数不同：文本里的 `€` 算一个字符，编码成 UTF-8 占三个字节，因此同一段内容按字符计 17、按字节计 19。文本模式读出 `str`，二进制模式读出 `bytes`，因此同一个文件的两种长度不同；解码之后按字符计，字节模式下按字节计。`with` 在块结束时关闭文件，块内抛出异常时同样关闭——这条保证的完整模型（`__enter__`/`__exit__`、异常路径、资源生命周期）见 <CrossRef id="python.context-managers" />，编码与字节的模型见 <CrossRef id="python.text-and-bytes" />。文件一律用 `with` 打开；`read()` 不带参数会读入整个文件，大文件要按行迭代或分批读。

## 失败情形

```python run id="py.mod.failures"
import os

try:
    import module_that_does_not_exist
except ModuleNotFoundError as failure:
    print("missing module:", type(failure).__name__, "-", failure)

import math

try:
    math.no_such_function
except AttributeError as failure:
    print("missing attribute:", type(failure).__name__, "-", failure)

try:
    with open(os.path.join(os.getcwd(), "missing-file.txt"), "r", encoding="utf-8") as handle:
        handle.read()
except FileNotFoundError as failure:
    print("missing file:", type(failure).__name__, "-", failure)
```

三类错误指向三个不同的原因：模块不在搜索路径上、模块里没有这个名字、文件不在这个路径上。相对路径按**进程的工作目录**解析，而不是按源文件所在目录——脚本被从别处调用时这一条决定了它能不能找到自己的数据文件，因此数据文件的路径应与调用方约定，或由调用方传入。模块搜索路径（`sys.path`）的来源、包与 `__init__.py`、相对导入与循环导入的失败方式见 <CrossRef id="python.modules-and-imports" />；本课只覆盖单文件模块的导入与文件读写。
