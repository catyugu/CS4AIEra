数值是程序里最常见的值。运算符在两种数值类型上的行为基本一致，除法与取模的规则由结果类型与符号决定。

## 运算符

| 运算 | 符号 | 结果 |
| --- | --- | --- |
| 加、减、乘 | `+` `-` `*` | 两数同为 `int` 时是 `int`，任一为 `float` 时是 `float` |
| 除法 | `/` | 总是 `float` |
| 整除 | `//` | 向下取整的商 |
| 取模 | `%` | 余数，符号跟随除数 |
| 幂 | `**` | 幂运算 |

```python run id="py.numbers.operators"
print(7 + 3, 7 - 3, 7 * 3)
print(7 / 3)
print(7 // 3, 7 % 3)
print(2 ** 10)
print(10 / 4, 4 / 2)
print(2 + 3.0)
```

`7 / 3` 得到 `2.3333333333333335`。能整除时 `/` 也返回小数：`4 / 2` 是 `2.0`。整数与小数混合运算得到小数。除数为零时 `1 / 0`、`1 // 0`、`1 % 0` 都抛 `ZeroDivisionError`；跨类型比较按数值进行，`1 == 1.0` 为真。整数运算精确且没有上限，代价是内存与时间随位数增长。

## 整除与取模的符号

```python run id="py.numbers.floor-mod"
print(-7 // 3, -7 % 3)
print(7 // 3, 7 % 3)
print(-7 % 3, 7 % -3)
```

`//` 向下取整，不是向零截断，因此 `-7 // 3` 是 `-3`。余数由恒等式 `a == (a // b) * b + a % b` 决定，所以 `%` 的结果符号跟随除数：`-7 % 3` 是 `2`，`7 % -3` 是 `-2`。

这条恒等式是判断奇偶、把值映射到固定范围（例如把秒数折算成分钟内的秒）的依据。

## 类型转换

```python run id="py.numbers.conversion"
print(int(3.7), int(-3.7))
print(float(3))
print(int("42"))
print(round(2.5), round(3.5))
```

`int()` 向零截断，`int(-3.7)` 是 `-3`。`float(3)` 得到 `3.0`。`int("42")` 解析文本；`int("3.5")` 抛 `ValueError`，要先 `float("3.5")` 再取整。

`round()` 使用「四舍六入五成双」：`round(2.5)` 是 `2`，`round(3.5)` 是 `4`。它取最近的偶数，处理金额时会造成意外。

## 小数的表示

```python run id="py.numbers.float-approximation"
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

`0.1 + 0.2` 得到 `0.30000000000000004`，与 `0.3` 的相等比较为 `False`。小数在计算机里是二进制近似，多数十进制小数无法精确存储。当前的结论只有一条：**需要精确十进制计算的场景（金额、账目）不能默认使用 `float`**。除零抛 `ZeroDivisionError`，而 `float("inf")` 这类特殊值会参与运算并把结果传播成 `inf` 或 `nan`，不抛错。近似模型的完整内容——可精确表示的条件、舍入、聚合顺序——由 <CrossRef id="python.numbers-and-floats" /> 给出。
