要同时维护三条各自独立的计数，用变量就得写三份重复的自增代码。类把一份状态的形状和作用于它的操作绑在一起：每条计数是一个实例，各自保存自己的值，共用同一套操作。

## 定义一个类并创建实例

```python run id="py.classes.instances"
class Counter:
    def __init__(self, start=0):
        self.value = start

    def increment(self):
        self.value += 1


first = Counter()
second = Counter(10)

print(type(first).__name__, first is second)
first.increment()
first.increment()
print(first.value, second.value)
print(Counter)
```

`class Counter:` 执行时创建一个类对象并把名字 `Counter` 绑定到它；`Counter()` 调用这个类对象创建**实例**，返回值是实例。`first` 与 `second` 是两份独立实例，各自持有自己的 `value`，因此 `first` 自增两次之后 `second` 的值不受影响。

`instance.value` 是属性访问，`instance.value = 3` 是属性赋值，赋值在实例上创建或覆盖属性。`instance.increment` 得到绑定到该实例的可调用对象，`first.increment()` 修改的是该实例的状态。`__init__` 初始化一个已经创建出来的实例，它不创建对象；漏赋某个属性会推迟到读取它时才失败。类对象本身是普通的值，打印出来是 `<class '__main__.Counter'>`。

## 实例属性与类属性

一份状态该放在实例上还是类上，在定义处语法相同，行为差别决定程序是否正确。下面这个类的 `members` 写在类体里：

```python run id="py.classes.mutable-class-attribute"
class Team:
    members = []

    def add(self, name):
        self.members.append(name)


a = Team()
b = Team()
a.add("Ada")

print(a.members, b.members)
print(a.members is b.members, Team.members is a.members)
```

`members = []` 属于类对象，是所有实例共享的一个对象；实例属性属于单个实例。读取属性时先看实例自己的属性，再看类（含基类），两层都没有则抛 `AttributeError`；数据描述符优先于实例属性，完整的查找顺序由 <CrossRef id="python.attributes-and-descriptors" /> 细化，继承链的顺序由 <CrossRef id="python.inheritance-and-mro" /> 建立。

`a` 与 `b` 都没有自己的 `members`，读取时沿层次找到类上的那一个，`append` 修改的是同一个列表：两个实例的输出相同，且 `a.members is b.members` 为真。这是<Term id="class-attribute">类属性</Term>最常见的失效模式，执行过程中没有任何错误，只是两个实例的状态合流了。把可变状态放进 `__init__`，属性就落在实例上：

```python run id="py.classes.instance-attribute-fix"
class Team:
    def __init__(self):
        self.members = []

    def add(self, name):
        self.members.append(name)


a = Team()
b = Team()
a.add("Ada")

print(a.members, b.members)
print(a.__dict__, b.__dict__)
```

两个实例各有自己的列表，不再互为<Term id="alias">别名</Term>；`a.__dict__` 与 `b.__dict__` 把属性直接列在实例上，是判断属性归属的直接证据。同样的共享也出现在默认参数上，见 <CrossRef id="python.mutability-and-copy" />。

赋值总是落在被赋值的对象上。`c.retries = 5` 在实例上创建 `retries`，类上的那一个不变：

```python run id="py.classes.rebinding"
class Config:
    retries = 3


c = Config()
c.retries = 5
print(c.retries, Config.retries, c.__dict__)

Config.retries = 7
print(c.retries, Config.retries, Config().retries)
```

随后 `Config.retries = 7` 只改类属性：`c` 上的实例属性遮蔽了它，因此 `c.retries` 仍是 5，只有新创建的实例读到 7。读代码时要区分这两种写法：「改共享的默认值」影响所有还没有自己值的实例，「给这个实例设一个值」只影响一个对象。属性赋值不要求预先声明。

## self 是普通形参

```python run id="py.classes.self-is-a-parameter"
class Counter:
    def __init__(self, start=0):
        self.value = start

    def increment(self):
        self.value += 1


instance = Counter()
Counter.increment(instance)
instance.increment()

print(instance.value)
print(type(Counter.increment).__name__, type(instance.increment).__name__)
print(Counter.increment is instance.increment)
```

`Counter.increment` 是函数，`instance.increment` 是绑定到该实例的方法；两者不是同一个对象，调用效果相同。`instance.increment()` 与 `Counter.increment(instance)` 是同一次调用，`self` 按位置接住那个实例；`self` 是普通形参的惯用名称，不是关键字。

```python run id="py.classes.missing-self"
class Greeter:
    def greet():
        return "hello"


greeter = Greeter()
print(greeter.greet())
```

方法定义里漏掉 `self` 时，调用把实例当成多出来的实参：`TypeError` 的消息指出 `Greeter.greet()` 接收 0 个位置参数，却收到了 1 个。
