`import geometry` 要把一个名字落到磁盘上的某个模块。程序里只有一个 `geometry.py` 时，名字与文件一一对应；一旦目录多起来，同一个名字可能出现在多处，同一个目录在搜索路径上的先后又取决于程序怎样启动。改过的文件不生效、导入到的不是刚写的那个文件，都出自同一条解析路径：一次普通 `import name` 先查已经导入过的模块缓存，名字不在里面才沿搜索路径去找，找到的第一个位置就是答案。

## 一次导入的四个阶段

一次成功的 `import name` 依次做四件事：

1. **查缓存**：`sys.modules` 是以模块名为键、保存已导入模块的字典，名字在里面就直接取用，模块体不再执行。
2. **查找**：沿 `sys.path` 逐项查找，由查找器把模块名映射到一个位置（文件、目录、内置模块）。
3. **执行**：创建模块对象、放进 `sys.modules`，再在它自己的命名空间里执行模块体。
4. **绑定**：把名字绑到调用方的命名空间。

缓存按模块名索引，而且在模块体开始执行之前就写入，所以模块体运行期间，别的代码已经能在缓存里找到这个还没执行完的模块。下面的模块自报它执行时看到的缓存状态：

```python
# resolution_demo.py
import sys

SEEN_WHILE_RUNNING = "resolution_demo" in sys.modules
STATE = "ready"

# main.py
import resolution_demo

print("already cached while its body ran:", resolution_demo.SEEN_WHILE_RUNNING)
```

运行 `python main.py` 打印 `already cached while its body ran: True`。第 3 步还意味着模块体的顶层代码在第一次导入时运行——读配置、连数据库、扫描目录都是导入的代价与失败点。同一个文件作为程序直接运行时用 `"__main__"` 作名字，与作为模块导入时是两个缓存条目，判据见 <CrossRef id="python.modules-basics" />。

## 名字落在哪个文件

名字不在缓存里时，答案由搜索路径给出。`sys.path` 是一个有序的目录列表（见 [sys.path](https://docs.python.org/3/library/sys.html#sys.path)），导入系统按顺序逐项查找，第一个含有该名字的位置被选中；一旦选中并进入缓存，程序后续对这个名字的导入拿到同一个模块对象。所以同一个模块名出现在多处时，选中哪一个由 `sys.path` 的顺序与缓存里已有的条目共同决定：

```python
# first_dir/shared_name.py
ORIGIN = "from first_dir"

# second_dir/shared_name.py
ORIGIN = "from second_dir"

# first_dir 排在 sys.path 更前时
import shared_name

print(shared_name.ORIGIN)      # from first_dir
```

被选中的是搜索顺序靠前的那个文件，`shared_name.__file__` 指向它；排在后面的同名文件不为这个名字提供代码。自己写的 `utils.py` 覆盖同名依赖，机制就在这里。

`sys.path` 的第一项由启动方式决定：直接运行 `python file.py` 时是 `file.py` 所在目录，以 `-m` 运行模块、以 `-c`、交互式或从标准输入进入时是当前工作目录。因此「脚本所在目录先于已安装的包被搜索」只在直接启动脚本时成立，换一种启动方式，导入可能落到另一个模块。

## 包与子模块

目录可以整体成为一个模块。目录含 `__init__.py` 时它本身是一个包：导入时执行 `__init__.py`，目录成为这个模块的 `__path__`，子模块的名字是 `包名.子模块名`，对应目录里的文件。目录没有 `__init__.py` 时，只要它在 `sys.path` 上，仍是可导入的命名空间包，只是没有可执行的初始化代码。

```python
# geometry/__init__.py
KIND = "regular package"

# geometry/shapes.py
def rectangle(width, height):
    return width * height

# 调用方
import geometry.shapes
from geometry import shapes

print(geometry.KIND, geometry.shapes.__name__, shapes.rectangle(3, 4))
# regular package geometry.shapes 12
```

`import geometry.shapes` 先解析 `geometry` 再解析 `geometry.shapes`，最终只在调用方绑定 `geometry`——子模块成为包的属性，用 `geometry.shapes` 访问。`from geometry import shapes` 把子模块对象直接绑到名字 `shapes`。两种写法都要先导入 `geometry`，会执行一次 `__init__.py`。

以 `.` 或 `..` 开头的导入是相对导入：`from . import metrics` 的解析起点是当前模块所在的包，只在包内的模块里有意义，它把模块在树里的位置写进代码。写在 `sys.path` 上的普通文件里（包括被当作脚本直接运行的文件），没有可以相对的「当前包」，运行抛 `ImportError: attempted relative import with no known parent package`；要改的是导入语句所在的位置，改成绝对导入，或把文件移进包里。

## 循环导入

模块在模块体执行之前就进入缓存，这条顺序让互相导入的两个模块能「半成功」：第二个模块拿到的是已经存在、但还没执行完的模块对象，它的命名空间里只有已经执行过的名字。

```python
# cycle_first.py
import cycle_second

CONSTANT = "from first"

def describe():
    return cycle_second.read()

# cycle_second.py   —— 导入期读取
import cycle_first

VALUE = cycle_first.CONSTANT
```

运行 `import cycle_first` 抛 `AttributeError`，抛出点在 `cycle_second.py` 的 `VALUE = cycle_first.CONSTANT` 一行：执行到它时 `cycle_first` 已在缓存里，却只执行到 `import cycle_second`，`CONSTANT` 还没有定义。

把这次读取推迟到函数体里（`read` 在调用时才取 `cycle_first.CONSTANT`），两个模块都能完成初始化，`cycle_first.describe()` 随后拿到值。判据是导入期不读取对方尚未定义的名字；导入期出现 `AttributeError` 时，先看依赖环，再决定把这次读取推迟到哪一步。
