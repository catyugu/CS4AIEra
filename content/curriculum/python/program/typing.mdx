`def parse(text: str) -> list[int]` 写下参数与返回值的类型契约。静态检查器在运行前读取源码，依据标注和类型推断发现不一致；解释器不据此检查实参或容器元素。读代码时需要分开三个问题：类型契约是否自洽、运行时工具怎样读取标注、这次输入是否满足业务约束。

## 标注与运行时对象

类型契约可以描述参数、返回值、容器元素与可空性。普通的 `int` 标注不限制取值范围，也不排除 `bool`：`bool` 是 `int` 的子类型。正数、非空、单位一致等业务不变量仍需另外建立。

```python run id="py.typing.not-enforced"
def resize(width: int, height: int) -> int:
    return width * height


print(resize(3, 4))
print(resize("abc", 4))
try:
    resize(3)
except TypeError:
    print("missing argument: call binding failed")
```

检查器应拒绝 `resize("abc", 4)`，运行时却返回重复的字符串。少传参数仍抛 `TypeError`，这来自 <CrossRef id="python.call-semantics" /> 的参数绑定规则，与标注无关。这里及下文标出的静态错误是类型契约的推导；浏览器单元格运行 Python，不运行静态检查器。

`list[int]` 是运行时存在的参数化泛型对象，类型为 `types.GenericAlias`；类型检查器把它解释为列表元素契约，运行时不检查元素（见 [内置类型：GenericAlias](https://docs.python.org/3.14/library/stdtypes.html#types-genericalias)）。`int | None` 同样可在运行时求值得到联合类型对象。

```python run id="py.typing.annotation-objects"
alias = list[int]
print(type(alias).__name__)
print(alias.__origin__, alias.__args__)
print(alias(["unchecked"]))
print(isinstance(None, int | None))
try:
    isinstance([1], alias)
except TypeError:
    print("isinstance rejects a parameterized generic")
```

别名可以保存和调用，却不能把 `isinstance(values, list[int])` 当成元素校验。标注也不负责赋值：类体中单写 `label: str` 不会创建一个已有值的属性。

## Any 与 object

`object` 表示任意 Python 对象，但只允许依赖所有对象共有的操作。`Any` 允许检查器接受任意操作与类型赋值，因而在该处放弃类型保证（见 [typing：Any](https://docs.python.org/3.14/library/typing.html#the-any-type)）。两者都能接收字符串，之后的推理能力不同：

```python
from typing import Any


def unchecked(value: Any) -> int:
    return value + 1      # Any 使检查器接受这条数据流


def unknown(value: object) -> int:
    return value + 1      # 静态错误：object 没有承诺数值加法
```

`unchecked("text")` 仍会在运行时失败。把未知数据记作 `object`，要求代码在使用前提供证据；把它记作 `Any`，允许代码跳过这一步。`Any` 常用于与缺少类型信息的代码交接，但需要知道保证在哪里中断。

## union 与收窄

联合类型（union）`int | None` 表示值可能属于两种情形。收窄（narrowing）是检查器依据分支条件缩小当前可能类型集合的过程：

```python run id="py.typing.narrowing"
def increment(value: int | None) -> int:
    if value is None:
        return 0
    return value + 1


def describe(value: object) -> str:
    if isinstance(value, str):
        return value.upper()
    return "not text"


print(increment(None), increment(4))
print(describe("hello"), describe(4))
```

`None` 分支返回后，剩余路径上的 `value` 为 `int`，加法才有依据。`isinstance` 分支把 `object` 收窄为 `str`，于是字符串方法可用。分支既提供静态证据，也在运行时选择路径；单写标注或 `typing.cast` 不会执行这种验证。

## 泛型保留类型关系

把参数和返回值都写成 `object` 会丢掉二者之间的关系；都写成 `Any` 又会放弃检查。泛型（generic）用同一个类型参数表达这条关系：

```python run id="py.typing.generic-relation"
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def first(values: Sequence[T]) -> T:
    if not values:
        raise ValueError("empty sequence")
    return values[0]


print(first([3, 4]), first(["a", "b"]))
try:
    first([])
except ValueError as failure:
    print(failure)
```

输入 `Sequence[int]` 时返回 `int`，输入 `Sequence[str]` 时返回 `str`，检查器沿调用保留这条关系（见 [typing：Generics](https://docs.python.org/3.14/library/typing.html#generics)）。`T` 不承诺序列非空；空输入的失败契约仍由函数体建立。

## 可变容器与 invariance

若 `S` 是 `T` 的子类型，容器类型也允许从 `Container[S]` 赋给 `Container[T]`，就称其在该参数上协变（covariant）。对允许写入的 `list`，这个规则会破坏共享对象的元素契约：

```python run id="py.typing.mutable-alias"
flags: list[bool] = [True]
numbers: list[int] = flags  # 静态错误；运行时赋值照常建立别名
numbers.append(2)
print(flags)
print(numbers is flags)
```

`bool` 是 `int` 的子类型，写入整数对 `numbers` 的契约合法，却破坏了 `flags` 只含布尔值的契约。两个名字指向同一个列表，后果来自 <CrossRef id="python.names-and-objects" /> 的别名模型。因此 `list` 的元素类型参数是不变的（invariant）：不能仅凭元素的子类型关系在两种列表类型间赋值（见 [类型规范：方差](https://typing.python.org/en/latest/spec/generics.html#variance)）。

`Sequence[T]` 提供读取接口，不提供 `append` 这类写入操作，因此可以协变；接收 `Sequence[int]` 的函数可读取 `list[bool]`。这不保证底层对象永不变化，只限制通过当前接口可以做什么。

## Protocol 的结构类型

结构类型（structural typing）按成员与签名判断兼容性，不要求对象继承指定类。`Protocol` 可以表达「需要一个无参数、返回字符串的 read 方法」：

```python run id="py.typing.protocol"
from typing import Protocol, runtime_checkable


@runtime_checkable
class Reader(Protocol):
    def read(self) -> str: ...


class FileReader:
    def read(self) -> str:
        return "contents"


class WrongSignature:
    def read(self, size: int) -> str:
        return "contents"


def consume(reader: Reader) -> str:
    return reader.read()


print(consume(FileReader()))
print(isinstance(WrongSignature(), Reader))
try:
    consume(WrongSignature())  # 静态错误：read 要求额外实参
except TypeError:
    print("member exists, but the call contract fails")
```

`FileReader` 没有继承 `Reader`，仍满足静态契约。`WrongSignature` 有同名方法，却要求必传的 `size`，不能替代无参数调用。`@runtime_checkable` 只检查所需成员是否存在，不核对签名或返回类型，因此上面的 `isinstance` 为真；它不能校验列表元素，也不能证明业务行为（见 [typing：runtime_checkable](https://docs.python.org/3.14/library/typing.html#typing.runtime_checkable)）。

## 外部数据与业务约束

外部数据的静态类型来自 API 声明，不证明实际值满足业务要求。例如 `os.environ` 是字符串键、字符串值的映射（见 [os：environ](https://docs.python.org/3.14/library/os.html#os.environ)）；JSON 解析结果则可以包含数字、布尔值、列表、映射与空值。不能统一把外部数据称为文本或 `Any`。

```python run id="py.typing.validation"
def parse_limit(raw: str) -> int:
    value = int(raw)
    if not 1 <= value <= 100:
        raise ValueError("limit must be in 1..100")
    return value


for raw in ("12", "abc", "0"):
    try:
        print(repr(raw), "->", parse_limit(raw))
    except ValueError as failure:
        print(repr(raw), "->", type(failure).__name__)
```

三个输入都满足 `str` 契约，只有一个满足业务约束。解析检查表示是否有效，范围检查建立领域不变量。静态检查回答「依据声明，这段代码的类型使用是否一致」；运行时校验回答「这次实际输入是否满足前提」。跨越不可信数据边界时，需要后者的证据。

## 标注内省的版本边界

Python 不在运行时强制标注；标注本身是可以被运行时工具读取的数据，例如库可以据此生成字段或接口。标注表达式的求值时机属于版本敏感行为：Python 3.14 默认延迟求值，需要内省时优先用当前官方 API `annotationlib.get_annotations()`（见 [annotationlib](https://docs.python.org/3.14/library/annotationlib.html) 与 [标注最佳实践](https://docs.python.org/3.14/howto/annotations.html)）。

```python run id="py.typing.introspection"
from annotationlib import get_annotations


def parse(text: str) -> list[int]:
    return [int(part) for part in text.split()]


print(get_annotations(parse))
```

本例使用 Python 3.14 的 API。读取并求值标注不等于校验一次调用；若维护其他版本的内省工具，应按该版本文档选择读取方式。
