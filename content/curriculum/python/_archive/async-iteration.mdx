设想程序消费一条消息流：下一条消息什么时候到不由你决定，因此每一次取消息都可能要等。普通的 `for` 把取元素当作立刻完成的步骤，等待无处安放，事件循环也就无法在等待期间去跑别的任务。`async for` 让取元素可以挂起，做法是在对应位置放入一个 `await`。它的展开与 <CrossRef id="python.iteration-protocol" /> 记下的同步约定逐条对应，唯一的差别就是哪一步可以挂起。

## async for 的展开

`async for` 要求对象提供 `__aiter__`，它直接返回一个异步迭代器；异步迭代器提供 `__anext__`，返回一个可等待对象，取完时抛 `StopAsyncIteration`（见[数据模型](https://docs.python.org/3/reference/datamodel.html#asynchronous-iterators)）。语句的展开是固定的：

```python
iterator = iterable.__aiter__()
while True:
    try: item = await iterator.__anext__()
    except StopAsyncIteration: break
    ... 循环体 ...
```

与同步展开的两处差别是实质性的：取下一个元素要 `await`，因此**每次取元素都是一个挂起点**；结束信号是 `StopAsyncIteration`，不是 `StopIteration`。展开式的每一步都是普通属性查找加一次 `await`，因此可以手工执行：

```python run id="py.async.async-for-expansion"
import asyncio


class Countdown:
    def __init__(self, start):
        self.current = start

    def __aiter__(self):
        print("__aiter__ ran")
        return self

    async def __anext__(self):
        if self.current == 0:
            raise StopAsyncIteration
        self.current -= 1
        await asyncio.sleep(0)
        return self.current + 1


async def main():
    async for value in Countdown(3):
        print("took", value)

    iterator = Countdown(1).__aiter__()
    print("manual first element:", await iterator.__anext__())
    try:
        await iterator.__anext__()
    except StopAsyncIteration:
        print("the second call raised StopAsyncIteration")


await main()
```

`__aiter__` 打印一次就返回了迭代器自身，`async for` 随后只调用 `__anext__`。手工展开给出同样的结果：第一次取值拿到 1，第二次抛出 `StopAsyncIteration`。

两个方向的不匹配都会在运行时报错，而不是静默降级：

```python run id="py.async.iteration-protocols-are-separate"
class AsyncOnly:
    def __aiter__(self):
        return self

    async def __anext__(self):
        raise StopAsyncIteration


try:
    for value in AsyncOnly():
        print("never reached", value)
except TypeError as failure:
    print("async iterable used with for:", type(failure).__name__, "-", failure)

try:
    async for value in ["a", "b"]:
        print("never reached", value)
except TypeError as failure:
    print("list used with async for:", type(failure).__name__, "-", failure)

try:
    compile("async for item in data: pass", "<cell>", "exec")
except SyntaxError as failure:
    print("outside a coroutine function:", type(failure).__name__, "-", failure.msg)
```

一个可迭代对象不会因为「看起来像」就能用于 `async for`，反过来也一样：两套协议的名字与方法互不替代。最后一条说明 `async for` 与 `async with` 只能出现在协程函数体内，写在别处是语法错误——这条限制由语法检查执行，与对象是否有 `__aiter__` 无关（见[语言参考](https://docs.python.org/3/reference/compound_stmts.html#the-async-for-statement)）。

## 异步生成器

函数体里同时出现 `async def` 与 `yield` 时得到的是异步生成器函数：调用它不执行函数体，返回一个异步生成器对象，该对象同时是异步迭代器。它的作用是让上面那对手写方法不必逐个写出：

```python run id="py.async.async-generator"
import asyncio


async def ticker(limit):
    for value in range(limit):
        await asyncio.sleep(0)
        yield value


async def main():
    print("calling it returns:", type(ticker(2)).__name__)
    async for value in ticker(3):
        print("value", value)

    generator = ticker(2)
    print("first:", await generator.__anext__())
    print("second:", await generator.__anext__())
    try:
        await generator.__anext__()
    except StopAsyncIteration:
        print("the third call raised StopAsyncIteration")


await main()
```

生成器的状态同样保存在挂起的帧里，因此取值之间函数体不进不退；与同步生成器一样，它是**一次性**的：`__aiter__` 返回自身，耗尽之后不能重来（<CrossRef id="python.generators" />）。异步生成器还有 `asend` 与 `athrow`，语义分别对应同步生成器的 `send` 与 `throw`。

收尾的差别更值得注意：同步生成器被回收时由解释器在挂起点抛 `GeneratorExit`，异步生成器的收尾要经过事件循环，因此显式关闭才是可控的做法：

```python run id="py.async.async-generator-close"
import asyncio


async def stream():
    try:
        while True:
            await asyncio.sleep(0)
            yield "item"
    finally:
        print("the finally inside the generator ran")


async def main():
    generator = stream()
    print("first:", await generator.__anext__())
    print("second:", await generator.__anext__())
    await generator.aclose()
    try:
        await generator.__anext__()
    except StopAsyncIteration:
        print("a closed generator stays exhausted")


await main()
```

`aclose()` 在挂起点把 `GeneratorExit` 送进生成器，`finally` 因此运行，关闭之后的取值立即结束迭代。不显式关闭时，收尾取决于引用何时被回收，而回收要经过事件循环的异步生成器终结流程——与「对象被回收就释放资源」一样不可依赖，资源仍应交给 `async with`（见 <CrossRef id="python.async-context-managers" />）。
