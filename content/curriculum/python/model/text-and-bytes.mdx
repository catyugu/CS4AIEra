## 目的

本课解释 `str` 与 `bytes` 的表示，以及编码边界上的故障模式。

字符串的度量单位有三种：码点数、字节数与字形数，三者互不相等。`len()` 给出的是第一种，而协议、存储与用户界面常常按另外两种施加约束。这类不匹配表现为静默截断、乱码与「看起来一样却不相等」的标识符。

## 模型：三种单位

- `str` 是 Unicode 码点序列，`len(s)` 是码点数。
- `bytes` 是字节序列。`s.encode(enc)` 把码点序列编码为字节，`b.decode(enc)` 反向转换。
- 字形是渲染后的可见单位，由一到多个码点组成，可能包含组合字符、变体选择符与零宽连接符。
- UTF-8 是变长编码：ASCII 占一个字节，多数常用字符占两到三个字节，其余平面占四个字节。

```python run id="py.text.code-points"
import unicodedata

composed = "\u00e9"
decomposed = "e\u0301"

print(len(composed), len(decomposed))
print(composed == decomposed)
print(composed.encode("utf-8") == decomposed.encode("utf-8"))
print(unicodedata.normalize("NFC", decomposed) == composed)
print([hex(ord(c)) for c in composed])
print([hex(ord(c)) for c in decomposed])
```

`"\u00e9"` 是一个码点，`"e\u0301"` 是 `e` 加组合尖音符两个码点。两者渲染结果相同，`len` 分别为 1 与 2，相等比较为 `False`，UTF-8 字节序列也不同。`normalize("NFC", ...)` 把分解形式合成，与预组合形式相等。

标识符比较必须在同一个规范化形式下进行，否则同一个名字会得到两个不同的键。

## 编码与解码

```python run id="py.text.decode"
raw = "na\u00efve".encode("utf-8")
print(raw)
print(raw.decode("utf-8"))
print(raw.decode("latin-1"))

try:
    raw.decode("ascii")
except UnicodeDecodeError as exc:
    print(type(exc).__name__, exc.start, exc.end)
```

同一段字节用不同编码解码得到不同文本。`latin-1` 把每个字节映射到一个码点，因此任何字节序列都能成功解码，产生乱码。`ascii` 遇到大于 127 的字节抛 `UnicodeDecodeError`，异常携带 `start` 与 `end`，指向出错的字节位置。

## 截断与边界

```python run id="py.text.truncation"
text = "\u65e5\u672c\u8a9e"
raw = text.encode("utf-8")

print(len(text), len(raw))
print(raw)
print(text[:2])

try:
    raw[:4].decode("utf-8")
except UnicodeDecodeError as exc:
    print(type(exc).__name__, exc.reason)
```

三个码点编码成九个字节。按字节截断到 4 字节切断了第三个码点的序列，解码失败并报告数据在结尾处不完整。按码点切片在解码侧安全，切出的位置仍可能落在组合字符之间，渲染出错误的字形。

## 比较与大小写

```python run id="py.text.ordering"
print(sorted(["Zoe", "apple", "\u00c1lvaro", "\u65e5\u672c"]))
print("apple" < "Zoe")
print("stra\u00dfe".lower())
print("stra\u00dfe".casefold())
print("stra\u00dfe".casefold() == "STRASSE".casefold())
```

比较按码点进行：大写字母排在小写字母之前，非 ASCII 字符排在 ASCII 之后。这个顺序与任何语言的习惯排序都不一致。

`casefold()` 做大小写折叠，覆盖 `lower()` 处理不了的规则，德语的 `ß` 折叠为 `ss` 是一例。语言相关的排序规则由 `locale` 或数据库的排序规则提供，Python 的内置比较不提供。

## 边界与失败情形

- **编码未指定**：`open()` 与 `bytes.decode()` 的默认编码依赖环境；读写文件与解析协议时显式写出编码。
- **按字节截断**：HTTP 头、数据库的 `varchar(n)`、终端宽度各自按不同单位限制长度，截断多字节序列会产生非法字节。
- **规范化冲突**：同一名字的两种规范化形式在文件系统与数据库中是两个不同的键。部分文件系统在写入时自动归一化，读取时又不还原。
- **不可见字符**：零宽空格、双向控制符与同形字符让两个不同的字符串看起来一样，影响标识符与审查。
- **正则与 Unicode**：`re` 的 `\w` 与 `\d` 默认按 Unicode 类别匹配，字符类的范围行为与字节模式不同。
- **拼接开销**：`str` 不可变，循环内 `s += part` 在大规模下产生二次方复制，用 `join` 或列表缓冲。
- **容量估计**：UTF-8 下字节数取决于内容，按码点数分配缓冲会低估。

## 生产后果

- 长度校验的单位决定边界：按码点限制的用户名可以在字节长度上超出下游存储的限制。
- 排序与去重在跨语言数据上不一致，数据库的排序规则与应用层的比较可能给出不同顺序。
- 大小写折叠用于认证或去重时必须与存储侧一致，否则同一个账号名可以注册两次。
- 日志与终端输出中的控制字符会改变显示，影响审计与排错。
- 序列化边界：JSON 默认转义非 ASCII，CSV 的编码由写入方决定，客户端与数据库编码不一致会产生乱码或写入失败。
- 生成代码常按 `len(s)` 做长度限制，在需要字节数的协议边界上出错。

## 小结

- `str` 是码点序列，`bytes` 是字节序列，两者之间的转换是显式编码与解码。
- `len(str)` 是码点数，字节数与字形数需要单独计算。
- 同一文本的两种规范化形式比较不等，比较标识符前先归一化。
- 同一段字节用不同编码解码得到不同文本，`latin-1` 从不失败。
- 按字节截断会切断多字节序列，按码点切片可能切在字形内部。
- 排序与大小写折叠按码点与折叠规则进行，语言相关排序由外部排序规则提供。
