## 目的

本课解释 Python 两种数值类型的表示，以及浮点误差的来源与后果。

数值是语言层面唯一自带近似语义的基础类型。把它当作实数推理，会在比较、聚合与金额计算上产生静默错误：结果看起来合理，与预期只差一点，而这个「一点」随数据规模放大。

## 模型：两种表示

- `int` 是任意精度整数。只要内存允许，运算结果精确，不存在溢出回绕。
- `float` 是 IEEE 754 binary64：1 位符号、11 位指数、52 位尾数，共 53 位有效位。可精确表示的值是形如 `m * 2^e` 的有理数，且 `m` 需要不超过 53 位。
- 十进制小数 `0.1` 在二进制中是无限循环小数。写下 `0.1` 时，内存里存的是与它最接近的可表示值。
- 运算在这些近似值上进行，误差随之传播。

```python run id="py.numbers.representation"
from decimal import Decimal

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(f"{0.1:.20f}")
print(Decimal("0.1") + Decimal("0.2"))
```

三个事实：`0.1 + 0.2` 得到 0.30000000000000004；与 `0.3` 的相等比较为 `False`；把 `0.1` 展开到 20 位小数可以看到它的二进制近似值。`Decimal` 用十进制表示与十进制舍入，`Decimal("0.1")` 精确表示十进制的十分之一。

## 运算顺序与抵消

```python run id="py.numbers.cancellation"
import math

total = 0.0
for _ in range(10):
    total += 0.1
print("loop total:", total)
print("sum():      ", sum([0.1] * 10))
print("fsum():     ", math.fsum([0.1] * 10))

print("1e16 + 1.0 - 1e16:", 1e16 + 1.0 - 1e16)
print("1e16 - 1e16 + 1.0:", 1e16 - 1e16 + 1.0)
```

浮点加法不满足结合律。`1e16 + 1.0` 舍入回 `1e16`，因此两个表达式的结果分别是 `0.0` 与 `1.0`。相减两个相近的数会丢掉有效位，这种情形称为灾难性抵消，它在方差、差值与求和公式中出现得最多。

逐项累加 0.1 十次得到 0.9999999999999999，`math.fsum` 用精确累加得到 1.0。`sum()` 在本运行时返回 1.0：CPython 3.12 起对浮点使用补偿求和，3.11 及更早返回 0.9999999999999999。这是实现行为，语言不承诺它。

## 整数与浮点的边界

```python run id="py.numbers.int-float-boundary"
big = 10 ** 20

print(big + 1 == big)
print(float(big + 1) == float(big))
print(float(big) == big)
print(2 ** 100 == float(2 ** 100))
print(float(2 ** 100))
```

整数运算精确，`10**20 + 1 == 10**20` 为 `False`。转换到浮点后两者相等，因为 `10**20 + 1` 舍入到最近的可表示值 `10**20`。

`10**20` 与 `2**100` 本身可以精确表示，因此 `float(x) == x` 成立。判定依据是有效位是否超过 53 位，与数值大小无关：`2**100` 数值巨大但有效位只有 1 位。

## 精确算术

```python run id="py.numbers.decimal"
from decimal import Decimal, ROUND_HALF_UP

price = Decimal("19.99")
total = (price * 3).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print("total:", total)
print("1 / 3:", Decimal("1") / Decimal("3"))
print("Decimal(0.1):", Decimal(0.1))
```

`Decimal` 的精度来自上下文（默认 28 位有效数字）与显式舍入模式。`quantize` 指定小数位数与舍入方式，金额计算必须在这一点上明确。

构造方式决定语义：`Decimal("0.1")` 得到十进制的十分之一，`Decimal(0.1)` 得到浮点近似值的精确十进制展开。从字符串或整数构造，从浮点构造会把浮点误差带进精确类型。

`Fraction` 提供精确有理数算术，代价是分母随运算增长。金额场景用整数最小单位或 `Decimal`，并在边界处明确舍入规则。

## 边界与失败情形

- **NaN 与无穷**：`float("nan") != float("nan")`，含 NaN 的任何比较为 `False`，`float("inf") - float("inf")` 得到 NaN。含 NaN 的序列排序结果不再保证有序。
- **除以零**：整数除法抛 `ZeroDivisionError`；浮点除以零得到 `inf` 或 `nan`。两种类型的失败方式不同。
- **负零**：`-0.0 == 0.0` 为真，`math.copysign` 可以区分两者；作为字典键时是同一个键。
- **混合比较是精确的**：`10**20 + 1 == float(10**20 + 1)` 为 `False`，Python 在整数与浮点比较时按精确值比较，不先做浮点转换。
- **聚合顺序**：`sum`、`math.fsum`、`math.prod` 与向量化库的累加顺序不同，同一批数据的和可能不同。
- **显示与存储**：`repr` 给出最短的可往返表示，因此 `0.1 + 0.2` 显示为 0.30000000000000004；把浮点格式化成固定位数会掩盖误差，也会引入新的舍入。

## 生产后果

- 金额用浮点存储会在对账时出现分币级差异，差异随数据量累积。用整数最小单位或定点十进制。
- 指标聚合的顺序影响结果。同一份数据在 Python、SQL 与向量化库中求和可能得到不同值，跨系统对账需要固定口径。
- 用精确相等断言浮点结果的测试会间歇失败。改用容差或 `math.isclose`，并在测试里说明容差的来源。
- 序列化边界：JSON 数字、SQL 的 `REAL`、其他语言的双精度都按 binary64 语义。把超过 2^53 的整数放进 JSON 再读回可能丢精度。
- 用浮点做计数器或索引，超过 2^53 后不再能表示相邻整数。
- 生成代码常用 `==` 比较浮点结果，或用 `float` 累计金额。

## 小结

- `int` 精确且无溢出；`float` 是 binary64 近似，只有 53 位有效位。
- 十进制小数通常不可精确表示，误差在运算中传播。
- 浮点加法不满足结合律，相减相近数造成灾难性抵消。
- 比较用容差；金额用整数最小单位或 `Decimal`。
- `Decimal("0.1")` 与 `Decimal(0.1)` 语义不同，构造方式决定结果。
- NaN 不等于自身，含 NaN 的比较与排序都不可靠。
