## 目的

本课解释复制的准确语义，以及共享可变状态如何在函数、容器与模块之间传播。

上一课建立了赋值只绑定名称这一结论。本课处理它的直接后果：两个名称指向同一对象时，一个名称下的原地修改对另一个名称可见。复制是控制这种可见性的手段，而复制有深度之分，用错深度会留下仍然共享的部分。

复制语义也是接口契约的一部分。函数返回内部容器、把传入的列表存进自己的字段、把可变对象用作模块级缓存，都会让状态的所有权变得模糊。这类缺陷在单次调用里看不出来，在长驻进程与并发下才显现。

## 模型：绑定、浅拷贝与深拷贝

三种操作要分开：

| 操作 | 效果 |
| --- | --- |
| `b = a` | 增加一个指向同一对象的名字 |
| `copy.copy(a)` | 新建外层容器，元素仍是原来的引用 |
| `copy.deepcopy(a)` | 递归新建对象图，图内的身份关系被保留 |

判断共享只需要两个问题：两个名字是否指向同一对象（`is`），以及通过一个名字修改后另一个名字是否看到变化。

```python run id="py.copy.shallow-vs-deep"
import copy

inner = [1, 2]
outer = [inner, 3]

shallow = copy.copy(outer)
deep = copy.deepcopy(outer)

inner.append(99)

print("outer:  ", outer)
print("shallow:", shallow)
print("deep:   ", deep)
print("shallow[0] is inner:", shallow[0] is inner)
print("deep[0] is inner:   ", deep[0] is inner)
```

`copy.copy(outer)` 新建了外层列表，元素 `inner` 仍是同一个对象。`inner.append(99)` 因此在 `outer` 与 `shallow` 中都可见，在 `deep` 中不可见。`shallow[0] is inner` 为 `True` 说明浅拷贝没有进入第二层。

## 深拷贝与对象图

`deepcopy` 递归复制，并在复制过程中维护一张「已复制对象到副本」的映射（memo）。这个 memo 让两个性质同时成立：原图中共享的子对象在副本中仍然共享，循环结构不会导致无限递归。

```python run id="py.copy.graph-identity"
import copy

shared = [1]
cyclic = [shared, shared]
cyclic.append(cyclic)

clone = copy.deepcopy(cyclic)

print("clone[0] is clone[1]:", clone[0] is clone[1])
print("clone[2] is clone:   ", clone[2] is clone)
print("clone[0] is shared:  ", clone[0] is shared)
```

原对象中 `cyclic[0]` 与 `cyclic[1]` 是同一个列表，`cyclic[2]` 指向 `cyclic` 自身。副本保留了这两种关系，而副本中的元素与原件不再共享。朴素递归复制在这个结构上会无限展开。

## 重复引用与构造顺序

`[x] * n` 复制的是引用。用它构造嵌套结构会得到每一行都指向同一个列表的矩阵。

```python run id="py.copy.repeated-reference"
grid = [[0] * 3] * 3
grid[0][0] = 1
print("grid:", grid)

rows = [[0] * 3 for _ in range(3)]
rows[0][0] = 1
print("rows:", rows)
```

`[[0] * 3] * 3` 先构造一个内层列表，再把这个引用重复三次，于是三行是同一个对象。推导式在每次迭代求值一次内层表达式，得到三个不同的列表。两者在只读时行为相同，在写入时立刻分叉。

## 所有权与接口契约

返回内部容器等于把修改权交给调用方：

```python run id="py.copy.ownership"
class Buffer:
    def __init__(self):
        self._items = []

    def add(self, item):
        self._items.append(item)

    def items(self):
        return self._items


buffer = Buffer()
buffer.add(1)
snapshot = buffer.items()
snapshot.append(999)
print("internal state:", buffer._items)
```

`items()` 返回内部列表本身，`snapshot.append(999)` 修改了 `Buffer` 的内部数据。返回副本或返回不可变视图把所有权留在对象内部。这个选择无法从签名看出，必须写进接口文档。

## 边界与失败情形

- **浅拷贝不构成隔离**：`list(x)`、`x[:]`、`dict(x)`、`copy.copy(x)` 都只复制一层，嵌套元素继续共享。
- **深拷贝的代价与限制**：对象图越大越慢；文件、套接字、锁、模块等对象不可复制并会抛错；定义 `__deepcopy__` 的类可以改写语义。
- **不可变容器的可变元素**：`t = ([1], 2)` 上的 `t[0].append(3)` 合法。元组的不可变性只覆盖元素绑定。
- **分片是浅拷贝**：`a[:] is a` 为 `False`，而 `a[:][0] is a[0]` 为 `True`。
- **循环引用与回收**：容器参与循环时引用计数无法归零，需要垃圾回收器介入。这影响内存画像，不影响正确性。
- **迭代中修改**：遍历容器同时增删元素会跳过或重复元素。需要边遍历边改时先构造副本或先收集再修改。

## 生产后果

- **模块级缓存与类属性**：可变对象作为类属性时被所有实例共享，一处写入跨实例串味。
- **缓存污染**：缓存返回内部对象，调用方就地修改后缓存里存的是被改过的值，失效逻辑无法察觉。
- **请求间串味**：长驻进程把请求数据放进共享容器，一次请求的残留出现在下一次请求里。
- **并发**：共享可变状态是竞态的前提。线程、协程与数据库事务都在处理同一个问题——谁在什么时候看到谁写的哪个版本。
- **序列化边界**：跨进程、跨网络、跨语言时不存在共享内存，复制是强制的，此时共享语义由序列化格式决定。
- **生成代码**：把 `list(x)` 当作隔离手段，在嵌套结构上留下 <Term id="alias">别名</Term>。

## 小结

- 复制的是引用。修改对象与重绑定名称是两种不同的操作。
- 浅拷贝复制一层容器，元素继续共享。
- 深拷贝递归复制并保留图内身份关系，memo 同时解决共享与环。
- `[x] * n` 重复的是引用；构造独立元素用推导式。
- 返回内部容器等于交出所有权，接口文档必须说明是否共享。
