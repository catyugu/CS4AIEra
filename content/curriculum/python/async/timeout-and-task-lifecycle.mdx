取消本身由 <CrossRef id="python.cancellation-and-timeouts" /> 建立：它是一次注入到执行流里的异常，在挂起点到达。取消用于两类场景：给一段等待设定期限，和给一组任务划定共同的生命周期。两者的失败模式都来自同一个事实：**谁被取消、谁负责收尾，由结构决定而不是由意图决定**。

## 超时取消的是当前 task

`asyncio.timeout(delay)` 返回一个异步上下文管理器。到期时它**取消进入这个上下文的那个 task**，并在上下文内部处理由此产生的 `CancelledError`，把它转换成 `TimeoutError` 抛出：

```python run id="py.async.timeout"
import asyncio


async def slow():
    try:
        await asyncio.sleep(10)
    except asyncio.CancelledError:
        print("the deadline cancelled this task")
        raise


async def main():
    try:
        async with asyncio.timeout(0.001):
            await slow()
    except TimeoutError as failure:
        print("the deadline reported:", type(failure).__name__)

    print("the loop is still usable:", await asyncio.sleep(0, result="yes"))


await main()
```

被等待的代码看到的是普通的取消，因此它的清理路径照常运行；调用方看到的是 `TimeoutError`。两个异常不是同一个东西，来源也不同：`CancelledError` 进入 task 内部，`TimeoutError` 由上下文管理器在退出时产生（见 [asyncio: Timeouts](https://docs.python.org/3/library/asyncio-task.html#timeouts)）。

两类异常的区分在块内捕获异常时立刻显出后果：`timeout` 只能转换它自己传进去的那个 `CancelledError`。块内的 `except CancelledError` 把它截住并继续执行，上下文退出时就看不到异常，`TimeoutError` 也不会出现——超时被降级成了一次被吞掉的取消，这正是 <CrossRef id="python.cancellation-and-timeouts" /> 里描述的破坏。期限内完成的等待不受影响：

```python run id="py.async.timeout-not-expired"
import asyncio


async def main():
    async with asyncio.timeout(10):
        value = await asyncio.sleep(0, result="finished in time")
    print("within the deadline:", value)

    try:
        async with asyncio.timeout(0.001):
            await asyncio.sleep(10)
    except TimeoutError:
        print("past the deadline: TimeoutError reached the caller")


await main()
```

到期时间由循环的时钟决定，`timeout` 保证的是「不会早于」这个下界，不保证毫秒级的准时（见 <CrossRef id="python.asyncio-scheduling" />）。期限在创建时还不知道时用 `asyncio.timeout(None)` 加 `reschedule()`，之后用 `expired()` 读回是否已经到期。

## 屏蔽

`shield` 的目标是让内部任务在外部这次取消中活下来。它挡住的只是取消本身，不改变调用方仍在被取消这个事实：

```python run id="py.async.shield"
import asyncio


async def important():
    await asyncio.sleep(0.02)
    return "finished anyway"


async def main():
    task = asyncio.create_task(important())
    try:
        async with asyncio.timeout(0.001):
            await asyncio.shield(task)
    except TimeoutError:
        print("the caller timed out | the shielded task is finished:", task.done())
    print("and it still produces its result:", await task)


await main()
```

调用方的等待被取消了，`task` 没有被取消——它继续运行并给出结果。屏蔽不是保留控制权，而是把这次取消挡在外部：调用方仍要在超时之后决定那个还在运行的任务怎么办，或者等待它。事件循环对 task 只持弱引用，被屏蔽的任务如果没有别处引用它，可能在结束前被回收，因此必须保留一个引用（见 [asyncio: Shielding from cancellation](https://docs.python.org/3/library/asyncio-task.html#shielding-from-cancellation)）。

## 结构化并发与聚合失败

`TaskGroup` 为它创建的任务建立共同的生命周期：正常退出时等待全部任务；某个子任务以非 `CancelledError` 异常失败时，取消其他任务，等待它们收尾，再把失败聚合后抛出。单个子任务被取消不自动触发兄弟任务取消。任务组作用域所在的父任务被取消时，组内任务也会被取消并等待结束（见 [asyncio：Task Groups](https://docs.python.org/3.14/library/asyncio-task.html#task-groups)）。

```python run id="py.async.task-group"
import asyncio


async def failing(ready):
    await ready.wait()
    raise ValueError("boom")


async def waiting(ready):
    try:
        ready.set()
        await asyncio.Future()
    finally:
        print("sibling cleanup")


async def main():
    ready = asyncio.Event()
    try:
        async with asyncio.TaskGroup() as group:
            group.create_task(waiting(ready))
            group.create_task(failing(ready))
    except* ValueError as failures:
        print("handled subgroup:", type(failures).__name__)
        print("failures:", [str(error) for error in failures.exceptions])
    print("scope ended after cleanup")


await main()
```

`ready` 保证等待任务已经进入受清理保护的路径，失败任务才抛异常。任务组交出的通常是 `ExceptionGroup`；若聚合中包含不属于 `Exception` 的基类异常，则使用 `BaseExceptionGroup`。`KeyboardInterrupt` 与 `SystemExit` 有特殊规则：取消并等待其他任务后重新抛出原异常，不聚合它们。

异常组（exception group）是保留多个失败的异常树，不能只按一个异常类型判断整组。普通 `except ValueError` 不会匹配包含 `ValueError` 的异常组；`except* ValueError` 则拆出匹配的子组交给处理块，剩余异常继续传播（见 [语言参考：except*](https://docs.python.org/3.14/reference/compound_stmts.html#except-star)）。即使只有一个失败，TaskGroup 也可能抛出异常组。

```python run id="py.async.exception-group-partial"
try:
    try:
        raise ExceptionGroup("two failures", [ValueError("bad value"), TypeError("bad type")])
    except* ValueError as matched:
        print("handled:", [type(error).__name__ for error in matched.exceptions])
except ExceptionGroup as remaining:
    print("propagated:", [type(error).__name__ for error in remaining.exceptions])
```

第二个例子直接构造固定异常组，使选择性处理的结果不依赖任务完成顺序。多个 `except*` 可以各自处理匹配部分；同一个 `try` 不能混写 `except` 与 `except*`。TaskGroup 的聚合规则不保证失败列表的次序，不能把顺序当作接口约定。

## 创建关系与等待关系

`create_task()` 本身不建立结构化父子所有权。需要区分三个机制：

| 结构 | 取消与收尾规则 |
| --- | --- |
| `create_task(child())` | 调度独立任务；仅凭创建关系，创建者的取消不会传给它 |
| `parent` 正在 `await child` | 取消 parent 会取消当前等待的 Future 或 Task；取消可沿等待边传播 |
| `TaskGroup` | 显式建立作用域，按组的取消、等待收尾与失败聚合规则管理任务 |

等待边规则由 [asyncio：Task.cancel](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.Task.cancel) 规定；`shield` 可以挡住沿这条边传给内部任务的取消。它不会自动接管内部任务的后续生命周期。

```python run id="py.async.waiting-edge"
import asyncio


async def child(started):
    try:
        started.set()
        await asyncio.Future()
    finally:
        print("child cleanup")


async def parent(started, children, await_child):
    inner = asyncio.create_task(child(started))
    children.append(inner)  # 调用方保留强引用并负责最终收尾
    try:
        if await_child:
            await inner
        else:
            await asyncio.Future()
    finally:
        print("parent cleanup")


async def compare(await_child):
    started = asyncio.Event()
    children = []
    outer = asyncio.create_task(parent(started, children, await_child))
    await started.wait()
    outer.cancel()
    try:
        await outer
    except asyncio.CancelledError:
        pass
    inner = children[0]
    print("await child:", await_child, "| child cancelled:", inner.cancelled())
    if not inner.done():
        inner.cancel()
        try:
            await inner
        except asyncio.CancelledError:
            pass


await compare(False)
await compare(True)
```

不等待 child 时，parent 正在等待另一个 Future，取消先沿那条边传播，child 仍然挂起；调用方随后显式取消并等待它。等待 child 时，取消传入 child，其清理先运行，再传播回 parent。示例里的 child 让取消继续传播；若它吞掉 `CancelledError`，不能据此保证 task 最终处于 cancelled 状态（<CrossRef id="python.cancellation-and-timeouts" />）。

等待边能传递当前取消，却不提供「作用域退出时所有创建的任务都结束」的保证。需要这条保证时，使用 TaskGroup：

```python run id="py.async.task-group-parent-cancel"
import asyncio


async def child(started):
    try:
        started.set()
        await asyncio.Future()
    finally:
        print("group child cleanup")


async def parent(started, children):
    try:
        async with asyncio.TaskGroup() as group:
            children.append(group.create_task(child(started)))
            await asyncio.Future()
    finally:
        print("parent cleanup | all children done:", all(task.done() for task in children))


async def main():
    started = asyncio.Event()
    children = []
    outer = asyncio.create_task(parent(started, children))
    await started.wait()
    outer.cancel()
    try:
        await outer
    except asyncio.CancelledError:
        print("parent cancellation reached caller")


await main()
```

父任务等待的不是 child，组内 child 仍会被取消并收尾，父任务才离开作用域。这条保证来自任务组的所有权规则。
