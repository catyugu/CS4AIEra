取消本身由 <CrossRef id="python.cancellation-and-timeouts" /> 建立：它是一次注入到执行流里的异常，在挂起点到达。这一课讲取消的两类应用——给一段等待设定期限，和给一组任务划定共同的生命周期。两者的失败模式都来自同一个事实：**谁被取消、谁负责收尾，由结构决定而不是由意图决定**。

## 超时取消的是当前 task

`asyncio.timeout(delay)` 返回一个异步上下文管理器。到期时它**取消进入这个上下文的那个 task**，并在上下文内部处理由此产生的 `CancelledError`，把它转换成 `TimeoutError` 抛出：

```python run id="py.async.timeout"
import asyncio


async def slow():
    try:
        await asyncio.sleep(10)
    except asyncio.CancelledError:
        print("the deadline cancelled this task")
        raise


async def main():
    try:
        async with asyncio.timeout(0.001):
            await slow()
    except TimeoutError as failure:
        print("the deadline reported:", type(failure).__name__)

    print("the loop is still usable:", await asyncio.sleep(0, result="yes"))


await main()
```

被等待的代码看到的是普通的取消，因此它的清理路径照常运行；调用方看到的是 `TimeoutError`。两个异常不是同一个东西，来源也不同：`CancelledError` 进入 task 内部，`TimeoutError` 由上下文管理器在退出时产生（见 [asyncio: Timeouts](https://docs.python.org/3/library/asyncio-task.html#timeouts)）。

这条区分在块内捕获异常时立刻显出后果：`timeout` 只能转换它自己传进去的那个 `CancelledError`。块内的 `except CancelledError` 把它截住并继续执行，上下文退出时就看不到异常，`TimeoutError` 也不会出现——超时被降级成了一次被吞掉的取消，这正是 <CrossRef id="python.cancellation-and-timeouts" /> 里描述的破坏。期限内完成的等待不受影响：

```python run id="py.async.timeout-not-expired"
import asyncio


async def main():
    async with asyncio.timeout(10):
        value = await asyncio.sleep(0, result="finished in time")
    print("within the deadline:", value)

    try:
        async with asyncio.timeout(0.001):
            await asyncio.sleep(10)
    except TimeoutError:
        print("past the deadline: TimeoutError reached the caller")


await main()
```

到期时间由循环的时钟决定，`timeout` 保证的是「不会早于」意义上的边界，不保证毫秒级的准时（见 <CrossRef id="python.asyncio-scheduling" />）。期限在创建时还不知道时用 `asyncio.timeout(None)` 加 `reschedule()`，之后用 `expired()` 读回是否已经到期。

## 屏蔽

`shield` 的目标是让内部任务在外部这次取消中活下来。它挡住的只是取消本身，不改变调用方仍在被取消这个事实：

```python run id="py.async.shield"
import asyncio


async def important():
    await asyncio.sleep(0.02)
    return "finished anyway"


async def main():
    task = asyncio.create_task(important())
    try:
        async with asyncio.timeout(0.001):
            await asyncio.shield(task)
    except TimeoutError:
        print("the caller timed out | the shielded task is finished:", task.done())
    print("and it still produces its result:", await task)


await main()
```

调用方的等待被取消了，`task` 没有被取消——它继续运行并给出结果。屏蔽不是保留控制权，而是把这次取消挡在外部：调用方仍要在超时之后决定那个还在运行的任务怎么办，或者等待它。事件循环对 task 只持弱引用，被屏蔽的任务如果没有别处引用它，可能在结束前被回收，因此必须保留一个引用（见 [asyncio: Shielding from cancellation](https://docs.python.org/3/library/asyncio-task.html#shielding-from-cancellation)）。

## 结构化并发

`TaskGroup` 让一组任务共享一个生命周期：任何一个子任务失败，其余被取消，并且全部结束之后才退出 `async with` 块。

```python run id="py.async.task-group"
import asyncio


async def failing():
    await asyncio.sleep(0)
    raise ValueError("boom")


async def waiting(name):
    try:
        await asyncio.sleep(10)
    finally:
        print("cleanup of the sibling:", name)


async def main():
    try:
        async with asyncio.TaskGroup() as group:
            group.create_task(waiting("a"))
            group.create_task(waiting("b"))
            group.create_task(failing())
    except Exception as failure:
        print("the group reported:", type(failure).__name__)

    print("the block is over only after every sibling has finished")


await main()
```

两个等待 10 秒的子任务都收到了取消并运行了清理，失败被聚合成一个异常组交给调用方。这正是 `create_task` 单独使用时不具备的保证：`TaskGroup` 会等待它创建的全部任务。失败是第一种触发路径，父任务被取消是第二种。

## 未被等待的子任务

`create_task` 创建的 task 不在任何任务的生命周期里，因此父任务被取消时它不会被收走。

```python run id="py.async.orphan-child"
import asyncio


async def child():
    try:
        await asyncio.sleep(0.01)
    finally:
        print("the child's cleanup ran")


async def parent():
    inner = asyncio.create_task(child())
    try:
        await asyncio.sleep(10)
    finally:
        print("the parent's cleanup ran | the child is finished:", inner.done())
    return inner


async def main():
    task = asyncio.create_task(parent())
    await asyncio.sleep(0)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("the parent was cancelled while its child was still running")
    await asyncio.sleep(0.1)
    print("the child outlived its parent and finished on its own")


await main()
```

取消只作用于被取消的那个 task。`parent` 里创建但没有等待的 `child` 不在取消范围内：父任务的清理已经跑完，子任务仍在自己推进，并独立地走完自己的收尾。要在取消时收走整棵子树，就必须用会等待所有子任务的结构（`TaskGroup`）或显式地取消并等待它们。
