进入一条需要握手的连接、以及关闭连接，同样可能要等。普通的 `with` 把进入与退出当作立刻完成的步骤，等待无处安放。`async with` 让这两步各自可以挂起，做法是在对应位置放入一个 `await`。它的展开与 <CrossRef id="python.context-managers" /> 记下的同步约定逐条对应，唯一的差别就是哪一步可以挂起。

## async with 的展开

`async with` 的展开与 `with` 逐条对应，区别只在进入与退出都是 `await`（见[语言参考](https://docs.python.org/3/reference/compound_stmts.html#the-async-with-statement)）：

```python
manager = expression
aenter = manager.__aenter__
aexit = manager.__aexit__
value = await aenter()
hit_except = False

try:
    target = value
    body
except:
    hit_except = True
    if not await aexit(*sys.exc_info()):
        raise
finally:
    if not hit_except:
        await aexit(None, None, None)
```

绑定 `as` 的名字、进入成功后正常与异常路径各调用一次 `__aexit__`、返回真值吞掉异常，这些不变量与同步版本相同，差别只在 `__aenter__` 与 `__aexit__` 是 await 的。进入阶段失败时 `__aexit__` 不执行：展开里 `value = await aenter()` 一旦抛出，`try` 还没有建立。三条路径可以直接观察：

```python run id="py.async.async-with-paths"
import asyncio


class Traced:
    def __init__(self, suppress):
        self.suppress = suppress
        self.log = []

    async def __aenter__(self):
        await asyncio.sleep(0)
        self.log.append("enter")
        return "resource"

    async def __aexit__(self, exc_type, exc, traceback):
        self.log.append(f"exit({exc_type.__name__ if exc_type else None})")
        return self.suppress


async def main():
    normal = Traced(suppress=False)
    async with normal as value:
        pass
    print("normal", normal.log, "bound", value)

    failing = Traced(suppress=False)
    try:
        async with failing:
            raise ValueError("boom")
    except ValueError:
        outcome = "propagated"
    print("raised", failing.log, outcome)

    swallowing = Traced(suppress=True)
    async with swallowing:
        raise ValueError("boom")
    print("truthy", swallowing.log, "suppressed")


await main()
```

正常退出时异常三元组是 `None`；块内抛出 `ValueError` 时 `__aexit__` 拿到它，返回假值让异常继续传播，返回真值则吞掉它，控制流在 `async with` 之后继续。抑制成立的条件与代价记在 <CrossRef id="python.context-managers" /> 里。

`contextlib.asynccontextmanager` 把异步生成器接到 `yield` 分段规则上：`yield` 之前是进入，之后的 `finally` 是退出，`yield` 的值绑定给 `as` 的名字；分段与异常注入的完整规则见 <CrossRef id="python.context-managers" />。

```python run id="py.async.asynccontextmanager"
import asyncio
from contextlib import asynccontextmanager


events = []


@asynccontextmanager
async def connected(name):
    events.append(f"acquire {name}")
    try:
        await asyncio.sleep(0)
        yield name
    finally:
        events.append(f"release {name}")


async def main():
    async with connected("db") as handle:
        events.append(f"body bound {handle}")
    print("normal", events)

    events.clear()
    try:
        async with connected("other"):
            raise RuntimeError("body failed")
    except RuntimeError as failure:
        print("failed", events, failure)


await main()
```

捕获后正常返回会在异步侧同时成立两件事：`__aexit__` 得到真值并抑制异常，异步生成器走到结束，同一个管理器不能第二次进入。

```python run id="py.async.asynccontextmanager-suppression"
from contextlib import asynccontextmanager


@asynccontextmanager
async def absorbing():
    try:
        yield
    except ValueError:
        pass


async def main():
    manager = absorbing()
    async with manager:
        raise ValueError("body failed")
    print("body ValueError:", "suppressed")
    reused = True
    try:
        async with manager:
            pass
    except Exception:
        reused = False
    print("reusable:", reused)

await main()
```
