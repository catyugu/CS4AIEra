一个程序要从两个远端服务各取一份数据，再读一份本地文件，然后把三份汇总。

```python
import json
import urllib.request


def load_dashboard():
    with urllib.request.urlopen("https://example.com/profile.json") as response:
        profile = json.load(response)   # returns after the network round trip
    with urllib.request.urlopen("https://example.com/prices.json") as response:
        prices = json.load(response)    # starts only after the first response
    with open("report.json") as f:
        report = json.load(f)           # waits on the disk
    return profile, prices, report
```

每次 `urlopen` 都要等一次网络往返，`open` 要等磁盘把文件读上来。三段等待依次发生，总耗时是它们的和；第一段没有结束，第二段无法开始，这段时间里 CPU 空闲，本可以去处理已经到达的那一份。

要让等待重叠起来，一个计算需要能在等待处暂停、条件满足后再从原地继续。`async def` 定义的就是这种计算，`await` 标出暂停的位置；谁来接着驱动它、下一次轮到哪个计算，由**事件循环**与**任务**（task）决定。分清「谁在驱动谁」之后，输出顺序与卡住的原因都可以从代码结构推出。

## 协程、await 与事件循环

- `async def` 定义的是协程函数。调用它返回一个**协程对象**（coroutine object），不执行函数体。协程对象是一次还没有开始的计算。
- 协程对象是可等待对象：`await expr` 驱动它运行，直到它返回或暂停在挂起点。
- `await` 有两个效果，在同一个表达式里一起发生：把当前协程挂起、把控制权交回驱动它的调度器，并把被等待对象的结果作为表达式的值。被等待的对象已经就绪时，控制权不离开当前协程。
- **task** 是被调度器驱动的协程。`asyncio.create_task(coro)` 立即返回一个 task 对象，并把该协程交给事件循环调度。默认调度模式下，协程要等创建它的协程到达下一个挂起点才有机会被步进。
- **事件循环**持有就绪队列，反复取出下一个条目并推进它。协程只在**挂起点**让出控制权：`await` 一个尚未就绪的对象是挂起点，`await` 一个已经就绪的对象不是。
- 因此切换总是由被运行的代码自己发起，任何位置都不会被抢占。一个不释放控制权的函数会占住整个循环：在协程里直接调用一个长时间返回的同步函数，循环里的其他 task 全部停住。

`await` 与协程对象的规定在[语言参考的协程一节](https://docs.python.org/3/reference/compound_stmts.html#coroutines)；task 与事件循环是标准库 [asyncio](https://docs.python.org/3/library/asyncio-task.html) 的接口约定，不是语言语法的一部分；让阻塞部分离开循环属于运行时结构问题，不在语言语法范围内。

## 调用 async def 不执行任何东西

```python run id="py.async.call-returns-coroutine"
async def greet(name):
    print("the body starts here")
    return "hello " + name


pending = greet("Ada")
print("calling an async def returned:", type(pending).__name__)
print("nothing in the body has run yet")

value = await pending
print("the awaited value is:", value)
```

调用返回的是 `coroutine` 对象，函数体一行都没有执行：`the body starts here` 出现在 `await` 之后。这一点把「创建一个计算」与「运行这个计算」分开——协程对象可以被传递、放进容器、稍后再驱动，也可以永远不被驱动：调用而不 await 它，函数体永远不执行，解释器在对象被回收时给出「协程从未被 await」的警告，告警点不在调用处。

## await 驱动被等待的对象

```python run id="py.async.await-drives"
import asyncio


async def worker(name):
    print(name, "starts")
    await asyncio.sleep(0)
    print(name, "resumes")


async def main():
    print("main reaches the await")
    await worker("A")
    print("main resumes after worker returned")


await main()
```

`await worker("A")` 把控制权交给 `worker` 的协程，直到它返回；`main` 在那一行之后才继续。整段代码的先后顺序由代码结构决定，与 `sleep(0)` 的时长无关——它要求的只是「让出一次」。被等待对象抛出的异常在 `await` 表达式处重新抛出，之后按普通异常传播（见 <CrossRef id="python.exceptions" />）；从未被取回的 task 异常在对应 task 被垃圾回收时记录为一条 “Task exception was never retrieved” 日志（[asyncio — Coroutines and tasks](https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task)）。

## task 什么时候运行

`create_task` 只把协程交给循环，执行交给循环调度。

```python run id="py.async.task-runs-later"
import asyncio


async def worker(name):
    print("task", name, "is running")
    return name


async def main():
    task = asyncio.create_task(worker("X"))
    print("create_task returned immediately | finished:", task.done())
    print("the coroutine has not started")
    await asyncio.sleep(0)
    print("after one suspension | finished:", task.done())
    print("the task's result:", await task)


await main()
```

在当前运行时的默认调度模式下，`create_task` 返回时 task 处于「已登记、未运行」状态，`done()` 为假；协程体要等 `main` 到达第一个挂起点才被步进，上面输出里的 `finished: False` 与 `the coroutine has not started` 就是本课程当前 Pyodide WebLoop 上的可观察结果。`await task` 取出结果：task 已经完成时它立即返回，未完成时它挂起当前协程直到 task 结束。`create_task` 自 3.14 起接受 `eager_start`：为真时协程在创建调用内立即开始执行，直到第一次阻塞点（[asyncio — Coroutines and tasks](https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task)）。

## 就绪队列顺序下的输出

两个 task 交替推进，一轮里各自前进一步。`sleep(0)` 让出控制权时，循环把当前 task 的续跑排在已注册的回调之后，于是先推进另一个 task：

```python run id="py.async.ready-queue"
import asyncio


async def worker(name, steps):
    for step in range(steps):
        print(name, step)
        await asyncio.sleep(0)


async def main():
    await asyncio.gather(worker("a", 2), worker("b", 2))


await main()
```

输出是 `a 0`、`b 0`、`a 1`、`b 1`：`sleep(0)` 让出控制权，循环通过 `call_soon` 把当前 task 的续跑排在已注册的回调之后（[asyncio — Event loop](https://docs.python.org/3/library/asyncio-eventloop.html#asyncio.loop.call_soon)），于是先推进另一个 task。这个具体交错是本课程当前 Pyodide WebLoop 上的可观察结果；整个任务池没有逐条顺序保证，asyncio 的概念文档把任务集合描述为一个队列，元素 generally (but not always) in order（[A conceptual overview of asyncio](https://docs.python.org/3/howto/a-conceptual-overview-of-asyncio.html)）。基于时间的相对完成顺序则由循环的时钟与负载决定，把它写进测试等于把调度器实现写进断言。

同样的性质解释了 `gather` 的返回值：任务的**完成顺序**不影响结果的**排列顺序**，结果按传入顺序排。

```python run id="py.async.gather-order"
import asyncio


async def delayed(value, turns):
    for _ in range(turns):
        await asyncio.sleep(0)
    return value


async def main():
    results = await asyncio.gather(delayed("first", 3), delayed("second", 1), delayed("third", 2))
    print("the result list follows the argument order:", results)


await main()
```

## 没有挂起点就没有交错

交错只发生在挂起点。一个内部不挂起的函数从头到尾占住循环。

```python run id="py.async.no-suspension-point"
import asyncio


async def compute(size):
    return sum(range(size))


async def report(name, size):
    print(name, "entered; nothing can interleave inside this function")
    result = await compute(size)
    print(name, "left with", result)


async def main():
    await asyncio.gather(report("a", 10_000), report("b", 10_000), report("c", 10_000))


await main()
```

`await compute(size)` 不是挂起点：`compute` 不等待任何东西，它在被驱动时一次跑完。三个 task 因此依次完成，输出里没有任何交错。把三份工作重叠起来，需要它们各自到达一个挂起点；放进同一个 `gather` 并不能让它们重叠。页面上的**停止**按钮通过终止 worker 结束执行，它不是协作式的打断。

## 事件循环由环境提供

```python run id="py.async.loop-provided"
import asyncio

loop = asyncio.get_running_loop()
print("the cell already runs inside a loop:", loop.is_running())
print("whose implementation is:", type(loop).__module__ + "." + type(loop).__name__)
print("this loop was provided by the environment, not created by the cell")
```

单元格的顶层代码本身运行在一个已经存在的事件循环里，因此单元格用顶层 `await` 驱动协程，不需要自己创建循环。打印出的实现名说明循环由运行环境提供，属于环境事实：本运行时是 Pyodide 的 WebLoop，语言只规定 task 与循环要满足 `asyncio` 的接口，不规定具体类型或时钟精度。`asyncio.current_task()` 给出当前正在被步进的 task，`task.get_name()` 给出名字，而 `type(task)` 的类名随运行环境变化。
