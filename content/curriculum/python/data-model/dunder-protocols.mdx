上一课把属性访问拆成了查找过程。语言里还有另一类「看起来像语法、实际是方法调用」的位置：`a + b`、`len(x)`、`x[0]`、`for item in x`、`with open(...)`、`obj()`。它们都不看对象的属性字典，而是调用对象的类型上的一组约定方法——这批方法叫特殊方法，这组约定叫协议。
## 特殊方法的调用与查找

特殊方法是普通函数，特殊之处只在**调用方式**与**查找位置**：

- 由解释器在特定语法或内置函数处调用，通常不写成 `obj.__add__(other)`——虽然那样写等价于 `a + b`（反射与回退除外）。
- **在类型上查找，不在实例上查找**。`len(instance)` 找的是 `type(instance).__len__`，实例字典里的同名条目被忽略；这与上一课的普通属性查找规则相反，是读这类代码时最容易出错的一点。
- 方法名是一份固定的清单，由语言定义，不能自己发明被语法调用的新名字。`__eq__` 与 `__hash__` 是一对：定义 `__eq__` 会让类型失去默认哈希，容器里能不能用它取决于 `__hash__`，完整约束见 <CrossRef id="python.equality-and-hashing" />。

常见对应关系：

| 语法或内置 | 特殊方法 | 找不到时的默认 |
| --- | --- | --- |
| `a + b` / `a * b` / `a - b` | `__add__` / `__mul__` / `__sub__` | `TypeError` |
| `a == b` / `a < b` | `__eq__` / `__lt__` | 同一性比较 / `TypeError` |
| `len(x)` | `__len__` | `TypeError` |
| `bool(x)` | `__bool__`，退回 `__len__` | 恒为真 |
| `x[i]` / `x[i] = v` | `__getitem__` / `__setitem__` | `TypeError` |
| `for item in x` | `__iter__` | 用 `__getitem__` 逐个取 |
| `item in x` | `__contains__` | 迭代后逐个比较 |
| `str(x)` / `repr(x)` | `__str__` / `__repr__` | 退回 `__repr__` / 默认形式 |
| `x()` | `__call__` | `TypeError` |
| `with x:` | `__enter__` / `__exit__` | `TypeError` |

三类回退值得记住：

1. **布尔上下文**：先找 `__bool__`，找不到再用 `__len__`，都没有就是真。
2. **`str()` 退回 `repr()`**：只定义 `__repr__` 时 `str(x)` 也用它；只定义 `__str__` 时 `repr(x)` 仍是默认形式。
3. **二元运算**：左操作数的类型先用正向方法；若它返回 `NotImplemented`，解释器换用右操作数类型上的反向方法（`__radd__`、`__rmul__` 等）；两边都放弃才抛 `TypeError`。返回 `NotImplemented` 的意思是「这个类型不处理这种操作数」，它与「操作结果为空」的 `None` 无关，也不能用 `NotImplementedError` 代替——后者是异常，直接终止。

**协议**是一组特殊方法的集合：实现它们，对象就获得了对应的语法行为；不需要继承任何类。`collections.abc` 提供的是**检查**：`isinstance(x, Sized)` 实际上在问「`type(x)` 上有 `__len__` 吗」，因此自定义类不必继承 ABC 也能通过检查。

## 查找发生在类型上

```python run id="py.dunder.lookup-on-type"
class Playlist:
    def __init__(self, tracks):
        self.tracks = list(tracks)

    def __len__(self):
        return len(self.tracks)

    def __getitem__(self, index):
        return self.tracks[index]


playlist = Playlist(["a", "b", "c"])
print("len:", len(playlist), "| index:", playlist[0])
print("iteration uses __getitem__ when __iter__ is absent:", [track.upper() for track in playlist])
print("membership reuses __getitem__:", "b" in playlist)

playlist.__len__ = lambda: 99           # set on the instance
print("an instance attribute with that name is ignored:", len(playlist))

type(playlist).__len__ = lambda self: 99
print("changing the type does change the result:", len(playlist))
```

实例上的 `__len__` 完全不起作用：`len()` 在 `type(playlist)` 上查找，实例字典不参与。把 `__len__` 从实例上删掉也不会有任何差别——这个位置对特殊方法从来就不是一个可选来源。类的属性被替换后才生效，因为查找的目标始终是类型。只实现 `__getitem__` 的对象在 `iter()`、`in` 与解包上走的是逐索引路径，效率与语义都与实现了 `__iter__` 的对象不同（见 <CrossRef id="python.iteration-protocol" />）。

```python run id="py.dunder.missing-method"
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y


point = Point(1, 2)
try:
    len(point)
except TypeError as failure:
    print("len on a class without __len__:", failure)

try:
    point + point
except TypeError as failure:
    print("+ without __add__:", failure)

print("x[0] on an object without __getitem__:")
try:
    point[0]
except TypeError as failure:
    print("  ", failure)
```

没有实现协议时错误来自调用点，消息里给出类型名与被调用的协议。这类 `TypeError` 是用错的信号：对象不支持这项操作，而不是它的某个属性有问题。

## 运算与反向方法

```python run id="py.dunder.reflected-operations"
class Scaled:
    def __init__(self, factor):
        self.factor = factor

    def __mul__(self, other):
        print("  __mul__ called with", other)
        if isinstance(other, (int, float)):
            return Scaled(self.factor * other)
        return NotImplemented

    def __rmul__(self, other):
        print("  __rmul__ called with", other)
        if isinstance(other, (int, float)):
            return Scaled(self.factor * other)
        return NotImplemented

    def __repr__(self):
        return f"Scaled({self.factor})"


print("Scaled(3) * 2 ->", Scaled(3) * 2)
print("2 * Scaled(3) ->", 2 * Scaled(3))

try:
    Scaled(3) * "x"
except TypeError as failure:
    print("both sides declined:", failure)
```

`2 * Scaled(3)` 先调用 `int.__mul__(2, scaled)`，它不认识 `Scaled` 并返回 `NotImplemented`，解释器于是调用 `scaled.__rmul__(2)`。第三次调用两边都返回 `NotImplemented`，`TypeError` 由解释器给出，而不是由任何一方抛出。

需要的规则是：**只要你的类型可能与内置类型混合运算，就要实现反向方法**；`__mul__` 里对不认识的操作数返回 `NotImplemented`，而不是抛异常，这样别的类型还有机会处理。运算符重载不等于数学定义：`+` 在自定义类型上的含义由实现者决定，列表的连接、字符串的拼接与数值的加法互不相同。`__lt__` 等六个比较方法各自独立，`sorted` 只需要 `__lt__`；只实现其中一部分时，另一部分语法仍然失败。

## 表示与真假

```python run id="py.dunder.repr-and-bool"
class Basket:
    def __init__(self, items):
        self.items = list(items)

    def __repr__(self):
        return f"Basket({self.items!r})"

    def __len__(self):
        return len(self.items)


class Label:
    def __init__(self, text):
        self.text = text

    def __str__(self):
        return f"label: {self.text}"


class Bare:
    pass


print("repr only:", repr(Basket(["apple"])), "| str falls back to repr:", str(Basket(["apple"])))
print("str only:", str(Label("x")), "| repr stays the default:", "Label" in repr(Label("x")) and "label:" not in repr(Label("x")))
print("the default repr names the type and an address:", "object at 0x" in repr(Bare()))

empty = Basket([])
print("truthiness comes from __len__:", bool(Basket(["apple"])), bool(empty))
print("no __bool__ and no __len__ means always true:", bool(Bare()))
```

`repr` 的默认形式带类型名与地址，对调试没有价值；一个只为内部使用的类定义 `__repr__` 就足够，`str` 会自动回退。反向不成立：只定义 `__str__` 时 `repr` 仍是默认形式，因为两个名字服务于不同读者——`repr` 面向开发者，要求无歧义且能看出类型；`str` 面向使用者，可以只求可读。真假的来源顺序是 `__bool__`、`__len__`、恒为真：定义 `__len__` 的容器因此自动获得「空即为假」的行为，这是容器语义的一部分，而不是巧合。

## 检查一个对象支持什么

```python run id="py.dunder.protocol-check"
from collections.abc import Callable, Iterable, Sized


class Bag:
    def __init__(self, items):
        self.items = list(items)

    def __len__(self):
        return len(self.items)

    def __iter__(self):
        return iter(self.items)


class Plain:
    pass


bag = Bag([1, 2, 3])
print("Bag without inheriting any ABC:", isinstance(bag, Sized), isinstance(bag, Iterable), isinstance(bag, Callable))
print("Plain:", isinstance(Plain(), Sized), isinstance(Plain(), Iterable))

print("the check reads the type:", isinstance(3, Sized), isinstance("abc", Sized))
print("a function is callable, a list is not:", isinstance(len, Callable), isinstance([], Callable))
```

`isinstance(bag, Sized)` 为真，而 `Bag` 与 `Sized` 没有任何继承关系：抽象基类在这里充当协议的定义——它规定了「要实现哪些方法才算支持这项能力」，检查则落到类型的方法上。因此**协议是隐式的**：写代码依赖的是方法存在，不是类型相等；需要显式检查时才用 ABC，或直接尝试调用并捕获 `TypeError`。协议只约束方法名，不约束语义——实现了 `__len__` 的对象会被当作有长度，长度是否合理由实现者负责；`len()` 还检查返回值，非整数抛 `TypeError`，负数抛 `ValueError`。
