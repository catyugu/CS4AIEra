在一个类型上定义 `__len__`，`len(obj)` 就会调用它；把同名方法挂到实例上，`len(obj)` 却视而不见。`a + b`、`x[0]`、`for item in x` 处是同一套做法：语法与内置函数把操作委托给一个固定名字的方法，而这些方法在**类型**上查找，不在实例上。名字由语言定为一份固定清单；实现其中一个，对象就获得对应的语法行为，不需要继承任何类。这批被调用的固定名字叫特殊方法，这组约定叫协议。

## 查找发生在类型上

```python run id="py.dunder.lookup-on-type"
class Playlist:
    def __init__(self, tracks):
        self.tracks = list(tracks)

    def __len__(self):
        return len(self.tracks)


playlist = Playlist(["a", "b", "c"])
print("len uses the type's __len__:", len(playlist))

playlist.__len__ = lambda: 99           # set on the instance
print("an instance attribute with that name is ignored:", len(playlist))

type(playlist).__len__ = lambda self: 99
print("changing the type does change the result:", len(playlist))

try:
    len(object())
except TypeError as failure:
    print("no __len__ on the type:", failure)
```

实例字典里的 `__len__` 不参与查找：`len(playlist)` 找的是 `type(playlist).__len__`，替换类属性才改变结果。类型上也没有这个方法时，`len()` 在调用点抛出 `TypeError`，消息里给出类型名与被调用的协议；这是对象不支持这项操作的信号。

## 运算与反向方法

```python run id="py.dunder.reflected-operations"
class Scaled:
    def __init__(self, factor):
        self.factor = factor

    def __mul__(self, other):
        print("  __mul__ called with", other)
        if isinstance(other, (int, float)):
            return Scaled(self.factor * other)
        return NotImplemented

    def __rmul__(self, other):
        print("  __rmul__ called with", other)
        if isinstance(other, (int, float)):
            return Scaled(self.factor * other)
        return NotImplemented

    def __repr__(self):
        return f"Scaled({self.factor})"


print("Scaled(3) * 2 ->", Scaled(3) * 2)
print("2 * Scaled(3) ->", 2 * Scaled(3))

try:
    Scaled(3) * None
except TypeError as failure:
    print("neither operand type handles it:", failure)
```

`2 * Scaled(3)` 先调用 `int.__mul__(2, scaled)`，它不认识 `Scaled` 并返回 `NotImplemented`，解释器于是调用 `scaled.__rmul__(2)`。`Scaled(3) * None` 里 `Scaled.__mul__` 返回 `NotImplemented`，右侧没有能处理 `Scaled` 的乘法方法，解释器据此给出 `TypeError`。类型可能与内置类型混合运算时就要实现反向方法，并在正向方法里对不认识的操作数返回 `NotImplemented`，让别的类型还有机会处理。`NotImplemented` 表示这个类型不处理这种操作数，与表示空结果的 `None` 无关，也不能用异常 `NotImplementedError` 代替。

## 表示与真假

```python run id="py.dunder.repr-and-bool"
class Basket:
    def __init__(self, items):
        self.items = list(items)

    def __repr__(self):
        return f"Basket({self.items!r})"

    def __len__(self):
        return len(self.items)


class Label:
    def __init__(self, text):
        self.text = text

    def __str__(self):
        return f"label: {self.text}"


class Bare:
    pass


print("repr only:", repr(Basket(["apple"])), "| str falls back to repr:", str(Basket(["apple"])))
print("str only:", str(Label("x")), "| repr stays the default:", "Label" in repr(Label("x")) and "label:" not in repr(Label("x")))
print("the default repr names the type and an address:", "object at 0x" in repr(Bare()))

empty = Basket([])
print("truthiness comes from __len__:", bool(Basket(["apple"])), bool(empty))
print("no __bool__ and no __len__ means always true:", bool(Bare()))
```

`repr` 的默认形式带类型名与地址，对调试没有价值；只在内部使用的类定义 `__repr__` 就足够，`str` 会自动回退。反向不成立：只定义 `__str__` 时 `repr` 仍是默认形式，因为两个名字面向不同读者——`repr` 面向开发者，惯例是无歧义且能看出类型；`str` 面向使用者，可以只求可读。语言只要求 `__repr__` 返回字符串；把它写成能重建该值的表达式只是惯例 <CrossRef id="python.runtime-vs-language" />。真假的来源顺序是 `__bool__`、`__len__`、恒为真：定义 `__len__` 的容器因此自动获得「空即为假」的行为。
