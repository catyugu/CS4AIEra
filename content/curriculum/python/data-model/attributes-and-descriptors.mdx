读 `temperature.celsius` 返回摄氏度，写它会先校验、越界时抛 `ValueError`。可 `celsius` 只定义在类上，往 `temperature.__dict__` 里放一个同名的 `celsius` 也改变不了读到的结果——「读属性先看实例，再看类」（见 <CrossRef id="python.classes" />）解释不了这两件事。要预测这类代码，得把 `obj.attr` 当成一次**查找过程**：读、写、删按固定的来源顺序落到某一段代码上。
## 属性查找的顺序

`obj.attr` 是一次调用，不是一个地址。它按固定顺序在几个来源里找 `attr`，找到后可能直接返回，也可能先调用一段代码再返回。顺序由语言参考的数据模型一章规定，所有实现一致。

普通对象上，读取 `obj.attr` 的顺序是：

1. `type(obj)` 上名为 `attr` 的数据描述符（定义了 `__set__` 或 `__delete__` 的描述符）；
2. `obj` 自己的属性字典（`__dict__`）；
3. `type(obj)` 的 MRO（见 <CrossRef id="python.inheritance-and-mro" />）上名为 `attr` 的非数据描述符或普通类属性。

三条推论：

- **实例字典不是第一顺位。** 只有类型上没有名为 `attr` 的数据描述符时，实例字典才参与。
- **函数是非数据描述符**，因此函数可以被实例字典里的同名属性遮蔽。
- **`__getattr__` 是兜底**：上面全部失败后才被调用，它必须抛 `AttributeError`，`hasattr` 与 `getattr(obj, name, default)` 都靠这个异常判断属性是否存在。覆盖每次访问都要走的 `__getattribute__` 会拦截一切读取，容易写出递归；要拦截特定属性用 `__getattr__`。

对象只要定义了 `__get__`、`__set__`、`__delete__` 中的任意一个，就是一个**描述符**：通过 `obj.attr` 的读、写、删由它的同名方法接管。定义了 `__set__` 或 `__delete__` 的是**数据描述符**，在查找里排第一；只定义 `__get__` 的是**非数据描述符**，排在实例字典之后。函数、`property`、`__slots__` 生成的槽位都走这套协议。

函数定义在类上，是一个非数据描述符。读取 `instance.method` 时协议被触发，`function.__get__(instance, type(instance))` 返回一个绑定方法，它记住实例与函数——`self` 在调用发生之前就被绑进可调用对象里。

## 属性来自哪里

```python run id="py.attr.sources-order"
class Base:
    kind = "class attribute"

    def label(self):
        return "method from the class"


class Item(Base):
    pass


item = Item()
print("1. found on the class:", item.kind)

item.kind = "instance attribute"
print("2. instance dict shadows a plain class attribute:", item.kind, "| class still:", Item.kind)

item.label = lambda: "lambda from the instance"
print("3. it also shadows a function:", item.label())

del item.label
print("4. after deletion the descriptor is found again:", item.label())
```

前三步说明实例字典的位置：它在普通类属性和非数据描述符之前，但在数据描述符之后。第四步说明「遮蔽」只是多了一层来源，删除之后查找重新落到类上。

## property 是数据描述符

`property` 是内置的数据描述符：它把读写转发到被装饰的函数上，并因此获得第一顺位。

```python run id="py.attr.property-wins"
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError(f"below absolute zero: {value}")
        self._celsius = value


temperature = Temperature(20)
print("reading it:", temperature.celsius, "| instance dict:", temperature.__dict__)

temperature.celsius = 30
print("after assignment:", temperature.celsius, temperature.__dict__)

try:
    temperature.celsius = -300
except ValueError as failure:
    print("the setter rejected the value:", failure)

temperature.__dict__["celsius"] = 999
print("an instance dict entry with the same name changes nothing:", temperature.celsius)
```

最后两步是关键证据：`celsius` 是数据描述符，因此 `temperature.__dict__` 里的同名条目**不参与读取**——实例字典在这一顺位之前就已经被跳过了。`property` 拿到了第一顺位，用它实现「读时计算、写时校验」，不靠外部约定。

`__dict__` 里的存储名是 `_celsius`：描述符协议只在通过 `obj.attr` 读写时被触发，直接写 `__dict__` 可以绕过它。同名条目留在实例字典里，则成为读取时不可见的死数据。

## 方法绑定

```python run id="py.attr.binding"
class Counter:
    def __init__(self):
        self.value = 0

    def increment(self, step=1):
        self.value += step
        return self.value


counter = Counter()
bound = counter.increment

print("on the class it is a plain function:", type(Counter.increment).__name__)
print("on the instance it is a bound method:", type(bound).__name__)
print("the method carries both parts:", bound.__self__ is counter, bound.__func__ is Counter.increment)
print("each access builds a new object:", counter.increment is counter.increment, counter.increment == counter.increment)
print("calling it:", bound(), counter.increment(5))
```

`type(Counter.increment).__name__` 是 `function`，`type(counter.increment).__name__` 是 `method`。绑定方法持有 `__self__`（实例）与 `__func__`（类上的函数），因此 `Counter.increment(instance)` 与 `instance.increment()` 调用的是同一段函数，后者只是把实例预先绑好了。

每次访问都创建一个新的绑定方法对象（`is` 为假，`==` 为真，因为方法按实例与函数比较）。把方法存下来备用，存的是一个已经绑定到实例的对象，它指向定义时那个函数。

## 自己写一个描述符

描述符的用途是让「通过属性访问」这件事自带行为：校验、惰性计算、把值转发到别处。一个最小实现只需要 `__get__` 与 `__set__`。

```python run id="py.attr.custom-descriptor"
class Positive:
    """A data descriptor that stores the value in the instance dict."""

    def __init__(self, name):
        self.name = name

    def __get__(self, instance, owner=None):
        if instance is None:
            return self
        return instance.__dict__[self.name]

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self.name} must be positive, got {value}")
        instance.__dict__[self.name] = value


class Order:
    quantity = Positive("quantity")
    price = Positive("price")

    def __init__(self, quantity, price):
        self.quantity = quantity
        self.price = price

    def total(self):
        return self.quantity * self.price


order = Order(2, 10.5)
print("total:", order.total(), "| stored in the instance dict:", order.__dict__)

try:
    order.quantity = 0
except ValueError as failure:
    print("the descriptor rejected it:", failure)

print("reading it on the class returns the descriptor itself:", type(Order.quantity).__name__)
order.__dict__["quantity"] = 100
print("writing through __dict__ bypasses __set__:", order.total())
```

两个细节：`__get__` 里 `instance is None` 的分支处理「通过类读取」（例如 `Order.quantity`）；描述符实例在类上只创建一次、被所有实例共用，所以值存在实例字典里，描述符只负责规则。

## 槽位描述符

```python run id="py.attr.slots"
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y


point = Point(1, 2)
print("values:", point.x, point.y)
print("the class holds descriptors, not values:", hasattr(Point.x, "__get__") and hasattr(Point.x, "__set__"))
print("has an instance dict:", hasattr(point, "__dict__"))

try:
    point.z = 3
except AttributeError as failure:
    print("an undeclared attribute cannot be assigned:", failure)
```

`__slots__` 取消实例字典：类上为每个名字生成一个数据描述符，值存在实例固定的槽位里，`point.x` 仍然是一次属性访问。没有 `__dict__` 后，给未声明的属性赋值会失败，拼错的名字从静默新建属性变成可见的错误；子类未声明 `__slots__` 会重新获得 `__dict__`。
