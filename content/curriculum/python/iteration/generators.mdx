在函数体里写一次 `yield`，调用行为就变了。下面 `tracked` 在函数体开头打印，再把每个值乘十；`tracked([1, 2])` 返回一个对象，调用那一刻，函数体里的 `print` 一行也不会执行。

## yield 与 return 的区别

```python run id="py.gen.lazy"
def tracked(values):
    print("generator body starts here")
    for value in values:
        print("about to yield", value)
        yield value * 10


generator = tracked([1, 2])
print("call returned a generator:", type(generator).__name__)
print("first next:", next(generator))
print("between calls, nothing runs")
print("second next:", next(generator))
try:
    next(generator)
except StopIteration:
    print("exhausted")
```

函数体直到第一次 `next` 才从头运行，`generator body starts here` 出现在 `first next` 之后。调用生成器函数只负责构造对象，执行在每次取值时推进：函数体运行到下一个 `yield` 停下，局部帧连同已绑定的名字留在原地，下一次取值从挂起处继续。`yield` 交出值之后函数还能接着跑，`return` 交出值就结束这次调用，两者的区别就在帧的去留上。

函数体里含 `yield` 的函数是生成器函数（generator function），调用它得到生成器对象（generator object）。生成器对象是迭代器（iterator），`for`、`next`、`list` 都按迭代协议消费它。

## 惰性：值在被取用时才算

函数体挂起之后，两次 `next` 之间不消耗计算，调用方取多少，生成器就算多少。两级生成器串成的管道直接体现这一点：

```python run id="py.gen.pipeline"
def squares(values):
    for value in values:
        yield value * value


def only_even(values):
    for value in values:
        if value % 2 == 0:
            yield value


pipeline = only_even(squares(range(1_000_000)))
print("first five results:", [next(pipeline) for _ in range(5)])
print("bounded aggregation:", sum(only_even(squares(range(10)))))

materialised = [value for value in only_even(squares(range(1000)))]
print("eager version holds every element:", len(materialised))
```

`only_even(squares(range(1_000_000)))` 描述了一百万个平方再过滤，调用方只取前五个时，`squares` 只算到能交出第五个偶数为止，其余元素从未计算。`materialised` 用列表推导式把每一步算完再放进列表，占用的元素数与输入规模成正比。生成器不保存中间结果，值一个接一个地从函数体传给调用方。

逐个取值的开销高于直接迭代列表：每次 `next` 都有一次函数调用与状态切换。需要完整结果又在意常数时，先物化成列表反而更快；用生成器是为了让只取一部分、以及一次算不完的序列变得可行。

## 生成器表达式

把一个列表推导式的方括号换成圆括号，得到的对象就是生成器：元素在被取值时才计算，构造它本身不跑循环体。

```python run id="py.gen.genexp"
squares = (value * value for value in range(5))
print("type:", type(squares).__name__)
print("computed on request:", next(squares), next(squares))
print("the rest:", list(squares))

eager = [value * value for value in range(5)]
print("already built:", eager)
```

`squares` 取值时才逐个算 `value * value`，`next` 取两个就算两个，构造它的那一刻一次乘法也没发生；`eager` 的方括号在构造时就把五个乘积全部算完放进列表。同一副骨架换一对括号，决定结果是按需产出还是立即物化。

## 生成器只能遍历一次

```python run id="py.gen.state"
def running_total(values):
    total = 0
    for value in values:
        total += value
        yield total


generator = running_total([1, 2, 3])
print("iter(g) is g:", iter(generator) is generator)
print("partial totals:", next(generator), next(generator))
print("remaining:", list(generator))
print("after exhaustion:", list(generator))
```

`total` 在两次 `next` 之间保持取值，它存在挂起的帧里。`iter(generator) is generator` 为真：生成器就是自身的迭代器，状态只有当前位置一处，没有第二个读取位置（见 <CrossRef id="python.iteration-protocol" />）。`list(generator)` 取走剩余部分之后，再 `list(generator)` 只剩空序列，迭代器耗尽不会重启，要重新遍历就重新调用生成器函数拿一个新对象。`for`、推导式与 `zip` 消费的是同一份帧，一个消费者取走的值，另一个看不到。

## 委托：yield from

`yield from` 让一个生成器把取值委托给另一个可迭代对象：内层产出的值直接穿过外层到达调用方，外层不必手写转发循环。

```python run id="py.gen.delegate"
def doubled(values):
    for value in values:
        yield value * 2


def concatenated(first, second):
    yield from doubled(first)
    yield from doubled(second)


print("delegated stream:", list(concatenated([1, 2], [3])))
```

`concatenated` 依次把两个 `doubled` 的产出委托出去，`list` 消费到两段翻倍连成的完整序列；两行 `yield from` 代替了 `for value in doubled(...): yield value`，谁委托给谁在代码里直接可见。
