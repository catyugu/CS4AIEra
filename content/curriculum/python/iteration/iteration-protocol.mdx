「能放进 `for` 里」不是一个类型属性，而是两个方法构成的协议。分清协议的两侧之后，`for`、推导式、`zip`、`sum` 与任何接受可迭代对象的库函数的行为都可以从这两个方法推出，包括「为什么第二次遍历得到空结果」这类常见故障。

## iterable 与 iterator 协议

协议由两个方法构成，作用不同：

| 方法 | 作用 |
| --- | --- |
| `__iter__` | 返回一个迭代器。可迭代对象的入口 |
| `__next__` | 返回下一个元素；没有更多元素时抛 `StopIteration` |

一个对象只要实现 `__iter__` 就是 iterable。迭代器（iterator）是实现 `__iter__` 与 `__next__` 的对象，它的 `__iter__` 返回自身。没有 `__iter__` 但有 `__getitem__` 的对象仍可被 `iter()` 接受，按 0、1、2… 依次取值直到 `IndexError`；这是历史兼容行为，新类型不应依赖它。

`for` 的展开过程是固定的：

```python
iterator = iter(iterable)      # 调用一次 __iter__
while True:
    try: item = next(iterator)
    except StopIteration: break
    ... 循环体 ...
```

这解释了三件事：

- **迭代器有状态**：当前位置保存在迭代器对象里，不在可迭代对象里；
- **迭代器是一次性的**：`StopIteration` 一旦抛出，该迭代器就永久耗尽；
- **可重复迭代取决于 `__iter__`**：返回新迭代器的对象（列表、元组、字典的键视图）可以反复遍历；返回自身的对象（生成器、文件对象、`map`/`zip` 的结果）只能遍历一次。

## 协议的手工展开

```python run id="py.iter.protocol"
values = ["a", "b", "c"]
iterator = iter(values)
print("iterator type:", type(iterator).__name__)

print("next:", next(iterator), next(iterator), next(iterator))
try:
    next(iterator)
except StopIteration:
    print("exhausted: StopIteration")

print("exhausted iterator keeps raising:", list(iterator))
print("a fresh iterator restarts:", list(iter(values)))
```

`list(iterator)` 在已耗尽的迭代器上得到空列表，不是错误；而 `iter(values)` 每次返回新的迭代器，因此列表本身可以反复遍历。`for` 只在开始时取一次迭代器，循环体里重新给循环目标赋值不改变迭代位置；循环结束后循环变量仍然存在，`for` 不创建新的作用域。

## 可重复迭代与一次性迭代

```python run id="py.iter.one-shot"
reusable = [1, 2, 3]
one_shot = (value * 10 for value in reusable)

print("list yields fresh iterators:", iter(reusable) is reusable, list(reusable), list(reusable))
print("generator is its own iterator:", iter(one_shot) is one_shot)
print("first pass:", list(one_shot))
print("second pass:", list(one_shot))
print("builtins that consume an iterator:", list(zip(iter(reusable), "xy")))
```

判断依据是一行：`iter(x) is x` 为真说明对象同时是迭代器，因此一次性。把一次性对象传给两个消费者时，第二个消费者看到的是剩余部分或空序列，这个错误没有任何异常伴随。

## 自己实现迭代器

```python run id="py.iter.custom-iterator"
class Countdown:
    def __init__(self, start):
        self.remaining = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.remaining <= 0:
            raise StopIteration
        self.remaining -= 1
        return self.remaining + 1


print("loop:", [value for value in Countdown(3)])
again = Countdown(3)
print("manual:", next(again), next(again))
print("shared state on the iterator, not on the class:", Countdown(2).remaining)
print("second pass over a used iterator:", list(again))
```

状态放在迭代器实例上而不是类上，这一点与类属性失效模式同源（见 <CrossRef id="python.classes" />）：把 `remaining` 写成类属性会让所有迭代器共享同一个计数器。

## 迭代中修改容器

```python run id="py.iter.mutate"
counts = {"a": 1, "b": 2, "c": 3}
try:
    for key in counts:
        counts[key + "!"] = 0
except RuntimeError as exc:
    print("dict size changed during iteration:", type(exc).__name__, "-", exc)

values = [1, 2, 3, 4]
seen = []
for value in values:
    seen.append(value)
    if value == 2:
        values.remove(value)
print("list silently skipped an element:", seen, values)
```

字典的保证更弱：**在迭代键视图或项视图时增删条目，可能抛出 `RuntimeError`，也可能让遍历没有走到全部条目**。上面这段代码在当前运行时（Python 3.14.2）观察到的是立即抛 `RuntimeError`，但那是这一次运行的观察结果，不是语言规范保证的行为——依赖它的代码在另一个实现或另一个版本上会静默地遍历不全。列表的迭代器只记位置，删除元素会让它跳过下一个元素，同样没有任何提示。需要边遍历边修改时，遍历副本或先收集要改动的元素。
