一个函数抛出异常，就不再返回它的调用方：控制权沿调用栈逐层向外展开，直到某一层的 `try` 接住它；没有一层接住时，解释器打印回溯（traceback）并结束程序。异常是一段控制流，抛出之后控制权如何沿调用栈离开、哪些代码必然运行、调用方最终看到什么信息，都由这条路径决定。

## 异常传播的路径

异常是一个对象。`raise` 接受异常类（会被实例化）或异常实例，并把它交给当前帧：

1. 当前帧的 `try` 语句在子句中从上到下匹配：`except SomeType` 匹配该实例的类型及其子类；
2. 没有匹配则退出当前帧，进入调用方，重复匹配；每退出一层帧，该层的 `finally` 块与 `with` 的退出逻辑都会运行；
3. 到达栈顶仍无人处理时，异常终止程序，并由解释器打印回溯；
4. 处理该异常的 `except` 块执行后，控制权在 `try` 语句之后继续——除非处理块自己又抛出。

一个 `try` 语句的四个部分各自有条件：

| 部分 | 何时运行 |
| --- | --- |
| `except` | 匹配到的异常出现时，按书写顺序取第一个匹配 |
| `else` | `try` 块正常结束且未处理异常时 |
| `finally` | 无论正常结束、返回、抛出还是被处理，都运行 |

`finally` 跨 `return`、`break`、`continue` 与异常展开都执行，因此是可靠的释放点。

## 子句顺序与各路径

`except` 子句**按书写顺序取第一个匹配**，并且**子类也匹配父类**（`except ConfigError` 会接住 `MissingKey`），因此具体的类型写在前面。`else` 在 `try` 块没有触发异常时运行，把「正常路径」与「异常处理」分开，处理块不会捕获自己抛出的异常。

```python run id="py.exc.matching"
class ConfigError(Exception):
    pass


class MissingKey(ConfigError):
    pass


CASES = {"missing": MissingKey, "config": ConfigError, "value": ValueError}


def load(kind):
    try:
        raise CASES[kind]()
    except MissingKey:
        return "except MissingKey"
    except ConfigError:
        return "except ConfigError"
    except (ValueError, TypeError):
        return "except (ValueError, TypeError)"


for kind in ("missing", "config", "value"):
    print(kind, "->", load(kind))
```

`missing` 抛出的 `MissingKey` 也匹配 `except ConfigError`，书写顺序把它交给写在前面、类型更具体的子句；`config` 与 `value` 各自只匹配一个子句。

## finally 的执行路径

```python run id="py.exc.finally-paths"
def with_return():
    try:
        return "from try"
    finally:
        print("finally runs before the function leaves")


def overridden():
    try:
        raise RuntimeError("original failure")
    finally:
        return "finally wins"


print("return value:", with_return())
print("swallowed:", overridden())

try:
    try:
        raise RuntimeError("propagating")
    finally:
        print("cleanup still runs while unwinding")
except RuntimeError as failure:
    print("the failure still reaches the caller:", type(failure).__name__, "-", failure)
```

`finally` 在函数离开之前运行，因此第一个函数先打印再返回值。第二个函数展示了 `finally` 中 `return` 的效果：它结束函数，原来的 `RuntimeError` 被丢弃，调用方看不到任何失败信号。这是把故障静默化的直接机制，清理代码里不应出现 `return`。

## 异常链

```python run id="py.exc.chaining-implicit"
import traceback


class ConfigError(Exception):
    pass


def parse(text, mode):
    try:
        return int(text)
    except ValueError as exc:
        if mode == "from":
            raise ConfigError(f"not a number: {text!r}") from exc
        raise ConfigError(f"not a number: {text!r}")


for mode in ("implicit", "from"):
    try:
        parse("x", mode)
    except ConfigError as exc:
        lines = traceback.format_exception(exc)
    print(mode, [line.strip() for line in lines if line.strip().startswith(("During handling", "The above exception"))])
```

在 `except` 块里抛出的新异常会与正在处理的异常关联。不写 `from` 时，回溯把原始异常报告为「在处理上一条异常期间发生」；`raise ... from exc` 把 `exc` 登记为新异常的直接原因，回溯据此声明因果。

```python run id="py.exc.chaining-from-none"
import traceback


class ConfigError(Exception):
    pass


def parse(text):
    try:
        return int(text)
    except ValueError:
        raise ConfigError(f"not a number: {text!r}") from None


try:
    parse("x")
except ConfigError as exc:
    lines = traceback.format_exception(exc)

print("from None connectors:", [line.strip() for line in lines if line.strip().startswith(("During handling", "The above exception"))])
print("from None exceptions:", [line.strip().split(":")[0].rsplit(".", 1)[-1] for line in lines if "Error:" in line])
```

`raise ... from None` 不建立这条关联，回溯里只剩新异常。

## 重新抛出

```python run id="py.exc.reraise"
import traceback


def inner():
    raise ValueError("original")


def bare_reraise():
    try:
        inner()
    except ValueError:
        raise


def instance_reraise():
    try:
        inner()
    except ValueError as exc:
        raise exc


for label, function in [("bare raise", bare_reraise), ("raise instance", instance_reraise)]:
    try:
        function()
    except ValueError as exc:
        frames = traceback.extract_tb(exc.__traceback__)
        print(label, "->", len(frames), "frames |", [frame.name for frame in frames])
```

裸 `raise` 保留原异常对象、回溯与传播位置，只增加调用方的帧；`raise exc` 抛出的是同一个对象，但把当前这一行记为抛出位置，回溯里因此出现两次处理帧：原始抛出点仍在，处理帧多了一次。

## 异常的边界

```python run id="py.exc.boundaries"
print("SystemExit is Exception:", issubclass(SystemExit, Exception))
print("KeyboardInterrupt is Exception:", issubclass(KeyboardInterrupt, Exception))
print("GeneratorExit is Exception:", issubclass(GeneratorExit, Exception))
```

`SystemExit`、`KeyboardInterrupt` 与 `GeneratorExit` 继承 `BaseException`，`except Exception` 不会接住它们。
