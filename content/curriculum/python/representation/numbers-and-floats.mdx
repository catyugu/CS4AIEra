数值是语言自带近似语义的基础类型。把 `float` 当作实数推理，会在比较、聚合与金额计算上产生静默错误：结果看起来合理，与预期只差一点，而这一点随数据规模放大。误差无法靠「小心」消除，只能通过选择表示与写清比较判据来管理。

## 整数与浮点的表示

- `int` 是任意精度整数。只要内存允许，运算精确，不存在固定宽度整数的溢出回绕。代价是大整数运算比机器字运算慢得多。
- `float` 是 IEEE 754 <Term id="binary64">双精度浮点格式</Term>（binary64）值：1 位符号、11 位指数、52 位存储尾数加 1 位隐含位，共 53 位有效二进制位。可精确表示的值是形如 `m * 2^e` 的有理数，其中 `m` 的位宽不超过 53。这个宽度是**本运行时**的表示，不是语言规范对所有实现的无条件规定：CPython 文档的表述是「几乎所有平台把 `float` 映射到 IEEE 754 binary64」，实际布局由构建与平台决定（见 [Floating Point Arithmetic: Issues and Limitations](https://docs.python.org/3/tutorial/floatingpoint.html)）。
- 十进制小数在二进制下可能无限循环。字面量 `0.1` 被舍入到最近的可表示值，之后所有运算都在这个近似值上进行。
- 每次运算对结果舍入一次。浮点加法不满足结合律与分配律，相减两个相近的数会丢掉有效位。
- `int` 与 `float` 混合运算时先把整数转换为浮点数；混合比较不转换，按精确值比较。
- 需要精确十进制时用 `decimal.Decimal`（可配置精度与舍入模式），需要精确有理数时用 `fractions.Fraction`（分母随运算增长）。金额用整数最小单位或 `Decimal`。

## 表示与误差

```python run id="py.num.representation"
from decimal import Decimal

print("0.1 + 0.2 =", 0.1 + 0.2)
print("equals 0.3:", 0.1 + 0.2 == 0.3)
print("0.1 to 20 places:", format(0.1, ".20f"))
print("0.1 in hexadecimal:", (0.1).hex())
print("Decimal sum:", Decimal("0.1") + Decimal("0.2"))
print("repr round-trips:", float(repr(0.1)) == 0.1)
```

四个观察：`0.1 + 0.2` 与 `0.3` 不相等，差值来自三个各自被舍入的近似值；展开到 20 位小数可以看到 `0.1` 存的并不是十分之一；`float.hex()` 给出精确的二进制形式（`0x1.999999999999ap-4`），尾数比十进制的 0.1 略大；`repr` 给出的是能往返转换回同一个浮点数的最短十进制表示，因此打印 `0.1` 不会暴露这个差。

`Decimal("0.1")` 从字符串构造，精确表示十进制的十分之一，与前三个结果无关。把浮点格式化成固定小数位会掩盖误差，并再引入一次舍入；日志与报告里的数字位数不等于存储精度。

```python run id="py.num.float-info"
import sys

info = sys.float_info
print("mantissa bits:", info.mant_dig)
print("epsilon:", info.epsilon)
print("largest finite:", info.max)
print("smallest positive subnormal equals 2**-1074:", 5e-324 == 2.0 ** -1074)
```

`sys.float_info` 的每一项都来自这次构建的 C 平台：位宽、可表示范围与最小正数都由它决定。引用这些常数时读运行时，而不是照抄别处（见 <CrossRef id="python.runtime-vs-language" />）。

## 运算顺序与抵消

浮点加法不满足结合律，改变运算顺序会改变结果。

```python run id="py.num.cancellation"
import math

total = 0.0
for _ in range(10):
    total += 0.1

print("loop total:", total)
print("sum():     ", sum([0.1] * 10))
print("fsum():    ", math.fsum([0.1] * 10))
print("(1e16 + 1.0) - 1e16 =", (1e16 + 1.0) - 1e16)
print("(1e16 - 1e16) + 1.0 =", (1e16 - 1e16) + 1.0)
print("isclose:", math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9))
```

逐项累加十次 `0.1` 得到 0.9999999999999999：中间结果各自舍入，误差逐步累积。`math.fsum` 用精确累加得到 1.0。

`sum()` 在本次运行返回 1.0。CPython 3.12 起对浮点求和使用补偿算法（见 [What's New in Python 3.12](https://docs.python.org/3/whatsnew/3.12.html)），因此比朴素循环更接近精确值；这是实现行为，语言没有规定 `sum` 的舍入方式，也不保证它能消除所有误差。依赖求和精度时应显式选择 `math.fsum`。数据库的 `SUM`、向量化库与朴素循环的累加顺序各不相同，同一批数据的和在跨系统对账时可能不一致，需要一致口径时固定实现与顺序。

用 `==` 断言浮点结果会间歇失败，比较用 `math.isclose` 或显式容差，并在代码或测试里写清容差的来源。`1e16 + 1.0` 的结果舍入回 `1e16`，于是先加后减得到 0.0，先减后加得到 1.0。两个表达式只差括号，结果相差 1。相减两个数量级相近的大数会丢掉有效位，这种情形称为<Term id="catastrophic-cancellation">灾难性抵消</Term>，它出现在方差、差值、求和公式与二次方程求根中。遇到它时改用数值稳定的等价形式，或提高精度。

## 整数与浮点的边界

```python run id="py.num.integer-boundary"
big = 10 ** 20
print("exact integer arithmetic:", big + 1 == big)
print("after float conversion:  ", float(big + 1) == float(big))
print("2**53:", float(2 ** 53) == 2 ** 53, float(2 ** 53 + 1) == 2 ** 53 + 1)
print("2**100:", float(2 ** 100) == 2 ** 100)
print("mixed comparison is exact:", big + 1 == float(big + 1))
print("float(2**53 + 1) =", float(2 ** 53 + 1))
```

整数运算精确，`10**20 + 1 == 10**20` 为假。转换到浮点后两者相等：`10**20 + 1` 被舍入到最近的可表示值，而 `10**20` 正好是那个值。

判据是有效位数量。`2**53` 与 `2**100` 都能精确表示（有效位分别是 1 位与 2 位），`2**53 + 1` 需要 54 位有效位，因此被舍入。整数值超过 2^53 之后不再能表示所有相邻整数。用浮点做计数器或索引时，超过 2^53 之后自增会静默停止变化。

混合比较是精确的：`10**20 + 1 == float(10**20 + 1)` 为假，Python 比较整数与浮点数时按两者的精确值比较，不先做浮点转换。混合运算则先转换，因此 `10**20 + 1` 参与浮点运算时会丢掉末尾的 1。

## 精确算术

```python run id="py.num.exact-arithmetic"
from decimal import Decimal, ROUND_HALF_UP
from fractions import Fraction

price = Decimal("19.99")
total = (price * 3).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print("total:", total)
print("Decimal('0.1') + Decimal('0.2') == Decimal('0.3'):", Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))
print("Decimal(0.1):", Decimal(0.1))
print("Decimal('0.1'):", Decimal("0.1"))
print("Decimal division:", Decimal("1") / Decimal("3"))
print("Fraction:", Fraction(1, 3) * 3 == 1)
print("Fraction from float:", Fraction(0.1) == Fraction(1, 10))
```

`Decimal` 的精度来自上下文（默认 28 位有效数字）与显式舍入模式，`quantize` 同时指定小数位与舍入方式。金额计算必须在这两点上明确，否则「四舍五入」的具体含义由默认值与版本决定。

构造方式决定语义：`Decimal("0.1")` 得到十进制的十分之一，`Decimal(0.1)` 把浮点近似值的精确十进制展开原样带进来，误差进入精确类型。同样，`Fraction(0.1)` 与 `Fraction(1, 10)` 不相等。

`Decimal` 除法的结果长度由上下文精度决定，不是无误差的实数结果。`Decimal` 精确表示有限十进制输入，并让精度与舍入规则显式可控；它没有消除所有舍入误差，例如 `1 / 3` 必须按上下文精度舍入，`quantize` 之外的操作也可能引入舍入。

## 特殊值与失败

```python run id="py.num.nan-and-inf"
import math

print("1e308 * 10 =", 1e308 * 10)

try:
    1.0 / 0.0
except ZeroDivisionError as exc:
    print("float division by zero:", type(exc).__name__, "-", exc)

try:
    math.exp(1000)
except OverflowError as exc:
    print("math.exp(1000):", type(exc).__name__, "-", exc)

print("inf - inf =", float("inf") - float("inf"))
nan = float("nan")
print("nan <= 1:", nan <= 1)
print("nan == nan:", nan == nan, "| nan != nan:", nan != nan)
print("nan is nan:", nan is nan)
```

数字超出可表示范围时得到 `inf`，`inf - inf` 得到 `nan`。Python 的除法不使用 IEEE 的「除以零得无穷」规则：`1.0 / 0.0` 与 `1 // 0` 都抛 `ZeroDivisionError`。数学库函数在上溢或参数超出定义域时抛 `OverflowError` 或 `ValueError`。

NaN 不等于任何数值，包括自身：`nan == nan` 为 `False`，`nan != nan` 为 `True`，有序比较 `nan <= 1` 也为 `False`。相等不再自反，有序比较也不建立全序，含 NaN 的序列排序结果因此不再有序，`min`、`max`、去重与分组都会给出难以预测的结果。检测 NaN 用 `math.isnan`，不要用相等比较。`-0.0 == 0.0` 为真，`math.copysign(1.0, x)` 可以区分两者，但作为字典键时两者是同一个键。
