函数是值，名字可以指向任何对象；装饰器是这个事实的机械应用，`@decorate` 与 `target = decorate(target)` 是同一件事。

## 模型

函数对象是普通值：可以赋给名字、放进容器、作为实参、作为返回值。装饰器是「接收一个可调用对象、返回一个可调用对象」的函数。

```text
@decorate
def target(): ...

target = decorate(target)
```

两行等价。因此：

- 装饰发生在 `def` 语句执行时（模块导入或函数体执行到该处），而不是调用 `target()` 时；因此装饰器里的任何工作——读文件、建连接、发请求——都发生在导入或定义那一刻，成本与失败点都不在调用处；
- `target` 这个名字最终指向 `decorate` 的返回值，原函数对象仍然存在，只是不再由该名字绑定；
- 装饰器返回什么，`target` 就是什么。返回非可调用对象时不报错，直到有人调用它，报错位置离原因很远。

包装（wrapper）是常见实现：装饰器定义内层函数，闭包捕获原函数与装饰时传入的参数，调用时转交实参并返回内层函数。捕获原函数与装饰参数会让它们随函数对象一直可达，长驻进程里被装饰的函数随模块存活，装饰参数也就一直可达。类对象也是值：装饰器可以修饰类，收到的是类对象，返回替身类型会改变实例化的行为，而不只是调用的行为。

## 装饰就是重新赋值

```python run id="py.dec.shorthand"
events = []


def traced(function):
    events.append(f"decorating {function.__name__}")

    def wrapper(*args, **kwargs):
        events.append(f"calling {function.__name__}")
        return function(*args, **kwargs)

    return wrapper


@traced
def add(left, right):
    return left + right


print("events before any call:", events)
print("result:", add(1, 2))
print("events after one call:", events)
print("name is bound to the wrapper:", add.__name__, add.__qualname__)
```

`decorating add` 在任何调用之前就出现在 `events` 里，说明装饰在定义时完成。装饰发生在类创建之前，绑定成方法发生在之后，因此方法上的装饰器收到的是未绑定的普通函数。`add` 现在指向 `wrapper`，因此 `add.__name__` 是 `wrapper`；原函数被闭包引用着，通过 `wrapper` 的闭包可以取回。

## 转交实参

```python run id="py.dec.forwarding"
def traced(function):
    def wrapper(*args, **kwargs):
        print(f"before {function.__name__}({args}, {kwargs})")
        result = function(*args, **kwargs)
        print(f"after {function.__name__} -> {result!r}")
        return result

    return wrapper


@traced
def area(width, height, unit="px"):
    return f"{width * height} {unit}"


print(area(2, 3))
print(area(2, height=3, unit="cm"))
```

包装函数用 `*args, **kwargs` 原样转交，因此被装饰函数的签名仍然可用。漏掉转交时，包装函数会吞掉实参或抛绑定错误：

```python run id="py.dec.without-forwarding"
def traced(function):
    def wrapper():
        return function()

    return wrapper


@traced
def area(width, height):
    return width * height


try:
    area(2, 3)
except TypeError as exc:
    print("wrapper swallowed the arguments:", type(exc).__name__, "-", exc)
```

## 恢复被替换的属性

```python run id="py.dec.wraps"
import functools
import inspect


def naive(function):
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


def documented(function):
    @functools.wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


@naive
def plain(width, height):
    """Return the area."""
    return width * height


@documented
def described(width, height):
    """Return the area."""
    return width * height


print("naive:", plain.__name__, "| doc:", plain.__doc__)
print("naive signature:", inspect.signature(plain))
print("documented:", described.__name__, "| doc:", described.__doc__)
print("documented signature:", inspect.signature(described))
print("original reachable:", described.__wrapped__ is not None)
```

`functools.wraps` 把原函数的 `__name__`、`__doc__`、`__module__`、`__dict__` 等复制到包装函数上，并设置 `__wrapped__` 指向原函数；`inspect.signature` 顺着 `__wrapped__` 读出原签名。没有它，日志、文档、参数检查与依赖注入都会看到 `wrapper`，而当被装饰对象是方法或路由处理器时，这个差异会直接改变框架行为。包装函数有自己的 `__dict__`，原函数上后加的自定义属性不会自动出现在包装对象上。

## 带参数的装饰器

```python run id="py.dec.factory"
def repeated(times=2):
    def decorate(function):
        def wrapper(*args, **kwargs):
            results = [function(*args, **kwargs) for _ in range(times)]
            return results

        return wrapper

    return decorate


@repeated(times=3)
def roll():
    return "attempt"


@repeated()
def once():
    return "single"


print(roll())
print(once())
```

`@repeated(times=3)` 先调用 `repeated(times=3)` 得到真正的装饰器，再对函数应用它，因此需要多一层函数。`times` 在装饰时被固定并存入闭包，调用期不可更改；需要每次调用不同的次数，就把次数做成被装饰函数的参数。

## 层叠顺序

```python run id="py.dec.stacking"
def first(function):
    def wrapper(*args, **kwargs):
        print("first: before")
        result = function(*args, **kwargs)
        print("first: after")
        return result

    return wrapper


def second(function):
    def wrapper(*args, **kwargs):
        print("second: before")
        result = function(*args, **kwargs)
        print("second: after")
        return result

    return wrapper


@first
@second
def action():
    print("action body")


action()
```

靠近 `def` 的那个装饰器先应用，因此执行时从外到内进入、从内到外返回。读代码时自上而下推应用顺序会得到相反的结论，这也是层叠装饰器的常见误读点。
