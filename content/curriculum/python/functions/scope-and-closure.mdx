模块顶层有列表 `totals`，下面这个函数先往列表里追加一个元素，再把它重置为空列表；追加那一行抛 `UnboundLocalError`。

## 赋值使名字成为局部

```python run id="py.scope.unbound-local"
totals = [1, 2, 3]


def append_bad():
    try:
        totals.append(4)
        totals = []
    except UnboundLocalError as exc:
        print("UnboundLocalError:", exc)


append_bad()
print("module-level list is untouched:", totals)
```

`totals = []` 写在函数体里，于是整个函数中的 `totals` 都是局部名。追加那一行读的是一个还没有绑定的局部名，抛 `UnboundLocalError`；模块层的 `totals` 全程没有被这次调用触及。函数体里任何位置的赋值都让这个名字属于本函数，`for` 目标、`with ... as`、`except ... as` 与解包目标同样如此。要让赋值作用到模块列表上，可以加一行 `global totals`，或者改由参数传入列表、把结果返回给调用方。

## 名称来自哪一层

换一个函数，看它读到的 `size` 是哪一个。

```python run id="py.scope.resolution"
size = "module"


def show():
    size = "local"
    return size


print("inside:", show())
print("module:", size)
print("builtin fallback:", len("abcd"))
```

`show` 里的 `size = "local"` 让这个名字在本函数里成为局部名，`return size` 读到的就是它，模块层的 `size` 不受影响。`len` 在函数层和模块层都没有绑定时由内建命名空间提供，所以可以直接调用；在当前模块里给 `len` 赋值会遮蔽内建的那一个，遮蔽只影响该模块。

## 名称查找的四个作用域

两次读取由同一条规则决定：一个名字属于哪一层，取决于它在函数体里的绑定。读取一个名字时，解释器按由内到外的顺序搜索四层作用域，返回第一次命中该名字的层：

| 层 | 内容 | 何时存在 |
| --- | --- | --- |
| Local | 当前函数执行帧中绑定的名字 | 函数执行期间 |
| Enclosing | 外层函数的局部名，供内层函数读取 | 外层函数执行期间及其内层函数存续期间 |
| Global | 定义该函数的模块的命名空间 | 模块存活期间 |
| Builtin | 内建命名空间（`len`、`print` 等） | 解释器存活期间 |

两条规则决定名字落在哪一层：

- **赋值使名字成为局部的**。函数体内任何位置的赋值（包括 `for` 目标、`with ... as`、`except ... as`、解包目标）都让该名字属于本函数，除非用 `global` 或 `nonlocal` 声明。函数体内的名称绑定在执行函数时建立，读取一个尚未绑定的局部名抛 `UnboundLocalError`。
- **函数对象带着它的定义作用域**。内层函数被返回后，外层帧已经结束，内层函数通过闭包（closure）继续访问外层帧里的那些名字。捕获的是变量本身，读取发生在函数被调用的时候。

模块对象是全局层的载体：模块顶层的名字存放在模块的命名空间里，导入该模块的代码与模块内的函数看到的是同一个对象。模块全局名对所有函数可见且可变，把模块级容器当作跨函数状态就是隐式共享状态，跨调用、跨请求都会累积。

## global 与 nonlocal

```python run id="py.scope.global-and-nonlocal"
counter = 0


def bump_global():
    global counter
    counter += 1


def make_counter():
    count = 0

    def bump():
        nonlocal count
        count += 1
        return count

    return bump


bump_global()
bump_global()
print("module counter:", counter)

first = make_counter()
second = make_counter()
print("first:", first(), first(), first())
print("second:", second())
```

`global` 让赋值作用于模块命名空间，`nonlocal` 让它作用于最近的外层函数帧。两者都只声明这个名字属于哪一层作用域，名字仍要由赋值产生；`nonlocal` 找不到外层帧里的同名绑定时抛 `SyntaxError`，这个错误在编译期确定。`make_counter` 的每次调用都产生新的 `count`，因此 `first` 与 `second` 各自累计，互不影响；闭包捕获的是变量本身，两次调用拿到的是两个不同的变量。

## 闭包捕获变量

```python run id="py.scope.closure-capture"
def make_accumulator():
    running = []

    def add(value):
        running.append(value)
        return sum(running)

    return add


accumulate = make_accumulator()
print("results:", accumulate(1), accumulate(2), accumulate(3))
print("still accumulating after the outer call returned:", accumulate(4))
```

`running` 是 `make_accumulator` 帧里的局部名。外层调用返回后帧本身结束，`add` 仍然读写同一个列表对象，每次调用都在上一次的结果上继续累加。闭包延长的是被引用对象的存活期；外层帧在返回时结束，只有被闭包引用的对象继续存活。被捕获的大对象随函数对象一起存活，长生命周期的回调会因此持有本可释放的内存。

## 延迟绑定

被捕获的是变量，读取发生在函数被调用时，因此同一变量上的多次修改对已创建的所有函数都可见。

```python run id="py.scope.late-binding"
functions = [lambda value: f"{index}:{value}" for index in range(3)]
print("late binding:", [function("x") for function in functions])

def make_formatter(index):
    return lambda value: f"{index}:{value}"


early = [make_formatter(index) for index in range(3)]
print("captured per call:", [function("x") for function in early])

with_defaults = [lambda value, index=index: f"{index}:{value}" for index in range(3)]
print("captured by default argument:", [function("x") for function in with_defaults])
```

推导式有自己的作用域，内部绑定的名字不泄漏到外层：`index` 属于推导式的作用域，三次迭代共用这一个变量，三个 lambda 都捕获了它，调用时它已经是 2。用具名工厂函数把当前值绑定到那次调用的形参，或用默认参数在定义时求值，都得到每次迭代自己的值。默认参数方案把绑定时机提前到定义时，代价是签名上多了一个不该出现在公共接口里的参数。
