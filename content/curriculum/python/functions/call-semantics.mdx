调用是 Python 里唯一把控制权从一个函数交给另一个函数的机制。读代码时的关键判断是：这次调用把哪些对象绑定到了哪些名字上，绑定失败在什么时刻以什么形式暴露。上一课只处理「会定义、会调用」，本课处理签名与实参之间的全部对应关系。

## 模型

一次调用固定分三步：

1. 按书写顺序求值每个实参表达式，得到对象；
2. 把实参对象按签名绑定到形参名，产生一个新的执行帧；
3. 执行函数体，`return` 的值成为调用表达式的值。

绑定本身不复制对象，形参名和调用方使用同一个对象；这与赋值语句的语义一致（见 <CrossRef id="python.names-and-objects" />）。

参数种类由签名决定，`/` 与 `*` 是分界标记：

| 种类 | 写法 | 绑定方式 |
| --- | --- | --- |
| 仅位置 | `def f(a, /)` | 只能由位置实参提供 |
| 位置或关键字 | `def f(a)` | 位置实参按顺序，或写成 `a=...` |
| 仅关键字 | `def f(*, a)` | 只能写成 `a=...` |
| 可变位置 | `def f(*args)` | 多余的未绑定位置实参收集成一个元组 |
| 可变关键字 | `def f(**kwargs)` | 多余的、名字不匹配的关键字实参收集成一个字典 |

默认值不是每次调用重新求值：`def f(a, items=[])` 中的 `[]` 在 `def` 语句执行时求值一次，结果保存在函数对象上，此后每次省略该实参的调用都复用同一个列表。

## 实参求值与绑定

```python run id="py.call.binding"
def describe(x, y):
    print("bound:", x, y)
    x = "rebound inside"
    print("after rebinding x inside:", x, y)


first = [1, 2]
second = [3]
describe(first, second)
describe(y=second, x=first)
print("caller still sees:", first, second)
```

同一组对象可以按位置或按关键字绑定，结果相同。函数内给 `x` 重新绑定只改变这一帧的名字，`first` 不受影响；如果函数对 `first` 指向的列表做原地修改，调用方就会观察到变化。

## 默认值在定义时求值

```python run id="py.call.default-evaluated-once"
def collect(item, bucket=[]):
    bucket.append(item)
    return bucket


print("first call:", collect("a"))
print("second call:", collect("b"))
print("default object identity:", collect("c") is collect("d"))
print("stored default:", collect.__defaults__)
```

三次调用返回的列表逐次增长，因为形参 `bucket` 每次都绑定到定义时创建的那一个列表。`collect.__defaults__` 直接显示出这个对象。同一事实换一种写法更清楚：默认值冻结的是定义时刻的结果，而不是定义里那个表达式的后续取值。任何在定义时求值的表达式——读取环境变量、打开连接、构造容器——都把函数行为绑定到定义发生的时刻，而不是调用时刻。

```python run id="py.call.default-from-call-time-state"
order = ["first"]


def current(item=order[0]):
    return item


order[0] = "changed before the call"
print("default is frozen at definition time:", current())
print("explicit argument still works:", current("passed in"))
```

把 `None` 作为「未提供」的标记，在函数体内新建容器，可以把状态限制在单次调用内：

```python run id="py.call.none-sentinel"
def collect(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket


print(collect("a"), collect("b"), collect("a") == collect("b"))
```

## 参数种类与调用期检查

```python run id="py.call.parameter-kinds"
def paginate(items, page_size, /, *, page=1):
    start = (page - 1) * page_size
    return items[start : start + page_size]


print(paginate([1, 2, 3, 4, 5], 2))
print(paginate([1, 2, 3, 4, 5], 2, page=2))

try:
    paginate(items=[1, 2, 3], page_size=2)
except TypeError as exc:
    print("positional-only violation:", type(exc).__name__, "-", exc)
```

`page_size` 之前的 `/` 表示它只能按位置传入，调用方写出 `page_size=2` 会在绑定阶段失败。`*` 之后的 `page` 只能按关键字传入，因此 `paginate(items, 2, 2)` 同样在绑定阶段失败；仅关键字参数可以没有默认值，此时它必填。这类约束把「参数顺序写错」从运行到函数体内部才出现的错误，提前成一次明确的调用错误。

## 可变参数与调用侧解包

```python run id="py.call.varargs"
def report(label, *values, **metadata):
    print("label:", label)
    print("values:", values, "| type:", type(values).__name__)
    print("metadata:", metadata, "| type:", type(metadata).__name__)


report("counts", 1, 2, 3, unit="rows", source="fixture")

rows = [(1, "a"), (2, "b")]
columns = {"id": "int", "name": "text"}
report("table", *rows, **columns)
```

`*values` 收集成元组，`**metadata` 收集成字典；调用侧写 `*rows` 与 `**columns` 则把可迭代对象与映射展开成多个实参。两者是同一个符号在两侧的对应写法。收集结果是新建的元组与字典，不是列表，也不是映射的视图；`**` 展开的键必须是字符串，否则绑定失败。缺少 `*` 时 `rows` 会被当成一个实参：

```python run id="py.call.unpacking-mismatch"
def report(label, *values):
    print("label:", label, "| values:", values)


rows = [(1, "a"), (2, "b")]
report("table", *rows)
report("table", rows)
```

## 绑定失败的种类

```python run id="py.call.binding-errors"
def area(width, height, unit="px"):
    return width * height


attempts = [
    ("too many positional", lambda: area(1, 2, 3, 4)),
    ("missing required", lambda: area(1)),
    ("unexpected keyword", lambda: area(1, 2, depth=3)),
    ("duplicate value", lambda: area(1, width=2)),
]

for label, call in attempts:
    try:
        call()
    except TypeError as exc:
        print(label, "->", type(exc).__name__, "-", exc)
```

四类失败都在绑定阶段发生，函数体一次都没有执行。异常消息描述的是签名与实参的差异，因此定位时先看消息里的参数名，再回到定义处。Python 不做隐式默认填充，也不按名字猜测，能绑定什么完全由签名与实参决定。
