## 目的

本课解释 Python 的名称绑定模型：赋值不复制数据，只把名字指向对象。由此产生的**别名**（<Term id="alias">alias</Term>）既是共享数据的机制，也是许多"改了这里，那里也变了"类缺陷的根源。

这个模型必须先建立，因为后面几乎所有内容都建立在它之上：函数参数传递、闭包捕获的变量、类属性与实例属性、并发下的共享状态、以及事务中对同一行的两个视图。

## 模型：名称、对象、绑定

Python 程序里有两类东西：

- **对象**：有身份（identity）、类型（type）、值（value）。对象存在与否与有没有名字无关。
- **名称**：存在于某个命名空间中，指向一个对象。名称是绑定，不是容器。

赋值语句 `name = expr` 的语义是两步：先求值 `expr` 得到一个对象，再把当前命名空间里的 `name` 绑定到它。它不改变任何对象的内容。

```python run id="py.names.rebinding"
a = [1, 2]
b = a
b.append(3)
print("a =", a)
print("b =", b)
print("same object:", a is b)
```

`a is b` 为真，因为两者是同一个对象。改一个名字看到的内容，另一个名字也看到，中间没有发生复制。

## 身份与相等

两个不同的关系经常被混用：

| 表达式 | 含义 | 判据 |
| --- | --- | --- |
| `x is y` | 身份 | 是否同一个对象 |
| `x == y` | 相等 | `x.__eq__(y)` 的判定结果 |

身份相同必然相等（对行为正常的对象），相等不蕴含身份相同。

```python run id="py.identity.vs.equality"
x = [1, 2]
y = [1, 2]
print("x == y:", x == y)
print("x is y:", x is y)
print("x is x:", x is x)
```

`x` 与 `y` 内容相同但是两个对象。把 `y = [1, 2]` 改成 `y = x`，`is` 变为真；这正是上一节的重绑定。

## 可变与不可变

不可变对象（`int`、`str`、`tuple`）没有原地修改的操作。所有"看起来在改它"的语句都是产生新对象并重绑定名字。

```python run id="py.immutable.rebind"
s = "ab"
t = s
s = s + "c"
print("s =", s)
print("t =", t)
print("same object:", s is t)
```

`t` 保持 `"ab"`。这里没有别名问题，因为 `s + "c"` 创建了新对象，`s` 只是换了指向。

可变对象（`list`、`dict`、`set`、大多数自定义类实例）有原地修改操作。`append`、`sort`、`update`、`+=` 中的原地形式都会改变对象内容，因此所有指向它的名字都能观察到变化。

```python run id="py.mutable.inplace"
items = [3, 1, 2]
alias = items
items.sort()
print("alias =", alias)
items = items + [0]
print("items =", items)
print("alias =", alias)
print("same object:", items is alias)
```

`sort()` 是原地操作，`alias` 看到排序结果；`items + [0]` 产生新列表并重绑定 `items`，此后两者分离。区分**修改对象**与**重绑定名字**是这一段的核心。

## 具名 session：显式共享状态

默认情况下，可执行单元格之间状态隔离：每个单元格在干净的命名空间里运行。需要在若干单元格之间共享状态时，作者必须显式给它们同一个 session 名。

下面两个单元格共享 `session="iterator-demo"`，因此第二个能看到第一个创建的迭代器。这正是真实程序里"两个函数操作同一个对象"的最小模型。

```python run id="py.session.iterator-create" session="iterator-demo"
it = iter([10, 20, 30])
print("first:", next(it))
```

```python run id="py.session.iterator-continue" session="iterator-demo"
print("second:", next(it))
print("remaining state is shared because the session is explicit")
```

如果把第二个单元格的 `session` 去掉，它会以 `NameError: name 'it' is not defined` 失败——隔离单元格看不到别的单元格的状态。这一默认行为阻止了隐藏的执行顺序依赖。

## 函数参数与默认参数

函数调用按对象引用传参：形参与实参绑定到同一个对象。函数内部对参数**重绑定**不影响调用方；对参数指向的对象**原地修改**会影响调用方。

```python run id="py.function.mutation"
def grow(values):
    values.append(99)

def replace(values):
    values = values + [99]

data = [1]
grow(data)
print("after grow:", data)
replace(data)
print("after replace:", data)
```

`grow` 修改了调用方的对象，`replace` 只重绑定了局部名字。两者写法相近，后果完全不同。

默认参数只在函数定义时求值一次，因此把可变对象用作默认值是共享状态的陷阱：

```python run id="py.default.argument"
def collect(item, bucket=[]):
    bucket.append(item)
    return bucket

print(collect("a"))
print(collect("b"))
print(collect("c"))
```

三次调用返回同一个列表。默认值 `[]` 是定义时创建的一个对象，被所有未传 `bucket` 的调用共享。正确写法是用 `None` 表示"未提供"并在函数体内新建：

```text
def collect(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

## 边界与失败情形

- **浅拷贝仍是别名**：`list(original)` 与 `original.copy()` 复制外层容器，元素仍然共享。嵌套结构需要 `copy.deepcopy`，而深拷贝对含环、含不可拷贝对象的结构有明确限制。
- **不可变容器里的可变元素**：`tuple` 本身不可变，但 `t[0].append(1)` 合法，因为被修改的是 `t[0]` 指向的对象，不是 tuple。tuple 的不可变性只保证元素绑定不变。
- **`is` 用于小整数或字符串**：`a = 256; b = 256; a is b` 在 CPython 上为真，这是实现中的对象缓存，不是语言保证。用 `is` 比较值在不同实现、不同版本上会给出不同结果；`is` 只应用于 `None`、哨兵对象与身份判断。
- **`+=` 的双重语义**：对列表 `x += y` 等价于原地 `extend`，对元组 `x += y` 产生新对象。同一运算符在两种类型上分别是"修改对象"与"重绑定名字"。
- **迭代中修改**：在遍历列表的同时增删元素会跳过或重复元素。需要边遍历边改时应遍历副本或先收集再修改。

## 生产后果

- 共享可变状态是并发缺陷的前提。线程、协程与事务都在处理同一个问题：谁在什么时候能看到谁写的哪个版本。
- 把可变对象当作默认值、模块级缓存或类属性，会让状态寿命超出预期，在长驻进程里表现为缓慢增长的内存与跨请求串味的数据。
- 函数签名里"我是否会修改你传进来的对象"是接口契约的一部分。不修改的约定需要写进文档或通过传入副本、返回新对象来体现，否则调用方只能靠阅读实现来推断。
- 生成式工具经常在"返回新对象"与"原地修改"之间不一致。评审时按对象身份逐个检查，比按函数名猜测可靠。

## 小结

- 赋值把名字绑定到对象，不复制对象内容。
- `is` 判断身份，`==` 判断相等；只有身份相同必然相等。
- 可变对象的原地修改对所有名字可见；不可变对象的"修改"都是新建加重绑定。
- 单元格默认隔离，共享状态必须用具名 session 显式声明。
- 函数按引用传参：重绑定形参不影响调用方，修改形参指向的对象会影响调用方。
- 可变默认参数在定义时求值一次，是共享状态的经典陷阱。
