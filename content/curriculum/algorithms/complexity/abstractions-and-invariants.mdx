一个能随时回答「当前最小元素是多少」的栈，小到可以一次写在屏幕上，却包含这个模块后面每一课都要处理的三件事：契约承诺了什么，内部状态怎样保存，以及为了把某个操作变便宜而缓存一个事实时要付出什么代价。

这一课建立处理这三件事的顺序。动态数组、链表、哈希表、树与堆都是同一顺序的实例：**契约 → 表示 → 表示不变量 → 操作 → 不变量为什么保持 → 成本**。每一步都要写出来，否则后面关于成本的每一句话都无从检验。

## 契约、表示与算法

同一个栈，可以沿着四层来看。

| 层 | 这个例子里是什么 |
| --- | --- |
| 问题规约 | 一个栈，支持 push 与 pop，并且能随时回答当前最小元素 |
| 抽象契约 | push(x) 之后 x 在栈顶；pop() 返回并移除栈顶；minimum() 返回当前元素中的最小值 |
| 表示 | 元素用什么保存；最小值是按需重算，还是随元素一起缓存 |
| 算法 | 每个操作怎样读写这些状态，以及什么时候重新计算缓存 |

第二层单独拿出来就是**抽象数据类型**（abstract data type, ADT）：一组操作的集合，以及每个操作承诺什么，其中不含状态怎样保存。契约只描述调用方能观察到的东西：每个操作的前置条件与后置条件。前置条件由调用方负责——`pop` 要求栈非空，空栈上调用它的行为由契约规定（抛错、返回哨兵值或另有说明），实现不必承诺别的。后置条件由实现负责：`pop` 返回的值必须是此前 push 进去、且尚未被弹出的值里最后进入的那个。

契约里不出现数组、下标、缓存这些词，它们都属于表示。同一份契约可以有多种表示，而**复杂度论断属于表示与算法，不属于契约**：同一个 `minimum()`，在一种表示上要扫描全部元素，在另一种表示上只读一次缓存。下两节各给出一个例子。

## 表示不变量

表示确定之后，内部状态里就有一些关系必须始终成立。对「按需重算」的版本，关系就是元素列表本身；对「缓存最小值」的版本，还多一条：<Term id="invariant">不变量</Term>——**缓存的最小值等于当前所有元素的最小值，且只有栈空时它才为空**。

不变量是每组操作返回之前都必须成立的性质：

- 它在操作执行过程中可以暂时不成立。`pop` 先移除元素、再修正缓存，中间那一刻缓存是过时的；要求是操作返回之前重新建立它。
- 它只对实现可见。调用方看到的是 `minimum()` 的返回值，看不到缓存；换一种表示，不变量也跟着换。
- 它让每个操作只需维护少量关系，而不必在每次调用时从头检查全部状态——缓存值能省下扫描，就是因为这些关系被维护住了。
- 违反不变量通常不会立刻报错。它先让实现所依赖的事实失效，然后在某次看起来无关的调用上表现为错误答案。

## 检查不变量：错误出现在哪一次操作

把不变量写成一个函数，它就有了第二个用途：在被破坏的那一次操作之后立刻报出来。

```python run id="alg.adt.invariant-check"
class MinStack:
    """Stack with a cached minimum.

    Representation invariant: `minimum` equals the smallest live element,
    and is None exactly when the stack is empty.
    """

    def __init__(self):
        self.values = []
        self.minimum = None

    def push(self, value):
        self.values.append(value)
        if self.minimum is None or value < self.minimum:
            self.minimum = value

    def pop(self):
        value = self.values.pop()
        self.minimum = min(self.values) if self.values else None
        return value

    def violations(self):
        """Every way the cached minimum disagrees with the elements."""
        if not self.values:
            if self.minimum is None:
                return []
            return [f"stack is empty, minimum={self.minimum}"]
        smallest = min(self.values)
        if self.minimum == smallest:
            return []
        return [f"minimum={self.minimum}, smallest live element={smallest}"]


class ForgetfulMinStack(MinStack):
    """pop() that returns the right value and leaves the cache stale."""

    def pop(self):
        return self.values.pop()


def drain(stack):
    for value in (5, 3, 7):
        stack.push(value)
    trace = [f"pushed 5, 3, 7 -> minimum {stack.minimum}"]
    for _ in range(2):
        trace.append(f"popped {stack.pop()} -> minimum {stack.minimum}")
    trace.append(f"violations: {stack.violations() or 'none'}")
    return trace


for label, stack in (("restores:", MinStack()), ("forgets :", ForgetfulMinStack())):
    for line in drain(stack):
        print(label, line)
```

两个版本的差别只有 `pop` 里的一行：返回之前是否重新计算缓存。前两行输出完全相同——第一次弹出的 7 恰好不是最小值，缓存不需要变；差别出现在第三行：栈里只剩 5，缓存还留着 3。此时没有异常，`pop` 也返回了正确的值，错误只在下一次问 `minimum()` 时暴露，而且表现出来的是答案错，不是原因错。检查器把定位提前到那一次 `pop`。

这项检查本身有成本：它遍历全部元素，把一次常数时间的调用变成 $O(n)$ 的扫描。所以检查器属于调试与教学路径，不属于热路径。

## 同一个契约，两种表示

「重新计算缓存」这一步正是成本的所在。同样满足契约的两种表示，把工作放在了不同位置。

```python run id="alg.adt.two-representations"
class RescanMin:
    """minimum() scans the live elements; nothing is cached."""

    def __init__(self):
        self.values = []

    def push(self, value):
        self.values.append(value)

    def pop(self):
        return self.values.pop()

    def minimum(self):
        comparisons = 0
        smallest = None
        for value in self.values:
            comparisons += 1
            if smallest is None or value < smallest:
                smallest = value
        return smallest, comparisons

    def slots(self):
        return len(self.values)


class CachedMin:
    """minimum() reads a cache that push and pop keep correct."""

    def __init__(self):
        self.values = []
        self.minima = []

    def push(self, value):
        best = value if not self.minima else min(value, self.minima[-1])
        self.values.append(value)
        self.minima.append(best)

    def pop(self):
        self.minima.pop()
        return self.values.pop()

    def minimum(self):
        return self.minima[-1], 0

    def slots(self):
        return len(self.values) + len(self.minima)


def build(implementation, size):
    stack = implementation()
    for value in range(size, 0, -1):
        stack.push(value)
    return stack


header = f"{'n':>5} {'rescan: comparisons':>20} {'cached: comparisons':>20}"
header += f" {'rescan: slots':>14} {'cached: slots':>14}"
print(header)
for size in (128, 256, 512):
    rescan = build(RescanMin, size)
    cached = build(CachedMin, size)
    _, rescan_comparisons = rescan.minimum()
    _, cached_comparisons = cached.minimum()
    row = f"{size:>5} {rescan_comparisons:>20} {cached_comparisons:>20}"
    row += f" {rescan.slots():>14} {cached.slots():>14}"
    print(row)
```

按需重算的表示把成本放在 `minimum()` 上：每问一次就扫一遍元素，比较次数等于当前元素个数。缓存表示把成本摊在每个元素上：为每个元素多保存一份「到这个位置为止的最小值」，`push` 与 `pop` 各多一次读写，而 `minimum()` 是读一次列表末尾。

两种表示都满足契约，也各自维护自己的不变量；差别来自表示，不来自契约。所以「`minimum()` 是 $O(1)$」这句话本身不可检验，完整的写法是：在缓存表示上，`minimum()` 是 $O(1)$ 次读取，代价是每个元素多一个槽位以及 `push`、`pop` 上的额外读写；在按需重算的表示上，同一个操作是 $\Theta(n)$ 次比较。规模、表示与成本模型要跟结论一起给出，见 <CrossRef id="algorithms.cost-model" />。

## 小结

- 问题规约、抽象契约与表示是三个不同的层次；复杂度论断属于表示与算法，不属于契约。
- 表示不变量是每个操作返回之前都必须重新建立的性质；前置条件由调用方负责，两者不能互相替代。
- 违反不变量通常延迟表现为错误答案；把不变量写成检查器可以把定位提前到破坏它的那次操作，代价是检查器自身的成本。
- 同一契约的不同表示在时间与空间上给出不同结论；报出成本时必须同时给出表示、规模与成本模型。
