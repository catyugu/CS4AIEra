成本模型那课把最坏、平均与摊还三种成本论断分开了。其中摊还可以变成可计算的东西：给出一串操作的总成本上界，并说明这个上界用什么代价换来。

对象是一串操作，不是一个规模。设 $\sigma = (op_1, \dots, op_m)$ 是一个合法操作序列，$T(\sigma) = \sum_{i=1}^{m} c_i$ 是它的真实总成本。摊还分析要给出**对所有合法序列统一成立**的总成本界；如果还能给每次操作规定一个摊还收费 $\hat a_i$，使任意合法序列都满足 $T(\sigma) \le \sum_i \hat a_i$，这组收费就给出该序列的摊还上界。特别地，如果总能取 $\hat a_i \le C$，就得到 $T(\sigma) \le C \cdot m$，即每次操作 $O(1)$ 的摊还上界；聚合分析常常直接证明 $T(\sigma) = O(m)$，不必真的给每一步分配收费。

$T(\sigma) / m$ 是这个具体序列上的**实际平均成本**，$\hat a_i$ 则是论证中人为构造的**收费**：两者不是一个量，收费也不由真实序列唯一确定（后文「势能法看动态数组」的例子会同时给出 2 与 3，两者都有效）。摊还分析不需要任何随机性假设，也不需要哈希或分布均匀；平均情形是另一种取平均的方式，它对输入分布取期望，因而需要说明分布假设（见 <CrossRef id="algorithms.cost-model" />）。本课的摊还证明都是确定性的，摊还与期望是两个独立维度、可以组合成期望摊还界，概率这一维留给 <CrossRef id="algorithms.average-and-randomized" />。

## 摊还成本的定义

摊还界是一条对**所有**合法操作序列成立的界：若存在收费 $\hat a_i$，使任意长度 $m$ 的合法序列 $\sigma$ 都满足

$$
T(\sigma) = \sum_{i=1}^{m} c_i \;\le\; \sum_{i=1}^{m} \hat a_i,
$$

这组收费就是该序列的摊还收费。收费一致有上界时（$\hat a_i \le C$）得到常数摊还成本 $T(\sigma) \le C \cdot m$。序列可以任意长、也可以在任意位置结束，而前缀本身也是一个合法序列，所以界必须覆盖每一个前缀。

聚合、记账与势能三种方法都用来证明对合法操作序列成立的总成本界，但构造出的收费方式和常数不必相同：

| 方法 | 做法 | 需要什么 |
| --- | --- | --- |
| 聚合分析 | 直接求 $T(m)$ 的上界，再除以 $m$ | 对整串操作计数 |
| 记账法 | 给操作预先规定摊还收费，多收的部分存成「信用」，用来支付后续的昂贵操作 | 一个信用不变式，保证余额不为负 |
| 势能法 | 定义状态函数 $\Phi$，令摊还成本 $\hat a_i = c_i + \Phi_i - \Phi_{i-1}$ | 一个非负的势函数 |

势能法与记账法等价：势可以解释为系统中尚未花掉的总信用（数学上的势函数可以很抽象，不必对应某一批实体硬币）。势能法更适合写证明，因为对每个前缀 $k$ 都有恒等式

$$
\sum_{i=1}^{k} \hat a_i = \sum_{i=1}^{k} c_i + \Phi_k - \Phi_0,
$$

因此只要对每个可达状态都有 $\Phi_k \ge \Phi_0$（最常见的规范化是 $\Phi_0 = 0$ 且 $\Phi$ 非负），第 $k$ 步停下时摊还收费之和仍然不低于真实成本：$T(\sigma_{1:k}) \le \sum_{i \le k} \hat a_i$。任何前缀都不会透支，靠的正是这条条件。

**摊还上界主张什么、不主张什么**：

- 主张：对任意合法操作序列、包括任意合法前缀，真实总成本不超过所证明的摊还收费之和。序列在任意位置停下都成立。
- 不主张：某一次操作的**真实**成本不超过它自己那次收费。单次最坏成本仍然可以远高于摊还收费。
- 不主张：概率。本课的确定性摊还证明不需要输入分布，也不需要随机化；摊还与期望是两个可以组合的维度。
- 不主张：没花掉的信用会被兑现。摊还收费之和可以严格大于已经发生的真实成本，这不影响上界成立。

因此能否用摊还结论，取决于系统关心的是**吞吐**还是**单次延迟**：批量导入、按批处理的流水线适合前者；若接口需要硬性的单次延迟保证，就必须分析单次最坏成本，而统计意义上的尾延迟还需要相应的分布或高分位信息——摊还界两者都提供不了。序列很短时，渐进记号隐藏的常数与初始化成本可能主导实际时间，仅凭一个 $O(1)$ 的摊还记号不足以判断性能。

## 势能法看动态数组

动态数组的追加操作大多数是常数时间，偶尔一次要复制全部已有元素。对本节这个「只追加、满载时容量精确翻倍」的动态数组，取势函数 $\Phi = 2 \cdot \text{size} - \text{capacity}$，所有取值都在完整操作的边界上算。这个势不是「动态数组」这一抽象结构天然拥有的：换成一倍半扩容、允许删除或别的缩容策略，势函数都要重新设计。数组满载时 $\text{size} = \text{capacity} = c$，于是 $\Phi_{\text{before}} = 2c - c = c$，正好等于那次追加要复制的 $c$ 个元素。这次追加复制 $c$ 个元素并写入一个新元素，所以 $c_i = c + 1$；操作结束后 $\text{size} = c + 1$、$\text{capacity} = 2c$，$\Phi_{\text{after}} = 2(c + 1) - 2c = 2$。于是 $\hat a_i = (c + 1) + (2 - c) = 3$。

```python run id="alg.amortized.potential"
class GrowingArray:
    """A dynamic array that reports the potential of each append."""

    def __init__(self):
        self.capacity = 0
        self.size = 0

    def potential(self):
        return 2 * self.size - self.capacity

    def append(self):
        before = self.potential()
        if self.size == self.capacity:
            real_cost = 1 + self.size          # write the element, copy the existing ones
            self.capacity = max(1, self.capacity * 2)
        else:
            real_cost = 1
        self.size += 1
        after = self.potential()
        return self.capacity, real_cost, after - before, real_cost + after - before


array = GrowingArray()
rows = [array.append() for _ in range(16)]

print(f"{'n':>3} {'capacity':>8} {'real':>5} {'dPhi':>5} {'amortized':>9}")
for step, (capacity, real, delta, amortized) in enumerate(rows, start=1):
    print(f"{step:>3} {capacity:>8} {real:>5} {delta:>5} {amortized:>9}")

total_real = sum(real for _, real, _, _ in rows)
total_amortized = sum(amortized for _, _, _, amortized in rows)
print("real costs:", [real for _, real, _, _ in rows])
print("amortized costs:", [amortized for _, _, _, amortized in rows])
print("sum of real costs:", total_real, "| sum of amortized costs:", total_amortized)
print("final potential:", array.potential())
print("identity T + Phi_m - Phi_0 = sum of amortized:", total_real + array.potential() == total_amortized)
print("worst single operation:", max(real for _, real, _, _ in rows))
```

每一个发生了复制的步骤都落回同一水平：`dPhi` 在大操作上是负的（信用被花掉），在小操作上是正的（信用被存入），两者相加得到固定的摊还收费 3。

同一个真实成本序列可以有不同的有效摊还证明：聚合计数给出 $T(m) < 2m$，所以 2 是一个更紧的一致上界；这个势函数构造出的逐次收费至多 3，是另一个有效但更松的上界。三个数要分清：$T(16)/16 \approx 1.94$ 是这个具体序列的实际平均成本，2 是聚合证明得到的一致上界，3 是该势函数产生的逐次收费上界。摊还收费不由真实序列唯一决定，只要能统一支付真实总成本即可。最后一次的大复制由前面各次存下的信用支付，因此单次成本的尖峰不会改变整串的结论。

这段代码说明了两件事，第二件比第一件重要：16 次追加的总真实成本约两倍于 16，$\Phi$ 在末尾还留着 $2 \cdot \text{size} - \text{capacity}$ 的正余额，因此 $T(m) + \Phi_m - \Phi_0$ 恰好等于摊还收费之和。恒等式成立说明「预收的信用」对应真实成本在时间上被推迟的部分。扩容策略决定结论成立与否：固定增量扩容的总成本是 $\Theta(n^2)$，几何扩容是 $\Theta(n)$，这个取舍的细节见 <CrossRef id="algorithms.arrays-and-lists" />。

## 聚合分析看栈

一个栈通常只支持 `push` 与 `pop`。给它加一个 `multipop(k)`：弹出 $\min(k, \text{size})$ 个元素。单次 `multipop` 的成本是 $\Theta(n)$，看起来让整串操作变贵了。

```python run id="alg.amortized.aggregate-multipop"
def run_sequence(operations):
    """Return (total element operations, worst single operation, remaining size)."""
    stack = []
    total = 0
    worst = 0
    for kind, count in operations:
        if kind == "push":
            for value in range(count):
                stack.append(value)
                total += 1
            worst = max(worst, count)
        else:
            popped = min(count, len(stack))
            for _ in range(popped):
                stack.pop()
                total += 1
            worst = max(worst, popped)
    return total, worst, len(stack)


sequences = {
    "push only": [("push", 1)] * 32,
    "push then multipop": [("push", 1)] * 32 + [("multipop", 32)],
    "interleaved": [item for _ in range(16) for item in (("push", 1), ("push", 1), ("multipop", 1))],
    "repeated whole-stack drains": [item for _ in range(8) for item in ([("push", 1)] * 8 + [("multipop", 8)])],
}

for name, operations in sequences.items():
    total, worst, remaining = run_sequence(operations)
    print(f"{name:28s} operations={len(operations):3d} work={total:4d} work/op={total / len(operations):.2f} worst single={worst:3d} remaining={remaining}")
```

四个序列的单次最差成本分别是 `1`、`32`、`1`、`8`，而每次操作的实际平均工作量都不超过 2。原因与这个结构有关：每一次 `push` 创建的栈内元素实例至多被弹出一次，因此整串操作的总工作量不超过 $2m$，与 `multipop` 的参数无关。

**给每个元素实例的生命周期计费**是聚合分析常见的一种证明模式。当昂贵操作在重复处理已有元素时，第一问就是：这段序列里每个元素实例最多被处理几次。二进制计数器和后面的并查集用的不是这种计数方式。

## 势能法看二进制计数器

一个 $k$ 位计数器每次加一，翻转从最低位开始的连续 1。单次加一的最坏情况是翻转全部 $k$ 位，即 $\Theta(k)$；只有当 $k = \Theta(\log(m + 1))$（计数器刚好够表示前 $m$ 次递增）时，才能把它写成 $\Theta(\log m)$。

```python run id="alg.amortized.binary-counter"
def increment(bits):
    """Add one, return the number of bit flips."""
    flips = 0
    for index in range(len(bits)):
        flips += 1
        if bits[index] == 0:
            bits[index] = 1
            return flips
        bits[index] = 0
    return flips  # wrapped back to zero


width = 32
for count in (8, 16, 64, 256):
    bits = [0] * width
    flips_per_increment = [increment(bits) for _ in range(count)]
    print(
        f"increments={count:4d} total flips={sum(flips_per_increment):4d} "
        f"flips/increment={sum(flips_per_increment) / count:.2f} worst single={max(flips_per_increment):2d}"
    )
```

第 $i$ 位每 $2^i$ 次加一翻转一次，因此 $m$ 次加一的总翻转次数是 $\sum_i \text{floor}(m / 2^i) < 2m$：摊还常数成本，而单次最坏是 $\Theta(\log m)$。势函数 $\Phi$ 取计数器中 1 的个数，一次加一翻转 $t + 1$ 位（其中 $t$ 位由 1 变 0）时，$\hat a = (t + 1) + (1 - t) = 2$。

## 摊还不是延迟保证

把三个结构的数字放在一起，区别就清楚了：摊还成本衡量整串操作，单次成本衡量一次调用。

```python run id="alg.amortized.latency-gap"
class GrowingArray:
    def __init__(self):
        self.capacity = 0
        self.size = 0

    def append(self):
        if self.size == self.capacity:
            real_cost = 1 + self.size
            self.capacity = max(1, self.capacity * 2)
        else:
            real_cost = 1
        self.size += 1
        return real_cost


def increment(bits):
    flips = 0
    for index in range(len(bits)):
        flips += 1
        if bits[index] == 0:
            bits[index] = 1
            return flips
        bits[index] = 0
    return flips


count = 4096
array = GrowingArray()
append_costs = [array.append() for _ in range(count)]

bits = [0] * 64
flip_costs = [increment(bits) for _ in range(count)]

for name, costs in (("dynamic array append", append_costs), ("binary counter", flip_costs)):
    total = sum(costs)
    print(
        f"{name:22s} actual average T/m={total / count:6.2f} "
        f"worst single={max(costs):5d} ratio={max(costs) / (total / count):8.1f}x"
    )
print("the same operations, two different questions: throughput and tail latency")
```

同一个序列里，聚合证明给出的一致上界是常数 2，而单次真实成本可以远超它（最紧的摊还上界是 2，单元格列的是这个具体序列的实际平均成本 $T(m)/m$）。**决定用哪个结论的是系统的问题**：批量任务关心总吞吐，摊还结论足够；在线路径关心尾延迟，必须看单次最坏成本。把摊还结论当作延迟保证写进接口文档，是把一个正确的数学结论用在了它不覆盖的场合；接口描述里省略「摊还」二字同样会让调用方对单次成本作出错误推断。

## 小结

- 摊还分析给出对所有合法操作序列（含任意前缀）成立的总成本界；$T(\sigma)/m$ 只是某个具体序列的实际平均成本，摊还收费由论证构造、不唯一。
- 聚合分析直接对整串操作计数；记账法预先规定摊还收费并维持信用余额非负；势能法把信用写成状态函数，$\hat a = c + \Delta \Phi$，条件是对所有可达状态有 $\Phi_k \ge \Phi_0$。
- 动态数组追加的势函数是 $\Phi = 2 \cdot \text{size} - \text{capacity}$，每次追加的摊还收费是常数 3；二进制计数器的势是 1 的个数，每次加一的摊还收费是 2。
- 栈加 `multipop` 后单次成本可以是 $\Theta(n)$，但每个元素实例至多被弹出一次，整串总成本仍是 $\Theta(m)$。
- 摊还结论回答吞吐问题，单次最坏界回答硬延迟上界问题；两者不能互相替换。
