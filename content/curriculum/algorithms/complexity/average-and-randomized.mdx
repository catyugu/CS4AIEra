上一课用摊还分析处理了一串操作的总成本，其中不需要任何随机性假设。另一种「平均」是对**输入**取期望，或者让**算法自己**掷硬币。

这两者经常被混为一谈，后果是把一个条件性结论当成无条件结论使用：说「哈希表查找是 `O(1)`」时省略了「在什么假设下」，说「快速排序是 `n log n`」时省略了「对什么分布」。把假设写出来之后可以看到，随机化把结论从「对随机输入平均」升级为「对该算法可能产生的每一次随机选择平均」——后者对每个输入都成立，包括对手精心构造的输入。

## 平均情形与期望

- **平均情形**是对输入分布取期望：`E[成本] = Σ P(输入) · 成本(输入)`。没有分布就没有结论；同一个算法在不同分布下的平均成本可以差一个数量级。
- **期望**由随机性来源决定。两种来源必须分开：
  - 输入是随机的（假定或实测的分布）——结论只对该分布成立；
  - 算法内部的随机选择（掷硬币）——结论对**每一个**输入都成立，随机性由算法掌控。
- **随机化的价值在对抗场景里最明显**：确定性算法的对手可以预先构造输入让它进入最坏情形；随机化算法让对手无法预知会走哪条路径，因而无法针对某一次运行构造输入。
- **随机化算法有两类**：
  - Las Vegas：结果始终正确，运行时间随机（随机化快速排序）；
  - Monte Carlo：运行时间固定或有界，结果有可控制的错误概率（随机点上的多项式判等、概率素性测试）。
- **期望界不约束单次运行**：期望 `n log n` 允许某次运行更慢，甚至退化为最坏情形。需要单次上界时用最坏情形；需要把「偶尔很慢」变成「几乎不会很慢」时，用重复执行与集中不等式（本课演示前者，后者只需知道存在）。
- **期望不是平均值**：实验测出的样本均值只是对期望的估计，它验证实现是否符合模型；结论本身来自对分布或随机选择的计数论证，测得「平均很快」不构成复杂度结论（见 <CrossRef id="algorithms.cost-model" />）。

## 平均情形需要分布

线性查找的成本取决于目标在序列中的位置。同一个实现，两种分布，两个结论。

```python run id="alg.avg.linear-search"
import random


def search(items, target):
    """Return the number of comparisons the lookup costs."""
    for index, item in enumerate(items):
        if item == target:
            return index + 1
    return len(items)          # absent: the scan runs to the end


size = 100
items = list(range(size))
generator = random.Random(0)

uniform_positions = [generator.randrange(size) for _ in range(2000)]
absent_keys = [size + offset for offset in range(2000)]

uniform_cost = [search(items, items[position]) for position in uniform_positions]
absent_cost = [search(items, key) for key in absent_keys]

print(f"uniform positions: mean comparisons={sum(uniform_cost) / len(uniform_cost):.1f} worst={max(uniform_cost)}")
print(f"keys that are absent: mean comparisons={sum(absent_cost) / len(absent_cost):.1f} worst={max(absent_cost)}")
print("closed forms: (n + 1) / 2 =", (size + 1) / 2, "| n =", size)
```

两种分布的差别不是常数因子：均匀分布下平均比较次数趋近 `(n + 1) / 2`，而「查找一个不存在的键」时每次都要走完全程，平均等于 `n`。**同一段代码，同一个规模，两个不同的结论**。任何「线性查找平均是 n/2」的说法都隐含了「目标等可能地出现在任意位置」这一假设。

## 随机化拿掉对手的杠杆

确定性快速排序取首元素为基准点：对已经有序的输入，每次划分都极不均衡，成本是 `Θ(n²)`。随机化版本按随机顺序取基准点，同一个输入下的成本变成期望 `O(n log n)`。

```python run id="alg.avg.randomized-quicksort"
import math
import random


def quicksort(items, pivot_choice):
    """Sort in place, return the number of comparisons."""
    comparisons = 0
    stack = [(0, len(items) - 1)]
    while stack:
        low, high = stack.pop()
        if low >= high:
            continue
        index = pivot_choice(low, high)
        items[low], items[index] = items[index], items[low]
        pivot = items[low]
        boundary = low
        for scan in range(low + 1, high + 1):
            comparisons += 1
            if items[scan] < pivot:
                boundary += 1
                items[boundary], items[scan] = items[scan], items[boundary]
        items[low], items[boundary] = items[boundary], items[low]
        stack.append((low, boundary - 1))
        stack.append((boundary + 1, high))
    return comparisons


size = 300
sorted_input = list(range(size))
generator = random.Random(1)

fixed_pivot = lambda low, high: low
random_pivot = lambda low, high: generator.randrange(low, high + 1)

fixed_cost = quicksort(sorted_input.copy(), fixed_pivot)
random_costs = [quicksort(sorted_input.copy(), random_pivot) for _ in range(20)]

print(f"deterministic pivot on sorted input: {fixed_cost} comparisons ({size * (size - 1) // 2} is the worst case)")
print(f"random pivot on the same input: mean={sum(random_costs) / len(random_costs):.0f} worst={max(random_costs)}")
print("n log2 n for reference:", round(size * math.log2(size)))
```

同一份已排序输入：固定基准点是 44850 次比较（`n(n−1)/2`，最坏情形），随机基准点的平均约 2000 多次，最坏的一次也远离最坏情形。**输入没有变，变的只是算法自己的随机选择。**

结论的形式也不同。固定基准点的 `Θ(n²)` 是对这个输入说的；随机基准点的期望 `O(n log n)` 是对**每一个**输入说的——对手知道你会随机选，但不知道这一次选到哪，因此无法构造让它必然退化的输入。

输出的第三行 `n log₂ n` 只是量级参考，不是这个实现的常数：常数由划分与移动的具体写法决定，属于实现，不属于成本模型。

## 哈希函数的随机化

哈希表在「简单均匀哈希」假设下期望 `O(1)`；固定哈希函数给了对手构造全冲突键集的机会。随机化从一族函数里抽取，让任何**固定**键集在期望上分布均匀。

```python run id="alg.avg.universal-hashing"
import random


def bucket_sizes(keys, hash_function, buckets):
    counts = [0] * buckets
    for key in keys:
        counts[hash_function(key) % buckets] += 1
    return counts


buckets = 64
prime = 1000003
trials = 200

# an adversarial key set for the fixed function "key % 64": every key is a multiple of 64
keys = [offset * buckets for offset in range(400)]

fixed_sizes = bucket_sizes(keys, lambda key: key, buckets)
print(f"fixed hash on an adversarial key set: max bucket={max(fixed_sizes)} over {len(keys)} keys")

generator = random.Random(2)
maxima = []
for _ in range(trials):
    a = generator.randrange(1, prime)
    b = generator.randrange(0, prime)
    maxima.append(max(bucket_sizes(keys, lambda key, a=a, b=b: (a * key + b) % prime, buckets)))

# control: hand every key a uniform random bucket, without any hash function
control = [max(bucket_sizes(keys, lambda key: generator.randrange(buckets), buckets)) for _ in range(trials)]

even_load = len(keys) / buckets
print(f"family {trials} times on the same keys: mean max bucket={sum(maxima) / len(maxima):.2f} worst={max(maxima)}")
print(f"uniformly random assignment as a control: mean max bucket={sum(control) / len(control):.2f} worst={max(control)}")
print(f"even loading would be {even_load} keys per bucket, but the largest of 64 random buckets is above it")
print("family trials with a bucket above twice the even load:", sum(1 for value in maxima if value > 2 * even_load))
```

固定函数把 400 个键全部放进同一个桶：目标明确、构造简单，而程序本身没有任何异常信号。随机化后用同一批键，最大桶的平均值降到 8.5 左右，最坏一次 44，全部落在「几十」这个量级上，而固定函数是 400。

注意**不要**把随机化理解为「桶会很均匀」：200 次抽取里有 6 次出现了超过均匀负载两倍的桶。把每个键真正均匀随机地分配到 64 个桶里做对照，平均最大桶反而更大（见输出）。原因是「64 个桶中的最大值」本身就是一个大于平均负载的量——即使每次分配完全独立均匀，也总会有桶偏多。

这是**全域哈希**（universal hashing）的实际形态：从一族函数中随机抽取，使任意两个固定键冲突的概率不超过 `1 / buckets`。它约束的是期望与冲突概率，不是每次抽取的桶占用；用它推理时该问的是「期望查找成本」，而不是「最大桶不超过多少」。随机数生成器的质量就是算法的一部分：可预测的伪随机数让对手重新获得预知能力，固定种子的生成器只适合可复现的实验。随机化与摊还可以叠加，但结论要分开写——哈希表查找的 `O(1)` 期望来自哈希假设，扩容的摊还来自势函数，混在一句里会让假设与结论都失去含义。不可预测也不等于更快：随机化的价值在于消除对手的针对性，常数因子通常比确定性版本略大。

语言实现把同一条思路用作防护——字符串的哈希值在进程间随机化，正是为了不让外部输入预知哈希函数（见 <CrossRef id="python.equality-and-hashing" />）。哈希表结构本身见 <CrossRef id="algorithms.hash-tables" />。

## 期望之外：错误概率与重复

Monte Carlo 算法用**可控的错误概率**换取确定的运行时间。判等是标准例子：在两个多项式的差上随机取点求值，非零多项式只有一个很小的概率取到零。

```python run id="alg.avg.monte-carlo"
import random

field = 101
generator = random.Random(3)


def same_at(first, second, point):
    return (first(point) - second(point)) % field == 0


p = lambda x: (x * x + 1) % field
r = lambda x: (x * x + x + 1) % field      # differs from p at every point except x = 0

trials = 2000


def verdict(points):
    """Declare the polynomials equal unless some point shows a difference."""
    return all(same_at(p, r, generator.randrange(field)) for _ in range(points))


single = sum(1 for _ in range(trials) if verdict(1))
repeated = sum(1 for _ in range(trials) if verdict(3))

print(f"one random point: wrong verdicts={single} of {trials} ({single / trials:.4f}, theory {1 / field:.4f})")
print(f"three random points: wrong verdicts={repeated} of {trials} (theory {1 / field ** 3:.2e})")
print("the two polynomials agree only at x = 0, one point out of", field)
```

一次随机取点的错误概率是 `1 / 101`（两个多项式只在 `x = 0` 处相等），实测接近理论值；取三个独立点后错误概率降到 `(1 / 101)³ ≈ 10⁻⁶`，2000 次试验里一次都没有失败。**这就是 Monte Carlo 结论的形态**：运行时间固定，错误概率由重复次数控制，而单次结果无法从这一次运行看出来对不对——算法自己也不知道这次的「相等」是真是假，只有重复与独立性能把它压下去。

Las Vegas 算法相反：结果永远正确，代价花在时间上（前面随机化的快速排序）。两者都需要重复的策略：Las Vegas 在超时后重启，Monte Carlo 用独立的多次运行降低错误概率。重复的前提是独立性——同一个种子、同一次采样结果重用不会降低错误概率。

## 小结

- 平均情形是对输入分布取期望；没有分布就没有结论。
- 随机化算法把随机性放进算法内部，结论对每个输入成立，对手无法针对单次运行构造输入。
- Las Vegas 正确性确定、时间随机；Monte Carlo 时间确定、正确性有可控错误概率。
- 全域哈希从函数族中随机抽取，使任意固定键集的最大桶期望可控；语言对字符串哈希做随机化是同一思路。
- 期望界不约束单次运行；重复与独立性把 Monte Carlo 的错误概率降到可接受水平。
- 实验用于验证模型，模型由计数论证给出。
