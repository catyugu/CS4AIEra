从整数列表里挑出最大的元素，小到可以一口气写完。下面这段扫描维护一个已比较前缀中的最大值，`start` 是 `best` 的初值：

```python run id="alg.correctness.counterexample"
def maximum(values, start):
    """Return the largest element, with the running best starting at `start`."""
    best = start
    i = 1
    while i < len(values):
        if values[i] > best:
            best = values[i]
        i += 1
    return best


values = [-3, -1, -2]
print("start = values[0]:", maximum(values, values[0]))
print("start = 0:        ", maximum(values, 0))
```

以列表首元素起算得到 `-1`，也就是输入的最大值。把初值改成 `0` 得到 `0`，而 `0` 不在输入列表里，输出却看不出任何异常。`[-3, -1, -2]` 这一个合法输入就推翻了「这段实现对所有输入都返回最大值」。一个反例足以推翻一条全称主张；反过来，跑通再多输入也只是没发现问题，有限测试不能证明所有输入都正确。判断一段代码「对」还是「错」，要先把「对」写成一条可以判定真假的命题，再让论证把它接上实现。

## 把「对不对」写成规约

写下这条命题，就是在写这段代码的 <Term id="specification">规约</Term>：<Term id="precondition">前置条件</Term>界定允许执行开始时的状态，由调用方负责满足；<Term id="postcondition">后置条件</Term>界定执行结束后必须成立的性质，可以关联初始状态、最终状态与返回值。

取最大值的后置条件有两条：返回值属于输入列表，且输入中不存在比它更大的元素。两条缺一不可——只写「不小于输入中的每个元素」，会放过一个根本不在列表里的返回值，上面的反例正是这么失败的。前置条件要覆盖实现实际用到的操作：这一族实现在比较元素，所以除了非空，还要求元素两两可比；`[1, "x"]` 非空却无法比较。

## 循环不变量

**循环不变量**是在**循环头**——每次检查循环条件之前——都成立的性质。这个位置既包括第一次检查，也包括最后一次条件为假、循环即将退出时的检查。它对循环体的要求是：若循环头满足不变量且循环条件为真，则执行一次循环体后，回到下一次循环头时不变量仍然成立。

## 用不变量论证扫描

论证一个循环满足后置条件分三步。设 $P$ 是前置条件，$B$ 是循环条件，$Q$ 是后置条件，$I$ 是候选不变量：

1. **初始化**：从满足 $P$ 的状态执行循环之前的初始化代码，第一次到达循环头时 $I$ 成立。
2. **保持**：若循环头满足 $I$ 且 $B$ 为真，执行一次循环体之后，回到下一次循环头时 $I$ 仍然成立。这一步必须用循环体的代码说话。
3. **退出**：循环条件为假时，$I$ 与 $\neg B$ 一起推出 $Q$。

要论证扫描对每个满足前置条件的输入都给出正确答案，先写下循环头处必须成立的性质。把 $i$ 记为本轮开始时已经比较过的元素个数，候选不变量是：

- `1 <= i <= len(values)`
- `best == max(values[:i])`

第一条把 $i$ 限制在合法范围里，第二条把 `best` 钉死在已比较前缀的最大值上。它比「返回值是最大值」更强：后者只描述终态，在循环中途无从检查，也无法被循环体逐轮重建。

下面的代码在每一次求值循环条件之前打印已处理的前缀与当前的 `best`：

```python run id="alg.correctness.loop-invariant"
def maximum(values, start):
    """Running-best scan; print the state at each loop head."""
    best = start
    i = 1
    while i < len(values):
        print(f"loop head: processed={list(values[:i])}  best={best}")
        if values[i] > best:
            best = values[i]
        i += 1
    print(f"loop head: processed={list(values)}  best={best}")
    return best


values = [3, 1, 4, 2]
maximum(values, values[0])
```

每次打印出的 `best` 都是 `processed` 这一段的最大值：处理到 `[3]` 时是 `3`，到 `[3, 1]` 时仍是 `3`，到 `[3, 1, 4]` 时是 `4`，整个列表处理完也是 `4`。把这条观察写下来，就是上面两个不等式的第二条；循环体把前缀扩大一格，同时把 `best` 更新到新的前缀最大值。

轨迹检查只在它执行过的输入上成立，不构成一般性的证明。一般的证明要交代三件事。

**初始化**：循环开始前 `best = values[0]`、$i = 1$，需要 `best == max(values[:1])`。单元素前缀的最大值就是那个元素本身。这一步用到的假设是前置条件里的「列表非空」：`values[0]` 才有定义。

**保持**：假设本次循环头满足 $I$ 且循环条件为真（$i \lt n$）。循环体只做两件事：当 `values[i]` 大于 `best` 时把 `best` 换成 `values[i]`，然后把 $i$ 加一。回到下一个循环头时 $i$ 变成 $i+1$。新的 `best` 是上一轮 `best` 与 `values[i]` 中较大的一个；由 `best == max(values[:i])`，它等于 `max(values[:i+1])`。这一步用到的假设是元素两两可比，`values[i] > best` 这个条件才总能选出较大者。

**退出**：循环条件为假时 $i \ge n$，与 $I$ 中的 $i \le n$ 合起来得到 $i = n$，于是 `best == max(values[:n]) == max(values)`。返回值属于输入列表由赋值来源推出：`best` 要么是 `values[0]`，要么在循环体里被赋成某个 `values[k]`，一定是输入中的一个元素。后置条件的两条都满足。

初始化与退出各只需一句话；需要论证的是保持这一步，它必须用循环体的代码说话，并且整段证明只用到元素两两可比这一条假设。

## 终止

循环不变量的三步证明：循环一旦结束，结果就满足后置条件。它没有说循环会不会结束；正确性还要求**终止**——对每个满足前置条件的输入，循环都在有限步内结束。

找最大值的扫描把 $i$ 从 $1$ 推到 $n$，尚未处理的元素个数 $n - i$ 是非负整数，每轮严格减一，不可能无限下降，因此循环一定在有限轮内触底于 $0$。这种「取值不能无限下降」的结构一般称为 <Term id="well-founded-order">良基序</Term>；$n - i$ 是它套在非负整数上的一个实例。

终止是一条对所有输入成立的主张，观测只覆盖跑过的那些输入，「跑一会儿看会不会停」回答不了它。忘记推进的循环没有可用的下降度量：循环体若从不改变 `index`，`while index < len(values)` 就永远为真，终止主张不成立。
