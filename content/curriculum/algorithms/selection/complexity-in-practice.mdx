一次单位成本的 RAM 分析把每次基本操作当作 1，把一次内存访问计为固定的单位成本、忽略缓存层次，并假定地址空间足够；有些结论另外声明比较模型、哈希概率模型等附加假设。真实的机器里单位操作代价不同、内存分层次、内存有限。因此同一渐近阶内的一对实现可能可以差出数量级，这个差别在渐近记号里看不见。

渐近记号描述函数的增长率；成本模型决定我们在数什么。这三条约定属于成本模型，不属于 $O$ 与 $\Theta$ 记号本身：换一个模型，$\Theta(n)$ 次缓存失配、$\Theta(n/B)$ 次 I/O、$\Theta(n)$ 空间、位复杂度、外存复杂度都是合法的渐近结论；改变成本模型既可能只改变常数，也可能改变得到的渐近式。差额通常不改变关于输入规模的阶——常数因子就是这样——但换到比特复杂度或外存模型的计数方式，渐近表达式本身也可能变；而在阶不变的地方，差额经常改变同一渐近阶内部的选择，大部分工程决策正发生在这里。

## 单位成本模型把什么当作 1

一份成本模型要能应用就得给出三个约定，单位成本的 RAM 模型把它们的取值固定成最省事的那种：

| 约定 | 模型假设 | 实际 |
| --- | --- | --- |
| 单位操作 | 每次基本操作代价相同 | 比较、加法、分配、方法调用的代价差几倍到几十倍 |
| 内存 | 访问任意位置代价相同 | 寄存器、各级缓存、主存之间差一到三个数量级 |
| 内存容量 | 无限，忽略占用 | 容量有限，占用决定能处理多大规模 |

三个约定各自对应一类现实成本：**常数因子**来自第一条，**局部性**来自第二条，**内存占用**来自第三条。它们不在单位成本模型的时间函数里，也不会因为 $O$ 相同就自动相等；换一个成本函数（缓存失配次数、I/O 次数、比特数），也可以继续用 $O$ 与 $\Theta$ 描述它们。

## 常数因子从哪来

同一渐近阶的两个实现，差异来自可以点数的地方：

- 每个元素要做多少次基本操作（比较次数、拷贝次数、方法调用次数）；
- 单位操作本身的代价（整数比较远便宜于一次字典查找或一次分配）；
- 每次操作的固定开销（函数调用、边界检查、对象创建）；
- 内存布局与访问顺序（下一条）。

这些量分两类，回答的问题不同。**操作次数可以数**：比较几次、拷贝几次、调用几次，插一段计数就能得到，而且可复现。**单位操作的代价数不出来**：一次整数比较、一次字典查找、一次分配各计多少成本，只能来自成本模型或实测，不是计数能得到的。点数说明差额从哪里来，实测给出差额有多大；两者都要，且要分开陈述。点数与计时各有所长：点数可复现、可解释来源，但需要自己定义单位操作；计时包含真实效果，但依赖环境——受控条件下它当然可以复现，只是带噪声，也不像抽象计数那样跨机器、跨解释器可移植，所以给出数字时要连同环境与统计一起报。常数不能脱离规模谈：同一实现「快 3 倍」只对特定规模、特定工作负载成立；把限定条件写进结论。

## 局部性：同一渐近阶下的数量级差别

遍历 $n$ 个元素在两种表示里都是 $\Theta(n)$，但访问模式不同。连续数组按下标前进，相邻元素落在同一条缓存行里；链式结构顺着指针跳到下一个节点，而节点的位置由分配顺序决定，与遍历顺序无关。把内存分成固定大小的行、用一个直接映射的小缓存来数：

```python run id="alg.practice.locality"
import random
import sys

LINE = 8      # cells per cache line
LINES = 64    # lines the modelled cache holds


def count_misses(addresses):
    """Direct-mapped cache: an access misses when its line is not the one the
    slot currently holds."""
    resident = {}
    misses = 0
    for address in addresses:
        line = address // LINE
        slot = line % LINES
        if resident.get(slot) != line:
            resident[slot] = line
            misses += 1
    return misses


n = 8192
rng = random.Random(20260605)
jumps = list(range(n))
rng.shuffle(jumps)

print(f"{n} accesses | line = {LINE} cells | cache = {LINES} lines")
print(f"  forward scan:  {count_misses(list(range(n))):>5} misses")
print(f"  random jumps:  {count_misses(jumps):>5} misses")
print()
import array
import struct

values = list(range(1000))
packed = struct.pack("<1000i", *values)   # the same 1000 integers, 4 bytes each
print("the same 1000 integers in three representations (sizes are for this build):")
print("  representation footprint of these 1000 values, under this accounting:")
print(f"  list:                {sys.getsizeof(values) + sum(sys.getsizeof(v) for v in values):>6} bytes"
      "  (the list object + the 1000 separate int objects it points at)")
print(f"  array('l'):          {sys.getsizeof(array.array('l', values)):>6} bytes")
print(f"  struct '1000i':      {sys.getsizeof(packed):>6} bytes"
      "  (the bytes object, 4000 of payload plus its header)")
```

顺序扫描的失配次数约为 $n / L$，随机跳转接近 $n$：两者都是 $\Theta(n)$，差额却由行的长度决定。它说明的是同一组抽象地址下，顺序访问比随机访问用到了更多<Term id="locality">空间局部性</Term>；指针追逐型的结构（链表、树、哈希表的链地址）**更容易付出这类局部性代价**，但真实机器上还有分配布局、硬件预取与依赖加载在起作用，具体倍数得由这个模型之外的证据给出。这也是「数组比链表快」这句话的真实内容：两者的渐近阶相同，差别出在访问模式与成本模型假设上。模拟不是硬件：上面的缓存模型只有一套参数，真实机器有多级缓存、预取与乱序执行；模型能说明机制，不能预测具体机器的倍数。微基准要固定条件：解释器版本、机器、输入分布、是否预热；换一个环境结论可能翻转，所以报告数字时必须连条件一起报告。

## 内存

第三个约定是内存无限。同一份逻辑数据换一种表示，占用的内存可以差出数倍，来源是对象的表示方式：`list` 存的是指向对象的指针，每个整数是一个独立对象、自带对象头；`array` 与 `bytes` 把定宽整数直接存放在对象内部，没有每元素的对象头与指针。

上面的单元格按「表示这批值所需的直接对象大小」计数：对 `list` 计容器本身加它引用的每个 `int` 对象的直接大小，对 `array` 与 `bytes` 一次 `sys.getsizeof` 已包含元素存储。三个数字都只统计直接占用，不含共享对象、分配器开销与元数据，具体字节数只对当前这次运行所用的构建成立——指针与对象头的宽度不同，数字就不同，所以引用时必须连构建一起说明。内存占用决定两件事：能处理的最大规模，以及缓存与分页的压力，它把第一条与第二条的代价又带回来一部分。`sys.getsizeof` 的统计口径见 [sys.getsizeof](https://docs.python.org/3/library/sys.html#sys.getsizeof)，`array` 的定宽元素见 [array](https://docs.python.org/3/library/array.html)，对象头与值分开存放、`list` 只持有指针这一布局见 CPython 的 [object.h](https://github.com/python/cpython/blob/main/Include/object.h)。

## 模型过粗的两个例子

**期望常数时间依赖散列函数的行为与负载因子**。哈希表的期望 $O(1)$ 成本来自两条前提：散列把键均匀分散到桶里，并且负载因子受到控制。前者是关于哈希落点或探测序列的概率模型，后者是结构状态与扩容策略维持的条件；二者都是该期望界的前提，但都不是渐近记号本身的含义，也不属于单位成本模型的那三条约定。换一个把全部键映到同一个桶的散列函数，同一份代码就退化了：第 $k$ 次插入要探测 $\Theta(k)$ 个位置，连续插入 $n$ 个键的总探测数是 $\Theta(n^2)$：

```python run id="alg.practice.probing"
import random

def probes(keys, buckets, hash_of):
    """Linear probing: count the probes used by every insertion."""
    table = [None] * buckets
    total = 0
    for key in keys:
        index = hash_of(key) % buckets
        while table[index] is not None:
            total += 1
            index = (index + 1) % buckets
        table[index] = key
        total += 1
    return total


count, buckets = 200, 400
spread = list(range(count))
rng = random.Random(20260606)
placement = {key: rng.randrange(buckets) for key in spread}   # uniform initial buckets
print(f"linear probing, {count} insertions into {buckets} buckets"
      f" (load factor {count / buckets:.2f})")
print(f"  uniform hashing:              {probes(spread, buckets, lambda key: placement[key]):>6} probes")
print(f"  every key hashes to bucket 0: {probes(spread, buckets, lambda key: 0):>6} probes"
      f"  = {count * (count + 1) // 2}")
```

在同样的最终负载因子 $0.5$ 下，均匀散列的插入每次平均只探测与负载因子有关的常数次，退化的构造则要 $\Theta(n^2)$ 次：$n$ 次插入每次都从空槽位一路探测到下一个空位，合计 $n(n+1)/2$ 次探测。两项的具体次数由单元格给出；差别不在代码，在哈希概率模型与负载因子这两个分析前提。

这条退化来自分析前提被破坏：分析给出的界带前提，前提不成立时界也不成立。输入由对手控制时，这从「慢」升级为「可被构造的攻击面」。

**摊还界控制一段操作序列的总成本，不给单次操作单独的最坏上界**。动态数组的追加是摊还 $O(1)$，其中有些追加会触发扩容并搬移全部元素（<CrossRef id="algorithms.amortized" />）。对吞吐量而言摊还界就是答案；对单次延迟有上限要求的场景，它不构成保证，要按单次最坏成本重新比较。摊还界与平均情形分析不是一回事：它不假定输入的分布，也不对随机变量取期望。

## 渐近分析仍然不可替代

反过来也不成立：不能因为常数重要就跳过渐近分析。它给出三类别的工具给不出的判断：

- **趋势**：$\Theta(n \log n)$ 与 $\Theta(n^2)$ 在小规模上可以互相超越，规模一大次序就固定下来；
- **不可行**：小规模输入上用指数级方案当然可行，但规模一大，指数增长很快压倒常数优化，所以换更快的机器不改变可扩展性结论；
- **约束**：内存占用给出可处理规模的上限，与实现速度无关。

所以顺序是固定：先做渐近分析排除掉错误的量级，再在剩下的同阶候选项之间比较常数、局部性与内存，并且把比较的条件写清楚。结论是分两层判断：量级用渐近记号，同阶内部用常数、局部性与内存；同阶内部的比较把这些量变成成本模型里的单位成本系数，再与工作负载频率合起来解出临界点（见 <CrossRef id="algorithms.choosing-structures" />）。
