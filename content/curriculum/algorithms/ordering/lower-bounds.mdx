## 比较模型

下界总是相对于某个模型而言的。本节把讨论限制在这个模型里：

```text
输入是 n 个键，两两不同
算法唯一能做的事，是取两个键问「第一个是否小于第二个」
每次比较得到一个布尔答案
```

真实程序当然还能做别的事：读内存、比较下标、检查数组长度。但关于**键的相对次序**，在这个模型里算法只能从两两比较中得到信息。本节要证明的结论都要带上这个前提；脱离模型就没有这条下界。

模型里「键两两不同」这条限制是为了让计数论证保持干净。一旦允许重复键，输入不再对应 $n!$ 个彼此不同的严格全序；需要区分的相对次序取决于重复的模式。极端地，当所有键值都相同时，根本不存在 $n!$ 种不同的严格次序需要区分。重复键下的精确比较下界需要另外计数，本节不展开。

## 热身：找最小值需要 n - 1 次比较

在排序之前先看一个更小的任务，因为它和下界的关系最直接。

```text
不变量：每次比较之后，「仍可能是最小值」的候选集合至多减少一个元素

比较两个候选者时，较大者立刻可以被排除
因此 n 个候选缩到 1 个，至少要排除 n - 1 个，也就是至少要 n - 1 次比较
而一次线性扫描恰好用 n - 1 次比较就能找到最小值
```

这条论证里没有出现数组、循环或语言细节，只有「一次比较能排除几个候选者」。它是本节的第一个下界：**找最小值至少需要 $n - 1$ 次比较**，而扫描达到这个数，所以找最小值是 $\Theta(n)$。

这也把上一节接了起来。上一节对任意固定秩给出了期望 $O(n)$ 的 quickselect，而这里的最小值就是 $r = 0$ 的特例；$n - 1$ 次比较的下界说明这个特例在线性量级上已经最优。若要把 $\Omega(n)$ 下界推广到任意秩，还需要更细的选择下界论证，本节不展开。所以这里只用最小值当作下界证明的热身，不据此把上一节所有秩的 $O(n)$ 上界改写成 $\Theta(n)$。

```python run id="alg.ordering.minimum-lower-bound"
def scan_for_minimum(values, counters):
    """A linear scan: every element after the first is compared with the running minimum."""
    best = values[0]
    for value in values[1:]:
        counters["comparisons"] += 1
        if value < best:
            best = value
    return best


n = 4096
values = list(range(n))
values.reverse()
counters = {"comparisons": 0}
best = scan_for_minimum(values, counters)
print("scan on n =", n, ": minimum", best, "| comparisons", counters["comparisons"],
      "| equals n - 1:", counters["comparisons"] == n - 1)

print()
print("how far can n - 2 comparisons take the candidate set?")
n = 8
candidates = list(range(n))
for step in range(n - 2):
    first, second = candidates[0], candidates[1]
    if first > second:
        winner, eliminated = second, first
    else:
        winner, eliminated = first, second
    candidates = [winner] + candidates[2:]
    print(f"  comparison {step + 1}: eliminated {eliminated} | still possible minima: {len(candidates)}")
print("after", n - 2, "comparisons at least", len(candidates), "candidates remain:",
      "you cannot name the minimum yet")

n = 8
candidates = list(range(n))
while len(candidates) > 1:
    first, second = candidates[0], candidates[1]
    if first > second:
        winner = second
    else:
        winner = first
    candidates = [winner] + candidates[2:]
print("it takes", n - 1, "comparisons to leave exactly one candidate:",
      len(candidates) == 1)
```

扫描的实测比较次数是 4095 = $n - 1$，与下界一致；下半段用一个小例子说明 $n - 2$ 次比较之后为什么仍然无法给出答案：每一步至多排除一个候选者，所以候选集合至少还剩 2 个。

## 排序的决策树

排序的下界需要更强的东西，因为一次比较能排除的候选者不再是一个。做法是把「任何比较算法」都看成一棵树。

```text
内部节点：一次比较，两个分支对应两个可能的答案
叶子：算法给出的输出
从根到叶的一条路径：算法在这次运行里做过的全部比较及其结果
```

要下界的是这棵树的高度，也就是最坏情况下从根到叶的比较次数。关键一步是数一数叶子至少要有多少：

```text
算法到达叶子之后不再获得关于键的信息，并必须给出一个固定的输出顺序
如果两个不同的严格全序能够到达同一个叶子，同一个输出不可能同时对这两个输入次序正确
所以每个叶子至多代表一种输入相对次序
```

$n$ 个两两不同的键一共有 $n!$ 种相对次序，而算法对每一种都必须给出正确答案，因此决策树至少有 $n!$ 个叶子。这一步把「$n!$ 种排列」从直觉变成了可用的事实。

## 从叶数推出高度

一棵高度为 $h$ 的二叉树最多有 $2^h$ 个叶子，于是

$$2^h \ge n! \quad \Longrightarrow \quad h \ge \lceil \log_2(n!) \rceil.$$

把它写成关于成本的形式，量词要贴着公式写：

$$\max_{x} C_A(x) \ge \lceil \log_2(n!) \rceil$$

对任意确定性的比较排序 $A$ 成立。$\max_x C_A(x)$ 是「最坏输入上的比较次数」，$\ge$ 说的是：**总存在某个输入**让这个算法做这么多次比较。

它不是说每个输入都需要这么多比较。已排序输入上插入排序只用 $n - 1$ 次比较，Timsort 会利用输入里已有的有序片段——这些都与下界不矛盾：下界约束的是最坏输入，不约束每一次运行。

```python run id="alg.ordering.decision-tree-height"
from math import factorial, log2


def smallest_height(n):
    """Smallest h with 2**h >= n!: a binary decision tree of height h has at most 2**h leaves."""
    leaves = factorial(n)
    return (leaves - 1).bit_length()


print(f"{'n':>5} {'ceil(log2(n!))':>15} {'n log2 n':>10} {'ratio':>7}")
for n in (2, 4, 8, 16, 32, 64, 4096):
    height = smallest_height(n)
    print(f"{n:>5} {height:>15} {n * log2(n):>10.1f} {height / (n * log2(n)):>7.3f}")

for n in range(2, 200):
    assert 2 ** (smallest_height(n) - 1) < factorial(n) <= 2 ** smallest_height(n), n

print()
print("n = 4 by hand: 4! = 24, and a decision tree of height 4 has at most 2**4 = 16 leaves.")
print("  2**4 =", 2 ** 4, "< 24 <= 2**5 =", 2 ** 5, "so the height is at least",
      smallest_height(4), ".")
```

## 不靠 Stirling 的 Ω(n log n)

$\lceil \log_2(n!) \rceil$ 这个表达式已经可以计算，但为了看出它的量级，需要一个不依赖 Stirling 公式的界。把 $n!$ 写成 $n$ 个因子的乘积，只看后半部分：

```text
n! 的最后 ceil(n/2) 个因子，每个都不小于 n/2
因此 n! >= (n/2)^(n/2)
取以 2 为底的对数：(1/2) * n * (log2 n - 1) <= log2(n!)
```

所以

$$\log_2(n!) \ge \frac{n}{2}\left(\log_2 n - 1\right) = \Omega(n \log n).$$

这条推导只用整数因子计数，没有用 Stirling 公式，也不需要知道 $\log_2(n!)$ 的精确值。Stirling 在这里只作为补充：它给出

$$\log_2(n!) = n \log_2 n - \Theta(n),$$

即主项之外还有一个线性的修正（约 $1.44\,n$ 的负项），这个更精确的表达式在解释实测比值为什么低于 1 时有用，但它不是本节证明的依赖。

## 随机化不改变下界

决策树的论证针对的是一个给定的确定性算法。随机化算法（例如 <CrossRef id="algorithms.comparison-sorting" /> 里的随机 pivot 快速排序）每次运行会掷不同的随机数，那它是不是绕过了下界？

先要补上一个事实：叶数下界只说明「树高至少是 $\lceil \log_2(n!) \rceil$」，也就是某个输入很深；它并不能直接推出「在均匀随机的输入上平均也要这么多次比较」。平均深度的下界要用 Kraft 不等式单独证明。设 $N = n!$。对这 $N$ 种严格全序中的每一种，确定性比较算法都会沿唯一一条路径到达一个可达叶；两个不同的全序不能共享同一个正确叶子，所以这 $N$ 个输入对应 $N$ 个不同的可达叶。记它们的深度为 $d_1, \dots, d_N$。这些叶子只是二叉决策树叶集合的一个子集，因此同样满足 Kraft 不等式

$$\sum_{i=1}^{N} 2^{-d_i} \le 1.$$

对它用算术几何平均（AM-GM）：

$$2^{-\frac{1}{N}\sum_i d_i} = \left(\prod_i 2^{-d_i}\right)^{1/N} \le \frac{1}{N} \sum_i 2^{-d_i} \le \frac{1}{N}.$$

两边取 $-\log_2$，得到本节的第二个下界：

$$\frac{1}{N} \sum_{i=1}^{N} d_i \ge \log_2 N = \log_2(n!).$$

**任何正确决策树的平均叶深也至少是 $\log_2(n!)$。** 有了这一步，随机化算法就好处理了：把一个每次运行都正确并终止的随机比较排序固定住它的随机比特，就得到一棵正确的确定性决策树；上面刚证明每棵这样的树在均匀随机排列上的平均成本至少是 $\log_2(n!)$。再对所有随机比特取平均：

$$\mathbb{E}_{\pi}\, \mathbb{E}_{R}\left[C(\pi, R)\right] \ge \log_2(n!).$$

一个平均值不小于 $\log_2(n!)$，说明至少有一个输入达到或超过它：

$$\text{存在输入 } \pi\text{，使 } \mathbb{E}_{R}\left[C(\pi, R)\right] \ge \log_2(n!).$$

这就是随机化版本的量词：**对任何永远正确的随机比较排序，都存在某个输入，使它对内部随机性的期望比较次数为 $\Omega(n \log n)$。**

这个下界本身只给出一个存在性结论：至少有一个输入 $\pi$ 满足 $\mathbb{E}_{R}[C(\pi, R)] = \Omega(n \log n)$。它并不排斥某个具体的随机算法对每一个固定输入都有 $O(n \log n)$ 的期望上界。事实上，<CrossRef id="algorithms.comparison-sorting" /> 里的随机 pivot 快速排序，在键两两不同、每轮独立均匀选择 pivot 的模型下，对任意固定输入都有期望 $\Theta(n \log n)$ 的比较次数。它没有的是「每一次随机运行都在 $O(n \log n)$ 内结束」的确定性保证：极少数随机选择序列仍可能造成 $\Theta(n^2)$ 的运行。

这里只讨论「每次运行都正确」的情形。如果算法允许以正概率输出错误答案（Monte Carlo 一类），需要另一套论证，本节不涉及。

```python run id="alg.ordering.decision-tree-witness"
from itertools import permutations
from math import factorial, log2


def build_decision_tree(orders):
    """Greedy comparison tree over a set of distinct full orders; leaves are single orders."""
    if len(orders) == 1:
        return ("leaf", orders[0], 1)
    n = len(orders[0])
    best = None
    for i in range(n):
        for j in range(i + 1, n):
            left, right = [], []
            for order in orders:
                (left if order[i] < order[j] else right).append(order)
            if not left or not right:
                continue
            balance = max(len(left), len(right))
            if best is None or balance < best[0]:
                best = (balance, i, j, left, right)
    assert best is not None
    _, i, j, left, right = best
    left_tree = build_decision_tree(left)
    right_tree = build_decision_tree(right)
    return ("node", i, j, left_tree, right_tree)


def leaves(tree, depth=0):
    if tree[0] == "leaf":
        return [depth]
    return leaves(tree[3], depth + 1) + leaves(tree[4], depth + 1)


for n in (3, 4):
    orders = list(permutations(range(n)))
    tree = build_decision_tree(orders)
    depths = leaves(tree)
    kraft = sum(2.0 ** -d for d in depths)
    average = sum(depths) / len(depths)
    bound = log2(factorial(n))
    print(f"n = {n}: leaves {len(depths)} | heights seen {sorted(set(depths))} "
          f"| height {max(depths)} | Kraft sum {kraft:.4f} (<= 1: {kraft <= 1 + 1e-12})")
    print(f"  average leaf depth {average:.4f} | log2(n!) = {bound:.4f} "
          f"| average >= log2(n!): {average >= bound - 1e-12}")
```

## 下界只约束比较次数

$\Omega(n \log n)$ 是关于**比较次数**的下界。决策树只数比较，一次比较之后跟着多少次元素移动、占多少额外空间、输出是否稳定，它都没有记录。所以这条下界不推出：

- **写入门槛**：找最小值可以只读不写，也可以每发现一个更小的元素就把它交换到最前面；两者的比较次数都是 $n - 1$，写入次数一个是 0、一个最多 $n - 1$。
- **辅助空间**：比较次数与空间是两条独立的成本轴。本课程这份归并排序的比较工作是 $\Theta(n \log n)$，并使用 $\Theta(n)$ 缓冲；<CrossRef id="algorithms.comparison-sorting" /> 里的堆排序具有 $\Theta(n \log n)$ 的最坏比较成本，却只使用 $O(1)$ 辅助空间。比较下界本身推不出空间下界。
- **稳定性**：稳定性是输出契约的一部分（见 <CrossRef id="algorithms.sorting" />），与比较次数之间没有推出关系。归并排序的实现稳定，<CrossRef id="algorithms.comparison-sorting" /> 里的原地堆排序实现不稳定；这一差异不是由 $\Omega(n \log n)$ 比较下界决定的。

模型也有边界。如果键带有比较之外可利用的结构，例如键取自一个已知的有限整数域，算法可以检查数字的位或桶编号，而不只是问「谁更小」。计数排序与基数排序就属于这一类，它们不在本节这棵二元比较决策树里，因此不构成反例。它们的实际成本取决于值域大小、字长与基数，本节不把它们展开成一组算法对照。

## 小结

- 下界是关于模型的结论：本节限制在「键两两不同、只能通过两两比较获知次序」的比较模型里。
- 找最小值至少 $n - 1$ 次比较（一次比较至多排除一个候选者），线性扫描达到这个数，所以最小值这个 $r = 0$ 的选择特例是 $\Theta(n)$；任意秩选择的线性下界本节不证明。
- 决策树的每个内部节点是一次比较，每个叶子至多对应一种相对次序，所以正确算法至少有 $n!$ 个叶子，高度至少 $\lceil \log_2(n!) \rceil$。
- 量词是「总存在某个输入」，不是「每个输入」；插入排序与 Timsort 的自适应行为与之不矛盾。
- 由 $n! \ge (n/2)^{n/2}$ 得到 $\log_2(n!) = \Omega(n \log n)$，不需要 Stirling 公式。
- 用 Kraft 不等式与 AM-GM 得到「任何正确决策树的平均叶深也至少是 $\log_2(n!)$」，由此推出随机比较排序也存在输入使期望比较次数为 $\Omega(n \log n)$。
- 这条下界只约束比较次数，不影响写入次数、辅助空间与稳定性；非比较排序利用了模型之外的信息，不构成反例。
