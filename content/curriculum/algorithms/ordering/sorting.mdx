<CrossRef id="algorithms.binary-search" /> 要求输入已经有序。拿到一组无序记录时，我们先要制造这份顺序；但「排好」并不是排序的完整契约：元素不能丢失或重复，若相等键的原顺序有意义，还要决定是否保持稳定。

## 契约

**前置条件**：`key(x)` 的结果属于一个全序域；排序算法只根据这些键决定记录之间的先后。本节用记录表示被排序的元素，用 `key` 表示参与排序比较的字段。

| 后置条件 | 内容 |
| --- | --- |
| 有序 | 输出按非降序排列 |
| 是排列 | 输出的多重集与输入相同：每个值出现的次数不变 |

「是排列」这一条不免费。只在比较与交换上做动作的实现天然满足它；一旦实现里出现就地覆盖、按索引写回、丢弃某个分支这类操作，就必须单独论证没有元素被覆盖或遗漏。被排序的是记录本身，键只是其中一个字段，因此「输出是排列」要连记录一起保持。

**稳定性**是基本排序契约之外的一条可选后置条件：键相等的元素在输出中保持输入里的相对次序。未承诺<Term id="stable-sort">稳定性</Term>时，任意等键次序都仍满足「有序＋是排列」这两条基本后置条件；一旦接口承诺稳定性，破坏等键记录的相对次序就是契约错误。

## 三种互相独立的成本

排序的成本不能只用一个数字概括，至少要分开三个量：

- **比较次数**：调用元素比较的次数。当比较本身很贵（长字符串、复杂结构）时它是主导项。另一个规模参数是比较键本身的成本。
- **元素写入次数**：把元素写进数组槽位的次数。一次普通数组赋值计一次写入；一次交换按两个数组槽位被写入，计两次写入。局部变量赋值不计入这个量。
- **辅助空间**：除输出之外额外占用的槽位。

三者是彼此不能互相推出的成本维度。这份插入排序在已排序输入上做 $n-1$ 次比较和 $n-1$ 次数组写入；这份选择排序每轮都执行交换，因此固定执行 $n-1$ 次交换，即按本节口径计 $2(n-1)$ 次数组写入；归并排序的比较次数是 $\Theta(n \log n)$ 量级，常见的数组实现可以复用一块 $\Theta(n)$ 的工作缓冲。这里的 $\Theta(n)$ 缓冲是这种常规实现的空间选择；原地合并的变体只额外占用 $O(\log n)$ 的递归栈，$\Theta(n)$ 的辅助空间属于这种数组写法，不是归并排序必须付的下界。

成本类别上，插入排序最好 $\Theta(n)$（已排序输入），最坏 $\Theta(n^2)$（键两两不等且严格递减）；这份归并排序的最好情形和最坏情形在渐进阶上都是 $\Theta(n \log n)$。输入顺序会改变具体的比较次数，但不会把它从这一渐进阶降到 $\Theta(n)$ 或推高到 $\Theta(n^2)$。两者的差别落在最坏情形的增长阶：插入排序会退化到 $\Theta(n^2)$，归并排序保持 $\Theta(n \log n)$。

需要前 $k$ 个或第 $k$ 个元素时，不必为全部元素排出顺序；这类需求见 <CrossRef id="algorithms.selection-and-top-k" />；「任何基于比较的排序都需要 $\Omega(n \log n)$ 次比较」这一结论需要比较模型的形式化，见 <CrossRef id="algorithms.lower-bounds" />。

## 插入排序：用前缀不变量论证

插入排序维持一条不变量：

`items[0 .. i)` 已经按非降序排列，并且是原输入前 $i$ 个元素的一个排列。

初始时 $i = 1$，前缀只有原输入的第一个元素，因此不变量成立。第 $i$ 轮先把新加入的元素 `items[i]` 保存为 `current`。内层循环只把键严格大于 `current` 的元素向右移动；循环停止时要么 `position == -1`，要么当前位置的键不大于 `current`。因此把 `current` 写入 `position + 1` 后，新的前缀仍然非降序。整个过程只移动已有记录，并最终把暂存的 `current` 写回，所以前 $i+1$ 个位置仍然恰好包含原输入前 $i+1$ 个记录。内层循环每继续一次都令 `position` 减 1，而它的下界是 $-1$，所以必然终止；外层 `for` 只取有限个索引，也必然终止。最后 $i$ 覆盖整个输入，于是全部 $n$ 个元素有序，并且仍是原输入的一个排列。

```python run id="alg.ordering.insertion-sort"
def insertion_sort(items, key, counters):
    """Postcondition: items is non-decreasing by key, and a permutation of the input."""
    for index in range(1, len(items)):
        current = items[index]
        position = index - 1
        while position >= 0:
            counters["comparisons"] += 1
            if not key(items[position]) > key(current):
                break
            items[position + 1] = items[position]
            counters["writes"] += 1
            position -= 1
        items[position + 1] = current
        counters["writes"] += 1


key_of = lambda record: record[0]
records = list(enumerate("abcdefgh"))
cases = {
    "already sorted": list(records),
    "all keys equal": [(0, label) for _, label in records],
    "strictly reversed": list(reversed(records)),
}
for name, case in cases.items():
    counters = {"comparisons": 0, "writes": 0}
    insertion_sort(case, key=key_of, counters=counters)
    print(f"{name:>17} comparisons={counters['comparisons']:>2} "
          f"writes={counters['writes']:>2} {case}")
```

三行给出同一份契约在三种输入上的代价。已排序输入每一轮只与左侧相邻的那条记录比较一次就停下，做 $n-1 = 7$ 次比较和 7 次数组写入。键全部相等时同样是 7 次比较：内层循环在第一个等键记录处停下，不越过它。键两两不等且严格递减时，每一对元素都形成一次严格逆序，比较次数达到 $n(n-1)/2 = 28$，数组写入是 28 次右移再加每轮写回一次 `current` 的 7 次，共 35 次。严格递减这一行是插入排序的最坏情形，比较次数按 $n(n-1)/2$ 二次增长。三行的输出都是非降序，也都含输入的每一条记录，契约的两层后置条件同时成立；比较次数与写入次数是两个独立的量，在已排序输入上都是 7，在严格递减输入上一个是 28、另一个是 35。

## 归并排序：用递归式论证

归并排序把问题对半分，递归排好两半，再合并两个有序序列。合并用两个游标向前走：每次比较两侧当前元素，取较小者写入缓冲；某一侧用完之后把另一侧余下的部分直接接上。合并一次恰好把 $n$ 个元素写进缓冲一次，所以是 $\Theta(n)$。

当 $n$ 是 2 的幂时可以直接写成 $T(n) = 2T(n/2) + \Theta(n)$；对一般的 $n$，更精确地写是 $T(n) = T(\lfloor n/2 \rfloor) + T(\lceil n/2 \rceil) + \Theta(n)$。两者都解为 $\Theta(n \log n)$（见 <CrossRef id="algorithms.cost-model" />）：递归树有 $\Theta(\log n)$ 层，每层所有合并合计处理 $\Theta(n)$ 个元素。

稳定的实现只有一个细节：合并时两侧键相等就取左侧，这样相等键不会因为合并而换位。

```python run id="alg.ordering.merge-sort"
from random import Random


def merge_sort(records, key, counters):
    """Postcondition: non-decreasing by key, stable, and a permutation of the input."""
    if len(records) <= 1:
        return list(records)
    middle = len(records) // 2
    left = merge_sort(records[:middle], key, counters)
    right = merge_sort(records[middle:], key, counters)
    merged = []
    i = 0
    j = 0
    while i < len(left) and j < len(right):
        counters["comparisons"] += 1
        if key(left[i]) <= key(right[j]):
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged


print(f"{'n':>6} {'comparisons':>12} {'n log2 n':>9} {'ratio':>6}")
for size in (8, 64):
    records = [(index % 4, index) for index in range(size)]
    Random(20261003).shuffle(records)
    counters = {"comparisons": 0}
    merge_sort(records, key=lambda record: record[0], counters=counters)
    reference = size * (size.bit_length() - 1)
    print(f"{size:>6} {counters['comparisons']:>12} {reference:>9} "
          f"{counters['comparisons'] / reference:>6.2f}")

tiny = [(1, "a"), (0, "x"), (1, "b")]
print("equal keys keep their order:", merge_sort(tiny, key=lambda record: record[0], counters={"comparisons": 0}))
```

两行的比较次数与 $n \log_2 n$ 的比值分别是 0.67 和 0.74，稳定在同一量级：规模扩大 8 倍时比较次数从 16 涨到 285，多出来的正是那个对数因子。`equal keys keep their order` 一行给出稳定性的证据：输入里 `a` 在 `b` 前面，两条记录键都为 1，输出仍是 `a` 在前——合并分支在两侧键相等时取左侧。合并每次都要一块能放下当层的缓冲，顶层 `merged` 的长度达到 $n$；常见的数组归并排序显式复用一个长度 $n$ 的工作缓冲再加 $O(\log n)$ 的递归栈，辅助空间是 $\Theta(n)$，这是它比插入排序多付的那一项。

## 稳定与原地是两条独立的轴

这两个属性经常被一起提到，但它们互不蕴含。同一个三元素输入交给两种都只用常数个额外槽位的排序过程，得到两个次序不同的输出：

```python run id="alg.ordering.stability-and-in-place"
key_of = lambda record: record[0]


def selection_sort(records):
    for start in range(len(records) - 1):
        low = min(range(start, len(records)), key=lambda index: key_of(records[index]))
        records[start], records[low] = records[low], records[start]
    return records


def insertion_sort(records):
    for index in range(1, len(records)):
        current = records[index]
        position = index
        while position and key_of(records[position - 1]) > key_of(current):
            records[position] = records[position - 1]
            position -= 1
        records[position] = current
    return records


tiny = [(1, "a"), (1, "b"), (0, "c")]
print("selection:", selection_sort(list(tiny)))
print("insertion:", insertion_sort(list(tiny)))
```

选择排序把最小的 $(0, "c")$ 换到开头时，顺带把两个键为 1 的记录换成了 `b` 在前；插入排序的输出里 `a` 仍在 `b` 前面。两者都只暂存常数条记录，输出都满足「非降序 + 是排列」，稳定性却不同。

| 实现 | 稳定 | 原地 | 决定它的结构 |
| --- | --- | --- | --- |
| 插入排序 | 是 | 是 | 只把键严格大于 `current` 的记录右移，等键记录不会被越过 |
| 选择排序 | 否 | 是 | 取最小值时可能跨过等键记录，一次交换打乱一段相等区 |
| 归并排序 | 是 | 否 | 合并时相等取左，代价是一块随 $n$ 增长的缓冲 |

前两行给出「原地」不蕴含「稳定」，归并排序的一行给出「稳定」不蕴含「原地」，四格中有三格已经出现。要判断一个实现落在哪一格，只需问两件事：键相等时它是否可能跨过对方，以及它额外占用的槽位是否随 $n$ 增长。插入排序与选择排序只暂存常数条记录，归并排序的缓冲随 $n$ 增长。

Python 的 `sorted()` 与 `list.sort()` 保证稳定；官方文档把 Python 的排序算法描述为 Timsort，并明确指出它会利用输入中已经存在的顺序：完全有序的输入可以在线性级的比较工作内处理，含有较长已有有序片段的数据通常也能少做很多工作；但「局部有序」本身并不足以保证比较次数接近线性。`list.sort()` 原地修改列表并返回 `None`，`sorted()` 构造一个新的已排序列表。`key=` 决定用于比较的键，而且内置排序对每个输入记录只计算一次键；`reverse=` 改变排序方向，但仍保持稳定性，因此可以先按次要字段排序、再稳定地按主要字段排序。排序过程使用 `<` 建立先后关系：没有 `key=` 时比较元素本身，有 `key=` 时实际参与排序比较的是键值；因此直接排序自定义类型时可以通过一致的 `__lt__` 提供排序关系，而提供 `key=` 时记录本身甚至不必可比较。
