同一批数据上，「第 $k$ 个元素」「前 $k$ 个元素」「全部有序」各自要求把结果里不同数量的元素固定下来。这一节问：为每一种需求，算法至少要保存什么，成本因此落在哪条表达式上。可以原地修改的随机访问数组与只能单遍读取的流是两种访问条件，同一种需求在两者上的实现与成本分别给出。

## 第 k 个元素：一次分区，只递归一侧

秩 $r$ 的顺序统计量（order statistic）是完整排序后位于下标 $r$ 的那个元素，契约要求 $0 \le r < n$，其余元素不要求有序。找到它只需确定落在位置 $r$ 的元素，任何其他元素的最终位置都不必知道。

quickselect 复用 <CrossRef id="algorithms.comparison-sorting" /> 的分区：一次分区把区间按 pivot 分成两段，并让 pivot 落在它的最终位置 $p$。目标秩小于 $p$ 时答案只可能在左段，大于 $p$ 时只可能在右段，相等就直接返回。无论走哪一边，另一侧连同 pivot 一起被排除，此后不再参与任何比较。

它维持的循环不变量是：目标秩始终位于当前区间 $[low, high]$ 内，已经排除在左侧的元素都不大于候选区间里的元素，已经排除在右侧的元素都不小于候选区间里的元素。第一条保证目标还在区间里，后两条保证被丢掉的部分里没有更小的候选：

```python run id="alg.ordering.quickselect"
from random import Random


def partition(items, low, high):
    """Postcondition: returns the pivot index p with items[low..p) < pivot <= items[p..high]."""
    pivot, boundary = items[high], low
    for j in range(low, high):
        if items[j] < pivot:
            items[boundary], items[j] = items[j], items[boundary]
            boundary += 1
    items[boundary], items[high] = items[high], items[boundary]
    return boundary


def quickselect(items, low, high, rank, rng):
    """Postcondition: returns the element that would sit at index rank after sorting."""
    if low == high:
        return items[low]
    index = rng.randrange(low, high + 1)
    items[index], items[high] = items[high], items[index]
    position = partition(items, low, high)
    if position == rank:
        return items[position]
    if rank < position:
        print(f"pivot at {position}: recurse into the left, {high - position + 1} elements excluded")
        return quickselect(items, low, position - 1, rank, rng)
    print(f"pivot at {position}: recurse into the right, {position - low + 1} elements excluded")
    return quickselect(items, position + 1, high, rank, rng)


size = 4096
case = list(range(size))
Random(20261040).shuffle(case)
rank = 16
value = quickselect(case, 0, size - 1, rank, Random(20261040))
print("rank", rank, "->", value, "| matches a full sort:", value == sorted(case)[rank])
```

这一次运行在 $n = 4096$、目标秩 $r = 16$ 上做了 9 次分区。第一次分区的 pivot 落在下标 2103，右侧 1993 个元素连同 pivot 一起被排除；之后八轮被排除的规模依次是 1824、206、2、44、16、4、5、1。九次分区排除的总数是 4095，等于 $n - 1$：留在区间里的那一个元素就是答案，打印出的值与完整排序的第 16 个元素一致。

随机 pivot 的秩在当前区间里均匀分布，因此它落在中间一半（约从 $m/4$ 到 $3m/4$）的概率不低于 $1/2$；只要落在这里，这一轮之后保留的区间长度就至多原来的 $3/4$。设当前区间长度为 $m$，等到一次这样的成功所需的轮数期望不超过 2，等待中每一轮的成本不超过 $m$ 次比较，把区间从 $m$ 收到至多 $3m/4$ 的期望成本是 $O(m)$。总期望成本因此是一个公比为 $3/4$ 的几何级数：

$$
O\left(m + \frac{3}{4} m + \left(\frac{3}{4}\right)^2 m + \cdots\right) = O(m).
$$

这条论证对任意固定秩都成立：要最小、中位数还是第 $n - 1$ 个，期望成本都是 $O(n)$。它依赖键两两不同的假设；二路 `<` / `>=` 分区在大量重复键上会退化，随机 pivot 也避免不了。最坏情形仍是 $\Theta(n^2)$：固定取末元素作 pivot 时，已排序输入每次都把 pivot 放在端点，区间每轮只缩小一个元素；随机化把这种输入变成低概率事件，单次运行的上界不变。

本节实现沿目标秩所在的一侧递归：额外空间随递归深度增长，随机 pivot、键两两不同的模型下期望深度为 $O(\log n)$，单次运行最坏仍可能达到 $O(n)$。

## 前 k 个元素：一个有界堆

「取前 $k$ 个」最弱的契约只要求恰好 $k$ 个最小元素、保留重复元素，这 $k$ 个之间的次序不作要求；要求它们按非降序排列是更强的契约，比前者多出的工作只是对这 $k$ 个元素排序。

输入只能单遍读取、也不该整份保留时，用一个最大堆装当前见过的 $k$ 个最小元素，堆顶是缓冲里的最大值。新元素先与堆顶比较一次：更小就替换堆顶，否则直接丢弃。缓冲大小因此始终不超过 $k$，堆顶是当前已见元素里第 $k$ 小的门槛值。

```python run id="alg.ordering.streaming-top-k"
import heapq


def keys(count, seed):
    """The same deterministic key stream on every run, produced one value at a time."""
    state = seed
    for _ in range(count):
        state = (1103515245 * state + 12345) % 2147483648
        yield state % 100000


def stream_top_k(stream, k):
    """Postcondition: one pass, returns the k smallest values in order; the heap never exceeds k."""
    heap = []                                    # max-heap of negatives, size <= k
    for seen, value in enumerate(stream, start=1):
        if len(heap) < k:
            heapq.heappush(heap, -value)
        elif value < -heap[0]:
            heapq.heapreplace(heap, -value)
        if seen % 10000 == 0:
            print(f"after {seen} values: heap size {len(heap)} of k = {k}, top {-heap[0]}")
    return sorted(-value for value in heap)


count, k = 50000, 8
result = stream_top_k(keys(count, 20261040), k)
print("k smallest:", result)
print("matches a full sort of the same stream:", result == sorted(keys(count, 20261040))[:k])
```

五万条键的流只被遍历一次：每个检查点上堆的大小都是 8，等于 $k$；堆顶依次是 88、38、30、21、18，它是当前已见元素里第 $k$ 小的门槛值，缓冲大小由 $k$ 决定、与 $n$ 无关。取出的八个值 $2, 3, 4, 9, 10, 14, 14, 18$ 与整条流排序后的前 8 个一致。

前 $k$ 个元素用于建立缓冲，每个花 $O(\log(k + 1))$；此后每个元素做一次常数时间的门槛比较，通过门槛的才触发一次 $O(\log(k + 1))$ 的堆替换。若替换发生 $r$ 次，总时间是 $O(k \log(k + 1) + (n - k) + r \log(k + 1))$，最坏 $O(n \log(k + 1))$，空间恒为 $\Theta(k)$。要按非降序给出这 $k$ 个元素，再对缓冲排一次序，附加 $O(k \log k)$。

Python 的 `heapq.nsmallest()` 与 `heapq.nlargest()` 返回已排序的前 $k$ 个结果；[Sorting HOWTO](https://docs.python.org/3/howto/sorting.html) 把它们描述为单遍处理输入、同时只保留所需数量元素的部分排序工具。当前 CPython 实现通常维护一个大小受 $k$ 限制的堆，并在 $k$ 不小于输入长度时退回完整排序；这些属于具体实现的策略，`heapq` API 不承诺它们。

## 三种需求与完整排序的成本

四种需求在成本上的差别来自各自必须保存下来的结果有多大，把「要保存什么」写清楚，成本就跟着出来：

- **保存一个值**（第 $k$ 个元素）：只有目标秩最终落在哪个位置需要确定，其余 $n - 1$ 个元素不产生输出。每轮分区把候选区间按常数比例期望缩小，总成本期望 $O(n)$。
- **保存 $k$ 个值，不管次序**（无序 Top-K）：每个元素与「当前第 $k$ 小」的门槛值比较一次，通过门槛的才做一次 $O(\log k)$ 的缓冲更新，$n$ 个元素合起来 $O(n \log k)$。
- **保存 $k$ 个有序的值**（已排序 Top-K）：先得到那 $k$ 个值（$O(n \log k)$），再对这 $k$ 个排一次序（$O(k \log k)$），合计 $O(n \log k + k \log k)$。
- **保存 $n$ 个有序的值**（完整排序，见 <CrossRef id="algorithms.sorting" />）：所有元素都要进入输出顺序。基于比较的排序对每一条输入都至少要做 $\Omega(n \log n)$ 次比较（<CrossRef id="algorithms.lower-bounds" />），归并与堆排序以 $\Theta(n \log n)$ 达到这个阶。

| 需求 | 需要保存的结果 | 典型成本 |
| --- | --- | --- |
| 第 $k$ 个元素 | 一个值 | 期望 $O(n)$ |
| 无序 Top-K | $k$ 个值 | $O(n \log k)$ |
| 已排序 Top-K | $k$ 个有序值 | $O(n \log k + k \log k)$ |
| 完整排序 | $n$ 个有序值 | $O(n \log n)$ |

把 $\log k$ 写成 $\log(k + 1)$ 让 $k = 1$ 也严格成立；$k \ge 2$ 时通常简写成 $O(n \log k)$。$k = n$ 时已排序 Top-K 就是完整排序，$1 \le k < n$ 时它要求的信息比完整排序少。

表里的表达式只在 $n$ 与 $k$ 两个参数上变化。下面这个单元格把它们相对「找第 $k$ 个元素」的比值打印成一张表，比值以一趟线性扫描为单位：无序 Top-K 的比值是 $\log_2 k$，已排序 Top-K 的比值是 $\log_2 k (1 + k/n)$，完整排序的比值是 $\log_2 n$。

```python run id="alg.ordering.three-contracts"
from math import log2

print("cost in units of one pass over the input, so the k-th element is the baseline 1 n")
print(f"{'n':>10} {'k':>8} {'top-k / k-th':>14} {'sorted top-k / k-th':>21} {'full sort / k-th':>18}")
for n, k in ((2**20, 2**3), (2**20, 2**10), (2**20, 2**17), (2**16, 2**3), (2**24, 2**3)):
    print(f"{n:>10} {k:>8} {log2(k):>14.1f} {log2(k) + k * log2(k) / n:>21.1f} {log2(n):>18.1f}")
```

表里可以读出三件事：无序 Top-K 相对第 $k$ 个元素的倍数是 $\log_2 k$，只随 $k$ 变（$k = 8$ 时 3.0，$k = 1024$ 时 10.0，$k = 131072$ 时 17.0）；完整排序的倍数是 $\log_2 n$，只随 $n$ 变（$n = 2^{16}$ 时 16.0，$n = 2^{20}$ 时 20.0，$n = 2^{24}$ 时 24.0）；已排序 Top-K 的倍数在 $k$ 小时与无序 Top-K 几乎相同，在 $k$ 接近 $n$ 时被 $k \log_2 k$ 抬到接近完整排序（$k = 2^{17}$ 时 19.1，同一行完整排序为 20.0）。

本节证明的是上界：在只要求部分顺序时，可以构造比完整排序更便宜的算法。至于哪些成本是任何算法都无法突破的，需要先形式化比较模型与决策树；完整排序的 $\Omega(n \log n)$ 比较下界与「找最小至少 $n - 1$ 次比较」都在 <CrossRef id="algorithms.lower-bounds" /> 中证明。
