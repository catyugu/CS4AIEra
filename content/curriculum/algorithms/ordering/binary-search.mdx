你已经知道二分查找怎么走：在有序序列上取中点，把候选区间砍掉一半，对数轮之后锁定一个位置。它的两种典型失败都很具体，值得先看清楚。

一种失败发生在序列并没有排序的时候。「中点左边的元素都比中点小」这步推理失效，程序不会报错，它会照常收缩区间并返回一个位置；键确实在序列里，也可能被判成「不存在」。正确性论证的每一步都依赖输入有键序。

另一种失败发生在区间的开闭写混的时候。把「中点已经满足条件」当成「答案在中点左边」，于是那一支写成 `hi = mid - 1`，程序会跳过第一个满足条件的位置本身，返回一个偏小的下标。

这两种失败指向同一条前提：**输入已经有序（非降序，允许重复元素）**。二分查找把它当作调用方保证的条件，不在运行中检查。

二分查找定位的是一段边界的位置。键越大，这段边界的下标越靠后，键与位置之间的这条单调对应正是每轮能砍掉一半的原因。给定有序序列与键 `key`，`lower_bound` 问「第一个满足 `items[i] >= key` 的下标」，`upper_bound` 问「第一个满足 `items[i] > key` 的下标」。精确查找——键在不在——建在 `lower_bound` 之上，先定位再比较，不必另写一套散布的相等判断。

## 边界定位与精确查找

**前置条件**：序列 `items` 按非降序排列（重复元素允许）。

| 操作 | 后置条件 |
| --- | --- |
| lower_bound | 返回第一个满足 `items[i] >= key` 的下标；不存在则返回 `len(items)` |
| upper_bound | 返回第一个满足 `items[i] > key` 的下标；不存在则返回 `len(items)` |
| 精确查找 | 若键存在，返回第一个等于 `key` 的位置；不存在则返回缺失标志 |

前置条件是一项契约设计的选择：它划定调用方允许传入的形状，让后置条件的证明得以进行。它不声称越出契约的行为在客观上无从定义，只是把这些行为排除在承诺之外，交给调用方承担。调用方违反它时，代码返回什么、是否抛异常，都是具体实现的行为——Python 的 `a[-1]` 合法地取到末元素，`list.insert(99, x)` 把下标截断到末尾——契约不为这些行为背书，也不能用它们反过来解释前置条件。这份契约描述的是操作之间的约定，不描述 Python `list` 在任何下标下的语言级行为。

精确查找可以建在 lower_bound 之上：先定位，再比较该位置的键是否等于目标。这样就避开了「找到就返回、否则缩小区间」里散布的相等判断，也把重复元素的情形统一处理掉；比边界定位多出的只是至多一次相等性检查，量级不变。在动态序列上维护这份键序是另一组操作的代价，见 <CrossRef id="algorithms.ordered-maps" />。

下面所有计数都在一个成本模型下进行：一次按键比较记 1，一次随机访问记常数成本。长字符串或复杂键要把比较成本与比较次数分开计；序列本身也要支持常数时间的按下标取值。

## 循环不变量与终止

二分查找容易写错的地方都集中在区间的开闭上。用**半开区间** $[lo, hi)$ 表述可以消除大部分歧义，此时两条不变量是：

1. `items[0 .. lo)` 里的键都 `< key`
2. `items[hi .. n)` 里的键都 `>= key`

初始时 $lo = 0$、$hi = n$，两条都空成立。每轮取中点 $mid = lo + (hi - lo) // 2$，比较 `items[mid]` 与 `key`：

- 若 `items[mid] < key`，由有序性可知下标不超过 $mid$ 的元素都小于 `key`，这些位置都不可能是 lower_bound，于是 $lo = mid + 1$；
- 否则 `items[mid] >= key`，答案不会位于 $mid$ 的右侧，但 $mid$ 本身仍可能就是第一个满足位置，于是 $hi = mid$。

循环在 $lo = hi$ 时结束，此时 $[lo, hi)$ 已经是空区间，两条不变量说明 $[0, lo)$ 全部小于 `key`、$[lo, n)$ 全部不小于 `key`。这个公共边界 $lo$ 正是第一个满足条件的位置；若所有元素都小于 `key`，它就是 $n$。

**每轮至少减半**：设当前候选区间长度 $L = hi - lo > 0$，取 $mid = lo + \lfloor L/2 \rfloor$。若进入 $hi = mid$ 分支，新长度是 $\lfloor L/2 \rfloor$；若进入 $lo = mid + 1$ 分支，新长度是 $L - \lfloor L/2 \rfloor - 1 \le \lfloor L/2 \rfloor$。因而每轮之后都有 $L' \le \lfloor L/2 \rfloor$。从初始长度 $n$ 出发，经过 $t$ 轮有 $L_t \le \lfloor n / 2^t \rfloor$；对 $n \ge 1$，当 $2^t > n$ 时右边为 0，因此最坏迭代次数不超过 $\lfloor \log_2 n \rfloor + 1 = \lceil \log_2 (n+1) \rceil$。

空数组 $n = 0$ 不做任何比较。每轮恰好做一次 `items[mid] < key` 的顺序比较，所以这就是 lower_bound 的最坏顺序比较次数，并且由某些输入达到：$n = 64$ 时最坏取 $\lceil \log_2 (64+1) \rceil = 7$ 次，比 $\lfloor \log_2 64 \rfloor = 6$ 多一次。这些最坏情形界不需要期望或摊还假设，除序列有序之外没有别的前提。

```python run id="alg.ordering.lower-bound"
import math


def lower_bound(items, key, comparisons):
    """Postcondition: the first index i with items[i] >= key, or len(items)."""
    lo, hi = 0, len(items)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        comparisons.append(mid)
        if items[mid] < key:
            lo = mid + 1
        else:
            hi = mid
    return lo


size = 64
items = [2 * index for index in range(size)]
worst = 0
for key in (-1, 0, 62, 63, 200):
    comparisons = []
    position = lower_bound(items, key, comparisons)
    worst = max(worst, len(comparisons))
    print(f"key {key:>4}: lower_bound {position:>3} | comparisons {len(comparisons)}")
print("worst comparisons:", worst, "| ceil(log2(n+1)) =", math.ceil(math.log2(size + 1)))
```

五个探针键覆盖了小于全部元素、命中已有元素、落在相邻元素之间、大于全部元素四类边界情形，返回的下标依次是 0、0、31、32、64；最坏比较次数是 7，与 \lceil \log_2 (64+1) \rceil 一致。

空间上没有对应的优势：迭代写法只用常数个额外变量，写成递归则把区间长度的一半作为下一次的规模，占用 $\Theta(\log n)$ 栈空间。

## 重复元素与「不存在」

序列允许重复，lower_bound 与 upper_bound 一起给出**等值区间**：所有等于 `key` 的元素恰好占据下标 $[lb, ub)$，出现次数是 $ub - lb$。

```python run id="alg.ordering.equal-range"
def lower_bound(items, key):
    lo, hi = 0, len(items)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if items[mid] < key:
            lo = mid + 1
        else:
            hi = mid
    return lo


def upper_bound(items, key):
    lo, hi = 0, len(items)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if items[mid] <= key:
            lo = mid + 1
        else:
            hi = mid
    return lo


items = sorted(index % 5 for index in range(40))
for key in (-1, 0, 3, 4, 5):
    lo, hi = lower_bound(items, key), upper_bound(items, key)
    print(f"key {key:>2}: [{lo}, {hi})  count {hi - lo}")
```

$key = 3$ 出现 8 次，等值区间是 $[24, 32)$；不存在的键 $-1$ 与 $5$ 得到空区间，`hi - lo` 为 0，精确查找据此报告缺失。序列两端之外的键把两条边界收到同一端点：$-1$ 得到 $[0, 0)$，$5$ 得到 $[40, 40)$。这份契约只依赖「非降序」，不需要元素互不相同；等值区间由一次 lower_bound 加一次 upper_bound 得到，两次边界定位各是对数个比较，合起来仍是 $O(\log n)$。

## 单调谓词的边界定位

把 lower_bound 的比较方向抽象出来，它找的是**第一个使谓词成立的位置**：定义 $p(i)$ 为 `items[i] >= key`，则 $p$ 在序列上是单调的（前面全假、后面全真），lower_bound 返回第一个真值的位置。

这层抽象是二分查找适用范围的关键。设有限离散候选域按全序排列、谓词 $p$ 呈「前面全假、后面全真」的单调形态，并且我们能按下标或数值区间取中点，就可以定位第一个真值的位置；全部为假时，答案取候选域的右边界。典型问题是「求最小的整数 $x$ 使某个性质成立」：把可能的 $x$ 包在一个已知区间里，每轮在中点算一次判定函数。若一次判定的成本至多为 $T$、候选范围含 $m$ 个位置，二分部分的总成本是 $O(T \log m)$；若判定成本随 $x$ 变化，就要累加各轮的实际成本。搜索连续数值域时还必须另外指定精度或其他终止条件，不能指望有限次比较给出任意精度的实数边界。

## 常见的区间错误

同一份不变量写成不同的开闭形式都能得到正确的代码，把两种形式混用则会产生错误结果。常见的一处是把「$mid$ 已满足谓词」当成「越过答案」，写成 $hi = mid - 1$：这会跳过第一个满足位置本身。

```python run id="alg.ordering.interval-hazards"
def lower_bound(items, key):
    lo, hi = 0, len(items)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if items[mid] < key:
            lo = mid + 1
        else:
            hi = mid
    return lo


def overshooting(items, key):
    """Treats a satisfied predicate at mid as an overshoot."""
    lo, hi = 0, len(items)
    while lo < hi:
        mid = (lo + hi) // 2
        if items[mid] >= key:
            hi = mid - 1
        else:
            lo = mid + 1
    return lo


items = [2 * index for index in range(32)]
for key in (0, 1, 5, 8):
    correct = lower_bound(items, key)
    variant = overshooting(items, key)
    note = "" if variant == correct else "  <-- misses the boundary"
    print(f"key {key:>2}: lower_bound {correct}, hi = mid - 1 {variant}{note}")
```

在 $items = [0, 2, 4, \ldots, 62]$ 上，$key = 0$ 与 $8$ 时两种写法返回同一位置；$key = 1$ 时正确的边界是 1，$hi = mid - 1$ 的变体返回 0；$key = 5$ 时正确边界是 3，变体返回 2。偏差的来源固定：谓词在 $mid$ 成立时，答案可能就是 $mid$ 本身，把 $hi$ 置为 $mid - 1$ 越过它，返回的位置就不再是「第一个使 $items[i] \ge key$ 成立」的下标。

## 与 bisect 对照

Python 的 `bisect` 模块直接实现这类边界定位：`bisect_left` 给出左边界，`bisect_right` 给出右边界。它们定位的是插入位置，比较过程使用 `<` 而不需要调用 `==`，因此精确查找仍要在拿到位置后自行检查元素是否等于目标。`insort_left` / `insort_right` 先二分定位，再调用序列的插入操作；对 Python `list` 来说，$O(\log n)$ 的定位会被后续 $O(n)$ 的元素搬移支配。使用 `key=` 参数时，排序与搜索还必须保持同一套键序规则。需要按键序做区间遍历时，库不提供额外结构，`bisect` 给出的是下标区间，取值仍要自己按区间切片。

**实现边界**：`bisect_left` 返回最左插入位置，这是 [`bisect`](https://docs.python.org/3/library/bisect.html) 模块的公开契约，由标准库承诺，任一符合该文档的实现都给出同一结果；CPython 与本课浏览器里运行的 Pyodide 装载的是同一份标准库，同一输入上观测到的下标一致，差别只落在底层比较与元素搬移的耗时上。二分本身的比较次数由算法决定，不随实现版本变化。
