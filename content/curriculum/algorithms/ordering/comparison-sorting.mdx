三种排序满足 <CrossRef id="algorithms.sorting" /> 给出的同一套正确性条件：<CrossRef id="algorithms.mergesort" /> 把区间对半切开、分别排好再合并，<CrossRef id="algorithms.quicksort" /> 按一个 pivot 分成两段、其余交给递归，<CrossRef id="algorithms.heapsort" /> 不切分，把整个数组看成一个优先结构、反复取出当前最大值。三者决定子问题规模的方式不同，额外空间花的位置也不同，最坏成本、期望成本、辅助空间与稳定性因此各自独立。


## 三条路线的结构比较

| 算法 | 切分与代价 | 成本 | 稳定性 |
| --- | --- | --- | --- |
| 归并排序 | 切分固定平衡，代价在合并：每层线性合并 | 最坏 $\Theta(n \log n)$ | 稳定 |
| 快速排序 | 切分是线性的，但子问题规模由数据决定 | 期望 $\Theta(n \log n)$，最坏 $\Theta(n^2)$ | 不稳定 |
| 堆排序 | 不做切分，维护一个全局优先结构 | 最坏 $\Theta(n \log n)$，原地 | 不稳定 |

- **最坏界**：归并与堆排序对任何输入都保持 $\Theta(n \log n)$；快速排序的这一界依赖分区平衡，最坏会退化到 $\Theta(n^2)$。随机 pivot 的分析依赖「每轮独立均匀取 pivot」；一旦随机源被固定或被输入安排，退化情形重新可用。随机化改变的是「最坏情形是否容易被输入触发」，不改变单次运行的成本上界。
- **辅助空间**：递归快速排序在平衡分区时递归深度为 $O(\log n)$，但连续极端分区时深度会达到 $O(n)$，因此它的最坏辅助栈空间是 $O(n)$；随机 pivot 在「键两两不同」的模型下有期望 $O(\log n)$ 的递归深度，单次运行的最坏情形仍是 $O(n)$。常规归并实现使用 $\Theta(n)$ 工作缓冲；堆排序使用 $O(1)$ 辅助空间。
- **稳定性**：稳定与否取决于恢复结构时有没有远距离交换。分区交换会越过等键元素，堆的堆顶交换同样如此，所以这两份原地实现都不保证等键记录的相对次序；归并把两个有序段按顺序取用，不会越过。稳定性结论针对这两种原地实现；稳定的快速排序与堆排序变体同样存在。


这三条轴的取值互相独立，所以「哪种排序更好」必须先说清在哪个轴上看。常数因子由实现与输入共同决定，不在比较之列。

Python 的 `list.sort()` 与 `sorted()` 使用稳定的 Timsort；`list.sort()` 会原地修改列表，`sorted()` 构造新列表。这里的「原地修改 API 对象」不要与算法分析中的 $O(1)$ 辅助空间混为一谈：Timsort 可以使用随输入规模增长的临时存储。手写两节里的快速排序与堆排序，目的是显式观察分区不变量与堆的两条不变量；它们不构成替代内置排序的性能建议。至于完整比较排序为什么存在 $\Omega(n \log n)$ 的比较下界，需要先建立比较模型与决策树，见 <CrossRef id="algorithms.lower-bounds" />。
