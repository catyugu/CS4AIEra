贪心把「每一步之后，当前的部分解仍然可以扩展成原问题的一个最优解」当作主不变量，而它在 0/1 背包上从第一步就不成立。既然不存在「选中它以后仍保持最优」的承诺，「取」与「不取」两条分支就必须同时留着，于是要把分支枚举出来；把这两条分支直接展开成递归又会发现，不同的选择序列反复走到同一个情形——「考虑完前 $i$ 件物品、剩余容量 $c$」。枚举解决分支的取舍，状态复用解决情形的重合：把这层情形显式写成一个状态、按依赖顺序每个状态只求一次，就是动态规划。

两个成分缺一不可：**状态空间有限**，以及**同一个状态只求一次**。前者让求值有界，后者把重复的状态合并成一次计算。回忆 <CrossRef id="algorithms.divide-and-conquer" /> 里朴素斐波那契的调用树——同类的子问题互相重叠，把重叠的部分折叠起来就得到这里的方法。

## 0/1 背包的状态与转移

回到这组物品。契约：

| 项 | 内容 |
| --- | --- |
| 输入 | 物品 $(w_i, v_i)$，$w_i > 0$、$v_i \ge 0$、$W \ge 0$，全部是整数 |
| 可行 | 总重量不超过 $W$ 的子集 |
| 输出 | 最大总价值 |

离散性：容量型动态规划要求状态取值离散——$W$ 是整数，或可取值集合有限。连续容量下状态不可数，要么离散化并接受近似，要么换方法。

状态取 $(i, c)$，值是「只考虑前 $i$ 件物品、容量为 $c$」时的最大总价值。一份动态规划由四件事描述：

| 项 | 内容 |
| --- | --- |
| 状态 | 把子问题压缩成的有限个「情形」，每个状态带一个值 |
| 值 | 状态的值是这一类子问题的答案（这里是最大总价值） |
| 递推 | 一个状态的值由其它状态的值算出，这一步称为转移 |
| 依赖 | 递推引用的状态必须先算出来，求值顺序是状态依赖图的一个拓扑序 |

基本情形是没有更小状态可引用的那些状态，它们的值直接给出；这里 $i = 0$ 时价值为 $0$。

**状态必须足以决定剩余子问题**。判断办法是问：给定这个状态，剩下的子问题答案唯一吗？两条不同的路径走到同一个状态之后，后续可能的成本或计数若不同，被压缩掉的信息就不够，状态写错了。0/1 背包的状态里必须带「考虑过哪些物品」的进度：只留剩余容量，不足以表示「每件物品最多取一次」这个子问题。

聚合方式不保证状态充分：加法、取最小、取最大、计数都只是把子问题的值合成当前值的方式，它们不保证状态里已经保存了未来所需的全部信息。充分性只有一条判断标准——未来所有合法选择及其贡献，是否都能由当前状态确定；不能就必须扩充状态（把已访问集合、剩余资源或时间并入状态，例如带时间窗的路径成本）。状态空间也会爆炸：约束越多，状态维度越高，「已用过的物品集合」是 $2^n$ 个状态，这时动态规划不比穷举省力——把历史塞进状态之前先看它的规模。

转移逐件做决定：

$$table[i][c] = \max\bigl(table[i-1][c],\ table[i-1][c - w_i] + v_i\bigr).$$

第一项 $table[i-1][c]$ 与第二项 $table[i-1][c - w_i] + v_i$ 分别对应**不取第 $i$ 件**与**取第 $i$ 件**（当 $w_i \le c$），转移取两者的最大。这个转移补上了贪心缺的那一步：密度规则在第一步无法保证「存在包含当前选择的最优解」，而这里把「取」与「不取」两条分支都枚举出来，因此不需要那条不变量。取第 $i$ 件之后剩下的问题恰好是「前 $i-1$ 件、容量 $c - w_i$」，是同一族的更小实例。

```python run id="alg.dp.knapsack"
import math


def knapsack_table(items, capacity):
    """table[i][c] is the best value using the first i items with capacity c."""
    table = [[0] * (capacity + 1) for _ in range(len(items) + 1)]
    for i in range(1, len(items) + 1):
        weight, value = items[i - 1]
        for c in range(capacity + 1):
            best = table[i - 1][c]
            if weight <= c:
                best = max(best, table[i - 1][c - weight] + value)
            table[i][c] = best
    return table


def brute_value(items, capacity):
    best = 0
    for mask in range(1 << len(items)):
        weight = value = 0
        for index, (w, v) in enumerate(items):
            if mask >> index & 1:
                weight += w
                value += v
        if weight <= capacity and value > best:
            best = value
    return best


def greedy_by_density(items, capacity):
    """The greedy density rule, which 0/1 knapsack refutes."""
    chosen, total = [], 0
    for weight, value in sorted(items, key=lambda item: item[1] / item[0], reverse=True):
        if total + weight <= capacity:
            chosen.append((weight, value))
            total += weight
    return sum(value for _, value in chosen)


items = [(6, 8), (5, 5), (5, 5)]
capacity = 10
print("the density-greedy counterexample, solved by the capacity recurrence")
print("  recurrence value:", knapsack_table(items, capacity)[-1][-1],
      "| exhaustive oracle:", brute_value(items, capacity),
      "| density greedy:", greedy_by_density(items, capacity))
print("  table cells:", (len(items) + 1) * (capacity + 1), "| transitions per cell: at most 2")

print()
print("the same logical instance with every weight scaled: W acts through its magnitude")
print(f"{'factor':>7} {'n':>2} {'W':>7} {'states':>9} {'bits of W':>10} {'optimal':>8}")
for factor in (1, 10, 100, 1000):
    scaled = [(w * factor, v) for w, v in items]
    big = capacity * factor
    print(f"{factor:>7} {len(scaled):>2} {big:>7} {(len(scaled) + 1) * (big + 1):>9} "
          f"{int(math.log2(big)) + 1:>10} {knapsack_table(scaled, big)[-1][-1]:>8}")

print()
print("a one-row table filled in ascending capacity solves the unbounded problem instead:")
row = [0] * 13
for c in range(1, 13):
    if 6 <= c:
        row[c] = max(row[c], row[c - 6] + 8)
print("  0/1 with the single item (6, 8) and W = 12:",
      knapsack_table([(6, 8)], 12)[-1][-1], "| the ascending one-row table:", row[12])
```

## 求值顺序与正确性

转移的两项都只引用第 $i-1$ 行的状态：$table[i-1][c]$ 与 $table[i-1][c - w_i]$。于是状态 $(i, c)$ 依赖 $(i-1, c)$ 与 $(i-1, c - w_i)$，拓扑序就是按 $i$ 递增逐行求值，同一行内的状态互不依赖。

依赖方向也决定哪张表算的是哪个问题。把二维表压成一行、按容量**升序**填，转移读到的是同一行已经更新过的格子，同一件物品就能被反复取用，得到的转移算的是无界背包；只有引用第 $i-1$ 行才保持「每件最多取一次」。区分两者靠的是转移引用 $i-1$ 行还是 $i$ 行，这正是「状态必须足以决定剩余子问题」的一个实例（本课的单元格给出这个差别）。

**正确性用归纳**，归纳沿依赖图的拓扑序进行：假设每个依赖状态已经持有它对应子问题的正确值，再证明转移式由这些值算出当前状态的正确值。优化问题里「正确值」是最优值，计数问题里是正确的计数，模板同一条。这与分治的归纳基础相同，区别是分治的子问题互不重叠，而这里不同的路径可以汇合到同一个状态。

## 状态数与伪多项式时间

表里一共有 $(n+1)(W+1)$ 个状态，每个状态的转移是常数次操作，且每个状态只被求一次，所以求出整张表的代价与状态数同阶；在 $n, W \ge 1$ 的非退化区域，这个界简写成 $\Theta(nW)$。这里的 $W$ 不能和 $n$ 并列看待。**输入长度**是写清这一组整数所需的位数，其中 $W$ 占 $\Theta(\log(W+1))$ 位；而状态数随 $W$ 的**数值**线性增长。把所有重量与容量同乘 1000，四个整数各多出约十位、输入总共只多几十个比特，状态数却涨了约 1000 倍——这样的界称为**伪多项式**（pseudo-polynomial）：它是输入中数值的多项式，不是输入长度的多项式。标准二进制编码下的整数版 0/1 背包判定问题是 NP 完全的，这里的 $\Theta(nW)$ 与那一事实并不矛盾：两者按不同的量度量规模。

数值很大的整数权重：$W = 2^k$ 只需要 $k + 1$ 个二进制位就能写出，容量 DP 却有 $\Theta(2^k)$ 个容量状态，伪多项式的代价在这里最刺眼。适当条件下可以换成按总价值索引的 DP，让代价依赖 $\sum_i v_i$，但那同样是伪多项式，只是在价值范围远小于容量范围时更合适；只按物品数换轴得不到一般的精确多项式算法。

## 二维前缀状态

背包的状态有两维，第二维是容量。另一族二维状态把两维都取成序列的前缀，同一族状态可以承载不同的转移。最长公共子序列的契约：

| 项 | 内容 |
| --- | --- |
| 输入 | 两个序列 $a$、$b$，长度 $n$、$m$ |
| 输出 | $a$ 与 $b$ 的最长公共子序列的长度（子序列由删除若干元素得到，保持原有顺序） |
| 后置 | 返回值等于所有公共子序列长度的最大值 |

状态取 $(i, j)$，值是以 $a[:i]$ 与 $b[:j]$ 为输入的子问题答案，即这两个前缀的最长公共子序列长度。转移分两种情形。当 $a[i-1] = b[j-1]$ 时：

$$table[i][j] = table[i-1][j-1] + 1.$$

否则：

$$table[i][j] = \max\bigl(table[i-1][j],\ table[i][j-1]\bigr).$$

基本情形：$i = 0$ 或 $j = 0$ 时 $table = 0$（有一个前缀为空）。

末尾字符相同时，两个方向都要证。下界：取 $a[:i-1]$ 与 $b[:j-1]$ 的一条最长公共子序列，再接上这对相同的末字符，得到一个公共子序列。上界：任取 $a[:i]$ 与 $b[:j]$ 的一条最长公共子序列 $S$，长度记 $k$；若 $S$ 的最后一对匹配就是双方的末字符，删掉它剩下的部分是 $a[:i-1]$ 与 $b[:j-1]$ 的公共子序列，于是 $k - 1 \le L(i-1, j-1)$；若不是，则 $S$ 的前面 $k - 1$ 对匹配已经全部落在 $a[:i-1]$ 与 $b[:j-1]$ 之内（两端都没占满时 $S$ 本身就是更短前缀的公共子序列，界更松），同样有 $k - 1 \le L(i-1, j-1)$。两种情形合起来就是 $k \le L(i-1, j-1) + 1$。

末尾字符不同时，任何公共子序列都不会同时以这两个字符结尾，所以它至少是 $a[:i-1]$ 与 $b[:j]$、或 $a[:i]$ 与 $b[:j-1]$ 中之一的公共子序列；两个分支取最大即可。

```python run id="alg.dp.lcs"
def lcs_table(a, b):
    """Postcondition: table[i][j] is the LCS length of a[:i] and b[:j]."""
    table = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                table[i][j] = table[i - 1][j - 1] + 1
            else:
                table[i][j] = max(table[i - 1][j], table[i][j - 1])
    return table


def brute_lcs_length(a, b):
    """Independent oracle: the longest subsequence of the shorter input that is
    also a subsequence of the longer one."""
    shorter, longer = sorted((a, b), key=len)
    best = 0
    for mask in range(1 << len(shorter)):
        candidate = "".join(shorter[i] for i in range(len(shorter)) if mask >> i & 1)
        if len(candidate) <= best:
            continue
        stream = iter(longer)
        if all(char in stream for char in candidate):
            best = len(candidate)
    return best


pairs = [("AGCAT", "GAC"), ("AAAA", "AA"), ("ABCBDAB", "BDCABA"), ("xyz", "abc")]
print(f"{'a':>9} {'b':>9} {'n*m':>5} {'states':>7} {'lcs':>4} {'oracle':>7} {'agree':>6}")
for a, b in pairs:
    table = lcs_table(a, b)
    oracle = brute_lcs_length(a, b)
    print(f"{a:>9} {b:>9} {len(a) * len(b):>5} {(len(a) + 1) * (len(b) + 1):>7} "
          f"{table[-1][-1]:>4} {oracle:>7} {str(table[-1][-1] == oracle):>6}")

a, b = "AGCAT", "GAC"
print()
print("the whole table for a =", a, "and b =", b, "(row i is a prefix of a, column j of b)")
for row in lcs_table(a, b):
    print("  " + " ".join(str(cell) for cell in row))
```

表里一共有 $(n+1)(m+1)$ 个状态，每个状态的转移是常数次操作，因此时间与空间都与 $(n+1)(m+1)$ 同阶；$n, m \ge 1$ 时才把它简写成 $\Theta(nm)$，空序列也在契约里，简写之前先看清参数域。转移只引用上一行与同一行的前一个状态，所以一行滚动数组可以把空间降到 $\Theta(\min(n, m) + 1)$（空序列也在契约里，槽位至少有一个），$n, m \ge 1$ 时才简写成 $\Theta(\min(n, m))$；那条路径放弃了表格本身，要重建序列就得另找办法——例如 Hirschberg 的分治变体，这是空间与可重建性之间的取舍。

编辑距离是同一个状态族、不同的转移。它把字符串 $a$ 改成 $b$，允许替换、插入、删除三种操作，状态仍是两个前缀 $(i, j)$：

$$table[i][j] = \min\bigl(table[i-1][j-1] + (0 \text{ if } a[i-1] = b[j-1] \text{ else } 1),\ table[i-1][j] + 1,\ table[i][j-1] + 1\bigr).$$

三项依次是**替换或匹配**、**删除 $a$ 的末字符**、**插入 $b$ 的末字符**。基本情形：$table[i][0] = i$（把 $a[:i]$ 逐个删掉）；$table[0][j] = j$（把 $b[:j]$ 逐个插入）。

状态空间、转移的局部性与依赖方向都与最长公共子序列一样，状态数与 $(n+1)(m+1)$ 同阶，因此同样只在 $n, m \ge 1$ 时简写成 $\Theta(nm)$；改变的是合并方式——最长公共子序列取最大、编辑距离取最小——与基本情形的取值。把最长公共子序列与编辑距离并排看，二维前缀状态是一个模板，具体问题是往里面填一张转移表；背包的第二维是容量，不在这一族里。

## 状态依赖图上的顺序与路径

有些状态取区间 $[i, j]$，转移引用严格更短的区间。此时依赖图按区间长度分层，拓扑序就是长度递增：先算长度为 1 的区间，再算长度为 2 的，依此类推。最长回文子序列是这个形状的例子。当 $text[i] = text[j]$ 时两端接上：

$$table[i][j] = table[i+1][j-1] + 2.$$

否则丢掉一端：

$$table[i][j] = \max\bigl(table[i+1][j],\ table[i][j-1]\bigr).$$

基本情形：$i = j$ 时为 $1$；$i > j$ 时为空区间，取 $0$。转移引用 $[i+1, j-1]$、$[i+1, j]$、$[i, j-1]$，三个都比 $[i, j]$ 短，因此按长度递增求值时它们都已算出。

```python run id="alg.dp.interval-order"
def longest_palindrome_by_length(text):
    """States are intervals; fill them in increasing interval length."""
    n = len(text)
    table = [[0] * n for _ in range(n)]
    order = []
    for length in range(1, n + 1):
        for i in range(0, n - length + 1):
            j = i + length - 1
            order.append((i, j))
            if i == j:
                table[i][j] = 1
            elif text[i] == text[j]:
                table[i][j] = table[i + 1][j - 1] + 2
            else:
                table[i][j] = max(table[i + 1][j], table[i][j - 1])
    return table, order


def longest_palindrome_by_left_endpoint(text):
    """The same recurrence filled in increasing left endpoint: row i needs row i + 1."""
    n = len(text)
    table = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(i, n):
            if i == j:
                table[i][j] = 1
            elif text[i] == text[j]:
                table[i][j] = table[i + 1][j - 1] + 2
            else:
                table[i][j] = max(table[i + 1][j], table[i][j - 1])
    return table


def brute_longest_palindrome(text):
    best = 0
    for mask in range(1 << len(text)):
        candidate = "".join(text[i] for i in range(len(text)) if mask >> i & 1)
        if candidate == candidate[::-1] and len(candidate) > best:
            best = len(candidate)
    return best


text = "agbdba"
table, order = longest_palindrome_by_length(text)
print("text:", text, "| the first cells in the order they are filled (i, j):")
print("  " + " ".join(f"({i},{j})" for i, j in order))
print()
print("  filled by increasing interval length:", table[0][len(text) - 1],
      "| exhaustive oracle:", brute_longest_palindrome(text))
print("  the same recurrence in increasing left endpoint:",
      longest_palindrome_by_left_endpoint(text)[0][len(text) - 1],
      "-> row i reads row i + 1 before it exists")
```

把状态当作顶点、把转移当作边，统一约定状态依赖图的边为「先决状态 $\to$ 当前状态」。形如「单个前驱的值加一个局部增量」的最优值递推可以直接读成这张有向图上的路径优化：$dp[s] = \min/\max_{p \to s} \lbrace dp[p] + w(p, s) \rbrace$。每条边的增益是这次转移对目标的贡献，状态的值就是从基本情形到它的最优路径值。编辑距离的边代价是 $0$ 或 $1$，聚合取最小；最长公共子序列的边增益是 $0$ 或 $1$，聚合取最大；0/1 背包里「不取」边的增益是 $0$、「取」边的增益是 $v_i$；重量 $w_i$ 决定「取」这条转移是否合法、以及它从哪个容量状态 $c - w_i$ 连过来，它约束可行转移而不进入目标函数的路径增益。三类聚合要分开看：

| 聚合 | 特征 |
| --- | --- |
| 取最小 | $\min(\text{前驱的值} + \text{代价})$ 一类，对应状态依赖图上的最短路径 |
| 取最大 | $\max(\text{前驱的值} + \text{增益})$ 一类，对应最长路径（最大权路径） |
| 计数 | 把全部前驱的贡献相加，不挑选任何一条路径，因此两者都不是 |

前两类能这样读，靠的是值沿路径可加；计数型没有「一条最优路径」的对应物，只有前驱数量的累加。

一次转移同时组合多个子状态的递推不属于这一类。区间分割型的 $dp[i, j] = \min_k \lbrace dp[i, k] + dp[k+1, j] + c(i, k, j) \rbrace$ 一个候选同时取两个子区间的值，不是普通状态图上一条边的松弛。状态形状是区间并不构成例外的理由：最长回文子序列的状态也是区间，但它的每个候选都只是「单个前驱的值加局部增量」，完全可以放进这个框架。

同一张 DAG 上因此有两种求值策略：按拓扑序求值，是在状态依赖图上按拓扑序做一遍松弛；记忆化递归，是同一张图上的深度优先搜索，每个顶点第一次算出后缓存。一般含环图上的最短路径不是这张状态 DAG 的第三种求值策略。若要把同步 Bellman–Ford 改写成这里的 DAG 动态规划，可以增加轮次维度 $k$，得到状态 $(k, v)$。

这里的分界需要说准确：**状态依赖无环**决定能否按拓扑序一遍求值，原始图有没有环是另一件事。同步 Bellman–Ford 就是例子：原图 $G$ 可以有环，把状态写成「轮次 $k$ 加顶点 $v$」之后，依赖总从 $(k-1, u)$ 连向 $(k, v)$，状态依赖图仍然是 DAG。反过来，状态依赖图里出现任何有向环都会让拓扑序不存在——自环只是最短的一种依赖环——那时得到的是一组互相定义的方程，已经不是动态规划。

这也把它接回 <CrossRef id="algorithms.bellman-ford" />：同步 Bellman–Ford 每轮都先用上一轮的标签算完全部顶点再统一更新，因此第 $k$ 轮的结果正是至多用 $k$ 条边的最短距离（原地更新的版本没有这样整齐的轮次语义）。于是 $|V| - 1$ 轮给出至多 $|V| - 1$ 条边的最优值；从源点可达的相关负环不存在时，这就是有限的最短距离，再多做一轮若仍有顶点被改善，则说明存在可达负环。

## 终止、成本与空间

**终止**由三件事合起来保证：状态数有限、依赖关系无环、求值按拓扑序进行；三者齐备时求值必然结束。这里要挑对良基秩。0/1 背包的两条边是 $(i-1, c) \to (i, c)$ 与 $(i-1, c - w_i) \to (i, c)$：容量在「不取」那条边上根本不变化，每条边都严格增长的是物品进度 $i$。选秩看的是**递归引用关系**（当前状态引用它需要的先决状态），在那层关系上 $i$ 每条边都严格下降，因此用它作秩。

**成本**是求出每个状态的全部转移所花代价之和，结论属于最坏情形。只有当每个状态的转移数有统一上界、且单条转移按单位成本计价时，才能简化成「状态数乘常数」——本课三个例子都属于这种情况。规模度量要写清楚：最长公共子序列用两个长度 $n$ 与 $m$，背包用 $n$ 与容量 $W$，两个度量不能混成一个数，否则伪多项式那一步会被抹掉。

**空间**：完整表格与状态数同阶；当转移只引用上一层（或上一层加同一层的前一个状态）时，一层滚动数组就够了。这是空间与可重建性之间的取舍：值容易滚动，解本身通常还需要额外信息。

动态规划相对朴素递归的收益只有一处：**重复状态被合并成一次计算**。本课的最长公共子序列与 0/1 背包若按分支直接递归，最坏情况下调用次数随输入指数增长，而备忘版本把它压到有限状态数那一档；这是一条关于这两个例子的陈述，不是一个普遍定理——并非任何动态规划都比直接递归快指数级，代价始终是状态表占用的空间（对照 <CrossRef id="algorithms.recursion" /> 的调用树：那里算的是调用次数，这里算的是不同状态数）。
