0/1 背包给出一组物品，每件物品有重量 $w_i$ 与价值 $v_i$，以及一个容量 $W$：选出一个子集，使总重量不超过 $W$、总价值最大，且每件物品至多取一次。

| 项 | 内容 |
| --- | --- |
| 输入 | 物品 $(w_i, v_i)$，$w_i > 0$、$v_i \ge 0$、$W \ge 0$，全部是整数 |
| 可行 | 总重量不超过 $W$ 的子集 |
| 输出 | 最大总价值 |

决定落在最后一件物品上。不取第 $i$ 件时，最优价值是「只用前 $i-1$ 件、容量为 $c$」的最优价值；取第 $i$ 件时（前提 $w_i \le c$），先得到 $v_i$，剩下的问题恰好是「只用前 $i-1$ 件、容量为 $c - w_i$」，是同一族的更小实例。两个值谁大取决于具体的数，无法先验排除任一个，于是把两条分支都留下。设 $best(i, c)$ 为「只用前 $i$ 件、容量为 $c$」的最大总价值：

$$best(i, c) = \max\bigl(best(i-1, c),\ best(i-1, c - w_i) + v_i\bigr), \quad w_i \le c ;$$

当 $w_i > c$ 时第 $i$ 件装不下，只有 $best(i, c) = best(i-1, c)$；基本情形 $i = 0$ 的值是 $0$。按价值密度 $v_i / w_i$ 降序扫描的贪心没有这条递推可用（<CrossRef id="algorithms.greedy" />）。

递推的第二个参数 $c$ 取整数值。容量型动态规划要求状态取值离散——$W$ 是整数，或其可取值集合有限；连续容量下状态不可数，要么离散化并接受近似，要么换方法。

## 同一情形被反复问到

递推给出了答案的写法，代价要靠展开它才知道。把递推直接写成递归，同一件物品的「取」与「不取」把调用分成两支，不同的选择序列会走到同一个情形——「考虑完前 $i$ 件、容量为 $c$」。数一数同一个情形在朴素递归里被问到多少次：

```python run id="alg.dp.repeat-calls"
calls = {}


def best_value(items, capacity, i):
    """Best value from the first i items with the given capacity."""
    calls[(i, capacity)] = calls.get((i, capacity), 0) + 1
    if i == 0:
        return 0
    weight, value = items[i - 1]
    best = best_value(items, capacity, i - 1)
    if weight <= capacity:
        best = max(best, best_value(items, capacity - weight, i - 1) + value)
    return best


items = [(6, 8), (5, 5), (5, 5), (4, 4)]
capacity = 12
print("best value:", best_value(items, capacity, len(items)))
repeated = {state: n for state, n in calls.items() if n > 1}
print("distinct (i, c) states:", len(calls), "| total calls:", sum(calls.values()))
for (i, c), n in sorted(repeated.items()):
    print(f"  best({i}, {c}) asked {n} times")
```

四件物品、容量 12 的实例上，朴素递归触及 19 个不同的 $(i, c)$，做了 25 次调用，其中 6 个情形被问到两次。不同的取法顺序走到同一个情形，递归每次都从头再算一遍。

把这个情形命名为一个**状态**：状态 $(i, c)$ 的值是它所代表的这一类子问题的答案，递推式是状态之间的一条**转移**。`best(1, 3)` 与 `best(1, 7)` 各由两条不同的选择序列到达，值相同。分支反复汇合到同一批状态，是重叠子问题的形状（<CrossRef id="algorithms.divide-and-conquer" />）。

把算过的状态的值存进一张表，再次遇到同一个状态就查表返回，这称为<Term id="memoization">记忆化</Term>。每个状态至多计算一次，重复的调用被折叠：上例的 25 次调用里独立状态只有 19 个，记忆化之后每个只算一次。

## 求值顺序

记忆化是自顶向下的：从 $(n, W)$ 出发，遇到没算过的状态才递归下去。同一条递推也能自底向上填表，能不能这样做，取决于转移引用了哪些状态。$best(i, c)$ 只引用 $(i-1, c)$ 与 $(i-1, c - w_i)$，两者都在第 $i-1$ 行。按 $i$ 从小到大逐行填，填第 $i$ 行时它引用的状态都已算好；同一行内部的转移互不引用，行内顺序任意。逐行递增 $i$ 是状态依赖图的一个**拓扑序**。

```python run id="alg.dp.knapsack"
def knapsack_table(items, capacity):
    """table[i][c]: best value from the first i items with capacity c."""
    table = [[0] * (capacity + 1) for _ in range(len(items) + 1)]
    for i in range(1, len(items) + 1):
        weight, value = items[i - 1]
        for c in range(capacity + 1):
            table[i][c] = table[i - 1][c]
            if weight <= c:
                table[i][c] = max(table[i][c], table[i - 1][c - weight] + value)
    return table


def best_subset(items, capacity):
    best = 0
    for mask in range(1 << len(items)):
        weight = value = 0
        for index, (w, v) in enumerate(items):
            if mask >> index & 1:
                weight += w
                value += v
        if weight <= capacity:
            best = max(best, value)
    return best


items = [(6, 8), (5, 5), (5, 5), (4, 4)]
capacity = 12
table = knapsack_table(items, capacity)
print("states filled once:", (len(items) + 1) * (capacity + 1))
print("best value:", table[-1][-1], "| best of all 16 subsets:", best_subset(items, capacity))
```

表里共 $(n+1)(W+1)$ 个状态，这里 $n = 4$、$W = 12$，是 65 个；填出的最优值 13 与枚举全部 16 个子集得到的最优值一致。

状态也可以取区间 $[i, j]$。$[i, j]$ 的转移引用 $[i+1, j-1]$、$[i+1, j]$、$[i, j-1]$，三个都比 $[i, j]$ 短，因此按区间长度从小到大填时，引用到的状态都已算好。最长回文子序列是这个形状：两端字符相同时接上，

$$table[i][j] = table[i+1][j-1] + 2,$$

否则丢掉一端，

$$table[i][j] = \max\bigl(table[i+1][j],\ table[i][j-1]\bigr).$$

基本情形 $i = j$ 时为 $1$，$i > j$ 为空区间取 $0$。

```python run id="alg.dp.interval-order"
def longest_palindrome(text):
    """States are intervals [i, j]; each reads only strictly shorter intervals."""
    n = len(text)
    table = [[0] * n for _ in range(n)]
    order = []
    for length in range(1, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            order.append((length, i, j))
            if i == j:
                table[i][j] = 1
            elif text[i] == text[j]:
                table[i][j] = table[i + 1][j - 1] + 2
            else:
                table[i][j] = max(table[i + 1][j], table[i][j - 1])
    return table, order


text = "agbdba"
table, order = longest_palindrome(text)
first_of_length = {}
for length, i, j in order:
    first_of_length.setdefault(length, (i, j))
print("first cell of each length, in fill order:",
      " ".join(f"L{length}->({i},{j})" for length, (i, j) in sorted(first_of_length.items())))
print("longest palindromic subsequence:", table[0][len(text) - 1])
```

按长度递增填 `"agbdba"`，最长回文子序列长度是 5。把外层循环从长度递增改成左端点递增，$[i, j]$ 会先读 $[i+1, \cdot]$ 这一尚未填的行，同一组数上得到 2。填表顺序由转移的引用关系决定。

**正确性用归纳**，归纳沿依赖图的拓扑序进行：假设每个依赖状态已经持有它对应子问题的正确值，再证明转移式由这些值算出当前状态的正确值。优化问题里「正确值」是最优值，计数问题里是正确的计数，模板同一条。归纳基础与分治相同，区别是分治的子问题互不重叠，这里不同的路径可以汇合到同一个状态。

## 状态数与伪多项式时间

表里一共有 $(n+1)(W+1)$ 个状态，每个状态的转移是常数次操作，且每个状态只被求一次，所以求出整张表的代价与状态数同阶；在 $n, W \ge 1$ 的非退化区域，这个界简写成 $\Theta(nW)$。这里的 $W$ 不能和 $n$ 并列看待。**输入长度**是写清这一组整数所需的位数，其中 $W$ 占 $\Theta(\log(W+1))$ 位；而状态数随 $W$ 的**数值**线性增长。把所有重量与容量同乘 1000，四个整数各多出约十位、输入总共只多几十个比特，状态数却涨了约 1000 倍——这样的界称为<Term id="pseudo-polynomial">伪多项式</Term>（pseudo-polynomial）：它是输入中数值的多项式，不是输入长度的多项式。标准二进制编码下的整数版 0/1 背包判定问题是 NP 完全的，这里的 $\Theta(nW)$ 与那一事实并不矛盾：两者按不同的量度量规模。

数值很大的整数权重：$W = 2^k$ 只需要 $k + 1$ 个二进制位就能写出，容量 DP 却有 $\Theta(2^k)$ 个容量状态，伪多项式的代价在这里最刺眼。适当条件下可以换成按总价值索引的 DP，让代价依赖 $\sum_i v_i$，但那同样是伪多项式，只是在价值范围远小于容量范围时更合适；只按物品数换轴得不到一般的精确多项式算法。

## 二维前缀状态

背包的状态有两维，第二维是容量。另一族二维状态把两维都取成序列的前缀，同一族状态可以承载不同的转移。最长公共子序列的契约：

| 项 | 内容 |
| --- | --- |
| 输入 | 两个序列 $a$、$b$，长度 $n$、$m$ |
| 输出 | $a$ 与 $b$ 的最长公共子序列的长度（子序列由删除若干元素得到，保持原有顺序） |
| 后置 | 返回值等于所有公共子序列长度的最大值 |

状态取 $(i, j)$，值是以 $a[:i]$ 与 $b[:j]$ 为输入的子问题答案，即这两个前缀的最长公共子序列长度。转移分两种情形。当 $a[i-1] = b[j-1]$ 时：

$$table[i][j] = table[i-1][j-1] + 1.$$

否则：

$$table[i][j] = \max\bigl(table[i-1][j],\ table[i][j-1]\bigr).$$

基本情形：$i = 0$ 或 $j = 0$ 时 $table = 0$（有一个前缀为空）。

末尾字符相同时，两个方向都要证。下界：取 $a[:i-1]$ 与 $b[:j-1]$ 的一条最长公共子序列，再接上这对相同的末字符，得到一个公共子序列。上界：任取 $a[:i]$ 与 $b[:j]$ 的一条最长公共子序列 $S$，长度记 $k$；若 $S$ 的最后一对匹配就是双方的末字符，删掉它剩下的部分是 $a[:i-1]$ 与 $b[:j-1]$ 的公共子序列，于是 $k - 1 \le L(i-1, j-1)$；若不是，则 $S$ 的前面 $k - 1$ 对匹配已经全部落在 $a[:i-1]$ 与 $b[:j-1]$ 之内（两端都没占满时 $S$ 本身就是更短前缀的公共子序列，界更松），同样有 $k - 1 \le L(i-1, j-1)$。两种情形合起来就是 $k \le L(i-1, j-1) + 1$。

末尾字符不同时，任何公共子序列都不会同时以这两个字符结尾，所以它至少是 $a[:i-1]$ 与 $b[:j]$、或 $a[:i]$ 与 $b[:j-1]$ 中之一的公共子序列；两个分支取最大即可。按定义枚举所有子序列能独立核对这两个分支，代价随序列长度指数增长，只对短序列可行。

```python run id="alg.dp.lcs"
def lcs_table(a, b):
    """Postcondition: table[i][j] is the LCS length of a[:i] and b[:j]."""
    table = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                table[i][j] = table[i - 1][j - 1] + 1
            else:
                table[i][j] = max(table[i - 1][j], table[i][j - 1])
    return table


pairs = [("AGCAT", "GAC"), ("AAAA", "AA"), ("ABCBDAB", "BDCABA"), ("xyz", "abc")]
print(f"{'a':>8} {'b':>8} {'n*m':>5} {'states':>7} {'lcs':>4}")
for a, b in pairs:
    table = lcs_table(a, b)
    print(f"{a:>8} {b:>8} {len(a) * len(b):>5} {(len(a) + 1) * (len(b) + 1):>7} {table[-1][-1]:>4}")

a, b = "AGCAT", "GAC"
print()
print("the whole table for a =", a, "and b =", b, "(row i is a prefix of a, column j of b)")
for row in lcs_table(a, b):
    print("  " + " ".join(str(cell) for cell in row))
```

表里一共有 $(n+1)(m+1)$ 个状态，每个状态的转移是常数次操作，因此时间与空间都与 $(n+1)(m+1)$ 同阶；$n, m \ge 1$ 时才把它简写成 $\Theta(nm)$，空序列也在契约里，简写之前先看清参数域。转移只引用上一行与同一行的前一个状态，所以一行滚动数组可以把空间降到 $\Theta(\min(n, m) + 1)$（空序列也在契约里，槽位至少有一个），$n, m \ge 1$ 时才简写成 $\Theta(\min(n, m))$；那条路径放弃了表格本身，要重建序列就得另找办法——例如 Hirschberg 的分治变体，这是空间与可重建性之间的取舍。

编辑距离是同一个状态族、不同的转移。它把字符串 $a$ 改成 $b$，允许替换、插入、删除三种操作，状态仍是两个前缀 $(i, j)$：

$$table[i][j] = \min\bigl(table[i-1][j-1] + (0 \text{ if } a[i-1] = b[j-1] \text{ else } 1),\ table[i-1][j] + 1,\ table[i][j-1] + 1\bigr).$$

三项依次是**替换或匹配**、**删除 $a$ 的末字符**、**插入 $b$ 的末字符**。基本情形：$table[i][0] = i$（把 $a[:i]$ 逐个删掉）；$table[0][j] = j$（把 $b[:j]$ 逐个插入）。

状态空间、转移的局部性与依赖方向都与最长公共子序列一样，状态数与 $(n+1)(m+1)$ 同阶，因此同样只在 $n, m \ge 1$ 时简写成 $\Theta(nm)$；改变的是合并方式——最长公共子序列取最大、编辑距离取最小——与基本情形的取值。把最长公共子序列与编辑距离并排看，二维前缀状态是一个模板，具体问题是往里面填一张转移表；背包的第二维是容量，不在这一族里。

## 终止与成本

**终止**由三件事合起来保证：状态数有限、依赖关系无环、求值按拓扑序进行；三者齐备时求值必然结束。这里要挑对良基秩。0/1 背包的两条边是 $(i-1, c) \to (i, c)$ 与 $(i-1, c - w_i) \to (i, c)$：容量在「不取」那条边上根本不变化，每条边都严格增长的是物品进度 $i$。选秩看的是**递归引用关系**（当前状态引用它需要的先决状态），在那层关系上 $i$ 每条边都严格下降，因此用它作秩。

**成本**是求出每个状态的全部转移所花代价之和，结论属于最坏情形。只有当每个状态的转移数有统一上界、且单条转移按单位成本计价时，才能简化成「状态数乘常数」——本课三个例子都属于这种情况。规模度量要写清楚：最长公共子序列用两个长度 $n$ 与 $m$，背包用 $n$ 与容量 $W$，两个度量不能混成一个数，否则伪多项式那一步会被抹掉。

## 状态依赖图

把状态当作顶点、把转移当作边，约定边由先决状态指向当前状态，本课出现的几种状态形状就落在同一张有向图上。状态充分（无后效性）在这张图上的说法是：一个状态的值只由它的先决状态决定，与走到它的路径无关，同一状态无论被哪条路径到达，值唯一。这正是「状态必须足以决定剩余子问题」，也是<Term id="optimal-substructure">最优子结构</Term>：递推由先决状态的值算出当前状态的值。依赖图无环时，求值顺序就是这个图的一个拓扑序——0/1 背包按物品进度 $i$ 递增逐行求值，区间状态按区间长度递增求值。

**状态要足以决定剩余子问题**。判断办法是问：给定这个状态，剩下的子问题的答案唯一吗？两条不同的路径走到同一个状态之后，后续可能的成本或计数若不同，被压缩掉的信息就不够，状态就写错了。0/1 背包的状态必须带「考虑过哪些物品」的进度 $i$：只留剩余容量，无法表示「每件物品至多取一次」这个子问题。

聚合方式不保证状态充分：取最小、取最大、加法、计数都只是把子问题的值合成当前值的方式，它们不保证状态里已经保存了未来所需的全部信息。充分性只有一条标准——未来所有合法选择及其贡献，是否都能由当前状态确定；不能就必须扩充状态，把已访问集合、剩余资源或时间并入状态，例如带时间窗的路径成本。扩充的代价是状态空间随维度膨胀：「已用过的物品集合」是 $2^n$ 个状态，这时动态规划不比穷举省力，把历史塞进状态之前先看它的规模。

形如「单个前驱的值加一个局部增量」的最优值递推可以读成这张图上的路径优化：

$$dp[s] = \min/\max_{p \to s} \lbrace dp[p] + w(p, s) \rbrace.$$

每条边的增益是这次转移对目标的贡献，状态的值就是从基本情形到它的最优路径值。编辑距离的边代价是 $0$ 或 $1$，聚合取最小；最长公共子序列的边增益是 $0$ 或 $1$，聚合取最大；0/1 背包里「不取」边的增益是 $0$、「取」边的增益是 $v_i$，重量 $w_i$ 决定「取」这条转移是否合法、以及它从哪个容量状态 $c - w_i$ 连过来，它约束可行转移而不进入目标函数的路径增益。三类聚合要分开看：

| 聚合 | 特征 |
| --- | --- |
| 取最小 | $\min(\text{前驱的值} + \text{代价})$ 一类，对应状态依赖图上的最短路径 |
| 取最大 | $\max(\text{前驱的值} + \text{增益})$ 一类，对应最长路径（最大权路径） |
| 计数 | 把全部前驱的贡献相加，不挑选任何一条路径，因此两者都不是 |

前两类能这样读，靠的是值沿路径可加；计数型没有「一条最优路径」的对应物，只有前驱数量的累加。

一次转移同时组合多个子状态的递推不属于这一类。区间分割型的 $dp[i, j] = \min_k \lbrace dp[i, k] + dp[k+1, j] + c(i, k, j) \rbrace$ 一个候选同时取两个子区间的值，不是普通状态图上一条边的松弛。状态形状是区间并不构成例外的理由：最长回文子序列的状态也是区间，但它的每个候选都只是「单个前驱的值加局部增量」，完全可以放进这个框架。

同一张图上因此有两种求值策略：按拓扑序求值，是在状态依赖图上按拓扑序做一遍松弛；记忆化递归，是同一张图上的深度优先搜索，每个顶点第一次算出后缓存。一般含环图上的最短路径不是这张状态 DAG 的第三种求值策略。重叠的子问题在这两种策略下都被折叠成一次计算，这正是动态规划相对朴素递归的全部收益：本课的最长公共子序列与 0/1 背包若按分支直接递归，最坏情况下调用次数随输入指数增长，而带备忘的版本把它压到有限状态数那一档；这是一条关于这两个例子的陈述，代价始终是状态表占用的空间（对照 <CrossRef id="algorithms.recursion" /> 的调用树：那里算的是调用次数，这里算的是不同状态数）。

按拓扑序一遍求值靠的是**状态依赖无环**，原始图有没有环是另一件事。同步 Bellman–Ford 的原图可以有环，把状态写成「轮次 $k$ 加顶点 $v$」之后，依赖总从 $(k-1, u)$ 连向 $(k, v)$，状态依赖图仍是 DAG；第 $k$ 轮的结果正是至多用 $k$ 条边的最短距离，$|V| - 1$ 轮给出有限最短距离，再多做一轮若仍有顶点被改善就说明存在可达负环（<CrossRef id="algorithms.bellman-ford" />）。反过来，状态依赖图里出现任何有向环都会让拓扑序不存在——自环只是最短的一种依赖环——那时得到的是一组互相定义的方程，已经不是动态规划。

完整表格与状态数同阶；滚动数组把空间降到一层，前提是转移只引用上一层（或上一层加同一层的前一个状态）；把二维表压成一行、按容量升序填，转移读到的是同一行已经更新过的格子，同一件物品被反复取用，算的就不是 0/1 背包。空间压缩的正确性条件因此落在转移的引用范围上：引用 $i-1$ 行时值可滚动，引用同一行时改变了所解的问题。这是空间与可重建性之间的取舍：值容易滚动，解本身通常还需要额外信息才能回溯构造，放弃表格之后要重建序列就得换办法，例如 Hirschberg 的分治变体。
