0/1 背包给出一组物品，每件物品有重量 $w_i$ 与价值 $v_i$，以及一个容量 $W$：选出一个子集，使总重量不超过 $W$、总价值最大，每件物品至多取一次。用四件物品 $(5, 6)$、$(4, 7)$、$(3, 5)$、$(3, 4)$、容量 $W = 7$ 的实例。

决定落在最后一件物品上。第 4 件可以不取，也可以取：不取，价值全部来自前三件、容量仍是 7；取（重量 $3 \le 7$），先得到价值 4，剩下前三件、容量 $7 - 3 = 4$ 的同类情形。哪一边更大取决于具体的数，两个分支都留着。把一个「前 $i$ 件、容量 $c$」的情形记作 $best(i, c)$，它的值是这一类子问题的最大总价值；第 4 件上的分叉就是 $best(4, 7)$ 分出 $best(3, 7)$ 与 $best(3, 4)$。

## 同一个子问题被反复求解

把分叉写成递归：$best(3, 7)$ 与 $best(3, 4)$ 各自按第 3 件再分叉，一直分到没有物品。展开两层已经能看出问题：

```text
best(4, 7)
├─ 不取 4 → best(3, 7)
│  ├─ 不取 3 → best(2, 7)
│  └─ 取 3   → best(2, 4)
└─ 取 4   → best(3, 4)
   ├─ 不取 3 → best(2, 4)
   └─ 取 3   → best(2, 1)
```

两棵子树里 $best(2, 4)$ 出现两次：不取第 3 件落到它，取第 3 件也落到它，两条不同的选择序列汇合到同一个情形，它下面的整棵子树因此原样算两遍。汇合的情形不止这一对，把朴素递归的调用数出来：

```python run id="alg.dp.repeat-calls"
calls = {}


def best_value(items, capacity, i):
    """Best value from the first i items with the given capacity."""
    calls[(i, capacity)] = calls.get((i, capacity), 0) + 1
    if i == 0:
        return 0
    weight, value = items[i - 1]
    best = best_value(items, capacity, i - 1)
    if weight <= capacity:
        best = max(best, best_value(items, capacity - weight, i - 1) + value)
    return best


items = [(5, 6), (4, 7), (3, 5), (3, 4)]
capacity = 7
best_value(items, capacity, len(items))
print("distinct (i, c) states:", len(calls), "| total calls:", sum(calls.values()))
print("states asked more than once:", sum(1 for n in calls.values() if n > 1))
```

这个实例触及的不同 $(i, c)$ 情形不超过 $(n+1)(W+1)$，调用次数却更多，多出来的部分全花在把已经算过的情形重算一遍。把算过的情形的值记下来，再次遇到直接取用，同一个情形就只算一次。存下来的「前 $i$ 件、容量 $c$」称为一个**状态**，状态的值是这一类子问题的答案；把已算过的状态查出来返回，这一步称为<Term id="memoization">记忆化</Term>。分支反复汇合到同一批状态，是重叠子问题（overlapping subproblems）的形状（<CrossRef id="algorithms.divide-and-conquer" />）。

状态之间的值由一条递推式联系起来。$best(i, c)$ 只引用 $(i-1, c)$ 与 $(i-1, c - w_i)$：

$$best(i, c) = \max\bigl(best(i-1, c),\ best(i-1, c - w_i) + v_i\bigr), \quad w_i \le c ;$$

当 $w_i > c$ 时第 $i$ 件装不下，只有 $best(i, c) = best(i-1, c)$；基本情形 $i = 0$ 的值是 $0$。

| 项 | 内容 |
| --- | --- |
| 输入 | 物品 $(w_i, v_i)$，$w_i > 0$、$v_i \ge 0$、$W \ge 0$，全部是整数 |
| 可行 | 总重量不超过 $W$ 的子集 |
| 输出 | 最大总价值 |

按价值密度 $v_i / w_i$ 降序扫描的贪心没有这条递推可用（<CrossRef id="algorithms.greedy" />）。

递推的第二个参数 $c$ 取整数值。容量型动态规划要求状态取值离散——$W$ 是整数，或其可取值集合有限；连续容量下状态不可数，要么离散化并接受近似，要么换方法。

## 求值顺序

记忆化是自顶向下的：从 $(n, W)$ 出发，遇到没算过的状态才递归下去。同一条递推也能自底向上填表，能不能这样做，取决于转移引用了哪些状态。$best(i, c)$ 只引用 $(i-1, c)$ 与 $(i-1, c - w_i)$，两者都在第 $i-1$ 行。按 $i$ 从小到大逐行填，填第 $i$ 行时它引用的状态都已算好；同一行内部的转移互不引用，行内顺序任意。逐行递增 $i$ 是状态依赖图的一个**拓扑序**；物品进度 $i$ 在每条转移上都严格下降，按这个序求值因此终止。

```python run id="alg.dp.knapsack"
def knapsack_table(items, capacity):
    """table[i][c]: best value from the first i items with capacity c."""
    table = [[0] * (capacity + 1) for _ in range(len(items) + 1)]
    for i in range(1, len(items) + 1):
        weight, value = items[i - 1]
        for c in range(capacity + 1):
            table[i][c] = table[i - 1][c]
            if weight <= c:
                table[i][c] = max(table[i][c], table[i - 1][c - weight] + value)
    return table


items = [(5, 6), (4, 7), (3, 5), (3, 4)]
capacity = 7
table = knapsack_table(items, capacity)
print("states filled once:", (len(items) + 1) * (capacity + 1))
print("best value:", table[-1][-1])
```

表里共 $(n+1)(W+1)$ 个状态，每个只填一次，这段代码一次就填出这个实例的最优值。

求值顺序不是总按行前进。状态取区间 $[i, j]$ 时，$[i, j]$ 的转移引用 $[i+1, j-1]$、$[i+1, j]$、$[i, j-1]$，三个都比 $[i, j]$ 短，按区间长度从小到大填才保证引用到的状态都已算好。最长回文子序列是这个形状：两端字符相同时接上，

$$table[i][j] = table[i+1][j-1] + 2,$$

否则丢掉一端，

$$table[i][j] = \max\bigl(table[i+1][j],\ table[i][j-1]\bigr).$$

基本情形 $i = j$ 时为 $1$，$i > j$ 为空区间取 $0$。按长度递增填 `"agbdba"`，最长回文子序列长度是 5；把外层循环改成左端点递增，$[i, j]$ 会先读 $[i+1, \cdot]$ 这一尚未填的行，同一组数上得到 2。填表顺序由转移的引用关系决定。

**正确性用归纳**，归纳沿依赖图的拓扑序进行：假设每个依赖状态已经持有它对应子问题的正确值，再证明转移式由这些值算出当前状态的正确值。优化问题里「正确值」是最优值，计数问题里是正确的计数，模板同一条。归纳基础与分治相同，区别是分治的子问题互不重叠，这里不同的路径可以汇合到同一个状态。

## 状态数与伪多项式时间

表里一共有 $(n+1)(W+1)$ 个状态，每个状态的转移是常数次操作，且每个状态只被求一次，所以求出整张表的代价与状态数同阶；在 $n, W \ge 1$ 的非退化区域，这个界简写成 $\Theta(nW)$。规模由两个量共同决定：物品数 $n$ 与容量 $W$，两者不能混成一个数，否则伪多项式那一步会被抹掉。**输入长度**是写清这一组整数所需的位数，其中 $W$ 占 $\Theta(\log(W+1))$ 位；而状态数随 $W$ 的**数值**线性增长。把所有重量与容量同乘 1000，四个整数各多出约十位、输入总共只多几十个比特，状态数却涨了约 1000 倍——这样的界称为<Term id="pseudo-polynomial">伪多项式</Term>（pseudo-polynomial）：它是输入中数值的多项式，不是输入长度的多项式。标准二进制编码下的整数版 0/1 背包判定问题是 NP 完全的，这里的 $\Theta(nW)$ 与那一事实并不矛盾：两者按不同的量度量规模。

数值很大的整数权重：$W = 2^k$ 只需要 $k + 1$ 个二进制位就能写出，容量 DP 却有 $\Theta(2^k)$ 个容量状态，伪多项式的代价在这里最刺眼。适当条件下可以换成按总价值索引的 DP，让代价依赖 $\sum_i v_i$，但那同样是伪多项式，只是在价值范围远小于容量范围时更合适；只按物品数换轴得不到一般的精确多项式算法。

## 状态依赖图

把状态当作顶点、把转移当作边，约定边由先决状态指向当前状态。同一张图上有两条不同的性质，0/1 背包同时满足它们，因此最容易在这里被并成一条。

**状态充分性**（无后效性）回答的是：给定当前状态以后，未来所有可行选择及其贡献是否还依赖被丢掉的历史。判定标准只有一条——两条不同的路径走到同一个状态之后，剩余合法选择的集合、以及每个选择带来的成本或计数都相同；被压缩掉的历史不再进入未来的计算。落在图上，就是一个状态的值只由它的先决状态决定，与走到它的路径无关，同一状态无论被哪条路径到达，值唯一。

**<Term id="optimal-substructure">最优子结构</Term>**回答的是另一个问题：当前问题的最优值能否由相应子问题的最优值通过递推组合得到。判定标准是存在这样一条递推式——当前状态的最优值等于对各先决状态的最优值取最优（或求和、计数）。它管的是值能不能拼出来，与状态划分得够不够细无关：0/1 背包满足它，$best(i, c)$ 由两个先决状态的最优值取最大得到；最长路径不满足它，子路径最优会与「顶点不重复」冲突。

**状态要足以决定剩余子问题**。0/1 背包的状态必须带「考虑过哪些物品」的进度 $i$：同一个剩余容量下，前面取过哪些物品决定了还剩哪些可选，只留剩余容量无法表示「每件物品至多取一次」这个子问题，也就违反了状态充分性。

把先决状态的值合成当前值的方式——取最小、取最大、加法、计数——属于递推本身，它不补充状态里缺少的信息。状态充分性不够时，就得把历史并入状态：已访问集合、剩余资源、时间。代价是状态空间随维度膨胀，「已用过的物品集合」是 $2^n$ 个状态，这时动态规划不比穷举省力。把历史塞进状态之前先看它的规模。

同一张图上有两种求值策略：按拓扑序求值，是沿状态依赖图按拓扑序把每个状态算一遍；记忆化递归，是同一张图上的深度优先搜索，每个顶点第一次算出后缓存。重叠的子问题在两种策略下都被折叠成一次计算，这正是动态规划相对朴素递归的全部收益：0/1 背包若按分支直接递归，最坏情况下调用次数随输入指数增长，而带备忘的版本把它压到有限状态数那一档（对照 <CrossRef id="algorithms.recurrences-and-call-trees" /> 的调用树：那里算的是调用次数，这里算的是不同状态数）。

按拓扑序一遍求值靠的是**状态依赖无环**，原始图有没有环是另一件事。同步 Bellman–Ford 的原图可以有环，把状态写成「轮次 $k$ 加顶点 $v$」之后，依赖总从 $(k-1, u)$ 连向 $(k, v)$，状态依赖图仍是 DAG；第 $k$ 轮的结果正是至多用 $k$ 条边的最短距离，$|V| - 1$ 轮给出有限最短距离，再多做一轮若仍有顶点被改善就说明存在可达负环（<CrossRef id="algorithms.bellman-ford" />）。反过来，状态依赖图里出现任何有向环都会让拓扑序不存在——自环只是最短的一种依赖环。递推由更小的子问题算出当前状态，要求依赖无环；成环时它退化成一组互相定义的方程，不再确定任何状态的最优值，动态规划也就不适用。这与状态充分性无关：状态可以写得充分，依赖照样能成环。

完整表格与状态数同阶；滚动数组把空间降到一层，前提是转移只引用上一层（或上一层加同一层的前一个状态）。把二维表压成一行、按容量升序填，转移读到的是同一行已经更新过的格子，同一件物品被反复取用，算的就不是 0/1 背包。空间压缩的正确性条件因此落在转移的引用范围上：引用 $i-1$ 行时值可滚动，引用同一行时改变了所解的问题。
