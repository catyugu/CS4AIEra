贪心算法一次做一个不可撤回的选择，之后不回头修改，每一步选错都没有回头路。一条规则看起来合理，不足以保证结论正确；它站得住，靠的是能构造一个包含这一步所选对象的最优解。下面从一道规则一眼能想出来的题目做起：区间调度，选出一组两两不重叠的区间，使数量最大。

## 区间调度

问题定义：

| 项 | 规格 |
| --- | --- |
| 输入 | 一组区间 $[s_i, f_i)$，要求 $s_i < f_i$ |
| 可行 | 两两不重叠：对任意两个区间，其中一个的结束时刻不晚于另一个的开始时刻 |
| 目标 | 可行子集的最大势 |
| 后置 | 返回一个最大势的两两不重叠子集 |

本课用半开区间 $[s, f)$，因此 $[0,1)$ 与 $[1,2)$ 相容，而闭区间 $[0,1]$ 与 $[1,2]$ 在点 1 相交。不重叠的判据依赖这条约定，换约定必须重新陈述问题定义。

规则按结束时刻升序扫描：维护上一个被选中区间的结束时刻 `last_finish`，当区间开始时刻不早于 `last_finish` 时把它选入。结束得越早，后面留给其他区间的位置越多，这是这条规则的全部直觉。

```python run id="alg.greedy.interval-scheduling"
def earliest_finish(intervals):
    """Scan by finish; keep an interval when it is compatible with the last one."""
    chosen, last_finish = [], None
    for start, finish in sorted(intervals, key=lambda interval: interval[1]):
        if last_finish is None or start >= last_finish:
            chosen.append((start, finish))
            last_finish = finish
    return chosen


cases = (
    ("one long interval plus two short", [(0, 10), (1, 2), (3, 4)]),
    ("touching half-open intervals", [(0, 3), (3, 5), (4, 6), (5, 6)]),
    ("one interval nested over three", [(1, 9), (2, 3), (4, 5), (6, 7)]),
)
for label, intervals in cases:
    print(f"{label:33s} {intervals} -> {earliest_finish(intervals)}")
```

第一行丢掉最长的那段、留下两段短区间，第二、三行各留下三段。规则与直觉一致：结束得越早，越早把后面的位置让出来。半开约定在第二行起了作用——$[0,3)$ 与 $[3,5)$ 在点 3 相接仍然相容，闭区间会在这里相交。

## 最早结束为什么正确

**引理**：存在一个包含 $c$ 的最优解，其中 $c$ 是结束时刻最早的区间。

证明：任取一个最优解，把它按结束时刻升序排列，记第一个区间为 $o_1$。由 $c$ 的选法有 $f(c) \le f(o_1)$。把 $o_1$ 换成 $c$：解里其余区间原本在 $o_1$ 结束之后才开始，而 $c$ 结束得不晚于 $o_1$，所以它们仍然不与 $c$ 重叠。替换后的集合仍然两两不重叠、势不变，是一个同样好的最优解，且包含 $c$。

归纳：选定 $c$ 后，残余实例只保留开始时刻不早于 $f(c)$ 的区间。含 $c$ 的最优解去掉 $c$ 是残余实例的可行解；反过来，残余实例的任意可行解加上 $c$ 是原问题的可行解。因此原问题的最优值等于 $1$ 加残余实例的最优值。贪心在原问题上的输出恰好是 $c$ 加上它在残余实例上的输出，对残余实例归纳即得输出最优；基情形是空实例，最优值 $0$。

## 交换论证

典型的贪心证明都在做类似的事——构造一个包含当前贪心选择的最优解，并证明最优性不变；这类证明通常称为<Term id="exchange-argument">交换论证</Term>。区间调度上它就是上面那一次替换：把一个最优解的第一个区间换成结束最早的区间，最优性不丢，贪心的选择因此在某个最优解里有位置。

**扩展阅读**：这类「按固定次序扫描、能加就加」的规则在组合优化里的一般形式叫拟阵（matroid），<CrossRef id="algorithms.connectivity-and-spanning-trees" /> 的 Kruskal 最小生成树落在其中。

## 反例：0/1 背包按密度选择

同样的交换论证换一道题就走不完。0/1 背包的问题定义：

| 项 | 规格 |
| --- | --- |
| 输入 | 物品 $(w_i, v_i)$，$w_i > 0$、$v_i \ge 0$，容量 $W \ge 0$ |
| 可行 | 总重量不超过 $W$ 的子集 |
| 目标 | 总价值最大 |

规则：按价值密度 $v/w$ 降序扫描，能装下就装。问题定义里的 $w_i > 0$ 是密度有定义的前提；允许零重量会让密度无界，需要另行规定。

```python run id="alg.greedy.knapsack-density"
def by_density(items, capacity):
    """Take the densest item that still fits; items are (weight, value)."""
    chosen, weight = [], 0
    for w, v in sorted(items, key=lambda item: item[1] / item[0], reverse=True):
        if weight + w <= capacity:
            chosen.append((w, v))
            weight += w
    return chosen


def packed(subset):
    return sum(w for w, _ in subset), sum(v for _, v in subset)


capacity = 10
items = [(6, 8), (5, 5), (5, 5)]
greedy = by_density(items, capacity)
optimum = [(5, 5), (5, 5)]          # the only subset whose weight reaches the capacity
print("capacity", capacity, "items (weight, value)", items)
print("  densities       ", [round(v / w, 3) for w, v in items])
print("  density greedy  ", greedy, "-> weight, value", packed(greedy))
print("  true optimum    ", optimum, "-> weight, value", packed(optimum))
```

密度规则取走 (6, 8)，占掉 6 个单位重量，剩下 4 装不下任何一件，价值停在 8；两件 (5, 5) 合起来重量 10、价值 10，才是最优。含 (6, 8) 的可行子集都不能再放一件 (5, 5)（$6 + 5 > 10$），价值至多是 8，所以「密度最高的物品在某个最优解里」这个断言从第一步起就不成立，交换步没有可用的最优解。同一条扫描规则在区间调度上成立，在 0/1 背包上失败，差别落在约束怎样排除局部选择。

## 终止与成本

两个实现都是先排一次序、再扫一遍：循环下标每轮加一，列表有限，循环必然结束。

成本按 <CrossRef id="algorithms.cost-model" /> 的四项说清：哪一种实现、什么成本模型、按什么规模度量、成本怎样量化。

- **区间调度**：$n$ 是区间数，计数单位是结束时刻比较与排序时的区间比较，结论属于最坏情形。排序是 $\Theta(n \log n)$ 次比较（见 <CrossRef id="algorithms.sorting" />），扫描是 $\Theta(n)$ 次比较，合起来是 $\Theta(n \log n)$。输入已经按结束时刻有序时，扫描本身是 $\Theta(n)$。
- **空间**：排序产生一份长度为 $\Theta(n)$ 的引用副本（计数方式见 <CrossRef id="algorithms.arrays-and-lists" />），贪心状态本身是 $\Theta(1)$，输出另计。
- **背包的密度规则**同样是 $\Theta(n \log n)$ 次比较加 $\Theta(n)$ 次容量检查。这个数字描述的是这段实现，与它返回的答案是否最优无关。
