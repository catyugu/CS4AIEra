容量 7，四件物品（重,值）为 (3,5)、(3,5)、(4,6)、(2,3)。取一件 (3,5) 与 (4,6)，重量恰好 7，价值 11——这是目前找到的最好方案。回到只取了一件 (3,5) 的那一步：手头价值 5、剩余容量 4，可以接着取 (4,6)，也可以不取。不取时剩下的物品只有 (2,3)，容量 4 装得下它、值 3，这条走法最好也只能到 $5+3=8$。8 到不了 11，于是它连同下面所有取法被整棵跳过，一个节点都不再展开。

11 是搜索到目前为止拿到的最好值，称**当前最优解**（incumbent）；8 是被跳过的那条分支的**上界**（upper bound）。剪掉一支成立，靠的是这个界**覆盖整棵子树**——子树里每一个可行取法的价值都不超过它。分支定界与回溯共用同一份深度优先枚举骨架 <CrossRef id="algorithms.search-and-pruning" />，每个节点只多出当前最优解与界这两样维护量；节点选择次序不受限制，最优优先同样成立。

```text
root              v=0
├─ take (3,5)     v=5
│  ├─ take (3,5)   v=10
│  └─ skip (3,5)   v=5
│     ├─ take (4,6)   v=11
│     └─ skip (4,6)   v=5   ×
└─ skip (3,5)     v=0       ×
```

树里标 × 的两处都整棵剪掉：一处是上面那条封顶 8 的分支，另一处是根处「不取第一件」的分支，它的界正好追平 11，再往下走也不会更优。

## 最优性剪枝为什么正确

以求最大值为例，记节点 $p$ 处的界为 $U(p)$。跳过 $p$ 的条件是 $U(p) \le best$（$best$ 为当前最优值），这一步合法的前提是 $U(p)$ 覆盖整棵子树：对子树里每一个可行完成 $x$ 都有 $f(x) \le U(p)$。界算小了，就可能把含最优解的分支一起剪掉，算法照常返回一个答案，只是不再最优。界沿父子节点单调下降不是正确性的必要条件——需要的是上面那条覆盖性。

## 0/1 背包的规约

| 项 | 规约 |
| --- | --- |
| 输入 | 物品 $(w_i, v_i)$，$w_i$ 与 $v_i$ 是正整数，$W$ 是非负整数 |
| 可行 | 总重量不超过 $W$ 的子集 |
| 输出 | 最大总价值 |
| 变量 | `best` 搜索到目前为止见过的最大总价值，初始为 0 |
| 界 | `bound(index, room)` 是「只考虑 `index` 之后的物品、容量为 `room`」时任何可行子集总价值的上界 |
| 剪枝 | 当 `value + bound(index, room) <= best` 时整棵子树不必进入 |

## 分数松弛

界的取法决定剪枝的力度。取**分数松弛**：把剩下的物品按价值密度降序摆放，能整件放下就整件放，放不下的那件按比例切开塞满剩余容量。得到的值一定不小于任何整数子集的总价值，因此覆盖整棵子树。这个松弛值正好用来给界——松弛而快的算法专门算界，精确枚举只去走还有希望的分支。

下面的代码把界写成可执行的搜索，密度与按比例切开的贡献都用 `fractions.Fraction` 精确计算。

```python run id="alg.search.knapsack"
from fractions import Fraction


def branch_and_bound(items, capacity, use_bound=True):
    """Postcondition: (best value, nodes visited, a set attaining it).

    The bound is the fractional relaxation of the remaining items, computed so
    that no arithmetic step rounds it down; the number the code compares against
    the incumbent is therefore an upper bound on every completion in the subtree.
    """
    ordered = sorted(items, key=lambda item: Fraction(item[1], item[0]), reverse=True)
    best = {"value": 0, "taken": ()}
    stats = {"nodes": 0}

    def bound(index, room):
        total = Fraction(0)
        for weight, value in ordered[index:]:
            if weight <= room:
                room -= weight
                total += value
            else:
                total += Fraction(value * room, weight)
                break
        return total

    def explore(index, room, value, taken):
        stats["nodes"] += 1
        if value > best["value"]:
            best["value"], best["taken"] = value, taken
        if index == len(ordered):
            return
        weight, item_value = ordered[index]
        if weight <= room:
            explore(index + 1, room - weight, value + item_value, taken + (ordered[index],))
        if not use_bound or value + bound(index + 1, room) > best["value"]:
            explore(index + 1, room, value, taken)

    explore(0, capacity, 0, ())
    return best["value"], stats["nodes"], best["taken"]


cases = [([(6, 8), (5, 5), (5, 5)], 10), ([(4, 6), (3, 5), (3, 5), (2, 3)], 7)]
for items, capacity in cases:
    value, bounded, taken = branch_and_bound(items, capacity)
    _, plain, _ = branch_and_bound(items, capacity, use_bound=False)
    print(f"items {items}, capacity {capacity}")
    print(f"  value {value} from {taken} | nodes with the bound {bounded}, without it {plain}")
```

`use_bound=False` 关掉的正是最优性剪枝这一条：两次运行给出同一个最优值，访问的节点数不同。两次运行返回同一个值只是一次回归检查，不能代替对界合法性的证明——界不直接贡献目标值，却参与搜索的控制流，它的合法性是最终最优性的条件。

## 界的合法性

上面的界合法，是因为它对每个整数子集都成立。放松这条界不会破坏正确性，只降低剪枝能力：把界换成「剩余物品价值之和」，它不考虑剩余容量是否装得下，仍然覆盖整棵子树，但更难触发最优性剪枝，因此可能访问更多节点。

危险在另一个方向：整数贪心填出来的价值**不是合法上界**。它按密度整件整件地放，放不下的跳过，得到的其实是某个可行子集的价值，因而可能低于子树里能达到的最优值。低估落在关键子树上、当前 incumbent 又足够触发这次剪枝时，含有最优解的分支就被整棵跳过，搜索照常返回一个偏小的答案。

```python run id="alg.search.bad-bound"
def optimize(items, capacity, bound):
    """One depth-first search; bound(index, room) is the only plug-in, so swapping
    it swaps the pruning rule."""
    best = 0
    def explore(index, room, value):
        nonlocal best
        best = max(best, value)
        if index == len(items):
            return
        weight, item_value = items[index]
        if weight <= room:
            explore(index + 1, room - weight, value + item_value)
        if value + bound(index + 1, room) > best:
            explore(index + 1, room, value)
    explore(0, capacity, 0)
    return best


def whole_items(items):
    """Bound over items[index:], listed in decreasing density: pack whole items
    while they fit, skip the first one that does not. This is an integer greedy
    value, not a valid upper bound on the subtree."""
    def bound(index, room):
        total = 0
        for weight, value in items[index:]:
            if weight <= room:
                room -= weight
                total += value
        return total
    return bound


tiny, capacity = [(1, 1), (1, 1), (3, 3)], 3
print("whole items only, root bound:", whole_items(tiny)(0, capacity),
      "| best found:", optimize(tiny, capacity, whole_items(tiny)), "| optimum: 3")
```

容量 3 的那个实例只有三个物品：整数贪心填先放进两个各值 1 的物品，把值为 3 的那个物品挡在门外，根处的界因此是 2，而 $(3, 3)$ 单独就把总价值推到 3。这个「界」其实是一个可行子集的价值，从未保证覆盖整棵子树，跳过的正是含最优解的那条分支。

界用舍入的表示计算，是失效的另一条来源。以浮点为例，某一步向下舍入就可能把界压到真实上界以下，剪枝条件 $value + bound \le best$ 错误成立，含最优解的分支被整棵剪掉，搜索照常返回、只是不再最优。用于剪枝的界要在证明所假设的算术里计算——精确有理数就是保证它不被低估的一种实现。

## 界的计算成本

界不直接贡献目标值，但每个节点都要算一次，它的成本要算进每个节点的处理成本里。更紧的界剪掉更多节点，更贵的界抬高每个节点的成本，净效果取决于实例——一个更紧但更贵的界有时反而更慢。
