序列的组织方式是「前一个、后一个」；树把一对多的从属关系写进数据：每个节点有若干子节点，除根之外每个节点恰好有一个父节点。这一层关系是递归的——一棵树的每个子节点各自又是一棵树——所以遍历、高度、节点数这些量都自然写成递归定义；其中遍历的访问次数由节点数 $n$ 决定，而递归所需的辅助空间以及沿根到叶路径执行的操作还受到高度 $h$ 的控制。

同一棵树可以有多种表示，它们交付同一份契约，成本形态却不同。这一节把契约、表示与形状三件事分开讲，后面的二叉搜索树与堆各自在一种表示上继续。

## 树的契约与表示不变量

以下契约针对非空树；实现通常还允许一个「不含任何节点」的空树作为单独状态。

**契约**：一棵树由一组节点与一组父子关系组成，满足

```text
恰好一个根节点没有父节点
其余每个节点恰好有一个父节点
从根出发沿父到子的方向可以到达每个节点（连通）
不存在从节点出发经过若干子节点又回到自己的路径（无环）
```

这四条是为了检查表示而显式列全的性质，并不是四条逻辑独立的条件。事实上，在「恰好一个根没有父节点、其余节点恰有一个父节点、从根可以到达所有节点」都成立时，无环已经随之成立：任何可从根进入的环都会使环入口拥有两个父节点，或者使根本身拥有父节点。反过来，如果不要求根可达所有节点，那么仅有「唯一根 + 非根唯一父」确实允许根所在的树之外再出现独立的有向环。对可变指针表示而言，把「无环」单独列出来仍然有价值，因为一次错误的引用修改就可能破坏这项全局性质。

**子节点的次序是否属于契约**，决定了两种不同的抽象：**有序树**里兄弟之间有次序，遍历顺序是契约的一部分；**无序树**里兄弟之间没有次序，只有集合结构。二叉搜索树与二叉堆都使用左、右孩子位置有区别的有序二叉树结构。这里的「有序」只表示孩子的位置属于抽象结构，并不表示兄弟节点按照键值排好顺序；二叉搜索树的键序不变量与堆序不变量是另外的性质。

**表示**指的是内部状态怎样保存。三种常见形态：

| 表示 | 内部状态 | 访问子节点 | 形状要求 | 就地修改 |
| --- | --- | --- | --- | --- |
| 指针节点 | 每个节点一个对象，持有子节点引用 | 跟随引用，常数成本 | 无 | 改引用即可 |
| 嵌套容器 | 元组或列表的嵌套，子节点是元素 | 索引元素，常数成本 | 无 | 元组不可变，列表可改 |
| 隐式二叉树数组布局 | 一个数组按位置存节点 | 下标算术，常数成本 | 任意二叉形状可用空洞表示；近完全时才紧凑 | 需按下标关系维护 |

这里讨论的数组布局特指**隐式二叉树数组布局**。若一个节点位于下标 $i$，那么它存在的左、右孩子分别放在 $2i+1$ 与 $2i+2$。这个规则本身并不要求树是完全树：任意二叉形状都可以用空槽表示；真正需要接近完全形状的是空间紧凑性。指针节点与嵌套容器可以自然表示任意数量的孩子，而这一套下标公式已经把抽象结构特化成了二叉树。

不同表示对树不变量的保证程度也不同。可变指针节点不会自动阻止同一节点被两个父节点引用，也不会阻止某个孩子重新指向祖先，因此单父与无环必须由更新操作维护。纯粹由有限嵌套元组构成、并把每个出现位置视为一个节点的表示，会由嵌套结构本身给出唯一父位置并排除环；可变列表或共享对象仍可能重新引入别名和环。隐式数组布局中，每个下标 $i > 0$ 只有唯一的候选父下标 $(i-1) // 2$，而且父下标严格小于子下标，因此结构上不可能形成环；连通性还要求每个已占用位置的祖先位置都已占用。

## 遍历与递归结构

遍历顺序由「什么时候访问节点」相对「什么时候进入子节点」决定。对有序树，前序、后序和层序会给出确定的线性序列；对无序树，兄弟之间的相对次序不属于契约，因此遍历结果不唯一。二叉树还定义了中序遍历；它与二叉搜索树的键序直接相关，留到 `ordered-maps` 一节处理：

- 前序：先访问节点，再依次遍历每棵子树。
- 后序：先依次遍历每棵子树，再访问节点。
- 广度优先（层序）：按层从上到下、层内从左到右访问，它不用递归，用队列。

**覆盖与不重复不变量**：一次完整遍历应当使每个节点恰好被访问一次，因此总访问次数必然等于节点数 $n$。但反过来，总次数等于 $n$ 并不能证明遍历正确——完全可能漏掉一个节点，同时重复访问另一个节点。即使已经证明每个节点恰好一次，这也仍然只是遍历正确性的必要条件；前序、后序和层序还分别需要满足自己的次序约束。

```python run id="alg.trees.representations"
import sys


class Node:
    """Pointer representation: one object per node, children in a list."""

    def __init__(self, name, children=()):
        self.name = name
        self.children = list(children)


class SlottedNode:
    """The same, with the per-instance dictionary replaced by a fixed slot layout."""

    __slots__ = ("name", "children")

    def __init__(self, name, children=()):
        self.name = name
        self.children = list(children)


def preorder_pointer(node, visits=None):
    """Postcondition: the node's name, then each child's preorder, in order."""
    visits = visits if visits is not None else []
    visits.append(node.name)
    for child in node.children:
        preorder_pointer(child, visits)
    return visits


def preorder_nested(tree, visits=None):
    """Nested tuples: (name, child, child, ...)."""
    visits = visits if visits is not None else []
    visits.append(tree[0])
    for child in tree[1:]:
        preorder_nested(child, visits)
    return visits


def preorder_array(slots, index=0, visits=None):
    """Array layout: the children of i sit at 2i+1 and 2i+2."""
    visits = visits if visits is not None else []
    if index >= len(slots) or slots[index] is None:
        return visits
    visits.append(slots[index])
    preorder_array(slots, 2 * index + 1, visits)
    preorder_array(slots, 2 * index + 2, visits)
    return visits


pointer_root = Node("A", [Node("B", [Node("D"), Node("E")]), Node("C", [Node("F"), Node("G")])])
nested = ("A", ("B", ("D",), ("E",)), ("C", ("F",), ("G",)))
slots = ["A", "B", "C", "D", "E", "F", "G"]

orders = {
    "pointer nodes": preorder_pointer(pointer_root),
    "nested tuples": preorder_nested(nested),
    "array layout": preorder_array(slots),
}
for label, order in orders.items():
    print(f"{label:>15}: {order}")
print("all three agree:", len({tuple(order) for order in orders.values()}) == 1)

node = pointer_root
slotted = SlottedNode("A", [SlottedNode("B")])
print("dict-backed node:", sys.getsizeof(node), "bytes, plus its instance dict:",
      sys.getsizeof(node.__dict__), "bytes")
print("slot-backed node:", sys.getsizeof(slotted), "bytes")
print("one array slot:", (sys.getsizeof(slots) - sys.getsizeof([])) // len(slots), "bytes")
```

在这个具体的有序二叉树样例上，三种表示得到完全相同的前序序列，说明三个实现对这个实例给出了相同的抽象结构与遍历结果；一次样例本身当然不能证明三种表示在一般情况下等价。后面的字节数也是浅层存储测量：在本课当前的 32 位 WASM 运行时中，普通 `Node` 对象本体实测为 24 字节，其实例字典为 132 字节；`SlottedNode` 对象本体为 24 字节；这个 `list` 分配中每个元素槽位占 4 字节。这些数字不包含被引用的 children 列表、字符串、子节点对象等，因此不能把它们解释成一个完整节点的总内存占用。

## 形状决定成本

树的高度定义为最长的根到叶路径长度（按边计，叶节点高度为 0）。高度同时决定两件事：递归遍历的调用深度，以及在有序结构上做按键查找时需要跟随的引用数。节点数相同、形状不同，高度可以差出数量级。

```python run id="alg.trees.height"
import math


class Node:
    def __init__(self, key, left=None, right=None):
        self.key = key
        self.left = left
        self.right = right


def insert(root, key):
    """Binary search tree insertion; postcondition: the key is present exactly once."""
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root


def build_balanced(values):
    """Precondition: values is sorted ascending. Preorder of values keeps the shape shallow."""
    if not values:
        return None
    middle = len(values) // 2
    return Node(values[middle], build_balanced(values[:middle]), build_balanced(values[middle + 1:]))


def build_ascending(values):
    """Ascending keys make every new node the right child of the previous one."""
    root = None
    for value in values:
        root = insert(root, value)
    return root


def measure(node):
    """Postcondition: (node count, height in edges, maximum non-empty node levels on a root-to-leaf path)."""
    if node is None:
        return 0, -1, 0
    left_nodes, left_height, left_depth = measure(node.left)
    right_nodes, right_height, right_depth = measure(node.right)
    return 1 + left_nodes + right_nodes, 1 + max(left_height, right_height), 1 + max(left_depth, right_depth)


values = list(range(500))
for label, root in (("balanced", build_balanced(values)), ("ascending", build_ascending(values))):
    nodes, height, depth = measure(root)
    print(f"{label:>10}: nodes={nodes:4d}  height={height:3d}  non-empty recursion levels={depth:3d}")
print("the minimum possible height of a 500-node binary tree is", math.floor(math.log2(500)), "- log2(500) =", round(math.log2(500), 2))
```

同一批 500 个键，平衡形状的高度是 8，升序插入得到的链高度是 499。这里 `measure` 报出的非空节点递归层数分别是 9 与 500，也就是 $h+1$。由于这个具体函数还会对空孩子调用一次 `measure(None)`，真正最深的调用链还要多一个基例栈帧，共 501 帧；这个常数差异不改变递归辅助空间为 $\Theta(h)$ 的结论。随着 $h$ 继续增大，这类递归实现最终会受到 Python 递归深度限制（见 <CrossRef id="algorithms.recursion" />）。

高度还控制沿根到叶路径执行的操作：例如二叉搜索树查找一个键时，比较次数至多与 $h+1$ 同阶。所以「树的操作多快」这个问题的答案先落在形状与平衡保证上——这两点是 `ordered-maps` 的主线，堆则讨论另一条形状不变量。

## 数组布局的不变量与代价

数组布局用下标算术代替引用，省掉了每个节点的子指针；它的不变量是两条下标关系，代价落在空间的紧凑性上：

```text
若存在，下标 i 的左、右孩子位于 2i+1 与 2i+2
非根已占用位置 i 的父位置是 (i-1) // 2
```

```python run id="alg.trees.array-layout"
def parent_of(index):
    return (index - 1) // 2


def children_of(index):
    return 2 * index + 1, 2 * index + 2


def orphans(slots):
    """Indices whose parent slot is empty: a violation of the layout invariant."""
    return [index for index in range(1, len(slots))
            if slots[index] is not None and slots[parent_of(index)] is None]


def chain_of(depth):
    """A right-only chain of depth+1 nodes under implicit binary-tree indexing."""
    size = 2 ** (depth + 1) - 1
    slots = [None] * size
    index = 0
    for level in range(depth + 1):
        slots[index] = "node-" + str(level)
        index = 2 * index + 2
    return slots


slots = ["A", "B", "C", "D", "E", "F", "G"]
print("complete shape: slots =", len(slots), "| orphans =", orphans(slots))
print("children of 1 sit at", children_of(1), "| parent of 4 is", parent_of(4))

for depth in (3, 6, 9, 12):
    slots = chain_of(depth)
    used = sum(1 for slot in slots if slot is not None)
    print(f"chain of {depth + 1:2d} nodes: slots={len(slots):5d} used={used:3d} empty={len(slots) - used:5d}")
```

完全形状下数组可以没有空洞；稀疏形状仍然满足同一套下标规则，却可能产生指数级浪费。对连续取右孩子的高度 $h$ 链，最深节点下标为 $2^{h+1}-2$，因此截断到最后一个已用槽位的数组也需要 $2^{h+1}-1$ 个槽位：13 个节点就需要 8191 个槽位。连续取左孩子时需要的槽位数是 $2^{h}$，常数因子不同，但两者都是 $\Theta(2^{h})$。真正的结论是隐式数组对稀疏深树可能发生指数级空洞浪费：具体倍数取决于链的方向，8191 只对全右链成立。

## 成本类别、空间与假设

**规模与形状参数**：节点数 $n$ 是主要的规模参数，高度 $h$ 描述树的形状。保留 $h$ 可以显式写出形状敏感的成本：同样是 500 个节点，高度可以是 8，也可以是 499。

**成本模型**：一次节点访问记 1，一次子节点取值按表示机制计价；这里的引用跟随、序列索引和下标算术都视为常数成本。完整遍历访问每个节点恰好一次，因此时间为 $\Theta(n)$，与形状无关；递归深度优先遍历另需 $\Theta(h)$ 辅助栈空间。

**路径型操作**：在二叉搜索树中，查找、插入等沿一条根到叶路径执行的操作成本为 $\Theta(h)$。未经平衡约束时 $h$ 最坏可以达到 $\Theta(n)$；具有平衡保证时才有 $h = \Theta(\log n)$，从而得到相应的对数时间保证。因此不能笼统地说「树的操作是对数时间」，必须同时说明操作类型与高度保证。

**空间**：节点数是 $\Theta(n)$；每节点的额外开销由表示决定：指针节点至少多一个子引用结构，字典支撑的实例还要一份实例字典，数组布局则是每槽一个引用加可能的空洞。递归遍历另需 $\Theta(h)$ 栈帧，这部分不在节点里。

**假设**：如果采用就地更新，指针节点必须允许修改子引用；指针表示本身并不要求节点可变，不可变树也可以通过路径复制产生新树。嵌套元组不能就地修改，但可以通过构造新的嵌套值完成更新；列表版本可以原地修改。隐式数组可以表示稀疏二叉形状，但只有在形状接近完全树时才保持紧凑。对所有可变表示而言，更新操作都必须维持单父、连通与无环等全局不变量。

**实现对照**。Python 没有内置的树类型，常见写法包括对象加引用、嵌套容器，以及用 `list` 保存近完全二叉树；`heapq` 使用的正是后一种隐式下标关系。Python 的 `dict` 保证的是插入顺序，不是按键排序；需要按键序执行查找、前驱、后继或区间遍历时，需要另外维护具有键序不变量的数据结构。下一节会用二叉搜索树说明这种有序映射。

## 小结

- 树的契约列全了唯一根、单父、连通与无环，但无环在其余三条成立时可以推出；兄弟的次序是否属于契约区分了有序树与无序树。
- 指针节点、嵌套容器、数组布局交付同一份契约，差别在形状要求与每节点开销。
- 遍历顺序由访问节点相对进入子树的时机决定；访问次数等于节点数是必要条件，次序约束要另行验证。
- 高度同时驱动递归深度与查找成本：形状决定它们，节点数不决定。
- 隐式数组布局用下标算术换掉引用，稀疏深树会产生指数级空洞：13 个节点的全右链按该编码也要占 8191 个槽位。
