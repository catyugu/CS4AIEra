一个调度系统不断收到新任务，同时不断取出一项当前优先级最高（按优先级取最小）的任务。两种现成的数组表示都能承接这条工作负载，它们付出线性代价的位置不同。

**无序数组**：新任务追加到末尾，插入是常数时间；取出当前最小必须先扫描整个数组，一次取出是 $\Theta(n)$。按序取出全部 $n$ 个任务要 $n$ 次扫描，总计 $\Theta(n^2)$。

**有序数组**：把最小值放在数组末端，取出就是从末端弹出，不移动其余元素，是常数时间；插入要为新元素腾出位置，把一段连续槽位整体后移，一次插入最坏是 $\Theta(n)$。逐个插入全部任务同样总计 $\Theta(n^2)$。

两种表示各自在一侧付出线性代价：不维持有序，极值就要每次重新扫描；维持有序，插入就要承担整段搬移。这条工作负载从不问第 $k$ 小的元素是谁，也不按键序遍历，它只反复问同一个问题——当前最小是谁。把这份需求精确写下来，它就是<Term id="priority-queue">优先队列</Term>（priority queue）。

## 优先队列的抽象接口

**抽象状态**：一个有限**多重集**（multiset / bag），其中元素可以重复，元素之间按某个全序比较。

| 操作 | 后置条件 |
| --- | --- |
| 插入 $x$ | 增加一个 $x$ 的出现，其余元素不变 |
| 查最小 | 返回全序下的一个最小元素，不改变状态；空队列报告失败 |
| 取出最小 | 返回并移除一个最小元素；空队列报告失败 |
| 替换最小（可选） | 在非空队列中移除一个最小元素并插入新元素，是「取出最小 + 插入」的组合操作 |

接口止于此。它不提供按任意键查找、前驱与后继、按键序整体遍历、按区间取出。这些操作在有序映射里由更强的键序结构支持（见 <CrossRef id="algorithms.ordered-maps" />）；优先队列只保留极值这一组需求，因此可以用更弱的不变量和紧凑的数组表示来实现核心操作。

## 只约束父子关系：两条不变量

优先队列的表示是**堆**（heap）。把键的次序约束放弱到只约束父子之间，够不够支撑「插入 / 查最小 / 取出最小」？两条不变量合起来回答这个问题。

**形状不变量**：堆是一棵**完全二叉树**（complete binary tree）——除最后一层外每层都填满，最后一层从左到右连续填充。

**顺序不变量**（小顶堆）：每个节点的键不大于它的子节点的键。

顺序不变量沿父子链逐级传递，因此根是全树的最小元素；形状不变量把深度压到 $\lfloor \log_2 n \rfloor$，一条根到叶的路径因此很短。顺序不变量直接约束的只有父子对，左右孩子之间没有约束，节点与更深后代之间的次序由传递性给出。堆把约束收窄到父子之间，换来的是一次修改只需沿一条路径恢复堆序。

## 数组里的完全二叉树

用一个密集数组存节点，下标之间的关系就是树结构本身（见 <CrossRef id="algorithms.tree-representation" />）：

| 位置 | 下标 |
| --- | --- |
| 根 | $0$ |
| 下标 $i$ 的左孩子 | $2i + 1$ |
| 下标 $i$ 的右孩子 | $2i + 2$ |
| 下标 $i$ 的父节点 | $\lfloor (i - 1) / 2 \rfloor$ |
| 第一个叶子 | $\lfloor n / 2 \rfloor$ |

只要节点占满连续下标 $0, \dots, n-1$，完全二叉树的形状就由表示本身确定，形状不变量因此**按构造成立**，不需要另做平衡修复；只有表示里真的留下空洞时它才会被破坏。下标 $i$ 的深度是 $\lfloor \log_2 (i + 1) \rfloor$，从下标就能读出它离叶子的距离。基本优先队列不提供「删除任意元素」，抽象接口并不要求定位任意元素；在表示上删除一个中间槽位会移动后继槽位，数组保持连续，形状不变量不受影响，可能被破坏的是堆序。

## 破坏一处，沿一条路径修复

一次插入或一次取出只改动一个元素的位置，堆序却是全局性质。插入把新元素放到数组末尾，取出最小把末尾元素搬到根；不在这条根到叶路径上的父子对两端键都没有变，堆序对它们依旧成立。可能被违反的只有这条路径上的父子对，要证的只有一件事——沿这条路径可以把顺序不变量恢复。

向下的情形最直观：某个节点的键变大之后，它与孩子的关系可能不再成立。把它与两个孩子中较小的那个交换；同一个键在新位置上是否仍违反与两个孩子的关系，继续用同一条规则处理，直到它不再大于任何孩子或到达叶子。交换选较小的孩子，是因为被换上去的键要成为这两个孩子的新父节点，只有不大于两者才能同时满足两对父子关系。

一个小的隐式数组堆把这条路径暴露出来。

```python run id="alg.trees.heap-layout"
items = [1, 4, 3, 9, 5, 7, 8]     # a complete tree stored in array order
items[0] = 10                     # one slot now breaks the heap order


def sift_down(items, index):
    """Restore the heap order along one path; both children already satisfy it."""
    while True:
        left, right = 2 * index + 1, 2 * index + 2
        smallest = index
        for child in (left, right):
            if child < len(items) and items[child] < items[smallest]:
                smallest = child
        if smallest == index:
            return
        items[index], items[smallest] = items[smallest], items[index]
        print("swap", index, "<->", smallest, "->", items)
        index = smallest


print("broken  :", items)
sift_down(items, 0)
print("repaired:", items)
```

覆写的根 $10$ 与较小的孩子 $3$ 交换，沿着 $0 \to 2 \to 5$ 这条路径下移两次：第一次把 $3$ 送上去，第二次把 $7$ 送上去，$10$ 落到下标 $5$；下标 $5$ 没有孩子，循环在那里停下。每一层只比较当前节点的两个孩子，路径长度不超过高度 $\lfloor \log_2 n \rfloor$，所以一次向下调整是 $O(\log n)$。覆写的位置与数值决定这条路径，其余槽位上的键保持原来的相对位置；数组长度不变，形状不变量不动。

插入的方向相反。新元素落在末尾，是叶子，没有后代，唯一可能被违反的父子对是它与父节点。若它不小于父节点，堆序已经成立；否则交换它与父节点，问题变成同一个键在新位置上是否仍违反与父节点的关系。位置每交换一次上移一层，直到根或不再违反。修正只沿一条向上的根路径，长度同样不超过 $\lfloor \log_2 n \rfloor$，插入的调整因此是 $O(\log n)$；数组只追加了一个元素，形状不变量不动。

## 一次建堆：heapify

已经拿到一个完整数组时，逐个插入是 $n$ 次向上调整、每次代价 $O(\log n)$，最坏 $\Theta(n \log n)$。另一种做法从最后一个**有孩子**的下标往前扫，对每个下标做一次向下调整：处理下标 $i$ 时，它的两个孩子已经各自是合法子堆，向下调整只需在它这条路径上把键送到该在的位置。

```python run id="alg.trees.heapify"
import math

items = [9, 4, 7, 1, 8, 3, 6, 2, 5, 0]    # an arbitrary array, heap order not yet attained
comparisons = 0


def sift_down(items, index):
    """Restore the heap order along one path; both children already satisfy it."""
    global comparisons
    while True:
        left, right = 2 * index + 1, 2 * index + 2
        smallest = index
        for child in (left, right):
            if child < len(items):
                comparisons += 1
                if items[child] < items[smallest]:
                    smallest = child
        if smallest == index:
            return
        items[index], items[smallest] = items[smallest], items[index]
        index = smallest


print("plain:", items)
for index in range(len(items) // 2 - 1, -1, -1):
    sift_down(items, index)
print("heapified:", items)
print("comparisons:", comparisons, "| n =", len(items), "| n log2 n =", round(len(items) * math.log2(len(items))))
```

线性界可以按「节点还能向下走多少层」计数：能够向下至少 $1$ 层的节点至多约 $n/2$ 个，能够向下至少 $2$ 层的至多约 $n/4$ 个，至少 $3$ 层的至多约 $n/8$ 个，以此类推。所有节点能够执行的向下移动总数因此满足

$$\frac{n}{2} + \frac{n}{4} + \frac{n}{8} + \dots = O(n).$$

每下降一层只做常数次比较与移动，所以总工作是 $O(n)$；另一方面，处理 $\lfloor n/2 \rfloor$ 个非叶节点已经需要 $\Omega(n)$ 的基本工作，两头夹紧得 $\Theta(n)$。逐个插入则是 $n$ 条根路径、每条最长 $\lfloor \log_2 n \rfloor$，最坏 $O(n \log n)$。

在 $n = 10$ 的样例上，一次建堆用了 $14$ 次比较，约为 $1.4\,n$；逐个插入的最坏上界是 $n \lfloor \log_2 n \rfloor = 30$ 次比较，每条根路径都要走 $\lfloor \log_2 n \rfloor$ 层。$n \log_2 n = 33$ 给出这个规模的渐近量。单个规模上的两个数字推不出渐近阶；能够无条件下结论的是 $O(n \log n)$ 与 $\Theta(n)$ 这两个界。

## 堆不提供什么

堆的表示与不变量只服务极值这一组操作，把其余查询放到堆上就失去了它们的保证：

| 需求 | 堆表示上的位置 | 实际成本 |
| --- | --- | --- |
| 查最小 | 下标 $0$ | $O(1)$ |
| 最大键 | 没有固定位置，最大元素必定位于某个叶子 | 扫描全部叶子 $\Theta(n)$ |
| 第 $k$ 小 | 没有直接位置 | 连续取出最小 $k$ 次，最坏 $O(k \log n)$ |
| 按值查找 | 没有由不变量给出的路径 | 最坏 $\Theta(n)$ |
| 按键序取出 | 没有；连续取出最小产生升序 | 建堆 $\Theta(n)$ 加 $n$ 次取出，最坏 $\Theta(n \log n)$ |

最大元素为什么在叶子上：如果某个最大元素出现在内部节点，它的孩子既不小于它（堆序），也不大于全局最大值，因此孩子同样是最大元素；沿这样的孩子继续向下，最终到达一个包含最大元素的叶子。按值查找缺少类似的裁决：堆序可以在某节点已经大于目标时剪掉它的子树，却不能保证每次都排除一半。按键序取出就是把堆当作排序器用，建堆 $\Theta(n)$ 后连续取出，最坏 $\Theta(n \log n)$。

```python run id="alg.trees.heap-limits"
items = [0, 2, 1, 5, 3, 4, 6]     # a min-heap, in array order
print("as stored :", items)
print("sorted    :", sorted(items))
print("minimum at index 0; maximum at index", items.index(max(items)))
```

数组按堆序存放，同一个数组的排序序是另一份排列；根是全局最小，最大键落在某个叶子上，下标并不指向它。这几项缺失是接口选择的结果：优先队列只保证最小，堆用紧凑的数组表示把它的成本压到常数与对数。

堆的结论分属最坏与摊还两种类别（一次两个数组槽位的交换记 2 次移动）：查最小为 $O(1)$；插入与取出最小的堆序调整最坏为 $\Theta(\log n)$；一次建堆为 $\Theta(n)$；连续取出全部元素的总时间最坏为 $\Theta(n \log n)$。数组末尾追加的成本由底层动态数组的容量管理决定，属于摊还模型（见 <CrossRef id="algorithms.amortized" />），因此基于动态数组的 push 总体应理解为摊还 $O(\log n)$；堆结构本身不使用概率分析，摊还只来自底层动态数组的容量管理。空间上需要 $\Theta(n)$ 个数组槽位。

**实现边界**：在 Python 中这些槽位保存的是对象引用；动态数组的容量可能暂时大于元素数，这是容量与逻辑长度分离的常见情形；相等元素的相对次序不在契约内（堆序只要求父子之间 `<=`），需要稳定次序时要另外保存序号。[`heapq`](https://docs.python.org/3/library/heapq.html) 把堆当作普通 `list` 上的函数集合（`heapq.heapify` 建堆，`heapq.heappush` / `heapq.heappop` 是插入与取出最小，`heapq.heapreplace` 合并两者，`heapq.nlargest` / `heapq.nsmallest` 是部分选择），不提供按键序遍历，空堆上的取出抛出 `IndexError`。
