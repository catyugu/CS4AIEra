一批按键排序的键值集合，除了「某个键存了什么」，还要回答一批按序关系的问题：最小的键是谁、某个键的前驱与后继是谁、区间 $[a, b]$ 里有哪些键、按键序把全部键列一遍。哈希映射只按相等关系定位，这些问题它答不了（见 <CrossRef id="algorithms.maps-and-sets" />）。

同一批 500 个键、同一段查找代码、同一个被查找的键，一次访问 9 个节点，另一次访问 500 个。两次的键个数相同、比较代码相同，差别落在树的形状上。形状由什么写定，成本又落在哪个量上？

## 成本由高度决定

**表示**：每个节点保存一个键、一个左子树引用与一个右子树引用。

**表示不变量**：对每个节点 $x$，左子树里的所有键都小于 $x$ 的键，右子树里的所有键都大于 $x$ 的键。这条约束管的是整棵子树里的全部键；只检查一个节点与它直接相连的孩子是更弱的条件，满足它的树仍然可以让一次查找走错方向。

一次键比较因此决定往哪边走，查找沿一条从根向下的路径前进。剩下的量只有一个——这条路径有多长。下面用最少的部件读出这个长度：两种插入顺序写同一批 500 个键，再读回树高与最深的那次查找访问多少节点。

```python run id="alg.trees.bst-costs"
class Node:
    __slots__ = ("key", "left", "right")

    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right


def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root


def height(node):
    return -1 if node is None else 1 + max(height(node.left), height(node.right))


def middle_out(values):
    if not values:
        return []
    middle = len(values) // 2
    return [values[middle]] + middle_out(values[:middle]) + middle_out(values[middle + 1:])


keys = list(range(500))
for label, order in (("ascending", keys), ("middle-out", middle_out(keys))):
    root = None
    for key in order:
        root = insert(root, key)
    print(f"{label:>10}: height {height(root):3d} | deepest lookup visits {height(root) + 1:3d}")
```

同一批 500 个键，升序插入让每个新键都接在当前最右节点之后，得到一条链，高度 499；中位数优先的顺序（先放中位，左右两半再各自按同样方式排）得到高度 8 的树，与 $\log_2 500$ 同阶。一次查找在路径上每个非空节点按键比较决定方向（先判相等，再判大小，最多两次比较），命中即停，因此访问的节点数不超过 $h + 1$：链上最深的一次查找是 500 个节点，平衡形状上是 9 个。**成本由高度决定**，而高度完全由插入顺序写定。`height` 把空树的高度取为 $-1$，所以 $h = 8$ 对应 9 个节点的路径。

按升序或降序插入 $n$ 个键，高度就是 $n - 1$，单次操作退化到 $\Theta(n)$。对「插入顺序是随机排列」这一分布，树的期望高度是 $O(\log n)$；这是关于分布的期望，它对任意输入都不给出保证，也不排除某个具体输入退化成链。仅凭 BST 不变量推不出 $O(\log n)$：它约束的是键的次序，对树的形状不作任何要求。要拿到对数级的**保证**，需要对形状本身再提出一条要求。

**实现边界**：`height` 与 `insert` 写成递归，调用深度随树高增长，链形状上的深度达到 $n$，会先撞到解释器的递归深度上限（见 <CrossRef id="algorithms.recursion" />）；改成沿路径循环只改变常数与栈空间，不改变成本由高度决定这一结论。上面的数字计的是访问的节点数与键比较次数；节点用对象表示时，每个节点另带固定的对象开销，长字符串键的一次比较本身也随键长增长，比较次数与比较成本要分开算。

## 有序映射的抽象接口

把表示与不变量要求的东西精确写下来，就是**有序映射**（ordered map）：

**抽象状态**：一组 (键, 值) 条目，键互不相等，且键集合上定义了一个全序。

| 操作 | 后置条件 |
| --- | --- |
| 查找 $k$ | 返回 $k$ 对应的值，不存在则返回缺失标志 |
| 插入 $(k, v)$ | $k$ 映射到 $v$；其余键的映射不变；键集合仍互不相等 |
| 删除 $k$ | $k$ 不再映射到任何值；其余键的映射不变 |
| 最小键 / 最大键 | 返回全序下最小 / 最大的键，空映射返回缺失标志 |
| 后继 / 前驱 $k$ | 返回全序下大于 / 小于 $k$ 的最小 / 最大键，不含 $k$ 本身 |
| 区间 $[a, b]$ | 按升序返回全序落在 $[a, b]$ 内的键 |

接口里的顺序必须是**全序**（total order）：比较具有传递性，并且任意两个不同的键 $a, b$ 中恰有一个满足 $a < b$ 或 $b < a$。哈希表表示要求键上有相等关系，并额外需要一个与相等一致的哈希值，Python 因而要求 `dict` 的键可哈希；有序映射需要的是键上的全序，与可哈希性无关——基于比较的树可以接受不可哈希但可比较的键。两者是对键的两种独立要求。完整中序遍历按键序访问全部键，不变量直接保证它按升序：左子树的键全部更小、右子树的键全部更大，「先左、再节点、再右」的访问顺序恰好是全序下的升序。

表中前三项各自只沿一条向下路径工作，最小键、最大键、前驱与后继也各自沿一条路径工作；区间查询与完整中序遍历要进入更多节点。这一批操作的单价因此统一落在树高上。

## 插入与删除只改一条路径

插入沿一条路径下降到空位置，把新键挂在那里。新键与路径上每个节点的大小关系都检查过，不变量因此在路径上成立；未经过的子树不受影响。已有键在完整映射中只更新值，键集合仍互不相等。

删除分三种情况。节点是叶子时直接剪掉；只有一个孩子时用那个孩子顶替它的位置。两个孩子都在时，节点不能直接剪掉，否则两个子树没有位置可放；可行的替身是**右子树的最小键**，也就是该节点的中序后继。它大于左子树的所有键、小于右子树其余所有键，放到节点位置后两条不等式都保持。选前驱做替身同样可行，不变量论证对称。找到后继与把它从原位置摘掉可以在一次下降里完成。

插入与删除都只沿一条向下路径工作，成本为 $O(h)$，最坏是 $\Theta(h)$。以条目数 $n$ 为规模，完整中序遍历访问每个节点恰好一次，因此按键序取出全部键是 $\Theta(n)$。

**实现边界**：删除两孩子节点时替换的是整个 (键, 值) 条目。若允许重复键，还需要额外的消解规则（计数、链表或明确的取舍），它不由 BST 不变量本身给出。

## 按键序的查询

接口多出来的那几个操作靠同一点：不变量给出了方向，要更大的键就往右走，要更小的往左走。最小键从根一路向左，后继从根走到叶，各自是一条路径。区间查询按中序剪枝，只进入仍可能包含区间内键的子树——下面这棵 7 个节点的树里，区间 $[25, 65]$ 只进入 5 个节点。

```python run id="alg.trees.ordered-query"
class Node:
    __slots__ = ("key", "left", "right")

    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right


tree = Node(50, Node(20, Node(10), Node(30)), Node(70, Node(60), Node(80)))

entered = []


def range_keys(node, low, high):
    if node is None:
        return []
    entered.append(node.key)
    out = range_keys(node.left, low, high) if node.key > low else []
    if low <= node.key <= high:
        out.append(node.key)
    if node.key < high:
        out.extend(range_keys(node.right, low, high))
    return out


window = range_keys(tree, 25, 65)
print("keys in [25, 65]:", window)
print("nodes entered:", len(entered), "of 7:", entered)
```

输出里的 `[30, 50, 60]` 是区间内的键，升序；进入的节点是 `[50, 20, 30, 70, 60]`，节点 10 与 80 被剪掉：20 的键已经小于下界 25，它的整棵左子树不可能落在区间内；70 的键已经大于上界 65，它的右子树同样不可能。区间查询的时间上界是 $O(h + k)$，$k$ 是输出的键数，$h$ 来自两端搜索边界；最坏情形达到 $\Theta(h + k)$。

哈希结构只按相等关系定位，最小键、前驱后继与区间内的键都不在它的能力里：要得到区间内的键，必须扫描全部键，代价是 $\Theta(n)$。按键序的查询因此需要在键上定义全序，并把这份顺序写进表示。

## 把高度压到对数级：平衡树

普通 BST 对形状不作要求，高度可以坏到 $\Theta(n)$，那批路径操作的 $O(h)$ 保证也就可能退化到线性。要拿到对数级的保证，需要在 BST 不变量之外再维持一条限制形状的**平衡不变量**。自平衡搜索树（self-balancing search tree）靠这样一条不变量工作，例如 AVL 树要求每个节点的左右子树高度差至多为 1。这条不变量推出 $h = O(\log n)$，再加上任何二叉树容纳 $n$ 个节点都需要 $h = \Omega(\log n)$，便得到 $h = \Theta(\log n)$。

代价落在更新维护上：插入或删除之后要检查并恢复平衡条件，经典实现用**旋转**改变少数引用，同时保持中序序列不变；节点中还保存平衡因子、高度或子树大小等少量元数据。对数高度由这套额外维护换来，BST 不变量本身给不出它。

同一个抽象接口也有别的表示，取舍落在更新一侧：

| 表示 | 键上需要的结构 | 最小键 / 后继 / 区间 | 插入 |
| --- | --- | --- | --- |
| 哈希映射（`dict`） | 相等关系与一个一致的哈希值 | 不支持，要扫描全部键 | 摊还 $O(1)$ |
| 有序数组 | 全序与排好序的连续槽位 | 二分查找 $O(\log n)$，区间一次切片 | 搬移插入点之后的引用，最坏 $\Theta(n)$；末端追加是摊还 $O(1)$（见 <CrossRef id="algorithms.amortized" />） |
| 普通二叉搜索树 | 全序与每个节点的左右子树引用 | 沿一条路径 $O(h)$，区间 $O(h + k)$ | $O(h)$，$h$ 无保证 |
| 平衡搜索树 | 全序与平衡元数据 | 沿一条路径 $O(\log n)$，区间 $O(\log n + k)$ | $O(\log n)$ |

Python 没有内置的平衡树；`dict` 保证插入顺序，不提供按键序的查找，也不提供前驱、后继与区间操作。需要在语言里直接使用有序映射时，常见做法是第三方平衡树实现或数据库索引。

合起来：普通 BST 用节点上的次序不变量实现有序映射的抽象接口，查找、插入、删除、最小键、前驱与后继都沿一条根到叶路径前进，单次时间是 $O(h)$，最坏情形是 $\Theta(h)$；只有当插入顺序是随机排列时期望高度才落到 $O(\log n)$，任意输入都可以退化到线性。加上平衡不变量之后 $h = \Theta(\log n)$，这些操作才具有 $O(\log n)$ 的最坏时间保证，代价是更新路径上额外的平衡维护。
