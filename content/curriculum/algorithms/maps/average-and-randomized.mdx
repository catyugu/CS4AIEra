哈希表查找记作期望常数成本：负载因子受控时，一次查找平均只探测少数几个位置。这个「平均」取在什么上？桶数与键集固定之后，一次查找探测几个位置就是一个确定的数；要让它成为随机变量，需要额外引入随机性。

## 最小概率工具

一次查找的成本只有三种取值：1、2、5，概率分别是 $1/2$、$1/4$、$1/4$。把每个成本乘上它的概率再相加，一次查找平均花

$$
\frac{1}{2}\cdot 1 + \frac{1}{4}\cdot 2 + \frac{1}{4}\cdot 5 = 0.5 + 0.5 + 1.25 = 2.25.
$$

把这件事一般化，就得到**期望**：一次运行的成本是随机变量 $T$，取值有限时按概率加权，$E[T] = \sum_t t \cdot P(T = t)$。

成本里出现随机量，只可能是输入在变，或者算法自己在掷硬币。前者是平均情形：针对规模 $n$ 的输入先给定一族分布 $D_n$，成本对这个分布取期望：

$$
C_{\text{avg}}(n) = E_{X \sim D_n}[C(X)] = \sum_{x : \lvert x \rvert = n} D_n(x) \cdot C(x)
$$

没有分布就没有结论；换掉 $D_n$，原先的结论要重新验证，结果可能改变。后者把随机性放进算法内部：输入 $x$ 固定，算法自己产生随机位 $R$，成本是 $E_R[C(x, R)]$——哈希表查找的常数成本取在算法随机位 $R$ 上，省略的是哈希把键分散开的假设（<CrossRef id="algorithms.hash-tables" />）。

**指示器与线性性。** 事件 $A$ 的指示器 $[A]$ 取值 0/1，$E[[A]] = P(A)$。一个总次数可以写成若干指示器之和，期望随之拆成若干概率之和：

$$
\begin{aligned}
\text{线性查找的比较次数} &= \sum_{i=0}^{n-1} [\text{第 } i \text{ 次比较发生}] \\
E[\text{比较次数}] &= \sum_{i=0}^{n-1} P(\text{第 } i \text{ 次比较发生})
\end{aligned}
$$

拆分成立的依据是**期望的线性性**：对期望有限的随机变量，$E[X + Y] = E[X] + E[Y]$；更一般地，$T = T_1 + \cdots + T_k$ 时 $E[T] = \sum_j E[T_j]$。各部分之间通常明显相关，线性性照样成立。独立性只是充分条件：只有当某一步明确把联合概率分解为概率之积，或调用一个以独立性为前提的概率界时，才需要它。

## 平均情形先给出分布

线性查找的成本取决于目标在序列中的位置。同一个实现，两种分布，两个结论。

```python run id="alg.avg.linear-search"
def search(items, target):
    """Return the number of comparisons the lookup costs."""
    for index, item in enumerate(items):
        if item == target:
            return index + 1
    return len(items)          # absent: the scan runs to the end


size = 100
items = list(range(size))
present = [items[0], items[24], items[74], items[99]]
absent = size + 1

for target in present:
    print(f"target at index {target:>3}: comparisons={search(items, target)}")
print(f"target absent          : comparisons={search(items, absent)}")

uniform_mean = sum(search(items, items[k]) for k in range(size)) / size
print(f"uniform over all positions: exact mean comparisons={uniform_mean}")
print(f"every target absent       : exact mean comparisons={size}")
print("closed form (n + 1) / 2 =", (size + 1) / 2)
```

均匀分布下，第 $i$ 次比较发生的概率是 $(n - i)/n$——目标落在第 $i$ 个位置或更靠后，共 $n - i$ 个位置。把每次比较写成指示器再求和，$\sum_{i=0}^{n-1}(n - i)/n$ 恰好化成 $(n + 1)/2$，用到的假设只有期望的线性性；目标必然不存在时，每个位置的比较都发生，求和得 $n$。两种分布给出不同的**精确**期望，渐近量级却都仍是 $\Theta(n)$，目标总在第一个位置时是 $\Theta(1)$。$(n + 1)/2$ 的推导采用「目标等可能地位于任意位置」这个分布；只给出这个期望而不声明所采用的分布，论断是不完整的。

## 探测长度的期望

哈希表查找的成本是「定位一个桶」加「在冲突链或探测序列中比较的次数」，两部分都由哈希把键落到哪些位置决定；两种冲突策略在 <CrossRef id="algorithms.hash-tables" />。键集固定后，剩下的随机性由算法自己引入：哈希函数从某个函数族中选取。取期望的对象是 $E_R[\cdot]$，与输入分布无关。

把 <Term id="load-factor">负载因子</Term>记作 $\alpha = n/m$——$n$ 个已存键，$m$ 个槽位。**均匀探测**（uniform probing）把一次查询的探测序列建模为槽位的一个随机排列：每次从未探测过的槽位里均匀取一个，取过的不再取。第 $i$ 次探测发生，要求前 $i - 1$ 次都落在已占用的槽位上；第 $j$ 次取到已占槽位的条件概率是 $(n - j + 1)/(m - j + 1)$，已占槽位与剩余槽位同时减少。把探测次数写成指示器之和 $T = \sum_{i \ge 1}[\text{第 } i \text{ 次探测发生}]$，取期望后由线性性逐项相加：

$$
E[T] = \sum_{i \ge 1} \prod_{j = 1}^{i - 1} \frac{n - j + 1}{m - j + 1}.
$$

每一项的因子都不超过 $n/m$：$n \le m$ 时 $\frac{n - j + 1}{m - j + 1} \le \frac{n}{m}$，所以第 $i$ 项不超过 $\alpha^{i - 1}$；无放回地取过 $n$ 个已占槽位之后，下一次必然取到空槽，探测次数因此不超过 $n + 1$。两头夹住这条和式，得到：

$$
E[T] \le \sum_{j \ge 0} \alpha^{j} = \frac{1}{1 - \alpha}.
$$

$\frac{1}{1 - \alpha}$ 是均匀探测下的**上界**：$\alpha$ 小时它已经紧贴精确期望，$\alpha$ 趋近 $1$ 时逐项放缩的累积差与截断一起把它抬高。实测值、精确和式与这条上界并排放在一次运行里。

```python run id="alg.avg.probe-cost"
import random

capacity, seed, trials = 512, 20261003, 20000
rng = random.Random(seed)


def exact_mean(capacity, filled):
    """Uniform probing: the probe sequence is a permutation of the slots."""
    total, term = 0.0, 1.0
    for step in range(filled + 1):
        total += term
        term *= (filled - step) / (capacity - step)
    return total


def measured_mean(capacity, filled):
    """Draw from the unprobed slots and stop at the first empty one."""
    total = 0
    for _ in range(trials):
        probes, occupied_left, slots_left = 0, filled, capacity
        while True:
            probes += 1
            if rng.randrange(slots_left) >= occupied_left:
                break
            occupied_left -= 1
            slots_left -= 1
        total += probes
    return total / trials


print(f"capacity = {capacity} slots, {trials} searches per row")
print(f"{'filled':>7} {'alpha':>6} {'measured':>9} {'exact sum':>10} {'1/(1-alpha)':>12}")
for filled in (256, 384, 448, 486):
    alpha = filled / capacity
    print(f"{filled:>7} {alpha:>6.3f} {measured_mean(capacity, filled):>9.2f}"
          f" {exact_mean(capacity, filled):>10.3f} {1 / (1 - alpha):>12.3f}")
```

表里每行三个数：同一批无放回探测下实测的平均值、上面那条精确和式、以及 $\frac{1}{1 - \alpha}$ 这条上界。低负载处这条上界在数值上很接近精确期望，高负载处两者的差随 $\alpha$ 增大。

这条界依赖均匀探测这个模型：探测序列是槽位的一个随机排列，每次落到哪个槽位与前几次无关。线性探测做不到这一点——它把冲突的键排成连续的占用区间，相邻区间会合并，一次查找扫过的槽位比这个模型多；哈希表实现里通常测的又是多次插入中最长的一次探测，与这里的平均探测次数不是同一个量。真实实现里探测序列由哈希函数决定，键集由对手挑出时随机排列的前提并不成立，随机化哈希正是为补上这个前提准备的。
