哈希表查找记作期望常数成本：负载因子受控时，一次查找平均只探测少数几个位置。这个「平均」取在什么上？桶数与键集固定之后，一次查找探测几个位置就是一个确定的数；它成为随机变量，只可能来自两处：被查找的目标从某个输入分布里抽出，或者算法在运行时自己掷硬币，而目标固定。两种取平均写成的量词位置不同，承诺的形状也不同——一个对整族输入负责，一个对每一条固定输入负责。

## 对什么取平均

针对规模 $n$ 的输入，**平均情形**先给定一族分布 $D_n$，成本再对这个分布取期望：

$$
C_{\text{avg}}(n) = E_{X \sim D_n}[C(X)] = \sum_{x : \lvert x \rvert = n} D_n(x) \cdot C(x)
$$

没有分布就没有结论；换掉 $D_n$，原先的结论要重新验证，结果可能改变。

**随机化算法**把随机性放进算法内部：输入 $x$ 固定，算法自己产生随机位 $R$，成本是 $E_R[C(x, R)]$。它的承诺是一条对每个输入都成立的期望界：

$$
\exists\, c > 0, n_0,\quad \forall x:\, \lvert x \rvert \ge n_0 \Rightarrow E_R[C(x, R)] \le c \cdot f(\lvert x \rvert)
$$

常数 $c$ 与规模门槛 $n_0$ 不依赖 $x$——「对每个输入成立」指的就是这一点；若把每个 $x$ 各自的常数收进 $O$ 记号，这条界退化成一个逐点的上界，统一常数这一内容随之消失。

这条界依赖一条前提：随机位在挑输入的一方选定输入之后才产生。输入先定、算法再掷硬币，对方就无从预知这一次会走哪条路径；能在运行过程中观察并继续构造输入的适应性对手另当别论。哈希表查找的常数成本落在这一侧：说「哈希表查找是 $O(1)$」时省略的是哈希把键分散开的假设，那是键集固定、对哈希函数的随机性取的期望（<CrossRef id="algorithms.hash-tables" />）；随机基准点快速排序的 $n \log n$ 同样是「对每个输入成立」的期望（<CrossRef id="algorithms.comparison-sorting" />）。

## 期望与线性性

一次运行的成本是随机变量 $T$，取值有限时，期望是按概率的加权平均：$E[T] = \sum_t t \cdot P(T = t)$。**指示器随机变量**把事件变成 0/1 计数：事件 $A$ 的指示器满足 $E[[A]] = P(A)$，于是一个总次数可以写成若干指示器之和，期望随之拆成若干概率之和：

$$
\begin{aligned}
\text{线性查找的比较次数} &= \sum_{i=0}^{n-1} [\text{第 } i \text{ 次比较发生}] \\
E[\text{比较次数}] &= \sum_{i=0}^{n-1} P(\text{第 } i \text{ 次比较发生})
\end{aligned}
$$

**期望的线性性**是这条拆分成立的依据：对期望有限的随机变量，$E[X + Y] = E[X] + E[Y]$；更一般地，$T = T_1 + \cdots + T_k$ 时 $E[T] = \sum_j E[T_j]$。各部分之间通常明显相关，线性性照样成立。独立性只是充分条件：只有当某一步明确把联合概率分解为概率之积，或调用一个以独立性为前提的概率界时，才需要它。

下面两个指示器由同一次抽取决定，第二个事件包含第一个事件，因此两者相关：

```python run id="alg.avg.linearity"
size, threshold = 4, 2


def indicators(first, second):
    """Two indicators from one draw of two values."""
    return (1 if first < threshold else 0,
            1 if first < threshold or second < threshold else 0)


outcomes = [indicators(a, b) for a in range(size) for b in range(size)]
weight = 1 / len(outcomes)
mean_x = sum(x for x, _ in outcomes) * weight
mean_y = sum(y for _, y in outcomes) * weight
mean_sum = sum(x + y for x, y in outcomes) * weight

p = threshold / size
print(f"E[X] = {mean_x:.4f}  closed form p = {p:.4f}")
print(f"E[Y] = {mean_y:.4f}  closed form 1-(1-p)^2 = {1 - (1 - p) ** 2:.4f}")
print(f"E[X+Y] = {mean_sum:.4f}  sum of the two = {p + 1 - (1 - p) ** 2:.4f}")
print("joint values:", sorted(set(outcomes)))
```

三行的精确值与闭式相符，恒等式本身来自期望的线性性。联合取值只有三种：$X = 1$ 时 $Y$ 必然是 $1$，于是 $P(Y = 0 \mid X = 1) = 0$ 而 $P(Y = 0) > 0$——两个指示器明显相关，线性性不因相关性失效。

## 平均情形要先写分布

线性查找的成本取决于目标在序列中的位置。同一个实现，两种分布，两个结论。

```python run id="alg.avg.linear-search"
def search(items, target):
    """Return the number of comparisons the lookup costs."""
    for index, item in enumerate(items):
        if item == target:
            return index + 1
    return len(items)          # absent: the scan runs to the end


size = 100
items = list(range(size))
present = [items[0], items[24], items[74], items[99]]
absent = size + 1

for target in present:
    print(f"target at index {target:>3}: comparisons={search(items, target)}")
print(f"target absent          : comparisons={search(items, absent)}")

uniform_mean = sum(search(items, items[k]) for k in range(size)) / size
print(f"uniform over all positions: exact mean comparisons={uniform_mean}")
print(f"every target absent       : exact mean comparisons={size}")
print("closed form (n + 1) / 2 =", (size + 1) / 2)
```

两种分布给出不同的**精确**期望，渐进量级却都仍是 $\Theta(n)$。上面那几条输入已经把成本的结构摆出来：目标排在第 $k$ 个位置（从 1 数起）要比较 $k$ 次，目标不存在要比较 $n$ 次。

要得到均匀分布下的 $(n + 1)/2$，只需要算一件事：第 $i$ 次比较发生的概率。把第 $i$ 次比较写成指示器，等可能命中时它取 $1$ 当且仅当目标落在第 $i$ 个位置或更靠后——共 $n - i$ 个位置，概率是 $(n - i)/n$；对这些指示器取期望再求和，$\sum_{i=0}^{n-1}(n - i)/n$ 恰好化成 $(n + 1)/2$。这一步用到的假设只有期望的线性性。目标必然不存在时，每个位置的比较都发生，求和得 $n$。

**同一段代码，同一个规模，两个不同的结论**。换别的分布还可能改变量级——目标总在第一个位置时是 $\Theta(1)$。$(n + 1)/2$ 的推导采用「目标等可能地位于任意位置」这条分布；只给出这个期望而不声明所采用的分布，论断是不完整的。

## 探测长度的期望

哈希表查找的成本是「定位一个桶」加「在冲突链或探测序列中比较的次数」，两部分都由哈希把键落到哪些位置决定；两种冲突策略与桶数组的表示不变量在 <CrossRef id="algorithms.hash-tables" />。键集固定下来以后，剩下的随机性在算法这一侧：哈希函数从某个函数族中选取，探测序列按某个模型生成。取期望的对象是 $E_R[\cdot]$，与输入分布无关。

把 <Term id="load-factor">负载因子</Term>记作 $\alpha = n/m$——$n$ 个已存键，$m$ 个槽位。均匀探测模型把一次查询的探测序列建模为独立、均匀的槽位取样。查询的第 $i$ 次探测发生，当且仅当前 $i - 1$ 次都落在已占用的槽位上，这个概率是 $\alpha^{i-1}$。把探测次数写成指示器之和 $T = \sum_{i \ge 1}[\text{第 } i \text{ 次探测发生}]$，取期望后由线性性逐项相加：

$$
E[T] = \sum_{i \ge 1} P(\text{第 } i \text{ 次探测发生}) = \sum_{j \ge 0} \alpha^{j} = \frac{1}{1 - \alpha}
$$

$\alpha < 1$ 时几何级数收敛，探测长度的期望由 $\frac{1}{1 - \alpha}$ 控制，$\alpha$ 趋近 $1$ 时它急剧上升。这条推导只用到期望的线性性，与各处探测是否独立无关。

固定的桶数与一批固定的键下测出这条曲线：

```python run id="alg.avg.probe-cost"
import random

capacity, keys = 512, [f"key-{index:03d}" for index in range(500)]
rng = random.Random(20260605)

def mean_probes(filled, trials=40000):
    """Uniform probing: each probe samples a slot and stops at the first empty one.
    Only the number of occupied slots enters, so they are the first `filled` slots."""
    total = 0
    for _ in range(trials):
        probes = 0
        while True:
            probes += 1
            if rng.randrange(capacity) >= filled:
                break
        total += probes
    return total / trials


print(f"capacity = {capacity} slots, {len(keys)} fixed keys")
for count in (256, 384, 448, 486):
    alpha = count / capacity
    print(f"keys = {count:3d}  alpha = {alpha:.3f}  measured = {mean_probes(count):7.2f}"
          f"  1/(1-alpha) = {1 / (1 - alpha):7.2f}")
```

四行实测值是 $2.01$、$3.99$、$7.95$、$19.74$，同一行的 $1/(1 - \alpha)$ 是 $2.00$、$4.00$、$8.00$、$19.69$，偏差落在抽样波动之内。单元格里每次探测独立取样，$P(\text{命中已占用}) = \alpha$ 精确成立，所以 $\frac{1}{1 - \alpha}$ 是这个模型下的**精确**期望；实际实现把探测序列取成槽位的随机排列（无放回），同一个 $\frac{1}{1 - \alpha}$ 是那条更精细模型的上界。哪几个槽位被占用不进这个期望，只有 $\alpha$ 进。

## 运行时间是随机变量

把一个随机化算法用在固定输入上，期望与单次运行的距离就现出来。目标固定在表尾、扫描方向固定从左到右时，每次运行的比较次数都是 $n$；换成先用一次确定性洗牌打乱扫描顺序，同一个输入上的比较次数就随种子变化：

```python run id="alg.avg.randomized-search"
import random


def scan(order, target):
    """Comparisons a scan of `order` spends before reaching `target`."""
    for index, item in enumerate(order):
        if item == target:
            return index + 1
    return len(order)


size = 64
items = list(range(size))
target = size - 1                      # fixed input: the target sits in the last slot
generator = random.Random(20260604)
runs = [scan(generator.sample(items, size), target) for _ in range(5)]

print(f"deterministic scan, fixed input: {scan(items, target)} comparisons")
print(f"randomized scan, five fixed-seed permutations: {runs}")
print(f"sample mean: {sum(runs) / len(runs):.2f}"
      f" | exact expectation (n + 1) / 2 = {(size + 1) / 2:.1f}")
```

确定性扫描在这个输入上每次都返回 $64$；随机化扫描的五次运行是 $58$、$47$、$17$、$25$、$5$，随随机位取不同的值。这个输入的精确期望是 $32.5$，五次运行只给出样本均值 $30.40$。期望界说的是 $E_R[C(x, R)] = 32.5$，它不阻止某一次运行跑到最坏情形的 $64$ 次比较。

期望界与高概率界是两条不同的保证。$E[T] = O(n \log n)$ 不排除某次运行成本更大，甚至达到算法的最坏情形；接口要求「每次运行都有硬上界」时用最坏情形分析，要求「超过某个阈值的概率很小」时还要另行证明尾概率界。只有期望值并不给出高概率保证：对非负随机变量，期望经由马尔可夫不等式只给出 $P[T \ge c\,E[T]] \le 1/c$ 这样的弱尾界。

样本均值只是对期望的估计，它用来核对实现是否符合模型；结论本身来自计数论证（见 <CrossRef id="algorithms.cost-model" />）。在独立同分布、单次成本方差为 $\sigma^2$ 时，$m$ 次运行的样本均值方差是 $\sigma^2 / m$，随 $1/m$ 下降，但它始终是估计。

期望与摊还是两个可以叠加、但必须分开陈述的维度：一个操作的期望成本与一串操作的摊还成本是两条独立论断，期望界与硬延迟界同样是两条独立论断（见 <CrossRef id="algorithms.amortized" />）。

把「先固定输入、再对随机位取期望」这条量词规则用到算法契约上，就要分开写两栏承诺：运行时间的期望或高概率界，以及出错的概率。Las Vegas 与 Monte Carlo 的分类、单侧与双侧错误、独立重复与概率放大由 <CrossRef id="algorithms.randomized-algorithms" /> 展开。

实现边界：`random.Random(seed).sample` 产出的是伪随机置换，给定种子后完全可复现，序列由解释器的伪随机数生成器决定（CPython 的 [random 模块](https://docs.python.org/3/library/random.html)）；这是本页为了可复现而做的选择，不改变上面任何一条期望结论。
