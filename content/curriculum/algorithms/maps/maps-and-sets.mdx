`counts[name] = 1` 写完再写一次 `counts[name] = 2`，字典里仍旧只有一个条目，值是 2；把同样两次写入放进一个序对列表 `[(name, 1), (name, 2)]`，列表里就有两个条目，先写的那个还在。同一个键被写第二次时究竟是新增一个条目还是覆盖已有值，取决于「同一个键」这句话由哪条关系定义。

第二次写入时，语言拿到的是一个新对象，它先要在这个对象与已存条目的键之间做一次判定，才能决定更新还是另起一个。判定所用的关系就是相等关系：它把键集划分成等价类（equivalence class），每个等价类至多留下一个条目，这就是**唯一性**。按键组织数据的整件事都建立在它上面：没有它，「同一个键」就没有定义。

## 什么算同一个键

**唯一性**说键集是一个集合，同一个键只出现一次。这句话里的「同一个」由一条等价关系（equivalence relation）定义——自反、对称、传递。若这些性质不成立，键就不能稳定地划分成等价类；例如传递性失败时，插入与查询的结果可能依赖操作顺序。Python 允许用户自行定义 `__eq__`，不会替用户验证这些性质。

在 Python 里，相等关系由 `__eq__` 给出，键的定位依赖 `__hash__`。抽象映射要求键上存在一条等价关系；Python 的可哈希键在此之上还要求相等与哈希一致：**相等则哈希相等**。语言的数据模型直接约束这条要求，却不替用户检查；它与「插入之后不再改动参与哈希的字段」是同一条约束的两面（见 <CrossRef id="python.equality-and-hashing" />）。用户写出让相等的对象哈希不同的 `__eq__` 与 `__hash__` 时，破坏的是可哈希键的契约：抽象映射的模型不再适用，这一运行的结果不构成映射的语义。

`__eq__` 始终读值；`__hash__` 读值，或者读每个实例各自不同的标记——对象身份哈希的等价物。在契约成立与契约被破坏两种情形下，两次写入之后字典分别留下什么？

```python run id="alg.maps.key-equality"
class Key:
    """Equality reads the value; the hash reads the value or a per-instance tag."""

    hash_by_value = True

    def __init__(self, value, tag):
        self.value = value
        self.tag = tag

    def __eq__(self, other):
        return isinstance(other, Key) and self.value == other.value

    def __hash__(self):
        return hash(self.value) if Key.hash_by_value else hash(self.tag)


def entries():
    table = {Key("k", 1): 1}
    table[Key("k", 2)] = 2
    return len(table), sorted(table.values())


print("equality and hash agree   ->", entries())
Key.hash_by_value = False
print("equality and hash disagree ->", entries())
```

一致时两个相等的键落进同一个等价类，第二次写入覆盖第一个条目的值，条目数停在 1，这正是抽象映射对重复写入的规定。把哈希改成读实例标记之后，相等判定说两个键相同，哈希却把两次写入送进不同的候选集合：可哈希键的契约已经破坏，抽象映射的模型对它不再作任何规定，此刻能观察到的条目数与取值是这一实现的结果，映射的语义并不给出它们。集合与映射共用这份判定：`s.add(x)` 与 `M[k] = v` 都先找到 $k$ 所在的等价类；映射的条目还要记下这个等价类当前对应的值，覆盖因此可观察。

键存入之后，它的相等与哈希被期望不再改变。若哈希读的是对象的可变状态，插入之后再修改那个状态，已存条目留在旧落点，重新用相等的键查询会按新哈希定位，命中的落点没有条目，查找因此失败。语言不禁止这种键，只是不再保证查找会命中。

映射 $M$ 是一组键到值的对应，它规定的一组操作与后置条件：

| 操作 | 前置条件 | 后置条件 |
| --- | --- | --- |
| `M[k]` | 无（缺失键的处理单独约定） | 键 $k$ 对应的值；键不存在时按约定报错或返回缺省 |
| `M[k] = v` | 无 | 键 $k$ 的值变为 $v$；若 $k$ 原本不存在，键集增加 $k$ |
| `k in M` | 无 | $k$ 在键集中时为真 |
| `del M[k]` | $k$ 在键集中 | 键集去掉 $k$ |
| 迭代 | 无 | 遍历键集（顺序由契约决定：有序映射保证键的次序，无序映射不作保证） |

集合的成员、插入与删除与之对应：`x in s`、`s.add(x)`、`s.remove(x)`，其中 `remove` 在元素缺失时失败；`s.discard(x)` 把缺失元素也定义为成功且不改变集合。集合与映射是同一个东西的两面：集合是「键到无值」的映射，映射是「带值的集合」。两者的差别落在覆盖上：映射的第二次写入改变已存的值，集合的重复插入不留下痕迹。

## 定位一个键的三种表示

按键定位的命中判定落到一次相等测试上：在候选键里找到与查询键相等的那个。候选键有多少、放在哪里，决定了一次定位要做几次相等测试，也就决定了成本。同一组按键操作至少有三条实现路线：

| 表示 | 成员查询 | 插入 | 删除 | 迭代顺序 | 空间 |
| --- | --- | --- | --- | --- | --- |
| 位图（bitmap，全集有界且编码为常数成本） | 最坏 $\Theta(1)$ | 最坏 $\Theta(1)$ | 最坏 $\Theta(1)$ | 全集次序 | $\Theta(U)$ 位 |
| 有序数组 + 二分 | 最坏 $\Theta(\log n)$ | 最坏 $\Theta(n)$ 搬移 | 最坏 $\Theta(n)$ 搬移 | 键的次序 | $\Theta(n)$ |
| 哈希表（hash table，负载因子受常数上界） | 期望 $\Theta(1)$，最坏 $\Theta(n)$ | 期望摊还 $\Theta(1)$，最坏 $\Theta(n)$ | 期望 $\Theta(1)$，最坏 $\Theta(n)$ | 不保证键序 | $\Theta(n)$ |

三行都实现上面那组按键操作，差别在于哪一项操作便宜，以及表示对输入提了什么前提。成本模型规定一次键比较记 1、一次槽位访问记 1（见 <CrossRef id="algorithms.cost-model" />）：位图把键本身当作槽位下标，成员查询与插入都只是一次槽位访问，前提是键能编码成 $0$ 到 $U-1$ 的整数，空间按全集 $U$ 付；有序数组按键的次序把键排开，二分以 $\Theta(\log n)$ 次比较定位，插入与删除在最坏情况下要搬移线性数量的元素。哈希表按哈希值把键折到槽位，再用相等测试在候选里确认目标；它的常数成本是一条期望结论，依赖哈希把键分散开的假设，最坏情形仍可退化为 $\Theta(n)$（见 <CrossRef id="algorithms.hash-tables" />）。内容型键的哈希本身随键长度增长，把一次哈希记作常数成本属于成本模型的一项假设（见 <CrossRef id="algorithms.strings" />）。

键集规模从 16 长到 65536，位图的成员查询始终是一次槽位访问，有序数组的键比较次数随规模怎样变化？

```python run id="alg.maps.representation-cost"
def sorted_member(sorted_keys, key):
    """Binary search on a sorted array; returns the answer and the key comparisons."""
    low, high, comparisons = 0, len(sorted_keys) - 1, 0
    while low <= high:
        middle = (low + high) // 2
        comparisons += 1
        if sorted_keys[middle] == key:
            return True, comparisons
        if sorted_keys[middle] < key:
            low = middle + 1
        else:
            high = middle - 1
    return False, comparisons


for size in (16, 1024, 65536):
    universe = 2 * size
    keys = list(range(0, universe, 2))      # size keys: every even integer below universe
    bits = [0] * universe                   # one slot per integer in the universe
    for key in keys:
        bits[key] = 1
    absent = universe - 1
    found, comparisons = sorted_member(keys, absent)
    print(f"n={size:>6}  bitmap: {bits[absent] == 1}, 1 access"
          f"  |  sorted: {found}, {comparisons} comparisons")
```

位图那一列无论 $n$ 多大都停在一次访问，代价是空间由全集 $U$ 决定；有序数组那一列的比较次数随 $n$ 对数增长，换来的是它保留了键的次序信息。同一组成员查询操作因此对应三份不同的成本表与前提，选哪一种由「哪一项操作最常被问到」与「输入满足哪条前提」共同决定。

## 迭代顺序与范围查询

按键接口里「迭代」那一行只规定遍历键集，顺序由契约决定。Python 的 `dict` 保插入序，这是语言规范保证的行为（[stdtypes](https://docs.python.org/3/library/stdtypes.html#dict)）；`set` 不保证迭代顺序。插入序记录的是写入发生的先后，它不回答「哪个键最小」；无序表示没有保存键的次序。

**有序映射的接口提供更多操作**：除按键查找外，还提供最小键、最大键、前驱（predecessor）、后继（successor）与区间查询（range query）。有序数组已经按键的次序排开，能以对数时间定位前驱、后继与区间起点，代价是插入与删除最坏需要线性搬移；哈希表没有保存键序，这些查询通常要扫描全部键。树表示（见 <CrossRef id="algorithms.ordered-maps" />）也能实现这组操作，在平衡不变量下按序查询与更新同时保持对数成本。

「最小的键不小于 $q$」在同一份键集上有两种实现：不保存次序时每个键都要看一遍，保存次序后二分只检查对数个位置。

```python run id="alg.maps.ordered-gap"
def successor_by_scan(keys, query):
    """Smallest key >= query; with no stored order every key is a candidate."""
    candidates = [key for key in keys if key >= query]
    return (min(candidates) if candidates else None), len(keys)


def successor_by_bisect(sorted_keys, query):
    """The same answer on a sorted array, with the binary search's comparisons."""
    low, high, comparisons = 0, len(sorted_keys), 0
    while low < high:
        middle = (low + high) // 2
        comparisons += 1
        if sorted_keys[middle] < query:
            low = middle + 1
        else:
            high = middle
    return (sorted_keys[low] if low < len(sorted_keys) else None), comparisons


keys = [index * 3 for index in range(500)]
sorted_keys = sorted(keys)
for query in (1, 501, 1496):
    scanned, scan_cost = successor_by_scan(keys, query)
    divided, bisect_cost = successor_by_bisect(sorted_keys, query)
    print(f"{query:>5} {str(scanned):>6} {scan_cost:>4} {str(divided):>6} {bisect_cost:>4}")
```

扫描那一列对每个键各检查一次，检查次数恒等于键集大小；二分那一列停在个位数，并随 $n$ 对数增长。这份差别随规模拉大：范围查询的便宜来自表示里已经排好的次序；要在一份没有次序的键集上回答同样的查询，只能把每个键逐个比过。
