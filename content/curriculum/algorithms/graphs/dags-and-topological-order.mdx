一张依赖表给出一组「先做 $u$ 才能做 $v$」的约束。把约束兑现成一份可执行的顺序，也就是把全部顶点排成一条线，让每条有向边都从左指向右。这样的排列在什么图上存在，又怎样在一趟遍历里把它造出来？

本节固定表示：有限简单**有向**图，邻接表保存出边，顶点集合 $V$ 显式给出，规模参数用 $|V|$ 与 $|E|$。

## 有向可达与环

有向图里的「可达」沿有向路径定义，方向不可逆。从每个未发现顶点重启的遍历（见 <CrossRef id="algorithms.graph-traversal" />）在有向图上只得到一个**遍历森林**，它的划分可能依赖顶点的处理顺序，因此不能当作分量的分解。

**有向<Term id="cycle">环</Term>** 是一列顶点 $v_0, v_1, \dots, v_k$，满足 $k \ge 1$、$v_k = v_0$、$v_0, \dots, v_{k-1}$ 两两不同，并且对每个 $0 \le i < k$ 都有有向边 $(v_i, v_{i+1})$。

「除首尾外两两不同」是定义的一部分：只要求「闭合的有向行走」会把更松的重复结构也算进来，而下面所有论证——后向边、Kahn 判环——用的都是这个精确形状。

| 图 | 最短的环 | 两条边能否单独成环 |
| --- | --- | --- |
| 本节的有向简单图 | $u \to v \to u$ | 可以：两条方向相反的有向边即闭合 |
| 允许自环的有向图 | $v \to v$ | 可以：一条自环就是长度 1 的环 |
| 无向简单图 | 至少 3 条边 | 不可以：一条边单独不成环 |

判定方法对含自环的图同样有效，本节只是默认不出现自环。

## 拓扑序

**定义**：有向图的一个 <Term id="topological-order">拓扑序</Term> 是一个顶点排列 $\pi$，使得对每条有向边 $(u, v)$ 都有 $\pi(u) < \pi(v)$。

把顶点排成一行而让所有边都从左指向右，这样的排列是否存在，完全由环决定：

**定理**：有向图存在拓扑序，当且仅当它没有有向环（这样的图称为 **DAG**，有向无环图）。

**（存在拓扑序 => 无环）** 若 $v_1 \to v_2 \to \dots \to v_k \to v_1$ 是一个环，拓扑序要求 $\mathrm{pos}(v_1) < \dots < \mathrm{pos}(v_k) < \mathrm{pos}(v_1)$，矛盾。

**（无环 => 存在拓扑序）** 取一条最长的有向路径，它的起点没有入边：若有入边 $(x, \mathrm{start})$，把 $x$ 接在路径前面会得到一条更长的有向路径（沿路径不可能回到 $x$，否则路径上已有环），矛盾。于是每个**非空**有限无环图都有入度为 0 的顶点，称为源点。输出这个源点、从图中删去，剩下的图仍然无环，归纳下去即得。空图的空排列就是它唯一的拓扑序。

第二个方向直接给出 Kahn 算法的构造：反复删除当前入度为 0 的顶点。DFS 那一路走另一条路线，用完成时间的偏序得到拓扑序。

## 三色 DFS 检测环

要在一趟 DFS 里认出环，先摆出一个必须回答的问题：扫描边 $(u, v)$ 时，怎样区分「$v$ 还在当前 DFS 路径里」与「$v$ 早已彻底处理完」？

这两种处境对判环的作用相反。$v$ 还在路径上，意味着 DFS 正沿着它往下走、尚未返回；从 $v$ 沿这条路径走到 $u$，再沿 $(u, v)$ 回到 $v$，就闭合了一个环。$v$ 已经处理完，意味着它的邻接扫描结束、已经退出调用栈；$(u, v)$ 指向一个与当前路径无关的顶点，不闭合环。

一个只记录「见没见过」的访问标志回答不了这个问题：它把「还在路径上」与「已经处理完」写进同一个值。把「见过」拆成两档，再加上尚未见过的起点，就得到三个状态：

| 状态 | 含义 |
| --- | --- |
| `undiscovered` | 尚未被首次发现 |
| `discovered` | 已发现，但邻接扫描尚未完成——在递归 DFS 里它就是当前调用栈上的顶点 |
| `finished` | 邻接扫描已经完成 |

**定理**：从每个尚未发现的顶点重启、最终覆盖整个 $V$ 的 DFS 中，图存在有向环，当且仅当扫描中出现一条指向 `discovered` 顶点的边。这样的边称为后向边。

「覆盖整个 $V$」是前提：只做单源 DFS 时，它只能检测从该源点可达的那部分里的环。

**（后向边 => 有环）** 记这条边为 $(u, v)$ 且 $v$ 是 `discovered`。$v$ 在栈上，从 $v$ 到 $u$ 恰好是栈上的一段路径，于是 $v \rightsquigarrow u \to v$ 是一个环。

**（有环 => 后向边）** 取环上最先被 DFS 发现的顶点 $v$，$u$ 为环上 $v$ 的前驱。$v$ 被发现的瞬间，环上其余顶点都还是 `undiscovered`；$v$ 只有在它递归到的后继全部返回之后才 `finished`。从 $v$ 沿环可以到达 $u$，所以 DFS 会在 $v$ 仍为 `discovered` 时处理到 $u$；当 $u$ 扫描边 $(u, v)$ 时，$v$ 仍在栈上，得到一条后向边。

指向 `finished` 顶点的边是另一回事：目标可能来自同一次遍历里已经完成的子树，也可能来自先前已经完成的遍历树，两种情形在 DAG 中都很常见，都不构成环。

同一段递归 DFS 在一条 DAG 与一张含环图上留下的收尾不同：DAG 的完成顺序反转后让每条边都从左指向右，含环图上则跳出一条指向仍在栈上顶点的后向边。

```python run id="alg.graphs.three-colour-dfs"
def three_colour_dfs(adjacency):
    """Grey on entry, black on exit. Returns the finish order and the first back edge."""
    colour, finish_order, back_edge = {}, [], [None]

    def visit(u, path):
        colour[u] = "grey"
        for v in adjacency[u]:
            if v not in colour:
                visit(v, path + [v])
            elif colour[v] == "grey" and back_edge[0] is None:
                back_edge[0] = (u, v, path[path.index(v):] + [v])
        colour[u] = "black"
        finish_order.append(u)

    for start in adjacency:
        if start not in colour:
            visit(start, [start])
    return finish_order, back_edge[0]

dressing = {"shirt": ["tie", "belt"], "tie": ["jacket"], "belt": ["jacket", "shoes"],
            "socks": ["shoes"], "jacket": [], "shoes": [], "watch": []}
cyclic = {"a": ["b"], "b": ["c"], "c": ["b", "d"], "d": []}

finish, back = three_colour_dfs(dressing)
place = {v: i for i, v in enumerate(finish[::-1])}
print("DAG finish order:", " ".join(finish), "| back edge:", back)
print("  reversed:", " ".join(finish[::-1]), "| every arc left to right:",
      all(place[u] < place[v] for u in dressing for v in dressing[u]))
finish, back = three_colour_dfs(cyclic)
print("cyclic finish order:", " ".join(finish), "| back edge:", back)
```

DAG 上完成顺序是 $jacket\,tie\,shoes\,belt\,shirt\,socks\,watch$，反转后得到 $watch\,socks\,shirt\,belt\,shoes\,tie\,jacket$，每条边都从左指向右。含环图上出现后向边 $(c, b)$，它闭合的环是 $b \to c \to b$。

## 拓扑序 = finish 顺序的反转

完成顺序对任何有向图都存在，能不能反转成拓扑序由后向边决定。对每条边按扫描到 $(u, v)$ 时 $v$ 的状态分类：

| $v$ 的状态 | 情形 | 结论 |
| --- | --- | --- |
| `undiscovered` | $v$ 成为 $u$ 的后代 | $v$ 先 `finished` |
| `discovered` | 后向边，存在环 | DAG 中不会出现 |
| `finished` | 另一次遍历、或同一次遍历里更早完成的部分 | $v$ 已经先 `finished` |

在 DAG 中三种情形都指向同一个结论：$finish(v) < finish(u)$。把完成顺序整个反转，每条边 $(u, v)$ 都有 $u$ 出现在 $v$ 之前，这正是拓扑序的定义。

**定理**：若图是 DAG，则 DFS 的完成顺序反转是一个拓扑序。

成本与遍历相同：$\Theta(|V| + |E|)$。一旦发现后向边，正确的返回是指出图含环、不存在拓扑序；把完成顺序反转当作结果，会在有环图上给出一个不满足定义的排列。

## Kahn 算法

第二个构造更直接：反复取出当前入度为 0 的顶点。

1. 计算每个顶点的入度
2. 把所有入度为 0 的顶点放进队列
3. 反复取出队首顶点 $v$，输出 $v$，并把它每条出边 $(v, w)$ 的 $w$ 的入度减一；若某个 $w$ 的入度减到 0，就把 $w$ 放入队列
4. 队列为空时结束

**运行不变量**（把 `in_degree` 读作「剩余入度」）

1. 对每个尚未输出的顶点 $v$，`in_degree[v]` 恰等于「尚未输出的顶点指向 $v$ 的边数」
2. 队列恰好保存当前尚未输出、且剩余入度为 0 的顶点
3. 每条边 $(u, v)$ 只在 $u$ 被输出时处理一次，并把 $v$ 的剩余入度恰好减一

**正确性**：算法在任何时刻产生的 output 都是一个合法的**拓扑前缀**——一个顶点只有在它的所有尚存前驱都已经输出之后才可能进入队列。因此，若算法最终输出了全部 $|V|$ 个顶点，output 就是整张图的拓扑序；若队列提前为空而仍有顶点未输出，算法应返回失败，那段部分输出只是拓扑前缀。

**环判定**：算法输出全部 $|V|$ 个顶点，当且仅当图无环。

**（提前停止 => 剩余子图含环）** 若算法提前停止，剩余子图非空，且其中每个顶点的剩余入度都大于 0。反设剩余子图无环：由「非空有限 DAG 必有源点」，它应有一个剩余入度为 0 的顶点，与「每个剩余顶点的剩余入度都大于 0」矛盾。所以剩余子图含有有向环。

**（无环 => 不会卡住）** 反过来，若原图无环，则每个非空剩余子图仍然无环，因此始终存在源点，Kahn 不会在处理完全部顶点之前卡住。

成本同样是 $\Theta(|V| + |E|)$：每个顶点入队出队各一次，每条边被检查常数次；队列空间 $O(|V|)$。两种方法给出的顺序一般不相等（DFS 版本还受邻居枚举顺序影响），两者都只承诺「是一个拓扑序」。在同一张 DAG 与含环图上各跑一遍 Kahn：DAG 上它输出全部顶点，含环图上它在剩余入度都大于零处停下。

```python run id="alg.graphs.kahn"
from collections import deque


def kahn(adjacency):
    """Queue by remaining in-degree; returns the output and the vertices left behind."""
    in_degree = {v: 0 for v in adjacency}
    for u in adjacency:
        for v in adjacency[u]:
            in_degree[v] += 1
    queue = deque(v for v in adjacency if in_degree[v] == 0)
    output = []
    while queue:
        u = queue.popleft()
        output.append(u)
        for v in adjacency[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    return output, [v for v in adjacency if v not in set(output)]


dressing = {"shirt": ["tie", "belt"], "tie": ["jacket"], "belt": ["jacket", "shoes"],
            "socks": ["shoes"], "jacket": [], "shoes": [], "watch": []}
cyclic = {"a": ["b"], "b": ["c"], "c": ["b", "d"], "d": []}

output, left = kahn(dressing)
print("Kahn output:", " ".join(output), "| processed:", len(output), "of", len(dressing))
output, left = kahn(cyclic)
print("cyclic graph leaves behind:", sorted(left), "| output:", " ".join(output))
```

DAG 上 Kahn 输出 $shirt\,socks\,watch\,tie\,belt\,jacket\,shoes$，与 finish 反转得到的顺序不同，两者都是合法的拓扑序。含环图上它只输出 $a$，剩下 $b, c, d$：每个剩余顶点都还有一条来自剩余集合的入边，这正是「提前停止 => 剩余子图含环」的实例。

拓扑序一般不唯一，Kahn 的队列直接给出判据：某一步队列里同时有多个候选时，先输出哪一个都行，剩下的图仍能按同样规则跑完，于是至少存在两种拓扑序；每一步队列都只有一个候选时，任何拓扑序的首项都被这一步逼定，删去它再对剩余图重复同一推理，整个顺序就被唯一确定。唯一性因此不必枚举排列——在一次 Kahn 运行里记录队列长度是否始终为 1 即可判定，成本仍是 $\Theta(|V| + |E|)$。

```python run id="alg.graphs.topological-uniqueness"
from collections import deque


def candidates_per_step(adjacency):
    """Kahn by remaining in-degree, recording the candidate count at every step."""
    in_degree = {v: 0 for v in adjacency}
    for u in adjacency:
        for v in adjacency[u]:
            in_degree[v] += 1
    queue = deque(v for v in adjacency if in_degree[v] == 0)
    order, widths = [], []
    while queue:
        widths.append(len(queue))
        u = queue.popleft()
        order.append(u)
        for v in adjacency[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    return order, widths


chain = {"a": ["b"], "b": ["c"], "c": ["d"], "d": []}
diamond = {"a": ["b", "c"], "b": ["d"], "c": ["d"], "d": []}

for name, graph in (("chain", chain), ("diamond", diamond)):
    order, widths = candidates_per_step(graph)
    print(f"{name:8s} {' '.join(order):12s} candidates per step: {widths}")
```

链上每一步的候选数都是 1，输出被唯一确定；菱形图在 $a$ 之后同时出现两个候选，Kahn 输出 $b$ 或 $c$ 都合法，顺序不再唯一。
