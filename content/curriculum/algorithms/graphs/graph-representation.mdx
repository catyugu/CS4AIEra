同一批连接关系——一个顶点集合，以及它们之间的连接——可以写成好几种样子。选哪一种，取决于它要反复回答哪一个问题：某个顶点的邻居有哪些、某一对顶点之间有没有边、整张图的边有哪些。一种表示把其中一类问题做得便宜，代价由另外两类承担。因此同一张图值得有不止一种表示。

## 同一张图的三种写法

取一张具体的图 $G$：顶点 `a`、`b`、`c`，两条无向边 $a$-$b$ 与 $a$-$c$，记 $|V| = 3$、$|E| = 2$。同一对集合——顶点集合与边集合——可以同时写成三种形式：

```text
    b       c
     \     /
      \   /
       \ /
        a
```

```python
adjacency = {"a": ["b", "c"], "b": ["a"], "c": ["a"]}   # vertex -> neighbour list
matrix = [[0, 1, 1], [1, 0, 0], [1, 0, 0]]               # |V| by |V|, rows and columns indexed a, b, c
edges = [("a", "b"), ("a", "c")]                         # one pass over all edges
```

`adjacency` 按顶点索引邻居列表，`matrix` 按顶点对索引一个槽位，`edges` 把全部边排成一个可以一次走完的序列。三种写法存的是同一份连接关系；前两者本身带着顶点集合，`edges` 要另外配上 $V$ 才完整。矩阵按 $0$ 到 $|V| - 1$ 的整数下标索引行列，顶点集合不是这段连续整数时要额外维护一个顶点到下标的映射——单元格里的 `index` 就是这个映射；顶点集合一变，矩阵的行与列要跟着重建。

默认建模为有限<Term id="simple-graph">简单图</Term>：没有<Term id="self-loop">自环</Term>，也没有<Term id="parallel-edge">平行边</Term>。在邻接表里，简单性表现为邻居列表中不出现顶点自己、也不出现重复项；在邻接矩阵里，表现为对角线全假、非对角元素非零即一。这是本模块各算法的建模条件，离开它之前要先检查哪些结论依赖它。

## 三个操作，三种成本

下面的三个单元格对同一份 `adjacency`、`matrix`、`edges` 直接操作，每个问题都在三种写法上各做一次。

**我要列出 `a` 的邻居。** 邻接表把 $a$ 的邻居聚在一条列表里，一次取出；矩阵只有一整行，要逐个槽位看过才知道哪些顶点相邻；边列表要走过每一项，看哪一项以 `a` 为端点。

```python run id="alg.graphs.representation-neighbours"
adjacency = {"a": ["b", "c"], "b": ["a"], "c": ["a"]}
matrix = [[0, 1, 1], [1, 0, 0], [1, 0, 0]]
edges = [("a", "b"), ("a", "c")]
vertices = ["a", "b", "c"]
index = {"a": 0, "b": 1, "c": 2}

print("adjacency list: one lookup ->", adjacency["a"])

row = index["a"]
slots, neighbours = 0, []
for position in range(len(vertices)):
    slots += 1
    if matrix[row][position]:
        neighbours.append(vertices[position])
print("adjacency matrix:", slots, "slots ->", neighbours)

entries, neighbours = 0, []
for u, v in edges:
    entries += 1
    if u == "a":
        neighbours.append(v)
    elif v == "a":
        neighbours.append(u)
print("edge list:", entries, "entries ->", neighbours)
```

邻接表读 $\deg(a) = 2$ 个邻接项，矩阵读 $|V| = 3$ 个槽位，边列表读 $|E| = 2$ 个边项。枚举一个顶点的邻居，这一类的成本在三种写法上分别由 $\deg(u)$、$|V|$、$|E|$ 决定。

**我要问 `b` 与 `c` 之间有没有边。** 邻接表要在 $b$ 的邻居列表里找 `c`；矩阵只查一个槽位；边列表要扫到那条边，或者扫完所有边才知道没有。

```python run id="alg.graphs.representation-edge-lookup"
adjacency = {"a": ["b", "c"], "b": ["a"], "c": ["a"]}
matrix = [[0, 1, 1], [1, 0, 0], [1, 0, 0]]
edges = [("a", "b"), ("a", "c")]
index = {"a": 0, "b": 1, "c": 2}

print("adjacency list: 'c' in adjacency['b'] ->", "c" in adjacency["b"])

i, j = index["b"], index["c"]
print("adjacency matrix: matrix[1][2] ->", matrix[i][j])

found, entries = False, 0
for u, v in edges:
    entries += 1
    if (u, v) == ("b", "c") or (v, u) == ("b", "c"):
        found = True
        break
print("edge list:", entries, "entries scanned ->", found)
```

邻接表读 $\deg(b) = 1$ 个邻接项，矩阵读 1 个槽位，边列表读 $|E| = 2$ 个边项。矩阵把查边做成一次访问，邻接表的成本由度数决定，边列表的成本由边数决定。邻接表这一项假定邻居容器是顺序列表：换成哈希集合，查边变成一次哈希查找，代价转到存储与迭代顺序上。

**我要扫描所有边。** 邻接表把每条无向边存了两遍——它出现在两个端点的列表里各一次；矩阵有 $|V|^2$ 个槽位，要逐个看过才确定哪些是真实存在的边；边列表本身就是全部边，走一遍即可。

```python run id="alg.graphs.representation-edge-scan"
adjacency = {"a": ["b", "c"], "b": ["a"], "c": ["a"]}
matrix = [[0, 1, 1], [1, 0, 0], [1, 0, 0]]
edges = [("a", "b"), ("a", "c")]

items = []
for u, neighbours in adjacency.items():
    for v in neighbours:
        items.append((u, v))
print("adjacency list:", len(items), "items ->", items)

slots = 0
for row in matrix:
    for _ in row:
        slots += 1
print("adjacency matrix:", slots, "slots; true entries:",
      sum(sum(row) for row in matrix))

entries = 0
for _ in edges:
    entries += 1
print("edge list:", entries, "entries ->", edges)
```

邻接表数出 $2|E| = 4$ 个邻接项，矩阵扫过 $|V|^2 = 9$ 个槽位（其中 $2|E| = 4$ 个为真），边列表恰好 $|E| = 2$ 个边项，没有重复。扫描全部边，只有边列表的项数与 $|E|$ 相等。

邻接表的冗余是一条<Term id="invariant">表示不变量</Term>：$v$ 出现在 `adjacency[u]` 里，当且仅当 $u$ 出现在 `adjacency[v]` 里。插一条无向边要写两个方向，删一条要删两个方向，只改一个方向就把结构留在违反它的状态。

## 稀疏与稠密

矩阵恒为 $|V|^2$ 个槽位，与边数无关；邻接表的规模是 $|V| + 2|E|$，随边数增长。按 $|E|$ 相对 $|V|^2$ 的大小，图分成<Term id="sparse-and-dense">稀疏图与稠密图</Term>：稀疏（$|E| \ll |V|^2$）时矩阵为大量不存在的边留了槽位，邻接表更合适；稠密（$|E|$ 接近 $|V|^2$）时矩阵查边只需一次访问，一次访问的常数优势可以抵过它的空间开销。表示的取舍跟着工作负载走：反复按顶点取邻居就建邻接表，反复走全部边就建边列表。

## 图作为抽象数据类型

三种写法保存的是同一对集合，把共同的顶点集合与边集合显式写成一个<Term id="abstract-data-type">抽象数据类型</Term>：抽象状态由顶点集合 $V$ 与边集合 $E$ 组成，加权图再附带一个定义在边上的权重函数；无向边是无序对 $\lbrace u, v \rbrace$，有向边是有序对 $(u, v)$，权重是边的属性。顶点集合独立于边集合：度为 0 的孤立顶点仍然属于 $V$，只保存边就分不清「这个顶点不存在」与「这个顶点存在但没有边」。

枚举 $u$ 的邻居、查询 $u$ 与 $v$ 之间有没有边、扫描全部边，这三类操作定义在抽象状态 $(V, E)$ 上，都以 $u, v \in V$ 为<Term id="precondition">前置条件</Term>；用哪一种表示去实现它们是选择。邻接表把「按顶点取邻居」做成一次取出，矩阵把「查一条边」做成一次访问，边列表把「走全部边」做成一次遍历。

本模块的算法各自稳定地采用一种表示：遍历（见 <CrossRef id="algorithms.graph-traversal" />）与 Dijkstra 在邻接表上运行，Bellman–Ford 与 Kruskal 在边列表上运行；表示之间的转换由算法需要哪一种访问决定。
