连接所有顶点、总权重最小的一棵树：在一张加权无向图上，这就是最小生成树。困难在于不枚举全部生成树就把它找出来。

Kruskal 用并查集维护的划分（<CrossRef id="algorithms.union-find" />）判断一条边会不会成环，连通输入下它收下的边数恰好是 $|V| - 1$。两个算法都由同一段交换论证支撑：割上的安全边引理。

## 最小生成树：目标本身

在 $G$ 的全部 <Term id="spanning-tree">生成树</Term>中，权重总和最小的那一棵就是最小生成树（minimum spanning tree，MST）。生成树的数量有限，所以最小值一定存在。输入约定为非空连通无向图。

权重允许任意实数，包括负数：候选对象始终是有限多棵无环的生成树，不存在绕环无限下降的可能，边权的取值范围不影响最小值的存在性。

## 割与安全边引理

Kruskal 与 Prim 都是贪心算法，它们的正确性来自下面这个引理。

图的一个 <Term id="cut">割</Term>（cut）是把 $V$ 分成两部分 $(S, V \setminus S)$，其中 $S$ 非空且不含全部顶点；一条边**跨越**这个割，如果它两个端点分居两侧；它**不被森林 $A$ 跨越**，如果 $A$ 里没有边跨越这个割。

**引理（安全边）**：设森林 $A$ 被某棵最小生成树 $T$ 包含，割 $(S, V \setminus S)$ 不被 $A$ 的任何边跨越，则这个割上任意一条权重最小的边 $e$ 都是安全边：存在某棵最小生成树包含 $A \cup \lbrace e \rbrace$。

证明是一次交换：

**证明。** 若 $e$ 已经在 $T$ 中，直接取 $T$。否则把 $e$ 加入 $T$：$T$ 是生成树，加一条边后恰好出现一个环 $C$。$e$ 跨越这个 cut，环上还有另一条边 $f$ 也跨越同一个割（环要从 $S$ 侧走到 $V \setminus S$ 侧再回来），且 $f \notin A$（割不被 $A$ 跨越，而 $e$ 在环上）。$e$ 是这个割上权重最小的边，所以 $w(e) \le w(f)$。把 $f$ 从 $T + e$ 中删掉，得到一棵生成树，它包含 $A \cup \lbrace e \rbrace$，总权不增加，因此仍是一棵最小生成树。

引理只用到两件事：$e$ 在权重最小的位置上（给 $w(e) \le w(f)$），以及 $f \notin A$（保证换完之后 $A \cup \lbrace e \rbrace$ 还在）。

## Kruskal：按权重从小到大

1. 把无向边按权重升序排成一个序列（每条无向边只出现一次）
2. $F$ 置空，并查集初始化为 $|V|$ 个单点块
3. 依序取每条边 $(u, v)$：若 `find(u) != find(v)`，接受它并把两块合并；否则跳过
4. 返回 $F$

排序输入是每条无向边一次的边列表。无向邻接表把一条边存成两个邻接项，把 $2|E|$ 个邻接项当成待排序的边仍然无环——第一份被接受、反向副本随后被跳过——但待排序项从 $|E|$ 变成 $2|E|$，成本分析与调试轨迹（trace）一起失真。

**Kruskal 用的割是哪一个？** 设当前已选边为 $F$，被接受的是边 $e = (u, v)$，取 $S$ 为 $F$ 中含 $u$ 的那个连通分量的顶点集。$e$ 的两个端点此前属于不同的块，所以 $e$ 跨越 $(S, V \setminus S)$，且这个割不被 $F$ 的任何边跨越。要证 $e$ 是这个割上的权重最小的边，比较范围是整个割——割之外还有别的分量，只在两个块之间取权重最小并不足以满足引理的条件。反设有跨这个割的边 $g$ 满足 $w(g) < w(e)$：$g$ 排在 $e$ 之前被处理；处理 $g$ 时它的两个端点不可能同块（同块则此后永远同块，与 $g$ 现在跨越割矛盾），于是当时必被接受、此后它们永久同块，同样矛盾。所以 $e$ 是这个割的权重最小的边，安全边引理给出 $F \cup \lbrace e \rbrace$ 仍被某棵最小生成树包含。

```python run id="alg.graphs.kruskal"
def find(parent, vertex):
    while parent[vertex] != vertex:
        parent[vertex] = parent[parent[vertex]]
        vertex = parent[vertex]
    return vertex


def union(parent, u, v):
    root_u, root_v = find(parent, u), find(parent, v)
    if root_u == root_v:
        return False
    parent[root_v] = root_u
    return True


vertices = ["s", "a", "b", "c", "d"]
edges = [(2, "s", "a"), (2, "s", "b"), (1, "a", "b"), (3, "a", "c"),
         (-1, "b", "c"), (4, "c", "d"), (5, "b", "d")]
parent = {vertex: vertex for vertex in vertices}
chosen = []
for weight, u, v in sorted(edges, key=lambda edge: edge[0]):
    if union(parent, u, v):
        chosen.append((weight, u, v))
print("|V| =", len(vertices), "|E| =", len(edges), "chosen:", chosen)
print("total weight:", sum(weight for weight, _, _ in chosen))
```

Kruskal 在这张图上选出 4 条边、总权重 6，其中包含权重 $-1$ 的 $b$-$c$；负数不影响结论，因为候选始终是有限多棵生成树。

**这棵生成树不是最短路树。** 选中的边包含 $s$-$a$（权重 2）与 $a$-$b$（权重 1），$s$ 与 $b$ 在树上的路径是 $s \to a \to b$，权重 $2 + 1 = 3$；原图里有一条权重 2 的 $s$-$b$ 边被跳过了。一条边是否入选由它对全局总权重的贡献决定，与它在某条两顶点路径上是否最短无关。

成本分两段：排序 $O(|E| \log |E|)$，并查集 $O((|V| + |E|)\alpha(|V|))$，合起来是 $O(|E| \log |E| + (|V| + |E|)\alpha(|V|))$，非平凡输入里由排序主导。权重相同的边可以按任意顺序处理，输出边集不必唯一，算法只保证返回一棵权重最小的生成树。

## Prim：同一个引理的第二个应用

Prim 从任意一个顶点开始生长一棵树，每次把「树到外面的权重最小的边」加进来：

$$key[v] = \min \lbrace w(u, v) : u \text{ 在树中} \rbrace, \qquad \text{对每个 } v \text{ 不在树中}.$$

1. $S$ 置空，$key[r] = 0$，其余为 $+\infty$
2. 反复取 $key$ 最小的顶点 $v$（起点 $r$ 就是这样第一个入树的）
3. 把 $v$ 加入 $S$；若 $v \ne r$，把 $(parent[v], v)$ 加入树
4. 用 $v$ 的邻边更新其余顶点的 $key$
5. 直到所有从 $r$ 可达的顶点都入树

$key[v]$ 是「从 $S$ 到 $v$ 这个顶点」的权重最小的边，不是从 $r$ 到 $v$ 的路径总权重。Dijkstra（见 <CrossRef id="algorithms.dijkstra" />）维护 `distance[v]`（从源点出发的路径总权重），Prim 维护 `key[v]`（一条边的权重）；两者的松弛更新写法相近，量的含义不同。

正确性复用同一个引理：设当前树顶点集为 $S$，被选中的 $v^*$ 的父边是跨割 $(S, V \setminus S)$ 的权重最小的边，而 $S$ 内部的边不跨这个割，于是引理直接给出「加入这条边后仍存在某棵最小生成树包含新的树」。引理里没有非负假设，负边同样允许。

```python run id="alg.graphs.prim"
def prim(vertices, edges, start):
    in_tree = {start}
    chosen = []
    while len(in_tree) < len(vertices):
        crossing = [(weight, u, v) for weight, u, v in edges
                    if (u in in_tree) != (v in in_tree)]
        weight, inside, outside = min(crossing, key=lambda edge: edge[0])
        if inside not in in_tree:
            inside, outside = outside, inside
        chosen.append((weight, inside, outside))
        in_tree.add(outside)
    return chosen


vertices = ["s", "a", "b", "c", "d"]
edges = [(2, "s", "a"), (2, "s", "b"), (1, "a", "b"), (3, "a", "c"),
         (-1, "b", "c"), (4, "c", "d"), (5, "b", "d")]
tree = prim(vertices, edges, "s")
print("|V| =", len(vertices), "|E| =", len(edges), "chosen:", tree)
print("total weight:", sum(weight for weight, _, _ in tree))
```

在同一个边列表上 Prim 也选出 4 条边、总权重 6，顺序与 Kruskal 不同。上面的实现每一步重扫全部边取权重最小的跨割边，成本 $O(|V| |E|)$；改用优先队列维护 $key$ 降到 $O(|V| + |E| \log |V|)$：`heapq` 没有 decrease-key，于是把 $(key, serial, vertex)$ 压进堆、pop 时丢弃过期条目，`serial` 计数器保证堆不去比较两个顶点。$|V|$ 那一项来自必须逐个查看顶点；连通图上 $|E| \ge |V| - 1$，可以简写成 $O(|E| \log |V|)$。

## 算法对照

| 算法 | 前置条件 | 维护的不变量 | 成本 |
| --- | --- | --- | --- |
| Kruskal | 非空连通无向图，边列表每条边一次 | $F$ 无环、划分正确、始终可扩展成某棵最小生成树 | $O(\lvert E \rvert \log \lvert E \rvert + (\lvert V \rvert + \lvert E \rvert)\alpha(\lvert V \rvert))$ |
| Prim | 非空连通无向图 | $key[v]$ 是从当前树到 $v$ 的权重最小的边；被选中的那条是跨整个割的权重最小的边 | $O(\lvert V \rvert + \lvert E \rvert \log \lvert V \rvert)$ |

两个算法对安全边引理取了不同的割：Kruskal 用按当前分量划分的割，Prim 用「已选顶点与其余顶点」的割，引理对两者同时成立。
