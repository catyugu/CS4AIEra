对一个按需增长的只追加数组连续追加 $m$ 个元素。它的表示与成本固定：元素个数到达已分配容量时容量精确翻倍；未满载的追加写入一个槽位，成本 1；满载的那次追加先把已有的 $c$ 个元素复制进新块，再写入新元素，成本 $c + 1$。判断这个实现能不能用，要看 $m$ 次追加的**总成本**有多高，以及能否把它分摊成每次追加的一个常数。

单次追加的最坏成本可以高达当时的元素个数，昂贵的复制却只发生在容量翻倍的那一次。把它算清楚需要一种对**整串操作**给出总成本界的论证：设 $\sigma = (op_1, \dots, op_m)$ 是一个合法操作序列，$T(\sigma) = \sum_{i=1}^{m} c_i$ 是它的真实总成本，其中 $c_i$ 是第 $i$ 次操作的真实工作量。<Term id="amortized-analysis">摊还分析</Term>给出一条**对所有合法序列统一成立**的总成本界——为每次操作规定一个摊还代价 $\hat c_i$，使任意合法序列都满足 $T(\sigma) \le \sum_{i=1}^{m} \hat c_i$；若还能取 $\hat c_i \le C$，就得到 $T(\sigma) \le C \cdot m$，即每次操作 $O(1)$ 的摊还上界。

## 聚合分析：对整串追加计数

逐次界定一次追加的成本很难，整串追加的总成本却可以直接数出来。复制只发生在容量从 $2^{j-1}$ 扩到 $2^j$ 的那一次追加上，搬运的元素数依次是 $1, 2, 4, \dots$，前 $j$ 次复制加起来不到 $2^j$，因此 $m$ 次追加里复制搬运的元素总数小于 $m$；再加上每次追加写入一个新元素、共 $m$ 次写入，得到

$$
T(m) \;<\; 2m .
$$

除以操作次数，$T(m) / m < 2$：每一次追加摊到不到两次基本操作。这条论证只用对整串操作的计数，没有为任何一次操作单独规定摊还代价，也不要求序列停在某个特定长度上。

把 16 次追加逐次跑出来，容量、实际成本与累计复制量就是要核对的量。

```python run id="alg.amortized.aggregate"
class GrowingArray:
    """A dynamic array that doubles its capacity and reports each append's cost."""

    def __init__(self):
        self.capacity = 0
        self.size = 0
        self.copies = 0

    def append(self):
        if self.size == self.capacity:
            real_cost = 1 + self.size          # write the element, copy the existing ones
            self.copies += self.size
            self.capacity = max(1, self.capacity * 2)
        else:
            real_cost = 1
        self.size += 1
        return self.capacity, real_cost, self.copies


array = GrowingArray()
rows = [array.append() for _ in range(16)]

print(f"{'n':>3} {'capacity':>8} {'real':>5} {'copies':>6}")
for step, (capacity, real, copies) in enumerate(rows, start=1):
    print(f"{step:>3} {capacity:>8} {real:>5} {copies:>6}")

real_costs = [real for _, real, _ in rows]
total_real = sum(real_costs)
writes = len(rows)
print("real costs:", real_costs)
print("sum of real costs:", total_real, "| average T/m:", round(total_real / writes, 2))
print("worst single operation:", max(real_costs))
print("copies + writes:", array.copies, "+", writes, "=", array.copies + writes)
```

16 次追加的实际成本是 $1, 2, 3, 1, 5, 1, 1, 1, 9, 1, 1, 1, 1, 1, 1, 1$，总和 31；其中复制搬运共 15 个元素，写入 16 个，合计 31，小于 $2 \times 16 = 32$。单次最大的一次是 9，出现在把容量从 8 扩到 16 的那次追加上。

$31 / 16 = 1.94$ 是这个具体序列上的**实际平均成本**；聚合计数给出的是一致的摊还界 2，对每个合法序列都成立，与序列具体长什么样无关。整串成本随追加次数线性增长，单次成本却在 1 与 9 之间摆动：偶尔一次 $O(n)$ 的复制，不会让连续 $m$ 次追加变成非线性的总成本。

## 摊还上界与单次最坏成本

摊还上界衡量整串操作，单次成本衡量一次调用，两者回答的是不同问题。

```python run id="alg.amortized.latency-gap"
class GrowingArray:
    def __init__(self):
        self.capacity = 0
        self.size = 0

    def append(self):
        if self.size == self.capacity:
            real_cost = 1 + self.size
            self.capacity = max(1, self.capacity * 2)
        else:
            real_cost = 1
        self.size += 1
        return real_cost


count = 64
array = GrowingArray()
append_costs = [array.append() for _ in range(count)]

total = sum(append_costs)
print(
    f"appends={count} actual average T/m={total / count:.2f} "
    f"worst single={max(append_costs)} ratio={max(append_costs) / (total / count):.1f}x"
)
print("same sequence, two questions: throughput and tail latency")
```

这 64 次追加的实际平均成本是 1.98，单次最大的一次是 33，是平均值的 16.6 倍。批量导入、按批处理的流水线关心总吞吐，摊还结论足够；在线路径关心尾延迟，必须看单次最坏成本。把摊还结论当作延迟保证写进接口文档，就是把一个正确的数学结论用在了它不覆盖的场合。序列很短时，渐进记号隐藏的常数与初始化成本可能主导实际时间，仅凭一个 $O(1)$ 的摊还记号不足以判断性能。

## 进一步形式化：记账法与势能法

聚合计数给出总成本界，却不给每次操作指定代价。记账法与势能法为每次操作规定一个摊还代价 $\hat c_i$，适合操作不再是一串同型追加、无法直接数总成本的情形；两种写法都可以用上面同一串追加核对。

### 记账法

记账法（accounting method）给每次操作预先指定一个固定的摊还代价，把多出的部分累加成一个**累计差额**，用来承担之后那次昂贵的复制。对这串追加取每次的摊还代价为 3（第一次在空数组上不发生复制，取 2 即可）：容量未满的追加实际代价为 1，多出的 2 累加进累计差额；在规模 $c$ 上满载、这一次要复制 $c$ 个元素时，这次追加的实际代价为 $c + 1$，多出的 $c - 2$ 由累计差额承担。

累计差额从 0 起累加「摊还代价减实际代价」，在满载复制发生前它恰好等于当时的规模 $c$（$c = 4$ 与 $c = 8$ 的两次复制之前它分别是 4 与 8），覆盖掉 $c - 2$ 之后回到 2。它在整串追加里从不下降为负，所以把每次摊还代价取 3 得到的和覆盖真实总成本：

$$
T(\sigma) \;\le\; 3m .
$$

这里有三个不同的数。$1.94$ 是那个具体序列的实际平均成本；聚合计数给出的一致上界 2；记账法构造出的逐次摊还代价 3，比 2 更松，却同样有效。摊还代价由论证构造、不由真实序列唯一决定——只要它在任何合法序列上的和都不低于真实总成本，就是一组合法的摊还代价。

### 势能法

记账法的累计差额只取决于当前状态（元素个数与已分配的容量），把它写成状态函数，每次操作的摊还代价就有了公式。取

$$
\Phi = 2 \cdot \text{size} - \text{capacity},
$$

规定第 $i$ 次追加的摊还代价为 $\hat c_i = c_i + \Phi_i - \Phi_{i-1}$，$\text{size}$ 与 $\text{capacity}$ 取完整操作结束时的值，势能在操作的**边界**上读。数组满载时 $\text{size} = \text{capacity} = c$，于是 $\Phi_{\text{before}} = 2c - c = c$；这次追加复制 $c$ 个元素、写入一个新元素，$c_i = c + 1$；操作结束后 $\text{size} = c + 1$、$\text{capacity} = 2c$，$\Phi_{\text{after}} = 2(c + 1) - 2c = 2$。代入得

$$
\hat c_i = (c + 1) + (2 - c) = 3 .
$$

对任意前缀 $k$ 求和，得到恒等式

$$
\sum_{i=1}^{k} \hat c_i = \sum_{i=1}^{k} c_i + \Phi_k - \Phi_0 .
$$

只要对每个可达状态都有 $\Phi_k \ge \Phi_0$（最常见的规定是 $\Phi_0 = 0$ 且 $\Phi$ 非负），停在第 $k$ 步时摊还代价之和就不低于真实成本：$T(\sigma_{1:k}) \le \sum_{i \le k} \hat c_i$。这里 $\Phi = 2 \cdot \text{size} - \text{capacity}$ 在每次追加后都取非负值，因为容量总小于两倍的元素个数，所以条件成立。

势能法给出的逐次摊还代价与记账法逐字相同，因为势就是尚未用掉的累计差额；写成状态函数之后，不必再在每一步跟踪它的数值，数学上的势函数也可以比这个例子抽象得多。这套势属于**声明的扩容策略**：$\Phi = 2 \cdot \text{size} - \text{capacity}$ 是为「只追加、满载时容量精确翻倍」这个实现选的，换成一倍半扩容、固定增量扩容或允许删除的缩容策略，势函数都要重新设计，非负性与摊还常数也都要重算。扩容策略还决定结论本身：固定增量扩容的整串总成本是 $\Theta(n^2)$，几何扩容是 $\Theta(n)$，这个取舍的细节见 <CrossRef id="algorithms.arrays-and-lists" />。

### 摊还界的确切含义

把上面三种写法收紧成一条定义。摊还界是一条对**所有**合法操作序列成立的界：若存在摊还代价 $\hat c_i$，使任意长度 $m$ 的合法序列 $\sigma$ 都满足

$$
T(\sigma) = \sum_{i=1}^{m} c_i \;\le\; \sum_{i=1}^{m} \hat c_i ,
$$

这组摊还代价就是该序列的摊还界；当 $\hat c_i \le C$ 时得到常数摊还成本 $T(\sigma) \le C \cdot m$。序列可以任意长，也可以在任意位置结束，而前缀本身也是一个合法序列，所以界必须覆盖每一个前缀。三种写法都用来证明这一条，构造出的摊还代价与常数却不必相同：上面这串追加合法地同时有聚合界 2 与势能法给出的摊还代价 3。

摊还上界**主张**对任意合法操作序列、包括任意合法前缀，真实总成本不超过所证明的摊还代价之和，序列在任意位置停下都成立。它**不主张**某一次操作的**真实**成本不超过它自己那次的摊还代价——单次最坏成本仍然可以远高于摊还代价，那 16 次追加里最贵的一次用去 9，摊到每次上的摊还代价却是 3。也不主张未被用掉的摊还代价一定会被用到：$T(\sigma)$ 可以严格小于摊还代价之和，这不影响上界成立。

摊还证明不对序列施加分布。**期望摊还成本**是另一维：它对输入的随机性（或算法的随机位）取期望之后再摊还，因而需要写出所采用的分布，平均情形处理那一维（见 <CrossRef id="algorithms.cost-model" />），概率与期望留给 <CrossRef id="algorithms.average-and-randomized" />。两者可以组合，组合出的结论要把这两个维度分开陈述。

## 延伸：二进制计数器

同一套核算工具可以搬到别的结构上：先写下每次操作的实际代价，再决定给每次操作预先指定多少摊还代价，最后核对累计差额从不下降为负。

一个 $k$ 位二进制计数器每次加一，翻转从最低位开始的连续 1。单次加一的最坏情况是翻转全部 $k$ 位，即 $\Theta(k)$；只有当 $k = \Theta(\log(m + 1))$（计数器刚好够表示前 $m$ 次递增）时，才能把它写成 $\Theta(\log m)$。下面这段代码对若干次加一统计总翻转次数与单次峰值。

```python run id="alg.amortized.binary-counter"
def increment(bits):
    """Add one, return the number of bit flips."""
    flips = 0
    for index in range(len(bits)):
        flips += 1
        if bits[index] == 0:
            bits[index] = 1
            return flips
        bits[index] = 0
    return flips


width = 32
for count in (8, 16, 32, 64):
    bits = [0] * width
    flips = [increment(bits) for _ in range(count)]
    print(
        f"increments={count:3d} total flips={sum(flips):3d} "
        f"flips/increment={sum(flips) / count:.2f} worst single={max(flips):2d}"
    )
```

第 $i$ 位每 $2^i$ 次加一翻转一次，因此 $m$ 次加一的总翻转次数是 $\sum_i \lfloor m / 2^i \rfloor < 2m$：摊还常数成本，而单次最坏是 $\Theta(\log m)$。对应的势函数取计数器中 1 的个数，一次加一翻转 $t + 1$ 位（其中 $t$ 位由 1 变 0）时，$\hat c = (t + 1) + (1 - t) = 2$。
