序列要分成两层看：抽象 sequence 的契约，以及承担这个契约的具体表示。功能契约不决定复杂度：复杂度结论属于某个具体实现或算法，在指定成本模型、规模度量与量化方式下成立，同一个物理表示也不唯一决定算法或成本模型。本课程使用的 CPython/Pyodide 中，`list` 是动态对象引用数组的实现：它自己的语言级契约描述这一个类型能做什么，而下面这张抽象 sequence 契约表是为了让多种表示可以互相比较而独立写出的。成本来自连续内存与扩容策略。分清楚这两层之后，「为什么末尾追加便宜而头部插入昂贵」「为什么下标访问快而查找慢」都可以从表示的机制推出；成本表记录结论，不能替代这一步推导。

## 序列契约与表示

**抽象 sequence** 是一组操作契约，与实现无关。抽象状态是有限序列 $S = (s_0, \dots, s_{n-1})$，元素来自一个定义了相等关系的域；合法位置是 $0, \dots, n-1$，合法插入位置是 $0, \dots, n$。

| 操作 | 契约 |
| --- | --- |
| `get(i)` | 返回 $s_i$ |
| `set(i, value)` | 把 $s_i$ 替换为 `value`，其余位置不变 |
| `insert(i, value)` | 把序列变为 $S$ 的前 $i$ 个元素、`value`、$S$ 的剩余元素按序拼接（逻辑位置改变，与物理存储无关） |
| `delete(i)` | 把序列变为 $S$ 的前 $i$ 个元素与 $S$ 从 $i + 1$ 起的剩余元素按序拼接 |
| `iterate` | 按位置顺序访问每个元素一次 |
| `search(value)` | 返回最小的满足 $s_i = \texttt{value}$ 的 $i$，不存在时返回约定的未找到结果 |

表格中的 `get`、`set`、`delete` 以 $0 \le i < n$ 为前置条件，`insert` 以 $0 \le i \le n$ 为前置条件；不满足这些前置条件的调用不在本抽象 sequence 契约的范围内，本契约不规定其结果：具体类型可以另行规定这些输入的语义，例如 Python `list` 支持负索引，`insert` 对超出范围的位置也有自己的截断规则。相等关系属于契约层（它决定什么叫命中），而「一次相等判定的成本」属于成本模型：在 Python 里 `==` 可能执行用户代码，因此准确的结论是「最多 $n$ 次相等比较」，而不是对一般对象的真实时间下结论。

同一个契约可以有多种表示：连续数组、动态数组、链式结构、维护子树大小等秩信息的平衡树。它们的操作成本不同，因此「序列的查找是 $O(n)$」这种句子没有意义——要固定的是四件事：哪种表示、什么成本模型、按什么规模度量、成本怎样量化（见 <CrossRef id="algorithms.cost-model" />）。

**连续数组**：元素存放在一块连续内存里，元素 $i$ 的位置由基址与元素大小算出。在固定宽度槽位、单位成本地址访问的模型下，下标访问是一次地址计算，与 $n$ 无关。代价是插入与删除必须移动元素以维持连续性：在单位成本槽位移动的模型下，`insert(i)` 移动 $n - i$ 个已有元素，总成本是 $\Theta(n - i + 1)$；`delete(i)` 移动 $n - i - 1$ 个后继元素，合法删除总有 $n - i \ge 1$，因此总成本是 $\Theta(n - i)$。头部是 $\Theta(n)$，靠近尾部可以是 $\Theta(1)$，对位置取最坏情形才是 $\Theta(n)$；CPython 的复杂度表把 `insert` 简写成 $O(n - k)$，本课不沿用它在端点上的这种简写。

**动态数组**：在连续数组之上维护两个量——`capacity`（已分配槽位）与 `size`（实际元素数）；把两者混用会得出错误的复制量。它的表示不变量是 $0 \le \texttt{size} \le \texttt{capacity}$，前 `size` 个槽位表示抽象序列 $S$，其余槽位不属于抽象序列、其内容不参与抽象状态；`insert`、`delete` 与扩容都必须保持这条不变量。`size == capacity` 时扩容：分配更大的块，把已有元素复制过去。按固定增量扩容会让 $n$ 次追加的总复制量达到 $\Theta(n^2)$；按固定常数增长因子 $g > 1$ 的几何扩容，$n$ 次追加的总复制量是 $\Theta(n)$，因此摊还到每次追加是 $O(1)$。

## 随机访问与顺序查找

下标访问不遍历，查找必须遍历：面对同样多的元素，成本随元素个数增长的是查找，下标访问不随元素个数变化。这一差别来自表示。

```python run id="alg.arrays.access-vs-search"
def search_steps(values, target):
    """Count element comparisons until the target is found."""
    comparisons = 0
    for value in values:
        comparisons += 1
        if value == target:
            return comparisons
    return comparisons


values = list(range(1000))
print("index access needs no comparisons:", values[500])
for target in (values[0], values[500], values[-1]):
    print(f"search for {target:4d}: {search_steps(values, target):4d} comparisons")

values.append(2000)
print("a miss scans the whole input:", search_steps(values, -1), "comparisons for n =", len(values))
```

比较次数的上界在未命中或命中末尾时达到：两种情况都要扫完整个输入。这是 $\Theta(n)$ 的比较次数，与元素是否有序无关——有序性可以支持更快的查找，那是另一类表示与算法要解决的问题。

## 插入与删除要移动元素

```python run id="alg.arrays.insert-shift"
def insert_with_moves(values, index, value):
    """Insert while counting element moves."""
    moves = 0
    values.append(None)
    for position in range(len(values) - 1, index, -1):
        values[position] = values[position - 1]
        moves += 1
    values[index] = value
    return moves


for size in (100, 200, 400):
    values = list(range(size))
    front_moves = insert_with_moves(values, 0, -1)
    values = list(range(size))
    tail_moves = insert_with_moves(values, len(values) - 1, -1)
    print(f"n={size:4d}  insert at front moves {front_moves:4d}  insert near the end moves {tail_moves:2d}")

values = list(range(1000))
removals = len(values) // 2
moved = 0
for _ in range(removals):
    values.pop(0)
    moved += len(values)
print(f"deleting the front {removals} times moves about {moved} elements (n = 1000)")
```

Python `list` 的切片返回新的 `list`，是浅复制；在本课程使用的 CPython/Pyodide 实现中，长度为 $k$ 的切片要建立新的引用数组并复制 $k$ 个引用，因此在单位成本引用复制的模型下成本是 $\Theta(k)$。头部插入移动全部元素，尾部附近插入几乎不移动。连续删除头部元素的总移动量随删除次数与输入规模同时增长：初始长度为 $n$、删除 $m$ 次（$1 \le m \le n$）时总移动量是 $\sum_{j=0}^{m-1}(n - j - 1) = m(n - 1) - m(m - 1)/2$，即 $\Theta(n m)$。这种用法代价高昂：这正是「用 `list` 当队列」代价高昂的原因，队列需要另一种表示（见 <CrossRef id="algorithms.stacks-and-queues" />）。

## 容量、扩容与摊还成本

```python run id="alg.arrays.capacity-growth"
import sys


def sizes_during_appends(count):
    values = []
    observations = []
    previous = sys.getsizeof(values)
    for index in range(count):
        values.append(index)
        current = sys.getsizeof(values)
        if current != previous:
            observations.append((index + 1, current))
            previous = current
    return observations


observations = sizes_during_appends(4000)
print("first growth steps (appends, container bytes):", observations[:6])
print("capacity growth events for 4000 appends:", len(observations))
print("reported-size ratios between consecutive growth events:", [round(observations[i + 1][1] / observations[i][1], 3) for i in range(min(4, len(observations) - 1))])

exact = [0] * 1000            # allocated to fit the final length exactly
grown = []
for value in range(1000):
    grown.append(value)       # grew by appending
print("same length, different growth history:", len(exact), len(grown))
print("container bytes for the two:", sys.getsizeof(exact), sys.getsizeof(grown))
```

列表对象在追加过程中反复改变体积，而且每次都跳过若干槽位，不是每追加一个元素就重新分配。观测到的是容量按批增长这一现象，至于它由按比例的 over-allocation 造成，是 CPython（本课程用的 Pyodide 同源）的实现事实。具体字节数与增长比例随解释器版本与指针宽度变化。对增长因子为固定常数 $g > 1$ 的几何扩容模型（下面那个单元格）可以说：扩容次数是 $O(\log n)$，总复制量是 $\Theta(n)$；固定增量扩容没有这两条性质。这几行观测支持的只是「容量不是每追加一个元素就增长一次」，而采用按比例的 over-allocation 是 CPython（以及本课程使用的 Pyodide 运行时）的实现事实，不是由这几个观测点证明出来的渐进定理。

把这两点算清楚。下面这个单元格用的是我们自己设定的增长策略（因子可调），它的角色是成本模型，不是对 `list` 实际扩容行为的测量：

```python run id="alg.arrays.amortized-cost"
import math


def append_cost_sequence(count, growth_factor=2):
    """Count element copies for `count` appends under a geometric growth policy."""
    capacity = 1
    size = 0
    copies = 0
    expansions = 0
    for _ in range(count):
        if size == capacity:
            copies += size
            capacity = max(size + 1, math.ceil(capacity * growth_factor))
            expansions += 1
        size += 1
    return copies, expansions


for count in (1000, 2000, 4000):
    copies, expansions = append_cost_sequence(count)
    print(f"n={count:5d}  total copies={copies:5d}  copies/n={copies / count:.2f}  expansions={expansions}")

for factor in (1.1, 1.5, 2.0, 3.0):
    copies, expansions = append_cost_sequence(100_000, factor)
    print(f"growth factor {factor}: expansions={expansions:3d}  total copies={copies:7d}  copies/n={copies / 100_000:.2f}")
```

无论增长因子是 1.5 还是 2，总复制量都与 $n$ 成正比，因此摊还成本是常数。因子本身是一次取舍：因子越大，总复制量的常数上界越小（翻倍模型的总复制量小于 $2n$，$n$ 恰好接近容量边界时可以接近 $n$），但一次扩容刚完成后空闲槽位比例的峰值渐近接近 $(g - 1)/g$，之后随着继续追加而下降；因子越接近 1，复制总量越大而空闲越少，同时每次扩容额外申请的内存尖峰越小。这组取舍是动态数组实现的固有选择，不由语言决定。摊还成本不限制单次延迟：扩容时的那一次追加是 $\Theta(n)$；提供 `reserve` 这类接口的动态数组实现可以预留容量来避开它，Python `list` 本身没有通用的显式 reserve 接口。扩容后的块可能保留接近一半的空槽（例如 $g = 2$ 时），内存敏感的场景要按峰值容量估算，元素个数会低估占用。

## CPython 的 `list` 是具体的动态数组

CPython 中的 `list` 是可变长的对象引用数组：容器存储指向对象的引用，不存储对象本身。`sys.getsizeof` 统计的是直接归属于列表容器的内存，不递归计入它引用的对象——因此容器字节数与 payload 对象本身的大小无关，但确实取决于已分配容量以及运行时的分配与增长历史。每个槽位保存一个对象引用，被引用对象与指针数组分离，多个槽位也可以引用同一个对象。本课程的浏览器运行时 Pyodide 是 CPython 到 WebAssembly 的移植，本节研究的就是这一具体实现；其他实现的 `list` 不保证同样的表示。

```python run id="alg.arrays.list-holds-references"
import sys

shared = [0] * 1000
distinct = list(range(1000))
print("container size with repeated payload:", sys.getsizeof(shared))
print("container size with 1000 distinct payloads:", sys.getsizeof(distinct))
print("the repeated element is one object:", shared[0] is shared[1])

small = [0]
huge = [10 ** 100]
print("container size ignores payload size:", sys.getsizeof(small) == sys.getsizeof(huge))
print("payload sizes differ:", sys.getsizeof(small[0]), "vs", sys.getsizeof(huge[0]))
```

容器本身是连续排列的引用，被引用的对象与指针数组分离。这有两个后果：下标访问仍然 $O(1)$（引用数组可以按位置计算）；而在关注内存访问的原生成本模型里，引用数组多了一层间接寻址，payload 对象也没有随指针数组紧凑排列，因此通常具有更弱的空间局部性。这本身推不出「Python 层某个遍历循环必然更快或更慢」——实际时间还包含迭代器实现、装箱与拆箱等成本；紧凑的值数组、引用数组与复制出来的子序列三者的常数与内存行为也各不相同。把「连续数组」与「CPython 的 `list`」当成同一个东西，会得到错误的局部性结论。

需要紧凑布局时用 `array` 模块或 `bytes`/`bytearray` 这类按值存储的类型，它们存的是定长值序列，不是对象引用；本课程的浏览器运行时没有硬件性能计数器，因此无法把 wall-clock 差异归因到缓存行为，局部性收益需要在原生环境里做受控测量才能确认。

## 小结

- 抽象 sequence 的状态是有限序列，操作契约规定每个操作对抽象状态做什么；功能契约不决定复杂度，复杂度结论属于具体实现或算法，在指定成本模型、规模度量与量化方式下成立。
- 在固定宽度槽位、单位成本地址访问与单位成本槽位移动的模型下，连续数组的下标访问是 $\Theta(1)$；`insert(i)` 移动 $n - i$ 个已有元素（成本 $\Theta(n - i + 1)$）、`delete(i)` 移动 $n - i - 1$ 个后继元素（成本 $\Theta(n - i)$）：头部 $\Theta(n)$、靠近尾部 $\Theta(1)$、对位置取最坏才是 $\Theta(n)$。
- 动态数组区分 `capacity` 与 `size`，表示不变量是 $0 \le \texttt{size} \le \texttt{capacity}$ 且前 `size` 个槽位表示抽象序列；固定常数因子 $g > 1$ 的几何扩容使 $n$ 次追加的总复制量为 $\Theta(n)$，因此 append 是摊还 $O(1)$、单次最坏是 $\Theta(n)$。
- CPython 的 `list` 是可变长的对象引用数组：下标访问 $O(1)$；`sys.getsizeof` 不递归计入被引用对象，容器字节数还取决于已分配容量与增长历史；引用布局的空间局部性通常弱于紧凑值数组，但这不直接决定 Python 层的运行时间。
- 普通 packed 动态数组不适合频繁的头部插入与删除；双端操作需要环形缓冲区、分块 deque 或链式等不同表示。需要紧凑布局时用 `array` 或 `bytes`/`bytearray` 这类按值存储的类型。
