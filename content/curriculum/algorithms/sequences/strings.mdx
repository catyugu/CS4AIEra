匹配问题的输入是文本与模式，输出是模式在文本中出现的每一个位置。它和顺序查找共享同一个契约形态，成本结构却不同：朴素的重复扫描在特定输入上退化到两个长度的乘积，预处理模式之后可以达到两个长度之和，且这个保证不依赖任何输入分布。

两种结论的差别落在**失配之后还能不能保留已经读过的信息**上。文本已经被读过一遍，模式自己有没有重叠结构可以决定下一次对齐落在哪里；把这份结构预先算出来，扫描阶段就不必回头重读文本。这一课先量出朴素扫描的坏情形，再从模式的边界出发把线性时间的匹配器推出来。

## 匹配契约与朴素扫描

**契约**：给定文本 $t$（长度 $n$）与模式 $p$（长度 $m$，$1 \le m \le n$），返回所有满足 $t[i:i+m] = p$ 的下标 $i$，按升序排列。重叠的匹配全部报告：`"aaa"` 中的 `"aa"` 在位置 0 与 1 各出现一次。空模式是另一条约定，本课按前置条件排除它。

朴素扫描在每个可能的起点上逐字符比较，失配就整体右移一位从头再来。它的后置条件容易满足，代价却由失配的位置决定。

```python run id="alg.strings.naive"
def occurrences(text, pattern):
    """Postcondition: every start index where text[i:i+m] == pattern, ascending.

    Precondition: 1 <= m <= len(text). Overlapping occurrences are all reported.
    """
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return []
    return [start for start in range(n - m + 1) if text[start:start + m] == pattern]


def comparisons(text, pattern):
    """Character comparisons spent by the naive scan on this input."""
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return 0
    total = 0
    for start in range(n - m + 1):
        offset = 0
        while offset < m:
            total += 1
            if text[start + offset] != pattern[offset]:
                break
            offset += 1
    return total


cases = (
    ("scattered", "abcdefghij" * 40, "ghijklmn"),
    ("one repeated character", "a" * 400, "a" * 39 + "b"),
    ("overlapping matches", "a" * 400, "a" * 2),
)
print(f"{'input':>22} {'n':>4} {'m':>3} {'matches':>8} {'comparisons':>12} {'n*m':>7} {'n+m':>5}")
for label, text, pattern in cases:
    n, m = len(text), len(pattern)
    found = len(occurrences(text, pattern))
    spent = comparisons(text, pattern)
    print(f"{label:>22} {n:>4} {m:>3} {found:>8} {spent:>12} {n * m:>7} {n + m:>5}")
```

同样是 $n = 400$ 的输入，比较次数从 798 到 14440。第三行的模式出现在每一个位置，第二行的模式在**每一个**起点上都要比到最后一位才失配：文本全是同一个字符，模式的前 $m-1$ 位都与文本相同，只有最后一位不同。这个输入族在每个候选起点都做满 $m$ 次比较，因此比较次数恰为 $m(n-m+1)$，最坏情形是 $\Theta(m(n-m+1))$。例如当 $m \le n/2$ 时，$n-m+1 = \Theta(n)$，于是这个界也可写成 $\Theta(n \cdot m)$。

朴素扫描的问题不在常数因子：每一次失配之后它都从模式的第一个字符重新开始比较，尽管刚才那段比较已经证明文本里有一长串字符与模式的前缀相同。这部分信息被丢掉了，而它恰好能决定下一次对齐的位置。

## 模式的自重叠结构

称 $p[:k]$ 的一个**边界**是它的一段既是真前缀又是真后缀的子串，$\pi$ 记每个前缀的最长边界长度：

$$
\pi[i] = \max \lbrace \, \ell < i+1 : p[i+1-\ell : i+1] = p[:\ell] \, \rbrace
$$

括号里的条件是：把 $p$ 的后缀 $p[i+1-\ell:i+1]$ 与它的前缀 $p[:\ell]$ 对齐时两者相同。

$\pi[i]$ 度量的是模式自己和自己重叠的能力：$\pi[i] = \ell$ 意味着把模式右移 $i + 1 - \ell$ 位之后，前面的 $\ell$ 个字符仍然对得上。计算它本身只用 $\pi$ 的已知部分，因为 $\pi[i]$ 至多比 $\pi[i-1]$ 大 1，回退时沿着 $\pi$ 链跳。

```python run id="alg.strings.prefix-function"
def prefix_function(pattern):
    """Postcondition: pi[i] is the longest border of pattern[:i+1]."""
    pi = [0] * len(pattern)
    length = 0
    for i in range(1, len(pattern)):
        while length > 0 and pattern[i] != pattern[length]:
            length = pi[length - 1]
        if pattern[i] == pattern[length]:
            length += 1
        pi[i] = length
    return pi


def longest_border(pattern, end):
    """Independent check, straight from the definition: scan every candidate length."""
    prefix = pattern[:end + 1]
    for length in range(end, 0, -1):
        if pattern[:length] == prefix[-length:]:
            return length
    return 0


for pattern in ("ababaca", "aaaa", "abcabcd", "aabaaab"):
    pi = prefix_function(pattern)
    checked = [longest_border(pattern, i) for i in range(len(pattern))]
    print(f"{pattern:9s} pi={pi}  agrees with the definition: {pi == checked}")
```

检查器按定义逐个候选长度试；按 Python 字符串切片的长度计费，它的最坏时间是 $\Theta(m^3)$，这里只用来核对这张表。`"aabaaab"` 这一类模式同时可能含有多级边界：先取最长边界可以保留最多已经匹配的字符，也就是选择仍可能成立的最近一次对齐；若接下来仍失配，更短的边界由 $\pi$ 链依次覆盖。

## 线性时间的匹配

扫描阶段在每轮开始时维护一个量 `length`：已经处理 `text[:i]` 后，`0 <= length < m`，并且 `pattern[:length]` 是 `text[:i]` 的后缀中、长度小于 $m$ 的最长模式前缀（按 <CrossRef id="algorithms.correctness" /> 的三步交代）。初始时 $i = 0$、`length = 0`，性质成立。读入 `text[i]` 后，若当前前缀可以延长就把 `length` 加一；否则沿着 $\pi$ 链依次尝试仍可能成为后缀的较短前缀。若延长后 `length == m`，当前后缀就是完整模式，于是报告位置 `i - m + 1`，再令 `length = pi[m-1]`，重新建立 `length < m` 的不变量，同时保留可能形成重叠匹配的最长边界。扫描结束时，每个完整模式后缀都恰在其最后一个字符被处理时报告，因此得到全部且仅有真实出现位置。

```python run id="alg.strings.kmp"
def prefix_function(pattern):
    pi = [0] * len(pattern)
    length = 0
    for i in range(1, len(pattern)):
        while length > 0 and pattern[i] != pattern[length]:
            length = pi[length - 1]
        if pattern[i] == pattern[length]:
            length += 1
        pi[i] = length
    return pi


def linear_matches(text, pattern):
    """Postcondition: the naive match list, with the character comparisons it cost."""
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return [], 0
    pi = prefix_function(pattern)
    matches = []
    comparisons = 0
    length = 0
    for i, char in enumerate(text):
        while True:
            comparisons += 1
            if length < m and char == pattern[length]:
                length += 1
                break
            if length == 0:
                break
            length = pi[length - 1]
        if length == m:
            matches.append(i - m + 1)
            length = pi[length - 1]
    return matches, comparisons


def naive_matches(text, pattern):
    """Postcondition: the same match list, with the naive scan's comparisons."""
    n, m = len(text), len(pattern)
    if m == 0 or m > n:
        return [], 0
    matches = []
    comparisons = 0
    for start in range(n - m + 1):
        offset = 0
        while offset < m:
            comparisons += 1
            if text[start + offset] != pattern[offset]:
                break
            offset += 1
        else:
            matches.append(start)
    return matches, comparisons


cases = (
    ("abcdefghij" * 40, "ghijklmn"),
    ("a" * 400, "a" * 39 + "b"),
    ("a" * 400, "a" * 2),
    ("aabaaab" * 50, "aabaaab"),
    ("abababa", "ababa"),
)
print(f"{'n':>4} {'m':>3} {'matches':>8} {'linear':>7} {'naive':>8} {'n*m':>7} {'same result':>12}")
for text, pattern in cases:
    n, m = len(text), len(pattern)
    linear, spent = linear_matches(text, pattern)
    reference, naive_spent = naive_matches(text, pattern)
    print(f"{n:>4} {m:>3} {len(linear):>8} {spent:>7} {naive_spent:>8} {n * m:>7} {str(linear == reference):>12}")
```

线性匹配器的比较次数随两个长度之和增长：第二行 $n + m = 440$，匹配器花 761 次比较，朴素扫描在同一条输入上花 14440 次。

## 成本类别与假设

**最坏情形保证，不依赖分布。** 计入 `length` 的增减：每读入一个文本字符，`length` 至多加 1，因此整个扫描里它最多增加 $n$ 次；每次回退都严格减小 `length` 并把它设为某个 $\pi$ 值，而 $\pi$ 值严格小于回退前的长度。回退是唯一会重复比较的路径，它的总次数不超过增加的总次数 $n$，于是扫描阶段的字符比较不超过 $2n$。预处理模式花 $\Theta(m)$ 时间与 $\Theta(m)$ 空间。合起来是 $\Theta(n + m)$，**对每一条输入都成立**。

这是摊还论证的形态（见 <CrossRef id="algorithms.amortized" />）：同一个文本字符上因回退产生的额外比较，被此前使 `length` 增加的推进支付，不靠输入随机，也不靠平均情形。滚动哈希或指纹匹配也能让相邻窗口的指纹以常数增量更新，但哈希相等是否直接视为匹配、发生冲突后是否逐字符核验，会分别影响正确性保证与最坏成本；这些概率模型留到随机化算法一节。这里得到的是确定性的 $\Theta(n+m)$ 最坏界，不依赖输入分布或哈希随机性，代价是额外保存长度为 $m$ 的 $\pi$ 表。

**比较计数的单位是字符。** 上面所有数字都按「一次字符比较记 1」计数。把「比较两个模式串」定价为一次常数操作需要额外假设，因为模式长度没有先验上界（见 <CrossRef id="algorithms.cost-model" />）。字符集大小不影响结论：匹配器不对字符做算术，只做相等比较。

**实现对照。** 不要把本课朴素扫描的最坏界直接归给 CPython 的 `str.find`。当前 CPython 的 [fastsearch.h](https://github.com/python/cpython/blob/main/Objects/stringlib/fastsearch.h) 在字符串足够长时采用 Crochemore–Perrin Two-Way，源码注明该算法具有 $O(n)$ 最坏时间；另有自适应路径在累计了足够多的匹配工作后切换到 Two-Way。Python 对 `str.find` 的语言级承诺只是返回最低匹配下标，找不到时返回 -1，并不承诺这套复杂度。阅读实现时要把公开语义与某一版本解释器采用的算法分开。
