匹配问题的输入是文本与模式，输出是模式在文本中出现的每一个位置。朴素重复扫描在每个候选起点逐字符比较，能给出全部出现位置，在多数输入上代价并不大；但在特定输入上，它的比较次数会随文本长度和模式长度的增长一起放大，远远超过扫描一遍文本所需的次数。

退化的来源是失配之后被丢掉的比较结果：朴素扫描从模式的第一个字符重新开始，而刚比过的那一段字符里，已经含有决定下一次对齐的信息。要把它预先算出来，先得确定这段信息里可复用的究竟是哪一部分。

## 匹配问题的定义与朴素扫描

**问题定义**：给定文本 $t$（长度 $n$）与模式 $p$（长度 $m$，$1 \le m \le n$），返回所有满足 $t[i:i+m] = p$ 的下标 $i$，按升序排列。重叠的匹配全部报告：`"aaa"` 中的 `"aa"` 在位置 0 与 1 各出现一次。空模式是另一条约定，按问题的前置条件排除。

朴素扫描在每个可能的起点上逐字符比较，失配就整体右移一位从头再来。它的后置条件容易满足，代价却由失配的位置决定。

```python run id="alg.strings.naive"
def naive_matches(text, pattern):
    """The match list, and the character comparisons the scan spent."""
    m = len(pattern)
    matches, comparisons = [], 0
    for start in range(len(text) - m + 1):
        offset = 0
        while offset < m:
            comparisons += 1
            if text[start + offset] != pattern[offset]:
                break
            offset += 1
        else:
            matches.append(start)
    return matches, comparisons


for text, pattern in (("abcdefghij" * 40, "ghij"), ("a" * 400, "a" * 39 + "b")):
    matches, spent = naive_matches(text, pattern)
    print("n", len(text), "m", len(pattern), "matches", len(matches), "comparisons", spent)
```

两条输入的长度都是 $n = 400$，比较次数却相差近 28 倍：第一条上模式很少对齐，只花了 517 次；第二条的文本全是同一个字符，模式的前 $m - 1$ 位都与文本相同，只有最后一位不同，于是**每一个**候选起点都要比到最后一位才失配，比较次数是 14440。这个输入族在每个候选起点都做满 $m$ 次比较，因此比较次数恰为 $m(n-m+1) = 40 \times 361$，最坏情形是 $\Theta(m(n-m+1))$。例如当 $m \le n/2$ 时，$n-m+1 = \Theta(n)$，于是这个界也可写成 $\Theta(n \cdot m)$。

失配时已经得到了一条确定的信息：模式的前若干位与文本比对成功。设失配前成功的长度为 $k$，则文本刚读过的长度为 $k$ 的后缀与 $p[:k]$ 相同。下一个候选起点只有让这段后缀的一个更短后缀与模式的前缀对齐才可能成立，这就要求 $p[:k]$ 有一个真前缀同时是它的真后缀；其中最长的那个决定了下一次对齐能保留多少已匹配字符。可复用的信息就是这类前后缀，而朴素扫描在每个起点都从零重建它。

## 模式的自重叠结构

称 $p[:k]$ 的一段既是真前缀又是真后缀的子串为它的**边界**；$\pi$ 记每个前缀的最长边界长度，也就是模式的前缀函数：

$$
\pi[i] = \max \lbrace \, \ell < i+1 : p[i+1-\ell : i+1] = p[:\ell] \, \rbrace
$$

括号里的条件是：把 $p$ 的后缀 $p[i+1-\ell:i+1]$ 与它的前缀 $p[:\ell]$ 对齐时两者相同。

$\pi[i]$ 度量的是模式自己和自己重叠的能力：$\pi[i] = \ell$ 意味着把模式右移 $i + 1 - \ell$ 位之后，前面的 $\ell$ 个字符仍然对得上。计算它本身只用 $\pi$ 的已知部分，因为 $\pi[i]$ 至多比 $\pi[i-1]$ 大 1，回退时沿着 $\pi$ 链跳。

```python run id="alg.strings.prefix-function"
def prefix_function(pattern):
    """pi[i] is the longest border of pattern[:i+1]."""
    pi, length = [0] * len(pattern), 0
    for i in range(1, len(pattern)):
        while length > 0 and pattern[i] != pattern[length]:
            length = pi[length - 1]
        if pattern[i] == pattern[length]:
            length += 1
        pi[i] = length
    return pi


for pattern in ("ababaca", "aabaaab"):
    print(pattern, prefix_function(pattern))
```

`"aabaaab"` 这类模式含有多级边界：先取最长边界可以保留最多已经匹配的字符，也就是选择仍可能成立的最近一次对齐；若接下来仍失配，更短的边界由 $\pi$ 链依次覆盖。

## 线性时间的匹配

扫描阶段在每轮开始时维护一个量 `length`：已经处理 `text[:i]` 后，`0 <= length < m`，并且 `pattern[:length]` 是 `text[:i]` 的后缀中、长度小于 $m$ 的最长模式前缀（按 <CrossRef id="algorithms.correctness" /> 的三步交代）。初始时 $i = 0$、`length = 0`，性质成立。读入 `text[i]` 后，若当前前缀可以延长就把 `length` 加一；否则沿着 $\pi$ 链依次尝试仍可能成为后缀的较短前缀。若延长后 `length == m`，当前后缀就是完整模式，于是报告位置 `i - m + 1`，再令 `length = pi[m-1]`，重新建立 `length < m` 的不变量，同时保留可能形成重叠匹配的最长边界。扫描结束时，每个完整模式后缀都恰在其最后一个字符被处理时报告，因此得到全部且仅有真实出现位置。

```python run id="alg.strings.kmp"
def prefix_function(pattern):
    """pi[i] is the longest border of pattern[:i+1]."""
    pi, length = [0] * len(pattern), 0
    for i in range(1, len(pattern)):
        while length > 0 and pattern[i] != pattern[length]:
            length = pi[length - 1]
        if pattern[i] == pattern[length]:
            length += 1
        pi[i] = length
    return pi


def linear_matches(text, pattern):
    """The match list, and the character comparisons the matcher spent."""
    m = len(pattern)
    pi, matches, comparisons, length = prefix_function(pattern), [], 0, 0
    for i, char in enumerate(text):
        while True:
            comparisons += 1
            if length < m and char == pattern[length]:
                length += 1
                break
            if length == 0:
                break
            length = pi[length - 1]
        if length == m:
            matches.append(i - m + 1)
            length = pi[length - 1]
    return matches, comparisons


def naive_comparisons(text, pattern):
    m = len(pattern)
    spent = 0
    for start in range(len(text) - m + 1):
        offset = 0
        while offset < m and text[start + offset] == pattern[offset]:
            offset += 1
        spent += offset + (offset < m)
    return spent


text, pattern = "a" * 400, "a" * 39 + "b"
matches, spent = linear_matches(text, pattern)
print("matches", len(matches), "linear", spent, "naive", naive_comparisons(text, pattern))
```

在同一条输入上，$n + m = 440$：线性匹配器花 761 次比较，朴素扫描花 14440 次。

最坏情形保证，不依赖分布。计入 `length` 的增减：每读入一个文本字符，`length` 至多加 1，因此整个扫描里它最多增加 $n$ 次；每次回退都严格减小 `length` 并把它设为某个 $\pi$ 值，而 $\pi$ 值严格小于回退前的长度。回退是唯一会重复比较的路径，它的总次数不超过增加的总次数 $n$，于是扫描阶段的字符比较不超过 $2n$。预处理模式花 $\Theta(m)$ 时间与 $\Theta(m)$ 空间。合起来是 $\Theta(n + m)$，**对每一条输入都成立**。

这是摊还论证的形态（见 <CrossRef id="algorithms.amortized" />）：同一个文本字符上因回退产生的额外比较，由此前使 `length` 增加的推进承担，不靠输入随机，也不靠平均情形。这里得到的是确定性的 $\Theta(n+m)$ 最坏界，不依赖输入分布，代价是额外保存长度为 $m$ 的 $\pi$ 表。

比较计数的单位是字符。上面所有数字都按「一次字符比较记 1」计数。把「比较两个模式串」记为一次常数操作需要额外假设，因为模式长度没有先验上界（见 <CrossRef id="algorithms.cost-model" />）。字符集大小不影响结论：匹配器不对字符做算术，只做相等比较。
