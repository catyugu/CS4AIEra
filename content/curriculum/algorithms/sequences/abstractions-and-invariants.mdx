在序列的头部插入一个元素，连续存放的版本把已有的每个元素依次后移一位，链式存放的版本新建一个结点、改一条引用。两种情况调用方读到的序列完全相同，花掉的工作量却不同。

```python run id="alg.adt.two-representations"
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next


class Chain:
    """Linked nodes for a sequence; a tail reference keeps append at one write."""

    def __init__(self):
        self._head = None
        self._tail = None

    def append(self, value):
        node = Node(value)
        if self._head is None:
            self._head = self._tail = node
        else:
            self._tail.next = node
            self._tail = node

    def insert_front(self, value):
        self._head = Node(value, self._head)
        if self._tail is None:
            self._tail = self._head
        return 1

    def get(self, index):
        node, hops = self._head, 0
        while hops < index:
            node, hops = node.next, hops + 1
        return node.value, hops

    def to_list(self):
        out, node = [], self._head
        while node is not None:
            out.append(node.value)
            node = node.next
        return out


def array_get(slots, index):
    """Contiguous slots: one address computation, no element visits."""
    return slots[index], 0


def array_insert_front(slots, value):
    """Shift every existing slot to the right; count the moves."""
    slots.append(None)
    moves = 0
    for position in range(len(slots) - 1, 0, -1):
        slots[position] = slots[position - 1]
        moves += 1
    slots[0] = value
    return moves


slots = list(range(6))
chain = Chain()
for value in range(6):
    chain.append(value)

moves = array_insert_front(slots, -1)
writes = chain.insert_front(-1)
print("contiguous slots after insert(0, -1):", slots, "| element moves:", moves)
print("linked nodes after insert(0, -1)    :", chain.to_list(), "| reference writes:", writes)

print()
print(f"{'n':>4} {'array get(n-1)':>15} {'chain get(n-1)':>15}")
for size in (100, 200, 400):
    slots = list(range(size))
    chain = Chain()
    for value in range(size):
        chain.append(value)
    _, array_visits = array_get(slots, size - 1)
    _, chain_hops = chain.get(size - 1)
    print(f"{size:>4} {array_visits:>15} {chain_hops:>15}")
```

两种存放各自给出自己那条序列，逐项相等：头部插入在连续槽位上移动了全部已有元素，在链式结点上只写了一条引用；按下标读取时，链式结点要走下标那么多步引用，连续槽位不碰其他元素。调用方从返回值读不出用的是哪一种存放。序列接口规定的是按位置读取、追加、插入、删除四种动作与它们的结果；元素放在哪里、每种动作花多少工作量，由存放方式给出，也就是由**表示**给出。同一接口因此允许代价不同的多种表示。

## 表示不变量

链式存放要让追加保持在一次引用改写上，就得随时握住最后一个结点；上面那份实现额外存了一个尾引用 `_tail`。尾引用与结点之间有一条必须成立的关系：它指向从头结点沿引用走到的最后一个结点，且当且仅当链为空时它是 `None`。这条关系不写在任何一次动作的返回值里，它约束的是表示的合法状态。删除末尾的那个结点时，必须把尾引用移回新的末尾；漏掉这一步：

```python run id="alg.adt.invariant-check"
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next


class Chain:
    """Linked sequence with a cached tail; delete() never brings the tail back in line."""

    def __init__(self):
        self._head = None
        self._tail = None

    def append(self, value):
        node = Node(value)
        if self._head is None:
            self._head = self._tail = node
        else:
            self._tail.next = node
            self._tail = node

    def delete(self, index):
        if index == 0:
            value = self._head.value
            self._head = self._head.next
            return value
        previous = self._head
        for _ in range(index - 1):
            previous = previous.next
        value = previous.next.value
        previous.next = previous.next.next
        return value

    def to_list(self):
        out, node = [], self._head
        while node is not None:
            out.append(node.value)
            node = node.next
        return out


sequence = Chain()
for value in (5, 6, 7, 8):
    sequence.append(value)
print("built:", sequence.to_list(), "| tail:", sequence._tail.value)

removed = sequence.delete(3)
print("delete(3) returned:", removed, "| sequence now:", sequence.to_list())

sequence.append(9)
print("after append(9):", sequence.to_list(), "| cached tail:", sequence._tail.value)
```

删除本身做对了：它摘掉位置 3 的结点 8 并返回 8，没有抛出异常，紧跟其后列出的序列是 `[5, 6, 7]`。尾引用仍指着那个已经被摘掉的 8。下一次 `append(9)` 把新结点接到这个已经离开链的结点后面，从头结点出发再也走不到 9——追加执行了，序列却没有变长。缺陷不在这两次调用的任何一次返回上，而在两步之间，尾引用与末尾结点之间那条关系不再成立。

尾引用与末尾结点之间那条必须在每个公开操作返回时成立的关系，是链式表示的**表示不变量**（representation invariant）：尾引用指向最后一个结点，链为空时它与头引用同时为 `None`。

更一般地，<Term id="invariant">不变量</Term>规定哪些具体状态是合法表示；每个满足它的合法具体状态都解释为调用方能观察到的某个状态，多个不同的合法状态也可以对应同一个可观察状态。尾引用不表示序列里的任何元素，它是为了让追加便宜而添的一格**冗余表示状态**：去掉它、改成走到末尾，调用方看到的序列不变。哈希表用桶数组存放键值对、删除时留下的墓碑，属于同一类状态——对外它是一张键到值的映射，内部多出一层只为操作成本服务的结构。

在合法状态上，每个操作在返回之前都要让不变量重新成立：

| 步骤 | 需要证明的性质 |
| --- | --- |
| 构造器 | 构造完成时 I 成立 |
| 每个公开操作 | 假设进入这个操作时 I 成立，证明它在正常返回前重新成立 |

初始化是基例，每个操作是归纳步，两者合起来说明 I 在每一次调用边界上都成立。不变量在操作执行过程中可以暂时不成立：删除先摘掉结点、再把尾引用移回新的末尾，中间那一刻尾引用指着已经离开链的结点，它只需在返回之前重新成立；上面那次删除漏掉的正是最后这一步。

这是实现内部需要证明的性质；调用方依赖的是可观察的状态转移、返回值与失败行为，尾引用这类表示细节与它的不变量不在公开规约之内。违反它通常不会立刻报错：它先让实现所依赖的事实失效，再在某次看起来无关的调用上表现为错误结果，上面丢掉的那个 9 就是这种延迟表现。

## 抽象操作规约

两份实现共用的对外接口可以精确定义。抽象状态是一条序列 $S = (s_0, \dots, s_{n-1})$，元素按进入顺序排列。

| 操作 | 行为 |
| --- | --- |
| `get(i)` | 若 $0 \le i < n$，返回 $s_i$ |
| `append(x)` | 把 x 接到 $S$ 末尾 |
| `insert(i, x)` | 若 $0 \le i \le n$，把 $S$ 变为它的前 $i$ 个元素、x、其余元素按序拼接（逻辑位置改变，与物理存储无关） |
| `delete(i)` | 若 $0 \le i < n$，移除并返回 $s_i$，其余元素按序前接 |

抽象状态 $S$、上面这组操作，以及每个操作对 $S$ 的行为，合起来是这条序列的**抽象操作规约**；抽象状态与操作单独拿出来，就是**抽象数据类型**（abstract data type, ADT）。规约只规定调用方能观察到的东西，元素存在哪里、有没有握住尾结点、字段叫什么名字都留在规约之外。

同一个问题可以沿它数出四层：**问题规约**是要一条能按位置读取、在任意位置插入与删除的序列；**抽象操作规约**是上面那张表；**表示**是元素放在连续槽位里还是链式结点里、尾结点按需走到还是另存一个引用；**算法**是每个操作怎样读写这些状态、什么时候走结点改引用。连续槽位版与链式结点版只在表示与算法两层不同，问题规约与抽象操作规约是同一份。

表格中的 `get` 与 `delete` 以 $0 \le i < n$ 为**前置条件**，`insert` 以 $0 \le i \le n$ 为前置条件；不满足前置条件的调用不在规约范围内，规约不规定它们的结果。失败行为是另一种写法：把「越界时抛出哪一种异常」写进后置条件，调用方就能依赖它。二分查找把输入已有序写成前置条件，违反它时规约不保证正常的后置条件。

接口的功能不决定复杂度：同一个 `get(i)`，在连续槽位上是一次地址计算，在链式结点上要沿引用走 $i$ 步。具体的量级还要看表示、算法与计数方式。

## 两种表示的成本

连续槽位把工作留在修改上：`get(i)` 一步算到元素位置，`insert(0, x)` 却要移动全部已有元素。链式结点把工作挪到定位上：`get(i)` 走 $i$ 步引用，头部插入只写一条引用。

两种表示各记一次成本，得到这张对照。计数方式是在单位成本模型下「一次元素移动、一次引用跳转、一次引用改写各记 1」（见 <CrossRef id="algorithms.cost-model" />）；按位置读取与头部插入两列的计数来自上面那段真实运行，追加与删除两列由表示直接读出。

| 表示 | `get(i)` | `append(x)` | `insert(0, x)` | `delete(i)` | 额外空间 |
| --- | --- | --- | --- | --- | --- |
| 连续槽位 | 一次地址计算，$\Theta(1)$ | 写到末尾，$\Theta(1)$ | 移动 $n$ 个元素，$\Theta(n)$ | 移动 $n - i - 1$ 个后继元素，$\Theta(n - i)$ | $0$ |
| 链式结点（另存尾引用） | 沿引用走 $i$ 步，$\Theta(i)$ | 改尾引用，$\Theta(1)$ | 新建结点、改入口引用，$\Theta(1)$ | 定位前驱 $\Theta(i)$ 后改引用 | 每元素一个结点，另加一格尾引用 |

两行把同一笔工作量在按位置读取、修改与额外空间之间换位置：连续槽位让读取不碰其他元素，代价压在头部插入的移动上；链式结点让头部插入不碰其他元素，代价压在按位置读取的定位上，另存尾引用又把追加降到常数，代价是尾引用必须在每次改动末尾结点时同步。两份实现对调用方是同一条序列：同样的四种操作、同样的返回值、同样的前置条件，不同只在表示与算法两层。表示不变量在每次公开操作返回时重新成立，是这类用额外状态换操作成本的实现能成立的前提：漏掉一次重建，留下的是过去状态算出的结果。
