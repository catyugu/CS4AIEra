一个栈，支持压入元素、弹出最后压入的元素，还要随时回答当前的最小元素。前两个操作由后进先出顺序直接给出；`minimum()` 要在不断变化的元素上给出最小值，回答它的代价取决于实现把这份工作放在哪一个操作里。把最小值缓存下来，`minimum()` 变成一次读取，代价是每个公开操作返回之前，缓存都要与当时的元素对得上。

这份实现只在 `push` 里更新缓存：新元素与记录比较一次，更小就换掉记录。`pop` 弹出元素之后，记录与元素之间的那条关系可能不再成立；关系一旦不成立，`minimum()` 会继续给出一个过时的值。

## 缓存失效的那一次 pop

```python run id="alg.adt.invariant-check"
class MinStack:
    """Stack with a cached minimum; only push() updates the cache."""

    def __init__(self):
        self._values = []
        self._cached_min = None

    def push(self, value):
        self._values.append(value)
        if self._cached_min is None or value < self._cached_min:
            self._cached_min = value

    def pop(self):
        return self._values.pop()

    def minimum(self):
        return self._cached_min


stack = MinStack()
for value in (5, 3, 7, 3):
    stack.push(value)
print("pushed (5, 3, 7, 3): minimum() =", stack.minimum())
for step in range(3):
    popped = stack.pop()
    actual = min(stack._values)
    print(f"pop {popped}: minimum() = {stack.minimum()}, elements min {actual}, agrees {stack.minimum() == actual}")
```

四行 `push` 之后缓存给出的最小值是 3。前两次弹出之后缓存仍然正确：第一次弹出的 3 是当时最小值的一份，元素里还留着另一份，最小值没有变化；弹出 7 也不影响记录。第三次弹出移走了最后一个 3，剩下的元素只有 5，缓存里留着的仍是 3——这是缓存第一次与元素不一致的操作，`minimum()` 从这一刻起给出的就是错值。`pop` 返回的元素正确，也没有抛出异常，错误只在后续查询上显形。

修正只需要在 `pop` 返回之前补一句，把缓存重算为当前元素里的最小值。这句重算在单槽缓存上要扫描全部元素，花的正是它当初省下的那笔工作；要让修正也便宜，表示就得为每个前缀各留一个最小值。

## 表示不变量

缓存与元素之间那条必须在每个公开操作返回时成立的关系，是这份实现的**表示不变量**（representation invariant）。对只记一个最小值的设计，它是：缓存等于 `_values` 中的最小值，并且当且仅当 `_values` 为空时它是 `None`。

更一般地，<Term id="invariant">不变量</Term>规定哪些具体状态是合法表示；每个满足它的合法具体状态都解释为调用方能观察到的某个状态，多个不同的合法状态也可以对应同一个可观察状态。`_cached_min` 不表示元素序列的任何部分，它是为了让 `minimum()` 便宜而添加的**冗余表示状态**：去掉它，调用方看到的状态不变，`minimum()` 重新扫描元素即可。哈希表的桶数组与探测留下的墓碑属于同一类状态——对外它是一个键到值的映射，内部多出一层只为操作成本服务的结构。

在合法状态上，每个操作在返回之前都要让不变量重新成立：

| 步骤 | 需要证明的性质 |
| --- | --- |
| 构造器 | `__init__` 返回时 I 成立 |
| 每个公开操作 | 假设进入这个操作时 I 成立，证明它在正常返回前与异常退出前重新成立 |

初始化是基例，每个操作是归纳步，两者合起来说明 I 在每一次调用边界上都成立。不变量在操作执行过程中可以暂时不成立：`pop` 先移除元素、再修正缓存，中间那一刻缓存是过时的，它只需在返回之前重新成立。

这是实现内部需要证明的性质；调用方依赖的是可观察的状态转移、返回值与失败行为，`_cached_min` 这类表示细节与它的不变量不在公开规约之内。违反它通常不会立刻报错：它先让实现所依赖的事实失效，再在某次看起来无关的调用上表现为错误答案，上面那行打印出 3 的 `minimum()` 就是这种延迟表现。

## 抽象操作规约

两份实现共用的对外接口可以精确定义。抽象状态是一个序列 $S$，元素按进入顺序排列。

| 操作 | 行为 |
| --- | --- |
| `push(x)` | 把 x 接到 $S$ 末尾 |
| `pop()` | 若 $S$ 非空，返回并移除 $S$ 的最后一个元素；若为空，抛出约定异常 |
| `minimum()` | 若 $S$ 非空，返回 $S$ 中的最小元素且不改变 $S$；若为空，抛出约定异常 |

抽象状态 $S$、上面这组操作，以及每个操作对 $S$ 的行为，合起来是这份栈的**抽象操作规约**；抽象状态与操作单独拿出来，就是**抽象数据类型**（abstract data type, ADT）。规约只规定调用方能观察到的东西，元素存在哪里、缓存了什么、字段叫什么名字都留在规约之外。整份规约假定所有元素取自同一个可比较的有序域，否则「最小」在这些元素上没有定义。

同一个问题可以沿它数出四层：**问题规约**是一个栈，支持 `push`、`pop`，并能随时回答当前最小元素；**抽象操作规约**是上面那张表；**表示**是元素用什么保存、最小值按需重算还是随元素一起缓存；**算法**是每个操作怎样读写这些状态、什么时候重算缓存。扫描版与前缀最小值版的差别只落在后两层，前两层是同一份。

空栈上的行为被写进规约的后置条件，调用方可以依赖这个失败行为。前置条件是另一条路线，它限制一个操作能保证后置条件的输入范围：二分查找以输入已有序为前置条件，违反它时规约不保证正常的后置条件。这一课的两条边界各用一种写法，空栈写进规约的失败行为，「元素可比较」是整份规约的假设。

接口的功能不决定复杂度：同一个 `minimum()`，在一种表示上要扫描全部元素，在另一种表示上只读一次缓存。具体的量级还要看表示、算法与计数方式。

## 两种表示的成本

扫描版把工作留在查询上：栈里保存元素本身，`minimum()` 从头比较一遍。前缀最小值版把工作挪到修改上：每个元素多配一个槽位，记录到该元素为止的最小值，`push` 用一次比较更新这个槽位，`pop` 删掉末尾的槽位，`minimum()` 读最后一个槽位。下面两个函数把同一组输入分别交给两条路线，打印出各自的元素比较次数与额外槽位数。

```python run id="alg.adt.two-representations"
def scan_on_query(values):
    """A: compare every element when minimum() is asked; keep nothing else."""
    comparisons = 0
    smallest = values[0]
    for value in values[1:]:
        comparisons += 1
        if value < smallest:
            smallest = value
    return smallest, comparisons


def update_on_push(values):
    """B: one prefix-minimum slot per element; push updates it with one comparison."""
    minima, comparisons = [], 0
    for value in values:
        if minima:
            comparisons += 1
        minima.append(value if not minima else min(value, minima[-1]))
    return minima, comparisons


print(f"{'n':>5} {'same minimum':>12} {'A: comparisons at query':>24} {'B: comparisons at push':>23} {'B: extra slots':>14}")
for size in (100, 200, 400):
    values = list(range(size, 0, -1))
    smallest, query = scan_on_query(values)
    minima, pushes = update_on_push(values)
    print(f"{size:>5} {str(smallest == minima[-1]):>12} {query:>24} {pushes:>23} {len(minima):>14}")
```

两个版本对同一个输入给出相同的最小值，差别落在计数上。$n = 100$ 的输入上，扫描版回答一次 `minimum()` 花 99 次元素比较；前缀最小值版在 100 次 `push` 里一共花 99 次比较，另外持有 100 个冗余槽位。$n$ 取 200 与 400 时两组数字分别是 199 与 399，都等于当时的元素个数减一——两个版本的元素比较次数都是 $n - 1$，只是一份花在查询上、另一份花在压入上；查询本身在前缀最小值版里是一次槽位读取，一次元素比较都不做。

三份表示各记一次成本，得到这张对照：

| 表示 | 查询 `minimum()` | `push` | `pop` | 额外空间 |
| --- | --- | --- | --- | --- |
| 元素本身 | $\Theta(n)$ 次元素比较 | $\Theta(1)$ | $\Theta(1)$ | $0$ |
| 元素本身加一个当前最小值 | $\Theta(1)$ 次读取 | 新元素一次比较 | 重算缓存要 $\Theta(n)$ 次比较 | $\Theta(1)$ 个槽位 |
| 元素本身加每个前缀的最小值 | $\Theta(1)$ 次读取 | 新元素一次比较 | 删除末尾一个槽位 | $\Theta(n)$ 个槽位 |

对照的计数方式是单元成本模型下的「一次元素比较记 1，额外保存一个槽位记 1」（见 <CrossRef id="algorithms.cost-model" />），计数对象是上面那段真实运行。三行的差别是把同一笔总成本在查询、修改与额外空间之间换位置：单槽缓存把查询降到常数，却让 `pop` 上的修正是 $\Theta(n)$；前缀最小值版用每个元素一个槽位，把修改也压到 $\Theta(1)$，付出的空间是 $\Theta(n)$。

两份实现对调用方是同一个栈：同样的三个操作、同样的返回值、空栈上同样的失败行为，差别落在表示与算法两条上。表示不变量在每次公开操作返回时重新成立，是这类以额外状态换查询成本的实现能成立的前提：漏掉一次重建，缓存里留下的就是过去元素的答案。
