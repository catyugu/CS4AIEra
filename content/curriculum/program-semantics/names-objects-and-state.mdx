一个名字可以指向一个列表，两个名字也可以指向同一个列表。这个区别决定了修改会影响谁。

## 列表与点号调用

`[10, 20]` 创建一个列表，里面有两个元素。列表可以追加元素：`samples.append(30)` 中的点号表示使用 `samples` 这个对象提供的操作，`append` 是追加操作的名字，括号里是要追加的值。这种属于对象的函数叫方法（method）。

```python run id="program-semantics.names-objects-and-state.alias"
samples = [10, 20]
view = samples
view.append(30)
print("samples:", samples)
print("view:", view)
print("same object:", samples is view)

view = [40]
print("samples:", samples)
print("view:", view)
print("same object:", samples is view)
```

`samples = [10, 20]` 创建列表，把名字绑定到它。`view = samples` 读取已有对象，再绑定另一个名字，**没有复制列表**。两个名字指向同一个对象，互为<Term id="alias">别名</Term>。

`view.append(30)` 修改这个列表，所以两个名字都看到追加后的内容。`view = [40]` 则创建另一个列表，只改变 `view` 的指向。`samples` 仍指向原列表。

`is` 判断是不是同一个对象，返回 `True` 或 `False`。`==` 判断值是否相等：两个分别创建的 `[10, 20]` 内容相等，但不是同一个列表。

## 对象可以变，名字也可以换指向

Python 中的值都是对象。对象有身份（identity）、类型（type）和内容：身份区分它与其他对象，在其存活期间不变；类型规定允许哪些操作；内容是我们读取和运算的值。

列表是可变对象，可以通过 `append` 等操作修改内容。整数、浮点数和字符串是不可变对象，不能就地改写自己的值。

```python run id="program-semantics.names-objects-and-state.immutable"
number = 10
kept = number
number = number + 1
print("number:", number)
print("kept:", kept)
```

`number + 1` 算出另一个整数，再把 `number` 绑定到它。`kept` 仍指向原来的 `10`。原来的整数没有变成 `11`。

对名字的赋值 `name = expression` 改变绑定，不直接修改它原先指向的对象。右边的表达式仍可能调用会修改对象的函数，不能据此认为整条赋值语句一定没有副作用。

## 复制列表

`list(samples)` 创建一个新列表。给新列表追加元素，不会给原列表追加：

```python run id="program-semantics.names-objects-and-state.copy"
samples = [10, 20]
working = list(samples)
working.append(30)
print("samples:", samples)
print("working:", working)
print("same object:", samples is working)
```

但复制外层列表，并没有复制里面的对象。这叫<Term id="shallow-copy">浅拷贝</Term>。列表可以包含其他列表；`batches[0]` 读取第一个元素，下标从 0 开始。

```python run id="program-semantics.names-objects-and-state.copy-levels"
batches = [[10, 20], [30, 40]]
working = list(batches)
working[0].append(50)
print("batches:", batches)
print("working:", working)
print("same outer list:", batches is working)
print("same first list:", batches[0] is working[0])
```

两个外层列表不同，第一个元素却指向同一个内部列表。因此 `working[0].append(50)` 从两处都能看到。需要独立修改这个内部列表时，还要复制它；递归复制的含义见<Term id="deep-copy">深拷贝</Term>。

## 共享是否符合要求

共享本身可以是有意的。例如两处代码都要看到同一份待处理任务，追加任务就应该在两处可见。如果一处要求保留原记录，另一处却把它当工作清单修改，共享就违反了这个要求。

判断一次修改会影响谁，要找到哪些名字和容器元素仍指向这个对象，再检查那些使用方是否允许看到修改后的内容。

## 练习

预测三个名字的内容，以及哪些名字指向同一个列表，再运行验证：

```python run id="program-semantics.names-objects-and-state.exercise-append-then-rebind"
samples = [10]
view = samples
spare = list(samples)
view.append(20)
spare.append(30)
view = [40]

print("samples:", samples)
print("view:", view)
print("spare:", spare)
print("samples is view:", samples is view)
print("samples is spare:", samples is spare)
```
