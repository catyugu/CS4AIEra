函数把一段计算命名。调用方交给它参数，函数执行自己的代码，再把结果返回。读懂一个函数，需要分别追踪它返回什么、修改什么。

## 定义函数，再调用它

```python run id="program-semantics.functions-as-boundaries.return"
def task_label(name, status):
    return name + ": " + status


label = task_label("build-index", "pending")
print(label)
```

`def` 执行时创建函数对象，把它绑定到 `task_label`。下面缩进的函数体此时还不执行。调用时，实参 `"build-index"` 和 `"pending"` 分别绑定到形参 `name` 和 `status`，然后执行函数体。`return` 后的表达式求值得到字符串，成为调用的结果，赋给 `label`。

每次调用都有自己的局部名字。函数里的 `name` 不会成为调用方的名字；两次调用也不会共用同一份参数绑定。实参既可以按位置写，也可以按参数名写：`task_label(status="pending", name="build-index")` 返回相同的结果。

## return 结束当前调用

```python run id="program-semantics.functions-as-boundaries.find"
def first_above(numbers, limit):
    for number in numbers:
        if number > limit:
            return number
    return None


print(first_above([3, 8, 12], 5))
print(first_above([3, 8, 12], 20))
print(first_above([], 5))
```

找到第一个超过上限的数时，`return` 结束整个调用，剩下的列表元素不再检查。没有找到时，函数返回 `None`，表示没有结果。函数执行到末尾而没有遇到 `return`，也会返回 `None`。

返回值和输出是不同的事：`return` 把值交给调用方，`print` 把文本写入输出。调用方可以保存、比较或继续使用返回值；屏幕上有文字不表示函数返回了那个字符串。

## 参数绑定不复制对象

形参绑定到实参对象，是这个对象的另一个名字（<Term id="alias">别名</Term>）。对形参重新赋值只改变局部名字；通过形参修改列表，则会改变调用方持有的列表。

```python run id="program-semantics.functions-as-boundaries.binding"
def add_task(tasks, title):
    tasks.append(title)


pending = ["parse"]
result = add_task(pending, "render")
print("caller tasks:", pending)
print("returned:", result)
```

`append` 修改原列表，调用方看到 `['parse', 'render']`。函数没有 `return`，所以 `result` 为 `None`。如果把函数体改成 `tasks = [title]`，它只会改变局部参数名的绑定，不会修改调用方的列表。修改与重绑定的区别见 <CrossRef id="program-semantics.names-objects-and-state" />。

## 修改输入，还是返回一份新结果

修改传入对象、写入输出、改变模块里的共享数据，都属于调用的副作用（side effect）。函数返回什么和它修改什么，需要分别读清楚。

```python run id="program-semantics.functions-as-boundaries.copy"
def with_task(tasks, title):
    result = list(tasks)
    result.append(title)
    return result


pending = ["parse"]
updated = with_task(pending, "render")
print("original:", pending)
print("updated:", updated)
print("same list:", pending is updated)
```

这里 `pending` 仍只有 `parse`，新列表里有两项。`with_task` 可以用于需要保留原清单的场合；`add_task` 适合明确要修改原清单的场合。两个函数都能“加一项任务”，对调用方的影响却不同。

函数的<Term id="specification">规约</Term>说明允许什么输入、返回什么结果，以及有哪些副作用。例如 `with_task` 要求 `tasks` 是任务列表、`title` 是任务名字符串，返回追加后的新列表，不修改输入列表。输入必须满足的要求称为<Term id="precondition">前置条件</Term>。函数名和参数名只能提供线索，不能替代这些约定。

## 练习

`del tasks[count:]` 删除从下标 `count` 到末尾的元素。下面的函数声称“返回前 `count` 项任务，原清单保持不变”，允许 `count` 为非负整数。预测它的返回值和调用后 `tasks` 的内容，再运行验证。构造一个只有一项任务的输入，判断这个说法是否成立；然后改写函数，使空列表和 `count = 0` 时也满足要求。

```python run id="program-semantics.functions-as-boundaries.exercise-take"
def first_tasks(tasks, count):
    del tasks[count:]
    return tasks


tasks = ["parse", "render", "review"]
print("result:", first_tasks(tasks, 2))
print("original:", tasks)
```
