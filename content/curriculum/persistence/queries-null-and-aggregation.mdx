从书表中列出有库存的书，需要指定要读的表、要显示的列、筛选条件和输出顺序：

```sql run id="persistence.queries.available" fixture="catalog"
SELECT id, title, stock
FROM books
WHERE stock > 0
ORDER BY id;
```

`FROM books` 指定表，`WHERE stock > 0` 筛选有库存的行，`SELECT` 选择输出列，`ORDER BY id` 按编号排列。查询描述所需结果，数据库选择实际读取这些数据的方法。

## 查询结果与去重

列出每本书的分类，与列出所有不同分类，得到的行数不同：

```sql run id="persistence.queries.duplicates" fixture="catalog"
SELECT category FROM books ORDER BY category;
SELECT DISTINCT category FROM books ORDER BY category;
```

computing 分类有两本书，第一条查询输出两次 computing。`DISTINCT` 按输出列去重，所以第二条只保留一次。需要每本书的分类时保留重复，需要分类列表时才去重。

## 分组与统计

`GROUP BY category` 把相同分类的行分到一组。`COUNT(*)` 计算每组行数，`AVG(price)` 计算已有价格的平均值，`AS` 为输出列命名：

```sql run id="persistence.queries.aggregate" fixture="catalog"
SELECT category, COUNT(*) AS books,
       COUNT(price) AS priced_books, AVG(price) AS average_price
FROM books
GROUP BY category
ORDER BY category;
```

history 分类有两本定价 50 的书，平均价格是 50。computing 分类有一本定价 80，另一本未定价，所以 `COUNT(*)` 是 2，`COUNT(price)` 是 1，平均价格是 80。行数与已有价格的数量回答了不同问题。

## 缺失值怎样参与查询

表用 `NULL` 表示缺失。本例中，它表示价格尚未确定；0 表示已知价格为零。SQL 比较缺失价格与 60 时，得到未知（unknown）。`WHERE` 只保留条件为真的行，因此缺失价格既不会通过 `price > 60`，也不会通过它的取反条件。

```sql run id="persistence.queries.null" fixture="catalog"
SELECT id, price, price > 60 AS expensive,
       NOT (price > 60) AS not_expensive
FROM books ORDER BY id;
SELECT id, title FROM books WHERE price IS NULL ORDER BY id;
```

`IS NULL` 检查缺失值。实验中 SQLite 用 1、0 和 NULL 显示真、假、未知。完整表达式规则见 [SQLite 表达式](https://www.sqlite.org/lang_expr.html)。

`COUNT(price)`、`SUM(price)` 和 `AVG(price)` 忽略缺失价格。若需要“全部书的平均定价”，缺失数据意味着还无法计算这个量；把缺失值填成零会改变问题。聚合规则见 [SQLite 聚合函数](https://www.sqlite.org/lang_aggfunc.html)。

## 练习

列出价格不高于 60 的书，也包括尚未定价的书。先按原始数据写出编号，再运行下面的查询，补齐漏掉的记录：

```sql run id="persistence.queries.exercise-filter" fixture="catalog"
SELECT id, title, price
FROM books
WHERE NOT (price > 60)
ORDER BY id;
```

另一个报表把 `COUNT(price)` 标为“书的总数”。修改一条记录的价格，使这个标题与实际统计对象的差别显现出来。
