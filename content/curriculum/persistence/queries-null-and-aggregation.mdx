书店首页要按编号显示有货书目的书名和库存。

```sql run id="persistence.queries.available" fixture="catalog"
SELECT id, title, stock
FROM books
WHERE stock > 0
ORDER BY id;
```

`WHERE` 决定哪些行进入结果，`SELECT` 决定显示哪些列，`ORDER BY` 规定结果的顺序。数据库怎样读取记录，见 <CrossRef id="persistence.indexes-and-query-plans" />。

## 查询、排序与去重

首页还有一个分类下拉菜单，每个分类只出现一次。直接查询 `category` 会为每本书返回一行，两个分类各出现两次。加上 `DISTINCT`，相同的输出行合并为一行。

```sql run id="persistence.queries.duplicates" fixture="catalog"
SELECT category FROM books ORDER BY category;
SELECT DISTINCT category FROM books ORDER BY category;
```

## 分组与聚合

管理员在看板上同时查看各分类的书目数、已定价书目数和已定价书目的均价。`GROUP BY category` 按分类分组，聚合函数为每组算出统计值。`AS` 给输出列命名。

```sql run id="persistence.queries.aggregate" fixture="catalog"
SELECT category, COUNT(*) AS titles,
       COUNT(price) AS priced_titles, AVG(price) AS average_price
FROM books
GROUP BY category
ORDER BY category;
```

computing 的两本书价格为 80 和 `NULL`，所以 `COUNT(*)` 得到 2，`COUNT(price)` 得到 1，`AVG(price)` 得到 80。零元是已知价格，仍参与计数和均价。[SQLite 聚合函数](https://www.sqlite.org/lang_aggfunc.html)

## NULL 与缺失值

价格待定时，`price > 60` 与它的取反都得到未知。SQLite 用 `1`、`0`、`NULL` 显示真、假、未知。`WHERE` 只保留为真的行，因此要单独找出待定价书目，应写 `WHERE price IS NULL`。[SQLite 表达式](https://www.sqlite.org/lang_expr.html) · [SQLite SELECT 文档](https://www.sqlite.org/lang_select.html#whereclause)

```sql run id="persistence.queries.null" fixture="catalog"
SELECT id, price, price > 60 AS above_60,
       NOT (price > 60) AS not_above_60
FROM books
ORDER BY id;

SELECT id, title FROM books WHERE price IS NULL ORDER BY id;
```

## 练习

活动页面要列出价格不高于 60 元的书，也要显示待定价的书。先列出期望返回的编号，再用 `OR` 补充下面的筛选条件，核对结果。

```sql run id="persistence.queries.exercise-filter" fixture="catalog"
SELECT id, title, price
FROM books
WHERE price <= 60
ORDER BY id;
```

把报表中的 `COUNT(price)` 标为「书目总数」，再把一条已定价记录的价格改成 `NULL`。分别预测书目总数、已定价数和平均价格的变化。若改为 0，哪些结果会不同？
