结账要扣减库存并创建订单，两次写入应当一起生效。

## 事务提交与原子性

事务把一组操作组织成一次提交。`BEGIN` 开始事务，`COMMIT` 提交修改，`ROLLBACK` 撤销未提交的修改。一个事务中的修改共同生效或撤销，这个性质叫原子性。

下面用 SQLite 购买一册书，初始库存为 3。修改后在事务内查询，再撤销并重新查询。

```sql run id="persistence.transactions.rollback" fixture="catalog"
BEGIN;
UPDATE books SET stock = stock - 1 WHERE id = 1;
INSERT INTO orders (id, reference, book_id, quantity)
VALUES (13, 'r13', 1, 1);

SELECT stock FROM books WHERE id = 1;
SELECT id, reference FROM orders WHERE id = 13;

ROLLBACK;

SELECT stock FROM books WHERE id = 1;
SELECT id, reference FROM orders WHERE id = 13;
```

| 查询时点 | 库存 | 订单 13 |
| --- | --- | --- |
| 事务开始前 | 3 | 无记录 |
| 两次修改执行后 | 2 | 已写入，本连接可读取 |
| 撤销后 | 3 | 无记录 |

把 `ROLLBACK` 换成 `COMMIT`，最后两次查询会读取提交后的库存和订单。

## 回滚与异常处理

扣减成功后，插入订单可能触发唯一约束。SQLite 默认撤销失败语句，先前的扣减仍留在事务里，应用应显式回滚。[SQLite 冲突处理文档](https://www.sqlite.org/lang_conflict.html)

下面用 Python 重放请求编号重复的情况。

```python run id="persistence.transactions.failure"
import sqlite3

db = sqlite3.connect(":memory:")
db.executescript("""
    CREATE TABLE books (id INTEGER PRIMARY KEY, stock INTEGER);
    CREATE TABLE orders (reference TEXT NOT NULL UNIQUE);
    INSERT INTO books VALUES (1, 3);
    INSERT INTO orders VALUES ('r10');
""")
db.execute("BEGIN")
try:
    db.execute("UPDATE books SET stock = stock - 1 WHERE id = 1")
    db.execute("INSERT INTO orders VALUES ('r10')")
    db.commit()
except sqlite3.IntegrityError:
    db.rollback()
    print("订单请求编号重复")

print("库存", db.execute("SELECT stock FROM books WHERE id = 1").fetchone()[0])
db.close()
```

`execute` 遇到约束错误时抛出 `IntegrityError`，由异常处理执行 `rollback()`。程序最终输出库存 3。把 `db.rollback()` 改成 `db.commit()` 再运行，库存会变成 2，订单仍只有原来一笔。

## ACID

| 性质 | 在结账中的作用 |
| --- | --- |
| 原子性（Atomicity） | 库存扣减和订单写入共同提交，或一同撤销 |
| 一致性（Consistency） | 事务按约束与正确的业务逻辑维护数据规则，例如库存非负、订单引用有效书目 |
| 隔离性（Isolation） | 约定并发购买能观察到哪些数据，以及冲突时怎样处理 |
| 持久性（Durability） | 提交成功的修改在数据库承诺的故障条件下可以恢复 |

条件扣减影响零行时，应结束事务并报告库存不足。若继续插入订单，数据库可能成功提交实际发生的写入。并发情形见 <CrossRef id="persistence.concurrent-updates-and-isolation" />。

## 持久性与崩溃恢复

SQLite 的回滚日志保存改写前的数据页，供恢复未完成事务。采用<Term id="write-ahead-log">预写日志</Term>模式时，SQLite 先把修改写到日志，再写回主库。故障后能恢复哪些提交，取决于日志模式、同步设置和存储设备。[SQLite 原子提交文档](https://www.sqlite.org/atomiccommit.html) · [SQLite WAL 文档](https://www.sqlite.org/wal.html)

事务外的邮件等动作要另外协调，见 <CrossRef id="software-systems.delivery-and-recovery" />。
