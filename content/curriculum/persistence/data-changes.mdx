管理后台允许补录订单和调整价格。修改前先确认目标记录，执行后用同样的查询查看状态。下面每格都从 SQLite 的 <LabRef id="catalog" /> 数据开始。

## 补录与撤销误录

管理员补录订单 13，随后发现这条记录录错了，要将它移除。`INSERT INTO` 给出表名和列名，`VALUES` 按对应顺序提供值。`DELETE FROM` 用 `WHERE` 选中要删除的行。

```sql run id="persistence.changes.insert" fixture="catalog"
SELECT id, reference, book_id, quantity FROM orders WHERE id = 13;

INSERT INTO orders (id, reference, book_id, quantity)
VALUES (13, 'r13', 1, 2);

SELECT id, reference, book_id, quantity FROM orders WHERE id = 13;

DELETE FROM orders WHERE id = 13;

SELECT id, reference, book_id, quantity FROM orders WHERE id = 13;
```

| 查询时点 | 结果 |
| --- | --- |
| 新增前 | 空结果 |
| 新增后 | 订单 13，请求编号 `r13`，书 1，共 2 册 |
| 删除后 | 空结果 |

## 调整价格

`UPDATE` 中的 `SET` 给出新值，`WHERE` 选中要改的行。下面把书 1 的价格从 80 改成 70。省略 `WHERE` 会将整张表的价格设为 70。如果按分类批量调价，可以先用相同的条件查询，确认范围。

```sql run id="persistence.changes.update" fixture="catalog"
SELECT id, price FROM books ORDER BY id;

UPDATE books SET price = 70 WHERE id = 1;

SELECT id, price FROM books ORDER BY id;
```

| id | 改价前 | 改价后 |
| --- | --- | --- |
| 1 | 80 | 70 |
| 2 | `NULL` | `NULL` |
| 3 | 50 | 50 |
| 4 | 50 | 50 |

## 库存扣减

购买两册书要求库存至少为 2。把这个条件写进 `WHERE`，再用当前库存计算扣减后的值。`changes()` 返回前一条修改语句直接影响的行数。[SQLite changes 函数](https://www.sqlite.org/lang_corefunc.html#changes)

```sql run id="persistence.joins.conditional-update" fixture="catalog"
UPDATE books
SET stock = stock - 2
WHERE id = 1 AND stock >= 2;

SELECT changes() AS changed_rows;
SELECT id, stock FROM books WHERE id = 1;
```

初始库存为 3，更新影响一行，库存减至 1。把数量改为 100 时，`SET` 和 `WHERE` 都要改，结果是影响零行，库存仍为 3。对后端来说，零行表示本次扣减未完成。要区分书目不存在和库存不足，可以再查该书目。

扣库存和创建订单要一起提交，由 <CrossRef id="persistence.transactions-and-recovery" /> 继续讨论。

## 练习

书店要给已定价的缺货书降价 10 元。先用查询找出符合条件的行，再修改调价单元格并运行。当前唯一一本缺货书的价格是 `NULL`。在单元格开头先把这本书的价格设为 50，再运行一次，比较两个场景的结果。
