假设待办清单保存在 Python 列表中。运行时可以增删任务，但再次启动程序时，列表会按代码中的初始值重新创建。要保留上一次的任务，程序必须把数据存到进程之外，之后再读取。

## 内存状态与持久存储

让数据在程序结束后仍能保存，供下次运行读取，称为持久化。文件和数据库都可以承担这项工作，适用的访问方式有所区别。

| 保存位置 | 适合怎样使用 | 重启时要做什么 |
| --- | --- | --- |
| 进程内的列表、字典 | 当前计算、临时结果 | 重建或从其他地方读取 |
| 持久存储上的文件 | 配置、文档、图片等完整内容 | 找到文件并解析需要的内容 |
| 持久存储上的数据库 | 需要查询、关联和共同修改的记录 | 连接数据库，查询已有记录 |

文件按路径读取和写入字节，格式由程序约定。例如 JSON 文件可以保存整份清单。数据库则还提供记录的查询、约束和事务，应用不必每次读出全部内容再自行改写。

下面把清单编码为 JSON，写入文件，再重新读取。`Path` 表示文件路径，`write_text` 和 `read_text` 分别写入和读取文本，`encoding` 指定字符编码：

```python run id="persistence.files-and-durability.roundtrip"
import json
from pathlib import Path

path = Path("todo.json")
tasks = [{"title": "读一章书", "done": False}]
path.write_text(json.dumps(tasks, ensure_ascii=False), encoding="utf-8")
restored = json.loads(path.read_text(encoding="utf-8"))
print(restored)
print("same values:", restored == tasks)
```

这里 `json.dumps` 把列表转换为 JSON 文本，`write_text` 写入文件；`read_text` 读出文本，`json.loads` 将它解析成新的列表。`restored == tasks` 比较内容是否相等，即使两个列表是分别创建的对象，也会得到 `True`。文件 API 见 [Python pathlib](https://docs.python.org/3/library/pathlib.html#pathlib.Path.read_text)。

**本页的运行实验只验证一次执行中的写入和读回。**浏览器里的 Python 运行在隔离的文件系统中，页面刷新、运行环境重建或浏览器关闭后，文件能否保留取决于运行环境；这段代码无法证明数据跨重启保存。要检验正常重启后的持久化，需要在具有稳定存储目录的实际运行环境中，先写入文件、结束程序，再启动一个新进程读取。

同样，内存数据库的记录依附于它的运行环境。部署数据库时应确认数据文件所在的位置、数据卷的保留方式和清理策略。

## 重启、崩溃与备份

文件写入通常经过应用与操作系统的缓冲。写入调用成功，说明数据已交给相应的写入机制；它是否已经到达断电后仍可恢复的存储介质，还取决于同步操作、文件系统和设备。Python 的 `write_text` 示例足以验证数据的编码和读回，却无法验证突然断电后的恢复。

| 想确认的事情 | 可以怎样检查 |
| --- | --- |
| 程序能正确编码、写入和读回 | 在同一运行环境中写入后重新打开，核对内容 |
| 正常重启后仍有记录 | 结束程序，重新启动并读取 |
| 崩溃后能恢复已确认的修改 | 明确存储的提交与同步规则，在目标环境做故障恢复检查 |
| 设备损坏或误删后能找回数据 | 从独立备份恢复并核对 |

数据库提供事务提交和崩溃恢复机制，相关原理见 <CrossRef id="persistence.transactions-and-recovery" />。实际持久性仍受数据库配置、文件系统和设备的故障条件影响。

备份解决另一类问题：用户误删记录、数据文件损坏或设备丢失时，可以从独立副本恢复。备份需要与原数据分开保存，并通过实际恢复检验可用性。
