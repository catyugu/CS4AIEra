一家书店用程序维护商品目录。新增的书暂存在 Python 列表里，重启后列表会重新创建。要让下一次运行能读到上次的目录，程序得把记录写入进程之外的持久存储。

## 保存与读回文件

文件系统按路径组织文件，文件内的字节怎样解释由程序约定。下面把书目列表编码成 JSON，写入文件，再从文件读回。路径指向浏览器实验提供的临时文件系统。

```python run id="persistence.files-and-durability.roundtrip"
import json
from pathlib import Path

path = Path("books.json")
books = [{"id": 1, "title": "程序与状态", "stock": 3}]
path.write_text(json.dumps(books, ensure_ascii=False), encoding="utf-8")
restored = json.loads(path.read_text(encoding="utf-8"))
print(restored)
print(restored == books)
```

`json.dumps` 把 Python 值编码为文本，`write_text` 把文本以 UTF-8 写入文件。读回时，`read_text` 解码字节，`json.loads` 把文本解析成新的列表。比较两个列表会得到 `True`，因为它们的内容相同。要检验部署后的目录能否跨进程重启保留，可以用实际存储目录在一个进程写入，再启动另一个进程读回核对。[Python pathlib 文档](https://docs.python.org/3/library/pathlib.html#pathlib.Path.read_text)

## 完整文件与数据库记录

如果书店只需导出整份目录给管理员，JSON 文件便于传输，接收方也可以按同一格式导入。封面图片同样适合保存为文件，由商品记录保留封面路径。

到了日常营业，应用要按分类列出有库存的书，关联书目和订单，还要处理同一时间的多笔购买。关系数据库让应用查询所需记录、执行带约束的写入，并把一次购买涉及的多项修改一起提交。数据库可以直接在应用进程中运行，如 SQLite，也可以由独立的数据库服务提供。部署时要找到实际保存数据的位置，确认部署重启和替换实例后还能访问这份存储。

## 重启、崩溃与备份

文件写入可能经过应用、操作系统和设备的缓冲区。正常重启后能够读回文件，说明通常的关闭和加载过程有效。突然断电时能恢复到哪个状态，则取决于写入同步和存储配置。数据库如何恢复已提交的修改，见 <CrossRef id="persistence.transactions-and-recovery" />。

如果目录被误删或存储设备损坏，要从独立备份取回数据。实际做一次恢复并核对内容，才能检查备份是否可用。
