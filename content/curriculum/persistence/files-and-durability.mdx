一家书店用程序维护商品目录。新增的书暂存在 Python 列表里，重启后列表会重新创建。要让下一次运行能读到上次的目录，程序得把记录写入进程之外的持久存储。

## 内存状态与持久存储

在程序结束后仍能保存、供下次运行读取的数据称为持久化数据。这里的目录文件由应用决定数据格式。数据库还为记录提供查询、约束与事务。

文件系统按路径组织文件，文件内的字节怎样解释由程序约定。下面把书目列表编码成 JSON，写入文件，再从文件读回。路径指向浏览器实验提供的临时文件系统。

```python run id="persistence.files-and-durability.roundtrip"
import json
from pathlib import Path

path = Path("books.json")
books = [{"id": 1, "title": "程序与状态", "stock": 3}]
path.write_text(json.dumps(books, ensure_ascii=False), encoding="utf-8")
restored = json.loads(path.read_text(encoding="utf-8"))
print(restored)
print(restored == books)
```

在单元格中，`write_text` 以 UTF-8 保存 JSON 文本，`read_text` 读回后由 `json.loads` 解析。`True` 表示列表内容相同。[Python pathlib](https://docs.python.org/3/library/pathlib.html#pathlib.Path.read_text)

## 文件与数据库

整份交换的目录或封面适合存成文件。需要按分类查库存、关联书目与订单、保证多项修改共同提交时，可以使用关系数据库。

SQLite 在应用进程内访问数据库文件，适合本地工具或由同一个应用服务管理、并发写入有限的数据。PostgreSQL 等客户端／服务器数据库适合多个应用进程通过网络共用数据，并承担更多并发写入。部署时要另外配置服务、连接和备份。[SQLite 使用场景](https://www.sqlite.org/whentouse.html)

## 重启、崩溃与备份

数据可能暂留在应用、操作系统或设备的缓冲区。故障能恢复到哪个状态，取决于提交、同步和存储配置。见 <CrossRef id="persistence.transactions-and-recovery" />。

| 要确认的事 | 检查方法 |
| --- | --- |
| 正确编码与读回 | 在同一次运行中打开文件，核对内容 |
| 正常重启后仍有数据 | 由新进程读取同一持久目录 |
| 崩溃后恢复已确认的修改 | 在实际存储与同步配置下检查恢复结果 |
| 误删或设备损坏后能找回 | 从独立备份恢复，核对内容和时间点 |

浏览器单元格使用临时文件系统，对应第一行。部署时另需核对数据文件或数据卷在重启和替换实例后是否由同一服务继续使用。
