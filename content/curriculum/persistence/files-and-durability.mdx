待办清单放在 Python 列表里，添加和查询都很方便。程序退出再启动，列表却重新变成空的。代码文件仍在，但上次运行创建的对象已经随进程退出而消失。

## 内存适合工作，文件和数据库负责保存

需要在重启后找回清单，就要把内容写到进程之外，并在启动时重新读取。这种让数据跨过一次运行而保存下来的能力，称为持久化。

| 保存位置 | 适合怎样使用 | 重启时要做什么 |
| --- | --- | --- |
| 进程内的列表、字典 | 当前计算、临时结果 | 重建或从其他地方读取 |
| 持久存储上的文件 | 配置、文档、图片等完整内容 | 找到文件并解析需要的内容 |
| 持久存储上的数据库 | 需要查询、关联和共同修改的记录 | 连接数据库，查询已有记录 |

文件按路径读取和写入字节，格式由程序约定。例如 JSON 文件可以保存整份清单。数据库则还提供记录的查询、约束和事务，应用不必每次读出全部内容再自行改写。

“用了数据库”也不自动意味着永久保存：内存数据库随运行结束而消失，临时目录也可能被清理。要确认实际数据文件放在哪里、谁会删除它，以及部署后是否仍能保留。

浏览器里的 SQL 实验会重建夹具，文件实验使用浏览器运行时的文件系统。它们能展示读写和查询，刷新页面后不承诺保留数据。

## 保存成功，应当能应对什么故障

程序的写入可能先进入库或操作系统的内存缓冲，再交给存储设备。写入调用返回、正常读回新内容、断电后仍能找回新内容，是不同要求。

| 想确认的事情 | 可以怎样检查 |
| --- | --- |
| 程序能正确保存并读回格式 | 写入后重新打开，核对内容 |
| 正常重启后仍有记录 | 结束程序，重新启动并读取 |
| 崩溃后能恢复已确认的修改 | 明确存储的提交与同步规则，在目标环境做故障恢复检查 |
| 设备损坏或误删后能找回数据 | 从独立备份恢复并核对 |

刷新缓冲的 API 要按文档理解。例如 Python 的 `flush()` 将文件对象的缓冲交给底层流，不能单独承诺断电恢复，见 [Python io 文档](https://docs.python.org/3/library/io.html#io.IOBase.flush)。需要处理多条记录的共同提交时，应使用数据库的 <CrossRef id="persistence.transactions-and-recovery" />。

持久保存也会保存错误操作：误删已经成功写入后，重启不会把旧数据变回来。备份需要与原数据分开保留，并实际验证能否恢复。

一份清单要求“关闭程序后重新打开仍在”，其中的筛选结果却可以随时重算。哪份数据必须写入持久存储？启动时，应读取哪些原始记录，再重新计算什么？
