同名书可以同时在售，书名也可能修改。书店给每本书分配一个唯一编号，订单保存这个编号。改过书名以后，原来的订单仍然指向同一条书目记录。

## 表、主键与外键

关系数据库用表组织记录。书表 `books` 的一行代表一种在售书目，各列记录编号、书名、分类、价格和库存。订单表 `orders` 的一行表示一笔订单。这里每笔订单只购买一种书，可以购买多册。

本章用 SQL 查询和修改数据库，实验使用 SQLite 和预置的 <LabRef id="catalog" /> 数据。每次运行 SQL 单元格都会从初始数据开始，同一单元格里的语句按顺序作用于同一个数据库。

```sql run id="persistence.relations.tables" fixture="catalog"
SELECT id, title, category, price, stock
FROM books
ORDER BY id;

SELECT id, reference, book_id, quantity
FROM orders
ORDER BY id;
```

`SELECT` 指定要显示的列，`FROM` 指定读取的表，`ORDER BY id` 按编号排列输出。

每张表的主键（primary key）唯一标识该表里的一行。订单 10 和 11 用不同的 `id` 区分，它们的 `book_id` 都是 1，表示两次购买都指向书 1。这个引用列是外键（foreign key）。书表中的一行可被多个订单引用，也可以暂时没有订单。

## 数据库约束与写入

下面用与 `orders` 相同的列和约束新建一张实验表 `trial_orders`，再写入一笔订单。SQLite 的 `STRICT` 选项要求存入的值符合列声明的类型，预置脚本也为当前连接开启了外键检查。[SQLite 建表文档](https://www.sqlite.org/lang_createtable.html) · [SQLite 严格类型表](https://www.sqlite.org/stricttables.html) · [SQLite 外键文档](https://www.sqlite.org/foreignkeys.html#fk_enable)

```sql run id="persistence.relations.exercise-reference" fixture="catalog"
CREATE TABLE trial_orders (
    id INTEGER PRIMARY KEY,
    reference TEXT NOT NULL UNIQUE,
    book_id INTEGER NOT NULL REFERENCES books(id),
    quantity INTEGER NOT NULL CHECK (quantity > 0)
) STRICT;

INSERT INTO trial_orders (id, reference, book_id, quantity)
VALUES (13, 'r13', 1, 2);

SELECT id, reference, book_id, quantity FROM trial_orders;
```

查询得到订单 13，业务请求编号为 `r13`，购买书 1 共两册。建表语句同时规定了接收这笔订单的条件。

| 声明 | 对订单的要求 |
| --- | --- |
| `PRIMARY KEY` | 订单编号唯一 |
| `NOT NULL UNIQUE` | 业务请求编号必填且唯一 |
| `NOT NULL REFERENCES books(id)` | 必须填写已有书目的编号 |
| `NOT NULL CHECK (quantity > 0)` | 必须填写正数数量 |

网页表单可以在用户填写时提示数量错误。数据库约束同样会检查来自批量导入和管理脚本的订单，因此每条写入路径都遵循同一规则。

## 练习

把插入语句中的书编号改成 9，再运行。恢复书编号后，把数量改成 0。根据两次 SQLite 错误说明，分别判断写入违反了哪条约束。遇到报错时该单元格会停在出错语句。
