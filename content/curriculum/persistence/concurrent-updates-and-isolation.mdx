商品页面显示只剩一册，两位用户同时发起购买。如果请求先读出库存，在应用里算出新值，再将结果写入数据库，两次购买可能根据同一份旧库存作决定。

## 并发更新与更新丢失

下面的两次读取都发生在各自的写入事务开始之前。每个事务按先前算出的数量写入库存，同时创建自己的订单。

| 步骤 | 请求 A | 请求 B | 库存 | 新订单数 |
| --- | --- | --- | --- | --- |
| 1 | 读取库存 1 | | 1 | 0 |
| 2 | | 读取库存 1 | 1 | 0 |
| 3 | 写入库存 0，提交订单 | | 0 | 1 |
| 4 | | 写入库存 0，提交订单 | 0 | 2 |

第二次写入用同一旧值重新计算，把第一次扣减的效果覆盖了。这称为丢失更新。库存满足非负约束，订单却卖出了两册。要保证可售数量，结账时用一条语句按当前库存判断并扣减，也就是 <CrossRef id="persistence.data-changes" /> 中的条件更新。应用只在扣减成功的事务中创建订单。

## 版本检查

管理员编辑书目信息时，可能在页面上停留很久，再保存基于旧数据的修改。可以给记录加一个版本号。应用在读取记录时取得版本号，写入时要求数据库中的版本仍等于读到的值，并在成功写入时递增版本。这样，第二次编辑就能知道记录已被改过。

下面仍以一册库存为例，使用 SQLite 顺序重放两个请求各自取得的旧值和随后尝试的更新。这里演示版本条件的效果，完整购买还要在事务中检查库存并写入订单。

```python run id="persistence.isolation.version"
import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, stock INTEGER, version INTEGER)")
db.execute("INSERT INTO books VALUES (1, 1, 0)")

read_book = "SELECT stock, version FROM books WHERE id = 1"
old_a = db.execute(read_book).fetchone()
old_b = db.execute(read_book).fetchone()
update_book = """
    UPDATE books SET stock = ?, version = version + 1
    WHERE id = 1 AND version = ?
"""

for label, (stock, version) in [("A", old_a), ("B", old_b)]:
    changed = db.execute(update_book, (stock - 1, version)).rowcount
    print(label, changed)

print("库存与版本", db.execute(read_book).fetchone())
db.close()
```

`?` 是值参数的占位符。SQLite 接口把元组中的新库存和旧版本依次绑定到两个占位符。`rowcount` 返回受影响行数。[Python sqlite3 参数绑定](https://docs.python.org/3/library/sqlite3.html#sqlite3-placeholders)

A 用版本 0 写入成功，库存变为 0，版本变为 1。B 仍按版本 0 更新，结果是零行。若 B 要继续购买，必须重新读取库存、重新判断可售数量。

## 事务隔离与冲突

原子性让扣减库存与创建订单共同提交。隔离关心另一个事务在这些操作交错时能看到什么，以及数据库如何处理冲突。<Term id="isolation-level">隔离级别</Term>约定了这些并发行为的保证。数据库可以让写事务等待已有写入结束，也可以检查冲突并要求其中一个事务从头重做。对于读取，引擎可以通过<Term id="mvcc">多版本并发控制</Term>保留数据的多个版本，让读取按规则访问可见的版本。

应用要按数据库的实际保证安排读写。需要重试整个事务时，重新读取库存和版本，再按当前状态判断是否还能购买。[SQLite 隔离文档](https://www.sqlite.org/isolation.html) · [PostgreSQL 事务隔离文档](https://www.postgresql.org/docs/current/transaction-iso.html)
