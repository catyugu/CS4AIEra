异常指向 `int(record["seconds"])`，问题可能是文本无效，也可能是字段缺失，还可能是调用方把整个列表当成了一条记录。看到失败行后，仍需要找出该行依赖的哪个前提被破坏，以及那个前提由谁建立。

## 调用栈记录失败经过的位置

下面有三层调用。先运行，找到最后一行的异常类型，再从上到下读它经过的调用位置：

```python run id="debugging-and-observability.exceptions-and-diagnosis.traceback"
def seconds(record):
    return int(record["seconds"])


def summarize(records):
    total = 0
    for record in records:
        total += seconds(record)
    return total


def report(data):
    print(summarize(data))


report([{"seconds": "12"}, {"duration": "5"}])
```

回溯（traceback）给出异常传播经过的调用位置；异常类型和消息说明此次失败属于哪类操作。本例最后显示 `KeyError: 'seconds'`，说明字段访问失败，`int` 尚未取得输入。回溯中的 `report`、`summarize` 和 `seconds` 分别是外层到内层的调用位置，最后一个位置最接近本次失败。因而优先检查记录的结构与字段约定。异常传播规则见 <CrossRef id="program-logic-and-state.exceptions-and-cleanup" />。

调用栈显示“错误在哪被观察到”，不必然显示“错误在哪被制造”。数据可能早在载入、转换或缓存时就丢了字段；当前行只是第一个要求该字段存在的位置。把当前行包进宽泛的异常捕获并返回 0，会改变结果，却没有修复输入与接口之间的约定。

## 缩小复现时保留失效条件

可以先只保留出问题的那条记录，直接调用 `seconds`。如果仍触发同类缺失字段错误，就暂时排除了汇总循环、其他记录和输出步骤。随后对照接口文档：外部格式究竟提供 `duration` 还是 `seconds`，转换层是否应负责改名？

最小复现需要保留相同失败机制。若删掉一条记录后错误从字段缺失变成“空列表不合法”，虽然代码更短，却已经换了问题。依赖共享历史的错误还要保留建立该历史的调用顺序；并发错误要保留必要交错。

| 观察或实验 | 能排除的假设 | 仍需确认 |
| --- | --- | --- |
| 直接调用 seconds 仍失败 | 失败必须依赖汇总循环 | 记录在哪一步形成 |
| 原始返回已缺少字段 | 字段仅在本地汇总时丢失 | 外部契约是否允许缺失 |
| 原始返回有字段，转换后没有 | 读取端原本没有字段 | 转换逻辑及分支条件 |

每次实验都应该使某个假设变得不可能，或者暴露新的可检验差异。只在很多位置打印同一个值，会增加材料而不一定增加区分能力。

## 本机与部署环境的差异也是输入

进程读到的配置、当前目录、依赖版本、资源权限及实际载入的模块都会影响行为。本机能跑说明本机这些条件下的一次执行成功，不能推导部署时条件相同。

例如同一相对路径在不同当前目录下指向不同位置；同名模块可能来自不同安装位置；环境中的数值配置仍要先解析与校验。进程和装载边界见 <CrossRef id="program-execution.compilation-and-calls" /> 与 <CrossRef id="program-execution.processes-and-kernel" />。

要区分“配置值无效”与“没有读取到预期配置”，先观察配置来源和解析后的实际值。要区分“依赖实现改变”与“数据不同”，先固定输入，再比较实际载入的依赖及版本。观察对象应对准争议条件，秘密值可以只记录是否存在和来源，无需打印完整内容。

Python 提供结构化读取和格式化回溯的接口，见 [Python traceback 文档](https://docs.python.org/3/library/traceback.html)。输出更多局部变量之前，要确认它们是否参与当前假设，避免把整份请求数据复制进错误报告。

## 练习

将示例第二条记录改成 `{"seconds": "fast"}`。先预测失败类型和位置，再运行。对两种错误，都使用“返回 0 继续处理”的补丁，会使调用方失去哪两种不同信息？

一份最小复现把外部读取换成固定字典后无法重现错误。有人据此判断汇总代码正确、外部服务错误。审查这个推论：哪些读取后的类型、缺失条件或状态历史可能已经被替换掉？提出一个只改变其中一项条件的实验。
