语义化版本用主版本、次版本和修订版本表达变更性质。在正式版本阶段，破坏公开 API 兼容的变更增加主版本，兼容的新功能增加次版本，兼容的缺陷修复增加修订版本，见 [Semantic Versioning 2.0.0](https://semver.org/)。

规则依赖项目明确声明公开 API。初始开发阶段的主版本为零，规范允许 API 随时变化；预发布标识也有其单独规则。

版本号表达发布者按规范作出的声明。一次具体升级是否满足使用者的要求，还要核对实际接口、行为与使用条件。
