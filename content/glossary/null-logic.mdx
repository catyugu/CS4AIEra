SQL 的布尔表达式有三个真值：`TRUE`、`FALSE`、`UNKNOWN`。NULL 表示值未知或不存在，与空字符串或零不同，因此 `NULL = NULL` 与 `NULL = 1` 都求值为 `UNKNOWN`，任何与 NULL 的等值或大小比较都得到 `UNKNOWN`。`WHERE` 子句只保留求值为 `TRUE` 的行，`FALSE` 与 `UNKNOWN` 都被丢弃；判断值是否存在要用 `IS NULL` / `IS NOT NULL`，它们对 NULL 给出确定结果，且两者互补覆盖全部行。

未知会按三值逻辑传播：`NOT UNKNOWN` 为 `UNKNOWN`，`TRUE OR UNKNOWN` 为 `TRUE`，`FALSE OR UNKNOWN` 为 `UNKNOWN`。这带来两类静默错误：`col = 'x'` 与 `col <> 'x'` 的并集不包含 `col` 为 NULL 的行，完备的过滤条件要补上 `IS NULL`；`x NOT IN (a, b, NULL)` 在 `x` 不等于任何非 NULL 元素时为 `UNKNOWN`，整条查询可能返回空集，表达「不存在」应使用 `NOT EXISTS`。

聚合与分组对 NULL 的处理与比较不同：`COUNT(column)` 只计非 NULL 行、`AVG` 的分母是非 NULL 行数，而 `GROUP BY` 使用等价关系，把所有 NULL 归入同一组；`ORDER BY` 中 NULL 的位置由引擎决定（SQLite 视为最小值），属于方言。

约束对 NULL 的保证范围也要看清：`CHECK` 只在结果为 `FALSE` 时被违反，因此不禁止 NULL；`UNIQUE` 允许任意多行 NULL；外键列上的 NULL 不触发引用检查。用空字符串或 0 表示缺失，会让「未知」与「空值」在存储层无法区分。
