# CURRICULUM.md

本文件是课程地图：模块顺序、每个模块教什么、模块之间怎样分工。它描述**教学意图**，不描述清单。

精确的课程树——子章节、课时 `id`、标题、顺序与发布状态——由各目录的 `_section.yaml` 与课时 frontmatter 表达，那是唯一的权威来源：新增一节课、拆分一个章节或推进发布状态都不应该要求修改本文件。写作方法见 `doc/CONTENT_GUIDE.md`；产品与运行时的设计见 `doc/DESIGN.md`；仓库不变量与完成标准见 `AGENTS.md`。

Python 是唯一能在线运行的语言，其余模块的实验都在它上面建立；复杂度是后续所有性能与容量论断的记法，因此紧随其后；操作系统与网络提供数据库、分布式系统与安全所依赖的运行时与通信假设；软件工程讨论如何安全地变更这些系统，因此排在系统类模块之后；安全最后，因为它需要前七个模块的具体机制才能建立可信的威胁模型。

## Python 语言（`python`）

**定位**：课程的编程基础与唯一的在线实验载体。本模块建立后续模块反复使用的程序语义模型，使它们可以直接给出 Python 实验而不必再解释语言。

**核心主题**：语言的基本使用（程序、值、控制流、函数、类、内置容器）；程序语义模型（求值、绑定、对象与共享状态、调用、作用域、迭代协议、异常与资源生命周期、属性查找）；数据表示与语言保证的边界；协作式异步的调度模型、异步迭代与异步上下文协议、取消与清理、超时与结构化任务生命周期。要求是把「能写出程序」推进到「能精确预测程序的行为」：给定一段陌生的 Python，读者能预测其状态变化、控制流与失败行为；不能预测时，知道该构造什么实验来验证。`python.basics` 是有意设置的入门层，面向完全没有 Python 经验的读者，必须自洽地提供足以阅读、修改和编写后续示例的工作语言。

**边界与去处**：线程、GIL 与共享内存归 `operating-systems`（线程是操作系统的执行模型，本模块只讲语言的协作式异步语义）；剖析、依赖声明与锁文件、异常层次与失败契约设计归 `software-engineering`；真实并发与 I/O 下的任务生命周期由 `operating-systems` 与 `networks` 重新连接。结构模式匹配由首次使用它的模块引入。

## 数据结构、算法与复杂度（`algorithms`）

**定位**：建立成本模型与表示选择的语言。目标不是算法清单，而是让读者能自己推导复杂度、构造反例、判断常数与局部性、在真实约束下选择结构。

**核心主题**：主线是「契约与表示 → 成本与正确性 → 线性结构 → 关联结构 → 树与优先结构 → 查找／排序／选择 → 图 → 算法设计范式 → 综合选择」。分析基础只建立最小分析语言——在数什么成本、成本怎样随规模增长、一段算法为什么确实得到它声称的结果；契约与表示留到线性结构第一次比较两种表示的位置。

三件分析工具在第一次真正需要它们的位置出现，而不是排成一册先修手册：摊还跟随动态数组，递归、调用树与递推式（含主定理）靠近树与分治，平均与期望靠近哈希表与随机化。图子章节先只教「未访问／已访问」与 frontier，三状态模型留给真正区分「仍在递归路径上」与「已经完成」的地方（环检测与拓扑序）。

设计范式回答「怎样设计」：分治只讲拆分、同类性、合并、正确性的递归骨架与拆分比例对成本的影响，递推式分析属于分析工具；贪心的主线是交换论证，一般结构（含拟阵）只作延伸；动态规划先建立「状态 → 基本情形 → 转移 → 求值顺序」，再单独讲状态设计与成本（状态够不够、伪多项式、空间压缩的方向、前缀与区间状态、状态依赖图）。图的实验表示在模块内保持稳定：遍历与 Dijkstra 给邻接表，Bellman–Ford 与 Kruskal 给边列表，表示之间的转换只在图表示那一节讨论。本模块同时维护跨章节复用的术语层。

**边界与去处**：冷门命名算法的实现、非教学必要的手写平衡树、排序算法展览与常数因子对比表不进正文；复杂性理论与不可近似性不属于本模块，比较模型与决策树下界是它的终点；剖析与基准测试方法论归 `software-engineering`；缓存局部性背后的硬件与虚拟内存机制归 `operating-systems`；B 树、外部存储结构与查询计划在存储引擎中的形态归 `databases`；并发数据结构归 `operating-systems`。Python 只是实验语言，本模块不是 Python 容器教程，也不是面试题集。

## 操作系统（`operating-systems`）

**定位**：解释上层所有系统的运行时底座。内核边界、虚拟内存、调度、同步与 I/O 路径是数据库、分布式与安全模块反复依赖的机制。线程在本模块首次引入，实验载体是 Python 的 `threading`。

**核心主题**：进程与线程、文件与描述符、管道与 socket、权限与信号；内核边界的代价；虚拟内存、地址转换与分页；缺页与置换；调度与阻塞；同步原语、内存序、竞态与死锁；文件系统语义、缓冲与持久性；资源限额与背压；容器作为隔离机制。

**要求与边界**：每个概念都要落到能观察到的资源、延迟或错误上，读者能从一个现象回到内核机制；系统调用号、冷门调度器参数与发行版管理命令不进正文。

## 计算机网络（`networks`）

**定位**：协议行为与它的运维后果。重点在延迟的构成、可靠性机制的真实契约，以及超时与重试如何把传输层行为传播到应用层。

**核心主题**：分层与分组交换；IP 编址与路由；TCP 与 UDP 的真实契约；延迟构成与尾延迟；DNS、HTTP 与缓存语义；TLS 的信任建立；连接生命周期与连接池；超时、重试与幂等的相互作用；排队与部分连通。

**边界与去处**：字节级头部记忆、端口号表与厂商 CLI 语法不进正文。重点是协议承诺与运维后果之间的距离。

## 数据库（`databases`）

**定位**：持久状态与并发的核心。本模块用 SQL 夹具做可执行实验，把关系语义、约束、索引与事务后果呈现为可观察的输出与查询计划。

**核心主题**：关系模型与键；SQL 的包语义与三值逻辑；约束作为完整性规则；连接作为关系组合；变更语句与状态转移；B 树索引、访问路径、查询计划与基数估计；索引的写入代价；事务与日志、隔离级别、MVCC 与锁、崩溃恢复；复制；热点键、在线模式变更与 ORM 边界。核心模型是「声明式语句与它实际触发的执行之间的距离」：同一查询在不同计划下的成本差异。

**边界与去处**：分布式数据系统的一致性权衡归 `distributed-systems`；持久性的文件系统机制归 `operating-systems`；完整 SQL 语法、厂商管理命令与 ORM 方法清单不进正文。

**夹具**：现有 `sql.orders.basic` 覆盖关系语义、`NULL`、聚合、连接与约束；索引与查询计划需要更大的夹具（更多行与多个索引），事务与隔离需要可并发访问的夹具，按同一模式扩展。

## 软件工程、Git 与测试（`software-engineering`）

**定位**：变更与验证的方法论。前面所有模块讲系统如何工作，本模块讲如何安全地改动它们，以及什么证据能支持「改动正确」这一结论。

**核心主题**：仓库工作流与 Git 对象模型；接口与信息隐藏、耦合与依赖方向；兼容、弃用与迁移；测试判据设计、确定性与隔离、基于属性与不变量的测试；依赖与可复现构建；CI 作为验证管道；可观测性作为设计；从证据调试与评审生成代码。性能剖析在这里展开，它需要算法模块的成本模型与操作系统模块的 I/O 知识在前。

**边界与去处**：Git 参数含义与断言 API 清单不进正文。重点始终是「什么证据支持改动正确」，而不是工具用法。

## 系统设计与分布式系统（`distributed-systems`）

**定位**：部分失败下的推理。与单机系统的差别在于失败模型、时间假设与状态所有权，因此从失败模型与时钟开始，再进入复制、一致性与容量。

**核心主题**：失败模型与部分失败；时钟、顺序与超时；复制与一致性模型；quorum 与读写交集；分片与再平衡；幂等与投递语义；背压与容量估算；缓存、队列与状态所有权；恢复与对账。

**边界与去处**：单机并发原语归 `operating-systems`；持久化与事务语义归 `databases`。重点是从失败模型出发推导系统行为，而不是罗列产品与架构模式。

## 安全（`security`）

**定位**：对抗性场景下的系统推理。从资产、对手与信任边界开始，把前七个模块的机制放进威胁模型，再讨论密码学、Web 与供应链的具体控制。

**核心主题**：威胁建模与信任边界；认证、授权与会话；口令与密钥的生命周期；TLS 与哈希的正确使用；注入与解析歧义；XSS、CSRF 与源模型；沙箱与隔离；依赖与供应链；审计与隐私的取舍。

**边界与去处**：不理解机制就背漏洞缩写、没有威胁模型的检查表、密码学参数表不进正文。重点是先建威胁模型再谈控制，并识别「已加密」「已签名」这类表述并不等于所需性质。
