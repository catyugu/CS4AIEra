# DESIGN.md

本文件规定产品的架构，以及少数几个已经被反复挑战过的设计决策的**理由**。

精确的当前事实不在这里，它们在能被机器检查的地方：

| 事实 | 权威位置 |
| --- | --- |
| 课程树、顺序、标题与发布状态 | 各目录的 `_section.yaml` 与课时 frontmatter |
| 可执行单元格的合法字段与构建期校验规则 | `src/content-model/schema.ts`、`src/markdown/codelab-cells.ts`、`scripts/validate-content.ts` |
| 运行时报文、会话与输出类型的精确结构 | `src/runtime/protocol.ts`、`src/workers/pyodide.worker.ts`、`src/runtime/python-runtime.py` |
| 仓库不变量、文档职责与完成标准 | `AGENTS.md` |
| 一节课怎么写 | `doc/CONTENT_GUIDE.md` |
| 教什么、模块顺序与理由 | `doc/CURRICULUM.md` |

新增一节课、拆分一个章节、给单元格增加一个选项、推进发布状态，都不应该要求修改本文件。只有架构本身变化时才修改它。

## 目的与范围

产品是一个长期演进、内容优先的 Web 应用，面向可能无正式 CS 背景、但技术素养较高的自学者。系统须支持大型层级课程、精确技术阐述、显式术语，以及浏览器内可执行的 Python/SQL 演示；须便于版本化、评审、部署与多年扩展，而不退化成 LMS 或定制应用服务器。

产品分成四层：版本控制的课程内容；构建期的内容编译与校验；以静态为主的阅读 UI；用于交互实验的本地浏览器执行运行时。服务器只分发静态文件。有价值的「状态」要么在创作期存在于 Git，要么短暂存在于学习者浏览器中。

明确不在范围内：账号、进度、成绩与服务端执行（属于仓库级约束，见 `AGENTS.md`）；评论与论坛、云端 IDE、协同编辑、浏览器内 Git 客户端、把任意第三方包安装当作保证能力、集成式 AI 辅导、离线模式与 Service Worker。它们让系统更难理解、更难托管或更难保证安全。

**架构原则**

| 原则 | 含义 |
| --- | --- |
| 内容优先 | 耐久资产是课程而不是 Web 框架。一节课作为 Git 中的源文本必须仍可读；渲染组件增强正文，正文本身仍在源文本中 |
| 默认静态，例外才交互 | 正文、定理、表格与静态代码块在构建期渲染为 HTML。客户端 JS 只留给真正交互的能力：可执行单元格、术语浮层、树状态、搜索 UI |
| 显式语义优于推断 | 术语引用、可执行代码、共享 session 都由作者显式标注；构建系统不按拼写、源顺序或启发式文本匹配推断 |
| 稳定身份与呈现分离 | 课程与术语有稳定 ID；标题、URL slug、章节与顺序可以变；引用指向 ID，并在构建期解析 |
| 浏览器执行可丢弃 | 运行时状态不是用户数据，可能被 Reset、Stop、跳转或刷新销毁；创作模型不得依赖持久化 |

## 技术基线

**框架**：Astro + TypeScript。应用绝大部分是内容，适合输出静态 HTML、只对选定组件做 hydration。TypeScript 用于内容 schema、构建工具与运行时协议。关键要求是静态生成加组件化 MDX，架构不依赖 Astro 特有魔法。

**课时格式**：MDX。保留 Markdown 写作手感，在 Markdown 不足处使用显式语义组件。组件是创作 DSL 的一部分，接口必须小而稳定。

**数学记法**：`$...$` 与 `$$...$$`，构建期渲染为静态 KaTeX，页面不加载客户端数学运行时；样式与字体来自打包的 `katex` 依赖，因此不发出第三方请求。KaTeX 无法解析的公式让构建失败。

**编辑器**：CodeMirror 6，按需加载。足以支撑嵌入式实验，又比整套桌面 IDE 抽象轻得多。

**运行时**：固定版本、自托管的 Pyodide，运行在专用 Web Worker 中。它在一个运行时内同时覆盖 Python 与 SQL 基线用例。生产环境不得从非固定版本的公共 CDN 加载它。

**搜索**：构建期生成静态索引，不需要应用服务器。索引器是选型，不是内容契约。

**工具链**：`npm` 是包管理器与脚本运行器，Node 是唯一运行时；内容校验、类型检查与测试都在 Node 下执行。依赖的生命周期脚本按 `package.json` 的 `allowScripts` 白名单执行。

替换以上任何一项都需要减少复杂度或满足新的具体需求，而不是因为另一个库更流行（见 `AGENTS.md`）。

## 内容模型

**身份来自稳定 ID，不来自路径**。`id` 全局唯一，在移动文件与改标题后保持不变；`slug` 只是公开 URL；引用一律用 `id`，构建期解析。

**一个事实只有一个家**。章节的 `id`、`label`、`order`、`summary`、`status` 在 `_section.yaml`；课时的 `id`、`slug`、`order`、`title`、`status`、`objectives` 在 frontmatter。课程树由这些元数据组成，没有第二份镜像。文件的目录结构只服务于人的阅读。

**显式语义**。术语引用、课时与章节引用、实验夹具引用、可执行代码块都由作者显式标注；构建期不做文本推断。新增一个原语意味着同时补齐校验与渲染。

**可见性与路由**。`status` 决定内容是否进入站点，不决定 URL：`published` 生成页面并进入导航与阅读顺序；`draft` 与 `review` 只在开发服务器下可见；`archived` 任何模式下都不可见。章节不可见时其下的课时随之不可见。

**阅读顺序**是课程树的深度优先遍历：先排本节自己的课时，再进入子章节，同级按 `order` 排序。`order` 只在同级之间比较。

**拆分与删除**。拆分课时时新课时取新 `id`，原 `id` 留给覆盖原有范围的那一节。删除课时或章节要清掉引用（`CrossRef`、术语、实验），并删除被合并的文件；不为删掉的 ID 或 URL 保留兼容别名、归档页或重定向。

## 创作与渲染模型

正文是 MDX，服务它的原语刻意保持小：术语引用、跨课时引用、实验引用、可执行与静态代码块、行内与行间数学。构建期把正文、标题锚点与数学渲染成静态 HTML。

**可执行代码必须显式声明**：信息串中写出 `run` 与页面内唯一的 `id`，语言是 `python` 或 `sql`，其余选项由作者声明、由构建期校验。合法字段的完整清单属于 schema 与校验器，本文件与写作指南都不复制；非法选项、非法取值与不存在的夹具都是构建失败。

**标题锚点只有一个实现**：校验与渲染调用同一个函数，页面上的锚点与构建期检查的对象因此是同一个字符串。代价是标题的 Markdown 语法被限制在行内代码与强调之内。

**校验的策略**：断开的引用（`CrossRef`、`Term`、`LabRef`、夹具、资产）、重复的 ID、重复的 slug、同一页面内重复的标题锚点与重复的单元格 `id` 都是硬失败；孤立术语、未被引用的夹具这类编辑问题可以是警告。校验器必须能命名出错的文件与位置。

**阅读页面的脚本预算**：一个页面只加载它确实需要的能力——含可执行单元格的课时加载单元格运行时，含术语引用的页面加载浮层定位，含标题的页面加载目录标记。不 hydration 整页，不为排版引入客户端状态。

## 浏览器执行模型

**学习者代码只在浏览器里执行**，永远不进入服务端。这是产品边界的一部分，不是实现细节。

**一个惰性 worker**：含可执行单元格的每个课时页面使用一个惰性创建的 Pyodide worker，首次 Run 时建立，执行请求串行排队，页面跳转销毁它。每页一个 worker 在启动成本与故障隔离之间取平衡：每单元格一个 worker 浪费内存，整站一个 worker 带来跨页隐藏状态与更大的故障半径。自托管运行时缺失时构建直接失败，而不是产出一个单元格全部失效的站点。

**隔离与共享**：单元格默认在全新的命名空间里执行；作者可以让若干单元格加入同一个具名 session，此时它们共享命名空间（SQL 共享一个连接）。具名 session 的存在本身就是教学信息：共享状态必须是显式声明的，而不是执行顺序的副产品。

**Stop 与 Reset 都销毁运行时状态**。可靠的中断实现是终止 worker，随后一次执行重建它并按需重建夹具与 session；这比试图让所有 Python 负载都可协作取消要强得多。Reset 把编辑器内容恢复为作者源码，或重建单元格与 session 的执行上下文。UI 必须让读者看到哪些状态被丢弃了。

**输出是带类型的流**，不是任意 HTML：文本、表现、表格与受影响行数由 UI 决定如何渲染；表格要区分 SQL 的 `NULL`、字符串 `NULL` 与空字符串；运行时输出与异常文本一律作为不可信文本插入，绝不注入页面。

**资源与安全限制**：硬执行超时、可在执行期间使用的 Stop、输出字节上限、SQL 结果行数上限、固定发行版内的包白名单、每个 worker 同时只允许一个执行。具体数值与实现属于代码。

**SQL 与夹具**。基线 SQL 引擎是同一个 worker 里 Python 的 `sqlite3`：不需要第二个 WASM 运行时，Python 与 SQL 演示在有意设计时可以共享数据，作者提供的数据库也易于复现。实验夹具是声明式的（`lab.yaml` 加 `seed.sql`，或预构建的数据库文件），构建期校验被引用的夹具存在，运行时把作者的字节重放进一个全新连接——Reset 因此就是重放，不需要保存与恢复层。课程必须标注引擎特有行为：PostgreSQL、MySQL 特有的语义要被说明为如此，而不是悄悄模拟。

## 术语、导航与搜索

**术语三层**：行内显式标记；由词条 frontmatter 的短定义驱动的快速定义（纯 CSS 浮层，键盘与读屏可达）；稳定 URL 上的完整词条，含定义、适用范围与相关术语。词条不列出引用它的课时——正文里的显式标记本身就是那份记录。词条分普通与模型两档，结构由它在课程里的复用范围决定，两档不新增 frontmatter 字段。

**导航**：静态生成的三栏布局（课程树 / 正文 / 页内目录）。宽度不足时先收起页内目录列，再折为单栏并把课程树移进抽屉；第一屏必须落在面包屑与标题上，而不是整棵课程树。课时页给出面包屑、页首元信息、学习目标与按阅读顺序的前后课时。课程树使用原生 `details`，折叠状态不需要客户端脚本。

**没有进度系统，就不显示完成状态**。面向作者的计数（课时正文的 token 数）只在开发构建中出现：读者无法据它行动。

**搜索**：构建期生成静态索引，覆盖课时标题、各级标题、术语与别名、正文与 ID，并把标题层级排在正文之上；同时生成反向引用（某个实验被哪些课时使用）。这张图让系统在没有任何数据库服务器的情况下具备文档行为。

## 安全与可复现性

- 静态站点、无应用后端、无代理或执行学习者代码的服务端端点；页面不得包含学习者代码可以滥用的秘密、令牌或特权 API。
- 全部运行时资产自托管并固定版本，构建可离线复现；不承诺任意包安装，也不依赖第三方网络可用性。
- 所有渲染出的运行时输出都当作不可信输入处理。
- Web Worker 限制 UI 阻塞，但不构成强安全沙箱；目标不是声称任意 Python 被完美沙箱化，而是确保它周围没有多少有价值的高权限可滥用。
- 产物是静态的 `dist/`，可放在任何静态托管上；带哈希的资产长期缓存，HTML 短期或需重验证。

## 可访问性

技术深度不构成 UI 不可访问的理由：

- 课程树、单元格控件、术语快速定义与编辑器可完整键盘操作，焦点样式可见；
- 运行状态与错误以适当方式播报，输出容器是可键盘到达、带标签的区域；
- SQL 结果渲染为语义化表格，`NULL` 的表示不依赖颜色即可理解；
- 数学内容尽量以支持 MathML 或等价 ARIA 的方式渲染；
- 需要图像或图表时给出有意义的文字替代。

## 关键设计决策

**不用 notebook 架构**。notebook 把正文与可执行单元格混在一起，隐藏的执行顺序造成状态歧义，稳定引用与术语语义难以表达，服务端 notebook 还会违反「不在服务器执行」的目标。借用其中有用的部分——可编辑的可执行单元格——同时保留文档语义与显式状态。

**不用完整 SPA**。完整单页应用让静态正文依赖 JavaScript，增加 bundle 复杂度，并鼓励产品并不需要的全局客户端状态。

**不把任意 PyPI 安装当作能力**。可复现性比包的数量更重要；课程运行时的能力边界是固定的发行版，而不是学习者当前能下载到什么。

**运行时升级是内容变更**。Pyodide 发行版、Node 工具链与课时显式使用的包都固定版本；会改变课时可观察行为的依赖升级要按影响内容的变更评审，并区分「Python 语言语义」与「CPython 或浏览器运行时的实现行为」。
